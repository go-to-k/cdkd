# src/deployment

Secrets: [layout-deployment-secrets.md](layout-deployment-secrets.md). Index: [code-layout.md](code-layout.md).

- **deploy-engine.ts** - orchestration. `redactedAttributeReads` entries are STRUCTURED (`kind`/`logicalId`/`key`/`display`) and the bag's PRESENCE is the opt-in letting `refStateLookupFromResource` skip a masked leaf, so only the PROVISIONING sites pass one, never the deploy-internal diff context (#2847).
- **`deploy-engine/*.ts`** - `DeployEngine` method groups split out (#4200) as mixins: `export function name(this: DeployEngine, ...)`, a `declare module '../deploy-engine.js'` augmentation tagging each `@internal`, and `DeployEngine.prototype.name = ...` after the class, checked by `deploy-engine-mixins.test.ts`. The directory is in the `integ-destroy` scope by glob; a rule whose `paths:` names `deploy-engine.ts` for code that moved must name the new file. **`intrinsic-resolver/*.ts`** - code split out of `IntrinsicFunctionResolver` ([#4337](https://github.com/go-to-k/cdkd/issues/4337)); a split module imports helpers from its siblings, never values from the host, which tests `vi.mock`.
- **`DeployEngineOptions.inheritedSecrets`** - seeds a nested child's redaction, recorded AT RESOLUTION TIME and COUPLED to `diff-recursive.ts`'s `skipDynamicReferences: true`. Only the child's DIFF context binds a redacted parameter bag; PROVISIONING and CONDITION-EVALUATION keep real values, since an expression inside `Fn::Equals` flips a condition.
- **drain-budget.ts** - REMAINING wait, not a deadline. Lock-holding loops wrap in `withSharedDrainBudget`; condition evaluation keeps a budget PER CONDITION.
- **outputs-export-alias.ts** - key-space rules for the OUTPUTS bag (#1919). `state.outputs` is keyed by output NAME; an `Export:`-carrying output is ALSO aliased under its export name in the SAME bag, beside a parallel POSITION-source bag of unresolved template values. ONE module, four writers, but **deploy and scrub deliberately do NOT share every rule**: a condition-suppressed output publishes no value and does NOT reserve its name, while scrub ignores conditions and over-approximates.
- **stale-attribute-heal.ts** - the `Fn::GetAtt`-miss heal ([#1852](https://github.com/go-to-k/cdkd/issues/1852)), an import-free LEAF both the resolver and the engine read. The resolver asks `ResolverContext.attributeHealer` ONLY when `guardedPhysicalIdFallback` (or the placeholder-ARN / DBProxy `VpcId` refusal, or a `healBeforeConstructing` arm, [#3627](https://github.com/go-to-k/cdkd/issues/3627)) is reached, under a PROBE phase carried on a DERIVED context — never on the resolver instance, which concurrent resolutions share. `DeployEngine`'s healer reads through the provider's `import()` routed by the record's `provisionedBy`, once per record per deploy, never throws, and merges at `redactStateForPersist` — ADD-only except over a pre-#1681 placeholder ARN, never an empty value, so every save path persists it and `--dry-run` none. `cdkd diff` supplies the only other one, READ-ONLY (`read-only-attribute-healer.ts`, [#3456](https://github.com/go-to-k/cdkd/issues/3456)): the same read in the STACK's region, served to the preview and never merged or saved.
- **inline-policy-claims.ts** - whether ANOTHER resource of THIS deploy has ALREADY written an inline policy name onto a principal, asked LIVE by an `IAM::Policy` update / deploy-DELETE before each removal ([#4156](https://github.com/go-to-k/cdkd/issues/4156)). It reads only resources whose provider write COMPLETED (`inlinePolicyWriters`, recorded after the state record) and what they RECORDED, never the template: a wrong `true` keeps the removed policy's OLD document, a stale grant no record owns, so every doubt (not run, in flight, failed, a value outside IAM's name charset, a principal update that did not change its own `Policies`) answers `false` and the removal proceeds.
- **nested-child-journal.ts** - a nested child's journal across its PARENT's deploy ([#3754](https://github.com/go-to-k/cdkd/issues/3754)). A NESTED engine's success APPENDS a `nested-pending-parent` segment; only the ROOT's success deletes journals, its own and every descendant's. A revert of the row replays the child's segments for the SAME `runId`, bound by both rollback drivers via `withNestedRevertRun` — never a template re-deploy, which diffs NO_CHANGE. Correlate by run, not position: a self-rolled-back child leaves a segment the parent never reverts.
- **replacement-name-holder.ts** - who holds a replacement's colliding name. Deploy: does a replacement ask for a name the old resource does NOT hold (#3808)? A positive answer REFUSES delete-first and makes the update-failure fallback and `--recreate-via-*` create first (#3931), so it answers only a KNOWN difference; `undefined` keeps the old order. On a name-ADOPTING SDK create (`replacementNameProbe`, #3937) the engine first asks the provider's `import()`: another holder refuses, the old one voids the answer; a plain CREATE asks it for an EXPLICIT name (`createNameQuestion`, #4180) and refuses ANY holder, its own orphan included. That ORDER compares names exactly outside `CASE_INSENSITIVE_NAME_TYPES`, and a rule's bus move counts as a rename. Rollback: `reverseReplacementNewHoldsName` (#3979) is the INVERSE polarity — delete-new-first runs only on a PROVEN holder; its deploy twin `replacementOldHoldsSentName` gates `--replace`'s delete-first the same way, sharing one rule, and alone may prove a type with no name key: both sides on Cloud Control, the create sending the old physical id EXACTLY as a `...Name` / `...Identifier` property, every such property equal to the old record's (`--replace` is opted into, a rollback's delete is not). It runs BEFORE the Retain and no-flag refusals, which presume the holder and advise `--replace`. Anything undecidable refuses (a record and a read-back naming the holder differently included, both directions), per-type tables are read by OWN key only, and nothing may be folded that could name two resources (case outside `CASE_INSENSITIVE_NAME_TYPES`, an ARN against a bare scope). Values are masked BEFORE `displayIdent` renders them. A generated name counts only for a type whose SDK provider was audited to mint `applyDefaultNameForFallback`'s name verbatim (`GENERATED_NAME_VERBATIM`, a pinned literal); any other type ignores it, except one in `DERIVED_GENERATED_NAMES` (deploy only) — a provider wrapping its own `generateResourceName` call, derived in the caller's scope and pinned to the provider's create expression. A type whose SDK provider sends `generateResourceNameWithFallback` even for an EXPLICIT name (`SENT_NAME_REWRITTEN`: IAM, ELBv2) never trusts a recorded name: the sent name is derived in the caller's async scope (stack name, prefix flag) and proven only by the new physical id; the rollback runs that proof, the re-create and an in-place revert under the flag whose derived name reproduces the OLD physical id (`replayPrefixChoice`, #4024), since an earlier deploy may have created it under the other one; the table is fenced against the generator's callers in `src/`. Name keys are fenced against the create-only snapshot: a type with a name-shaped create-only property needs a key or a `NOT_NAME_KEYED_TYPES` entry.
- **dag-executor.ts** - event-driven DAG dispatcher: a resource starts as soon as its deps complete; no level barriers.
- **delete-outcome.ts** - shared `ResourceDeleteResult` helpers; must stay an import-free LEAF ([delete-outcome.md](delete-outcome.md)).
- **work-graph.ts** - DAG orchestrator for asset publishing and stack deployment.
- **resource-secrets-scope.ts** - `AsyncLocalStorage` holding a parent's resolved secret PAIRS around a provider CREATE/UPDATE call. ALS rather than a `CreateContext` field, since a plaintext-keyed bag on the shared context makes every provider a leak site ([providers.md](providers.md)). ABSENT reads as `undefined`. It also installs the logger's sink masker (`src/utils/log-line-masker.ts`). **A reader MUST NOT enumerate or log its KEYS.**
- **prior-attempt-scope.ts** - ALS carrying the rollback journal's bags for the logical id a CREATE/UPDATE dispatch is provisioning, read LAZILY by a provider that cannot tell its own leftover from another owner's identical resource (the `SecurityGroupIngress` duplicate arm, [#4355](https://github.com/go-to-k/cdkd/issues/4355)). ABSENT, another id's, or an unreadable journal is NO evidence, never "attempted". `markRefusedBeforeApplying` makes `execute.ts` journal a refused op without its attempted bag, or the refusal becomes the next deploy's evidence — mark only on PROOF nothing was applied (an unknown failure keeps its bag), and `isRefusedBeforeApplying` stops at a link naming another logical id, so a nested child's mark never strips its parent row.
- **producer-regions-scope.ts** - ALS carrying a stack's producer-region evidence to its nested child ([#4174](https://github.com/go-to-k/cdkd/issues/4174)), bound by the deploy engine and both replay entries. ABSENT is INCOMPLETE, never empty: every region-less secret reference refuses.
- **rollback-executor.ts** - one engine for in-process automatic rollback and `cdkd rollback` ([#1183](https://github.com/go-to-k/cdkd/issues/1183)). `replayRollback` runs UPDATE/DELETE in reverse completion order, then CREATE deletions dependency-sorted; best-effort and idempotent. Its helpers live in `rollback-executor/*.ts` (#4426), in the STRICT `integ-destroy` scope.
  - A replacement op (`previousState.physicalId !== op.physicalId`, OR a changed `Type`) is reverted by REVERSING it: re-create the old resource via its recorded `provisionedBy` route, then delete the new one. **A replacement has TWO types** ([#2668](https://github.com/go-to-k/cdkd/issues/2668)): everything aimed at the OLD resource routes on the state record's type (`oldResourceType` in the engine, `resolveReplacementOldType(op)` in the replay, which REFUSES rather than falling back to `op.resourceType`), everything aimed at the new one on the template's; an equal physical id across two types is two resources, and so is one across two Glue tables whose recorded `DatabaseName`s both anchor the id and differ (`equalIdNamesDifferentResources`, [#3892](https://github.com/go-to-k/cdkd/issues/3892)). Both create arms pass `CreateContext.replayingState: true` via the shared `REPLAYING_STATE_CREATE_CONTEXT` — the ONLY sites that may declare a state replay, so a provider PRE-FLIGHT REFUSAL downgrades to a warning there ([rollback-replay-create.md](rollback-replay-create.md)).
  - Providers that re-create inside their own `update()` pass no `replayingState` (at most the masker): **such a provider must not carry a create-side pre-flight refusal**.
  - If the deploy RETAINED the old resource (verdict `CompletedOperation.oldResourceRetained`, NOT re-derived from `previousState.updateReplacePolicy`): re-adopt it and do NOT delete the new copy.
  - A rolled-back CREATE's CURRENT record `DeletionPolicy` governs its delete: `Retain` ORPHANS it; `Snapshot` uses the `prepareFinalSnapshotForDelete` matrix unless `skipFinalSnapshot`; `RetainExceptOnCreate`/`Delete` delete plainly, and absent takes CloudFormation's default via `effectiveDeletionPolicy` (`Snapshot` for an RDS cluster or standalone instance, #4030).
  - The three reverse-replacement refusals (unroutable old type, unproven name holder, Retain-pinned new copy) end on `orphanRemedy`'s labelled `To orphan it:` line — except inside a nested child's revert (`RollbackExecutorContext.nestedChildRevert`, set only by `revertNestedChildFromJournal`), where no `--orphan` reaches the replay and they print none ([#3845](https://github.com/go-to-k/cdkd/issues/3845)), and in a nested child engine's OWN rollback (`nestedChildStack`, set by a `DeployEngine` with `parentStackInfo`) the command names the child stack, since only a rollback of the child honours `--orphan` for its ops ([#3859](https://github.com/go-to-k/cdkd/issues/3859)) — and the per-op `Rollback failed for` log renders those three per line (`rollbackFailureText`), keyed on the error OBJECT (`OWN_REMEDY_ERRORS`) and never on its code — the `deployment/deploy-engine/update-*.ts` arms and `deployment/deploy-engine/replacement.ts` throw `NAMED_REPLACEMENT_COLLISION` with raw text — while every other error is flattened whole — a newline in free-form text is the line forgery `displaySafe` removes ([#3092](https://github.com/go-to-k/cdkd/issues/3092)).
  - **Every line, error, retry line and event reason a replay renders goes through the op's `createOpMasker` mask**, never a bare `maskSecretsInText(..., secrets)`: a physical id can spell a secret-derived name the literal mask misses (a rewriting provider's derivation, or a record whose name is still a reference), and `addNamed` adds those spellings after each resolution ([#4037](https://github.com/go-to-k/cdkd/issues/4037)). A helper that logs on the op's behalf (the final-snapshot lines) takes a logger routed through it too. An event's `physicalId` FIELD stays exact, and an own refusal's `--orphan` line stays outside the mask.
  - **A replayed `{{resolve:...}}` reference resolves in the region it NAMES, not the stack's.** `classifyReplaySecretRegion` throws `ROLLBACK_SECRET_REGION_AMBIGUOUS` BEFORE any lookup when the reference is region-less AND state records a foreign producer region. `DeployEngine` supplies the UNION of the pre-deploy snapshot and this session's recorded reads, since the snapshot alone lacks the read the FAILING deploy introduced.
- **retryable-errors.ts** - transient-error classifier and a zero-import graph leaf, so `error-handler.ts` can import it without a cycle. Its message tables fold into ONE exported `RETRYABLE_ERROR_MESSAGE_PATTERNS`, so a misfiled pattern changes CADENCE, not retryability. `isTransientServerError` walks a SEPARATE status set (500/502/503/504): **do not widen `RETRYABLE_HTTP_STATUS_CODES`**, whose callers want a throttle-only classifier.
  - Name-collision predicates: [name-collision-classification.md](name-collision-classification.md). `isNameCooldownError` stays SEPARATE from the collision matcher, since a cooldown at a create-first site must not trigger delete-new-first.
  - `isUpdateUnsupportedError(error, logicalId)` means "this type has no UPDATE handler at all", not "this update was rejected", and triggers replacement. **The `logicalId` anchor bounds the cause walk**, since `NestedStackProvider.update` runs a child deploy inside the parent's `update()`.
  - `isMarkedNonRetryable` is consulted BEFORE any message heuristic, since classifiers match by SUBSTRING. Mark at the `throw` when only that raising is non-retryable, in the CONSTRUCTOR when the class refuses in every case. Marking is NOT the default for a deliberate refusal.
- **retry.ts** - THREE schedules picked per attempt from the error class: generic, DENSE (`IAM_PROPAGATION_*`) and LONGER (`NAME_COOLDOWN_*`). Special grids apply ONLY on the default schedule: any explicit retry option means the caller owns the cadence verbatim.
  - A give-up emits ONE `warn` line, not `debug`, because an exhausted retry rethrows the RAW AWS error; the note keys on the loop's exit condition (`sawPropagation && attempt >= attemptLimit`), NOT the retry count.
  - Once an attempt fails with an auxiliary-marked or ambiguous-outcome error, every error the call throws carries the auxiliary mark and the `markReplayMayCollide` stamp ([#3972](https://github.com/go-to-k/cdkd/issues/3972), [#3978](https://github.com/go-to-k/cdkd/issues/3978), [name-collision-classification.md](name-collision-classification.md)). Armed for every caller; on the UPDATE path it can withhold the `UnsupportedActionException` auto-replacement (a re-run replaces).
  - `RetryLogger.warn` is OPTIONAL because `drift.ts`'s revert threads a MASKING logger; a required `warn` would be satisfied by an unmasked `logger.warn`.
