# src/deployment

Secrets: [layout-deployment-secrets.md](layout-deployment-secrets.md). Index: [code-layout.md](code-layout.md).

- **deploy-engine.ts** - orchestration. `redactedAttributeReads` entries are STRUCTURED (`kind`/`logicalId`/`key`/`display`) and the bag's PRESENCE is the opt-in letting `refStateLookupFromResource` skip a masked leaf, so only the PROVISIONING sites pass one, never the deploy-internal diff context ([#2847](https://github.com/go-to-k/cdkd/issues/2847)).
- **`DeployEngineOptions.inheritedSecrets`** - seeds a nested child's redaction, recorded AT RESOLUTION TIME and COUPLED to `diff-recursive.ts`'s `skipDynamicReferences: true`. Only the child's DIFF context binds a redacted parameter bag; PROVISIONING and CONDITION-EVALUATION keep real values, since an expression inside `Fn::Equals` flips a condition.
- **drain-budget.ts** - REMAINING wait, not a deadline. Lock-holding loops wrap in `withSharedDrainBudget`; condition evaluation keeps a budget PER CONDITION.
- **outputs-export-alias.ts** - key-space rules for the OUTPUTS bag (#1919). `state.outputs` is keyed by output NAME; an `Export:`-carrying output is ALSO aliased under its export name in the SAME bag, beside a parallel POSITION-source bag of unresolved template values. ONE module, four writers, but **deploy and scrub deliberately do NOT share every rule**: a condition-suppressed output publishes no value and does NOT reserve its name, while scrub ignores conditions and over-approximates.
- **dag-executor.ts** - event-driven DAG dispatcher: a resource starts as soon as its deps complete; no level barriers.
- **delete-outcome.ts** - shared `ResourceDeleteResult` helpers; must stay an import-free LEAF ([delete-outcome.md](delete-outcome.md)).
- **work-graph.ts** - DAG orchestrator for asset publishing and stack deployment.
- **resource-secrets-scope.ts** - `AsyncLocalStorage` holding a parent's resolved secret PAIRS around a provider CREATE/UPDATE call. ALS rather than a `CreateContext` field, since a plaintext-keyed bag on the shared context makes every provider a leak site ([providers.md](providers.md)). ABSENT reads as `undefined`. **A reader MUST NOT enumerate or log its KEYS.**
- **rollback-executor.ts** - one engine for in-process automatic rollback and `cdkd rollback` ([#1183](https://github.com/go-to-k/cdkd/issues/1183)). `replayRollback` runs UPDATE/DELETE in reverse completion order, then CREATE deletions dependency-sorted; best-effort and idempotent.
  - A replacement op (`previousState.physicalId !== op.physicalId`, OR a changed `Type`) is reverted by REVERSING it: re-create the old resource via its recorded `provisionedBy` route, then delete the new one. **A replacement has TWO types** ([#2668](https://github.com/go-to-k/cdkd/issues/2668)): everything aimed at the OLD resource routes on the state record's type (`oldResourceType` in the engine, `resolveReplacementOldType(op)` in the replay, which REFUSES rather than falling back to `op.resourceType`), everything aimed at the new one on the template's; an equal physical id across two types is two resources. Both create arms pass `CreateContext.replayingState: true` via the shared `REPLAYING_STATE_CREATE_CONTEXT` — the ONLY sites that may declare a state replay, so a provider PRE-FLIGHT REFUSAL downgrades to a warning there ([rollback-replay-create.md](rollback-replay-create.md)).
  - Providers that re-create inside their own `update()` get no `CreateContext`: **such a provider must not carry a create-side pre-flight refusal**.
  - If the deploy RETAINED the old resource (verdict `CompletedOperation.oldResourceRetained`, NOT re-derived from `previousState.updateReplacePolicy`): re-adopt it and do NOT delete the new copy.
  - A rolled-back CREATE's CURRENT record `DeletionPolicy` governs its delete: `Retain` ORPHANS it; `Snapshot` uses the `prepareFinalSnapshotForDelete` matrix unless `skipFinalSnapshot`; `RetainExceptOnCreate`/absent/`Delete` delete plainly.
  - **A replayed `{{resolve:...}}` reference resolves in the region it NAMES, not the stack's.** `classifyReplaySecretRegion` throws `ROLLBACK_SECRET_REGION_AMBIGUOUS` BEFORE any lookup when the reference is region-less AND state records a foreign producer region. `DeployEngine` supplies the UNION of the pre-deploy snapshot and this session's recorded reads, since the snapshot alone lacks the read the FAILING deploy introduced.
- **retryable-errors.ts** - transient-error classifier and a zero-import graph leaf, so `error-handler.ts` can import it without a cycle. Its message tables fold into ONE exported `RETRYABLE_ERROR_MESSAGE_PATTERNS`, so a misfiled pattern changes CADENCE, not retryability. `isTransientServerError` walks a SEPARATE status set (500/502/503/504): **do not widen `RETRYABLE_HTTP_STATUS_CODES`**, whose callers want a throttle-only classifier.
  - Name-collision predicates: [name-collision-classification.md](name-collision-classification.md). `isNameCooldownError` stays SEPARATE from the collision matcher, since a cooldown at a create-first site must not trigger delete-new-first.
  - `isUpdateUnsupportedError(error, logicalId)` means "this type has no UPDATE handler at all", not "this update was rejected", and triggers replacement. **The `logicalId` anchor bounds the cause walk**, since `NestedStackProvider.update` runs a child deploy inside the parent's `update()`.
  - `isMarkedNonRetryable` is consulted BEFORE any message heuristic, since classifiers match by SUBSTRING. Mark at the `throw` when only that raising is non-retryable, in the CONSTRUCTOR when the class refuses in every case. Marking is NOT the default for a deliberate refusal.
- **retry.ts** - THREE schedules picked per attempt from the error class: generic, DENSE (`IAM_PROPAGATION_*`) and LONGER (`NAME_COOLDOWN_*`). Special grids apply ONLY on the default schedule: any explicit retry option means the caller owns the cadence verbatim.
  - A give-up emits ONE `warn` line, not `debug`, because an exhausted retry rethrows the RAW AWS error; the note keys on the loop's exit condition (`sawPropagation && attempt >= attemptLimit`), NOT the retry count.**
  - `RetryLogger.warn` is OPTIONAL because `drift.ts`'s revert threads a MASKING logger; a required `warn` would be satisfied by an unmasked `logger.warn`.
