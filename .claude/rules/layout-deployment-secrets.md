# Key files - secret redaction and masking

Deployment layer: [layout-deployment.md](layout-deployment.md). Index: [code-layout.md](code-layout.md).

## Important Files

- **src/deployment/secret-redaction.ts** - Redaction for resolved dynamic references. A LEAF module: it imports nothing, which is why the resolver's SecureString verdict store is homed here.
  - Secret-ness is decided by the RESOLVER, by TYPE not spelling: every `{{resolve:secretsmanager:...}}`, plus a `{{resolve:ssm:...}}` whose parameter is a `SecureString`. A `String` / `StringList` is public config and stays RESOLVED in state, or every parameter-backed property becomes a perpetual spurious UPDATE.
  - The verdict lives in the process-global `recordedSecretExpressions` (cleared by `resetAccountInfoCache`), keyed by SPELLING rather than the resolver's `isSecret`. `cachedDynamicReferences` instead lives on the RESOLVER INSTANCE, one per stack and region, each entry carrying the verdict that produced it.
  - Lookups are REGION-PINNED via `clientsForRegion` unless the ambient clients are PROVEN to point at the resolver's region — "unknown" means SCOPE, not skip. PROVEN is `AwsClients.configuredRegion`; a lazy service getter cannot answer while `switchRegion` mutates `AWS_REGION`. A template-derived region is further gated by `isClientSafeRegion`.
  - Exports `RecordedSecretValues` (`Map<plaintext, expression>`), `redactSecretsForState(bag, secrets, source?)`, `scrubResourceRecord` and `maskSecretsInText`. The RESOLVER owns the masking answer, `maskSecretsRaw` (the `maskSecretsForLog` name is GONE, go-to-k/cdkd#3426), which masks `context.inheritedSecrets` FIRST — a nested-stack child holds the parent-decrypted plaintext only in that bag — and which **NO-OPS, silently, against an absent or empty bag**, so a call site that lost its bag still reads as masked.
  - **A RESOLVER log line renders through the `displayMasked(value, context)` builder, never through `maskSecretsRaw` directly or through a local binding of it** (go-to-k/cdkd#3408, #3426). The raw masker answers only "does this contain a recorded secret", so rendering its result leaves the value masked but NOT control-stripped, and a template-supplied name could redraw a terminal. Enforced two ways: `tests/unit/deployment/resolver-display-masked-population.test.ts` asserts from the AST that `maskSecretsRaw` and the strip-and-mask composition each have ONE caller, and `scripts/check-resolver-mask-coverage.ts` resolves an interpolated identifier to its declaration — `MASKERS` there means "masks AND sanitizes", `RAW_MASKERS` is the other side, and a render reaching a raw masker is reported with the builder as the remedy (an exclusion marker cannot silence that verdict). The walk is deliberately `isMasked`'s dual and no wider: callback / literal / spread / `await` arms were withdrawn as defective, so those shapes take the annotatable verdict and the containment fence covers them.
  - Every mask is BOUNDED — `maskSecretsInText` matches LITERALLY, so a truncated or re-encoded plaintext, or one under `MIN_NEEDLE_LENGTH`, is not masked. A boundary mask needs BOTH halves: HOIST the bag above the `try` so the `catch` can name it, then MASK. Close a bag gap at the CALLEE by inventing a private map; per-sink and per-caller fixes each leave the next one open.
  - Concurrent resolutions DRAIN before a rejection surfaces, BOUNDED by one cap per resolution (`allSettledKeepingFirstRejection` in `src/deployment/intrinsic-function-resolver.ts`).
  - `maskSecretsInError` clones EVERY link in the `cause` CHAIN, so an identity return means nothing ANYWHERE changed. Each clone copies the prototype and every own DESCRIPTOR (symbols included) so `markNonRetryable`'s marker, `$metadata` / `Code` / `name` survive the retry classifiers; `cause` is rewired in a SECOND pass with a visited set and depth cap, which is what terminates a cyclic chain.
  - **Redaction is BOTH path-based and value-based.** Where the SOURCE bag's leaf is a `{{resolve:...}}` string it is persisted VERBATIM. Position is what the value map cannot supply: keyed by plaintext, two expressions with the SAME value collapse onto the survivor. The value scan covers what the source cannot position, and runs with an EMPTY map too — the point for an UNCHANGED resource, whose capture refresh would otherwise persist plaintext.
  - `positionByEmbeddedSpan` positions a LITERAL leaf EMBEDDING one token by the span its source states, gated on PASS-LOCAL evidence (`recordResolvedPair`) plus, unless the bag's generation is proven by `markSameGenerationBag`, equivalence with the value scan's answer.
  - `positionByIntrinsicSkeleton` positions `Fn::Join` / `Fn::Sub` leaves and persists only when the leaf's WHOLE value is a recorded plaintext, EXACTLY ONE candidate matches, and the match is not demonstrably another value's expression; refusals fall to `positionByIntrinsicFrame`, then the value scan.
  - `positionByCrossStackSource` handles `Fn::ImportValue` / `Fn::GetStackOutput`, which carry no text for a skeleton to match. `reresolveCrossStackValue` records `canonicalKey -> expression` into `recordedCrossStackExpressions`; `crossStackSourceKey` is computed by BOTH sides over the RAW intrinsic, NUL-separated, so the keys agree BY CONSTRUCTION — deriving one from RESOLVED names is not equivalent.
  - **That key is NOT unique per producer**, so safety comes from SCOPE: the associations live in a `WeakMap` keyed by the pass's own bag. Plaintext PAIRING remains the in-pass misalignment guard, and a key recorded against a different (expression, plaintext) pair is POISONED rather than overwritten. `recordCrossStackExpression` refuses an expression that is not a whole token, since the reader RETURNS it to be persisted.
  - **`PathSourceRules` gates which source leaves may be persisted; all three flags matter.** `descendArrays` follows the BAG's provenance (a resolved bag walks positionally, an AWS readback may be REORDERED) and first tries a KEYED descent by identity field, uniqueness required on BOTH sides, refusing the WHOLE array rather than mis-pairing. `trustAnyExpression` follows the SOURCE's: a TEMPLATE also carries PUBLIC ssm expressions, so only a KNOWN secret is substituted there. `sourceIsSameGeneration` is TRUE only for the three state-sourced constants — every template-sourced one is FALSE, since a record can still be on the PREVIOUS generation.
  - The substring arm spares COMPLETE tokens through ONE predicate: replace every recorded-plaintext match except one lying STRICTLY INSIDE a `{{resolve:...}}` span.
  - `refuseUncertifiedReadbackPositions` closes the MIXED-leaf row on every empty-map readback path and lives INSIDE `redactSecretsForState`, so `state refresh-observed`, `import`'s observed capture and a plain deploy inherit it. Gated on `trustAnyExpression && !descendArrays && sourceIsSameGeneration`; `unkeyedArrayPairsByAnchors` licenses a positional walk only under its four anchor conditions, and `deriveReadbackNeedles` runs only on an EMPTY map.
  - The walk FAILS CLOSED where it cannot certify, for a caller that DECLARES its bag a drift baseline (`STATE_SOURCED_BASELINE_RULES`); destination is not derivable here, so `import` and `drift.ts` declare it. `scrubResourceRecord` DERIVES it on TWO conditions — empty secrets map AND a generation-marked observed bag — since an empty map alone also describes a failure-path save over a PRIOR generation, where a mask destroys an intact baseline.
  - A MIXED leaf embedding a plain `{{resolve:ssm:` token splits on whether a SECRETS MAP exists: with one, absence from the verdict store is evidence the parameter is PUBLIC; with an EMPTY map nothing could have been recorded, so it fails closed.
  - The rollback JOURNAL is the consequential writer, since `resolveReplayProps` re-resolves it against AWS: `properties` / `attemptedProperties` take the TEMPLATE bag, `previousState` positions through `scrubResourceRecord` with no source. Other position-source writers: stack OUTPUTS (one `redactOutputs` helper, `TEMPLATE_SOURCED_RULES`), `cdkd scrub` (`STATE_SOURCED_CROSS_GENERATION_RULES`, since it repositions `properties` onto TODAY's template first), `cdkd import`, `redactRollbackRecord`, `state refresh-observed`.

- **The MASK-ONLY needle class** is the third kind of entry a bag can hold and the first with NO expression behind it: a custom resource declaring its `Data` sensitive with `NoEcho: true` yields a HANDLER-GENERATED value, so `SECRET_MASK` is persisted.
  - `recordMaskOnlyValue` writes `plaintext -> SECRET_MASK` into the SAME map, so every persistence reader already walks it; the SENTINEL VALUE is the marker and the per-pass map is the scope. `recordMaskOnlyValuesIn` takes an `excluded` set of the resource's own whole string leaves, so a handler echoing `ResourceProperties` cannot mask cdkd's own `ServiceToken` out of the record. `carriesSecretMask` is UNBOUNDED in depth, symmetric with the walk that WRITES the mask.
  - A mask-only needle must clear `MIN_NEEDLE_LENGTH`, which the expression class need not, and the classes MUST differ in the SUBSTRING arm: `substringNeedlesOf` excludes the mask class, so a mask only ever takes a leaf WHOLE — an inline `***` is indistinguishable from a user's literal, and `drift --revert` would push the corrupted string to AWS.
  - `ResourceState` carries no durable `NoEcho` flag, so a later deploy reads `***` back: `ResolverContext.redactedAttributeReads` collects such reads and `refuseRedactedAttributeReads` fails the resource rather than sending the mask. It RECORDS rather than throws, because the DIFF pass resolves the same leaf and a throw would fail every later deploy. Other readers: `drift.ts`, `refuseMaskedReplayBaseline`, `export.ts`.
  - The CROSS-STACK half is a RECOVERY, not a refusal: `recordRecoverableMaskedOutput` / `recoverMaskedOutput` remember `stack + region + output key -> plaintext` for the PROCESS; a hit is re-registered as a mask-only needle in the CONSUMER's bag, a miss refuses. The key is a COORDINATE, never a bare plaintext, and recovered outputs are reported PER ATTRIBUTE, or one sensitive child output would mask every sibling.

- **src/deployment/masking-retry-logger.ts** - The masking `RetryLogger` every `withRetry` caller holding a RESOLVED secret bag threads, since `retry.ts` interpolates the AWS message VERBATIM into both its `debug` line and its give-up `warn` summary. `RetryLogger.warn` is OPTIONAL because a required one would be silently satisfied by a raw `logger.warn`. A separate module because `secret-redaction.ts` is a no-import LEAF. `DeployEngine.maskingRetryLogger` keeps a LAZY variant for call sites holding no bag; every site that DOES hold one binds it eagerly.

- **src/cli/commands/scrub.ts** - `cdkd scrub [STACK...]`, the permanent state secret-hygiene command. Full entry in [layout-scrub.md](layout-scrub.md).

- **src/deployment/secret-region-classification.ts** - The ONE answer to "which region must answer for this `{{resolve:...}}` reference", shared by the deploy resolver, `cdkd scrub`, `cdkd drift` and the rollback replay. `classifyReplaySecretRegion` returns `local` (non-secret services, same-region ARNs, and any name-form reference with no foreign producer region on record), `named-region` (an `arn:` naming another region) or `ambiguous` (name form AND a foreign producer region — refuse). `producerRegionsFromState` derives the evidence from `state.imports[].sourceRegion` + `outputReads[].sourceRegion`. Deliberately a LEAF, not a general region-utilities module: a second spelling is how two commands come to disagree. `rollback-executor.ts` re-exports every name.
  - A consumer supplying the evidence owes TWO things: pass `ResolverContext.producerRegions`, AND let the refusal survive its own error handling — `cdkd scrub` wraps each pass in a best-effort `catch`, so it re-raises `DynamicReferenceRegionAmbiguousError` by cause-chain walk. Conversely a REGION-PINNED sibling must NOT inherit the evidence (`siblingContext` strips it), since `producerRegions` describes the CONSUMER's reads.

- **src/provisioning/masked-retry-logger.ts** - The `RetryLogger` a provider hands to `withRetry` when its payload carries template-derived values: `createMaskedRetryLogger` routes BOTH `debug` and `warn` through the masker, `maskerOrIdentity` defaults an absent masker to identity per the `SecretMaskingContext` contract. A provider receives the masking CAPABILITY (`CreateContext.maskSecrets` / `UpdateContext.maskSecrets`), never the bag, so this stays a LEAF with only a type-only import.
  - Masking the retry logger is NOT sufficient: `withRetry` rethrows the RAW error and a NON-retryable rejection emits no retry log at all, so each provider must ALSO mask `error.message` where it wraps the failure in a `ProvisioningError`. Mask the RAW `error.message`, not the assembled sentence — only the raw value reaches `maskSecretsInText`'s whole-value arm — and thread `cause` UNMASKED so `isRetryableTransientError`'s `$metadata` walk still classifies.
