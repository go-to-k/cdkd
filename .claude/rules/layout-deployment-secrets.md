# Key files - secret redaction and masking

Deployment layer: [layout-deployment.md](layout-deployment.md).

- **src/deployment/secret-redaction.ts** - Redaction for resolved dynamic references, a barrel over `secret-redaction/*.ts`. A LEAF family (imports nothing else), so the resolver's SecureString verdict store lives here.
  - Secret-ness is decided by the RESOLVER, by TYPE not spelling: every `{{resolve:secretsmanager:...}}`, plus a `{{resolve:ssm:...}}` whose parameter is a `SecureString`. A `String` / `StringList` is public config and stays RESOLVED in state, else every parameter-backed property is a perpetual spurious UPDATE.
  - The verdict lives in the process-global `recordedSecretExpressions` (cleared by `resetAccountInfoCache`), keyed by SPELLING, not the resolver's `isSecret`; `isKnownSecret` reads its region+identity SCOPED half (#4105). `cachedDynamicReferences` is per RESOLVER INSTANCE (one per stack and region), each entry carrying its verdict.
  - Lookups are REGION-PINNED via `clientsForRegion` unless the ambient clients are PROVEN to point at the resolver's region — "unknown" means SCOPE, not skip. PROVEN is `AwsClients.configuredRegion`; a lazy getter cannot answer while a per-stack switch mutates `AWS_REGION`. A template-derived region is gated by `isClientSafeRegion`.
  - Exports `RecordedSecretValues` (`Map<plaintext, expression>`), `redactSecretsForState(bag, secrets, source?)`, `scrubResourceRecord` and `maskSecretsInText`. The RESOLVER owns the masking answer, `maskSecretsRaw`: it masks `context.inheritedSecrets` FIRST — a nested-stack child holds the parent-decrypted plaintext only in that bag — and **NO-OPS, silently, against an absent or empty bag**, so a call site that lost its bag still reads as masked.
  - **A RESOLVER log line renders through the `displayMasked(value, context)` builder, never through `maskSecretsRaw` or a local binding of it**. The raw masker answers only "does this contain a recorded secret", so its result is masked but NOT control-stripped, and a template-supplied name could redraw a terminal. `resolver-display-masked-population.test.ts` asserts from the AST that `maskSecretsRaw` and the strip-and-mask composition each have ONE caller.
  - Every mask is BOUNDED — `maskSecretsInText` matches LITERALLY, so a truncated or re-encoded plaintext, or one under `MIN_NEEDLE_LENGTH`, is not masked. A boundary mask needs BOTH halves: HOIST the bag above the `try` so the `catch` can name it, then MASK. Close a bag gap at the CALLEE.
  - Concurrent resolutions DRAIN before a rejection surfaces, BOUNDED by one cap per resolution (`allSettledKeepingFirstRejection`); a nested drain passes its CAPTURE order up, so the earliest CAPTURE wins at any depth (bounds in its JSDoc).
  - `maskSecretsInError` clones EVERY link in the `cause` CHAIN, so an identity return means nothing ANYWHERE changed. Each clone copies the prototype and every own DESCRIPTOR (symbols included), so `markNonRetryable`'s marker and `$metadata` / `Code` / `name` survive the retry classifiers, each other DATA value masked into a COPY through plain objects / arrays, the classifiers' exact-match string fields (`CLASSIFIER_IDENTIFIER_FIELDS`) excepted; `cause` is rewired in a SECOND pass, whose visited set and depth cap terminate a cyclic chain.
  - **Redaction is BOTH path-based and value-based.** Where the SOURCE bag's leaf is a `{{resolve:...}}` string it is persisted VERBATIM. Position is what the value map cannot supply: keyed by plaintext, two expressions with the SAME value collapse onto the survivor. The value scan covers what the source cannot position and runs with an EMPTY map too — the point for an UNCHANGED resource, whose capture refresh would otherwise persist plaintext.
  - Positioners refuse rather than guess. `positionByEmbeddedSpan` takes a LITERAL leaf EMBEDDING one token by the span its source states, gated on PASS-LOCAL evidence (`recordResolvedPair`) plus — unless `markSameGenerationBag` proves the bag's generation — equivalence with the value scan. `positionByIntrinsicSkeleton` takes `Fn::Join` / `Fn::Sub` leaves and persists only if the leaf's WHOLE value is a recorded plaintext, EXACTLY ONE candidate matches, and the match is not provably another value's expression; refusals fall to `positionByIntrinsicFrame`, then the value scan. `positionByCrossStackSource` handles `Fn::ImportValue` / `Fn::GetStackOutput` (no text to match): BOTH sides compute `crossStackSourceKey` over the RAW intrinsic (NUL-separated), so keys agree BY CONSTRUCTION, unlike RESOLVED names. `positionByParameterPlaceholders` (before the skeleton), the persist twin of `redactParametersForDiff` (#2320), answers each parameter `Ref` and embedded cross-stack read in an `Fn::Sub` / `Fn::Join` (or an `Fn::If` selecting one) from its association, at the spans the RESOLVER recorded (`parameterSpans`, keyed by `crossStackSourceKey`, #4446/#4527) or else where the template reassembles the leaf (#2298); a pass moving text after recording must drop its spans.
  - **That key is NOT unique per producer**, so safety comes from SCOPE: `reresolveCrossStackValue` records `canonicalKey -> expression` into a `WeakMap` keyed by the pass's own bag. Plaintext PAIRING remains the in-pass misalignment guard, and a key recorded against a different (expression, plaintext) pair is POISONED rather than overwritten. `recordCrossStackExpression` refuses an expression that is not a whole token, since the reader RETURNS it to be persisted.
  - **`PathSourceRules` gates which source leaves may be persisted; all three flags matter.** `descendArrays` follows the BAG's provenance (a resolved bag walks positionally, an AWS readback may be REORDERED) and first tries a KEYED descent by identity field, uniqueness required on BOTH sides, refusing the WHOLE array rather than mis-pairing. `trustAnyExpression` follows the SOURCE's: a TEMPLATE also carries PUBLIC ssm expressions, so only a KNOWN secret is substituted there. `sourceIsSameGeneration` is TRUE only for the state-sourced constants — a template-sourced record can be on the PREVIOUS generation.
  - The substring arm has ONE predicate: replace every recorded-plaintext match except one STRICTLY INSIDE a `{{resolve:...}}` span of a RESOLVABLE service (#2743).
  - `refuseUncertifiedReadbackPositions` closes the MIXED-leaf row on every empty-map readback path and lives INSIDE `redactSecretsForState`, so `state refresh-observed`, `import`'s observed capture and a plain deploy inherit it. Gated on `trustAnyExpression && !descendArrays && sourceIsSameGeneration`; `unkeyedArrayPairsByAnchors` licenses a positional walk only under its anchor conditions, `deriveReadbackNeedles` only on an EMPTY map.
  - The walk FAILS CLOSED where it cannot certify, for a caller that DECLARES its bag a drift baseline (`STATE_SOURCED_BASELINE_RULES`): destination is not derivable here, so `import` and `drift.ts` declare it, while `scrubResourceRecord` DERIVES it on TWO conditions — an empty secrets map AND a generation-marked observed bag — since an empty map alone also describes a failure-path save over a PRIOR generation, where a mask destroys an intact baseline. Same split for a MIXED leaf embedding a plain `{{resolve:ssm:` token: WITH a map, absence from the verdict store proves the parameter PUBLIC; with an EMPTY one nothing could have been recorded, so it fails closed.
  - The deploy-start RE-CAPTURE of a masked baseline ([#3595](https://github.com/go-to-k/cdkd/issues/3595), `masked-baseline-recapture.ts`) resolves the record's own references into a map of ITS OWN — never `perResourceSecrets`, which would move that record's persist walk off the fail-closed rules — and changes only `***` leaves, each to a reference `properties` spells. Its bag is installed UNMARKED.
  - The rollback JOURNAL is the consequential writer, since `resolveReplayProps` re-resolves it against AWS: `properties` / `attemptedProperties` take the TEMPLATE bag, `previousState` positions through `scrubResourceRecord` with no source. `cdkd scrub` takes `STATE_SOURCED_CROSS_GENERATION_RULES`, since it repositions `properties` onto TODAY's template first. Derive the rest of the writer set with `grep -rn PathSourceRules src/`, never from a list here.

- **The MASK-ONLY needle class** is the one kind of entry with NO expression behind it: a custom resource declaring its `Data` sensitive with `NoEcho: true` yields a HANDLER-GENERATED value, so `SECRET_MASK` is persisted.
  - `recordMaskOnlyValue` writes `plaintext -> SECRET_MASK` into the SAME map, so every persistence reader already walks it; the SENTINEL VALUE is the marker, the per-pass map the scope. `recordMaskOnlyValuesIn` takes an `excluded` set of the resource's own whole string leaves, so a handler echoing `ResourceProperties` cannot mask cdkd's `ServiceToken` out of the record. `carriesSecretMask` is UNBOUNDED in depth, symmetric with the walk that WRITES the mask.
  - A mask-only needle must clear `MIN_NEEDLE_LENGTH`, which the expression class need not, and the classes MUST differ in the SUBSTRING arm: `substringNeedlesOf` excludes the mask class, so a mask only takes a leaf WHOLE — an inline `***` is indistinguishable from a user's literal, and `drift --revert` would push the corrupted string to AWS. A leaf CONTAINING a resolver-registered one (`containmentValuesOf`: a `NoEcho` value, a derived `Fn::Base64` needle) is flattened whole by the post-pass in `redactSecretsForState`; the custom resource's own `Data` and drift's registrations stay out of it (a `ServiceToken` would be flattened), and so does a value EQUAL to a public token (`publicNoEchoTokens`).
  - `ResourceState` carries no durable `NoEcho` flag, so a later deploy reads `***` back: `ResolverContext.redactedAttributeReads` collects such reads and `refuseRedactedAttributeReads` fails the resource rather than sending the mask. It RECORDS rather than throws, because the DIFF pass resolves the same leaf and a throw would fail every later deploy.
  - **The UPDATE arm's no-change skip does not trust a MASK** (go-to-k/cdkd#3662). It compares REDACTED bags, and a mask-only plaintext redacts to `***` on both sides, so a bag for which `carriesFreshNoEchoValue` is true — a `NoEcho` value supplied in THIS deploy, per a per-pass side set, not a DERIVED `Fn::Base64` needle — never takes the skip. The mark crosses a nested-stack parameter through `carryFreshNoEchoMark` (#3717), and the child engine tells the diff which parameters carry one. The UPDATE refusal runs AFTER that skip, since a skip sends nothing, which is what lets the diff promote a reader of a masked attribute speculatively.
  - **A create-only path holding a fresh `NoEcho` value is settled by an AWS READBACK, never by anything stored** (go-to-k/cdkd#3729). A salted hash beside the mask would be a confirm oracle for low-entropy `Data` leaves, the same one `skippedOutputs` refuses for a `NoEcho` parameter `Default`. `freshNoEchoLeafPositions` names the positions, and `DeployEngine.readReaderForFreshNoEchoCeiling` reads the reader once, routed by the RECORD and handed the MASKED record, never the resolved bag, so an echoing provider cannot confirm. Strict string equality is required at every position, and every uncertainty keeps the replacement. The readback never reaches `observedCaptureTasks`, and a failure logs only the error's `name`.
  - The CROSS-STACK half is a RECOVERY, not a refusal: `recordRecoverableMaskedOutput` / `recoverMaskedOutput` remember `credential identity + stack + region + output key -> plaintext` for the PROCESS (identity since #3691: a caller switching accounts must not get another account's plaintext); a hit is re-registered as a mask-only needle in the CONSUMER's bag, a miss refuses. The key is a COORDINATE, never a bare plaintext, and recovered outputs are reported PER ATTRIBUTE, or one sensitive child output masks every sibling.

- **The LOG-ONLY needle class** (#1998): a `NoEcho: true` PARAMETER's value and any `Fn::Split` piece or child list element's share of one (#4049), recorded by `recordLogOnlyValue` into a side set keyed by the bag INSTANCE, never the map. The PRINTING maskers (`maskSecretsInText`, `maskSecretsInError`, `createSecretMasker`) read it; anything that PERSISTS, or DECIDES what is persisted or sent, must not — a detector calls `maskRecordedSecretsInText`. A masking site's empty-bag test is `hasMaskableValues`, not `size`, a copy that later MASKS (`new Map(bag)`, an entry loop) must `carryLogOnlyValues`, and a recording VIEW over a pass map (`ForwardingSecrets`, `SharedEntriesSecrets`) must `shareLogOnlyValues` at creation, since a record can land late or on a throwing path. A printer testing a name against a MAP (the alias warnings) takes `printingCorpusOf(bag)`. ONE verdict does too: `exportNameSecretExposure` refuses an `Export.Name` holding a log-only needle, through `secretsPresentIn` over `printingCorpusOf` of the name's bag and of `noEchoParameterValueSeed` (every `NoEcho` value), by CONTAINMENT only: both are stack-wide, and counted wholesale would refuse every alias. Deploy and diff resolve EVERY name before deciding any alias (#4043). Every other publication, persistence or state-key verdict (`stateKeySecretExposure` included) reads the map alone. `ResolverContext.printingSecrets` is PRINT-ONLY: no detector, and no recording into `recordedSecretValues`, may read it (#4043).

- **src/deployment/masking-retry-logger.ts** - The masking `RetryLogger` a `withRetry` caller holding a RESOLVED secret bag threads: `retry.ts` interpolates the AWS message VERBATIM into its `debug` line and OPTIONAL give-up `warn`. `DeployEngine.maskingRetryLogger` is a LAZY variant for bagless sites. A resolver SDK call sending a template-derived name takes `namedRequestMasks`, masking that name by position (#3171).

- **src/cli/commands/scrub.ts** - `cdkd scrub [STACK...]`: [layout-scrub.md](layout-scrub.md).

- **src/deployment/secret-region-classification.ts** - The ONE answer to "which region must answer for this `{{resolve:...}}` reference", shared by the resolver, scrub, drift and the replay. `classifyReplaySecretRegion` returns `local`, `named-region` (an `arn:` naming another region) or `ambiguous` (name form AND a foreign producer region — refuse). `producerRegionsFromState` derives the evidence from the record's `imports` / `outputReads`.
  - A consumer supplying the evidence owes TWO things: pass `ResolverContext.producerRegions`, AND let the refusal survive its own error handling — `cdkd scrub` wraps each pass in a best-effort `catch`, so it re-raises `DynamicReferenceRegionAmbiguousError` by cause-chain walk. A resolution whose origin is already KNOWN must NOT inherit the evidence (`withoutProducerRegions` strips it): `producerRegions` describes the CONSUMER's reads.

- **src/provisioning/masked-retry-logger.ts** - The `RetryLogger` a provider hands to `withRetry` when its payload carries template-derived values: `createMaskedRetryLogger` routes BOTH `debug` and `warn` through the masker; `maskerOrIdentity` defaults an absent one to identity. A provider receives the masking CAPABILITY (`CreateContext.maskSecrets` / `UpdateContext.maskSecrets`), never the bag.
  - Masking the retry logger is NOT sufficient: `withRetry` rethrows the RAW error and a NON-retryable rejection emits no retry log, so each provider must ALSO mask `error.message` where it wraps the failure in a `ProvisioningError`. Mask the RAW `error.message` (only it reaches `maskSecretsInText`'s whole-value arm) and wrap via `wrapMaskedAwsError`, `cause` UNMASKED: it stamps `markRedactedCause` when the mask cut the text, so retry classifiers read the chain.
