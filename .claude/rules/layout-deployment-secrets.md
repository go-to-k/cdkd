# Key files - secret redaction and masking

Deployment layer: [layout-deployment.md](layout-deployment.md).

- **src/deployment/secret-redaction.ts** - Redaction for resolved dynamic references, a barrel over `secret-redaction/*.ts`. A LEAF family (imports nothing else), so the resolver's SecureString verdict store lives here.
  - Secret-ness is decided by the RESOLVER, by TYPE not spelling: every `{{resolve:secretsmanager:...}}`, plus a `{{resolve:ssm:...}}` whose parameter is a `SecureString`. A `String` / `StringList` is public config and stays RESOLVED in state, else every parameter-backed property is a perpetual spurious UPDATE.
  - The verdict lives in the process-global `recordedSecretExpressions` (cleared by `resetAccountInfoCache`), keyed by SPELLING, not the resolver's `isSecret`; `isKnownSecret` reads its region+identity SCOPED half (#4105). `cachedDynamicReferences` is per RESOLVER INSTANCE (one per stack and region), each entry carrying its verdict.
  - Lookups are REGION-PINNED via `clientsForRegion` unless the ambient clients PROVABLY point at the resolver's region (unknown means SCOPE). PROVEN is `AwsClients.configuredRegion`; a lazy getter cannot answer while a per-stack switch mutates `AWS_REGION`. A template-derived region is gated by `isClientSafeRegion`.
  - The RESOLVER owns the masking answer, `maskSecretsRaw`: it masks `context.inheritedSecrets` FIRST — a nested-stack child holds the parent-decrypted plaintext only in that bag — and **NO-OPS, silently, against an absent or empty bag**, so a call site that lost its bag still reads as masked.
  - **A RESOLVER log line renders through `displayMasked(value, context)`, never `maskSecretsRaw`**, which masks but does NOT control-strip. `resolver-display-masked-population.test.ts` pins each composition to ONE caller.
  - Concurrent resolutions DRAIN before a rejection surfaces (`allSettledKeepingFirstRejection`).
  - Every mask is BOUNDED: `maskSecretsInText` matches LITERALLY, missing a re-encoded plaintext or one under `MIN_NEEDLE_LENGTH`. A boundary mask HOISTS the bag above the `try`; close a bag gap at the CALLEE.
  - `maskSecretsInError` clones the WHOLE `cause` CHAIN (identity return: nothing changed), copying prototype and every own DESCRIPTOR so classifier markers survive; DATA values are masked into a COPY except `CLASSIFIER_IDENTIFIER_FIELDS` and the `markCreatedBeforeFailure` mark (#3869); `cause` is rewired in a SECOND, cycle-safe pass.
  - **Redaction is BOTH path-based and value-based.** Where the SOURCE bag's leaf is a `{{resolve:...}}` string it is persisted VERBATIM. Position is what the plaintext-keyed map cannot supply: two expressions with one value collapse. The value scan covers the rest, with an EMPTY map too (an UNCHANGED resource's capture refresh).
  - Positioners refuse rather than guess. A nested child's `{Ref: <Param>}` leaf carrying an inherited secret goes FIRST to `positionByInheritedParameter`: `redactInheritedParameterValue`, shared with `redactParametersForDiff` (#2349), failing closed to the arms below on a child-only plaintext. `positionByEmbeddedSpan` takes a LITERAL leaf EMBEDDING one token by the span its source states, or several whose source, rendered with this pass's pairs, IS the leaf (#4644), gated on PASS-LOCAL evidence (`recordResolvedPair`) plus — unless `markSameGenerationBag` proves the generation — equivalence with the value scan. `positionByIntrinsicSkeleton` persists an `Fn::Join` / `Fn::Sub` leaf only if its WHOLE value is a recorded plaintext, EXACTLY ONE candidate matches, not provably another value's expression; refusals fall to `positionByIntrinsicFrame`, then the scan. `positionByCrossStackSource` takes `Fn::ImportValue` / `Fn::GetStackOutput`: BOTH sides compute `crossStackSourceKey` over the RAW intrinsic, so keys agree BY CONSTRUCTION. `positionByParameterPlaceholders` (before the skeleton, #2320) answers each parameter `Ref` and embedded cross-stack read in an `Fn::Sub` / `Fn::Join` (or an `Fn::If` selecting one) from its association or rendered spelling (#4644), at the spans the RESOLVER recorded (`parameterSpans`, keyed by `crossStackSourceKey`, #4446/#4527) or else where the template reassembles the leaf (#2298); a pass moving text after recording must drop its spans.
  - **That key is NOT unique per producer**, so safety comes from SCOPE: `reresolveCrossStackValue` records `canonicalKey -> expression` into a `WeakMap` keyed by the pass's bag. Plaintext PAIRING remains the in-pass misalignment guard, and a key recorded against a different (expression, plaintext) pair is POISONED rather than overwritten. `recordCrossStackExpression` refuses an expression that is not a whole token, since the reader RETURNS it to be persisted.
  - **`PathSourceRules` gates which source leaves may be persisted; all three flags matter.** `descendArrays` follows the BAG's provenance (a resolved bag walks positionally, an AWS readback may be REORDERED) and first tries a KEYED descent by identity field, uniqueness required on BOTH sides, refusing the WHOLE array rather than mis-pairing. `trustAnyExpression` follows the SOURCE's: a TEMPLATE also carries PUBLIC ssm expressions, so only a KNOWN secret is substituted there. `sourceIsSameGeneration` is TRUE only for the state-sourced constants — a template-sourced record can be on the PREVIOUS generation.
  - The substring arm has ONE predicate: replace every recorded-plaintext match except one STRICTLY INSIDE a `{{resolve:...}}` span of a RESOLVABLE service (#2743).
  - `refuseUncertifiedReadbackPositions` closes the MIXED-leaf row on every empty-map readback path INSIDE `redactSecretsForState`. Gated on `trustAnyExpression && !descendArrays && sourceIsSameGeneration`; `unkeyedArrayPairsByAnchors` licenses a positional walk only under its anchor conditions, `deriveReadbackNeedles` only on an EMPTY map.
  - The walk FAILS CLOSED where it cannot certify, for a caller that DECLARES its bag a drift baseline (`STATE_SOURCED_BASELINE_RULES`): destination is not derivable here, so `import` and `drift.ts` declare it, while `scrubResourceRecord` DERIVES it on TWO conditions — an empty secrets map AND a generation-marked observed bag — since an empty map alone also describes a failure-path save over a PRIOR generation, where a mask destroys an intact baseline. A MIXED leaf embedding a plain `{{resolve:ssm:` token: WITH a map, absence from the verdict store proves it PUBLIC; with an EMPTY one only a PER-BAG proof does, and only for a readback EQUAL to the source with its proven value (#2036: the resolver's lookup, or `public-ssm-proof.ts`), never a bare store.
  - The deploy-start RE-CAPTURE of a masked baseline ([#3595](https://github.com/go-to-k/cdkd/issues/3595), `masked-baseline-recapture.ts`) resolves the record's own references into a map of ITS OWN — never `perResourceSecrets`, which would move that record's persist walk off the fail-closed rules — and changes only `***` leaves, each to a reference `properties` spells. Its bag is installed UNMARKED.
  - The rollback JOURNAL is the consequential writer, since `resolveReplayProps` re-resolves it against AWS: `properties` / `attemptedProperties` take the TEMPLATE bag, `previousState` positions through `scrubResourceRecord` with no source. `cdkd scrub` takes `STATE_SOURCED_CROSS_GENERATION_RULES`, since it repositions `properties` onto TODAY's template first. Derive the other writers with `grep -rn PathSourceRules src/`.

- **The MASK-ONLY needle class** is the one kind of entry with NO expression behind it: a custom resource declaring its `Data` sensitive with `NoEcho: true` yields a HANDLER-GENERATED value, so `SECRET_MASK` is persisted.
  - `recordMaskOnlyValue` writes `plaintext -> SECRET_MASK` into the SAME map, so every persistence reader walks it. `recordMaskOnlyValuesIn` takes an `excluded` set of the resource's own whole string leaves, so a handler echoing `ResourceProperties` cannot mask cdkd's `ServiceToken` out of the record. `carriesSecretMask` is UNBOUNDED in depth, symmetric with the walk that WRITES the mask.
  - A mask-only needle must clear `MIN_NEEDLE_LENGTH`, which the expression class need not, and the classes MUST differ in the SUBSTRING arm: `substringNeedlesOf` excludes the mask class, so a mask only takes a leaf WHOLE — an inline `***` is indistinguishable from a user's literal, and `drift --revert` would push the corrupted string to AWS. A leaf CONTAINING a resolver-registered one (`containmentValuesOf`: a `NoEcho` value, a derived `Fn::Base64` needle) is flattened whole by the post-pass in `redactSecretsForState`; the custom resource's own `Data` and drift's registrations stay out of it (a `ServiceToken` would be flattened), and so does a value EQUAL to a public token (`publicNoEchoTokens`).
  - A later deploy reads `***` back: `ResolverContext.redactedAttributeReads` collects such reads and `refuseRedactedAttributeReads` fails the resource rather than sending the mask (RECORDS, never throws: the DIFF pass resolves the same leaf). Since v11 `noEchoAttributeNames` makes a declared read exact (`declaredNoEcho`), still refused (#2449); a HELD producer's declared attribute is served per resolution through `noEchoAttributeOverrides`, matched to a value it was given this deploy, never persisted.
  - **The UPDATE arm's no-change skip does not trust a MASK** (#3662): a bag carrying a `NoEcho` value supplied in THIS deploy (a per-pass side set, not a DERIVED `Fn::Base64` needle) never takes it, unless the migration witness or a readback confirms it. The mark crosses a nested-stack parameter (`carryFreshNoEchoMark`, #3717). The UPDATE refusal runs AFTER that skip, since a skip sends nothing. A DERIVED mask takes the skip only while the record's `maskedPropertyFingerprints` (text, #4451) and `maskedPropertyInputFingerprints` (#4543) still match, as in the diff. NON-SECRET inputs are resolved, classed by PROVENANCE, never by matching a secret: a `NoEcho` parameter, a `{{resolve:...}}` reference, what reads one, a custom resource's attribute, a nested stack's output not classed clean from the assembly's TEMPLATES (never child state, or the diff pass and the arms disagree; #4565), a value whose resolution recorded a secret, and a parent-passed value the PARENT did not class clean stay as written (one it could not read is not compared).
  - **A create-only path holding a fresh `NoEcho` value is settled by an AWS READBACK, never by anything stored** (#3729): a salted hash would be a confirm oracle. `freshNoEchoLeafPositions` names the positions; `readReaderForFreshNoEchoCeiling` reads once, routed by the RECORD and handed the MASKED record, so an echoing provider cannot confirm. Strict equality at every position; for the custom-resource class every uncertainty keeps the replacement. Never reaches `observedCaptureTasks`; a failure logs only the error's `name`.
  - The CROSS-STACK half is a RECOVERY: `recordRecoverableMaskedOutput` / `recoverMaskedOutput` remember `credential identity + stack + region + output key -> plaintext` for the PROCESS (#3691); a hit is re-registered as a mask-only needle in the CONSUMER's bag, a miss refuses. The key is a COORDINATE, never a bare plaintext; recovered outputs are reported PER ATTRIBUTE.

- **A `NoEcho: true` PARAMETER (#4043, schema v11)** takes THREE arms: log-only (below), a fresh MASK-ONLY map entry (`recordNoEchoParameterFreshValue`, class set `noEchoParameterValuesOf`), and the POSITIONAL arm (`src/deployment/secret-redaction/noecho-leaves.ts`, applied by `src/deployment/deploy-engine/noecho.ts`): a leaf whose template reads the parameter (a bare declared-`NoEcho` `Fn::GetAtt` too) persists `***` whatever its type or length, named in `noEchoLeaves`. The comparison side masks alike. The PARAMETER class is settled by a readback whatever the property's class; a create-only one is replaced only where `noEchoExactEchoLeaves` proves an exact echo (#4656), else warns, a failed read fails it. A nested child positions each parameter its parent's row fills from a `NoEcho` source as one (`recordPassedNoEchoParameters` on the row's bag, read into `inheritedNoEchoParameters`). A rollback REVERT of a marked leaf (`src/deployment/rollback-executor/replay-noecho.ts`) reads AWS's value through the live record MASKED at those coordinates and sends that, never `***`; the value is a mask-only and log-only needle of the op, and the restored record is re-masked BY POSITION, since the value arm misses a number or a short value.

- **The LOG-ONLY needle class** (#1998): a `NoEcho` parameter's value and any `Fn::Split` piece or child list element's share of one (#4049), recorded by `recordLogOnlyValue` into a side set keyed by the bag INSTANCE. The PRINTING maskers (`maskSecretsInText`, `maskSecretsInError`, `createSecretMasker`) read it; anything that PERSISTS, or DECIDES what is persisted or sent, must not — a detector calls `maskRecordedSecretsInText`. A masking site's empty-bag test is `hasMaskableValues`, not `size`, a copy that later MASKS (`new Map(bag)`, an entry loop) must `carryLogOnlyValues`, and a recording VIEW over a pass map (`ForwardingSecrets`, `SharedEntriesSecrets`) must `shareLogOnlyValues` at creation, since a record can land late or on a throwing path. A printer testing a name against a MAP (the alias warnings) takes `printingCorpusOf(bag)`. ONE verdict does too: `exportNameSecretExposure` refuses an `Export.Name` holding a log-only needle, through `secretsPresentIn` over `printingCorpusOf` of the name's bag and of `noEchoParameterValueSeed` (every `NoEcho` value), by CONTAINMENT only: both are stack-wide, and counted wholesale would refuse every alias. Deploy and diff resolve EVERY name before deciding any alias (#4043). Every other publication, persistence or state-key verdict (`stateKeySecretExposure` included) reads the map alone. `ResolverContext.printingSecrets` is PRINT-ONLY: no detector, and no recording into `recordedSecretValues`, may read it (#4043). A read of a resource NAMED from a secret (#3869, `secret-name-needles.ts`) records its spellings and each served leaf holding one into the READER's bag, `printingSecrets` where it decides, or `secretNameSink` for a command reading state. Its own lines, a destroy delete, orphan replay (per entry), drift revert mask via `withPrintingSecrets`; their events, `maskEventTextWithBoundBags`; a carry over a sink compares masks with and without it.

- **src/deployment/masking-retry-logger.ts** - The masking `RetryLogger` for a `withRetry` caller holding a RESOLVED bag: `retry.ts` interpolates the AWS message VERBATIM into its `debug` / give-up `warn`. `DeployEngine.maskingRetryLogger` is a LAZY variant for bagless sites. A resolver SDK call sending a template-derived name takes `namedRequestMasks`, masking that name by position (#3171).

- **src/cli/commands/scrub.ts** - `cdkd scrub [STACK...]`: [layout-scrub.md](layout-scrub.md).

- **src/deployment/secret-region-classification.ts** - The ONE answer to "which region must answer for this `{{resolve:...}}` reference", shared by the resolver, scrub, drift and the replay. `classifyReplaySecretRegion` returns `local`, `named-region` (an `arn:` naming another region) or `ambiguous` (name form AND a foreign producer region — refuse). `producerRegionsFromState` derives the evidence from the record's `imports` / `outputReads`.
  - A consumer supplying the evidence owes TWO things: pass `ResolverContext.producerRegions`, AND let the refusal survive its own error handling — `cdkd scrub` wraps each pass in a best-effort `catch`, so it re-raises `DynamicReferenceRegionAmbiguousError` by cause-chain walk. A resolution whose origin is already KNOWN must NOT inherit the evidence (`withoutProducerRegions` strips it): `producerRegions` describes the CONSUMER's reads.

- **src/provisioning/masked-retry-logger.ts** - The `RetryLogger` a provider hands to `withRetry` when its payload carries template-derived values: `createMaskedRetryLogger` routes BOTH `debug` and `warn` through the masker; `maskerOrIdentity` defaults an absent one to identity. A provider receives the masking CAPABILITY (`CreateContext.maskSecrets` / `UpdateContext.maskSecrets`), never the bag.
  - Masking the retry logger is NOT sufficient: `withRetry` rethrows the RAW error, so each provider ALSO masks `error.message` where it wraps the failure in a `ProvisioningError`. Mask the RAW `error.message` (only it reaches `maskSecretsInText`'s whole-value arm) and wrap via `wrapMaskedAwsError`, `cause` UNMASKED: it stamps `markRedactedCause` when the mask cut the text, so retry classifiers read the chain.
