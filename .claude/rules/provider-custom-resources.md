# Provider Pattern - Lambda-backed Custom Resources

- **Response-bucket region correction.** A pre-signed URL's host is region-specific and the response bucket (cdkd's STATE bucket) may be elsewhere, so `ensureResponseClient()` corrects the client BEFORE the first response-bucket S3 call; `setResponseBucket()` deliberately takes no region parameter, keeping the shared client's credentials.
- **`disableOuterRetry = true`.** The engine's outer `withRetry` must NOT re-invoke `create()`: each invocation derives a fresh pre-signed URL and `RequestId`, stranding the first response at a key nobody polls.
- **Transient IAM-authorization retry.** A function can cold-start before IAM propagates the role policy cdkd just attached, so on a FAILED reason matching `CR_TRANSIENT_AUTHZ_SIGNALS` it re-invokes with a fresh URL / `RequestId` and recycles the execution environment (a no-op `UpdateFunctionConfiguration`). Keep that set NARROW: a re-invoke re-runs the user's `Create` and can create a SECOND physical resource.
- **A THROWN SDK error is retried PER CALL, never by a wrapper** (a blanket retry is the stranded-URL bug above). Replay is PRE-DELIVERY only, enforced by the `delivered` flag `sendRequest` flips on send. **TWO budgets, counted separately**: `IAM_PROPAGATION_MAX_RETRIES` pre-delivery, the small `transientAuthzMaxRetries` for the FAILED-response arm (only that one re-runs the USER'S handler). `CDKD_CR_AUTHZ_MAX_RETRIES` bounds handler re-invocations only.
- **The thrown-error classifier** (`isTransientAuthzThrow`) is the shared IAM-propagation patterns plus `CR_THROWN_AUTHZ_EXTRA_SIGNALS`, never `isRetryableTransientError` (post-acceptance errors). Admit an entry only if it is a rejection decided BEFORE the handler can run. It REFUSES a `markNonRetryable`d error, walking `.cause`, so a budget already spent cannot be spent twice.
- **No readiness-waiter arm may relay the `GetFunction` response** into a message persisted to `deployments/{runId}.jsonl`: TIMEOUT `observedResponses` keys can be the serialized response too ([#4255](https://github.com/go-to-k/cdkd/issues/4255)). `describeLambdaWaiterFailure` allowlists what it keeps, a rejected poll through `describeAwsFailure` (#2302).
- **The log tail is a DATA-CLASS decision.** `invokeLambda` passes `LogType: 'Tail'` and the retry matches `CR_TRANSIENT_AUTHZ_LOG_SIGNALS` against it. The tail is arbitrary handler stdout, possibly carrying the resource's properties, so only the matched cdkd-authored SIGNAL PHRASE reaches `cfnResponse.Reason`; the verbatim line stays in ephemeral `logger.warn`s capped by `CR_LOG_TAIL_WARN_MAX_CHARS`.
- **A terminal FAILED that nothing explained gets the whole tail, ephemerally**, only when the reason carried no authz wording AND the log matched no signal. `LogResult` is never absent on a `Tail` invoke, so `hasHandlerLogOutput` requires a HANDLER-authored line; its boilerplate set must include the COLD-START platform lines. Do NOT gate on `isAsyncPattern`; the tail is always the DISPATCH invoke's.
- **`create` / `update` refuse a resolved secret before the invoke** ([#4009](https://github.com/go-to-k/cdkd/issues/4009)): decided by `carriesResolvedSecret` on the bag the caller bound with `withCurrentResourceSecrets` (EXPRESSION entries only; a mask-only `NoEcho` value reaches a dependent in the clear), so a derived form is refused too; `findResolvedSecretPaths` only NAMES it, on BOTH update sides (`OldResourceProperties`). NOT downgraded on `replayingState`: it is a disclosure guard, and the downgrade is the leak.
- **A `***` at a `DeleteContext.recordedNoEchoLeaves` coordinate SKIPS the delete** (#4043) unless `noEchoDeleteValues` re-resolved EVERY one (#4682); then only the PAYLOAD carries them and delete-path messages mask with its `maskSecrets`. A `***` no coordinate names always skips. Every `delete()` caller threads the leaves.
- **Delete fail-fast on a gone backing Lambda.** `GetFunction` `ResourceNotFoundException` SKIPS on a stack destroy (`stackDestroy`), else warns and drops (#2115); other errors invoke. Create / update never pre-check.
- **`NoEcho` on the response envelope is HONOURED** ([#2274](https://github.com/go-to-k/cdkd/issues/2274)): relayed as `noEchoAttributes`, which become MASK-ONLY redaction needles. **The provider does NOT mask the attributes it returns** — CloudFormation delivers `NoEcho` `Data` to dependents in the CLEAR, so masking at capture would store the mask as a dependent's real property. The SIMPLE-HANDLER shape (`{PhysicalResourceId, Data}`) is synthesized field by field, so it must copy the flag explicitly, `=== true` — handler output is untrusted. See [layout-deployment-secrets.md](layout-deployment-secrets.md).
