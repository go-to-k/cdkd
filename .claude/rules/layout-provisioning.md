# Key Files and Directories - src/provisioning

Provider contract: [providers.md](providers.md). Deletes: [provider-delete-path.md](provider-delete-path.md). Index: [code-layout.md](code-layout.md).

## Important Files

- **register-providers.ts** - Which types HAVE an SDK provider (`provider-registry.ts` decides which one RUNS a resource), from the classes **provider-classes.ts** re-exports, loaded on demand (#4521).

- **provider-registry.ts** - The ROUTING decision, in order: Custom Resource -> CR provider; a `provisionedBy: 'cc-api'` record -> Cloud Control, STICKY unless `wouldReturnToSdkProvider` says otherwise (one spelling, shared with `cdkd diff`; per-type escapes in `STICKY_CC_MIGRATION_EXEMPT` — #2719); an SDK provider with no silent-drop property -> that one; a silent drop -> Cloud Control, unless `NON_PROVISIONABLE` or `disableCcApiFallback` refuse it pre-flight. **DELETE logic as much as create logic**, hence in the `integ-destroy` gate scope.

- **name-lookup.ts** - helpers for `lookupNames` (#4705). `withApiLimit` is PROCESS-wide per API key, so `deploy --all` shares one limit; a new lookup must go through it, not its own pool.

- **import-helpers.ts** - `resolveExplicitPhysicalId` + `normalizeAwsTagsToCfn` for `import()`. The normalizer strips `aws:`-prefixed tags (false drift; AWS rejects writing them).

- **data-delete-intent.ts** - The CDK auto-delete tag keys. S3 auto-empties, and ECR sends `force: true`, ONLY with the tag, `EmptyOnDelete: true`, or `DeleteContext.forceDataDelete`.

- **region-check.ts** - `DeleteContext` + `assertRegionMatch()`: region unset or empty -> no-op; match -> silent; mismatch or unresolvable client region -> non-retryable refusal. Physical ids are usually NAMES shared across regions, so a wrong-region call hits the WRONG resource.

- **config-shape.ts** - Shape guards for CFn config blocks, which otherwise substitute a default (often the OPPOSITE of the intent) for a malformed container (#1471). **A guard behind a TRUTHINESS gate is skipped by a FALSY malformed container: the gate must be `!= null`.** `onUnusable` (warn + default) is for UPDATE-path sites ONLY, since a rollback replays `update()` with a STATE record as the desired bag.

- **attribute-map.ts** - `definedAttributes(entries)` DROPS every `undefined` / `null`, because **an attribute cdkd could not read back must be ABSENT**: a recorded `''` would shadow the live-read arms forever. An empty string AWS ITSELF reported is KEPT. A LEAF (#3077).

- **auxiliary-failure.ts** - `markAuxiliaryFailure`: a failing AUXILIARY write inside a provider's `create()` is anchored to a logical id no template can spell, so the name-collision classifier never credits it to the resource ([name-collision-classification.md](name-collision-classification.md), #3826); `isAuxiliaryFailure` is what `withRetry` latches on to carry the mark forward (#3972); `isAuxiliaryMarkOf(link, RETRY_AUXILIARY_OWNER)` tells `withRetry`'s mark from a provider's (#3984). A LEAF.

- **created-resource-sink.ts** - `reportCreatedResource` / `retractCreatedResource`: the `markCreatedBeforeFailure` proof, written to an engine-owned AsyncLocalStorage sink the moment the create call returns, so it survives the per-resource deadline dropping the provider's late marked error (#5511). `execute.ts` scopes one sink per CREATE / UPDATE operation and, for that operation's own `ResourceTimeoutError` with no mark, reads it when the failure is saved (`settleReportedCreates`); a report or retraction after that save is lost. A retraction falls back to the earlier report. The engine clears it where it writes the resource to state (`clearCreatedReport`). Anchored on logical id and type.

- **delete-started.ts** - `markDeleteStarted`: a `delete()` that changed the resource (a detach, a disable) before a refused terminal call marks its error, so a replacement's `replacedDeleteFailureVerdict` reads `'unconfirmed'` and a rollback never re-adopts the stripped survivor (#4946). Mark after a strip whose failure propagates, before one whose failure is swallowed. A LEAF.

- **not-gone.ts** - `markNotGone`: a delete failure not the resource's own not-found; the already-deleted classifiers refuse it, retries untouched (#5228). A LEAF.

- **ec2-instance-state.ts** - `isSettledInstanceState(stateName)`: only `pending` and NO state are unsettled. Shared by the provider and the resolver's live arm. A LEAF.

- **changed-properties-consumers.ts** - `changedProperties` readers (#5112) whose readback returns the keys read get its NoEcho readback. A LEAF.

- **iam-policy-targets.ts** - every IAM principal list is read here (#3878, #3906). Malformed is refused before ANY call; only a secret-derived RECORDED list on a ManagedPolicy / InstanceProfile / User `Groups` UPDATE is read from IAM. `IAM::Policy` / `UserToGroupAddition` have no live source: the engine DROPS an UNCHANGED reference from their update's recorded side (`withUnchangedSecretPrincipalLists`, #4064) — never substitutes the resolved name, which after a rotation reads as already attached, and never across a `GroupName` / `PolicyName` change — and they refuse the rest; every create refuses it. A LEAF.
- **policy-document-content.ts** - the QueuePolicy / TopicPolicy failed-create deletes' shared document handling (#4612). `policyContentKey` compares IAM-equivalent spellings as equal (SQS stores a bare account id as its root ARN). `attemptedPolicyDocument` settles the entry (`unusable`) ONLY on a failure known to be permanent (missing or masked document, not-found secret, a cdkd refusal marked non-retryable, cdkd's token-scan refusal; a nested child's ambiguous region is `retry`); every other failure is `retry` (entry kept), so a credentials or access problem never settles it. A LEAF.
- **secret-reference-immutable.ts** - `unchangedBehindSecretReference`: what an `update()` immutable-name guard, and `CloudControlProvider.update`'s patch, consult (#4275): state keeps a secret-derived name as `{{resolve:`, `update()` gets plaintext. Compare with the PHYSICAL ID's name, if any; else only a key the ENGINE replaces on any change (registry, else create-only paths) qualifies, and a recorded `***` or no masker keeps the refusal. That arm cannot see a ROTATED secret, so a key whose DESIRED value addresses the writes needs AWS to confirm the recorded target (`DBProxyTargetGroup`'s ARN, a Schedule's `cdkd:CreationDate` + target ARN + role); unconfirmed is a plain `ProvisioningError`, never the typed error `--replace` turns into a create.
- **secret-principal-resolution.ts** - `resolveSecretDerivedPrincipals`: an `IAM::Policy` / `UserToGroupAddition` DELETE resolves a recorded secret-reference principal list to the CURRENT value's names, only under `DeleteContext.resolveSecretDerivedPrincipals` (a destroy, never a deploy: see its JSDoc) and only a token `local` under the producer-region evidence (#4150) or whose v12 record names its region (#4879) - only the latter when that evidence is incomplete (#4887). Fail-safe: else skip; maskers cover every printed name and the cause.

- **tag-list.ts** - provider CFn `Tags` diffs read both sides here (#3994): malformed desired is refused before ANY call, malformed recorded is ADD-only.

- **redacted-delete-address.ts** - A delete ADDRESSING a resource through a recorded property must not send cdkd's own redaction (`***` or a `{{resolve:...}}` expression) to AWS (#3952): an unknown name often answers not-found, which the idempotent arm reads as DELETED. Fall back to an unredacted source first; else `redactedDeleteAddressSkip`. A delete-then-create caller must ABORT on that skip. `CustomResourceProvider` keeps its own ServiceToken arms.

- **state-orphan-remedy.ts** - `stateOrphanRecordRemedy`: the `cdkd state orphan` a delete skip names (#4602). Whole-stack only on `DeleteContext.stackDestroy`; otherwise (no context too) `--resource <logicalId>`, since a deployed stack's whole-stack drop makes the next deploy re-create everything.

- **composite-id.ts** - Refusal guard for COMPOSITE physicalIds (#1672). The separator is unescaped, so a segment containing one yields the wrong ARITY yet passes every guard: the deploy SUCCEEDS, then destroy deletes the wrong one. `packCompositeId` is the ACTION (throws, or warns-and-packs while replaying state); `compositeIdSeparatorRefusal` is the bare PREDICATE for `import()` paths that warn-and-SKIP. A type whose every reader ANCHORS on a recorded segment need not pack through here: `AWS::Glue::Table` builds `<db>|<table>` directly (`segmentAfterAnchor`; `|` allowed in both; an unanchored id is skipped; #3892), and `AWS::Route53::RecordSet` its id, the name anchored on the recorded `Name` / `Type` (#3890).

- **nested-stack-messages.ts** - What `NestedStackProvider.delete` THROWS on child-destroy errors. **Must stay a LEAF — no imports, ever**: importing it back from the provider closes a cycle through `destroy-runner.ts`. A builder, not a literal: both callers classify failures by MESSAGE and read already-deleted phrases as idempotent success, DROPPING the state row.

- **replacement-protection-advice.ts** - What a provider says INSTEAD of a bare "re-deploy with `--replace`" for a protection-flagged resource (#2610): the deploy engine's DELETE never sets `DeleteContext.removeProtection`, so AWS refuses it. Callers owe `evidence` naming the BAG they read, and a `disable.command` changing nothing but the flag. Also the gate provider sites route a pasteable `aws ...` command's values through: `renderDisableCommand`, or the tagged `pasteableAwsCommand` for several values (#3136). Both insert the run's explicit `--profile` after every `aws` word; a HAND-BUILT `aws` command must call `withPasteableAwsProfile` (`src/utils/pasteable-aws-profile.ts`, #3959) or it pastes against the default profile, and hold each template- or state-borne value to `isInertUnquoted` AND `isAwsCliLiteral` — a `file://` prefix, a shorthand `@=` or a leading `-` is acted on by the CLI itself, whatever the quoting (#4199); an AWS-minted or cdkd-generated value needs neither.

- **final-snapshot.ts** - `DeletionPolicy` / `UpdateReplacePolicy: Snapshot`. ATOMIC types thread `DeleteContext.finalSnapshotIdentifier` — SDK route ONLY; `CloudControlProvider.delete` fail-closes on it, and when the delete's governing policy is `Delete` (or `skipFinalSnapshot`) hands an RDS cluster / instance or a Neptune cluster to its SDK provider pinned to the CC client's region: those handlers snapshot on every delete (#3993, #4029). `effectiveDeletionPolicy` applies CloudFormation's ABSENT default (`Snapshot` for an RDS cluster or standalone instance) where a DeletionPolicy is CONSUMED, never where it is recorded — `cdkd diff` compares the record to the template (#4030). **The atomic and pre-delete sets must stay DISJOINT**: atomic is tested first.

- **emr-configuration.ts** - CFn -> SDK converters for `AWS::EMR::*` config blobs (renames); the SDK v3 serializer DROPS unknown members.

- **dynamodb-warm-throughput.ts** - Shared by both DynamoDB providers. `coerceWarmThroughput`'s `spec` presence IS the sendability predicate (write and drift agree); `isWarmThroughputDecrease` fails OPEN on an unreadable live block: AWS rejects a LOWERING `UpdateTable`.

- **dynamodb-contributor-insights.ts** - ONE reader for the table-level and per-index `ContributorInsightsSpecification`. The per-index block is NOT an SDK `GlobalSecondaryIndex` member (`UpdateContributorInsights` + `IndexName`); its read-back is GATED on the desired entry declaring it (#1782).

- **dynamodb-stream-members.ts** - `StreamSpecification.ResourcePolicy` / `.Tags` are NOT SDK `StreamSpecification` members: they go to the STREAM arn, re-applied to the re-read `LatestStreamArn` after a `StreamViewType` change mints a new one. The plan's ORDER is a contract (policy delete first, put last); an unreadable member is REFUSED on a template-path update: it is an access grant (#3458).

- **dynamodb-vector-indexes.ts** - `AWS::DynamoDB::Table.VectorIndexes` (#2762): `UpdateTable` has Create / Delete only, one per call: a same-name definition change is REFUSED pre-flight. Planned against the LIVE list.

- **dynamodb-index-busy-delete.ts** - The index-busy `DeleteTable` rule BOTH DynamoDB providers read; it is TRANSIENT. The classifier is keyed on the MESSAGE: AWS reports a plain `ResourceInUseException` for terminal conflicts too. The settle poll warns and RETURNS on timeout (a throw would STRAND the resource), and **it runs PER RETRY**, so the budget is PER CALLING TYPE.

- **remove-protection-types.ts** - The ONE list every `--remove-protection` help string renders from (SDK types, then the CC registry), bound by `remove-protection-types.test.ts` to the provider files reading `removeProtection` both ways (#2660) and to **protection-flags.ts**: the ONE table of where each type's flag lives and which values are ON, read by the destroy prompt and by **recorded-protection.ts**, the deploy engine's stateful-replacement refusals (#2610). Those NARROW it (an ASG blocks a non-forced delete only at `prevent-all-deletion`), never widen it.

- **providers/ambiguous-create.ts** - For a CREATE with no idempotency token (#2080): `withoutServerErrorRetries` stops the SDK replaying a 5xx on the create client, and `AmbiguousCreateLatch` arms only on an AMBIGUOUS create failure, so the next attempt looks first. A lookup only REPORTS: a name is not attribution (the stack lock is per state location, names per account+region). `orphan-report.ts` is the shared lookup-and-report step; `{iam,lambda}-create-client.ts` build IAM / Lambda create clients. Rules: [docs/provider-rules.md](../../docs/provider-rules.md).

- **providers/create-token-ledger.ts** - A create token the service binds for the resource's LIFETIME (EFS `CreationToken`, FSx `ClientRequestToken`, OAI `CallerReference`) comes from `reserveStackCreateToken`, which folds in the stack's ledger nonce (`src/state/create-token-ledger.ts`, #4438); add a new such type to `LEDGER_TOKEN_RESOURCE_TYPES`. Any path that lets such a resource go while it still exists must replace the nonce and drop that logical id's `sent` entry (`deleteState` deletes the ledger; `cdkd orphan` and `noteRetainedResource` from every Retain arm, deploy and rollback, rotate it), or the stack's next create is handed it back or refused. A `sent` entry is kept until the deploy that wrote it succeeds (`forgetRecordedCreateTokens` after the final save): dropping it when the create returns reopens the interrupted-deploy refusal, and keeping it past that turns a let-go whose rotation failed into an adoption. A ledger that cannot be read or written REFUSES the create; never fall back to the nonce-free token, which a re-run would not send again.

- **providers/deletion-protection-compensation.ts** - Undoes a `--remove-protection` flip whose delete then failed TERMINALLY (#2204). A new flip site wraps its delete in `deleteWithProtectionCompensation`, flips through `observeThenDisableProtection` (a pre-flip readback, never state) and sets `flip.deleteAccepted` once AWS takes the delete (on Cloud Control, per attempt, once the handler may be deleting: an abandoned wait, an ambiguous handler code, or a conflict after such an attempt); otherwise a failed destroy leaves the guard silently stripped.

- **providers/db-instance-modify-retry.ts** - Resends a `ModifyDBInstance` refused as not `available`; never a succeeded one, but once an SDK replay of a lost response (#5194).

- **ec2-termination-protection.ts** - Shared `--remove-protection` helper for `AWS::EC2::Instance`: the modify WRITE lags the delete READ, so both routes flip protection off AND retry the delete. The FIRST flip goes through `observeThenDisableInstanceApiTermination`, or the compensation (#2204) records nothing. A CC-routed protected ASG is delegated to `ASGProvider.delete`.

- **ec2-volume-delete.ts** - `CloudControlProvider.delete` deletes EVERY `AWS::EC2::Volume` with EC2 `DeleteVolume`, never `DeleteResource`: the registry handler can snapshot the volume itself and then hang (#3455). Its region check runs OUTSIDE the delete `try`, and its timeout is a marked abandoned wait, because already-deleted classifiers match logical-id substrings.

- **guardduty-detector-patch.ts** - a GuardDuty detector's Cloud Control update patch (#4910).
- **apigwv2-body-import-patch.ts** - an imported HTTP API's definition updates via `ReimportApi` (#5260).

- **delete-gone-wait.ts** - The post-delete wait for a service that holds a NAME while `DELETING` and refuses a same-name create with its live-resource error (Kinesis, Firehose; #3872; DynamoDB `Table`, #5514). The delete was ACCEPTED, so a cap, Ctrl-C or unreadable status warns and RETURNS; only a caller-named TERMINAL status (Firehose `DELETING_FAILED`) throws (marked abandoned, keeping the state record) — never on a first read alone.

- **unsupported-types.ts** + **.generated.ts** - Pre-flight unsupported-type rejection. The generated half ships the Tier 3 set (`NON_PROVISIONABLE`), codegen'd from the provider-coverage JSON. `--allow-unsupported-types` routes named types through CC. Hand-written `SDK_PROVIDER_NON_PROVISIONABLE_TYPES` lists the REGISTERED `NON_PROVISIONABLE` types the audit drops from Tier 3; the CC auto-route reads both, per TYPE, via `hasNoCloudControlHandlers` (#3871).

- **property-coverage.ts** + **.generated.ts** - Property-level REPORTING and routing, NOT a rejection; the generated per-type `{ handled, silentDrop }` map is built from the schema fixtures, CI-checked. `--prefer-sdk-route` opts named entries back INTO the drop, keeping the SDK path. **An accepted drop is not RECORDED either** (#2750): the allow set is per `<Type>:<Prop>` but the ROUTE is per RESOURCE, so ONE un-allowed drop routes the whole resource through CC and nothing is dropped. Both narrowings must KEEP an un-allowed drop, and the WRITTEN record keeps a CREATE-ONLY drop, which would otherwise become an ADDITION (a replacement) on a flag-ful redeploy. The COMPARISON drops it once a deploy stops accepting it or the provider starts writing it (#5572); the engine refuses that replacement unopted (#2790). A property in NEITHER map (unrecognized) ROUTES like a drop unless read-only, allow-listed, on a type with no CC route, or held unchanged by the state record — that baseline is what keeps an existing deployment on its route, so every existing-resource caller threads the record's bag, and the narrowings stay schema-known only ([design](../../docs/design/3713-route-unrecognized-properties.md)).

- **mutually-exclusive-properties.ts** - Pre-flight rejection of property COMBINATIONS AWS accepts only one of, reachable nowhere else: once the resource exists the diff says `NO_CHANGE` forever. **The presence predicate is load-bearing**: pre-flight runs BEFORE intrinsic resolution, so a key behind an unresolved intrinsic counts as UNKNOWN, never declared.

- **custom-resource-secure-references.ts** - Pre-flight refusal of a SECURE dynamic reference (`secretsmanager` / `ssm-secure`) anywhere in a custom resource's properties, intrinsic parts included (a token SPLIT across `Fn::Join` parts or a `Fn::Sub` `${...}` counts by its opener), which CloudFormation does not support (#3976). A plain `ssm` reference stays accepted. Template path only, so a rollback replay never reaches it.

- **nested-required.ts** + **.generated.ts** - Pre-flight rejection of a PRESENT nested block missing a schema-`required` member (#1802). **A schema `required` list is not evidence CloudFormation enforces it**: `CFN_ENFORCED_TYPES` holds only types MEASURED to refuse, so a type joins it by measurement, never by reading its schema.
- **property-shape.ts** + **.generated.ts** - Pre-flight rejection of a list where the schema wants an object, or the reverse (#4357). **Only array-versus-object, only where the schema admits exactly one kind**: a scalar mismatch, a type list, an intrinsic or a legacy type (schema without `handlers`) passes, since a false refusal has no escape hatch. The rows come from `extractPropertyShapes` in `scripts/refresh-cfn-schemas.mjs`.

- **interrupt-watch.ts** - The ONE SIGINT watch every bounded wait here uses, plus `InterruptedWaitError` and the cause-chain classifier (NO depth ceiling: one error per nested-stack level). ONE error type: a bare `Error` from a provider reads as a resource failure and triggers an automatic ROLLBACK on Ctrl-C. ONE STICKY latch, cleared only by a COMMAND scope and armed only inside it — never on `process.listenerCount('SIGINT') > 0`, which a concurrent waiter's listener would arm permanently.
  - **A lock-holding command must release BEFORE unregistering its SIGINT handler.** `destroy-runner.ts` re-syncs `result.interrupted` GATED on `statePreserved`: **a stack whose state was deleted never reports `interrupted`**. Each signal has ONE owner: PER-STACK is `result.interrupted`, PER-RUN is the watch, and the exit code ORs in `stoppedEarly`.

- **describe-type.ts** - Shared `cloudformation:DescribeType` with THROTTLE-ONLY retry, for the write-only / read-only / create-only resolvers and `export.ts`, whose fallbacks would turn a throttle into a real failure. Every call takes a slot of ONE process-wide limiter (`DESCRIBE_TYPE_MAX_IN_FLIGHT`, #3718); a prefetch is BACKGROUND, so an awaited lookup never queues behind one. **Resolve the client when SCHEDULING, never inside the task**: a queued task starts inside whichever task finished, in THAT task's per-stack AWS scope. `hasNoRegistrySchema()` is the ONE list of types with no registry entry, for which DescribeType can only fail.

- **write-only-properties.ts** - Resolves the registry schema's `writeOnlyProperties`, caching **only SUCCESSFUL lookups**. `CloudControlProvider.update` strips them from the PREVIOUS side before patch generation: read handlers cannot return them, so one absent from the patch is dropped on every UPDATE — except an UNCHANGED key holding a create-only path that overlaps a write-only one, in either direction (`getTopLevelKeysHoldingUnreadableCreateOnly`): Cloud Control refuses any op bringing that value in, unchanged or not (#4416). `tryGetTopLevelWriteOnlyProperties` is the variant for a caller that must tell "none" from "unknown" — the diff's synthetic create-only fallback (#3803), which FAILS CLOSED on `undefined`. It warns nothing, and reads only SETTLED successes, never the other variant's in-flight promise, whose failure resolves to an empty set.

- **read-only-properties.ts** + **getatt-attributes.generated.ts** - `CloudControlProvider.import`'s attribute narrowing. **Certify `getTopLevelAttributeNames`, never `readOnlyProperties` alone**: `Fn::GetAtt` also reads the writable properties the generated table lists (#3735). **The RETURN TYPE is the point**: `undefined` means "could not find out", an empty set "declares no attributes", so returning `new Set()` on failure re-opens the disclosure.

- **cc-import-identifier.ts** - Completes the bare CloudFormation id `CloudControlProvider.import()` receives into the `|`-joined Cloud Control identifier for a COMPOSITE `primaryIdentifier`, read from the live schema (#3672). The completed value is also what gets RECORDED. It REFUSES rather than guesses when the template cannot supply exactly the other fields.

- **cc-autoroute-update-remedy.ts** - The note appended to an UPDATE this deploy moved from the SDK provider to Cloud Control (#4904). It names the cause CONDITIONALLY, since the failure may be anything, and must carry no phrase `isNotFoundMessage` or the retryable table matches.

- **slow-cc-operation-timeouts.ts** - Per-(resourceType, operation) wall-clock timeout FLOORS, and the SINGLE source for the CC poll cap and both outer deadlines, so they cannot drift.

- **resource-timeout-registry.ts** - Registry of the resolved `--resource-timeout` input: per-type override > explicit global > `undefined`. **The compile-time 30m default deliberately does NOT leak in**: only an explicit user value may lift an inner waiter's floor.

- **create-only-properties.ts** - Create-only resolution for REPLACEMENT detection, compared at PATH granularity so a nested entry forces replacement only when the value AT that path changed. **The fallback is only as good as the registry schema**: some types declare NO `createOnlyProperties` though AWS rejects the update (`AWS::EC2::Volume`, #1356), so they need a hand-authored `ReplacementRulesRegistry` entry, plus a `STATEFUL_TYPES` one if data-bearing. A FAILED lookup resolves the committed `create-only-snapshot.generated.ts` (the fixtures' `createOnlyPropertyPaths`, parsed by the live schema's `create-only-paths.ts` leaf) and is NOT cached, so the live answer wins once it returns. **A prefetch's owner must `cancel()` it when its diff is done**, on every path: an in-flight request holds the event loop until it answers, and an uncancelled prefetch competes with the deploy's own write-only lookups for the account's DescribeType quota.

- **stateful-types.ts** - The data-loss guard list and its verdict helpers (#615): a wrong edit here silently DELETEs + CREATEs a user's data. Its two mechanical LOWER BOUNDS miss the residual — a delete that destroys data with no opt-in — so such entries are hand-added with the reason AT the entry. Conditional reasons stay HEDGED — `renderStatefulReason` renders where no probe ran.
