# Key files - cdkd drift

Analyzer: [layout-analyzer.md](layout-analyzer.md). CLI: [layout-cli.md](layout-cli.md). Secrets: [layout-deployment-secrets.md](layout-deployment-secrets.md). Index: [code-layout.md](code-layout.md).

## Important Files

- **src/cli/commands/drift.ts** - `cdkd drift [<stack>...]`: the factory, re-exporting `drift/*.ts` (`detect` / `compare`, `secret-resolution`, `redaction`, `accept`, `revert*`, `plan`, `report*`). State-driven, no synth: reads S3 state, asks each provider's optional `readCurrentState`, compares through `drift-calculator.ts`. A `RESOURCE_NOT_FOUND` read is the `deleted` outcome, never `unsupported` (#4283). Exit: 0 clean; 1 drift or error; 2 clean but INCOMPLETE (drift unknown too, #6696), or a partly failed `--revert`.
  - The baseline holds unresolved `{{resolve:...}}` and the readback plaintext, so `resolveStateSecretExpressions` re-resolves it to COMPARE only, and again in `runRevert` before `provider.update` (#2108).
  - A reference routes to the region that must ANSWER it, not the stack's: `resolveDriftLeafByRegion` classifies the WHOLE leaf before any fetch via `classifyReplaySecretRegion`, re-exported by `rollback-executor.ts` so the two commands cannot disagree, then routes `named-region` through a per-STACK `DriftSecretResolvers`.
  - `logicalId` / `consumerRegion` / `producerRegions` are REQUIRED; a default silently verdicts `local` or refuses everywhere. A nested child's `producerRegions` includes every ancestor's, read from state (`driftProducerRegionEvidence`, #4213); an unreadable ancestor is INCOMPLETE and refuses every region-less reference. On `ambiguous`, detection falls back to the UNRESOLVED baseline and clears the `secrets` map; revert returns BEFORE `provider.update`.
  - `notCompared` is a MEMBER of the outcome union, so `clean` means compared-and-matched and CI gates on `notCompared` and `notSupported` both empty. `matchOutcome` maps over the union's `kind`: a new variant fails to compile everywhere. `outcomeExitSignal`: `unsupported` and each cause but `unresolvedToken` / `noEchoParameter` exit 2.
  - `redactDriftChanges` is the one redaction choke point behind the report, `--json` and `--accept`; keyed on PATH and value, it runs BEFORE the clean/drifted decision. Its rules constant follows the DESTINATION (#2939): `STATE_SOURCED_BASELINE_RULES` into `observedProperties` (every `--accept` write since [#6125](https://github.com/go-to-k/cdkd/issues/6125)), `STATE_SOURCED_READBACK_RULES` into `properties`, where a mask must never land. The revert's narrowing write uses the readback family, never `STATE_DERIVED_RULES`.
  - `partitionUncertifiedBaselineChanges` runs BEFORE `redactDriftChanges` (#3595): a change whose ONLY difference is a #2852 fail-closed mask becomes `notCompared: uncertifiedBaseline` (exit 2). The class comes from `properties` via `isUncertifiedBaselineMaskPosition`; a mask at a `noEchoLeaves` coordinate is `noEchoParameter`, any other stays `drifted`.
  - An ABSENT `awsValue` at the EXACT secret leaf is DROPPED (`secretPaths.has(path)`, not the ancestor-matching `isSecretBearingPath`); a SURVIVING token does NOT mark its path secret-bearing.
  - `preserveLiveValuesAtUnresolvedTokens` runs BEFORE `provider.update`, pairing array elements via `pairedLiveItems`, not by index; a refusal KEEPS the token. An EMBEDDED token keeps the live string only when `liveMatchesUnresolvedTokenFrame` matches outside the SURVIVING tokens' spans, resolved plaintext included (#2102).
  - `--accept` refuses a masked VALUE and a masked PATH via one `acceptRefusalReason` predicate shared with `printAcceptPlan`, keyed off a `maskedPaths` SET that also tells `runRevert` which subtrees it cannot overlay. `observedBaselineRefused` (v10) is `notCompared: baselineRefused` at detection, before any readback (#2952); both write paths keep their own refusal (#2944) as a second layer.
  - The legacy region-less refusal builds its `cdkd deploy` through the SHARED `pasteableCommand` gate and prints it LAST on a labelled line, with the identity on a `Stack:` line beside it (#3307). The gate sanitize-and-compares against the RAW value, caps, refuses empty, shell-quotes, and refuses a LEADING `-` and a `cdkd deploy` pattern (`*` / `/`). BOTH lines ALSO take `isPasteableIdent` (the state-malformed-containers.md rule for a value beside a labelled line): the `Stack:` line directly, the command through the gate's `plainIdent` option, whose `not-plain` arm refuses whatever the five older arms admit but that predicate does not. One predicate, one verdict: `$(printf INJECTED)` or a padded name spelling `Migrate with:` gets NO identity line and a quoted `'<stack>'` hole, with the reason clause from `withheldTargetClause` (verb as a parameter, reason read from the gate's own `withheld`). Exactly one of the identity line and the clause prints, pinned by `drift.test.ts` as the line immediately before `Migrate with:` in both cases. What unblocks them is the SEPARATE rule for naming a target BESIDE such a block (state-malformed-containers.md, #3328): `isPasteableIdent` in CONJUNCTION with the command gate on BOTH identifiers. `mayNameTarget` ships `isPasteableIdent` alone on both, because `^[A-Za-z0-9][A-Za-z0-9~_.-]*$` plus `displayIdent(v) === v` is strictly stronger than the gate on every arm (starts alphanumeric, so never option-shaped; admits no `*` or `/`; never empty; the compare carries alteration and the cap). ONE predicate shared by all three sites, both halves pinned (the stack name at sites 2 and 3, the region at site 4). Withheld there means the line is NOT PRINTED, since each block already displays the stack name.
  - `writeHumanReport` prints every record- or readback-derived value (heading stack / region, each row's logical id / type, each change's path and both values) through a `safeMsg` row template, never trimmed, identifiers capped by `reportIdent`, a string value JSON-quoted and `\u`-escaped by `reportValue` when it carries a C0 / DEL / C1 / U+2028-9 / bidi character or an unpaired surrogate, its edges are whitespace or it starts with `"` (so a difference in one of those characters, or in WHETHER an edge is whitespace, stays visible) (#3232); `printAcceptPlan` / `printRevertPlan` take the same helpers (plus `reportPath` / `reportPlanChangeLine`), a readback key masked BEFORE `reportPath` caps it (#3949); `--json` is not sanitised but escaped by `stringifyJsonPayload` (#4045), and the wrap-forgery class (#3328) is bounded by the cap for an identifier only — a property value is uncapped — and closed for neither.
  - `buildRevertNewProperties` overlays each drifted subtree onto the AWS snapshot, but `mergeTagListForRevert` keeps service-authored tags and `preserveUntemplated` merges untemplated paths in only when `observedProperties` is absent, never under a `drift-verbatim-paths.ts` key (#6622).
  - `stripDerivedEchoMembers` (`baseline-keys.ts`, #6497) drops a read's echo of a sibling member (rotation schedule `AutomaticallyAfterDays` beside `ScheduleExpression`) from both comparison sides and the revert's desired bag. On a Cloud Control route, `withDeclaredWriteOnlyValues` (`revert-write-only.ts`, #6498 / #6499) GRAFTS the template's value at every write-only path (`getSettledWriteOnlyPropertyPaths`) into the send bag: a key the bag lacks goes whole, a container the bag holds keeps its baseline members (an `--accept`ed one survives) and takes only the write-only leaves, `*` matched one to one by `pairListItems` (template leaves outside the write-only paths must equal the bag's, bag-only keys ignored, unique both ways; no match = the template list WHOLE + warn, deploy parity). Values come from the record's `properties` as the revert RESOLVED them into `secrets` (a `{{resolve:...}}` goes resolved and masked; one still unresolved, or a mask, is skipped + warned). Names come from the pure `revertWriteOnlyResendNames` via ONE lookup per region and type in `runRevert` before the plan, which prints them and threads them to the update; never named: a mask, an intrinsic, or a `getTopLevelKeysHoldingUnreadableCreateOnly` key (#4416: the update's unchanged-key skip needs a template-side previous).

- **src/analyzer/drift-calculator.ts** - State-vs-AWS comparator. Walks state's keys only (AWS-managed fields never surface); `unionWalkObjects` (observed) and `unionWalkPaths` (`drift-verbatim-paths.ts`, #6622 / #6624) walk the key union. `deepEqual` is JSON-roundtrip equality, plus policy-statement folds (#6852).
  - `ignorePaths` sources: `undeclaredEmptyObservedKeys` (undeclared key captured EMPTY), `undeclaredUncomparedDriftKeys` (per-type undeclared key, any writer: bucket `NotificationConfiguration`, #5736/#5741; event bus `Policy`, #6323; a managed policy's IAM attachment lists, #6328; a member a SIBLING record writes leaves both sides, and revert's desired bag keeps the LIVE ones: `provisioning/sibling-owned-members.ts`, the ONE table of child->parent pairs and their verdicts, #6610), `preFixBaselineUncomparedDriftKeys` (a pre-fix baseline, #5749 / #6629; never a recorded unique-id vs live ARN principal, #1515's call, #6680), `readOnlyUncomparedDriftPaths` (a Cloud Control read's undeclared schema read-only paths, exact, never reduced to the container; looked up beside the read, `undefined` compares all, #6485), and `getDriftUnknownPaths`, scoped by state `properties`. On an ABSENT bag, COMPARE.
  - Then the provider's `canonicalizeDriftProperties`, on BOTH sides — the seam for a difference no PATH can name, a member of an ARRAY ELEMENT. Pure, no `side` argument, identity if inapplicable. Then `canonicalizeDriftPair` gets both bags plus the recorded `properties`, for a READBACK SHAPE CHANGE absorbed only against a legacy-shape baseline (#3573). `runRevert` sends its DESIRED bag through it: never drop from the readback; drop from the baseline only a member whose absence is no removal, keyed on `properties` (#3777). **`--accept` is NOT symmetric**: it writes `awsValue` from the CANONICALIZED bags, so a stripping canonicalizer persists the stripped shape. LAST, `canonicalizeDerivedPatternBName` swaps a Pattern B baseline name for the live one when `derivesPatternBName` derives it under either prefix flag; it needs the stack's `withStackScope`, which `runRevert` lacks (#4081).

- **src/analyzer/drift-undeclared-grants.ts** - An IAM principal's undeclared grant keys (#6627): both baselines, lists ONE way (a lost recorded member is never re-granted); after the sibling strip (`compare.ts`), before `siblingOwnedRevertDesired`.

- **src/analyzer/drift-normalize.ts** - Order normalization on BOTH sides: `canonicalizeTagListsDeep` sorts any `{Key,...}[]` by `Key`, `canonicalizeIdArraysDeep` any array of AWS ids or ARNs except at a path `orderSignificantIdArrayPaths` declares for the type (e.g. Lambda `Layers`, #6761), which `calculateResourceDrift` reads from its `resourceType` option; every caller comparing a typed resource passes it. Every object arm here, in `drift-principal-normalize.ts` and `cc-api-strip.ts` rebuilds onto `nullPrototypeRecord()` and returns a non-plain value by IDENTITY (#3121).
  - Both declared path lists share ONE matcher, the exported `matchesPathPrefix`, which `isIgnoredPath` aliases. A plain entry declares a SUBTREE; `LEAF_ONLY_PATH_SUFFIX` (`[]`) claims the path ALONE, since this walk descends into array elements while `isIgnoredPath` never crosses one.
  - Declare an unordered path HERE, never by sorting inside `readCurrentState`: this runs on BOTH sides, so a read-side-only sort MANUFACTURES drift on the `properties` fallback baseline. Declaring an ORDER-SIGNIFICANT list hides real drift — why `KeySchema`, FSx `DnsIps` and ElastiCache `PreferredAvailabilityZones` are not declared.

- **src/analyzer/drift-principal-normalize.ts** - IAM principal-FORM canonicalization (#1515): AWS renders a principal as either its ARN or its `AROA…` / `AIDA…` unique id. Pure shape detection walks only `Principal` / `NotPrincipal` positions; one lookup goes through an injected `PrincipalUniqueIdResolver`. BOTH sides become the ARN form, only for a pair PROVEN equal: a missing `iam:GetRole` leaves the drift REPORTED. A JSON STRING policy is not rewritten.

- **src/utils/ip-protocol.ts** + **src/analyzer/drift-protocol-normalize.ts** - EC2 security-group `IpProtocol` VALUE canonicalization (#1643). The rename table + `canonicalizeIpProtocolValue` live in `src/utils/` (two layers consume them); the analyzer module owns only WHERE they apply.
  - The set is CLOSED: `1`→`icmp`, `6`→`tcp`, `17`→`udp`, `58`→`icmpv6`, NAMES matched case-insensitively but only those four, so it can never make two different values compare equal. `canonicalizeIpProtocols` is scoped by the CLOSED `IP_PROTOCOL_PATHS` table, never a walk for any `IpProtocol` key.
  - `canonicalizeIpProtocolValue` is ALSO consumed by `sg-rule-identity.ts`'s `sgProtocolKey` (re-exported by `sg-support.ts`), giving the standalone-rule physicalId lookup, `reconcileSgRules` and `applySecurityGroupRuleDiff` ONE definition of protocol identity; without it the readback lookup misses AWS's spelling and the resource reads "drift unknown" forever. The DIFF side folds the same way (`canonicalizeDesiredProperties`), since `IpProtocol` is create-only there.
