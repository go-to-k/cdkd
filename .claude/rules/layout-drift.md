# Key files - cdkd drift

Analyzer: [layout-analyzer.md](layout-analyzer.md). CLI: [layout-cli.md](layout-cli.md). Secrets: [layout-deployment-secrets.md](layout-deployment-secrets.md). Index: [code-layout.md](code-layout.md).

## Important Files

- **src/cli/commands/drift.ts** - `cdkd drift [<stack>...]`. State-driven, no synth: reads S3 state, asks each provider's optional `readCurrentState`, compares through `drift-calculator.ts`. Exit codes: 0 clean; 1 drift or error; 2 clean but a comparison was INCOMPLETE, or a partly failed `--revert`.
  - The baseline holds unresolved `{{resolve:...}}` and the readback plaintext, so `resolveStateSecretExpressions` re-resolves it for COMPARISON ONLY, and again in `runRevert` before `provider.update` ([#2108](https://github.com/go-to-k/cdkd/issues/2108)).
  - A reference routes to the region that must ANSWER for it, not the stack's: `resolveDriftLeafByRegion` classifies the WHOLE leaf before any fetch via `classifyReplaySecretRegion`, re-exported by `rollback-executor.ts` so the two commands cannot disagree, then routes `named-region` through a per-STACK `DriftSecretResolvers`.
  - `logicalId` / `consumerRegion` / `producerRegions` are REQUIRED options; a default silently verdicts `local` or refuses everywhere. On `ambiguous`, detection falls back to the UNRESOLVED baseline and clears the `secrets` map; revert returns BEFORE `provider.update`.
  - `notCompared` is a MEMBER of the outcome union, so `clean` means compared-and-matched and CI gates on `notCompared.length === 0`. `matchOutcome` is a mapped type over the union's `kind`, so a new variant is a compile error everywhere. The exit trigger is a STRICT SUBSET of the roll-up, `outcomeExitSignal` excluding `'unresolvedToken'`.
  - `redactDriftChanges` is the one redaction choke point behind the report, `--json` and `--accept`; it is keyed on PATH as well as value and runs BEFORE the clean/drifted decision. Its rules constant follows the DESTINATION ([#2939](https://github.com/go-to-k/cdkd/issues/2939)): `STATE_SOURCED_BASELINE_RULES` into `observedProperties`, `STATE_SOURCED_READBACK_RULES` into `properties`, where a mask must never land. The revert's narrowing write uses the readback family, never `STATE_DERIVED_RULES`.
  - An ABSENT `awsValue` at the EXACT secret leaf is DROPPED (`secretPaths.has(path)`, not the ancestor-matching `isSecretBearingPath`); a SURVIVING token does NOT mark its path secret-bearing.
  - `preserveLiveValuesAtUnresolvedTokens` runs BEFORE `provider.update`, only on a WHOLE-token leaf, pairing array elements via `pairedLiveItems`, not by index; a refusal KEEPS the token.
  - `--accept` refuses a masked VALUE and a masked PATH via one `acceptRefusalReason` predicate shared with `printAcceptPlan`, keyed off a `maskedPaths` SET that also tells `runRevert` which subtrees it cannot overlay. `observedBaselineRefused` (v10) skips both write paths but is still compared ([#2944](https://github.com/go-to-k/cdkd/issues/2944)).
  - Every command that interpolates a STACK NAME goes through `stackCommandFor` (go-to-k/cdkd#3307): sanitize-and-compare, cap, shell-quote, refuse a name the command would read as an option or a pattern, and print it LAST on a labelled line — withheld entirely rather than spelled differently. `stackIdentityLine` puts the identity on its own gated line beside it, and **every value in a block that carries a labelled line goes through `blockText`** — `ident` / `awsText` / `literal`, enforced by the argument type — since any raw value above such a line forges one, not just the name. **Not every pasteable command here**: the lock path prints `cdkd force-unlock` from `buildForceUnlockCommand` (`lock-contention-message.ts`), which applies the sanitize + exactness + quoting rules through its own code — but NO leading-`-` or cap gate, while `force-unlock` carries `commonOptions` / `stateOptions` / `stackOptions` (go-to-k/cdkd#3436). The class rule is in [lock-contention-message.md](lock-contention-message.md).
  - `buildRevertNewProperties` overlays each drifted subtree onto the AWS snapshot, but `mergeTagListForRevert` keeps service-authored tags and `preserveUntemplated` merges untemplated paths in only when `observedProperties` is absent.

- **src/analyzer/drift-calculator.ts** - State-vs-AWS property comparator. Descends only into keys present in state, so AWS-managed fields cdkd never set cannot surface as drift. `deepEqual` is JSON-roundtrip equality.
  - `ignorePaths` has two sources: `undeclaredEmptyObservedKeys` (an undeclared top-level key captured EMPTY) and `getDriftUnknownPaths`, called with the resource's state `properties` so an unreadable path is scoped per resource. On an ABSENT bag, default to COMPARING.
  - LAST in the chain is the provider's `canonicalizeDriftProperties`, applied to BOTH sides — the seam for a difference no PATH can name, a member of an ARRAY ELEMENT. No `side` argument on purpose; pure, identity-returning when inapplicable. **`--accept` is NOT symmetric with it**: it writes `awsValue` from the CANONICALIZED bags, so a stripping canonicalizer persists the stripped shape.

- **src/analyzer/drift-normalize.ts** - Order normalization on BOTH sides: `canonicalizeTagListsDeep` sorts any `{Key,...}[]` by `Key`, `canonicalizeIdArraysDeep` any array of AWS ids or ARNs. Every object arm here, in `drift-principal-normalize.ts` and `cc-api-strip.ts` rebuilds onto `nullPrototypeRecord()` and returns a non-plain value by IDENTITY ([#3121](https://github.com/go-to-k/cdkd/issues/3121)).
  - Both declared path lists share ONE matcher, the exported `matchesPathPrefix`, which `isIgnoredPath` aliases. A plain entry declares a SUBTREE; `LEAF_ONLY_PATH_SUFFIX` (`[]`) claims the path ALONE, since this walk descends into array elements while `isIgnoredPath` never crosses one.
  - Declare an unordered path HERE, never by sorting inside `readCurrentState`: this runs on BOTH sides, so a read-side-only sort MANUFACTURES drift on the `properties` fallback baseline. Declaring an ORDER-SIGNIFICANT list hides real drift — why `KeySchema`, FSx `DnsIps` and ElastiCache `PreferredAvailabilityZones` are not declared.

- **src/analyzer/drift-principal-normalize.ts** - IAM principal-FORM canonicalization ([#1515](https://github.com/go-to-k/cdkd/issues/1515)): AWS renders a principal as either its ARN or its `AROA…` / `AIDA…` unique id. Shape detection is pure and walks only `Principal` / `NotPrincipal` positions, never a `Condition` value; the one lookup goes through an injected `PrincipalUniqueIdResolver`. It rewrites BOTH sides to the ARN form and collapses only a pair PROVEN equal, so a missing `iam:GetRole` leaves the drift REPORTED. A policy held as a JSON STRING is not walked.

- **src/utils/ip-protocol.ts** + **src/analyzer/drift-protocol-normalize.ts** - EC2 security-group `IpProtocol` VALUE canonicalization ([#1643](https://github.com/go-to-k/cdkd/issues/1643)). The rename table + `canonicalizeIpProtocolValue` live in `src/utils/` (two layers consume them); the analyzer module owns only WHERE they apply.
  - The set is CLOSED: `1`→`icmp`, `6`→`tcp`, `17`→`udp`, `58`→`icmpv6`, NAMES matched case-insensitively but only those four, so it can never make two different values compare equal. `canonicalizeIpProtocols` is scoped by the CLOSED `IP_PROTOCOL_PATHS` table, never a walk for any `IpProtocol` key.
  - `canonicalizeIpProtocolValue` is ALSO consumed by `ec2-provider.ts`'s `sgProtocolKey`, giving the standalone-rule physicalId lookup, `reconcileSgRules` and `applySecurityGroupRuleDiff` ONE definition of protocol identity; without it the readback lookup misses AWS's spelling and the resource reads "drift unknown" forever. The DIFF side folds the same way (`canonicalizeDesiredProperties`), since `IpProtocol` is create-only there.
