## Important Files

- **scripts/gen-enrichment-coverage.ts** + **docs/_generated/enrichment-coverage.{json,md}** - CC-API enrichment-coverage matrix + CI critic (`vp run gen:enrichment-coverage` / `vp run audit:enrichment-coverage:check`; CI fails on drift AND on a pure-CC latent gap). Makes the enrichment-gap class (#844 / #864 / #865 / #866) non-regressing.
  - Parses the `enrichResourceAttributes` switch in `src/provisioning/cloud-control-provider.ts` via the TS Compiler API (per-`case` `enriched['Attr']` keys; flat keys like `Endpoint.Address` matched to the nested readOnly prop), cross-references each type's `readOnlyProperties` from the cached CFn schema fixtures (`tests/fixtures/cfn-schemas/*.json`).
  - Buckets: `enriched` / `no-computed-attr` / `sdk-fallback-gap` (gap on an SDK-backed type, only exposed on the #614 CC-fallback path — informational) / `unenriched-computed` (gap on a pure-CC type — the real bug class; the ONLY bucket `--check` hard-fails on).

  - Seed `ENRICHMENT_ALLOW_LIST`: `AWS::MSK::Cluster` (Arn == primaryIdentifier) + `AWS::Elasticsearch::Domain` (Tier-3 non-provisionable). Classifier unit-tested (`tests/unit/scripts/gen-enrichment-coverage.test.ts`). NO AWS integ (pure static analysis).
- **scripts/gen-sdk-attr-coverage.ts** + **docs/_generated/sdk-attr-coverage.{json,md}** - SDK-provider ARN/URL attribute-coverage matrix + CI critic (`vp run gen:sdk-attr-coverage` / `vp run audit:sdk-attr-coverage:check`; CI fails on drift AND on an unresolvable Arn/Url attribute). SDK-side sibling of `gen-enrichment-coverage.ts`. Makes the #1179 GetAtt-key class (ARN recorded under a non-CFn key) non-regressing. Filed as issue #1187.
  - Why it matters: cross-resource `Fn::GetAtt` reads cached `resource.attributes[<CFnName>]` in `IntrinsicFunctionResolver.constructAttribute` (never calls a provider's `getAttribute`), and a `*Arn`/`*Url` name under the wrong key HARD-FAILS the resolver's shape guard (#1179 stored `Arn` not `AgentRuntimeArn`, breaking a `CfnOutput`).
  - Parses via the TS Compiler API: (a) each provider's stored attribute keys (`collectStoredAttributeKeys`, object-literal + element-access-assignment keys; a `case '<Attr>':` label in `getAttribute` is deliberately NOT collected, so a provider handling the ARN only there is still flagged) — pooled per FILE, not per method (a provider may build attributes in a `buildAttributes()` helper, #1179), so ANY one of create / update / import literals classifies the type `cached`; per-path binding belongs in the provider's own unit suite, the file-level false-negative documented in the function's JSDoc; (b) `handledProperties` maps; (c) the `constructAttribute`-referenced type set.
  - An `Arn`/`Url` read-only attribute (minus `primaryIdentifier`) is a `gap` iff NEITHER cached NOR `constructAttribute`-handled NOR allow-listed. Scoped to `Arn`/`Url` because those are the ONLY suffixes the guard hard-fails on (non-ARN attrs warn-and-fallback and are legitimately uncached).
  - `SDK_ATTR_ALLOW_LIST` is EMPTY and that is its green state: every entry was retired by the mechanism working — `AWS::Lambda::EventSourceMapping.EventSourceMappingArn` (#1190) and `AWS::RDS::DBSubnetGroup.DBSubnetGroupArn` / `AWS::SSM::Parameter.Arn` (#1800 re-capture, fixed #1824) by caching the ARN (the critic verifies each stays cached); `AWS::SNS::Subscription.Arn` (NOT-A-BUG: physicalId IS the ARN) by the #1694 `primaryIdentifier` capture, which filters before the allow list. Re-adding an entry needs a rationale and, for a real gap, a tracking issue.
  - Unit-tested incl. a real-repo coverage floor (`tests/unit/scripts/gen-sdk-attr-coverage.test.ts`). NO AWS integ (pure static analysis).
- **scripts/gen-update-wrap-coverage.ts** + **docs/_generated/update-wrap-coverage.{json,md}** - SDK-provider `update()` error-wrapping coverage matrix + CI critic (`vp run gen:update-wrap-coverage` / `vp run audit:update-wrap-coverage:check`; CI fails on drift AND on a non-allow-listed gap). Third member of the codegen'd-critic family. Makes the "`update()` leaves AWS SDK errors unwrapped" class non-regressing — found twice by review, never by a test (#1263 -> PR #1265; #1267 -> PR #1268). Filed as issue #1269.
  - Scans `src/provisioning/providers/*.ts` PLUS `src/provisioning/cloud-control-provider.ts` (widest-coverage provider, one directory up, initially missed). Interprocedural within one class: walks from public `update()` with a `protected` flag; sets it inside any `try` whose `catch` raises a `ProvisioningError` — ALL THREE spellings count: literal `throw new ProvisioningError(...)`, throw-form FACTORY `throw this.wrapError(...)`, and STATEMENT-form `this.handleError(error, ...)` with no `throw` (CloudControlProvider's shape; missing it silently disabled the pass-through check there).
  - A genuinely SWALLOWING `catch` (log-and-continue) also sets the flag; a conditional re-throw, a `return Promise.reject(...)`, or a statement call to a `never`-returning helper are NOT swallows. A `never` return alone does not make a wrap factory; nor does a `new ProvisioningError` in a nested closure the method never returns. Follows `this.x()` into class members (arrow-function class properties included); reports any `.send(...)` reached with the flag clear; an unresolvable callee surfaces as `unresolved-callee`, never a silent `no-aws`. Delegation-following is load-bearing: both real shapes need it (the #1268 boundary-wrapper — wrap in `update()`, sends in `applyUpdate()` — and the inverse `s3-tables` shape), and a brace-matching grep without it produced a confirmed false positive.
  - Paired invariant (PR #1268): a wrapping `catch` that can capture a control-flow typed error — raised as `throw` OR `return Promise.reject(new ...)` (9 real sites; a throw-only match left them uncovered) — MUST re-throw the CAUGHT BINDING (`if (error instanceof CdkdError) throw error;`). A positive `instanceof` test that throws anything else is the #1268 defect itself; the negated form is the inverse shape — both rejected. `CONTROL_FLOW_THROW_CLASSES` (blocking): `ResourceUpdateNotSupportedError` (behavior changes when swallowed — the deploy engine matches it by class to fall back to replacement) + `ProvisioningError` (promoted by #1272; adding a class is only safe when the tree is already free of it). Kept SEPARATE from `TYPED_PASSTHROUGH_CLASSES` (accepted guards), where being generous is always safe. The pass-through may live in a delegated throw-helper (`handleError`), and a throw-form factory may `return` the typed error for the caller to throw (`lambda-microvm-image`'s `wrapError`) — both count; a `return` inside a STATEMENT-form helper does not (that swallows).
  - Buckets: `wrapped` / `no-aws` / `gap` (blocks) / `unguarded-wrap` (blocks) / `allow-listed` (real gap deliberately non-blocking, kept VISIBLE rather than relabelled `wrapped`) / `unresolved-callee` (visible, non-blocking).
  - `UPDATE_WRAP_ALLOW_LIST` keyed `Class#method` via `allowKey()` so one entry cannot silence a NEW gap in the same class; EMPTY as of #1270 (the 5 introduction-time gaps — EC2 / ELBv2 / Firehose / Kinesis stream-consumer / S3 Tables — all fixed with the #1268 boundary-wrapper shape; removing the entries is what made the critic block re-regression).
  - Unit tests (`tests/unit/scripts/gen-update-wrap-coverage.test.ts`): each shape + real-repo floors, incl. the EXACT `no-aws` class set pinned by name (a `>= 1` floor would let a lost delegation edge drop a class into `no-aws` silently), assertions that `unresolved-callee` AND `allow-listed` are both zero, a fence that the five #1263/#1267-fixed providers still classify `wrapped`, and a stale-allow-list-entry check. NO AWS integ (pure static analysis).

- **scripts/gen-handled-property-wiring.ts** + **docs/_generated/handled-property-wiring.{json,md}** - `handledProperties` WIRING coverage matrix + CI critic (`vp run gen:handled-property-wiring` / `vp run audit:handled-property-wiring:check`; CI fails on drift AND on a non-allow-listed gap). Widening the default is issue [#2276](https://github.com/go-to-k/cdkd/issues/2276).
- **scripts/check-provider-update-context.ts** - SDK-provider `UpdateContext` declaration fence (issue [#2613](https://github.com/go-to-k/cdkd/issues/2613) remedy 1), enforced by `tests/unit/scripts/provider-update-context.test.ts` (no `vp run` task and no `ci.yml` step — the unit test IS the CI enforcement, as with `check-verification-depth-rule.ts` and `check-source-control-bytes.ts`; the CLI exists so `node scripts/check-provider-update-context.ts` prints the remedy-2 worklist).
  - **What it enforces.** `ResourceProvider.update`'s `context` parameter is OPTIONAL, so a provider that does not declare it compiles, `deploy-engine.ts` / `rollback-executor.ts` (both replay arms) / `drift --revert` keep passing `expectedRegion` (issue #2301 item 1), and `assertRegionMatch` — the UPDATE twin of the DELETE-path guard — never runs for that provider. Nothing reds: the type allows the omission and the count drifts DOWN every time a provider is scaffolded from a template that omits the parameter. `OMITS_UPDATE_CONTEXT` records the omitting set BY NAME, so it can only move deliberately, in either direction, and doubles as the remedy-2 worklist.
  - **Population, and why it is not the issue's.** Measured 2026-09-06: 82 files, **85 provider classes, 18 declaring / 67 omitting** — where issue #2613's own `grep "async update("` reported 17 / 60 over 77 FILES. Both corrections come from the population rule: the unit is the CLASS (`glue-provider.ts` declares seven providers) and membership is `create` + `update` + `delete` being present rather than the OPTIONAL `implements ResourceProvider` keyword or the OPTIONAL `async`, which is what hid `ServiceDiscoveryProvider` (non-`async`, DECLARES the parameter) and `EFSProvider` (non-`async`, omits it).
  - **Declaring is structural, and everything else is REFUSED.** The 6th parameter must be a plain identifier — a REST element is refused by a SEPARATE `dotDotDotToken` test, because a rest element's name is an identifier too — whose annotation is `UpdateContext`, or a union of it with `undefined` / `null`, bound by an import whose resolved specifier ends with the module [src/types/resource.ts](../../src/types/resource.ts), matched INCLUDING the path separator in front of `types`. That separator is load-bearing: without it the suffix also accepted a hypothetical sibling module named `mytypes`, which review proved classified a provider as declaring against a type this repo does not own. Every other shape is a REFUSAL, not a bucket — including every FAIL-OPEN shape two review rounds proved (each had exited `rc=0` with the class in NEITHER `classes` nor `refusals`) and the member-name spellings legal in that position. That set is pinned as named `SELF_PROBE_CASES` in the checker and its suite, which is where to read it; a second copy here would drift against the arm it names. Grep rather than assume: the subdirectory and `.mts` / `.cts` refusals are separate `it()` arms, the private-identifier spelling only in the checker.
  - **Only a CANDIDATE can be refused, and the gate is calibration.** A class is a candidate when it says `implements ResourceProvider`, declares at least TWO of the three (a provider missing only `update` still has `create` and `delete`), or names `update` at all — in any spelling, readable or not. An earlier revision gated only two of the five arms on "declares at least one of the three", and review proved that refused five shapes no provider could ever be: a `static create()` factory, a `get create()` accessor, an options bag with `delete = true`, `class LruCache extends Map { delete() }` and `class WidgetFactory extends BaseFactory { create() }` — the last two through an arm that WAS gated, so gating the other three would not have helped. Appending that cache to a real provider file made the shipped binary exit 1 and tell the author to extend the checker.
  - **The limit that buys, named rather than claimed away.** A real provider outside the gate — inheriting `update` from a base, declaring fewer than two of the three itself, never naming `update` — is IGNORED. `HostedZoneNameNotFoundError` in `route53-provider.ts` is the in-tree shape it protects (it extends `ProvisioningError`; no class under `providers/` extends `Error` directly). The RUNTIME half covers such a provider once REGISTERED, where it fails "every registered provider is one the source scan found". It does NOT cover one that is reachable without being registered — `ProviderRegistry` constructs `CustomResourceProvider` in its own constructor — so that residual is bounded by inspecting that one file, and the suite pins the set by name in `UNREGISTERED_PROVIDER_CLASSES`.
  - **What it does NOT claim**, stated in the script header: declaring the parameter is not CALLING the guard (remedy 2 — no signature check can see it), and `CloudControlProvider` is out of scope (defined outside `providers/`, and already consuming `expectedRegion`).
  - **Two independent instruments, which must agree.** Collapse toward ZERO: `FLOORS` (files / classes / declaring) plus a hard failure on any parse diagnostic. Collapse toward GREEN: `SELF_PROBE_CASES`, fixed sources with known verdicts INCLUDING refusals, run before the tree is read, with `CDKD_SELF_PROBE_FORCE_FAIL=1` proving the SPAWNED binary still consults them; each REFUSAL case names a substring of ITS OWN arm, since a bare `refused` verdict cannot tell the arms apart. Their count is pinned as a literal by the unit suite rather than restated here. Plus a RUNTIME witness: `registerAllProviders` is run against a recording stand-in and every provider OBJECT's `update.length` must agree with the source verdict — a fact no formatting, comment or `async` keyword can fake, and the only instrument that sees a provider inheriting `update()` from a base. The unregistered-class set is pinned by name. No failure probe writes to `src/` — mutating probes run against a scratch COPY through the `--providers-dir=` seam. NO AWS integ (pure static analysis).
