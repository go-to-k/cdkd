# Key Files and Directories - scripts and docs/_generated

Index of every area: [code-layout.md](code-layout.md).

## Important Files

- **scripts/gen-enrichment-coverage.ts** + **docs/_generated/enrichment-coverage.{json,md}** - CC-API enrichment-coverage completeness matrix + CI critic (`vp run gen:enrichment-coverage` / `vp run audit:enrichment-coverage:check`; CI fails on drift AND on a pure-CC latent gap). Makes the enrichment-gap bug class (#844 / #864 / #865 / #866) non-regressing. The generator parses the `enrichResourceAttributes` switch in `src/provisioning/cloud-control-provider.ts` via the TypeScript Compiler API (per-`case` `enriched['Attr']` keys, flat-keys like `Endpoint.Address` matched to the nested readOnly prop `Endpoint`), cross-references each type's `readOnlyProperties` from the cached CFn schema fixtures (`tests/fixtures/cfn-schemas/*.json`), and classifies each into `enriched` / `no-computed-attr` / `sdk-fallback-gap` (gap on an SDK-backed type — only exposed on the #614 CC-fallback path, informational) / `unenriched-computed` (gap on a pure-CC type with no SDK provider — the real bug class). The `--check` critic hard-fails ONLY on `unenriched-computed`. A readOnly prop that is the type's `primaryIdentifier` is auto-classified not-a-gap (the resolver's physicalId fallback resolves it); `scripts/refresh-cfn-schemas.mjs` captures `primaryIdentifier` into the fixtures for this. The seed `ENRICHMENT_ALLOW_LIST` carves out `AWS::MSK::Cluster` (Arn == primaryIdentifier) + `AWS::Elasticsearch::Domain` (Tier-3 non-provisionable). Classifier is unit-tested (`tests/unit/scripts/gen-enrichment-coverage.test.ts`). NO AWS integ (pure static analysis / codegen).
- **scripts/gen-sdk-attr-coverage.ts** + **docs/_generated/sdk-attr-coverage.{json,md}** - SDK-provider ARN/URL attribute-coverage matrix + CI critic (`vp run gen:sdk-attr-coverage` / `vp run audit:sdk-attr-coverage:check`; CI fails on drift AND on an unresolvable Arn/Url attribute). The SDK-provider-side sibling of `gen-enrichment-coverage.ts` (which only audits the CC provider's `enrichResourceAttributes` switch). Makes the #1179 GetAtt-key bug class (SDK `create()`/`update()` records an ARN under a non-CFn key) non-regressing. Output / cross-resource `Fn::GetAtt` reads the cached `resource.attributes[<CFnName>]` in `IntrinsicFunctionResolver.constructAttribute` (which never calls a provider's `getAttribute`), so an ARN stored under the wrong key is missed and — for a `*Arn`/`*Url` name — HARD-FAILS the resolver's shape guard (#1179 stored `Arn` not `AgentRuntimeArn`, breaking a `CfnOutput`). The generator parses (a) each provider's stored attribute keys (`collectStoredAttributeKeys`, object-literal + element-access-assignment keys — a `case '<Attr>':` label in `getAttribute` is deliberately NOT collected, so a provider handling the ARN only in `getAttribute` is still flagged). Those keys are pooled per FILE, not per method, because a provider may build attributes in a `buildAttributes()` helper (#1179) — so ANY ONE of a provider's create / update / import literals is enough to classify its type `cached`, and this critic cannot tell you WHICH path records the ARN. Per-path binding belongs in the provider's own unit suite; the file-level false-negative is documented in the function's own JSDoc, (b) the `handledProperties` maps (which types each provider serves), and (c) the set of types `constructAttribute` references, all via the TS Compiler API. An `Arn`/`Url` read-only attribute (minus `primaryIdentifier`) is a `gap` iff it is NEITHER cached by the provider NOR the type is `constructAttribute`-handled NOR allow-listed — scoped to `Arn`/`Url` because those are the ONLY suffixes the resolver's guard hard-fails on (non-ARN attrs warn-and-fallback and are legitimately left uncached). The `SDK_ATTR_ALLOW_LIST` is now EMPTY, and that is its green state rather than a broken one — every entry it ever held was retired by the mechanism working as designed. `AWS::Lambda::EventSourceMapping.EventSourceMappingArn` (KNOWN GAP, #1190) and the `AWS::RDS::DBSubnetGroup.DBSubnetGroupArn` / `AWS::SSM::Parameter.Arn` pair (KNOWN GAPs added by the #1800 re-capture, fixed in #1824) were each retired by CACHING the ARN, and the critic now verifies each stays cached; `AWS::SNS::Subscription.Arn` (a NOT-A-BUG: the physicalId IS the subscription ARN) was retired by the #1694 `primaryIdentifier` capture, which filters the attribute out before the allow list is consulted. Re-adding an entry is a decision needing a rationale and, for a real gap, a tracking issue. Classifier + parsers are unit-tested (`tests/unit/scripts/gen-sdk-attr-coverage.test.ts`, incl. a real-repo coverage floor). NO AWS integ (pure static analysis / codegen). Filed as issue #1187.
- **scripts/gen-update-wrap-coverage.ts** + **docs/_generated/update-wrap-coverage.{json,md}** - SDK-provider `update()` error-wrapping coverage matrix + CI critic (`vp run gen:update-wrap-coverage` / `vp run audit:update-wrap-coverage:check`; CI fails on drift AND on a non-allow-listed gap). Third member of the codegen'd-critic family alongside `gen-enrichment-coverage.ts` (CC attribute enrichment) and `gen-sdk-attr-coverage.ts` (SDK ARN/URL attribute keys). Makes the "`update()` leaves AWS SDK errors unwrapped" class non-regressing — a defect found TWICE by review and never by a test (#1263 -> PR #1265 `LambdaUrlProvider`; #1267 -> PR #1268 EventBridge bus / SNS topic / Lambda event-source / Logs log-group). Scans `src/provisioning/providers/*.ts` PLUS `src/provisioning/cloud-control-provider.ts` (the widest-coverage provider, which lives one directory up and was initially missed). The analysis is **interprocedural within one class**: it walks from the public `update()` carrying a `protected` flag, sets the flag inside any `try` whose `catch` raises a `ProvisioningError` — counting ALL THREE spellings: the literal `throw new ProvisioningError(...)`, the throw-form FACTORY `throw this.wrapError(...)`, and the STATEMENT-form `this.handleError(error, ...)` with no `throw` keyword at all (`CloudControlProvider`'s shape; missing it made that clause look like a swallow and silently disabled the pass-through check for the widest-coverage provider in the repo) — and also sets it for a genuinely SWALLOWING `catch` (log-and-continue, where no raw error can propagate; a conditional re-throw, a `return Promise.reject(...)`, or a statement call to a `never`-returning helper are NOT swallows). A `never` return alone does not make a method a wrap factory, and a `new ProvisioningError` buried in a nested closure the method never returns does not either, follows `this.x()` calls into the class's own members inheriting the flag (arrow-function class PROPERTIES included), and reports any `.send(...)` reached with the flag clear. An unresolvable `this.x()` callee is recorded and surfaces as `unresolved-callee` rather than silently reporting `no-aws` — sends behind it are unobservable, so a confident green there would be a false clean. Following delegation is load-bearing, not a nicety: both real shapes depend on it (the #1268 boundary-wrapper — wrap in `update()`, sends in a private `applyUpdate()` — and the inverse `s3-tables` shape — bare `update()`, wrapping inside each helper), and a hand-rolled brace-matching grep lacking it produced a confirmed false positive. The critic ALSO enforces the paired invariant PR #1268 established: a wrapping `catch` that can capture a **control-flow** typed error — raised as `throw` OR as `return Promise.reject(new ...)` (9 real sites across ec2 / ecs / apigateway / lambda-layer, which a throw-only match left silently uncovered) — MUST re-throw the CAUGHT BINDING (`if (error instanceof CdkdError) throw error;`) — a positive `instanceof` test that throws anything else is the #1268 defect itself, and the negated `if (!(error instanceof CdkdError)) throw error;` is the inverse shape, so both are rejected. `CONTROL_FLOW_THROW_CLASSES` (blocking) holds `ResourceUpdateNotSupportedError` — which changes BEHAVIOR when swallowed (the deploy engine matches it by class to fall back to replacement) — plus `ProvisioningError`, promoted by #1272 once the last re-labelling site was fixed (swallowing one is cosmetic, but every site is clean so blocking keeps it that way; adding a class here is only safe when the tree is already free of it). It stays a SEPARATE set from `TYPED_PASSTHROUGH_CLASSES` (accepted guards), where being generous is always safe. The pass-through may live in a DELEGATED throw-helper rather than lexically in the catch (`CloudControlProvider`'s `handleError`), and a THROW-form factory may `return` the typed error for the caller to throw (`lambda-microvm-image`'s `wrapError`) — both count; a `return` inside a STATEMENT-form helper does not, since that swallows. Buckets: `wrapped` / `no-aws` / `gap` (blocks) / `unguarded-wrap` (blocks) / `allow-listed` (a real gap deliberately not blocking, kept VISIBLE rather than relabelled `wrapped`) / `unresolved-callee` (visible, non-blocking). `UPDATE_WRAP_ALLOW_LIST` is keyed `Class#method` via `allowKey()` so an entry for one method cannot silence a NEW gap elsewhere in the same class; it is EMPTY as of #1270 — the 5 gaps found on introduction (EC2 / ELBv2 / Firehose / Kinesis stream-consumer / S3 Tables) were all fixed with the #1268 boundary-wrapper shape, and removing their entries is what made the critic verify those fixes and block a re-regression. Unit tests (`tests/unit/scripts/gen-update-wrap-coverage.test.ts`) cover each shape plus real-repo floors — including the EXACT `no-aws` class set pinned by name (a `>= 1` floor would let a class silently drop into `no-aws`, the shape a lost delegation edge produces, while the aggregate `wrapped` floor absorbed it), assertions that `unresolved-callee` AND `allow-listed` are both zero, a fence that the five #1263/#1267-fixed providers still classify `wrapped`, and a stale-allow-list-entry check. NO AWS integ (pure static analysis / codegen). Filed as issue #1269.
- **scripts/gen-nested-key-coverage.ts** + **docs/_generated/nested-key-coverage.{json,md}** - Nested CFn->SDK key-divergence coverage matrix + CI critic (`vp run gen:nested-key-coverage` / `vp run audit:nested-key-coverage:check`; CI fails on drift AND on a non-allow-listed divergence). Fourth member of the codegen'd-critic family (issue #1373). Makes the write-side nested-key silent-drop class non-regressing — the AWS SDK v3 serializer drops unknown keys, so an SDK provider forwarding a nested CFn config blob silently loses every key whose spelling it does not convert; `property-coverage` compares TOP-LEVEL names only, and the class recurred 4 times before tooling (#1165/#1167 ECS casing, #1160 API GW v2, #1304 `MetricTimeZone`, #1370 CloudFront x5). Per declared target (`NESTED_KEY_TARGETS`: CloudFront Distribution, CloudWatch AnomalyDetector, API GW v2 x5, ECS Service / TaskDefinition, CodeBuild Project, S3 Bucket), the critic diffs the fixture's `nestedPropertyPaths` capture (`scripts/refresh-cfn-schemas.mjs` — per-top-level-property nested CHAINS, `$ref`-resolved + per-branch-cycle-guarded, arrays transparent; issue #1464 deepened the original flattened `nestedProperties` capture, which is still emitted for the shape pass and the floor-calibration story) for the provider's OWN `handledProperties` top-levels against the SDK client model member names (`node_modules/<pkg>/dist-types/models/*.d.ts` PropertySignatures via the TS Compiler API), with the provider's AST-level string literals (comments excluded) as evidence of explicit per-key handling. Key style is per-target (`exact` for PascalCase SDK models, `lower-first` for camelCase ECS). Buckets: `same-spelling` / `provider-handled` / `allow-listed` (rationale'd pass-throughs, e.g. the 3 legacy pre-2012 CloudFront members) / `case-divergence` (case-insensitive SDK near-miss — the highest-signal bucket, blocks CI) / `no-sdk-member` (blocks CI) / `no-write-evidence` (blocks CI, issue #1432 — see the WRITE-EVIDENCE pass below). Parser-regression floors: per-target `minNestedKeys` (re-calibrated to the 2-segment PATH unit by #1448 and again to the FULL chain by #1464) + `MIN_SDK_MEMBERS_PER_CLIENT` + `MIN_WRITTEN_MEMBERS_PER_PROVIDER` + per-target `minWrittenMembers` / `minWriteScopes`, so a broken parse fails loudly instead of passing vacuously; stale allow-list entries fail in BOTH modes (an SDK bump that makes an allow-listed key reachable forces the entry's removal). The first run found TWO live bugs fixed in the same PR: CloudFront `OriginCustomHeaders` (never renamed to the SDK's `CustomHeaders` — origin custom headers silently dropped on create AND actively wiped on update by the required-field fill) and ECS TaskDefinition `S3FilesVolumeConfiguration` (SDK member is the irregular all-lowercase-prefix `s3filesVolumeConfiguration`, unreachable by the mechanical first-letter flip — the whole S3 Files volume block was dropped); plus 8 keys resolved by bumping `@aws-sdk/client-cloudfront` / `client-ecs` (members newer than the pinned SDK). Since issue #1378 a SHAPE pass rides the same run: the fixtures additionally capture `definitionShapes` (per CFn definition, member -> terminal type kind, `$ref`-resolved; the top-level block under the reserved `#top` key), the SDK side parses full interfaces with member type kinds (`collectSdkInterfaces` + `wrapperInterfaceNames` — a `Quantity`-bearing interface is a `{Quantity, Items}` wrapper), and two CI-blocking shape buckets cover what the key pass is structurally blind to (the spelling exists SOMEWHERE in the SDK model): `array-vs-wrapper` (a CFn bare-array member whose same-spelled SDK members are all wrapper refs — mechanizes the previously hand-maintained CloudFront `QUANTITY_ITEM_FIELDS` class, so a NEW array member AWS adds flags until wrapped) and `definition-member-missing` (a CFn definition's member same-spelling an SDK member globally but missing from the same-named SDK interface — the `CachedMethods` sibling-vs-nested / `GeoRestriction.Locations` / legacy `S3Origin` class). Shape evidence uses the DOT-SEGMENT-EXPANDED literal set (`'ForwardedValues.Headers'` names both segments); the key pass keeps the strict set. Non-blocking visibility: `ambiguous` shapes + unmatched-definition counts. First shape audit found no live bug — the QUANTITY_ITEM_FIELDS family (13 wrapper re-shapings) and CachedMethods all classify provider-handled, with legacy `S3Origin` the one new allow-list entry (invisible to the key pass because the StreamingDistribution API still carries a same-spelled member). The #1378 rider also gave `refresh-cfn-schemas.mjs` a `--help` / unknown-flag guard (an unrecognized flag previously fell through to a silent FULL ~135-type re-fetch). Issue #1430 added `AWS::S3::Bucket` (190 nested key PATHS at the full-chain unit #1464 introduced — the largest target, ahead of CloudFront Distribution's 173 and ECS TaskDefinition's 142; it was 155 / 121 / 121 at #1448's 2-segment unit and 115 / 121 / 123 under the original de-duplicated-name unit) — the type had been forwarding a dozen nested blobs without a critic since before the #1388 / #1424 lifecycle defects were hand-fixed in PR #1426 — and its first run found `NotificationConfiguration.EventBridgeConfiguration.EventBridgeEnabled` broken in BOTH directions: CFn carries a required boolean while the SDK's block is an EMPTY structure whose PRESENCE enables delivery, so `EventBridgeEnabled: false` silently ENABLED notifications on the write side and `readCurrentState` returned the SDK `{}` shape the CFn-shaped state baseline could never match. Its three allow-list entries (`TableName` / `TableArn` / `TableNamespace`) are the FIRST real instance of the unreachable-definition false positive `classifyTargetShapes` documents — reachable only from silent-drop, Cloud-Control-routed top-levels, so no SDK forwarding path exists to drop them. Issue #1432 added a third, OPT-IN pass — WRITE-EVIDENCE — closing the fact that `same-spelling` is the critic's SILENT bucket and is only sound for a provider that FORWARDS a blob: one that builds a FRESH SDK object naming each member drops any member it never names, spelling agreement notwithstanding (`AWS::CodeBuild::Project` `BuildBatchConfig.BatchReportMode` stayed silent even with every occurrence of the SDK spelling `batchReportMode` renamed away, which is what proved the gap structural). A target setting `freshObjectMapper: true` requires each would-be-`same-spelling` key to ALSO appear as a WRITTEN SDK member name (object-literal property, shorthand property, assignment target incl. the compound `??=` / `||=` / `+=` forms, or `Object.defineProperty(sdk, 'x', {...})` — a READ deliberately does not count, which is what scopes the evidence to the CFn->SDK direction), else `no-write-evidence`. `REVERSE_MAP_FUNCTION_PREFIXES` skips reverse-map bodies by word-boundary PREFIX, because for an `exact`-style target the reverse map's CFn-spelled WRITE would otherwise vouch for the forward mapper — #1393 item 2 one bucket over (measured withdrawal: 8 names from `s3-bucket-provider.ts`, 71 from `codebuild-provider.ts`, 42 from `ecs-provider.ts`; the ECS number is 0 under an exact-name match, which is why the prefix form is load-bearing rather than cosmetic). **Issue #1448 made the whole critic PATH-based and the write evidence SCOPED**, closing the bound #1432 shipped with: evidence used to be a flat per-FILE name set over a de-duplicated key NAME, so a member written anywhere vouched for every key of that spelling (11 of CodeBuild's 55 same-spelling keys had >1 write site, and `BuildBatchConfig.ServiceRole` — the SIBLING of the motivating member — stayed silent when dropped). Now `nestedKeyPathsForTarget` yields one audited unit per (handled top-level, nested key) pair, and `collectWriteEvidence` returns `{ written, scopes, handoffScopes }` where each written PATH maps to the members written directly beneath it (#1448 keyed this by NAME and flattened the whole interior into it; #1464 made both the audited unit and the index a full chain), resolving `this.mapSource(x)` calls, `const` / `let` bindings, `?:` / `??` arms, array elements and `.map(cb)` callbacks (the reach of the #1404 taint walk); a path's terminal member is checked against the scope its FULL PARENT CHAIN maps to (case-folded ONE LEVEL AT A TIME while descending the index — never as a global lowercase union, which would merge the member sets of 80 unrelated `name`/`Name`-style scope pairs on `ecs-provider.ts` — since a CFn->SDK segment spelling is routinely not the mechanical first-letter flip; the TERMINAL member stays an exact compare, in the scope test AND in the SELF case of `isHandoffCovered`), or is credited by a hand-off path PREFIX. `feedsOnlyComparison` additionally denies credit to a literal that only feeds a comparison or a measurement — the write-side twin of `gen-handled-property-wiring`'s diff-is-not-delivery rule. The same reverse-map exclusion now applies to `collectStringLiterals` too (measured free: no key moves into a blocking bucket in either pass), removing the asymmetry where the write pass excluded the read path and the key pass did not. Allow-list entries gained a `passes` dimension (`AllowPass` = `key` | `shape` | `write`, defaulting to `['key','shape']`), so an entry rationale'd for a SHAPE verdict can no longer silently clear a future `no-write-evidence`; lookup is PATH-first, terminal-name-second, and the matched key is recorded on the verdict so staleness stays exact. Floors: per-target `minWrittenMembers` and `minWriteScopes` join `MIN_WRITTEN_MEMBERS_PER_PROVIDER` (default 10), because the name set and the scope index regress independently — a broken value walk leaves every name collected and every scope empty. The scope floor is per-target with NO module default: real-tree non-empty scope counts span 144 (S3) down to 1 (API GW v2, which forwards whole blobs and therefore builds almost no per-member literals), so any shared floor tight enough to fence CodeBuild would false-fire on a correct parse — which is exactly what happened when API GW v2 opted in under #1445 with `minWriteScopes: 1`. The pass is opt-in because the opt-in set was MEASURED, not predicted. **Issue #1445 then taught the collector to follow a WHOLE-BLOB HAND-OFF into a generic key converter**, which is what most of the blind spot actually was: `collectWriteEvidence` now also returns `handoffScopes` (the write PATHS whose value is a whole sub-blob delivered generically), and everything AT OR BENEATH such a path is credited by `isHandoffCovered`'s prefix test. #1445 shipped that fold through the SDK model's own reference graph instead (`reachableSdkMemberNames`, ref + array-element edges), because a flat scope could not express "beneath"; #1464's path keys can, so the prefix test replaced it — strictly tighter, and free of the fold's bare-name union (`Items` reached 217 CloudFront members). `reachableSdkMemberNames` survives only as the `minHandoffPoints` floor. The three steps mirror the #1404 taint walk one level down: SEED (a value read off the DESIRED property bag, `HANDOFF_BAG_PARAM_NAMES` + DECLARATION-scoped taint), PROPAGATE (`?:` / `??` / `||` arms, `const` bindings, spread-only literals, and `this.f(…)` / free-function / SIBLING-MODULE calls — `pascalToCamelCaseKeys` lives in `agentcore-case-convert.ts`, so `loadReport` passes a same-directory `resolveImportSource`), DELIVERY (the callee RETURNS the blob and the value is written; `feedsOnlyComparison` still refuses a diff-only literal). **GENERIC vs SPECIFIC is the whole discrimination**: a callee is generic only when it names NO member — no object-literal property (including the computed-but-literal `{ ['Foo']: v }`), no shorthand, no `o.Foo = …` — anywhere in its body OR in any callee it can reach, so `pascalToCamelCaseKeys` qualifies while `convertContainerDefinitions` (45 named members), `convertLoadBalancers` (4) and CloudFront's spread-and-patch `convertToSdkFormat` (30+) do not. The TRANSITIVE part closes a real hole rather than being tidy: with a body-local test the DELEGATING GUARD `convertLog(cfg) { if (!cfg) return cfg; return this.buildLog(cfg); }` passes — it names nothing and the delivery test is existential, so the `return cfg` arm alone satisfies it — while `buildLog` does the member-naming work; tightening delivery to `.every` instead is NOT an option, because `pascalToCamelCaseKeys` returns `result`, a binding to an empty literal. The test means exactly "names no member", NOT "can only emit keys it read": a FILTERING / RENAME-MAP / PICK converter names nothing and is still credited (recorded as known bound (5); `glue-provider.ts`'s `renameRecordKeys` is that shape one opt-in away, and the bound is pinned by a test that asserts the current, wrong-if-improved behaviour). The credit is bounded to the BLOB rather than the enclosing scope — `ContainerDefinitions` carries both the `LinuxParameters` hand-off and `convertPortMappings`, so a scope-wide wildcard would have hidden a real drop. The property-bag taint root is equally load-bearing: without it CloudFront's disable-then-delete `DistributionConfig: config` (a config read straight off `GetDistributionConfig`) measured as a hand-off and cleared 108 of its 110 findings. A new per-target floor `minHandoffPoints` fences the walk, since it regresses independently of the name set and the scope index — and it counts EXPANDING points (`countExpandingHandoffPoints`), not raw ones: `apigatewayv2-provider.ts` records 35 raw points of which only 3 carry a blob (`CorsConfiguration` / `DefaultRouteSettings` / `JwtConfiguration`), so a raw floor of 20 would have been satisfied by the 32 inert scalar forwards a collapsed walk still emits. The floor is 1, NOT the measured 3, and that is deliberate: at 3 every legitimate provider-side change aborts with "parser regression?" instead of reporting the divergences it causes (measured — all three hand-off probes stopped reaching the classifier), while the collapse mode the floor exists for yields 0. `minWriteScopes: 1` on that target is recorded as fencing NOTHING (its only non-empty scope is `attributes`, a cdkd-internal return field no audited path consults) rather than left looking meaningful, and two new hygiene tests keep both honest: one bands the write floors against their measured yields, the other derives "walk-dependent" by re-classifying with the hand-off points stripped and requires exactly those targets to declare `minHandoffPoints`. **Measured before/after** (would-be `same-spelling` paths with no scoped write evidence, re-measured at #1464's full-chain unit and again after #1474's builder recognizer): CodeBuild 0/95 -> 0/95 -> 0/95, API GW v2 13/13 -> **0/13** -> **0/13**, ECS TaskDefinition 30/136 -> **0/136** -> **0/136**, ECS Service 45/56 -> **0/56** -> **0/56**, CloudWatch AnomalyDetector 30/30 -> 3/30 -> **0/30**, S3 130/152 -> 125/152 -> 98/152, CloudFront 162/162 -> 162/162 -> 162/162 -> **0/162** (#1475's spread recognizer, the fourth stage); 410 -> 290 -> 260 -> 98 total. The opted-in set is NOT enumerated here — read `freshObjectMapper: true` off `NESTED_KEY_TARGETS` (the generated matrix's `fresh-object targets audited` count is the same number), because a hand-copied list goes stale on every opt-in and this one had already drifted past `AWS::S3::Bucket` (#1540) and the three AppSync targets (#609 / #1597) before `AWS::Glue::Database` (#1807) joined. Every opt-in's before/after measurement is recorded in the script header, which is where the decision per target lives. ECS's six SILENT-DROP residuals were REAL and the walk uncovered them — `ContainerDefinitions.PortMappings.ContainerPortRange` (issue #1472) and `LoadBalancers.AdvancedConfiguration` + its four members, the blue/green block (issue #1473) — both fixed, which is what unblocked the ECS opt-in. **Issue #1474 added the third recognizer, the BUILDER idiom** (`const mapped = {}; mapped.Foo = …; params.Configuration = mapped;` — the members ARE written, per member, on the forward path; only their AST location differs from a literal's, so `resolveLiterals` stopped at the empty seed): `resolveBuilders` / `walkBuilderAt` credit the assigned members at the SAME path the literal case gets, at full depth (`out.Rule.DefaultRetention = { Mode }` opens the intermediate scopes rather than flattening). A BUILDER requires an OBJECT-LITERAL initializer (the object's identity must be this file's — `const out = makeThing()`, `let out;` seeded later, and a binding REASSIGNED as a whole are all refused), DECLARATION IDENTITY rather than the bare name for every assignment (deliberately not inheriting known bound (3)), and the credit bounded to the BUILDER rather than the enclosing scope (the `ContainerPortRange` trap one recognizer over). Declaration identity required fixing `declarationOf` itself: it searched the nearest FUNCTION scope, descended fully into nested functions, and took the first textual match, so bound (3) reached INSIDE one function — two same-named `const cfg` builders in different `if` arms merged their member sets (each vouching for the other's blob), and a nested arrow's `cfg` declared textually first captured the enclosing function's own (outer member falsely flagged, inner falsely cleared). It now resolves outward through BLOCK scopes, which is what `const`/`let` actually obey; both shapes are pinned by tests, and the sibling-METHOD case that worked from the start is kept as a separate test so the two are not confused. The recognizer also WIDENS known bound (4): a reverse SDK->CFn helper not named `readCurrentState*` that uses the builder idiom (`s3-bucket-provider.ts`'s `readLifecycle`, `ecs-provider.ts`'s `volumesToCfn`) now contributes a populated scope where it used to contribute an empty seed — inert today (S3 is out; ECS is `lower-first`) but the direction that bites when the `exact`-style S3 target opts in, so widening `REVERSE_MAP_FUNCTION_PREFIXES` to a suffix match belongs to #1495. Delivery stays the caller's question — the builder walk runs only from `recordAt`, i.e. only at a write site the `feedsOnlyComparison` / `isComparisonOnlyLiteral` rules have already filtered — so a builder that is never handed to a write, or handed only to a diff, is never credited. The recognizer is MONOTONE (it only adds scoped members), so no target gained a finding; it took CloudWatch AnomalyDetector 3 -> **0** (opted in, with `minWrittenMembers: 12` / `minWriteScopes: 2` / `minHandoffPoints: 1` measured against 17 / 4 / 4) and S3 125 -> 98. Its bounds are recorded as known bound (8) and pinned by tests: computed keys, `Object.defineProperty` onto a builder, and non-literal / late-seeded bindings are all refused (under-crediting, loud), while the walk is flow-INSENSITIVE so a post-delivery assignment still counts (over-crediting, the statement-granularity twin of bound (1)). **Issue #1475 added the fourth recognizer, the SPREAD-AND-PATCH forwarder** (`const result = { ...config }` plus ~30 named patches — the shape the genericity test rejects on the patch names): a literal spreading a BAG-DERIVED seed registers a hand-off at its write path, BOUNDED by the keys the function `delete`s off the binding (`ProviderWriteEvidence.handoffExclusions`; delete keys resolve through the `Object.entries(TABLE)` / literal-array loop shapes, an unresolvable key refuses the registration fail-closed, and `deliversWholeBlob` now refuses a deleted-from binding so the bounded path takes over). - **scripts/check-withretry-interrupt.ts** - Interrupt-threading critic for `withRetry` call sites under `src/provisioning/**` (issue [#2053](https://github.com/go-to-k/cdkd/issues/2053)), run by `vp run audit:withretry-interrupt:check` (`cache: false`) with an explicit `ci.yml` step, and unit-tested by `tests/unit/scripts/withretry-interrupt.test.ts`. `withRetry` is the ONLY wait in cdkd that consults an interrupt DURING a backoff — the deploy engine, `destroy-runner.ts` and `rollback-executor.ts` poll only BETWEEN operations — so a call that omits `isInterrupted` / `onInterrupted` leaves Ctrl-C dead for its whole schedule, and on the destroy path `withResourceTimeout` has by then abandoned the promise, so the loop keeps issuing writes behind a run the user was told had ended. `docs/provider-development.md` already called the pair mandatory; the count at filing was 11 sites and ONE of them threaded, which is what turned a stated convention into an enforced one. It requires both names as DIRECT properties of an options OBJECT LITERAL: half a pair is a defect (a missing `onInterrupted` degrades to a bare `Error('Interrupted')` naming no resource; a missing `isInterrupted` means the other half is never called) and a conditional spread does not count, since it reads as threading to a reviewer while being absent whenever its guard is falsy. An options bag it cannot READ is reported as `opaque` rather than skipped, because a site a checker cannot see is a site it cannot guard. Its own two failure modes are defended separately, mirroring the sibling critic above: **collapse toward zero** by FLOORS on files scanned / sites found / sites threaded / files carrying a site, plus a hard failure on any file that does not parse (a parse failure contributes zero sites, which reads exactly like a clean file); **collapse toward green** by eleven fixed self-probes with known verdicts INCLUDING failing ones, analyzed before the real tree is read. - **scripts/check-local-reachability.ts** - Symbol-level reachability critic for `src/local/**` (issue [#2228](https://github.com/go-to-k/cdkd/issues/2228)), run by `vp run audit:local-reachability:check` (`cache: false`) with an explicit `ci.yml` step, and unit-tested by `tests/unit/scripts/local-reachability.test.ts`.
  - **What it enforces.** Every exported VALUE symbol with a cdkd-authored body under `src/local/**` must be transitively reachable from a shipped entry point (`src/index.ts` / `src/cli/index.ts`, i.e. `pack.entry` in `vite.config.ts`), or carry `@no-live-caller` / `@test-only-export` at its declaration saying it is not. `src/local/**` is half cdkd's own code and half a re-export surface over cdk-local, and that boundary has moved several times; a module that moves out does not stop compiling and does not stop being tested, it stops being CALLED. What is left is a DECOY at the path a grep lands on, and issue [#2203](https://github.com/go-to-k/cdkd/issues/2203)'s fix landed in two of them, passed every gate and shipped as a no-op — a live probe returned the whole value it was supposed to truncate. Earlier instance of the same class: issue [#1972](https://github.com/go-to-k/cdkd/issues/1972).
  - **Why the rule is SYMBOL-level, not module-level.** "every file has a live importer" does NOT catch #2203. `vtl-engine.ts` HAS one: `rest-v1-integrations.ts` imports `evaluateVtl`, and `local-start-api.ts` imports `warnSsrfRiskyUri` from that. Under ESM the chain LOADS `vtl-engine.ts`, so "unreferenced" is false of it, while every function it exports is called only from functions that are themselves never called. Three states, not two: **live**, **loaded-only** (evaluated, nothing in it reached — `vtl-engine.ts`, `reload-orchestrator.ts`) and **unreferenced** (no `src/` importer at all — `httpv2-service-integration.ts`, `cfn-local-state-provider.ts`). The last two are equally inert to a user.
  - **Why the annotation, and why it is not "just a comment".** #2228 offered delete / mechanize / annotate. Annotation alone is the weakest — a comment asking the next reader to remember is what both prior instances already had. But a check alone does not reach the author either: the tree already contains orphans, so anything that must be green today has to tolerate them, and a tolerated orphan is invisible at the moment someone edits it. This is the two together, with the mechanism making the annotation non-optional and non-stale in BOTH directions: an unreachable symbol with no annotation FAILS, and an annotation on a REACHABLE symbol fails as stale.
  - **Shims are exempt by CONSTRUCTION, not by an allowlist.** 36 of the 57 files are re-export shims (`export { startApiServer } from 'cdk-local/internal'`), which declare no value symbol, so there is no cdkd-authored body in them for a fix to land in and an author who greps into one follows it straight to cdk-local. That is the line the critic draws — "a shim that re-exports" versus "a fork with a body and no consumer" — and drawing it structurally means it cannot go stale.
  - **What defends it from itself.** **Collapse toward zero** by six FLOORS (src files parsed / modules in the load closure / reachable symbols / files in scope / live scope symbols / shims), plus a hard failure on any file with parse diagnostics and on a missing entry point. The floors are the part that can be neutralised WITHOUT changing a verdict, and review round 1 measured exactly that: zeroing all six left 30/30 green, and zeroing them alongside a scope matching nothing printed `check OK — 0 files ... 0 exported symbols` at exit 0 — a critic that examined nothing reporting success, which is the confluence-point shape the whole file exists to prevent. Two things close it. `FLOORS` is EXPORTED and pinned to literals by the unit test, which separately asserts the REAL magnitudes off `--json` (`scopeFiles` 57 / `shimFiles` 36 / `liveScopeSymbols` 55 — the last was asserted nowhere before), so a scope that silently stops matching fails even with the constants untouched. And `checkScopeIsNotVacuous` refuses a run with zero scope files or zero exported symbols WITHOUT consulting the floors at all, because those are not magnitudes to calibrate but the absence of a subject; it is exported so both branches are unit-tested, the second being unreachable from any directory in this repo.
  - **The entry-point check is SET EQUALITY, and the added direction is the dangerous one.** `checkBuildEntriesInSync` PARSES `pack.entry` out of `vite.config.ts` (a whole-file substring match was satisfied by a comment merely naming the path, so it survived the rename it existed to catch) and requires it to equal `ENTRY_RELATIVE`. A REMOVED entry is loud — the critic reports the whole tree dead. An ADDED one is silent: symbols reachable only from the new binary read as unreachable and this critic's own message tells the author to ANNOTATE them, converting a wrong verdict into a permanent self-certifying one. Unreadable input is refused outright rather than assumed to agree, at BOTH granularities: a missing or non-object `pack.entry` map, and — the one a first revision skipped silently — an individual MEMBER that is not a plain `name: 'literal'`. A real entry written as a spread, an identifier, a ternary or a template with substitutions used to leave the entry set short, the ADDED-entry list empty, and the run green at exit 0.
  - **Collapse toward green** primarily by `runSelfProbe` — a 21-module corpus with known verdicts covering all three module states, both halves of the shim exemption, all three finding kinds, and six SHAPES THE REAL TREE DOES NOT CONTAIN today: a type-only re-export, a module reached only by `import type`, an entry point declaring rather than re-exporting its API, a class reaching its base through `extends`, a re-export CYCLE, and an ANONYMOUS default export. Each is a clause whose removal changes nothing about `src/`. The cycle case is the subtle one — its MAP POSITION is load-bearing, since edges are built in insertion order and the poisoned lookup has to happen before the entry point's clean one, or the probe passes whether or not the guard exists. `CDKD_SELF_PROBE_FORCE_FAIL=1` is a test seam proving the BINARY still consults the probe: without it, `main()` dropping the call is unobservable, because the unit tests call `runSelfProbe` directly. While orphans exist the STALE direction is a second free defence (if everything is reachable, every annotation is stale), but it disappears the day the orphans are deleted, so it is not the primary one.
  - **Under `--json`, stdout is a DATA channel.** The human summary goes to stderr, because appending it made `--json | jq` fail on trailing text — and the test that had been written to tolerate that (slicing back to the last `}`) pinned the defect instead of catching it. `--scope=` with an EMPTY value is refused rather than falling back to the default, since `--scope=$DIR` with `DIR` unset would otherwise report a green for a directory the caller never named.
  - **What it does NOT claim.** Reachability is an OVER-APPROXIMATION of what runs: a reference anywhere inside a declaration counts, parameter and local names are not told apart from imports of the same spelling, and a namespace import or a dynamic `import()` marks every export of its target reachable. All of that biases toward LIVE, which is the safe direction for a gate — it cannot manufacture a false accusation — but a clean run is not proof that a symbol executes. The namespace widening has exactly ONE instance reaching this scope (`websocket-server.ts:28`'s `import * as websocketBody`), and it is inert only while `websocket-body.ts` exports a single value; the unit test asserts that count and the fact that no other namespace edge reaches `src/local/**`, resolving the specifier rather than pattern-matching it — the one real edge is a SIBLING import, so a regex looking for `/local/` in the path finds nothing and reads as clean. Two under-approximations are known: an entry re-exporting through TWO levels of `export *` loses reachability at the second hop (latent — `src/index.ts` uses direct named re-exports), and a re-export cycle used to memoize a frame truncated on `seen`, which is now guarded and fenced by the corpus.
