# src/utils

`ip-protocol.ts`: [layout-drift.md](layout-drift.md). Index: [code-layout.md](code-layout.md).

- **parameter-types.ts** - `isListParameterType(type)`, the ONE answer to "is this Parameter `Type` LIST-shaped?"; an import-free LEAF. **Deliberately NOT `indexOf('List<')`**, which also matches the SSM OUTER form carrying a Parameter Store KEY ([#2347](https://github.com/go-to-k/cdkd/issues/2347)).
- **own-keys.ts** - own-key / plain-prototype rule: [own-keys.md](own-keys.md).
- **caller-credentials.ts** - caller identity on the `cdkd local` env channel: [local-caller-identity.md](local-caller-identity.md).
- **display-safe.ts** - `displaySafe(value, { asciiOnly? })`, the ONE rule for rendering an untrusted value; an import-free LEAF ([#2170](https://github.com/go-to-k/cdkd/issues/2170)). Two modes: a DENYLIST default and `asciiOnly`, a positive ALLOWLIST for a known-charset value — a caller whose value has a known charset (a region, an account id) should pass it, since it is the only mode with no invisible-formatter residual. **An ABSENT value renders EMPTY, never `'undefined'`.** It is MANY-TO-ONE, so two distinct inputs can render identically; that is harmless in prose and is a COLLISION in a machine-readable payload ([#3479](https://github.com/go-to-k/cdkd/issues/3479)). A joined list sanitizes per ELEMENT to keep the separator byte-exact — a formatting rule for `displaySafe`, load-bearing for `displayIdent`, written once on the function. `displayAwsMessage` is the spelling for AWS text that ECHOES a submitted value back, where the LENGTH is caller-chosen too; `grep displayAwsMessage` answers that population.
  - `displayIdent(value)` is the spelling for an untrusted IDENTIFIER: allowlist + `UNRENDERABLE`, a 255-code-point cap, and a JSON-quoted BOUNDARY for a non-plain value — the same-line spoof the allowlist cannot see. **Do not read its callers as an enumerated list.** It started on journal / S3-key fields and took the `--profile` name class and then the IAM role-ARN class (with `ROLE_ARN_MAX_CODE_POINTS`); both widenings found sites a per-class list had missed. `grep displayIdent(` answers the population, and the ARN class additionally has a fence, `tests/unit/cli/local-profile-display-population.test.ts`.
- **assembly-path.ts** - `resolveAssemblyPath`, the ONE containment check for every path built from a Cloud Assembly ([#3489](https://github.com/go-to-k/cdkd/issues/3489)); an import-free LEAF apart from `display-safe.ts`, so layers 1, 2 and 7 may all import it. **It is NOT the absolute-path tripwire and does not replace one**: `path.join` keeps an ABSOLUTE value inside the directory, so the two refusals answer different questions and must stay worded apart. Lexical containment always, plus a real-path arm on BOTH sides resolving through the deepest existing prefix and following a dangling link by hand — a not-yet-existing path IS the write case. **Never plain `fs.realpathSync` on an assembly-derived path**: it is a lexical JS walker that both misanswers and SPINS uncatchably; `.native` is `realpath(3)`. `containWithin` widens the BASE (a Stage's assets sit in the app outdir) without weakening the rule. The one site that CREATES a file adds an `lstat`. **`absoluteAssemblyPathEscape` is the sibling for a site that HONOURS an absolute value** (`aws:asset:path` under `cdkd local invoke` / `start-api`, go-to-k/cdkd#3494): `resolveAssemblyPath` cannot answer there, its `path.join` folding an absolute candidate INTO the directory, so the verdict would describe a path no caller opens. It returns a verdict instead of throwing, because that arm WARNS; it reuses the same `isInside` / symlink walk so the rule has one spelling; and unlike `resolveAssemblyPath` it treats the bound ITSELF as inside, an asset path legitimately naming a directory. **Its real-path walk runs on the ACCEPTING side too**, not only to find a symlink escape ([#3532](https://github.com/go-to-k/cdkd/issues/3532)): bound and target arrive INDEPENDENTLY here, so they can be two spellings of one directory (`/var` vs `/private/var`), which `resolveAssemblyPath` never meets because its candidate is built by joining onto the base. Reporting that as an escape cried wolf on every ordinary macOS `--no-staging` run. **`namesTheSameDirectory(bound, candidate)` is the sibling predicate for "is this value the bound?"** and a caller must never re-spell it as `resolve(a) === resolve(b)`: the escape check EXONERATES a second spelling of the bound as INSIDE, so a lexical equality beside it answers "not the bound" for exactly the values that most need a verdict — how #3532's whole-assembly warning first shipped with three silent spellings. `assemblyPathEscape(base, bound, candidate)` is the third sibling, for a caller that only WARNS: it picks the absolute or relative arm by the value's own shape and returns a verdict rather than throwing, so a warn-only site does not re-spell that branch ([#3497](https://github.com/go-to-k/cdkd/issues/3497)'s BuildKit passthroughs have a dozen values and nothing to throw).
- **nested-template-cycle.ts** - `findNestedTemplateTreeDefect`, the static pre-deploy walk of a nested-template tree ([#3247](https://github.com/go-to-k/cdkd/issues/3247)). **Refuses a repeat along ONE root-to-node chain, never a repeat anywhere** — two sibling rows sharing a template is a legal diamond. It follows exactly the rows the deploy follows, so its `escaping-path` defect must stay in step with the containment every `aws:asset:path` index site applies; a walk accepting rows they refuse is not the guard it claims to be. It also only ever sees rows those indexes CONTAIN — a row they drop is a subtree this walk never visits ([#3480](https://github.com/go-to-k/cdkd/issues/3480)). Identity is the REAL directory plus the file name: a symlinked directory makes every level's joined path a new string for one file, while the file's own symlink is NOT followed, because children resolve against the directory a template was reached in. It runs UP FRONT, not as a chain threaded through `NestedStackProvider`'s recursion, because each level there is a deploy.
- **colors.ts** - ANSI helpers, kept out of `logger.ts` so a `vi.mock` of it cannot strip them.
- **resource-line.ts** - the shared status line. **Every successful op renders a check, never a cross**, operations differing by COLOUR.
- **error-handler.ts** - error rendering plus `normalizeAwsError` (synthetic `UnknownError` to HTTP-status). `formatError`'s `Caused by:` line is the one render of a cause THROUGH `formatError`, and it both sanitizes and BOUNDS it (`displayAwsMessage`), because a thrower that caps AWS's text and then passes the same error as `cause` otherwise printed the cut marker on one line and the whole text on the next ([#3479](https://github.com/go-to-k/cdkd/issues/3479)). **It is not the only sink for a cause, and the other one is outside its reach**: `src/cli/index.ts`'s top-level `main().catch` does `console.error('Fatal error:', error)`, which renders every `[cause]` link through `util.inspect` — unbounded and unsanitized, reachable only by an error escaping `main()` outside `withErrorHandling`. `secret-redaction.ts` measured it and is the authority on it; do not read the bound below as covering it. **Masking is upstream of it** — `maskSecretsInError` rewrites the error OBJECT at the throw site and nothing masks after `formatError` — so truncation only ever removes already-masked text; a masker introduced at or after this render would invert that and must not be.
- **aws-client-defaults.ts** / **proxy-routing-agent.ts** - proxy-aware defaults and per-request routing: [proxy-support.md](proxy-support.md).
- **aws-region-resolver.ts** - caches the `GetBucketLocation` probe. Its ENDPOINT walks `opts.region` -> `fallbackRegion` -> the SDK chain, never a hardcoded `us-east-1`, unreachable outside the commercial partition. **Only a SUCCESSFUL lookup is cached** ([#1763](https://github.com/go-to-k/cdkd/issues/1763)).
- **s3-endpoints.ts** - the host-shaped `AWS::S3::Bucket` `Fn::GetAtt` values, SHARED so `S3BucketProvider.buildAttributes` and `constructAttribute` cannot disagree and produce phantom drift ([#1745](https://github.com/go-to-k/cdkd/issues/1745)).
- **regexp.ts** - `escapeRegExp`, centralised because a widened match changes which assets `gc.ts` reads as referenced.
- **ecr-uri.ts** - `parseEcrRegistryHost` returns `{accountId, region}` or `undefined`, while `looksLikeEcrHostWithForeignSuffix` separates that from a public image. It owns `ECR_REGISTRY_HOST_FORMS` and the pattern builder `gc.ts` consumes, but **what is shared is the TABLE, not the matcher**: this module pairs suffix with region and refuses a mismatch, gc does not. Case folding and the charset refusal happen at ONE module-private boundary. **Keep it free of AWS SDK imports** ([#1793](https://github.com/go-to-k/cdkd/issues/1793)).
- **aws-partition.ts** - `derivePartitionAndUrlSuffix(region)`, the closed map behind `${AWS::Partition}` / `${AWS::URLSuffix}`; it canonicalises its own input. `getAccountInfo().partition` derives through it PER CALL, caches only `accountId` + `fabricated`, and its ARN-building consumers OMIT the attribute when `fabricated` is set ([#1746](https://github.com/go-to-k/cdkd/issues/1746)).
- **expected-bucket-owner.ts** - spreads `ExpectedBucketOwner` into EVERY state-bucket-family S3 call, so a predictable-name bucket in a foreign account is rejected by S3 itself. Best-effort, memoized by ACCESS KEY ID so an assumed-role session still resolves its own account.
- **deny-external-access-policy.ts** - the `DenyExternalAccess` document for all three cdkd-owned buckets. **Every caller passes the region of the CLIENT that writes the policy**, never a local `region`, which may be a commercial fallback ([#1794](https://github.com/go-to-k/cdkd/issues/1794)).
- **bucket-region-client.ts** - `rebuildClientForBucketRegion`, which returns `null` on a same-region short-circuit and never destroys a shared client by default. Its own module so each store's `vi.mock` of `resolveBucketRegion` still intercepts.
- **stack-context.ts** - `AsyncLocalStorage` per-stack log buffer, flushed atomically so stacks do not interleave.
- **single-flight.ts** - memoizes an async cleanup so repeated callers await the SAME invocation (the SIGINT-during-finally race).
- **docker-cmd.ts** - `getDockerCmd()` resolves the binary via `CDK_DOCKER`; every docker subprocess goes through streaming spawn, so BuildKit output cannot hit `execFile`'s `maxBuffer` ceiling.
  - `dockerSpawnEnvWithSensitive` / `partitionSensitiveEnv` / `isDockerClientEnvKey` build the env for a `docker run` forwarding value-less `-e KEY` flags, keeping a secret VALUE off argv ([#2183](https://github.com/go-to-k/cdkd/issues/2183)). The denylist of vars the docker CLIENT reads is matched CASE-INSENSITIVELY, and its prefix families are **fail-closed on the whole prefix**, as is a MALFORMED key. **A colliding secret gets NO `-e` flag at all**, since emitting one makes docker hand the container the HOST's value. Display-side twin: [docker-argv-redaction.md](docker-argv-redaction.md).
