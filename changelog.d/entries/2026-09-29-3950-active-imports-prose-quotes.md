- **`cdkd destroy`'s active-imports refusal no longer puts a non-plain state value inside cdkd's own quotes or prints it raw (issue [#3950](https://github.com/go-to-k/cdkd/issues/3950), partial)** -- `src/utils/error-handler.ts` (`StackHasActiveImportsError`), with paste cases in `tests/unit/utils/active-imports-prose-quotes.test.ts`. The refusal printed `Cannot destroy stack '<producer>'` and `imports export '<name>'` with the values raw, beside the raw consumer stack name and both regions. The consumer's name comes from its state key, its region from the key (a legacy record's from its body) and the export name from its `state.json`, so whoever can write the state bucket chose them. A value carrying `'` closed cdkd's quote, so pasting the sentence ran what followed it as shell. A plain value prints exactly as before, a CDK-generated export name carrying `:` included. Any other value is described (`an export whose name is not a plain identifier`, `a stack name that is not a plain identifier`, `a region that is not a plain identifier`).
