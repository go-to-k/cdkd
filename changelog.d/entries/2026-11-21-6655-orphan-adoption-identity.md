- **A deploy no longer re-adopts a rollback orphan's name from a resource someone else created under it (issue [#6655](https://github.com/go-to-k/cdkd/issues/6655))**. On a stack without an instance id, the next deploy re-adopted a `DeletionPolicy: Retain` resource a rollback left in AWS when a resource answered under the recorded physical id, a name match for a name-addressed type, and kept the recorded attributes over the live ones. For a type whose record holds an AWS-minted id (an IAM role's `RoleId`, a DynamoDB table's `TableId`, ...), the id the existence check's `import()` already returned is now compared with the recorded one: a different one refuses the deploy (and is listed under `Blocking` by `cdkd diff`), naming the attribute but neither value, with `cdkd import` as the way to take that resource. Only when an SDK `import()` returns no usable id is the provider's `resourceIdentity` read once, on this adoption path only (a Cloud Control record with a masked id has none to read); an unreadable id adopts with a warning naming `cdkd state orphan --resource`. A record without the id adopts as before. The docs no longer say an explicitly named S3 bucket or SNS topic is adopted on create (the pre-create name check refuses it), and `cdkd destroy`'s page states which types are deleted by name alone.
