- **A Cloud Control attribute enrichment that fails with a value JavaScript cannot stringify degrades to a debug line, instead of failing the whole create (issue [#3309](https://github.com/go-to-k/cdkd/issues/3309))** -- `src/provisioning/cloud-control-provider.ts`. Fifteen `catch` blocks read the caught failure's text with `error instanceof Error ? error.message : String(error)`. `String(value)` THROWS for a null-prototype object (`TypeError: Cannot convert object to primitive value`) and for anything with a hostile or `null` `toString`, and every one of these handlers exists to DEGRADE: an enrichment that cannot read an attribute logs at `debug` and carries on. The out-throw escaped the handler and failed the create or update instead, reporting a `TypeError` that names neither the resource nor the attribute. Reachable because a non-`Error` rejection genuinely travels this far -- the same shape [#3236](https://github.com/go-to-k/cdkd/issues/3236) measured reaching the poll loop. All fifteen now read `describeAwsFailure(error).detail`, which is byte-identical for an `Error` and applies the guard that module gained for exactly this. Two occurrences are deliberately left: `cleanupFailedCreateRemnant`'s catch, whose bare arm is UNREACHABLE (every throw into it comes from `this.delete(...)`, which wraps into a `ProvisioningError`) and where converting would blind `isNotFoundMessage`, a PROSE matcher, by replacing the message with a wire name; and one inside a comment explaining why the form is wrong. Both are pinned BY NAME rather than by a count, so a sixteenth site fails the fence instead of shifting a number.
