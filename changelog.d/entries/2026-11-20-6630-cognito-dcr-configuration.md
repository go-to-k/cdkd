- **A Cognito user pool's `DcrConfiguration` (dynamic client registration) stays on the SDK route (PR [#6630](https://github.com/go-to-k/cdkd/pull/6630))**. AWS added the property in the 2026-11-19 schema refresh; the `AWS::Cognito::UserPool` SDK provider did not send it, so a pool declaring it would have moved to Cloud Control, and stayed there. The provider now sends it on `CreateUserPool` and `UpdateUserPool` (where AWS replaces the whole block, so a dropped member returns to its default) and reads it back from `DescribeUserPool` for drift. Removing it from the template turns registration off with `EnableStatus: Disabled`, which is what CloudFormation does on the same edit (measured); an `UpdateUserPool` that merely omits the block would keep it on. The read emits no `{}` placeholder, because AWS treats an empty block as registration turned on. Adds unit coverage.
