- **A failed ECR repository, SQS queue, SNS topic, Step Functions state machine, WAFv2 web ACL or CodeBuild project create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/ecr-provider.ts`, `sqs-queue-provider.ts`, `sns-topic-provider.ts`, `stepfunctions-provider.ts`, `wafv2-provider.ts`, `codebuild-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDeniedException. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker. A cdkd-authored or transport error keeps its text, masked. The AWS error is still the wrap's `cause`, so an IAM grant that is still propagating and an SQS queue name still in its 60-second cooldown are retried as before, and an "already exists" from the create call is still stated as such. A delete failure whose class names a `NotFound` other than the resource's own (a missing KMS key, for example) is marked as not proving the resource gone, so the class now in the message is not read as "already deleted".
