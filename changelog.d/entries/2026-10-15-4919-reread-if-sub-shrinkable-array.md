- **`cdkd diff --recursive --fail` no longer reports a change on an unchanged nested stack in which one child resource reads a parameter the parent spelled as a literal embedding `{{resolve:...}}` tokens beside a sibling parameter spelling the same secret differently, either of the two through `Fn::If`, through `Fn::Sub` inside `Fn::Select`, or inside an array holding an `Fn::If` or `AWS::NoValue` element (issue [#4919](https://github.com/go-to-k/cdkd/issues/4919)).** After upgrading, the first deploy of such a stack shows a change on the child resources reading the literal parameter, because their state now records the parameter's own `{{resolve:...}}` spelling instead of the sibling's; the deployed VALUE is unchanged, and a create-only property is replaced once with an identical value. Before, cdkd fell back to the sibling's spelling for that parameter in the whole child while `cdkd diff --recursive` rendered its literal. The child leaf re-read (#4731) now evaluates `Fn::Sub` and `Fn::If`: an `Fn::If` is re-read only when every branch is and no two branches resolve to one value spelled two ways, so its branch is read off the persisted value with no condition outcome needed. A bag array shorter than its source pairs the remaining elements in order when the count alone says which `AWS::NoValue` elements dropped; this applies to any stack's resource arrays, so a `{{resolve:...}}` element there keeps its own spelling where two references share one secret value. Anything else keeps the old fallback. Source: `src/deployment/secret-redaction/{nested-stack,redact-path}.ts`, `src/deployment/intrinsic-resolver/parameter-secrets.ts`.
