- **Re-adding a DynamoDB GlobalTable replica now waits for a same-named table that is still being deleted in that region, instead of failing (issue [#3569](https://github.com/go-to-k/cdkd/issues/3569))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts` (`addReplica`, new `waitForRegionalCopyReleased` / `isReplicaCopyExistsRefusal`) and a new unit file. Deleting a GlobalTable waits only until each cross-region replica has left the source table's `Replicas[]`, and the replica region's own copy stays `DELETING` for minutes after that. A replica-add of the same name in that window was refused ("one or more replicas already existed as tables"). A reverse-replacement rollback of a multi-region table re-creates the old table under its old name straight after deleting it, so it hit this every time and left the table missing. `addReplica` now reads the replica region on that refusal: while the copy is `DELETING` it waits (up to ~15 minutes, interruptible) and retries, up to 3 attempts in total. A copy in any other state, or a probe that fails, re-throws AWS's refusal untouched. cdkd never removes a table it finds there.
