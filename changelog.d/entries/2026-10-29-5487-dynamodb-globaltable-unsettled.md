- **A failed DynamoDB GlobalTable update now records what it had already started, so the next deploy converges it (issue [#5487](https://github.com/go-to-k/cdkd/issues/5487))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`. Each property is marked just before the call that changes it: the flat UpdateTable, the billing flip, SSE and the replica keys, replica add / remove / update, per-replica settings, deletion protection, tags and autoscaling, index ops, and TTL. The marks reach these calls through an async-local scope, so only the running update's sends mark. An update that fails part way (a wait, the per-resource deadline, Ctrl-C, or a later call) therefore records the property as unsettled instead of leaving the old value in state. For the convergence step (#5496), the table reports template-shaped values. It reads every replica in its own region strictly, reports no `{}` write settings on PAY_PER_REQUEST, and keeps each replica's recorded tags (tags merge). The next deploy refuses to diff a property only while the table, a replica, an index, SSE or TTL is actually moving.
