- **`cdkd drift --revert` no longer sends an empty value for an ELBv2 attribute key the recorded baseline lacks (issue [#4147](https://github.com/go-to-k/cdkd/issues/4147))** -- `src/provisioning/providers/elbv2-provider.ts` (`diffAttributeBag`), `docs/_contents/cli-drift.md`, `docs/_contents/provider-rules.md`, `tests/integration/drift-revert-vpc/verify.sh`, `tests/unit/provisioning/elbv2-attribute-appearing-key-4147.test.ts`. When AWS started returning an attribute key after the observed baseline was captured (`ddos_protection.syn_cookie.mode` on an ALB, or an attribute AWS released later), `--revert` read the key as a removal and sent `Value: ''` or a documented default. AWS rejects `''` for an enum or boolean key, which failed the whole `Modify*Attributes` call, so no other drifted attribute of that load balancer, target group or listener was reverted either. On `--revert`, no attribute removal is sent now: the key keeps its live value, and a warning names it and points to `cdkd drift --accept`. `cdkd drift` still reports such a key, because one read cannot tell a key AWS started returning from a value an operator set. `cdkd deploy` and rollback still reset an attribute the template removed.
