- **`cdkd deploy` now refuses a nested stack with a remote `TemplateURL` before publishing or provisioning anything (issue [#6385](https://github.com/go-to-k/cdkd/issues/6385))** -- `src/cli/commands/nested-template-preflight.ts`, `src/cli/commands/deploy/command.ts`, `src/provisioning/providers/nested-stack/create-update.ts`. An `AWS::CloudFormation::Stack` with no template in the cloud assembly (every CDK `HostedRotation.*`, whose `AWS::SecretsManager-2024-09-16` transform expands into a nested stack on an AWS-hosted Serverless Application Repository template, or an L1 `CfnStack` with a remote `templateUrl`) started deploying, created the stack's other resources, then failed on the nested row, rolled the others back, and pointed at `Metadata['aws:asset:path']`, which such a row can never carry. The deploy now refuses a row with no `Metadata['aws:asset:path']` right after macro expansion, at any nesting depth, naming the row and its stack. For a hosted rotation it says a remote-`TemplateURL` nested stack is not supported and points at `rotationLambda` with a function the app owns; for any other row it names both causes (a remote template, or a `cdk.NestedStack` synthesized with asset metadata disabled) and both remedies. A row carrying a `Condition`, and anything nested under it, is still left to the nested-stack provider, with one info line per such row that has no local template; the provider's message names the same two causes. Integ fixture: `tests/integration/remote-nested-stack-refusal`.
