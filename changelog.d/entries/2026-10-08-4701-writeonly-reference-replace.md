- **A resource that holds a replaced resource through a create-only property the CloudFormation schema also lists write-only is now replaced with it, instead of updated in place** (`src/analyzer/diff-calculator.ts`, `src/deployment/recreate-target-readers.ts`, go-to-k/cdkd#4701). The most common case is `AWS::ApplicationAutoScaling::ScalingPolicy.ScalingTargetId`: a change that replaces the scalable target (a renamed DynamoDB table, a moved `ResourceId`) planned each policy as an in-place update. AWS deletes a target's policies when it deregisters it, so the policy was updated after it was gone, or left pointing at the deleted target. cdkd did not replace on a write-only create-only property, a rule meant for a fresh `NoEcho` secret AWS never returns (go-to-k/cdkd#3803). That rule now applies only when the property is not exactly a `Ref` or `Fn::GetAtt` of the replaced resource: a plain reference resolves to the resource's new id or attribute, which cdkd compares with the state record, not with an AWS read. A `Fn::GetAtt` of a custom resource or nested stack, and any value built from a reference (a `{{resolve:...}}` dynamic reference, an `Fn::If`), keep the old rule. The `--recreate-via-*` pre-flight lists such a reader under "Replaced if the id changes". Other types this reaches include ElastiCache `ReplicationGroup`, VPC Lattice listeners and rules, DataSync locations and `ServiceDiscovery::PrivateDnsNamespace.Vpc`. Tests: `tests/unit/analyzer/diff-calculator-synthetic-create-only.test.ts`, `tests/unit/deployment/recreate-target-readers.test.ts`; integ `dynamodb-autoscaling` Phase 3 (a table rename replacing both scalable targets and their policies).
