- **`cdkd drift` no longer reports a Cloud Control resource's read-only timestamp as drift, and `drift --revert` no longer fails on it (issue [#6485](https://github.com/go-to-k/cdkd/issues/6485))** -- `src/cli/commands/drift/{compare,detect,baseline-keys}.ts`, `src/provisioning/read-only-properties.ts`. For a resource read through Cloud Control, the drift baseline holds the whole model, read-only values included. After an out-of-band edit, a timestamp such as `AWS::Location::Tracker` `UpdateTime` read as drift beside the real change, and `--revert` sent the old timestamp back in its patch, which Cloud Control refuses (`readOnlyProperties ... cannot be updated`), so the real drift was not reverted either. Drift now skips every position the type's registry schema marks read-only, unless the template declares it, as CloudFormation drift compares only what a template declares. The schema is looked up once per type, beside the read. Without `cloudformation:DescribeType` every key is compared, as before. Existing state needs no redeploy.
