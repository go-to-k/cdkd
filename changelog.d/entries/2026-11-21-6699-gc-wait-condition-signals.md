- **`cdkd gc` collects orphaned wait condition signal objects (issue [#6699](https://github.com/go-to-k/cdkd/issues/6699))** -- `src/cli/commands/gc/wait-condition-signals.ts`, `src/cli/commands/gc/command.ts`, `src/cli/commands/gc/scan.ts`, `src/provisioning/wait-condition-signal-store.ts`, `docs/cli-gc.md`. A `WaitConditionHandle`'s `wait-condition-signals/{logicalId}-{uuid}.json` key in the state bucket was removed only by the handle's own delete, so an interrupted deploy, an orphaned handle or a failed cleanup left it, and every signal version, behind for good. gc now deletes such a key, with all its versions and its delete marker, when it has the minted key shape, is older than `--older-than`, and no handle in any state file (resources, `orphans`, `supersededResources`, nested children, any prefix) or `retained.json` points at it. The arm runs whether or not the region has asset storage, shares gc's single state scan, aborts with `GC_STATE_UNREADABLE` on a state file it cannot walk, and checks the locks again after the scan.
