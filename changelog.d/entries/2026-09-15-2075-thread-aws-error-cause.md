- **Six asset- and state-layer failures now thread the underlying error as `cause`.** The four `AssetError` arms (docker re-tag, ECR login, tag, push) and both `StateError` arms (`HeadBucket` reporting the state bucket missing, `PutObject` losing the optimistic-lock race) previously wrapped the caught value in an interpolated message and dropped it, so `isTransientServerError` / `isThrottlingError` / `isMarkedNonRetryable` classified on that message alone and `extractDeploymentEventError` lost the AWS error code and request id it persists. The four docker causes are REDACTED rather than raw: docker echoes the failing command line into its stderr, which becomes the error's message, so attaching the caught error verbatim would have printed a future `-e` / `--build-arg` value through `formatError`'s `cause.message` — the channel issue #2440 closed. Those four reject through `spawnStreaming`, whose error carries `stderr` / `stdout` / `exitCode` and nothing else, so `exitCode` is what the redacted cause preserves; for them the cause buys a legible diagnostic rather than a retry decision, which the AWS-shaped fields serve only where an SDK error can be the cause. Issue #2075.
