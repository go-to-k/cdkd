- **`cdkd destroy` masks a resource name taken from a `NoEcho` parameter in state written before schema v11 (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/secret-name-needles.ts`, `src/deployment/noecho-delete-reresolution.ts`, `src/deployment/rollback-executor/journaled-orphans.ts`, `src/cli/commands/destroy-runner.ts`. Since v11, a `NoEcho` value persists as `***`, and nothing migrates an older record when it is read. So a pre-v11 record still holds the value in plaintext, with no marker saying it is secret. Its delete lines printed the whole id (`Deleting Bucket <value>`), and so did a reader holding the name and the id spellings a provider folds. `cdkd destroy` now binds the stack's `NoEcho` values once from the synthesized template. It binds nothing when the template declares no `NoEcho` parameter. Every delete's printing bag, journaled failed-CREATE orphans and their pre-prompt listing included, is judged with these values and also masks the values themselves. `cdkd state destroy` holds no template, so its judgement stays record-only. Its plaintext records are masked once the next `cdkd deploy` rewrites them. Masking only. Tests: `tests/unit/cli/destroy-noecho-plaintext-name-3869.test.ts`, `tests/unit/deployment/secret-name-needles-3869.test.ts`, `tests/unit/deployment/noecho-delete-reresolution.test.ts`.
