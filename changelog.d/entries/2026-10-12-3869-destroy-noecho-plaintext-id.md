- **`cdkd destroy` masks a resource name taken from a `NoEcho` parameter in state written before schema v11 (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/secret-name-needles.ts`, `src/deployment/noecho-delete-reresolution.ts`, `src/deployment/rollback-executor/journaled-orphans.ts`, `src/deployment/intrinsic-resolver/support.ts`, `src/cli/commands/destroy-runner.ts`. Since v11, a `NoEcho` value persists as `***`, and nothing migrates an older record when it is read. So a pre-v11 record still holds the value in plaintext, with no marker saying it is secret. Its delete lines printed the whole id (`Deleting Bucket <value>`), and so did a reader holding the name and the id spellings a provider folds. `cdkd destroy` now binds the stack's `NoEcho` values once from the synthesized template, falling back to each literal `Default` when the binding fails, and hands them to a nested child. It binds nothing when no `NoEcho` parameter is declared, and waits at most 10 seconds, warning on expiry. Every delete's printing bag, journaled failed-CREATE orphans and both pre-prompt orphan listings included, is judged with these values and also masks the values themselves. Without a usable template (`cdkd state destroy`, `cdkd drift --revert`, the state-only fallback, a stack no longer in the app, a macro template, another region's synth), or for a value changed since the record was written, the judgement stays record-only until the next `cdkd deploy` rewrites the record. The prompt's list of resources an earlier rollback kept (`state.orphans`) now masks an id named from any secret, as `cdkd diff` does. A `NoEcho: "true"` string now redacts the parameter's `--verbose` line too. Masking only. Tests: `tests/unit/cli/destroy-noecho-plaintext-name-3869.test.ts`, `tests/unit/deployment/secret-name-needles-3869.test.ts`, `tests/unit/deployment/noecho-delete-reresolution.test.ts`, `tests/unit/deployment/noecho-string-true-parameter-log-3869.test.ts`.
