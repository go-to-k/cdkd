- **A Step Functions secret placed in a definition KEY no longer reaches the state file, and a numeric one is named only where the body places it (issue [#5333](https://github.com/go-to-k/cdkd/issues/5333))** -- `src/deployment/secret-redaction/{readback-certification,redact-path}.ts`, `src/analyzer/drift-calculator.ts`. A `DefinitionSubstitutions` secret used as a state name read back as an object key, which no redaction walk read, so it was persisted to `observedProperties` in plaintext. When any key of a read-back `Definition` is one the record's own definition does not spell, the whole `Definition` is now stored as `***`; `cdkd drift` reports it as an uncertified baseline (exit 2), and `--revert` sends AWS's live definition, never `***`. When a definition's substitutions carry a secret and the state does not hold its body (`DefinitionS3Location`), it is masked whole on the readback paths that resolve nothing, and on a deploy only when a key holds the resolved secret. The record's body is now read with each secret placeholder replaced by a marker, so a body with a `${name}` outside quotes keeps the numbers and booleans it spells instead of masking all of them, and the deploy's own capture replaces only the value at that position with its reference, leaving a literal `Seconds: 3` beside a secret `3` as a number; on the readback paths that resolve nothing, the secret positions are masked even where the secret equals a literal the body spells elsewhere. A state file written before this fix keeps the plaintext until `cdkd state refresh-observed` is run.
