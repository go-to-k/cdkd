- **An ElastiCache replication group `NumNodeGroups` or `NodeGroupConfiguration` change is now planned as a replacement, as CloudFormation does, behind `--force-stateful-recreation` (issue [#7100](https://github.com/go-to-k/cdkd/issues/7100))** -- `src/analyzer/replacement-rules/evidence.ts`, `src/analyzer/replacement-rules/spec-replacement-properties.generated.ts`, `src/deployment/deploy-engine/update-replace/preflight.ts`. Before this, the change was sent to Cloud Control in place and refused (`NotUpdatable: Immutable`). CloudFormation was measured replacing the group on both changes (new physical id, the old one deleted) when the template has no `UseOnlineResharding` update policy, though its change set reads `Replacement: False` / `Conditional`. The group is stateful, so the deploy refuses the replacement before any call unless `--force-stateful-recreation` is passed, and the refusal cites the CloudFormation measurement. Under `UpdatePolicy: UseOnlineResharding: true`, CloudFormation reshards the group online instead, so cdkd never replaces it there: the change goes in place, and Cloud Control's refusal now names online resharding.
