- **ElastiCache CacheCluster: a removed property that CloudFormation also leaves in place is now named in a warning (issue [#5545](https://github.com/go-to-k/cdkd/issues/5545))** -- `src/provisioning/providers/elasticache-provider.ts`. A real CloudFormation A/B (us-east-1, redis 7.0 and memcached 1.6.17 clusters, the removal alone and beside another change) showed that removing `EngineVersion`, `CacheParameterGroupName`, `PreferredMaintenanceWindow`, `SnapshotWindow` or `IpDiscovery` leaves the live value in place, as does removing `TransitEncryptionEnabled` or `PreferredAvailabilityZone` on a memcached 1.6.22 cluster: the cluster stays on its custom parameter group rather than moving to `default.<family>`, and CloudFormation's `ModifyCacheCluster` carries none of them. cdkd already sent nothing for these removals and still does, so the cluster is unchanged. Before this change it said nothing; now one warning per resource names each removed property that keeps its AWS value, these and the earlier-measured `SnapshotRetentionLimit`, `AutoMinorVersionUpgrade`, `NotificationTopicArn` and `VpcSecurityGroupIds` included. The type now declares `removalHandledInUpdate`, so the deploy's shared removal warning names only `AZMode` and `PreferredAvailabilityZones`, whose removal CloudFormation answers by replacing the cluster (issue [#5558](https://github.com/go-to-k/cdkd/issues/5558)). Tests: `tests/unit/provisioning/elasticache-provider-removal-5545.test.ts`; the `cache-streaming` integ's removal phase now also drops `EngineVersion`, `CacheParameterGroupName` and `SnapshotWindow`.
