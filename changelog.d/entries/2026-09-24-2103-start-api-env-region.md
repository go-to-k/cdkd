- **`cdkd local start-api` now folds an upper-cased `AWS_REGION` / `AWS_DEFAULT_REGION` to its canonical spelling, not only `--region` (issues [#2103](https://github.com/go-to-k/cdkd/issues/2103), [#1843](https://github.com/go-to-k/cdkd/issues/1843))** -- `src/cli/commands/local-start-api.ts`, `tests/integration/local-start-api/`, plus tests. The command folded the `--region` flag at its entry but read the two env vars raw, so `AWS_REGION=US-EAST-1 cdkd local start-api` handed `US-EAST-1` to every Lambda container it started, to the `--assume-role` STS client, to the API server's service-integration region and to the WebSocket container's `AWS_REGION`. AWS SDK endpoint resolution is case-sensitive, so a handler's own SDK calls could fail to sign, and `CN-NORTH-1` resolved the commercial partition. The handler entry now calls `foldRegionOption`, as the other region-taking commands do, and each of the four read sites folds again at the read, matching `cdkd local invoke`. Credentials forwarded into the container are still copied verbatim.
