- **`cdkd deploy`'s `Updated:` total no longer counts an orphaned predecessor left inside a nested stack (issue [#1989](https://github.com/go-to-k/cdkd/issues/1989))** -- `src/cli/commands/deploy.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/deploy-engine/{options,execute,provision,deploy-flow}.ts`. Since nested-stack counts reach the top-level stack (PR #4459), a replacement inside a nested child that left its old resource alive was added to the top-level `Updated:` total and its `of which left an orphaned predecessor` row, although `Updated:` counts the deployed stack's own resources only. Such survivors now print on their own row, `Left an orphaned predecessor in a nested stack: N`, and `RunCounts.updated` in `cdkd events` matches the console. The exit code and `RunCounts.skipped` still count them. `docs/cli-deploy-safety.md` no longer says the exit code covers top-level stacks only, and says a skipped DELETE inside a nested stack exits 2 on the first deploy and is re-attempted by the next. Tests: `tests/unit/cli/deploy-unaddressed-exit.test.ts`, `tests/unit/deployment/deploy-engine-nested-child-unaddressed.test.ts`.
