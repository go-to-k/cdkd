- **An API Gateway create that hits a 5xx now reports candidate orphans instead of duplicating silently (issue [#2080](https://github.com/go-to-k/cdkd/issues/2080), Plan C: API Gateway)** -- `src/provisioning/providers/{apigateway,apigatewayv2}-provider.ts`, `src/provisioning/providers/apigateway-orphan-report.ts` (new), `docs/troubleshooting.md`, `docs/provider-rules.md`. API Gateway `CreateAuthorizer` and `CreateDeployment`, and API Gateway v2 `CreateApi`, `CreateIntegration` and `CreateAuthorizer`, mint their id and carry no idempotency token, so a 5xx whose request had succeeded left a second, unrecorded resource behind. These five creates no longer let the AWS SDK retry a 5xx inside one call, where the duplicate was invisible; the 5xx reaches cdkd's retry, which first lists what the failed attempt may have made and reports each match at warn with a read command first: an HTTP API of the same name and protocol, or a deployment of the same REST API and description, created during the failed attempt (with a delete command, after confirming), or an authorizer of the same name and type, or an integration of the same type and URI, that this deploy did not record (no creation time, so no delete command). Nothing is adopted and nothing is deleted. A throttle, a 4xx or IAM propagation triggers no lookup. The lookup needs `apigateway:GET`; without it cdkd warns and the create proceeds. A reset connection or timeout after the send is still retried inside the SDK and not reported (#3978 layer (b)). Tests: `tests/unit/provisioning/{apigateway,apigatewayv2}-create-retry-2080.test.ts`.
