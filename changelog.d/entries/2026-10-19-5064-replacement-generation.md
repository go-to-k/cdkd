- **A replaced auto-named resource gets a new name and is created before the old one is deleted, as in CloudFormation (issue [#5064](https://github.com/go-to-k/cdkd/issues/5064), part 3)** -- `src/state/name-generation.ts`, `src/provisioning/resource-name.ts`, `src/deployment/deploy-engine/update*.ts`, `replacement.ts`, `create.ts`, `execute.ts`, `deploy-flow.ts`, `src/deployment/generated-name-guard.ts`, `orphan-adoption.ts`, the rollback executor, `cdkd import`, `cdkd orphan`. On a stack with a stack instance id, a resource the template does not name records its name generation (state v13, `nameGeneration`). A replacement (an immutable property, `--recreate-via-*`, an update the provisioning layer rejects) creates the new resource under the next generation's name first and then deletes the old one, with no `--replace`; a collision on that name refuses and names `cdkd import`, and `--replace` deletes nothing. A crash re-run asks for the same name (the generated-name guard takes back what the killed run made); a rollback restores the old resource and remembers the generation reached, so the retry gets a new name. A resource removed from the template (deleted, `Retain`, `cdkd orphan`) and later re-added gets a new name, and what a rollback left in AWS under `Retain` is no longer taken back: the deploy creates a new resource and names `cdkd import`. A CREATE a rollback took back (the automatic rollback, `cdkd rollback`, a nested child's) is created under a new name next time, as in CloudFormation, so a type that refuses a just-deleted name for a while (an SQS queue, a Secrets Manager secret) does not fail the retry. Legacy stacks keep their names and today's replacement behavior.
