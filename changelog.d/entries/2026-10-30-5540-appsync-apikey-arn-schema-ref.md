- **An `AWS::AppSync::ApiKey`'s `Arn` and `Ref`, and an `AWS::AppSync::GraphQLSchema`'s `Ref` and `Id`, now resolve to the values CloudFormation returns (issue [#5540](https://github.com/go-to-k/cdkd/issues/5540))** -- `src/provisioning/providers/appsync-provider.ts`, `src/deployment/intrinsic-resolver/ref-values.ts`, `src/deployment/intrinsic-resolver/getatt-construct-app.ts`, `src/cli/commands/export.ts`, and unit tests. Measured on a live CloudFormation stack, the API key ARN is `arn:<partition>:appsync:<region>:<account>:apis/<apiId>/apikeys/<keyId>`; cdkd built `.../apikey/<keyId>`, following the CloudFormation docs. A schema's `Ref` is `<apiId>GraphQLSchema`, where cdkd returned the bare API id; its `Fn::GetAtt Id` now returns the same value (CloudFormation itself fails a stack that reads it). A key created or imported from now on records the plural ARN, and a key recorded before keeps its singular one until the key is next updated. `cdkd export` now decodes an API key ARN in either spelling; before, it refused CloudFormation's own. Integration fixtures: `tests/integration/import-migrate-appsync` compares cdkd's stack outputs with CloudFormation's, and `tests/integration/appsync` asserts the plural segment.
