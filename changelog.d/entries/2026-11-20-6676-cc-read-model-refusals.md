- **Updating an OpenSearch domain or a DataSync task with no schedule or name through Cloud Control no longer fails on a value the template never declared (issue [#6676](https://github.com/go-to-k/cdkd/issues/6676))** -- `src/provisioning/cc-read-back-default-paths.ts` (new), `src/provisioning/cc-read-back-empty-keys.ts`. Cloud Control applies an update on top of the model it reads back, so a value AWS filled in was sent to the update API even when the change was elsewhere. An `AWS::OpenSearchService::Domain` reads back `AdvancedOptions.override_main_response_version` and disabled `AIMLOptions`, which `UpdateDomainConfig` refuses ("Unrecognized advanced option 'override_main_response_version'"), so every deploy change and `cdkd drift --revert` of a domain failed. An `AWS::DataSync::Task` without a schedule or a name reads back `Schedule: {}`, which `UpdateTask` refuses, and `Name: ""`, which Cloud Control's own validation refuses. The update now leaves those values out, as CloudFormation does, and AWS keeps them. 80 Cloud Control-routed types were measured against real AWS; the results are in `docs/_generated/cc-update-measurements.md`, and CI checks that every type measured as refusing has a fix.
