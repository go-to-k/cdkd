- **A refused replacement of a security group ingress rule whose source is a secret reference no longer leaves the new rule open (issue [#7084](https://github.com/go-to-k/cdkd/issues/7084))** -- `src/deployment/type-change-guard.ts`, `src/deployment/deploy-engine/update-replace/create-first.ts`. When a standalone `AWS::EC2::SecurityGroupIngress` takes its `CidrIp` (or another source) from a `{{resolve:secretsmanager:...}}` reference, cdkd records the source masked and cannot tell an old rule from a new one under the shared physical id, so a source change still refuses as a name-idempotent create. The create-first attempt had already authorized the new rule, and the refusal left it in place, recorded nowhere. The new rule's AWS-assigned `sgr-` id now proves it is not the recorded one, so it is deleted again before the refusal, which says so; `--replace` still completes the move. Integ: `sg-ingress-secret-source`.
