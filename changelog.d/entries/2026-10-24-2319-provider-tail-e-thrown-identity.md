- **A failed Lambda function, permission, layer version or event invoke config no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/{lambda-function,lambda-permission,lambda-layer,lambda-event-invoke-config,s3-bucket-policy,appsync,glue,s3-tables,s3-bucket,servicediscovery}-provider.ts` unit cases. The create, update and delete failure messages quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker. A cdkd-authored or transport error keeps its text, masked. The S3 bucket policy wrap, which already named the class, now masks it and the cdkd-authored text too. The AWS error is still the wrap's `cause`, so an IAM grant that is still propagating, a throttle or a Lambda function still updating is retried as before, and an "already exists" is still stated as such, except from a post-create step of a Lambda function, AppSync GraphQL API or S3 bucket. A delete failure whose class is another resource's not-found (for example `KMSNotFoundException`) no longer reads as "already deleted" for these providers or for the AppSync, Glue, S3 Tables and S3 bucket deletes: the state record is kept. The Lambda function post-create cleanup lines, the AppSync GraphQL API rollback warning and the Cloud Map service cleanup warning name an AWS failure by its class too.
