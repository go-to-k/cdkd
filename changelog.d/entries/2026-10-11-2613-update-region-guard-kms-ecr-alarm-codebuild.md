- **An update of a KMS key or alias, an ECR repository, a CloudWatch alarm or a CodeBuild project is refused when the AWS client's region differs from the region recorded in cdkd state (issue [#2613](https://github.com/go-to-k/cdkd/issues/2613))** -- `src/provisioning/providers/{kms,ecr,cloudwatch-alarm,codebuild}-provider.ts` (`update()` now takes the `UpdateContext` and calls `assertRegionMatch` before any AWS call), `scripts/check-provider-update-context.ts` (four names leave `OMITS_UPDATE_CONTEXT`), and unit cases in each provider's test file. These providers ignored the recorded region on update, so a deploy, rollback or `cdkd drift --revert` run with a client in another region sent its writes to whatever carried the same name there, a resource cdkd does not manage. The update now stops before the first call and names both regions. An update whose state record has no region is unchanged.
