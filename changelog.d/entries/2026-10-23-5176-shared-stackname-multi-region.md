- **A multi-region app that deploys one CDK Stage per region under a shared `stackName` is now deployed, diffed, listed and destroyed in every region, as the AWS CDK CLI does (issue [#5176](https://github.com/go-to-k/cdkd/issues/5176))** -- `src/cli/stack-matcher.ts`, `src/analyzer/cross-stack-deps.ts`, `src/cli/commands/{deploy,destroy,diff,list,synth,publish-assets,scrub,local-run-task}.ts`, `src/deployment/intrinsic-resolver/cross-stack.ts`, `docs/cross-stack-internals.md`, unit cases and the `shared-stackname-multi-region` integ fixture. Before, `cdkd deploy '**'` (and `diff`, `list`, `synth`, `publish-assets`, `scrub`) kept one stack per physical name and silently deployed only the first region's. `cdkd destroy UsWest/Api` destroyed the FIRST Stage's stack (us-east-1). Now each selected stack is handled under its own name and region: deploy work-graph nodes, asset nodes, dependency edges and destroy targets. A dependency resolves to the producer in the dependent's own Stage, or to the stack that exports an imported name. A name shared by two app stacks is destroyed only where its selected stack lives. Two selected stacks with the same name AND region (or a selected one and an unselected one pinning that region in a possibly-equal account) would be one CloudFormation stack, so they are refused before any lock or engine runs, with both CDK paths named. destroy skips a shared-name stack pinned to another account than the run's. `Fn::ImportValue` now prefers a producer in the consumer's own region. A cross-region import with no same-region producer resolves as before. `cdkd list` without a pattern no longer drops a same-named stack. `cdkd synth --verbose` writes `<name>.<region>.template.json` for a shared name. `scrub --all` reads each shared-name stack in its own region. `cdkd local run-task` no longer takes the first Stage's state for a shared name.
