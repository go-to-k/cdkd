- **An `AWS::RDS::DBCluster` recorded under `--prefer-sdk-route` before restores were wired is no longer read as restored (issue [#6104](https://github.com/go-to-k/cdkd/issues/6104))** -- `src/provisioning/providers/rds/{cluster-restore,cluster-delete,cluster-update}.ts`, `src/types/resource/contexts.ts`, `src/provisioning/region-check.ts` and every `delete()` / `update()` caller that passes `recordedAttributes`. Before #6096 / #6098, `--prefer-sdk-route` could drop `SourceDBClusterIdentifier`, `SourceDbClusterResourceId` or `SnapshotIdentifier` and run a plain `CreateDBCluster`, while the record kept the key. Such a record then read as a restore's: its destroy skipped the express-configuration writer when the record held no writer id, so RDS refused the cluster delete until the writer was deleted by hand, and a rollback replay kept a `GlobalClusterIdentifier` the cluster had left. The callers now pass the record's `acceptedCreateOnlyDrops` as `recordedCreateOnlyDrops`, and a source key listed there no longer makes the record a restore's. A record whose `WithExpressConfiguration` was itself dropped deletes no instance under the writer's name, since RDS made no writer. A record without the list behaves as before. Also, a point-in-time restore whose declared `SnapshotIdentifier` names no readable snapshot no longer says "there is nothing to restore": the message says the restore does not use the snapshot but the create is refused because CloudFormation reads it first.
