- **A failed update that cdkd moved from an SDK provider to Cloud Control API now names the move and the two ways through** -- `src/provisioning/cc-autoroute-update-remedy.ts`, `src/deployment/deploy-engine/update-in-place.ts`. When a property the SDK provider does not handle is added to a resource recorded on that provider, the deploy routes its update through Cloud Control, which addresses the resource by the physical id the SDK provider recorded; for some types Cloud Control does not accept that id. Such a failure printed only Cloud Control's error. It now also says the update moved the resource to Cloud Control because of the named properties, and gives `--recreate-via-cc-api <LogicalId>` (re-create it on Cloud Control) and `--prefer-sdk-route <Type>:<Property>` (stay on the SDK provider without sending them). A successful deploy runs nothing new, and other failures keep their message. Issue [#4904](https://github.com/go-to-k/cdkd/issues/4904).
