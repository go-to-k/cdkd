- **`Fn::GetAtt` into an `AWS::Lambda::WebFunctionEndpoint`'s `RegionalEndpoints.<region>.<Member>` resolves again instead of returning the endpoint ARN (issue [#4978](https://github.com/go-to-k/cdkd/issues/4978)).** Since the dedicated SDK provider landed in 0.300.0, `Fn::GetAtt` on `RegionalEndpoints.us-west-2.DomainName` (and the other members) logged `Unknown attribute ... returning physical ID` and served the endpoint ARN, so a CloudFront origin built from it failed with `origin name cannot contain a colon`. The provider now records `RegionalEndpoints.<region>.{DomainName,AuthType,State,StateReason,UpdateStatus,UpdateStatusReason}` from `GetWebFunctionEndpointResponse.regionalEndpoints`; a member AWS did not assign (a `MultiRegion` endpoint reports `domainName: null` per region) is not recorded. A record written by 0.300.x gains the keys on the next deploy that reaches the `Fn::GetAtt`, through the stale-attribute heal. Source: `src/provisioning/providers/lambda-web-function-endpoint-provider.ts`.
