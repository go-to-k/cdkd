- **`cdkd state resources` and `cdkd state show` no longer invent resource rows from a `resources` bag that is not an object (issue [#3172](https://github.com/go-to-k/cdkd/issues/3172))** -- `src/cli/commands/state.ts`, `src/cli/commands/export.ts`, `docs/cli-state.md`, `docs/cli-flag-coverage.*` + `docs/_generated/integ-last-run.tsv` (regenerated), `tests/unit/cli/state-record-shape.test.ts`, `tests/unit/scripts/integ-aws-commands.test.ts`, `tests/integration/state-info-command/verify.sh`. A state record is read as an unchecked cast, so a hand-edited or truncated one can carry a string, a list, a number or a boolean in `resources`. `Object.entries` accepts all four: `"abcdef"` yielded six `[index, character]` pairs, rendered by `cdkd state resources` as six resources that do not exist -- in `--json` too -- and by `cdkd state show`'s text view under a `Resources (6):` header. One pair per element also made a planted multi-megabyte bag a memory-exhaustion path. Both commands now repair the bag through `repairMalformedResourcesForReadOnly` and warn through `malformedResourcesWarning` (`src/state/malformed-resources-bag.ts`), the treatment `cdkd diff` already takes; neither refuses. `cdkd state resources` repairs at its LOAD, covering both output modes; `cdkd state show` repairs after every `--json` branch, per node of the `--show-nested` tree, so `cdkd state show --json` still emits the stored bag verbatim, preserving the evidence. The nested-stack walker reads the bag before either, so it now returns a childless node on an unreadable one at EVERY depth: that closes the allocation under `--show-nested` (both modes) plus a hard failure where a bag edited from a map into a LIST of resource objects made the walk seek a child at `<parent>~0` and abort. An absent or `null` bag warns too, rendering unchanged; `cdkd state list --long` still counts those as `0`. A healthy or empty bag is untouched and silent.
