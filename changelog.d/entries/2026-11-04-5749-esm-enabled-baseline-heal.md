- **`cdkd drift --revert` no longer disables an `AWS::Lambda::EventSourceMapping` deployed by an earlier cdkd (issue [#5749](https://github.com/go-to-k/cdkd/issues/5749))** -- `src/cli/commands/drift.ts` (new `preFixBaselineUncomparedDriftKeys`) and its unit tests. A mapping deployed before the fix for [#5737](https://github.com/go-to-k/cdkd/issues/5737) still holds `Enabled: false` in its recorded snapshot, so `cdkd drift` reported `Enabled: false -> true` and `--revert` sent `Enabled: false`, stopping the consumer. Drift now does not compare that value while the template does not set `Enabled: false` and the live mapping reads enabled, the same answer CloudFormation's drift detection gives, so no `cdkd drift --accept` is needed first. A template that sets `Enabled: false` is compared as before, and so is a live mapping that reads disabled. Nothing is written to state; the old snapshot is replaced by the next deploy that updates the mapping or by `cdkd state refresh-observed`.
