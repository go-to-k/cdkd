- **Every remaining consumer of a `resources` ROW that is not a resource record now refuses or drops it by name, instead of throwing, misreporting or saving it (issue [#3202](https://github.com/go-to-k/cdkd/issues/3202))** -- `src/cli/commands/destroy-runner.ts`, `deploy.ts`, `scrub.ts`, `import.ts`, `src/deployment/orphan-adoption.ts`, `src/local/s3-local-state-provider.ts`, plus five new texts and three refusal entry points in `src/state/malformed-resources-bag.ts`. `cdkd destroy` / `cdkd state destroy` refuse such a row before the prompt and the lock, and again on the record re-read under the lock (a `null` row died on a bare `TypeError` in the pre-prompt listing; a falsy row was skipped as "not found in state" and the record removed with its resource live; a typeless row was routed to a provider on `undefined`). `cdkd deploy`'s pre-lock `--recreate-via-*` check refuses the bag and the rows before validating, so a `null` named row is no longer reported as *missing from state*. `cdkd scrub` refuses on a real run (exit 2) and, under `--dry-run`, drops the rows, warns, and reports a `malformedResourceRows` finding. A selective `cdkd import` refuses pre-flight only the unreadable rows it would NOT re-import -- a row named by `--resource` is that row's repair -- and refuses again on the assembled map when a listed row's import did not succeed; whole-stack `--force` and `--migrate-from-cloudformation` replace the map. Every `cdkd local * --from-state` load reads an unreadable map as empty and drops unreadable rows, warning with local texts. The rollback-orphan claim scan walks a sibling record past a row with no readable physical id -- a list-shaped bag included -- so the set that stops adopting another stack's resource is never narrowed.
