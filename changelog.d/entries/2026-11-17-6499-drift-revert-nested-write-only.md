- **`cdkd drift --revert` works on a Cloud Control resource whose property holds a nested write-only field, such as an EventBridge connection's API key (issue [#6499](https://github.com/go-to-k/cdkd/issues/6499))** -- `src/cli/commands/drift/{plan,revert,revert-outcome,revert-write-only}.ts`, `src/provisioning/write-only-properties.ts`. AWS never returns a write-only field on a read, and the revert built its request from the read, so an `AWS::Events::Connection`'s `AuthParameters` went out without `ApiKeyValue` and Cloud Control refused every revert of a connection (`required key [ApiKeyValue] not found`). The revert now puts the template's value back at each write-only field, as a deploy sends it, while the rest of the property keeps the recorded value (an `--accept`ed one included); the plan names those properties before the confirmation. A `{{resolve:...}}` value is sent resolved and stays masked in the output; one cdkd cannot resolve, or one in a list whose items cannot be matched to the template's, is not sent and the revert warns. This also covers a top-level write-only value held in a dynamic reference, which the fix for [#6498](https://github.com/go-to-k/cdkd/issues/6498) left out.
