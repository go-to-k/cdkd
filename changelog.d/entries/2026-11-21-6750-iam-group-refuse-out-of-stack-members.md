- **`cdkd destroy` refuses an IAM group that a user outside the stack is still in, instead of removing the user from it (issue [#6750](https://github.com/go-to-k/cdkd/issues/6750), group half)** -- `src/provisioning/providers/iam-user-group/group.ts`, `tests/unit/provisioning/iam-group-refuse-out-of-stack-members-6750.test.ts`, and an arm in the `iam-access-key` integ. Before `DeleteGroup`, a destroy removed every member user from the group. CloudFormation's delete handler holds no `iam:RemoveUserFromGroup`, so there `DeleteGroup` fails with `DeleteConflict`. The stack's own memberships (a user's `Groups`, an `AWS::IAM::UserToGroupAddition`) are removed before the group, so the removal only reached a user the stack did not add. On a stack destroy the group is now deleted as is. When `DeleteGroup` answers `DeleteConflict`, cdkd re-reads the members every two seconds until the list has not changed for ten seconds (at most a minute). A group left with no member is deleted again; otherwise the delete fails without a retry, naming the users that `ListGroupsForUser` confirms are still in the group (at most five), and the next step. A deploy's delete still removes the members, since a same-name re-create relies on that (#4461).
