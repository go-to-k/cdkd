- **The `--prefer-sdk-route` accepted-drop warning no longer tells a type with no Cloud Control route to remove the override (issue [#2792](https://github.com/go-to-k/cdkd/issues/2792))** -- `src/provisioning/provider-registry.ts` (`reportSilentDropDecisions`, new `ccRouteUnavailableReason`), `tests/unit/provisioning/provider-registry-unroutable-drop-warn.test.ts`. For every accepted silent drop the warning said "Remove the override for <Prop> to route this resource via Cloud Control API instead", or, for a create-only property, that it can only be applied by recreating the resource. Neither holds for a type Cloud Control cannot serve -- a provider declaring `disableCcApiFallback` (`AWS::CloudFormation::Stack`, FSx, EMR and others) or a NON_PROVISIONABLE type: removing the override makes the next deploy refuse at pre-flight instead of rerouting, and a recreate lands on the same SDK provider that drops the property. For those types the warning now says so, names the reason, and prescribes no remedy, since no route applies the property. Other types keep their per-property remedies unchanged.
