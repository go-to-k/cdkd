- **A property CloudFormation replaces, but whose registry schema calls it mutable, now replaces the resource instead of failing the deploy (issue [#7070](https://github.com/go-to-k/cdkd/issues/7070))** -- `scripts/spec-replacement-candidates.ts`, `scripts/gen-spec-replacement-properties.ts`, `scripts/refresh-registry-create-only-paths.ts`, `src/analyzer/replacement-rules/spec-replacement-properties.generated.ts`, `src/analyzer/replacement-rules/evidence.ts`, `src/analyzer/replacement-rules/evidence-baseline.ts`, `src/provisioning/create-only-properties.ts`. Before this, changing an `AWS::Route53Resolver::ResolverRule` `DomainName` was sent to Cloud Control as an in-place update, which AWS refused (`NotUpdatable`), so `cdkd deploy` failed where CloudFormation replaced the rule. Every property `@aws-cdk/aws-service-spec` calls a replacement while the registry schema leaves it mutable, array and map members included, is now a candidate that needs a measured verdict or a line in an unmeasured baseline, and CI fails on a new unclassified one. The spec is not trusted on its own: 12 of the 14 probed rows update in place, so only measured `replace` rows change what a deploy does. The others keep their in-place update.
