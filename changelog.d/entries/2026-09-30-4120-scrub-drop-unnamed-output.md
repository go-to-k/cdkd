- **`cdkd scrub` now drops a stored output key the template no longer declares, instead of leaving its value beside the references it writes** (`src/cli/commands/scrub.ts` `planUnnamedOutputDrop`, go-to-k/cdkd#4120). Scrub rewrote only the outputs it could name. A deleted output's value, possibly a plaintext an older cdkd stored, stayed in the record next to the plain `{{resolve:ssm:...}}` token scrub had just written. `cdkd diff` reads that token as proof the record is redacted, so it printed the value on the output's removal row. On a run that records a secret for the stack, such a key is now removed, and named in a `Dropped` / `Would drop` line without its value. `--dry-run --fail` exits `1` until a real run or a deploy removes it. Kept instead: a key a pass rewrote onto its reference; one holding only whole references or no string; one whose name holds a recorded secret (still reported); one that may be a live export alias whose `Export.Name` this run could not reproduce, with a warning; and one another stack's recorded `Fn::ImportValue` / `Fn::GetStackOutput` still reads, which is a finding (`--fail` exits `1`) while the rest of the record is still scrubbed. A dropped alias also leaves the record's `exportNames`. When the other stacks' state cannot be read, nothing is dropped and the run ends with `SCRUB_DROPPED_OUTPUT_READERS_UNVERIFIED` (exit `2`). Tests: `tests/unit/cli/commands/scrub-drop-unnamed-output.test.ts`, `tests/unit/cli/commands/scrub-export-index.test.ts`.
