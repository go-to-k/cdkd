- **`cdkd scrub` now drops a stored output key the template no longer declares, instead of leaving its value beside the references it writes** (`src/cli/commands/scrub.ts` `planUnnamedOutputDrop`, go-to-k/cdkd#4120). Scrub rewrote only the outputs it could name. A deleted output's value, possibly a plaintext an older cdkd stored, stayed in the record next to the plain `{{resolve:ssm:...}}` token scrub had just written. `cdkd diff` reads that token as proof the record is redacted, so it printed the value on the output's removal row. Such a key is now removed, and named in a `Dropped` / `Would drop` line without its value. `--dry-run --fail` exits `1` until a real run or a deploy removes it. Three kinds are kept: a key a pass rewrote onto its reference; one holding only whole references or no string; and one that may be a live export alias whose `Export.Name` this run could not reproduce, which gets a warning instead. That last kind is one the record lists as an export, or any key when the record has no export list, unless every declared `Export.Name` resolved to a key the record holds. A dropped alias also leaves the record's `exportNames`. Before dropping, scrub reads every other stack's state record. It refuses the stack, writing nothing, with `SCRUB_DROPPED_OUTPUT_STILL_READ` when a recorded `Fn::ImportValue` / `Fn::GetStackOutput` reads a key it would drop, and with `SCRUB_DROPPED_OUTPUT_READERS_UNVERIFIED` when that state cannot be read. Tests: `tests/unit/cli/commands/scrub-drop-unnamed-output.test.ts`.
