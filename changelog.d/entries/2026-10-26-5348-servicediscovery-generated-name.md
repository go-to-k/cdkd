- **An `AWS::ServiceDiscovery::Service` without `Name` is now created under a generated name instead of being refused (issue [#5348](https://github.com/go-to-k/cdkd/issues/5348))** -- `src/provisioning/providers/servicediscovery-provider.ts`, `src/provisioning/resource-name.ts`. The CloudFormation schema leaves the name optional (aws-cdk-lib's L2 `Service` documents a CloudFormation-generated name), but the SDK provider failed the create with `Name is required for ServiceDiscovery Service`. The type now has a generated-name rule (63 characters: one DNS label), so a nameless service is named `{stack}-{logicalId}-{suffix}`, like the other generated names. A legacy stack's Cloud Control create still leaves the name to the handler, and the type is not admitted to orphan adoption. Unit cases in `tests/unit/provisioning/providers/servicediscovery-provider.test.ts`; the Cloud Map provider joins the SDK wire harness (`tests/unit/provisioning/sdk-wire-cases-cloudmap.ts`), whose create probe without `Name` now delivers the generated name; the `servicediscovery` integ fixture deploys a nameless service and keeps its name across every redeploy.
