- **`cdkd deploy --replace-resource <logicalId>` plans a resource's update as a replacement, and a Cloud Control `NotUpdatable` refusal says how to use it (issue [#7079](https://github.com/go-to-k/cdkd/issues/7079))** -- `src/cli/options/provisioning-route.ts`, `src/cli/commands/deploy/{stack-deploy,command,replace-resource-checks}.ts`, `src/deployment/replace-resource-targets.ts` (new), `src/deployment/deploy-engine/deploy-flow/{diff,plan-checks}.ts`, `src/deployment/deploy-engine/update-in-place/update-failure-remedy.ts` (new), `src/deployment/deploy-engine/update-in-place.ts`, `src/deployment/recreate-target-readers.ts`. A property AWS refuses to update in place that neither the registry schema nor a replacement rule names was sent as an update, and Cloud Control's `NotUpdatable` failed the deploy with no property named and no way out in cdkd. The new repeatable flag marks the named resource for replacement at plan time, as a template create-only change is: the plan and `--require-approval` show it, its readers are promoted, and a stateful target or reader is refused before anything changes unless `--force-stateful-recreation` is also given. A target with no change, a nested stack, or an id that does not name exactly one resource of the run is refused. `cdkd diff` does not take the flag yet ([#7089](https://github.com/go-to-k/cdkd/issues/7089)). The `NotUpdatable` refusal now names the resource and property, states that CloudFormation replaces it, prints the `--replace-resource` command (naming the data loss for a stateful resource), and links a prefilled issue carrying only the type, the property and the error code (for an `AWS::` or `Alexa::` type; any other type gets no link).
