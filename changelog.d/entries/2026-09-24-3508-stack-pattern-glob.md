- **Stack patterns: `*` is the only wildcard, and a star-heavy pattern no longer hangs (issue [#3508](https://github.com/go-to-k/cdkd/issues/3508))** -- `src/utils/glob-match.ts` (new), `src/cli/stack-matcher.ts`, `src/synthesis/failed-stages.ts`. A stack pattern containing `*` used to be compiled into a regular expression, in which every other character was regex syntax. So `'My.Stage*'` also matched `MyXStage1`, and `'My(Stage*'` failed with a `SyntaxError`, while the same characters in a pattern without `*` stayed literal. A pattern such as `'*a*a*a*a*a*a*a*a*b'` backtracked exponentially in the length of the stack name, taking about a minute at 60 characters. Both matchers now share one linear glob matcher: `*` matches any run of characters, line terminators included, and every other character is literal. This covers `deploy`, `diff`, `destroy`, `list`, `synth`, `publish-assets`, `scrub`, the `cdkd local` stack resolvers, and the Stage named when a selection comes back empty. A pattern that uses only `*` matches what it matched before.
