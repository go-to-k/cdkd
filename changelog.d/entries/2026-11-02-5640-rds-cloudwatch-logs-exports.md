- **The SDK provider sends `EnableCloudwatchLogsExports` for `AWS::RDS::DBCluster` and `AWS::RDS::DBInstance` (issues [#5639](https://github.com/go-to-k/cdkd/issues/5639), [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and new arms in the `rds-aurora` and `rds-dbinstance-backfill` integs. Before, a cluster or instance exporting logs to CloudWatch Logs, such as a CDK `rds.DatabaseCluster` or `rds.DatabaseInstance` given `cloudwatchLogsExports`, routed through Cloud Control. The list now rides `CreateDBCluster` / `CreateDBInstance`, and an update sends `ModifyDB*`'s `CloudwatchLogsExportConfiguration`: the log types the template added are enabled and the ones it dropped disabled, as CloudFormation's handlers compute it from the previous and the new template. Removing the property disables every log type the previous template declared; a log type enabled outside the template is left alone. The update waits until the change is applied (skipped under `--no-wait`). A value that is not a list of log type names is refused before any call. `cdkd drift` reads the enabled log types back, in any order. Resources already deployed through Cloud Control stay there.
