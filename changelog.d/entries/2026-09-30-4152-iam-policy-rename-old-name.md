- **Renaming an `AWS::IAM::Policy` in place no longer leaves the old-named inline policy on the principals it stays attached to** (`src/provisioning/providers/iam-policy-provider.ts` `update()`, go-to-k/cdkd#4152). The update put the new name on every listed role, group and user, but removed the old name only from principals that left the list. So a principal in both the old and the new list kept both policies, and the old grant was named by no cdkd record. The old name is now removed from every recorded principal that stays listed across a rename, and a principal that leaves the list loses every name it may hold. A rollback revert is covered too: it replays the update with the attempted bag as the recorded side while the physical id still names the old policy, so the name that record carries is also removed. A recorded `PolicyName` that is not an IAM policy name (a secret reference, the `***` mask) is never sent. A case-only rename removes nothing from a retained principal: IAM inline policy names are case-insensitive on one principal (measured: a second put in another casing updates the one policy, keeping its first spelling), so the removal would delete the live policy. A role, group or user the template respells only in case is the same principal and no longer loses the policy as a leaver. An update that must detach a leaving principal but has no usable recorded policy name now refuses before any call. Two `AWS::IAM::Policy` resources swapping names on one principal in the same deploy can still remove each other's grant (go-to-k/cdkd#4156). Tests: `tests/unit/provisioning/iam-policy-provider-target-shape.test.ts`; fixture: `iam-role-policies-drift-clean` (rename phase).
