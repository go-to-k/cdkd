- **An `Export.Name` that reads a `NoEcho: true` parameter is now refused whatever the value's length, and a no-change deploy re-checks an export alias it carries forward** (`src/deployment/deploy-engine/outputs.ts`, `src/analyzer/outputs-diff.ts`, `src/deployment/no-change-outputs-merge.ts`, `src/deployment/outputs-export-alias/secret-scan.ts`, go-to-k/cdkd#4657). An `Export.Name` intrinsic that reads a `NoEcho` parameter through `Ref`, an `Fn::Sub` variable, or an `Fn::Join` / `Fn::Select` / other intrinsic over one is refused from the template. Before, such a name was refused only when the value was 4 or more characters long, so a name embedding a 1-3 character value was published to `state.json`, `exportNames` and the exports index. An `Fn::If` reads only the branch its condition selects. The warning names the output and the parameter, never the name. A nested child also refuses a name reading a parameter its parent fills from a `NoEcho` source. When a no-change deploy carries a failed output's literal export alias forward from the previous record, it now runs the export-name check on that alias again. It drops an alias the check refuses, with the same warning, so a consumer's `Fn::ImportValue` of it stops resolving. When a no-change deploy instead keeps the previous outputs whole, one warning names the outputs whose earlier alias would be refused, never the alias. `cdkd diff` previews both, and shows an earlier alias under a now-refused name as a removal with its name withheld. Tests: `tests/unit/deployment/export-name-noecho-refusal-4043.test.ts`, `tests/unit/deployment/no-change-carried-alias-noecho-4657.test.ts`, `tests/unit/deployment/no-change-outputs-merge.test.ts`, `tests/unit/cli/diff-export-name-noecho-positional-4657.test.ts`.
