- **`cdkd drift` no longer hides a drift at a key literally named `__proto__` and no longer flattens a `Date` readback to `{}` before comparing it (issue [#3121](https://github.com/go-to-k/cdkd/issues/3121))** -- `src/analyzer/{drift-normalize,drift-principal-normalize,cc-api-strip,drift-calculator}.ts`, new `src/utils/own-keys.ts` (`hasOwnKey` / `ownValue` / `defineOwnKey` / `hasPlainPrototype` / `nullPrototypeRecord`, moved out of `src/cli/commands/drift.ts`, which now imports them), unit tests. The six comparison-side canonicalizers rebuilt every object node onto a `{}` literal, on BOTH comparison copies: an own `__proto__` key (what `JSON.parse` yields from `state.json` or a Cloud Control `Properties` document) was assigned as the rebuilt node's prototype and dropped symmetrically, so `calculateResourceDrift` returned `[]` for two bags differing only there; and `Object.entries(new Date())` is `[]`, so a `Date` member of a raw SDK readback reached the comparator as `{}` -- phantom drift against an ISO-string baseline, and `cdkd drift --accept` then persisted `{}` into the baseline. Each walk now rebuilds onto a null-prototype record and returns a non-plain value by identity, the pattern PR #3124 applied inside `drift.ts`. Net effect: a top-level or nested `__proto__` drift is detected, reported and accepted like any other key, and a `Date` readback is compared as itself and -- on a resource with no recorded secret -- persisted by `--accept` as its ISO string (with a recorded secret the redaction value walk still flattens it, [#2427](https://github.com/go-to-k/cdkd/issues/2427)); `drift-calculator.ts` compares a `Date` in its JSON form, so the next run reads that string and the readback's `Date` as EQUAL rather than as drift forever. Sweep: `grep -rn "Record<string, unknown> = {}" src/analyzer/` 9 -> 3 (the three left are `orphan-rewriter.ts` / `diff-calculator.ts`, not on the drift comparison path); 0 `key in bag` membership tests in the three files.
