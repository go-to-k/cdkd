- **`cdkd import` and `cdkd scrub` store a NoEcho parameter's position as `***`, and `cdkd export` exports a record masked only there (issue [#4043](https://github.com/go-to-k/cdkd/issues/4043), Phase C)** -- `src/cli/commands/{import,scrub,export}.ts`, `docs/cli-scrub.md`, `docs/cli-export.md`. `cdkd import` now writes a property its template fills from a `NoEcho` template parameter as `***` whatever the value's type or length, names it in `noEchoLeaves`, masks the observed baseline there, and masks and declares a same-named attribute echoing the value, as a v11 deploy does. Before, a value under 4 characters or a number stayed in the clear. `cdkd scrub` applies the same positional arm without a deploy. Where a record still holds a plaintext at such a position (a pre-v11 stack, or one deployed under an older `Default`), that value also masks its copies elsewhere in the record. A stack with no other secret is scrubbed for it, and `--dry-run --fail` counts it. An `Export.Name` the deploy refuses for holding or reading a `NoEcho` value no longer makes scrub keep every unnamed output key as a possible alias. `cdkd export` no longer blocks a resource whose only masks sit at those positions: the exported template reads the parameter, and CloudFormation receives its value. It still blocks one whose import identifier, or `AWS::IAM::Policy` pre-delete principals or name, a `NoEcho` parameter fills. Tests: `tests/unit/cli/import-noecho-positional-4043.test.ts`, `tests/unit/cli/commands/scrub-noecho-positional-4043.test.ts`, `tests/unit/cli/export-noecho-v11.test.ts`.
