- **`cdkd deploy` now refuses a list where the resource type's schema wants an object, or the reverse, before any provider runs (issue [#4357](https://github.com/go-to-k/cdkd/issues/4357))** -- `src/provisioning/property-shape.ts` + `.generated.ts`, `src/provisioning/provider-registry.ts`, `scripts/gen-property-shape.ts`, `scripts/refresh-cfn-schemas.mjs`, `tests/fixtures/cfn-schemas/*.json`. CloudFormation validates properties against the type schema up front (`Properties validation failed ... expected type: JSONArray, found: JSONObject`); cdkd forwarded such a value, which then failed inside an SDK call with an unrelated-looking error or was silently dropped. The deploy pre-flight now names each offending resource, type and property path in one error, in CloudFormation's words. Only array-versus-object contradictions the schema pins exactly are refused: scalars, type lists, disagreeing `oneOf` / `anyOf` arms, unknown types and paths, and every intrinsic (`Ref`, `Fn::*`) pass. The per-path table is generated offline from the committed schema fixtures (new `propertyShapes` section, `vp run gen:property-shape`); no AWS call is added. Tests: `tests/unit/provisioning/property-shape.test.ts`, `tests/unit/scripts/gen-property-shape.test.ts`.
