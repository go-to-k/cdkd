- **A Cloud Control update no longer restarts a running Kinesis Data Analytics (Flink) application, fails on a Zeppelin one, or fails on a Fargate Batch compute environment's `ComputeResources` change by re-sending unchanged write-only keys (issues [#6821](https://github.com/go-to-k/cdkd/issues/6821), [#6822](https://github.com/go-to-k/cdkd/issues/6822))** -- `src/provisioning/write-only-properties.ts`, `src/provisioning/cloud-control/update.ts`, `tests/unit/provisioning/cloud-control-write-only-kept-6788.test.ts`. Every update of an `AWS::KinesisAnalyticsV2::Application` re-sent its `ApplicationConfiguration` (and `RunConfiguration`), so the handler called `UpdateApplication`: a tag change restarted a running Flink application and took a snapshot (138-156 s vs 3 s), and failed on a Zeppelin application. Both now stay out while unchanged; an `ApplicationConfiguration`, `RunConfiguration`, `RuntimeEnvironment` or `ServiceExecutionRole` change still sends them together. A Fargate (`FARGATE` / `FARGATE_SPOT`) compute environment's `ComputeResources` change re-sent `UpdatePolicy` and `ReplaceComputeEnvironment`, which Batch refuses for Fargate ("parameters can't be updated for Fargate compute environment"); they now stay out while unchanged on Fargate, and an EC2 environment still sends them with a `ComputeResources` change.
