- **The ECS provider masks secret-resolved values in its own log lines, failure messages and pasteable commands (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), ECS slice)** -- `src/provisioning/providers/ecs-provider.ts`; unit tests in `tests/unit/provisioning/ecs-provider-masked-log.test.ts`. `create()` and `update()` of `AWS::ECS::Cluster`, `TaskDefinition` and `Service` used to write their debug, info and warning lines through a logger no deploy-engine mask reaches. They now route every line through the deploy's masker. A cluster name, task-definition family, service name or `Cluster` value that is secret-derived is masked wherever it occurs, including inside the ARN a success or tag line prints and the service ARN's embedded cluster name, and the `aws ecs wait services-stable` / `list-tasks` / `delete-service` commands that would carry one are withheld rather than printed. The AWS error text a create or update failure message wraps is masked before it is joined; when the mask changed that text, the failure is stamped so the retry classifiers still read AWS's unmasked wording (the issue [#4244](https://github.com/go-to-k/cdkd/issues/4244) class), so a secret overlapping retry wording does not turn a transient failure terminal. Also masked are the non-ECS deployment controller refusal and the `--full-wait` cleanup warnings. A Cluster or Service whose previous name in state is a secret reference or the redaction mask `***` has its recorded name masked too, which covers a rotated secret whose old plaintext is in no bag of this deploy. A secret shorter than four characters embedded in AWS error text is caught only when it is one of those names. The `delete()` path still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
