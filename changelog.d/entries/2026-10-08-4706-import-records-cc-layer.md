- **`--recreate-via-cc-api` of an imported Application Auto Scaling scalable target is now refused instead of silently losing its scaling policies, and `cdkd import` records a resource it read through Cloud Control as `provisionedBy: cc-api`** (`src/cli/commands/import.ts`, `src/deployment/recreate-targets/validate.ts`, `src/deployment/child-of-recreated-parent.ts`, go-to-k/cdkd#4706). Import recorded every resource as `sdk`, including a type with no SDK provider, which a deploy records as `cc-api`. For an `AWS::ApplicationAutoScaling::ScalableTarget` that let `--recreate-via-cc-api` past its already-on-Cloud-Control refusal: the recreate deregistered the target, which deletes its scaling policies, and re-registered it under the same `ResourceId|ScalableDimension|ServiceNamespace` id, so each `AWS::ApplicationAutoScaling::ScalingPolicy` resolved exactly as recorded, was skipped as unchanged, and state kept policies AWS no longer had under a green deploy. Import now records the layer its routing chose; the pre-flight refuses `--recreate-via-cc-api` of a type with no SDK provider whatever its record says, so a record an earlier import wrote is covered too; and a scaling policy whose target is re-created under the same id is re-created with it, like a Lambda permission with its function (go-to-k/cdkd#4411). Tests: `tests/unit/cli/import.test.ts`, `tests/unit/deployment/recreate-targets.test.ts`, `tests/unit/deployment/child-of-recreated-parent.test.ts`; integ `app-autoscaling-recreate`.
