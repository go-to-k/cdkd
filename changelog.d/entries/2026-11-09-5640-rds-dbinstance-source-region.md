- **An `AWS::RDS::DBInstance` declaring `SourceRegion` (a cross-region read replica) stays on the SDK provider (issue [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds-provider.ts`, `src/provisioning/providers/rds/read-replica.ts`, `instance-create.ts` and `drift.ts` beside it, `src/utils/ecr-uri.ts` (`isKnownAwsRegionId`), `src/provisioning/property-coverage.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, the read-replica unit file, the RDS wire cases, and a cross-region replica arm in the `rds-dbinstance-backfill` integ (a second stack holds the source in another region). Before, a declared `SourceRegion` routed the instance through Cloud Control. CloudFormation's handler refuses a region it does not know ("Unknown source region") and otherwise only hands the value to its SDK, which signs the cross-region `PreSignedUrl` for that region and never sends `SourceRegion` itself; the JS SDK signs the same URL from the source ARN's region, so cdkd sends nothing for it and refuses an unknown or non-string value before any call (a rollback replay of a recorded state only warns). `cdkd drift` does not compare it: RDS never returns it. An `aws-cn` cross-region replica (a source ARN in another `aws-cn` region) keeps the Cloud Control route: RDS in China honours the cross-region `PreSignedUrl`, and the JS SDK signs it for the commercial `amazonaws.com` host rather than `amazonaws.com.cn`.
