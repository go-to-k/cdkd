- **An IAM role or managed policy delete refuses a resource that took over the recorded name, and a rollback refuses a same-named managed policy, table, DB instance or DB cluster someone else created (issue [#6655](https://github.com/go-to-k/cdkd/issues/6655))**. Both deletes address AWS by name, so a role re-created under its name outside cdkd was deleted by a destroy, template removal, replacement or rollback. The `GetRole` / `GetPolicy` each delete already made now compares the live `RoleId` / `PolicyId` with the recorded one; a difference still there on a re-read 5 s later refuses before any detach, non-retryable, naming the attribute (no value) and the `cdkd state orphan --resource` remedy, record kept. Unlike CloudFormation, which deletes that resource, the destroy fails until the record is dropped with `cdkd state orphan`. No recorded id: by-name delete as before. The rollback's survivor check adds `PolicyId`, `TableId`, `DbiResourceId` and `DBClusterResourceId` beside `RoleId`. A record without its id acquires it once from an update or `Fn::GetAtt` read; a recorded id is never replaced (an in-place update answering another warns), and a failed delete-first replacement replaces the dead one with the id its create reported (or drops it).
