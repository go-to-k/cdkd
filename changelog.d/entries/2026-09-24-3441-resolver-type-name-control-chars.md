- **Resolver messages no longer print a template's type name or malformed `Fn::GetAtt` text raw (issue [#3441](https://github.com/go-to-k/cdkd/issues/3441))** -- `src/deployment/intrinsic-function-resolver.ts`. A resource `Type`, a parameter `Type`, a string-form `Fn::GetAtt` operand or a non-literal `Fn::GetStackOutput` `RoleArn` from a hand-written or migrated template could carry terminal control characters, and several resolver refusals and warnings printed that text as written: the physical-ID fallback's two refusals and two warnings, the placeholder-account refusal, the unserved-attribute refusal, `Invalid Fn::GetAtt format`, the `RoleArn` shape echo, the nested-stack secret-coercion refusal, and the unrecognized SSM parameter `Type` warning. Each now renders through the resolver's display builder, which strips control characters and line or bidi overrides and masks recorded secrets. An ordinary type name prints exactly as before. Three renders stay raw because they are reached only after an exact match against cdkd's own type names. Tests: `tests/unit/deployment/resolver-type-name-control-chars.test.ts`.
