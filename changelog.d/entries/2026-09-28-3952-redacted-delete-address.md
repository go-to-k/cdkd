- **A delete whose recorded address property cdkd redacted is now a named skip, or uses an unredacted source, instead of sending the redaction to AWS (issue [#3952](https://github.com/go-to-k/cdkd/issues/3952))** -- new `src/provisioning/redacted-delete-address.ts` (`redactedDeleteAddressSkip`, `REDACTED_DELETE_ADDRESS_SKIP_REASON`), the ApiGateway, ApiGatewayV2, ECS, Glue, Scheduler, Route 53, EC2 (security-group ingress), CloudWatch anomaly-detector, RDS DB proxy target-group, IAM policy / access key / UserToGroupAddition, Lambda permission and EMR instance fleet / group providers, and `tests/unit/provisioning/redacted-delete-address.test.ts`. State stores the `***` mask of a `NoEcho` value a resource read, and a secret `{{resolve:...}}` reference as its expression; a delete that named the resource by such a property sent it to AWS, where several APIs answer an unknown name with "not found" -- which the provider read as already deleted, dropping the record over a live resource (a Route 53 TXT record whose value holds a masked token is the likeliest case). Now a second source is used where one exists (a Lambda permission's function or an ECS service's cluster in its physicalId, an IAM policy's name, an access key's owner looked up from IAM, a Route 53 record's zone in its physicalId), and otherwise the delete reports `outcome: 'skipped'` before any AWS call: the record is kept and `cdkd destroy` exits 2. A security-group ingress UPDATE whose old rule cannot be revoked now fails before authorizing the new one, and an ApiGateway Resource replacement reports the old resource as a survivor. EMR TASK configs skip only their best-effort scale-to-0.
