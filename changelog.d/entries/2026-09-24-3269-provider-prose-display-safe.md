- **The SSM parameter and S3 bucket providers, and the log group cleanup warning, now render the names, physical ids and logical ids in their own message prose display-safe (issue [#3269](https://github.com/go-to-k/cdkd/issues/3269))** -- `src/provisioning/providers/ssm-parameter-provider.ts`, `src/provisioning/providers/s3-bucket-provider.ts`, `src/provisioning/providers/logs-loggroup-provider.ts`, new `tests/unit/provisioning/provider-prose-display-safe.test.ts`. Issue #3136 made the pasteable `aws ...` command in four of these messages safe, but the same value was also written into the sentence beside it unchanged, so a terminal escape, `U+0085`, a Unicode line separator or a bidi override in a template-supplied parameter or bucket name reached the terminal in the same line as the hardened command. Each such value now goes through `displaySafe` where it is interpolated, across both files: the partial-create cleanup warnings, the `cdkd import` refusal for an ARN-shaped SSM id, the delete / update / create log lines, the lifecycle-rule warnings, and the value a malformed analytics or inventory destination refusal quotes (which `JSON.stringify` alone did not make terminal-safe). The `AWS::Logs::LogGroup` partial-create cleanup warning (`src/provisioning/providers/logs-loggroup-provider.ts`) had the same raw prose copy beside its hardened command; it is sanitized too, and that warning now goes through the caller's secret masker, which it never reached before, with the masker also threaded into its command so a secret-bearing log group name suppresses the command. Where a masker is available it runs before `displaySafe`, so a secret that contains a character `displaySafe` rewrites is still masked. A clean value renders exactly as before.
