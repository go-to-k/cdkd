- **`cdkd deploy` waits for an `AWS::BedrockAgentCore::Runtime` to be `READY` after its create and update (issue [#6490](https://github.com/go-to-k/cdkd/issues/6490))** -- `src/provisioning/providers/agentcore-runtime-provider.ts`. The SDK provider used to return while the runtime was still `CREATING` or `UPDATING`, so a dependent resource or the next call could meet a runtime in flight, and a runtime ending in `CREATE_FAILED` or `UPDATE_FAILED` did not fail the deploy. Both now fail it, as Cloud Control does. `--no-wait` skips the wait. A delete of a runtime still `CREATING` or `UPDATING` now waits for it first, in every mode.
