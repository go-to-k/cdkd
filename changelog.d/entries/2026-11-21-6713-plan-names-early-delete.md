- **The deploy's plan now says when a replacement deletes the old resource before the deploy succeeds, so a failed deploy cannot bring back what it held (issue [#6713](https://github.com/go-to-k/cdkd/issues/6713))** -- `src/analyzer/destructive-changes.ts` (`DestructiveChange.earlyDelete`, `plannedEarlyDelete`), `src/analyzer/diff-calculator/provider-replacement.ts` (each planner's `oldDeleted`), `src/deployment/rollback-executor/early-deleted-old.ts` (`plannedEarlyDeleteNote`, shared with the rollback's wording), `src/cli/commands/diff-recursive/render.ts` and `json.ts`, `docs/cli-diff.md`, `docs/cli-diff-json.md`, `docs/destructive-changes.md`, `docs/cli-rollback-limitations.md`. Before, `cdkd diff --fail-on destructive` and the `--require-approval destructive` prompt listed such a change as a plain `will be replaced`, and only the rollback said afterwards that the old resource came back from its recorded properties only. Now the line ends `— the deploy deletes the old resource before creating its replacement, so a failed deploy's rollback does not restore what AWS held for it beyond its recorded properties` for an SNS subscription its provider re-creates, a renamed Route 53 record set (`before the deploy succeeds`) and, in the approval prompt, a `--recreate-via-*` target not kept by `UpdateReplacePolicy: Retain`; the diff's `[requires replacement: ...; deleted, then created again]` line carries the same consequence, and `--json`'s `destructiveChanges` gains an optional `earlyDelete`. An IAM inline policy gets no note (its record restores it whole). Cases only the deploy learns (an update AWS rejects, a new resource holding the old physical id and type, `--replace` after a name collision) are not noted. No AWS call and no exit code changes.
