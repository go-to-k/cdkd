- **`cdkd deploy --no-wait`: a Bedrock AgentCore runtime endpoint waits for its runtime to be `READY` (issue [#6962](https://github.com/go-to-k/cdkd/issues/6962))** -- `src/provisioning/deferred-refusal-edges.ts`, `src/provisioning/cloud-control/create.ts`, `src/provisioning/cloud-control/update.ts`, `docs/cli-deploy-waits.md`, `docs/cli-deploy.md`, `src/cli/options.ts`. AWS refuses `CreateAgentRuntimeEndpoint` while the runtime is `CREATING` (`Agent version 1 must be in READY status`, measured), so under `--no-wait` an `AWS::BedrockAgentCore::RuntimeEndpoint` create or update now waits for the runtime's skipped `READY` wait first instead of failing. The other measured candidates need no wait: an RDS proxy target group registers a still-`creating` DB instance or Aurora cluster, no CloudFormation resource uses a Lambda MicroVM image, and an ACM certificate left in `PENDING_VALIDATION` is the point of `--no-wait`. Tests: `tests/unit/provisioning/deferred-refusal-edges-6962.test.ts`.
