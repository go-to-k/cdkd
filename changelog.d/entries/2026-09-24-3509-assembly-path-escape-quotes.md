- **A containment refusal no longer wraps an assembly-derived path in quotes of its own (issue [#3509](https://github.com/go-to-k/cdkd/issues/3509))** -- `src/utils/assembly-path.ts` (`renderAssemblyPathEscape`, new `displayAssemblyPath`). The shared tail of every "resolves to ..., outside ..." refusal printed the resolved path, the symbolic-link target and the assembly directory inside cdkd's own `'...'`. The resolved path embeds the value the assembly chose, and the sanitizer passes `'`, so a crafted `directoryName`, `templateFile`, asset `file` or `aws:asset:path` could close that quote and write a clause saying the opposite of the refusal. Each path now renders bare only when every character is a visible letter (with any combining accents on it), a digit, or one of `/ \ . _ ~ + @ : = -`. Anything else renders as a JSON string. Inside that string, an embedded `"`, a curly or fullwidth quote, and any character that draws as a blank are escaped, so none of them can pass for the end of the value. A legitimate path loses its quotes (`resolves to /etc/passwd, outside /path/to/cdk.out.`); one with a space or any other symbol renders in double quotes. Non-ASCII letters and long paths are shown in full. The command still refuses in every case; only the explanation changes.
