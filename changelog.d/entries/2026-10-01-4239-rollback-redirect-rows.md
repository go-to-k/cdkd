- **`cdkd rollback`'s Type-change plan rows and the Scheduler `GroupName` refusal say `from <a> to <b>` instead of ` -> `, and `cdkd rollback` describes a stack name or region that is not a plain identifier in its plan header, prompt and completion lines (issues [#4239](https://github.com/go-to-k/cdkd/issues/4239), [#3760](https://github.com/go-to-k/cdkd/issues/3760))** -- `src/cli/commands/rollback.ts`, `src/provisioning/providers/scheduler-schedule-provider.ts`. Pasted into a shell, `->` is `-` plus a `>` redirect onto the type or group name after it, so the pair dragged from a `reverse-replace` / failed-Type-change row, or from the `GroupName addresses the schedule` refusal, created or truncated a file named by that value. The refusal also masks the group names where it builds the message, as the provider's debug line already did for a secret-derived group (go-to-k/cdkd#4275), and describes a group name that is not a plain identifier, since the line names `cdkd deploy --replace`. The rollback plan header, the confirmation prompt, the `State for ... removed` and `Rollback of ... complete` lines and the nested-stack plan preview printed a journal-key stack name with its interior spaces; in a run whose failed-persist warning prints a `Re-run with:` row (with that name withheld), a padded name could wrap on screen into a counterfeit row beside it. They now print the name only when it is a plain identifier and describe it otherwise, with a pointer to `cdkd state list --long` under the header, and at the end of each nested-stack block, that described one; a nested-child preview whose read failed withholds the backend's error text when it names a padded child.
