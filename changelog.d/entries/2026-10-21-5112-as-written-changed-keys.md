- **A Cloud Map Service whose `Description` comes from a secret dynamic reference or a `NoEcho` parameter now keeps a removed `HealthCheckConfig` when the `Description` did not change, as CloudFormation does (issue [#5112](https://github.com/go-to-k/cdkd/issues/5112))** -- `src/types/resource.ts`, `src/deployment/deploy-engine/{update,update-in-place}.ts`, `src/provisioning/providers/servicediscovery-provider.ts`. State records such a `Description` as its `{{resolve:...}}` token or `***`, which the provider could not compare with the resolved value, so it treated it as changed: every update of that Service sent `UpdateService` (a `Tags`- or `ServiceAttributes`-only change included), clearing a removed `HealthCheckConfig` and, with a removed `DnsConfig`, failing. The deploy now hands providers the properties that changed template to template (`UpdateContext.changedProperties`), counting a masked or secret-derived value as changed when its template, inputs or secret version moved, or when AWS did not confirm a `NoEcho` value (for a Service, cdkd reads it back to check); the Service sends `UpdateService` only for a `Description` / `HealthCheckConfig` change among them. A rollback and `cdkd drift --revert` compare as before.
