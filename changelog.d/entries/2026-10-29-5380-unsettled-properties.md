- **A failed update now records the property changes it had already started, so the next deploy converges them (issue [#5380](https://github.com/go-to-k/cdkd/issues/5380); state schema v14)** -- `src/types/state.ts`, `src/types/resource.ts`, `src/state/unsettled-properties.ts`, `src/deployment/deploy-engine/{execute,update,update-in-place}.ts`, `src/analyzer/diff-calculator.ts`, `src/cli/commands/drift.ts`, `src/provisioning/providers/firehose-provider.ts`. A Firehose encryption Start or Stop whose wait failed (`*_FAILED`, the per-resource deadline, Ctrl-C) left the previous block in state, so a deploy back to that template diffed empty and the stream stayed in the other state until `cdkd drift`. A provider now calls `UpdateContext.markUnsettled(key)` just before such a call, and a failed update records the names (never values) as `ResourceState.unsettledProperties`. The next deploy treats each one as changed, whichever template it deploys, and the provider reads AWS and sends only what differs. A successful update, `cdkd rollback --revert-failed` and `cdkd drift --accept` / `--revert` clear them, and `cdkd drift` lists them (`unsettled` in `--json`). Firehose encryption is the first adopter. State written by this version needs a cdkd that reads schema 14.
