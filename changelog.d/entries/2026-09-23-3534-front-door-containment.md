- **`cdkd local start-alb` and `cdkd local start-cloudfront` now contain a Lambda's `Metadata['aws:asset:path']`, like their siblings (issue [#3534](https://github.com/go-to-k/cdkd/issues/3534), PR #3545)** -- `package.json`, `pnpm-workspace.yaml`, `docs/local-emulation.md`. Those two reach Lambda code through the bundled `cdk-local` engine rather than cdkd's own resolver, so go-to-k/cdkd#3494's guard did not apply to them: an assembly naming a directory outside the output directory had it bind-mounted at `/var/task` with no refusal and no warning, while `cdkd local invoke` and `cdkd local start-api` warned about the identical value. **Behavior change:** the bump to `cdk-local@0.149.0` carries go-to-k/cdk-local#744, which applies the same rule in that engine -- a relative escape is refused, an absolute one is accepted with a warning naming the directory, and the bound is the asset outdir rather than the manifest directory, so a Stage's `../asset.<hash>` still resolves. Verified against the installed package, not the version number: the guard's text is present in `node_modules/cdk-local/dist` and the old unguarded `isAbsolute(assetPath) ? assetPath : …` spelling is gone. `cdk-local` is also excluded from pnpm's `minimumReleaseAge`, with the trade recorded at the entry -- it is first-party and reviewed in its own repository before the tag, and the cost is that a compromised publish would install immediately.
