- **When the delete of the old resource fails with an AWS API error during `cdkd deploy --replace`'s delete-first fallback or `--recreate-via-cc-api` / `--recreate-via-sdk-provider`, the `RESOURCE_FAILED` event now records the AWS error code and request id (issue [#1889](https://github.com/go-to-k/cdkd/issues/1889))** -- `src/deployment/deploy-engine/replacement.ts`, `src/deployment/deploy-engine/update-replace.ts`. Both paths re-threw the delete's failure as a new error with no `cause`, so the event's `awsErrorCode` / `requestId` were absent. The delete error is now chained as the `cause`, masked with the resource's resolved secrets like the message. A Cloud Control handler failure or a refusal cdkd raises itself still records neither, since neither carries AWS response metadata. The `--replace` re-create wrap's existing `cause` is masked the same way, and the `--recreate-via-*` destroy message is now masked where it is built. Tests: `tests/unit/deployment/deploy-engine-rewrap-masked-cause-1889.test.ts`; integ `recreate-via-cc-api` gains Sub-3e, a recreate whose bucket delete a bucket policy denies.
