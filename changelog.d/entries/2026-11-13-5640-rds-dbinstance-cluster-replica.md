- **The SDK provider creates an `AWS::RDS::DBInstance` read replica of a Multi-AZ DB cluster (issue [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds/read-replica.ts`, `instance-create.ts`, `instance-update.ts`, `instance-delete.ts`, `instance-pitr.ts`, `read-state.ts`, `drift.ts`, `rds-provider.ts`, the regenerated property-coverage map, unit tests, and a cluster-replica phase in the `rds-dbinstance-snapshot-restore` integ. Before, an instance declaring `SourceDBClusterIdentifier` routed through Cloud Control. Now the create is a `CreateDBInstanceReadReplica` from that cluster, as CloudFormation's handler makes it: the members it carries and the follow-up `ModifyDBInstance` are the instance replica's, and an undeclared engine is read from the cluster. Declaring both `SourceDBInstanceIdentifier` and `SourceDBClusterIdentifier` is refused before anything is made, as RDS refuses the pair. On an existing instance, a removed `SourceDBClusterIdentifier` promotes the replica; an added or changed one is refused, as CloudFormation refuses it. The replica is deleted without a final snapshot, and drift reads its source back. A point-in-time key beside it still makes a point-in-time restore, which names the cluster key as not applied. Resources deployed through Cloud Control stay there.
