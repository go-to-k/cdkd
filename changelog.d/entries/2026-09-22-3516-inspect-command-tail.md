- **A malformed-`resources` message no longer buries its pasteable `cdkd state show` mid-sentence, and three refusals no longer name a target whose own name could forge the command beside it (issue [#3516](https://github.com/go-to-k/cdkd/issues/3516), PR #3517)** -- `malformed-resources-bag.ts`. `malformedStateDetail` baked a fully-substituted `cdkd state show <stack> --stack-region <region> --json` into the end of a shared diagnosis half that every consumer appends prose after, so the one runnable command sat a single space from the next clause and a line-select paste handed it that clause as positional arguments. **Behavior change 1:** `cdkd deploy`'s refusal, the shared write refusal and the read-only `resources` warning now END on the read command; the two DESTROY refusals emit one command per line instead (`Inspect the record:` then `Drop the record:`), because one line cannot both end on the read and keep the `cdkd state orphan <stack> --stack-region <region>` template last with no substituted region after it. **Behavior change 2, and INDEPENDENT of the placement change:** every message that offers the destructive remedy as a TEMPLATE now requires its identifiers to be shell-plain (`isPasteableIdent`) as well as exactly rendered, so a stack name or region spelling one of cdkd's own labels no longer takes the naming arm. Three messages therefore WITHHOLD a target they previously named: both destroy refusals and `cdkd destroy`'s divergent-record-region refusal. Each still names how to find the record; only the DELETING command degrades to a template. `cdkd orphan`'s properties refusal is deliberately NOT gated here -- it substitutes rather than templating, so the same change would withhold the drop command from a legacy record whose name merely needs quoting; tracked by go-to-k/cdkd#3523. The divergent-region exposure predates this issue and is closed here opportunistically. Residuals: go-to-k/cdkd#3518, go-to-k/cdkd#3519.
