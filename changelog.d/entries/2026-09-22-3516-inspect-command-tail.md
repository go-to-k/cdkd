- **The pasteable `cdkd state show` command in a malformed-`resources` message no longer sits mid-sentence, and the two destroy refusals put each command on its own line (issue [#3516](https://github.com/go-to-k/cdkd/issues/3516), PR #3517)** -- `malformed-resources-bag.ts`. `malformedStateDetail` baked a fully-substituted `cdkd state show <stack> --stack-region <region> --json` into the end of a shared DIAGNOSIS half, and all four of its consumers appended prose after it, so the one runnable command in each message was followed by the next clause with a single space between: a line-select paste handed `cdkd state show` the rest of the sentence as positional arguments. `malformedDeployResourcesRefusalMessage`'s own doc comment already claimed "the command is emitted LAST", which it was not. **Behavior change:** the diagnosis half now carries no command, and `cdkd deploy`'s refusal, the shared write refusal and the read-only `resources` warning each END on the read command, which is `inspectCommand`'s documented contract and the shape the `outputs` and `orphans` destroy twins already had. The two DESTROY refusals -- for `resources` and for `orphans` -- now emit one command per line instead, `Inspect the record:` then `Drop the record:`, because a single line cannot hold both safely: the pasteable read has to end its line, and the `cdkd state orphan <stack> --stack-region <region>` template has to be last with no substituted region after it, or the value an operator is told not to trust sits below the holes they must fill by hand. That template is still never substituted, the exactness gate still decides whether any target is named, and the withhold arm still offers no destructive line at all. An absent region still drops the `--stack-region` flag. The stale sentence blaming "the region cdkd was pointed at" is replaced by the reason that still holds: an S3 key segment is chosen by anyone who can write the bucket.
