- **A fix-forward deploy now deletes the IAM instance profile or managed policy an earlier failed CREATE left behind (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606), IAM instance profile and managed policy slice)** -- `src/provisioning/providers/iam-instance-profile-provider.ts`, `src/provisioning/providers/iam-managed-policy-provider.ts`. When a `cdkd deploy --no-rollback` made an `AWS::IAM::InstanceProfile` or `AWS::IAM::ManagedPolicy`, failed wiring it (adding its role, or attaching the policy to a group, role or user) and could not delete it again, and a later deploy kept the logical id under another name, the successful deploy warned about the earlier profile or policy, left it in AWS and exited 2; `cdkd rollback` and `cdkd destroy` kept it the same way. The providers now answer both questions: an instance profile or policy name is unique per account, so the earlier one is a different one once the record's reads back (two whose names are equal ignoring case are never compared); and the failed CREATE records the `InstanceProfileId` / `PolicyId` its `CreateInstanceProfile` / `CreatePolicy` returned, so the earlier one is deleted (a policy detached first) only while its name still reads back under that id. One deleted by hand and re-created under the name has another id and is kept, with a warning. A managed policy that reads back but is gone by its `DeletePolicy` (a concurrent delete) is now treated as already deleted, after the region check, instead of failing the delete. Tests: `tests/unit/provisioning/iam-profile-policy-provider-same-resource-4606.test.ts`; integ: `iam-profile-policy-fix-forward-orphan`.
