- **A planted stack name or region can no longer render byte-identical to a different, genuine `Stack (region)` reference in `cdkd state list` or in the `state orphan` / `state refresh-observed` confirmation prompts (issue [#3164](https://github.com/go-to-k/cdkd/issues/3164))** -- `src/cli/commands/state.ts` (`formatStackRefSafe`), `docs/cli-state.md`, new `tests/unit/cli/state-ref-display-boundary.test.ts`. Both halves of a reference now render through `displayIdent` instead of the bare `displaySafe(..., { asciiOnly: true })` allowlist. That allowlist closes line FORGERY and nothing more -- it is the identity on printable ASCII -- while the ` (region)` suffix is cdkd's OWN annotation, so a 2-segment legacy key `cdkd/ProdStack (us-east-1)/state.json` yielded a region-less ref printing byte-equal to the genuine `ProdStack` in `us-east-1`. A `cdkd state list | while read -r ref` cleanup loop -- the consumer the sanitization exists for -- could not tell them apart, so it acted on the wrong reference. The REGION half is the same attack from the other side: a planted `x) (us-east-1` made `Decoy` read as `Decoy (x)` in `us-east-1`. `displayIdent` JSON-quotes any value that is not a plain identifier, keeps the `<unrenderable>` fallback, and caps the length -- the NAME half at 1152, not the 255 default, because a cdkd state-record name is not a CloudFormation stack name (nested-stack children accrete a `~<logicalId>` per level) and 255 would CUT a legitimate deep child. `cdkd rollback`'s candidate list takes that cap too. All SIX callers change together -- the plain listing, `--long`, `--tree`, both `state orphan` sites and the `state refresh-observed` prompt -- rather than the listing alone. Every legitimate row is unchanged to the byte. The quotes are a boundary for a READER, not shell quoting, and a terminal that wraps a very long name can still show a line reading like a genuine row; `--json` is unchanged and still unsanitized (go-to-k/cdkd#3163, go-to-k/cdkd#3179).
