- **A planted stack name or region can no longer render byte-identical to a different, genuine `Stack (region)` reference in `cdkd state list` or in the `state orphan` / `state refresh-observed` confirmation prompts (issue [#3164](https://github.com/go-to-k/cdkd/issues/3164))** -- `src/cli/commands/state.ts` (`formatStackRefSafe`), `docs/cli-state.md`, new `tests/unit/cli/state-ref-display-boundary.test.ts`. Both halves of a reference now render through `displayIdent` instead of the bare `displaySafe(..., { asciiOnly: true })` allowlist. That allowlist closes line FORGERY and nothing more -- it is the identity on printable ASCII -- while the ` (region)` suffix is cdkd's OWN annotation of the line, so a 2-segment legacy key `cdkd/ProdStack (us-east-1)/state.json` yielded a region-less ref whose `stackName` is literally `ProdStack (us-east-1)` and printed byte-equal to the genuine `ProdStack` in `us-east-1`. A `cdkd state list | while read -r ref` cleanup loop -- the consumer the sanitization exists for -- could not tell them apart, so it acted on the wrong reference and the planted record survived the sweep. The REGION half is the same attack from the other side (a region is an S3 key segment, or the state body via `readLegacyRegion`): a planted `x) (us-east-1` made `Decoy` read as `Decoy (x)` in `us-east-1`. `displayIdent` JSON-quotes any value that is not a plain identifier, cuts at 255 code points, and keeps the existing `<unrenderable>` fallback. All SIX callers change together -- the plain listing, `--long`, `--tree`, both `state orphan` sites and the `state refresh-observed` prompt -- rather than the listing alone; in a prompt the quoted form is the most valuable, that sentence being the one an operator answers `y` to. Every legitimate row is unchanged to the byte: stack names (`Parent~Child` included) and AWS region codes are all plain identifiers. `--json` is unchanged and still unsanitized (go-to-k/cdkd#3163).
