- **A planted stack name or region can no longer render byte-identical to a different, genuine `Stack (region)` reference in `cdkd state list` or in the `state orphan` / `state refresh-observed` confirmation prompts (issue [#3164](https://github.com/go-to-k/cdkd/issues/3164))** -- `src/utils/display-safe.ts`, `src/cli/commands/{state,rollback}.ts`, `docs/cli-state.md`, new `tests/unit/cli/state-ref-display-boundary.test.ts`. Both halves of a reference now render through `displayIdent` instead of the bare `displaySafe(..., { asciiOnly: true })` allowlist. That allowlist closes line FORGERY only -- it is the identity on printable ASCII -- while ` (region)` is cdkd's OWN annotation, so a 2-segment legacy key `cdkd/ProdStack (us-east-1)/state.json` printed byte-equal to the genuine `ProdStack` in `us-east-1`, and a `cdkd state list | while read -r ref` cleanup loop acted on the wrong one. One trailing space did it too: sanitization maps non-printable ASCII to a space then TRIMS, so `cdkd/ProdStack /...` was trimmed back to `ProdStack` before any boundary test -- as were leading space, tab, NUL, ESC and a padded REGION. `displayIdent` now renders a value bare only when sanitization was the IDENTITY on it AND what remains is a plain identifier; the identity half closes the padding class at its root. The NAME half caps at 1152, not the 255 default, because a state-record name is not a CloudFormation stack name (nested-stack children accrete a `~<logicalId>` per level) and 255 would CUT a legitimate deep child; `cdkd rollback` takes that cap at all twelve of its stack-name renders. All SIX callers change together, and every legitimate row is unchanged to the byte. The quotes are a boundary for a READER, not shell quoting, and a terminal that wraps a very long name can still show a line reading like a genuine row; `--json` is unchanged and still unsanitized (go-to-k/cdkd#3163, go-to-k/cdkd#3179).
