- **Switching a Route 53 record from `HostedZoneName` to the same zone's `HostedZoneId` now updates it in place (issue [#6537](https://github.com/go-to-k/cdkd/issues/6537))** -- `src/analyzer/replacement-rules/rules.ts` + `predicates.ts` (`route53ZoneReferenceChanged`), `src/provisioning/providers/route53/record-set.ts`, `route53/record-set-group.ts` and `route53/shared.ts`, unit tests and a `route53` integ fixture phase. For an `AWS::Route53::RecordSet` or `AWS::Route53::RecordSetGroup`, cdkd planned that switch (or the reverse) as a replacement, whose create-first collided with the live record, so the deploy failed while CloudFormation updates it in place. A switch between the two keys is no longer a replacement by itself; the update checks that the new reference names the zone the records are in and refuses one naming another zone. Two different ids, or two different names, still replace.
