- **`cdkd orphan` reads every `AWS::EC2::Subnet` return value live when it rewrites a dependent's `Fn::GetAtt` (issue [#5968](https://github.com/go-to-k/cdkd/issues/5968))** -- `src/provisioning/providers/ec2/subnet-attributes.ts`. Before, the SDK provider's `getAttribute` answered only `SubnetId`, `AvailabilityZone`, `AvailabilityZoneId`, `CidrBlock` and `VpcId`, so orphaning a subnet that a sibling read through `Ipv6CidrBlocks`, `NetworkAclAssociationId`, `BlockPublicAccessStates` (or a dotted `BlockPublicAccessStates.<member>`) or `OutpostArn` aborted as unresolvable without `--force`. Each now comes from `DescribeSubnets` (`DescribeNetworkAcls` for `NetworkAclAssociationId`) in the value shape a deploy resolves (#5944): `Ipv6CidrBlocks` lists the associated blocks, `[]` when the subnet has none. A block still associating with none associated, a value AWS does not report, or a failed read stays unresolvable, as the deploy refuses it. Tests: `tests/unit/provisioning/ec2-subnet-getattribute-5968.test.ts`; integ: `orphan-getatt-takeover`.
