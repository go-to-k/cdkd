- **`cdkd drift`'s human report no longer prints a state- or readback-derived value raw (issue [#3232](https://github.com/go-to-k/cdkd/issues/3232))** -- `src/cli/commands/drift.ts` (`writeHumanReport`, three row helpers and `reportValue`), new `tests/unit/cli/drift-report-sanitize.test.ts`. The stack name and region of every heading, each `~` / `!` / `?` row's logical id and resource type, and each changed property's path and both of its values go through `safeMsg` at the row that prints them, so a hand-edited record or a hostile value on the live resource can no longer invent a `✓ ... no drift detected` row or reorder what the reader sees. In an identifier, a control character becomes a space and a CSI or terminated OSC is removed whole (cdkd's own colour codes are kept, as on every logger line, and any other colour code becomes a reset); identifiers are capped at 255 code points (the stack name at the state-reference cap) with a `...` mark. A property value is never trimmed or capped; a string value that carries a control character (ESC included), has whitespace at either end or starts with `"` prints as its JSON string, with every control character written as an escape (`"abc\n"`, `"a\tb"`, `" value "`), so a drift that differs only by a trailing newline, a tab or padding still shows two different sides; a structured value's JSON is escaped the same way, and any other string prints byte-for-byte as before. What this does not cover (another invisible character, one kind of space for another, a look-alike letter, a string vs a number spelling the same text) is in [the docs](https://cdkd.dev/cli-drift/#what-the-human-report-does-to-a-malformed-value). `--json` is unchanged. An identifier that WRAPS into a row-shaped line (#3328's class) is bounded by the cap, not closed; a property value, uncapped, is not bounded either.
