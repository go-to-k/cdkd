- **`cdkd drift`'s human report no longer prints a state- or readback-derived value raw (issue [#3232](https://github.com/go-to-k/cdkd/issues/3232))** -- `src/cli/commands/drift.ts` (`writeHumanReport` and three row helpers), new `tests/unit/cli/drift-report-sanitize.test.ts`. The stack name and region of every heading, each `~` / `!` / `?` row's logical id and resource type, and each changed property's path and both of its values go through `safeMsg` at the row that prints them: a newline, a C0 control, LINE SEPARATOR or a bidi override in any of them is replaced by a space, as is the ESC of any sequence other than a CSI or a terminated OSC, and a CSI or terminated OSC is removed whole (the colour and styling codes cdkd's own output uses, which `safeMsg` allows everywhere, are kept; any other colour code becomes a reset), so a hand-edited record or a hostile value on the live resource can no longer invent a `✓ ... no drift detected` row or reorder what the reader sees. Identifiers are capped (255 code points; the stack name at the state-reference cap) with a `...` mark; property values are neither trimmed nor capped, so an ordinary value renders byte-for-byte as before and a drift that differs only by surrounding whitespace still shows two sides. A structured value is JSON-encoded first, so a control nested inside it arrives as JSON's escape text (inert) while a LINE SEPARATOR or bidi override, which JSON leaves literal, is replaced. `--json` is unchanged. An identifier that WRAPS into a row-shaped line (#3328's class) is bounded by the cap, not closed; a property value, uncapped, is not bounded either.
