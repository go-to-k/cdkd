- **`cdkd diff` now agrees with `cdkd deploy` on nested-stack and routing decisions (issues [#3450](https://github.com/go-to-k/cdkd/issues/3450), [#3453](https://github.com/go-to-k/cdkd/issues/3453))** -- `src/cli/commands/diff-recursive.ts`, `src/cli/commands/import.ts`, `docs/cli-diff.md`, `docs/cli-deploy-safety.md`, `docs/provisioning-layers.md`, and unit tests. `cdkd diff --recursive` now refuses a nested-template cycle spelled through a symbolically linked directory (`d -> .` with a row naming `d/child.json`) at its first repeat. It keys the ancestor chain on the same template identity the deploy-side guard uses. Before, it walked on until the path or S3 key limit stopped it with an error that did not name the cause. In asset-redirect mode it indexes a child's nested rows before the asset-reference rewrite, so it follows the file the deploy follows, and `cdkd import --migrate-from-cloudformation` now finds a grandchild's template the same way. A row the deploy replaces (a `[requires replacement]` property change or a `Type` change) no longer carries `[via CC API: sticky]` or `[returning to SDK provider]` from the old record, because the replacement is routed as a fresh create. A `Type` change into or out of `AWS::CloudFormation::Stack` is now listed under `Blocking (cdkd deploy will refuse):` and exits `3`, where it used to preview as an ordinary update that the deploy then refused.
