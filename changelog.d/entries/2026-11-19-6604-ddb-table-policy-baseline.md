- **Removing or adding a DynamoDB table's `ResourcePolicy` no longer leaves a drift baseline that `cdkd drift --revert` would undo (issue [#6604](https://github.com/go-to-k/cdkd/issues/6604))** -- `src/provisioning/providers/dynamodb-table/read-current-state.ts`, `src/cli/commands/drift/baseline-keys.ts`, unit tests, integ `dynamodb-table-policy-baseline`. `GetResourcePolicy` lags each write by seconds (measured: a deleted policy is still served for about 2 seconds), and the deploy recorded its first answer as the `observedProperties` baseline right after `PutResourcePolicy` / `DeleteResourcePolicy`. After a removal the baseline kept the deleted policy, so `cdkd drift` reported it on an untouched stack and `drift --revert` re-granted it; after an add the baseline could lack the policy, so `--revert` would delete it. The table-level read now re-asks an answer that differs from the template on the same schedule as the stream-level policy (#4112), and the capture after cdkd's own write keeps a declared policy that is still not visible. A baseline written by an earlier cdkd is not compared on `ResourcePolicy` while the live table matches the template (no policy where none is declared, or exactly the declared one); the next update of the table rewrites it.
