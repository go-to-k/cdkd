- **`cdkd rollback`'s `Re-run with:` line and `cdkd events`' `Read one run's events with:` line name a stack only when it is a plain identifier (issue [#3773](https://github.com/go-to-k/cdkd/issues/3773))** -- `src/cli/commands/rollback.ts` (a shared `rerunRollback` for its three refusals), `src/cli/commands/events.ts`, and unit tests in `tests/unit/cli/commands/rollback.test.ts` and `tests/unit/cli/events-display-safe.test.ts`. Both commands can take the stack name from an S3 key (a rollback journal, or the event history), and they printed it on a labelled pasteable line through the command gate alone, which names any exactly-rendering value. So a name padded to wrap on screen could print a counterfeit labelled row such as `Re-run with: cdkd destroy --all --force #`. Each line now requires a plain identifier (a letter or digit, then letters, digits, `~`, `_`, `.` or `-`, the rule `cdkd drift`, `cdkd state` and `cdkd destroy` already apply). Any other name prints a quoted `'<stack>'` hole, with a sentence before the line saying why. A real stack name is always a plain identifier.
