- **`cdkd rollback`'s `Re-run with:` line and `cdkd events`' `Read one run's events with:` line name a stack only when it is a plain identifier, and a newline in a stack name, logical id or resource type no longer starts a line in the per-resource status line, the skipped-delete message, or `cdkd destroy`'s progress lines (issue [#3773](https://github.com/go-to-k/cdkd/issues/3773))** -- `src/cli/commands/rollback.ts` (a shared `rerunRollback` for a warning and two refusals), `src/cli/commands/events.ts`, `src/utils/resource-line.ts`, `src/deployment/delete-outcome.ts`, `src/cli/commands/destroy.ts`, and unit tests. `cdkd rollback` can take the stack name from a journal S3 key, and printed it on a labelled pasteable line through the command gate alone, which names any exactly-rendering value, so a name padded to wrap on screen could print a counterfeit row such as `Re-run with: cdkd destroy --all --force #`. `cdkd events` names the stack the operator typed, so its footer gets the same rule as defence for a typed or pasted name. Each line now requires a plain identifier (a letter or digit, then letters, digits, `~`, `_`, `.` or `-`, the rule `cdkd drift`, `cdkd state` and `cdkd destroy` already apply); any other name prints a quoted `'<stack>'` hole, with a sentence before the line saying why. A real stack name is always a plain identifier. Separately, the per-resource `✓ <id> (<type>) deleted` line and the `could not address <id> (<physical id>)` skipped-delete message now fold control characters in their identifiers and skip reason onto one line, and so do `cdkd destroy`'s progress, skip, `--remove-protection` bypass and `--purge-events` lines for the stack name, region and AWS error text.
