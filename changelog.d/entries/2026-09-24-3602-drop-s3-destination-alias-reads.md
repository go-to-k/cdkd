- **`AWS::S3::Bucket` no longer reads the SDK spellings of the inventory / analytics `Destination` block (issue [#3602](https://github.com/go-to-k/cdkd/issues/3602))** -- `src/provisioning/providers/s3-bucket-provider.ts`, five `tests/unit/provisioning/s3-bucket-provider-*.test.ts` files, and the `tests/integration/s3-analytics-inventory/` comments. A `Destination` written as the nested SDK `{ S3BucketDestination: { ... } }` shape, or with a `Bucket` alias for `BucketArn`, deployed before and is now refused before any AWS call by the nested required-member check ([#3567](https://github.com/go-to-k/cdkd/issues/3567)), because `BucketArn` and `Format` are schema-required. CloudFormation rejects these spellings too: the L1 `CfnBucket.DestinationProperty` declares only `bucketArn` / `bucketAccountId` / `format` / `prefix`. `resolveS3BucketDestination` now reads only that CFn block. If a replayed pre-#1707 state record still carries one of these spellings, the block has no destination bucket: it is refused, or on the update path warned about and skipped, and no Put is sent. The #1707 record fold stays for the CFn block, since the warn-and-substitute `Format` still reaches it. Same decision as [#3585](https://github.com/go-to-k/cdkd/issues/3585).
