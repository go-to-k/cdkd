- **A Cloud Control `AWS::EFS::MountTarget` or `AWS::Route53::HostedZone` returns to its SDK provider (go-to-k/cdkd#5641)** -- `src/provisioning/provider-registry.ts`. Both types' SDK providers cover every property, yet a record created through Cloud Control stayed there and kept paying its polling. Both are now `'sdk-coverage'` members of `STICKY_CC_MIGRATION_EXEMPT`, so the next deploy that changes such a resource moves it to the SDK provider; `--pin-cc-api` declines that. Both layers address the resource by the same id, measured on live resources: the bare `fsmt-...` id and the bare `Z...` zone id, without Route 53's `/hostedzone/` prefix. Observed by the new `cc-to-sdk-reroute-mount-target` and `cc-to-sdk-reroute-hosted-zone` integ fixtures.
