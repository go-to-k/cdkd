- **A state-bucket read, write, listing or delete that S3 refuses no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/state/s3-state-backend.ts` unit cases. A denied `ListObjectsV2` during an `Fn::ImportValue` lookup, or a denied state save, ended the deploy with S3's own sentence in the recorded failure. The state errors (`Failed to list stacks: ...`, `Failed to save state for stack ...`, `Failed to get state ...`, the create-token ledger and write-ahead id refusals, and `Failed to verify state bucket ...`) now name the error class instead (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), with S3's text in the debug log. The S3 error is still the error's cause, so retries decide as before. A `cdkd events prune` that S3 refuses for some keys names each key's error code, with S3's per-key message in the debug log. cdkd's own rewrites, such as `Access denied to bucket '<name>'. Verify credentials and bucket policy.`, are unchanged.
