- **The four remaining HAND-QUOTED pasteable `aws ...` commands in provider messages now sanitize, shell-quote and suppress their id -- and a secret-bearing id is suppressed too (issue [#3136](https://github.com/go-to-k/cdkd/issues/3136), the hand-quoted half)** -- `src/provisioning/providers/ssm-parameter-provider.ts`, `src/provisioning/providers/s3-bucket-provider.ts`, `src/provisioning/replacement-protection-advice.ts`, new `tests/unit/provisioning/pasteable-command-hand-quoted-ids.test.ts`. Four sites wrapped a TEMPLATE- or state-borne value in `'...'` by hand inside a command the user is told to paste: the SSM partial-create cleanup warning, `refuseUnwritableParameterId`'s thrown remedy, and BOTH S3 partial-create cleanup arms. A `'` in the value broke out of the quoting, and a control byte forged lines on the operator's terminal. All four now render through the exported `renderDisableCommand` -- `displaySafe(asciiOnly)`, then `shellQuote`, then SUPPRESS the whole command when sanitizing CHANGED the value, since a command naming the sanitized id would act on a DIFFERENT resource. The S3 pair shares one `manualBucketDeletionClause`, and both S3 arms now route their whole warning through the caller's masker, which they previously never reached at all. `renderDisableCommand` gained an optional `maskSecrets`: `shellQuote` rewrites an inner `'` to `'\''` and a message-level masker matches by LITERAL occurrence, so without it a secret-bearing id carrying a quote would have come through in PLAINTEXT -- a regression the hand-quoted form did not have. Such an id is now suppressed too. **A clean value renders BARE**, which is what `shellQuote` emits and what issue [#2669](https://github.com/go-to-k/cdkd/issues/2669) established; three existing assertions moved with it. Residuals: the PROSE half is [#3269](https://github.com/go-to-k/cdkd/issues/3269), the unquoted S3 directory-bucket command [#3270](https://github.com/go-to-k/cdkd/issues/3270).
