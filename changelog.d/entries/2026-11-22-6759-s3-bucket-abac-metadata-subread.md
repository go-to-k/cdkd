- **`cdkd drift` reports `readFailed` when an S3 bucket's `AbacStatus` or `MetadataConfiguration` cannot be read, instead of the declared value standing in for it (issue [#6759](https://github.com/go-to-k/cdkd/issues/6759), part of [#6696](https://github.com/go-to-k/cdkd/issues/6696))** -- `src/provisioning/providers/s3-bucket/{read-state,read-state-lists,apply-core}.ts`, `src/provisioning/providers/s3-bucket-provider.ts`. When `GetBucketAbac` or `GetBucketMetadataConfiguration` failed (an `AccessDenied` from a narrow drift role, a throttle), the drift read used the template's declared value as the live one, so the run reported the bucket clean over two properties it never compared. That failure now fails the bucket's read: `cdkd drift` reports it `readFailed` (exit 2), naming the denied call, so the user knows which permission to grant. The other properties of that bucket are not compared in that run. A bucket gone under either read (`NoSuchBucket`) keeps the old answer. The deploy path that adopts an existing bucket still reads both calls tolerantly, as before.
