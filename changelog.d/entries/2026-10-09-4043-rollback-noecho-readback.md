- **A rollback reverts a resource whose recorded properties hold a NoEcho parameter's value only as `***` (issue [#4043](https://github.com/go-to-k/cdkd/issues/4043), Phase C)** -- `src/deployment/rollback-executor.ts`, `src/deployment/rollback-executor/{replay-noecho,replay-revert,replay-reverse-replacement,replay-props}.ts`, `src/deployment/nested-child-journal.ts`, `src/deployment/deploy-engine/{rollback,outputs}.ts`, `docs/_contents/cli-rollback.md`. Since state schema v11 a property fed by a `NoEcho` template parameter (or a `NoEcho` attribute read through `Fn::GetAtt`) is recorded as `***` at the coordinates `noEchoLeaves` names, and every rollback revert of such a resource, automatic or `cdkd rollback` (with or without `--revert-failed`), failed with `ROLLBACK_REDACTED_BASELINE`. The revert now reads the resource back from AWS, handing the provider the record masked at those coordinates, and sends the value AWS holds there, so a `NoEcho` value the failed deploy changed is not reverted (the next deploy restores it). The value becomes a mask-only and a log-only needle of the operation, and the restored record keeps `***` by position and its `noEchoLeaves`, so it never reaches state, the events or the log in the clear (inside longer text, from 4 characters). A value that cannot be read back (write-only, absent, itself `***`, no readback, a failed read) and the re-create of a reversed replacement refuse with a `NoEcho`-specific remedy. A nested stack row's masked `Parameters` entry no longer refuses its revert. A nested child's journal no longer snapshots a previous export alias that today's export-name verdict refuses, so a revert of the child cannot republish an alias an older cdkd wrote. Tests: `tests/unit/deployment/rollback-executor-noecho-readback.test.ts`, `deploy-engine-noecho-v11.test.ts`, `nested-child-journal.test.ts`; integ arm in `tests/integration/noecho-parameter-masking/`.
