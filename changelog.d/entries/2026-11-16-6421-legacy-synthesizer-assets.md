- **A stack synthesized with `LegacyStackSynthesizer` that carries assets now deploys (issue [#6421](https://github.com/go-to-k/cdkd/issues/6421))** -- `src/assets/legacy-synthesizer-assets.ts`, `src/assets/cdk-toolkit-bucket.ts`, `src/assets/asset-publisher.ts`, `src/assets/docker-asset-publisher.ts`, `src/synthesis/assembly-reader.ts`, `src/cli/commands/deploy/work-graph.ts`, `src/cli/commands/{publish-assets,diff}.ts`, `src/cli/commands/{import,refactor,export}/command.ts`, `docs/cli-bootstrap.md`. Such a stack has no asset manifest: its assets are `aws:cdk:asset` metadata entries and its template declares `AssetParameters...` parameters with no default, so `cdkd deploy` stopped with "Parameter AssetParameters...S3Bucket... is required but no value was provided". cdkd now builds an in-memory asset manifest from those entries and binds the parameter values the AWS CDK CLI supplies: a file or directory asset goes to `assets/<hash><ext>` in the cdkd-owned asset bucket (cdkd-assets mode) or the `CDKToolkit` stack's `BucketName` output (legacy mode), and an image asset to the repository the synthesizer names, created when missing. `deploy` (also under `--skip-assets`), `publish-assets`, `diff`, `import`, `export` and `refactor` bind the same values; `import` records the CDK toolkit bucket in state in cdkd-assets mode so the next deploy repoints the resource. Integ: `tests/integration/legacy-synthesizer-assets/`. Tests: `tests/unit/assets/legacy-synthesizer-assets.test.ts`, `tests/unit/cli/{deploy-work-graph-legacy-assets,publish-assets-legacy-synthesizer,diff-legacy-synthesizer-assets}.test.ts`.
