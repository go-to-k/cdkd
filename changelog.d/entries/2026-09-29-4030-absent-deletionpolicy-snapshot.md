- **Behavior change: an `AWS::RDS::DBCluster`, or an `AWS::RDS::DBInstance` without `DBClusterIdentifier`, that declares no `DeletionPolicy` now gets a final snapshot when deleted, as CloudFormation does (issue [#4030](https://github.com/go-to-k/cdkd/issues/4030))** -- `src/provisioning/final-snapshot.ts`, `src/cli/commands/destroy-runner.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/rollback-executor.ts`, `src/provisioning/cloud-control-provider.ts`, `src/provisioning/region-check.ts`, `src/cli/options.ts`. CloudFormation's default `DeletionPolicy` is `Snapshot` for these two shapes and `Delete` for everything else. cdkd used to treat a missing policy as `Delete` everywhere, so destroying an L1 `CfnDBCluster` or standalone `CfnDBInstance` without the attribute deleted its data with no snapshot. `cdkd destroy`, `cdkd state destroy`, a deploy that removes the resource from the template, and a rollback of its creation now take the final snapshot (`<physical id>-final-<UTC timestamp>`) on the SDK route. On the Cloud Control route they refuse, as for an explicit `Snapshot`. Pass `--skip-final-snapshot` to delete without it; on the Cloud Control route that delete now also goes through RDS directly, since the Cloud Control handler would take an untracked snapshot of its own (issue [#4029](https://github.com/go-to-k/cdkd/issues/4029)). CDK's L2 `DatabaseCluster` / `DatabaseInstance` always write a `DeletionPolicy`, and a cluster-member instance keeps the plain delete, so neither changes. `UpdateReplacePolicy` defaults to `Delete` for every type, so replacement deletes are unchanged. The recorded policy is not rewritten, so `cdkd diff` shows no change. The `rds-dbinstance-backfill` and `rds-aurora` integration fixtures now assert the snapshot of their policy-less L1 instance and cluster, then delete it.
