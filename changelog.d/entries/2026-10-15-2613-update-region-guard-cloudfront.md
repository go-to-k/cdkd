- **An update of a CloudFront distribution, origin access control or origin access identity is refused when the AWS client's region differs from the region recorded in cdkd state (issue [#2613](https://github.com/go-to-k/cdkd/issues/2613))** -- `src/provisioning/providers/cloudfront-{distribution,oac,oai}-provider.ts` (`assertRegionMatch` now runs before any AWS call in these `update()`s; their `delete()`s compare the regions only on a NotFound), `scripts/check-provider-update-context.ts` (`OMITS_UPDATE_CONTEXT` is now empty, so every SDK provider's update takes the region the deploy engine passes), and unit cases. CloudFront's client is built in the stack's region rather than pinned to us-east-1, so a stack in any region updates as before; only a client whose region disagrees with the record now stops before the first call, names both regions, and says that the global endpoint would have reached the same resource through a client not built for that stack. A state record with no region is unchanged.
