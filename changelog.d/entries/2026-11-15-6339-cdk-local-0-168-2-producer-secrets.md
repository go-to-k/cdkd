- **`cdkd local` keeps a producer stack's exported secret off the `docker run` command line under `--from-cfn-stack` and in `start-service` / `start-alb` too (issue [#6339](https://github.com/go-to-k/cdkd/issues/6339))** -- `cdk-local` `^0.168.1` -> `^0.168.2` (go-to-k/cdk-local#982). Under `--from-cfn-stack`, a value read through `Fn::ImportValue` that holds a secret of the exporting stack (an `AWS::AppSync::ApiKey`'s key, an output traced to a `NoEcho` parameter or a secret attribute) is refused in an ECS `Command` / `EntryPoint` / health-check command, passed value-less in `Environment` and Lambda / AgentCore env vars, and dropped as a `Secrets` `ValueFrom` (one that cannot be checked but is a well-formed Secrets Manager / SSM ARN is kept, under `--from-state` too); judging it reads `cloudformation:ListStackResources`, `DescribeStacks` and `GetTemplate` on the exporting stack, and a value that cannot be checked (a missing permission, a YAML template) fails closed with a refusal naming the failed call. `local start-service` / `start-alb` apply the same check under either state flag, and their refusal names the upstream stack when a re-export blocked the `--from-state` check. A `local invoke-agentcore` fromS3 bucket read from such an export is now withheld from the download line and its errors as well.
