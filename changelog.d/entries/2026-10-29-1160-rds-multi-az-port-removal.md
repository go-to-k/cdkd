- **Removing `Port` from a Multi-AZ `AWS::RDS::DBCluster` (`mysql` / `postgres`) now fails the deploy as CloudFormation does (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160), rds-provider.ts row)** -- `src/provisioning/providers/rds-provider.ts` (`CLUSTER_REMOVED_PORT`, `clusterPortToSend`); unit tests in `tests/unit/provisioning/rds-provider-update-removal.test.ts`. A redeploy that dropped the cluster's `Port` used to send nothing, so the deploy reported success while the old port stayed live. Measured against CloudFormation, the removal sends port 3306, which RDS refuses ("You can't modify the port for a Multi-AZ DB cluster"), and the stack update fails. cdkd now sends the same port, so the deploy fails with that error. The same A/B confirmed two removals already at parity, with only the source comments corrected: a removed `MasterUserSecret` while `ManageMasterUserPassword` stays `true` keeps the secret on its customer key, and a removed `DBInstanceClass` keeps the live class.
