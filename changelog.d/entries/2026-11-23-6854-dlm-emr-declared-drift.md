- **`cdkd drift` now compares a DLM lifecycle policy's `PolicyDetails` and an EMR cluster's `AutoTerminationPolicy` / `ManagedScalingPolicy` (issue [#6854](https://github.com/go-to-k/cdkd/issues/6854))** -- `src/provisioning/drift-declared-projection.ts`, `src/provisioning/providers/dlm-lifecycle-policy-provider.ts`, `src/provisioning/providers/emr-cluster-provider.ts`, `src/provisioning/providers/emr-cluster/read-state.ts`, `docs/design/6854-e-unowned-normalization-rules.md`, `tests/unit/provisioning/unowned-skip-drift-6854.test.ts`, `tests/unit/provisioning/iam-name-fold-boundaries-6854.test.ts`, `tests/integration/dlm-lifecycle-policy/verify.sh`. These properties were never compared, so an out-of-band change (a policy's `RetainRule.Count` edited from 7 to 30, a cluster's idle timeout changed or removed) reported no drift. Each is now read (EMR's only when the template declares it) and compared on the members the template declares; members AWS fills with defaults are not compared while they hold the filled value (a member added out of band, such as a schedule's `FastRestoreRule`, is), a policy whose read is denied or throttled is left uncompared with a warning instead of failing the whole read, and a default policy's shorthand fields (`CreateInterval`, `RetainInterval`, ...) are compared the same way. A record captured before this change is compared against the template's value until the next deploy recaptures it.
