- **An "already exists" from a DynamoDB global table's replica add or TTL call during create no longer reads as the table's own name collision (issue [#3877](https://github.com/go-to-k/cdkd/issues/3877), the residual of [#3826](https://github.com/go-to-k/cdkd/issues/3826))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`, with a row in `tests/unit/provisioning/auxiliary-failure-3826.test.ts`. A failure after `CreateTable` returns (the replica add's `UpdateTable`, `UpdateTimeToLive`) now passes through `markAuxiliaryFailure` in the catch that already retires the partial table. Before this change, such a failure relaying AWS's "already exists" was treated as a collision on the table's own name, so `--replace` deleted the live old table and a replacement rollback deleted the live new one. The error text is unchanged, and a collision on `CreateTable` itself still classifies.
