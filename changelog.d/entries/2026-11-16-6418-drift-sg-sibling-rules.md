- **`cdkd drift` no longer reports a security-group rule that a separate `AWS::EC2::SecurityGroupIngress` / `SecurityGroupEgress` of the same stack adds, and `cdkd drift --revert` no longer revokes it (issue [#6418](https://github.com/go-to-k/cdkd/issues/6418))** -- `src/provisioning/sg-sibling-rules.ts`, `src/deployment/deploy-engine/observed-capture-sg-siblings.ts`. CDK writes every group-to-group rule (`connections.allowFrom(otherGroup, ...)`, `db.connections.allowDefaultPortFrom(fn)`) as its own resource, and keeps CIDR rules inside the group. On a group with both, `cdkd drift` read the separate rule as the group's drift on a freshly deployed stack, and `--revert` removed it from AWS while printing `reverted`, cutting the access it granted. Drift now skips such a rule on the group, as CloudFormation's drift detection does; a rule nothing in the stack declares is still reported. The snapshot a deploy records for the group leaves such a rule out too, and an existing stack is fixed without a redeploy.
