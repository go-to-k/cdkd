The `indexScopeAt` guard the review of issue [#3255](https://github.com/go-to-k/cdkd/issues/3255) added for exactly this covered the create-path and capacity sites and missed this one. The CLASS is now swept rather than the reported site: this method's four interpolations plus three more that survived elsewhere in the file (both adopted-index warns and `skipZeroCapacityIndexUpdate`'s zero-capacity refusal, the one of the three a numeric name can actually reach) all read through it, and `indexName` is typed `unknown` at both methods so a future direct interpolation does not compile. The population is derivable: `grep -nE 'maskSecrets\((name|indexName)\)'` over the file returns only the two lines inside the scope builders themselves. A string name renders byte-identically; a non-string renders `<unnamed>` instead of throwing.
