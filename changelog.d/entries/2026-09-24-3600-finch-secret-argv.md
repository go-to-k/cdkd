- **`cdkd local run-task` / `invoke-agentcore` now refuse to forward secrets under `CDK_DOCKER=finch` on macOS / Windows unless `CDKD_ALLOW_SECRETS_ON_ARGV=1` is set, and warn that finch puts forwarded AWS credentials on a process command line (issue [#3600](https://github.com/go-to-k/cdkd/issues/3600))** -- `src/utils/docker-cmd.ts`, `src/local/docker-runner.ts`, `src/local/ecs-task-runner.ts`, `src/local/ecs-network.ts`, `docs/local-run-task.md`, plus tests. cdkd passes a secret as a value-less `-e KEY` so its value stays off the `docker run` command line. finch on macOS / Windows resolves each such flag itself and rewrites it as `-e KEY=<value>` on the command line of the `limactl` process it starts, where other local processes can read it, so the documented guarantee did not hold there. A task with an ECS `Secrets` entry now fails before any image, secret or container work, and an AgentCore runtime with a decrypted SecureString fails before its container starts; both name the secrets and the opt-in. `cdkd local start-service` runs through the cdk-local engine and does not apply the refusal or the warning yet. The AWS credential set cdkd hands the container is still forwarded, with a warning naming the keys, never the values: finch already puts the operator's own credentials on that command line for every command. Detection matches the binary's basename (`finch` / `finch.exe`), so a wrapper or symlink under another name is not recognised; finch on Linux is unaffected.
