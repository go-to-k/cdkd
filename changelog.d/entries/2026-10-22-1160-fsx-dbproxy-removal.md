- **`AWS::RDS::DBProxy`: removing `Auth` from the template is now refused before any AWS call, as CloudFormation's update fails on it; the FSx and DBProxy removal warnings now say when CloudFormation keeps the value too (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/rds-dbproxy-provider.ts`, `src/provisioning/providers/fsx-filesystem-provider.ts`. A CloudFormation A/B on the issue (us-east-1) measured each removal. CloudFormation sends an `Auth` removal, and AWS refuses it while `DefaultAuthScheme` is `NONE` or unset. cdkd used to keep `Auth` and warn; it now stops the deploy with an error that says to declare `Auth` again. A rollback replay still keeps it and warns; `drift --revert` keeps it without a warning, as before. CloudFormation keeps a removed DBProxy `RequireTLS` / `IdleClientTimeout` / `DebugLogging` / `VpcSecurityGroupIds`, an FSx `FileSystemTypeVersion`, a Lustre `DataCompressionType` / `AutoImportPolicy` / `WeeklyMaintenanceStartTime`, and an OpenZFS `AutomaticBackupRetentionDays` / `CopyTagsToBackups` / `CopyTagsToVolumes` / `DailyAutomaticBackupStartTime` / `WeeklyMaintenanceStartTime` / `DiskIopsConfiguration`. cdkd already kept them, so only the warning changes: it now reads `... and keeps its current AWS value, as CloudFormation leaves it; ...`. A warning that names an unmeasured property (FSx `StorageType`, `NetworkType`, a Windows or ONTAP sub-property) keeps its old wording. Tests: `tests/unit/provisioning/rds-dbproxy-provider.test.ts`, `tests/unit/provisioning/providers/fsx-filesystem-provider.test.ts`; the `fsx-lustre` and `rds-aurora` integ needles now require the new wording.
