- **A Cloud Control update no longer re-sends an unchanged password passed as a `{{resolve:...}}` secret reference, CDK's default for generated secrets (issue [#6824](https://github.com/go-to-k/cdkd/issues/6824))** -- `src/deployment/deploy-engine/update-in-place/write-only-secret-skip.ts`, `src/provisioning/cloud-control/update.ts`, `src/deployment/reference-provenance-record.ts`. The #6788 skip compared values, and a reference never equals its resolved value, so a tag change still re-set a Redshift / ElastiCache / Amazon MQ / DMS (and other measured) password on every update. The key is now left out when the secret version this deploy resolved is the one the state record says was last sent; a rotation, `PutSecretValue`, `PutParameter` or a stage move changes the version and sends it. Before an update sends another version, cdkd saves the record without it, so an update that fails or is interrupted after applying the new password, a deploy after any failed or interrupted one, a record an older cdkd wrote, `cdkd drift --revert` and a rollback all send it again on the next deploy. A state that records such a sent version is written as schema version 18 (only then), which an older cdkd refuses with "Upgrade cdkd": it would send a rotated password without saving ahead. A password changed outside cdkd with the secret untouched is not detected, as in CloudFormation.
