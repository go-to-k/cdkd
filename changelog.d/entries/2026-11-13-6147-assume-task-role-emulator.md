- **`local run-task --assume-task-role --aws-emulator` runs the containers as the task role in AWS Emulator (issue [#6147](https://github.com/go-to-k/cdkd/issues/6147))** -- `src/cli/commands/local-run-task/{command,credentials,stack-account}.ts`, `src/local/ecs-task-runner/{docker-run-args,types}.ts`, `src/local/ecs-task-runner.ts`, `src/local/local-aws-wiring.ts`, unit tests and docs. Before, the role's credentials were dropped: the containers held the emulator's keys, and the metadata sidecar's `/creds` answered 500, because the sidecar exchanges long-lived keys for a session on real STS, which refuses the emulator's keys. Now cdkd assumes the role in the emulator, and every container and the sidecar get the role's session credentials, which the sidecar serves as they are; real STS is never called under `--aws-emulator`. In mixed mode the role is assumed in real AWS only for a container that marks STS as a `"real-aws"` exception, and a container that marks only other services gets your own identity: the re-signing sidecar signs every call to the emulator with the emulator's keys, whatever the container holds. When no container marks STS, cdkd warns that the flag has no effect.
