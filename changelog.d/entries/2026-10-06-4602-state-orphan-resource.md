- **`cdkd state orphan <stack> --resource <logicalId>` drops one resource's record without a CDK app, and provider skip warnings name it instead of the whole-stack form outside a destroy (issue [#4602](https://github.com/go-to-k/cdkd/issues/4602))** -- `src/cli/commands/{state,orphan}.ts`, `src/analyzer/orphan-rewriter.ts`, `src/provisioning/{state-orphan-remedy,redacted-delete-address,composite-id}.ts`, `src/provisioning/providers/{custom-resource,cloudwatch-anomaly-detector,lambda-permission,iam-policy,iam-user-group,s3-bucket,ec2}-provider.ts`, docs. No command removed one record of a deployed stack whose construct had left the template, so a skipped delete during `cdkd deploy` printed `cdkd state orphan <stack>`, which drops the record of every resource in the stack. The new repeatable `--resource` removes only the named entries, rewrites the `Ref` / `Fn::GetAtt` / `Fn::Sub` / `dependencies` / outputs that other records hold to them as `cdkd orphan` does (an unresolvable one refuses unless `--force`), takes the stack's lock (a held lock refuses, `--force` included) and saves conditionally; it needs one stack and refuses an ambiguous region, an unknown id, and a row whose nested-stack child still has a record. The provider delete-skip warnings and refusals now name `--stack-region <region> --resource <logicalId>` outside a stack destroy, and the whole-stack form (with the `--resource` alternative) only on `cdkd destroy` / `cdkd state destroy`; the SecurityGroupIngress update refusal always names `--resource`. `cdkd orphan --force` and `state orphan --resource --force` no longer copy a cached value cdkd recognises as a credential (by name, a custom resource's attribute, a known secret-valued attribute), the redaction mask or an unresolved `{{resolve:}}` into another record or print it. Tests: `tests/unit/cli/state-orphan-resource.test.ts`, `tests/unit/provisioning/state-orphan-remedy-4602.test.ts`; integ arm in `tests/integration/retain-orphan-redeploy/`.
