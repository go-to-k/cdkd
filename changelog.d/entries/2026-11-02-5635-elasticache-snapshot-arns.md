- **`AWS::ElastiCache::CacheCluster` sends `SnapshotArns` on the SDK route (go-to-k/cdkd#5635)** -- `src/provisioning/providers/elasticache-provider.ts`. A cluster seeded from an RDB file in S3 is now created by CreateCacheCluster with its `SnapshotArns`, instead of routing the whole cluster through Cloud Control and recording it there. The property is create-only, so a change replaces the cluster, as CloudFormation does. A cluster already recorded as `provisionedBy: cc-api` stays on Cloud Control. A cluster that reads `restore-failed` (a seed ElastiCache could not load) or `incompatible-network` now fails the deploy at once, naming the status, instead of waiting ten minutes for a generic timeout. `cdkd drift` no longer reports `SnapshotArns` or `SnapshotName` as removed from AWS on a record with no observed baseline: AWS never returns either.
