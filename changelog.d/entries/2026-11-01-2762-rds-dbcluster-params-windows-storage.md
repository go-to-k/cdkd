- **The SDK provider sends the parameter group, backup and maintenance windows, snapshot tag copying and storage type of `AWS::RDS::DBCluster` (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and new arms in the `rds-aurora` integ. Before, a DB cluster declaring any of `DBClusterParameterGroupName`, `PreferredBackupWindow`, `PreferredMaintenanceWindow`, `CopyTagsToSnapshot` or `StorageType` routed through Cloud Control. They now ride `CreateDBCluster`, and `ModifyDBCluster` when the template changes them; a removed one keeps its live value, as CloudFormation keeps it. A changed `EngineVersion` now goes out with `AllowMajorVersionUpgrade`, as CloudFormation sends it, so a major upgrade (CDK's L2 cluster changes its default parameter group's family with it) applies in place instead of being refused. A rollback that reverts the cluster no longer sends the old `EngineVersion`, which RDS refuses as a downgrade and which failed the whole revert; CloudFormation's rollback does not send it either. `cdkd drift` reads all five back, an Aurora cluster that reports no storage type as `aurora`, as CloudFormation reads it.
