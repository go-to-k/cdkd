- **A DynamoDB table replaced under the same name is no longer left deleted with nothing in its place when its re-create comes too soon (issue [#5131](https://github.com/go-to-k/cdkd/issues/5131))** -- `src/provisioning/providers/dynamodb-table-provider.ts`, `src/types/resource.ts`, `src/deployment/deploy-engine/{replacement,update-replace,update-in-place}.ts`, `src/deployment/rollback-executor/replay-reverse-replacement.ts`. A replacement that deletes the old table first and re-creates it under the same name (`--replace`'s delete-first fallback, `--recreate-via-*`, an update the provisioning layer rejects, and a rollback reversing one) could fail the re-create with `ResourceInUseException`: `DeleteTable` returns while the table is still `DELETING`, and DynamoDB keeps the name until it is gone, so the deploy ended with the old table deleted and no new one. These re-creates now wait (bounded, and Ctrl+C stops it) until `DescribeTable` reports the table gone. `cdkd destroy` and every other deploy path make no extra call.
