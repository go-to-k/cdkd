- **A CloudFront distribution whose origin sets `OriginHttpVersion` now stays on the SDK provider instead of routing through Cloud Control (issue [#6932](https://github.com/go-to-k/cdkd/issues/6932))** -- `src/provisioning/sdk-unmodelled-nested-paths.ts`, `tests/unit/provisioning/sdk-unmodelled-nested-paths-6690.test.ts`, `tests/unit/provisioning/sdk-wire-cases-8-cloudfront.ts`, `tests/integration/sdk-unmodelled-nested-route/`. `@aws-sdk/client-cloudfront` 3.1175.0 models `CustomOriginConfig.OriginHttpVersion` and `VpcOriginConfig.OriginHttpVersion`, and the SDK provider sends and reads back both, so the two paths leave the Cloud Control route PR [#6690](https://github.com/go-to-k/cdkd/pull/6690) added. A distribution an earlier version recorded on Cloud Control for the member returns to the SDK provider on its next change, keeping its id. The Route 53 hosted zone members stay routed: the provider does not send them. The deploy's reason for such a route now reads `<path> is not sent by cdkd's SDK provider` rather than claiming the SDK client does not model it.
