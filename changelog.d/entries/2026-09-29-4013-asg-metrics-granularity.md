- **An Auto Scaling group with several `GroupMetrics` now updates and drift-checks all of them (issue [#4013](https://github.com/go-to-k/cdkd/issues/4013))** -- `src/provisioning/providers/asg-provider.ts` (`foldMetricsCollection`, the `MetricsCollection` update diff, `canonicalizeDriftProperties`), with unit tests in `tests/unit/provisioning/asg-provider-metrics-granularity-4013.test.ts` and an update + drift arm in the `launchtemplate-asg-inplace` integration fixture. CDK renders one `MetricsCollection` entry per `GroupMetrics`, all at `1Minute`, and the update diff keyed the entries by granularity, so only the last entry counted on each side: adding two groups enabled only the last one's metrics, and dropping a metric from an earlier group left it enabled. A template-shaped drift baseline (a resource deployed before observed-capture) also never matched the readback's single entry. Both sides are now folded the way AWS holds the setting — one set of metrics per granularity, the union of every entry, with an entry that lists no metrics meaning all of them — so an update enables and disables exactly the difference between the two sets, and the same explicit set of metrics compares clean in `cdkd drift` however the template splits it (an entry that enables all metrics still differs from a readback listing them one by one when the baseline is template-shaped).
