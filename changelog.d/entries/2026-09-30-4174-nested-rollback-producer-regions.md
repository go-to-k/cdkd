- **A nested stack's rollback no longer re-resolves a parent-supplied secret reference in the wrong region (issue [#4174](https://github.com/go-to-k/cdkd/issues/4174))** -- `src/deployment/producer-regions-scope.ts`, `src/deployment/nested-child-journal.ts`, `src/deployment/rollback-executor.ts`, `src/deployment/deploy-engine.ts`, `src/provisioning/providers/nested-stack-provider.ts`, `src/cli/commands/rollback.ts`. A nested child receives a parent's cross-region value only as a Parameter and records it as the parent's region-less `{{resolve:...}}` expression, but a rollback of the child classified that expression against the child's own cross-stack reads only. So a reference the parent would refuse as ambiguous (issue #2057) was resolved against a same-named secret in the stack's region and written to a live resource. The child's replay now unions its own producer regions with its parent's (and every ancestor's): in a parent rollback that reverts the nested row, and in the child's own automatic rollback during the parent's deploy. Where the parent's regions are unknown -- `cdkd rollback '<parent>~<child>'` run on its own -- every region-less secret reference is refused, and the operation fails with the journal kept. Tests: `tests/unit/deployment/rollback-nested-cross-region-secret.test.ts`, `tests/unit/deployment/producer-regions-scope.test.ts`, `tests/unit/cli/commands/rollback-nested-producer-regions-4174.test.ts`.
