- **A Cloud Control status poll that fails with `EADDRNOTAVAIL` is now re-polled instead of abandoning the wait (issue [#4331](https://github.com/go-to-k/cdkd/issues/4331))** -- `src/provisioning/cloud-control-provider.ts`, `src/deployment/retryable-errors.ts`. `EADDRNOTAVAIL` is a local-address socket failure, seen on a machine running several deploys at once (`read EADDRNOTAVAIL`). The poll's transport classifier did not list it, so one such failure ended the wait with "the failure is not retryable": a CREATE that Cloud Control had accepted kept running in AWS with no cdkd state record, untracked by rollback and `cdkd destroy` (observed with an EKS cluster). The code now joins the other socket codes, matched on the error's `code` or, when a wrapper dropped it, in its message, and the poll -- a read of the same request token -- is retried within the existing transient grace. It also joins the socket codes cdkd treats as an ambiguous outcome (the call may have reached the service), since its `read` form can follow a request that was already written. Tests: `tests/unit/provisioning/cloud-control-wait-abandoned.test.ts`, `tests/unit/deployment/retry-ambiguous-create-replay-3978.test.ts`.
