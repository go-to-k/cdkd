- **A `NoEcho` template parameter's value no longer prints in a provider's warn line, in the deploy's error text or in the `deployments/*.jsonl` event (issue [#1998](https://github.com/go-to-k/cdkd/issues/1998))** -- `src/deployment/secret-redaction.ts` (`recordLogOnlyValue`, `maskRecordedSecretsInText`, `hasMaskableValues`), `src/deployment/intrinsic-function-resolver.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/rollback-executor.ts`, `src/provisioning/providers/nested-stack-provider.ts`, `src/cli/commands/scrub.ts`, and unit cases. Before, only the resolver's own `--verbose` parameter lines honoured `NoEcho`. A `Ref` or `Fn::Sub` variable serving a `NoEcho: true` parameter now records the value as a LOG-ONLY needle of that resource's secret bag, and the masker every provider receives masks it, as do the engine's error and event masking and the resolver's debug lines. So does a nested child consuming the value through its own parameter, and the in-process rollback of the resource. The `Fn::Base64` encoding of such a value is masked in the log too. Nothing cdkd PERSISTS changes: the value is not a recorded secret, `state.json` and every redaction decision are byte-identical with or without `NoEcho`, and an `Export.Name` embedding it is still published. Bounds: an `Fn::Split` fragment of the value is not recorded. The persistence half (`cdkd rollback`, `cdkd drift`, export names) is [#4043](https://github.com/go-to-k/cdkd/issues/4043); `cdkd diff`, the `--verbose` replacement line and the Outputs summary are [#4049](https://github.com/go-to-k/cdkd/issues/4049).
