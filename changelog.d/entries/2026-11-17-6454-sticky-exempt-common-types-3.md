- **Six more resource types recorded `provisionedBy: 'cc-api'` return to their SDK provider (issue [#6454](https://github.com/go-to-k/cdkd/issues/6454), batch 3)** -- `src/provisioning/provider-registry/sticky-exempt.ts` and the new `cc-to-sdk-reroute-common-types-3` integ. `AWS::CloudFront::CloudFrontOriginAccessIdentity`, `AWS::ServiceDiscovery::HttpNamespace`, `AWS::Glue::Database`, `AWS::Glue::Job`, `AWS::Events::EventBus` and `AWS::ECR::Repository` are now `'sdk-coverage'` members of `STICKY_CC_MIGRATION_EXEMPT`. A resource of one of these types on Cloud Control moves to the SDK provider in place on the next deploy that changes it; `--pin-cc-api <LogicalId>` declines that. Both layers record the same id for each type, observed on live resources together with an identity witness (the AWS-minted id or the resource's creation time), so nothing is replaced. `cdkd diff` annotates the move `[returning to SDK provider]`.
