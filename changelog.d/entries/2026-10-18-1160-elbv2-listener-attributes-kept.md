- **Removing a key from an `AWS::ElasticLoadBalancingV2::Listener`'s `ListenerAttributes` now keeps its live value, matching CloudFormation (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- A real CloudFormation A/B showed CloudFormation KEEPS a removed listener attribute key, whether one key or the whole list is dropped. cdkd used to reset it (to the documented default for `routing.http.response.server.enabled`, to an empty value for other keys) and now sends nothing for it, as it already does for `LoadBalancerAttributes` and `TargetGroupAttributes`. A removed CORS key (`routing.http.response.access_control_*`, which CloudFormation also keeps) or request-header rename (`routing.http.request.<header>.header_name`) prints one warning naming the keys, since a kept one can keep a cross-origin grant live or leave the backend reading a header the ALB no longer writes. A listener recorded on Cloud Control still returns to the SDK provider on its next change, now for the SDK path's speed; both routes keep the key. Changed: `src/provisioning/providers/elbv2-provider.ts`, `src/provisioning/provider-registry.ts` (rationale only), the ELBv2 listener unit suites, `tests/integration/alb/`, `docs/cli-deploy-safety-routing.md`, `docs/provider-rules.md`, `docs/state-schema-internals.md`, `docs/troubleshooting-internals.md`.
