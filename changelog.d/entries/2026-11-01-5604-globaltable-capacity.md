- **A `AWS::DynamoDB::GlobalTable` capacity change now reaches AWS with no billing flip (issue [#5604](https://github.com/go-to-k/cdkd/issues/5604))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts` left a flat `ReadCapacityUnits` change on the deploy region's replica unsent, and a literal `WriteCapacityUnits` change too, so the deploy reported success and the old capacity stayed in AWS. Both now reach AWS: a side the update does not change goes as AWS holds it, so an auto-scaled side stays with its scaling policy. With a cross-region replica, a read change goes out as the local region's override, since `ProvisionedThroughput` would overwrite every other region. A change that leaves such a table with no write auto-scaling is now refused before any call, as CloudFormation refuses a literal write and DynamoDB refuses replica updates on it; on a rollback or `drift --revert` it warns and skips that capacity. A replica added on an update now holds the read capacity it declares: DynamoDB drops the override on the replica create, so it goes out again once the replica is active. A changed literal that does not resolve to a number is reported instead of passing in silence.
