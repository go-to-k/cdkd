- **`cdkd local *` with a cross-account `--role-arn` now resolves `${AWS::AccountId}` to the deploy account, where the stack lives, except under `--from-cfn-stack` (issue [#5001](https://github.com/go-to-k/cdkd/issues/5001))** -- `src/local/local-role-arn.ts`, `src/cli/commands/local-invoke.ts`, `local-start-api.ts`, `local-run-task.ts`, `local-invoke-agentcore.ts`, `cdk-local` bumped to 0.153.1. `--from-state` already resolved the role's account (#3230); what changes is the case with NO state source (a `local run-task` image `Fn::Sub` or a bare `--assume-task-role`), which was the caller's account and is now the deploy account, so a pinned ECR image URI and account-derived ARNs point at the deployed resources. `--from-cfn-stack` keeps the caller's account (it reads as you; CloudFormation sees only your account). The engine commands (`start-service`, `start-alb`, `start-cloudfront`, `start-agentcore`) follow the same rule through cdk-local 0.153.1. Container credentials, assumed roles and secrets still resolve as you. Same-account use and runs without `--role-arn` are unchanged.
