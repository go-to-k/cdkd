- **A Cloud Control abandonment no longer persists AWS's raw rejection text, and no longer speaks in AWS's voice when it has nothing to say (issue [#3236](https://github.com/go-to-k/cdkd/issues/3236))** -- `src/provisioning/cloud-control-provider.ts`, `src/utils/aws-failure-text.ts`. `CloudControlWaitAbandonedError`'s message is copied verbatim into the durable `deployments/{runId}.jsonl`, and it interpolates whatever the poll failed with. A 403 there carries the account id and the assumed-role ARN; a `CredentialsProviderError` carries the `credential_process` helper's ARGV and its stderr (measured: a vault token). Both are now reduced to the wire error name, with the full text at `debug` so `--verbose` still diagnoses it. A TRANSPORT failure keeps its wording -- `connect ECONNREFUSED <ip>:443` is the sentence this issue was reported with, and it names a host, never a caller. The discriminator is a real service signal (`$fault`, or a NUMERIC `$metadata.httpStatusCode`) plus the `*ProviderError` family, which has neither because credential resolution runs outside the retry middleware that stamps `$metadata`, measured. Three shapes that previously rendered as nonsense or as a leak: an ABSENT cause (the ordinary slow-resource timeout) adds no clause now instead of `a non-Error value of type undefined`; a non-`Error` rejection is WITHHELD but reported by type rather than dropped; and an `Error` the SDK normalized to an empty message renders no dangling colon. `describeAwsFailure` also stopped being able to out-throw the failure it describes: `String(value)` throws for a null-prototype object, which replaced the abandonment with a `TypeError`. The shared `isAwsAuthoredFailure` keys on `$metadata` PRESENCE, which smithy stamps on socket errors too, so this path carries its own predicate; retiring that divergence is [#3297](https://github.com/go-to-k/cdkd/issues/3297). Per-arm reasoning, including the shapes deliberately NOT matched, is at `abandonWait`.
