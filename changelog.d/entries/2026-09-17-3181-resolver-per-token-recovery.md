- **`cdkd scrub` no longer stops learning a value's secrets at the first reference it cannot fetch** — the resolver walked a string's `{{resolve:...}}` tokens, an object's keys, and an `Fn::Sub` variable map in bare sequential loops with no per-unit `try`, so one unfetchable reference, or one unresolvable key beside one, abandoned every later unit in the same value. A leaf holding `{{resolve:ssm-secure:/deleted/param}}` before a live `{{resolve:secretsmanager:prod/db:SecretString:password}}` never fetched the second one, so recorded no needle for it — and a needle is the only thing that drives redaction, so a plaintext already in `state.json` survived a `cdkd scrub` that reported the stack clean. Each unit now resolves under its own `try`: a failed FETCH is recorded and the walk continues, so the later reference is scanned and redacted. `cdkd scrub` opts in at the three passes that discard the resolved value (resource properties, orphan records, output values); `Export.Name` keeps its value and stays on the previous abort. An abandoned unit is still counted and warned about (#3160), judged per unit and folded to the most severe — so a genuinely unfetched reference still gates `--dry-run --fail` even behind a template-shape failure, while an abandoned key carrying no reference of its own does not count. A deliberate REFUSAL still aborts the walk: a region-ambiguous reference, an `ssm-secure` spelling over a public parameter, and the NAMELESS spellings (`{{resolve:secretsmanager:}}`, #2692). The recovery is OPT-IN via `ResolverContext.abandonedResolutions`, and a caller that keeps its resolved value must fail on a non-empty bag; `deploy`, `diff`, `drift` and `rollback` pass no bag and keep the previous abort. One exception: a region no AWS client can safely be built for now raises a typed refusal on every path, bagless ones included, where it previously degraded. Issues #3181 and #3218; #3160 is the counted-finding half and #3196 the per-property half.
