- **A Synthetics canary's script change deploys instead of failing on the read-only `Code.SourceLocationArn` (issue [#6553](https://github.com/go-to-k/cdkd/issues/6553))** -- `src/provisioning/cloud-control/update.ts`, `src/provisioning/cc-nested-create-only-patch.ts`. A Cloud Control update sends a changed object property as one op writing the whole object. Cloud Control applies it to the model it reads, so a nested read-only member there that the template cannot declare was dropped, and Cloud Control refused the update: every change to a `AWS::Synthetics::Canary`'s inline or S3 code failed with `readOnlyProperties [/properties/Code/SourceLocationArn] cannot be updated`. The update now carries the live value of each nested read-only member the op omits, as it already did for nested create-only members (#6294). The read-only schema lookup is the one the update already made; the live read runs only when such an op omits such a member.
