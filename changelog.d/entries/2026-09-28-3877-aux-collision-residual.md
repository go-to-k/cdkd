- **An "already exists" from an auxiliary create call of a Route 53 hosted zone, Kinesis stream or DynamoDB table no longer reads as the resource's own name collision (issue [#3877](https://github.com/go-to-k/cdkd/issues/3877), the residual of [#3826](https://github.com/go-to-k/cdkd/issues/3826))** -- `src/provisioning/providers/route53-provider.ts`, `kinesis-provider.ts` and `dynamodb-table-provider.ts`, with rows in `tests/unit/provisioning/auxiliary-failure-3826.test.ts`. Each create now sets a flag once its main create call returns (`CreateHostedZone`, `CreateStream`, `CreateTable`) and passes any later failure through `markAuxiliaryFailure`: the hosted zone's `AssociateVPCWithHostedZone` and `UpdateHostedZoneFeatures`; the stream's `AddTagsToStream`, retention change, `StartStreamEncryption` and `EnableEnhancedMonitoring`; and the table's `UpdateContinuousBackups`, `UpdateTimeToLive`, `EnableKinesisStreamingDestination`, `UpdateContributorInsights` and the stream-arn `TagResource` / `PutResourcePolicy`. Before this change, such a failure relaying AWS's "already exists" was treated as a collision on the resource's own name, so `--replace` deleted the live old resource and a replacement rollback deleted the live new one. The error text is unchanged, and a collision on the main create still classifies. `AWS::DynamoDB::GlobalTable` remains open under #3877.
