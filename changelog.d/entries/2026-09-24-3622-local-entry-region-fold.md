- **`cdkd local invoke`, `local run-task` and `local invoke-agentcore` now fold an upper-cased `AWS_REGION` / `AWS_DEFAULT_REGION` at their entry, not only `--region` (issue [#3622](https://github.com/go-to-k/cdkd/issues/3622))** -- `src/cli/commands/local-invoke.ts`, `src/cli/commands/local-run-task.ts`, `src/cli/commands/local-invoke-agentcore.ts`, `src/cli/commands/local-state-loader.ts`, the three `*-from-state` integ fixtures, plus tests. Each command folded the `--region` flag and the region chains it builds itself, but the SDK clients it creates with no region read `AWS_REGION` directly and raw. So `AWS_REGION=US-EAST-1 cdkd local invoke --from-state` without `--region` failed outright with `Failed to verify state bucket ... HeadBucket (HTTP 400)`, and `applyRoleArnIfSet`'s STS client and the `--profile` credential resolver were exposed the same way. The three handlers now call `foldRegionOption`, as `local start-api` does since #2103. `local run-task` captures the raw env spelling before the fold and passes it to the bootstrap-marker read as `rawEnvRegion`, so the marker read's second probe now also tries the key an `AWS_REGION=US-EAST-1 cdkd bootstrap` writes (`cdkd-bootstrap/US-EAST-1.json`), including when the stack's own region decides the key. Before this change that read could not reach the state bucket at all.
