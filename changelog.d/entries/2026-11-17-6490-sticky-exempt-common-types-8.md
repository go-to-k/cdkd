- **An `AWS::ApiGatewayV2::Stage`, `AWS::ApiGatewayV2::Integration`, `AWS::ApiGatewayV2::Route`, `AWS::ApiGatewayV2::Authorizer`, `AWS::AppSync::GraphQLApi` or `AWS::S3Vectors::VectorBucket` recorded `provisionedBy: 'cc-api'` returns to its SDK provider (issue [#6490](https://github.com/go-to-k/cdkd/issues/6490), batch 8)** -- `src/provisioning/provider-registry/sticky-exempt.ts`, `src/provisioning/sticky-exempt-physical-id.ts` and the new `cc-to-sdk-reroute-common-types-8` integ. The six types are now `'sdk-coverage'` members of `STICKY_CC_MIGRATION_EXEMPT`, so such a resource on Cloud Control moves to the SDK provider in place on the next deploy that changes it; `--pin-cc-api <LogicalId>` declines that. Cloud Control records a v2 stage, integration and route as `<apiId>|<id>`, a v2 authorizer as `<authorizerId>|<apiId>` (the API id last), and a GraphQL API and a vector bucket by their ARN, while each SDK provider records the bare id or name, so each entry declares a strict physical-id normalizer and the flip writes the bare id; an id of any other shape is refused before any AWS call, naming `--pin-cc-api <LogicalId>`. Every form was measured on live resources. `Ref` of the GraphQL API and the vector bucket stays their ARN across the move. `cdkd diff` annotates the move `[returning to SDK provider]`.
