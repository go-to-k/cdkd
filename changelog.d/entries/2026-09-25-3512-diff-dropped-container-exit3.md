- **`cdkd diff` now exits 3 over a record whose DROPPED container `cdkd deploy` refuses, instead of 0 (issue #3512)** — an unreadable `resources` map, a `resources` entry that is not a resource record (a `null` row, or an object with no resource type, torn `properties` map or not), an `orphans` field that is not a list, and an `orphans` record the adoption preview cannot read. Each was already named in the preview, in `--json`'s `unreadable` and in the `--fail` count, so plain `cdkd diff` exited 0 and `--fail` exited 1 while the next deploy refused the record. Each now also puts one reason per container on the node's `blocking`, the rule #3335 set for the `properties` map and `outputs` bag: `countBlocking` raises `DeployRefusalPreviewError` (exit 3), ranked above `--fail`. The `unreadable` rows are unchanged, so `--json` consumers see the same `unreadable` list and a new `blocking` entry. TOP-LEVEL only, as for #3335: a nested child keeps its warning and its `unreadable` row and adds no reason. The dropped-entry list is now pushed one id at a time, so a record with more dropped entries than the engine's argument limit no longer aborts `cdkd diff` with a bare `RangeError`.
