- **A CloudWatch alarm on a cross-account metric now watches the metric in the account it names (issue [#3723](https://github.com/go-to-k/cdkd/issues/3723))** -- `src/provisioning/providers/cloudwatch-alarm-provider.ts`. CDK emits `Metrics[].AccountId` when an alarm's metric belongs to another account than the stack's. The SDK provider built each `PutMetricAlarm` metric entry from `Id`, `Expression`, `Label`, `ReturnData`, `Period` and `MetricStat` only, so `AccountId` never reached AWS: the deploy succeeded and the alarm watched the same-named metric in its own account. It is now sent on create and update. Found by the differential wire harness (`tests/unit/provisioning/sdk-wire-coverage.test.ts`), which now carries `AccountId` in its metric-math bag.
