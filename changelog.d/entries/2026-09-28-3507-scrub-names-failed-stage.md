- **`cdkd scrub` names a CDK Stage that failed to load when stack selection comes back empty (issue [#3507](https://github.com/go-to-k/cdkd/issues/3507))** -- `src/cli/commands/scrub.ts`, with unit tests in `tests/unit/cli/commands/scrub-stack-selection.test.ts`. A stack argument matching nothing answered a bare `No stacks matched.`, naming neither the pattern, the stacks the app does have, nor a Stage whose manifest could not be read -- whose stacks are dropped from the synthesized app, so `cdkd scrub MyStage/MyStack` could not select them. scrub now raises the same message `deploy`, `diff`, `list`, `publish-assets` and `synth` print: `No stacks matching <patterns> found in assembly. Available: <stacks>`, plus the failed-Stage note naming the targeted Stage or listing every failed Stage behind `Possibly unrelated:`. An app that synthesized no stacks is refused with `No stacks found in assembly` and the same note, where it answered `Multiple stacks found: .` with no argument and `No stacks matched.` under `--all`. The exit code is unchanged. `--all` over an app where some stacks synthesized still scrubs only those; the synthesis warning is what names the Stage.
