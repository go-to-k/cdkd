- **Every log line is now stripped of terminal control characters at the logger, and `cdkd state` messages flatten each interpolated value to one line (issue [#3479](https://github.com/go-to-k/cdkd/issues/3479), closes [#3374](https://github.com/go-to-k/cdkd/issues/3374))** -- `src/utils/logger.ts`, `src/utils/display-safe.ts` (`terminalSafe`, `safeMsg`), `src/cli/commands/state.ts`, new `scripts/check-raw-log-interpolation.ts` + `tests/raw-log-interpolation-baseline.json`. `ConsoleLogger` sanitized only its extra arguments, so a stack name, region, logical id or AWS message interpolated into the message itself reached the terminal raw, including cursor-movement, screen-clear and bidi-override sequences. It now removes every foreign escape sequence whole and replaces every other control character except newline and tab, keeping cdkd's own colours. That cannot tell cdkd's newline from a value's, so line forging is closed per call site by `safeMsg`, a tagged template that keeps the template's newlines and flattens each value; `cdkd state`'s messages are the first to use it, and its `destroy --all` confirmation list, written to stdout directly, renders each name through `displayIdent`. A per-file ratchet (`vp run audit:raw-log-interpolation:check`) fails CI when a file gains a logger call that interpolates raw.
