- **A stored `{{resolve:...}}` reference is re-resolved in the region and at the secret version its record names (issue [#4847](https://github.com/go-to-k/cdkd/issues/4847), part 2 of 3)** -- `src/deployment/intrinsic-resolver/recorded-reference-routes.ts`, `getatt.ts`, `dynamic-refs.ts`, `dynamic-ref-lookups.ts`, `src/deployment/rollback-executor/replay-secrets.ts`, `src/cli/commands/drift.ts`, `src/cli/commands/scrub.ts`. A resource named from a secret that a stack in another region publishes (`Fn::GetStackOutput` with `Region`) stores its `Arn` as `arn:...:{{resolve:...}}`; a reader of that `Arn` added while the resource was unchanged was sent the literal reference (SSM refused it; a queue policy matched nothing), because cdkd could not tell which region resolved it. It now uses the state schema v12 record: the recorded region answers, and a single recorded version is read by a pinned lookup, so a reader also gets the value the resource was named with after the secret rotated. A pinned version that is gone warns and falls back to the previous check. The rollback replay, `cdkd drift` and `cdkd scrub` resolve such a reference in its recorded region instead of refusing it. A record without the v12 field behaves as before; an unchanged deploy makes the same AWS calls, and a pin equal to the current version adds none. Integ: `getstackoutput-crossregion` (two-region arm), `rollback-cross-region-secret`, `rollback-nested-cross-region-secret`.
