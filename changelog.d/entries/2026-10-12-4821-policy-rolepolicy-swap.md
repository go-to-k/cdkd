- **A deploy that swaps an inline policy name between an `AWS::IAM::Policy` and an `AWS::IAM::RolePolicy` / `UserPolicy` / `GroupPolicy` on one principal now keeps both policies, and so does its rollback (issue [#4821](https://github.com/go-to-k/cdkd/issues/4821))** -- `src/deployment/inline-policy-claims.ts`, `deploy-engine.ts`, `deploy-engine/execute.ts`, `deploy-engine/replacement.ts`, `rollback-executor.ts`, `src/provisioning/cloud-control-provider.ts`. Such a swap used to run both writers at once, and the replaced standalone policy's delete of its old name removed the policy that had just taken it, so the principal could end up with neither. CloudFormation finishes the same swap holding only the standalone policy's new name: its cleanup-phase delete removes the other policy. cdkd now runs the writer releasing a name before the standalone policy that takes it (Cloud Control refuses to create a name the principal still holds). A standalone policy's delete then leaves a name another resource of the same deploy has already written there. A rollback reverses that writer before the standalone policy. Writers that share no (principal, name) pair are not ordered, so a deploy with no such collision runs as before.
