- **`--remove-protection --verbose` (on `cdkd destroy`, `cdkd state destroy` and rollback) now masks secret values in the debug line printed when cdkd cannot read a deletion guard before turning it off (issue [#5180](https://github.com/go-to-k/cdkd/issues/5180))** -- `src/provisioning/providers/deletion-protection-compensation.ts`, its callers in `src/provisioning/cloud-control-provider.ts` and `src/provisioning/providers/{asg,cognito,docdb,elbv2,emr-cluster,logs-loggroup,neptune,rds}-provider.ts`, `src/provisioning/providers/dynamodb-table-provider.ts`, and unit cases. The line `Could not read <guard> on <physical id> before disabling it: <AWS's text>` was printed without the delete's secret masker. A physical id can come from a dynamic reference (`{{resolve:secretsmanager:...}}`), and AWS's text quotes it, so `--verbose` output could show that plaintext. The same applied to the debug line printed when the guard could not be turned off, for an Auto Scaling group, load balancer, log group, Cognito user pool (whose AWS text can quote an echoed template value; also its failed write-back when the compensation restores the guard), DocDB cluster, Neptune cluster or instance, and DynamoDB table (also its wait after the flip). These lines now go through the masker. They are printed only with `--verbose` and are never written to the state bucket. The EC2 instance path is unchanged: its id is assigned by EC2 and cannot hold a template value.
