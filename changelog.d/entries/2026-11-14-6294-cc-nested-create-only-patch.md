- **A Cloud-Control-routed update that changes a member of an object holding a nested create-only path no longer fails when AWS defaulted that create-only member (issue [#6294](https://github.com/go-to-k/cdkd/issues/6294))** -- `src/provisioning/cc-nested-create-only-patch.ts`, `src/provisioning/cloud-control/update.ts`. The patch replaced the whole object with the template's copy, which drops members AWS filled in. Cloud Control applies a patch to the model it reads, so it saw a create-only member change and refused the update: changing `Port` on an `AWS::Route53::HealthCheck` failed with `createOnlyProperties [/properties/HealthCheckConfig/MeasureLatency] cannot be updated`, and the deploy rolled back. CloudFormation applies the same change in place. cdkd now reads the live model once, only for such an op, and carries each nested create-only member the template omits into the patch. Tests: `tests/unit/provisioning/cc-nested-create-only-patch-6294.test.ts`, `tests/unit/provisioning/cloud-control-provider.test.ts`, and the new `cc-nested-create-only-update` integ fixture.
