- **`cdkd scrub` can no longer read one producer's state record as another's (issue [#3323](https://github.com/go-to-k/cdkd/issues/3323))** -- new `src/state/record-keys.ts` plus eight files across `src/state/`, `src/cli/commands/` and `src/utils/`, four suites. Eight composite keys identified a producer by joining two attacker-influenced halves with a NUL: five from the issue and its file sweep, three more from a review round that grepped the OTHER source spelling. Three are in `scrub.ts` and all feed the cross-stack pre-pass that decides whether a producer still holds a plaintext secret: the read memoizer served record X's state for a query about Y, the chain walk SKIPPED a hop whose coordinate collided with the seed and reported no secret expression over a producer that has one, and the verdict cache misfiled a verdict. Each could end a run at `No plaintext secrets found` over surviving plaintext. The route is the consumer's own TEMPLATE: `Fn::GetStackOutput`'s `StackName` is gated only on being a non-empty string before the resolver records it, and a JSON string may contain a NUL. All eight now go through `producerRecordKey` (a `stack`+`region` record) or the new `producerCoordinateKey` (a `stack`+`export-name` coordinate) -- two names over one private `JSON.stringify` encoding injective over ALL string pairs, in the new leaf and re-exported. The fence now sweeps ALL of `src/` for six NUL spellings and requires every hit to be a helper call or a listed exemption CARRYING ITS COUNT, so neither a one-spelling sweep nor a whole-file exemption can be the last word again; the remainder is [#3496](https://github.com/go-to-k/cdkd/issues/3496). Per-site reachability (they are NOT equally exploitable; `listStacks` never was), the bound corrected from [#3308](https://github.com/go-to-k/cdkd/issues/3308), and the fences' limits: [docs/design/3323-composite-record-keys.md](https://github.com/go-to-k/cdkd/blob/main/docs/design/3323-composite-record-keys.md).
