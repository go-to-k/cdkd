- **`cdkd scrub` can no longer read one producer's state record as another's (issue [#3323](https://github.com/go-to-k/cdkd/issues/3323))** -- `src/state/{malformed-resources-bag,s3-state-backend}.ts`, `src/cli/commands/scrub.ts`, two suites plus one new one. Five composite keys identified a producer by joining two attacker-influenced halves with a NUL. Three are in `scrub.ts` and all three feed the cross-stack pre-pass that decides whether a producer still holds a plaintext secret: its read memoizer served record X's state for a query about record Y, its re-export chain walk SKIPPED a hop whose coordinate collided with the seed and so reported no secret expression over a producer that publishes one, and its verdict cache served one coordinate's verdict for another. Each could end a run at `No plaintext secrets found` over surviving plaintext. The reachable route is the exports index (`_index/<region>/exports.json`): `JSON.parse` casts each entry with no validation, the resolver records `entry.producerStack` verbatim, and a JSON string may contain a NUL. `s3-state-backend.ts`'s two `listStacks` dedupe keys are fixed too but were NOT exploitable: both halves are S3 key segments and, measured on this issue, S3 refuses to store a NUL-bearing key -- injectivity by an invariant this code neither states nor would notice losing. All five now go through `producerRecordKey` (a `stack`+`region` record) or the new `producerCoordinateKey` (a `stack`+`export-name` coordinate), two names over one private `JSON.stringify` encoding injective over ALL string pairs. The bound stated when [#3308](https://github.com/go-to-k/cdkd/issues/3308) shipped -- a collision costs only a dropped warning line -- is corrected, along with per-site costs, the provenance trace, the fences' limits and why `crossStackSourceKey` is deliberately unchanged: [docs/design/3323-composite-record-keys.md](https://github.com/go-to-k/cdkd/blob/main/docs/design/3323-composite-record-keys.md).
