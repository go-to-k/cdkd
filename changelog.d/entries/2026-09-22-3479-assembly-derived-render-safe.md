- **Every assembly-, manifest- or template-derived value `cdkd list`, `cdkd orphan`, synthesis and macro expansion render is now display-safe (issue [#3479](https://github.com/go-to-k/cdkd/issues/3479))** -- `src/cli/commands/{list,orphan}.ts`, `src/synthesis/{synthesizer,macro-expander}.ts`, `src/synthesis/context-providers/index.ts`; five suites. `displaySafe` maps C0 / DEL / C1, `U+0085`, the Unicode line terminators and the Trojan-Source bidi overrides to a space, neither quoting nor truncating, so a legitimate value is byte-identical. Previously a `stackName`, `displayName`, context key, transform name, `Parameters` key, template logical id or `aws:cdk:path` reached the terminal raw, and `formatError` sanitizes only an error's `cause`, so a crafted value could erase cdkd's own line with `ESC [ 2 K` plus CR and forge one after it. **The most reachable sites needed no error at all**: `cdkd list` writes one display id per line to stdout at default verbosity, so `cdkd list -a ./cdk.out` over someone else's assembly printed it; so do `cdkd orphan`'s `Target:` / success lines, the `[macros] Expanding` line and the parameter-placeholder warn. The `--long` / `--show-dependencies` payloads are covered too: measured per character, neither `JSON.stringify` nor `yaml` escapes DEL, C1, `U+2028` or the bidi overrides, so their encoder is no boundary. A region takes `asciiOnly`; AWS text echoing a template value back takes `displayAwsMessage`, which also caps it. Every unquoted `Available: ...` list in `cdkd orphan` takes `displayIdent` capped at `STACK_REF_MAX_CODE_POINTS`: `displaySafe` TRIMS, so a planted entry would otherwise render byte-identical to the genuine one said to be missing. `cdkd list` does NOT route through `describeStack`: its field order is inverted, and `displayIdent`'s quoting belongs in prose, not a payload a shell loop reads.
