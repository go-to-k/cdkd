- **Every assembly-, manifest- or template-derived value `cdkd list`, `cdkd orphan`, synthesis and macro expansion render is now display-safe (issue [#3479](https://github.com/go-to-k/cdkd/issues/3479))** -- `src/cli/commands/{list,orphan}.ts`, `src/synthesis/{synthesizer,macro-expander}.ts`, `src/synthesis/context-providers/index.ts`; five suites. `displaySafe` maps C0 / DEL / C1, `U+0085`, `U+2028` / `U+2029` and the Trojan-Source bidi overrides to a space; it neither quotes nor truncates, so every legitimate value renders byte-identically. Previously a `stackName`, `displayName`, context key, transform name, template logical id or `aws:cdk:path` reached the terminal raw; `formatError` sanitizes only an error's `cause`, never its own `message`, so a crafted value could erase cdkd's own line with `ESC [ 2 K` plus a carriage return and forge one after it. **The most reachable site needed no error at all**: `cdkd list` writes one display id per line to stdout at default verbosity, so `cdkd list -a ./cdk.out` over someone else's assembly printed it; so do `cdkd orphan`'s `Target:` / `Orphaned N resource(s)` lines and the `[macros] Expanding ...` line. The `--long` / `--show-dependencies` payloads are covered too, their encoder being no boundary: `JSON.stringify` escapes C0 and DEL but passes C1, `U+2028` and the bidi overrides, and `yaml` escapes ESC while passing C1 and `U+2028`. A joined list sanitizes per ELEMENT. `cdkd orphan`'s two unquoted `Available: ...` lists take `displayIdent` instead, capped at `STACK_REF_MAX_CODE_POINTS`: `displaySafe` trims, so a planted entry plus a terminator would otherwise render byte-identical to the genuine one the message says is missing. `cdkd list` deliberately does NOT route through `describeStack`, whose field order is inverted and whose `displayIdent` would quote a legitimate `My Stack` inside a payload a shell loop reads. Rows still open on the issue: the CDK-annotation display and the `nested-stack-messages.ts` remedy.
