- **An IAM role, user, group, managed policy or instance profile member, an S3 bucket policy, an event bus `Policy` or a security group rule that cdkd just wrote no longer leaves a drift baseline that `cdkd drift --revert` would undo when the write is not yet visible (issue [#6609](https://github.com/go-to-k/cdkd/issues/6609))** -- `src/provisioning/settle-own-write-members.ts`, `src/provisioning/sg-own-write-rules.ts`, `src/provisioning/providers/s3-bucket-policy-own-write.ts`, the IAM, event bus and EC2 read modules, `src/cli/commands/drift/baseline-keys.ts`, unit tests. The capture after cdkd's own write now re-reads a declared member whose first answer differs from the template (its own call, up to 3 more reads, 3.5 seconds at most, only when the first answer differs): a role's trust policy, boundary, managed policy ARNs and inline policies; a user's boundary, managed policy ARNs, groups and inline policies; a group's managed policy ARNs and inline policies; a managed policy's document and attachments; an instance profile's roles; a bucket policy; an event bus `Policy`; a security group's rules. A list settles once every declared entry reads back, and an entry the template does not declare never holds it. A list still lacking a declared entry gains it at its declared position, in the shape AWS reads it back; a boundary or bus policy still unset is recorded as declared; a bucket policy still absent records no baseline. Any other answer is recorded as read, with a warning that points at `cdkd state refresh-observed`. Drift, import and `state refresh-observed` still take the first answer. Drift no longer compares such a member while the live value is exactly the declared one (a list as a set, never a superset or a subset), which also heals a baseline written by an earlier cdkd.
