- **`cdkd local invoke` and `cdkd local invoke-agentcore` under `--from-state` keep a secret another stack exports off the `docker run` command line (issue [#6341](https://github.com/go-to-k/cdkd/issues/6341))** -- `src/local/cross-stack-watch.ts` (new), `src/cli/commands/local-invoke/command.ts`, `src/cli/commands/local-invoke-agentcore/env.ts`, `src/local/ecs-task-resolver/cross-stack.ts`, `docs/local-invoke.md`, `docs/local-invoke-agentcore.md`. A Lambda or AgentCore runtime env var reading a producer's exported `AWS::AppSync::ApiKey` key (or another secret its state records in plaintext, such as an `AWS::IAM::AccessKey`'s `SecretAccessKey`) through `Fn::ImportValue` / `Fn::GetStackOutput` went on the command line as `-e KEY=VALUE`, where `ps` and `docker inspect` show it. Both env builders now read the producer-secret verdict the `--from-state` resolver returns per call (#6337) and pass such a key value-less (`-e KEY`); the value still resolves into the container. A value cdkd cannot check (an unreadable producer record, a stale exports-index entry) is passed the same way. `run-task`'s resolver watcher moved to the shared module, unchanged. Tests: `tests/unit/cli/local-invoke-cross-stack-producer-secret-6341.test.ts`.
