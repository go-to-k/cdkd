- **An EC2 instance's `SsmAssociations` now treats a shared document's ARN and a bare document name as different documents (issue [#6866](https://github.com/go-to-k/cdkd/issues/6866))** -- `src/provisioning/providers/ec2/instance-ssm.ts`, `src/provisioning/providers/ec2/instance-support.ts`. The drift readback, the update diff and the association lookup matched a `DocumentName` by the text after the last `/`, so `arn:aws:ssm:...:222222222222:document/Baseline` (another account's shared document) equalled this account's own `Baseline`: drift missed a swap between them, a template edit between them re-associated nothing, and removing the ARN-declared association could also delete an own same-named one. SSM refuses an association by the ARN of an own or an AWS document (measured), so the two never name one document; all three now compare by the exact spelling. **Behavior change:** a deploy that edits `DocumentName` between a bare name and a shared ARN now deletes the old association and creates the new one. Deleting an ARN-declared association with no exact live match falls back to the bare-named one only after `DescribeDocument` (needs `ssm:DescribeDocument`) shows this account has no document by that name; any other answer leaves the association with a warning.
