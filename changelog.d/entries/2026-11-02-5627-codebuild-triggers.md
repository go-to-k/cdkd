- **`AWS::CodeBuild::Project` deploys with `Triggers` (go-to-k/cdkd#5627)** -- `src/provisioning/providers/codebuild-provider.ts`. A project declaring `Triggers`, which is what CDK's `webhook: true` emits, used to be refused pre-flight, because the type has no Cloud Control route. The provider now creates, updates and deletes the webhook. `Webhook: false` deletes a live webhook; a removed `Triggers` keeps it, and removed `FilterGroups` clear, both as CloudFormation does. What CloudFormation refuses is refused before any call: `FilterGroups` or `BuildType` with the webhook off, and `ScopeConfiguration` on a source location other than `CODEBUILD_DEFAULT_WEBHOOK_SOURCE_LOCATION`. A project deployed with `--prefer-sdk-route AWS::CodeBuild::Project:Triggers` gets its webhook on the next update of that project. A declared `ScopeConfiguration` that differs from the live webhook's is warned about, because `UpdateWebhook` cannot change it. A `CreateProject` or `UpdateProject` that reaches a `Source.Auth` connection through a just-created service role retries when CodeBuild answers `OAuthProviderException` with an invalid-token or not-authorized message. `Triggers` is not read back, so `cdkd drift` does not report it (write-only in the CloudFormation schema).
