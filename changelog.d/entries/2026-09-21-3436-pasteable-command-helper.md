- **Thirteen message modules now build the `cdkd` command they tell you to paste through one gate, and print it on its own labelled line (issue [#3436](https://github.com/go-to-k/cdkd/issues/3436))** -- new `src/utils/pasteable-command.ts`, 13 message modules across `src/cli/commands/`, `src/deployment/`, `src/assets/`, `src/provisioning/` and `src/utils/`, tests. A command printed inside a prose `'...'` span is pasted WITH those quotes, so an interpolated value carrying `'` closed the wrapper and the rest ran as shell -- measured in [#3363](https://github.com/go-to-k/cdkd/pull/3363) and reproduced by the maintainer over 324 arms; quoting the value does not help, the wrapper is what inverts. `pasteableCommand(verb, args, extraFlags)` sanitizes each value and compares it against the RAW one, caps it, then shell-quotes it or prints a QUOTED hole (`'<stack>'`) -- never the altered spelling, which addresses a different record, nor nothing, which resolves the ambient default. A flag and its value go or stay together, so `--stack-region` cannot outlive the region it names, and a value the command would read as an option (`--all`) or, for `cdkd deploy`, a pattern (`*` / `/`) becomes a hole too. Messages now end in labelled lines (`Bootstrap with:`, `Revert it with:` ...) rather than naming the command mid-sentence. `shellQuote` and `commandHole` moved into the new module and are re-exported from `src/state/lock-contention-message.ts`, since `src/utils/**` imports nothing from `src/state/**`. `scripts/check-docs-error-strings.ts` now collapses a `\n` escape in a template like the whitespace it renders as, without which a message carrying a trailing command line is unanchorable. The four `cdkd drift` sites are [#3307](https://github.com/go-to-k/cdkd/issues/3307) / [#3486](https://github.com/go-to-k/cdkd/pull/3486), and the source fence plus the remaining spelled-out templates are the follow-up on #3436.
