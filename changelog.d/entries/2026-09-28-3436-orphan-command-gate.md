- **`cdkd export`'s `cdkd state orphan` recovery commands build through the shared pasteable-command gate, and `cdkd state orphan`'s lock refusal no longer quotes the stack name by hand (issue [#3436](https://github.com/go-to-k/cdkd/issues/3436))** -- `src/cli/commands/export.ts`, `src/cli/commands/state.ts`. `orphanCommandFor` kept its own copy of the gate; it now builds through `pasteableCommand` and still names neither value when either is withheld. A non-string record value still fails closed. The note saying why comes from the gate's reason for each value (altered, empty, too long, or beginning with `-`; a region beginning with `-` is only refused conservatively, as `--stack-region` takes it as a value), and it sits on the line above its command: each command is on a line of its own, one per line in the nested-export list, where each note names its record by CloudFormation stack name, or describes it when that name is not a plain identifier. A stack name beginning with `-` is never to be filled back in, since Commander could read it as an option in the positional. On a sentence's line, an apostrophe (`the parent's record`) flipped the shell quote and a pasted `'x; touch OWNED; #'` ran. The lock refusal renders the name through `displayStackName`, not inside `'...'`, which a name `x'$(touch OWNED) #` closed when the sentence was pasted.
