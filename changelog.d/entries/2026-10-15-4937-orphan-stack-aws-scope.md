- **`cdkd orphan` now reads live `Fn::GetAtt` values in the orphaned stack's region, not the CLI's `--region` / `AWS_REGION` (issue [#4937](https://github.com/go-to-k/cdkd/issues/4937))** -- `src/cli/commands/orphan.ts`, new `tests/unit/cli/orphan-stack-aws-scope-4937.test.ts`, and a new phase 4b in `tests/integration/orphan-getatt-takeover/`. `cdkd orphan` picked the stack's region from its synthesized `env.region`, its state record or `--stack-region`, but built its providers on the CLI-region clients and never entered that stack's AWS scope. So when the rewrite read an orphan's attribute live (the record could not serve it), the read went to the CLI's region: a NotFound aborted the orphan, or a same-named resource's value (or an ARN naming the wrong region) was written into a sibling's state. The provider registry and the rewrite now run inside `runWithStackAwsClients` for the stack's region, as deploy does. The state backend and lock stay on the CLI's clients, and `process.env.AWS_REGION` is left unchanged.
