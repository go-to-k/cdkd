- **A `--profile <name>` you passed can no longer redraw your terminal from a `cdkd local` error; a name the shell would reinterpret is no longer pasted into a command cdkd tells you to run (issue [#3377](https://github.com/go-to-k/cdkd/issues/3377))** -- `local-profile-credentials-file.ts`, `local-start-api.ts` (`resolveProfileCredentials`), `local-invoke-agentcore.ts` (both `--assume-role` fallback notices). The issue reported two sites; the sweep found four here plus one in `buildForceUnlockCommand` (its own entry) -- the two fallback notices were nobody's report. `ConsoleLogger.formatMessage` sanitizes only a call's EXTRA ARGS and `formatError` only a `cause`, so a message's own text was raw argv. **The two shapes take DIFFERENT helpers, which is the substance rather than a detail.** A MESSAGE renders through `displayIdent` -- allowlist, length cap, and a JSON-quoted boundary only for a value that could spoof, so a legitimate name reads as before. The `aws sso login --profile <name>` line is a command an operator PASTES, and `displayIdent` is not enough: every character of `~evil` and `-rf` is a plain identifier character, so both render BARE while the shell reads one as a home directory and the other as a flag. That arm is gated on `isPasteableIdent` and writes no command out when it fails -- `cdkd gc`'s disposition for an unpasteable stack name. Unchanged on purpose: `writeProfileCredentialsFile`'s CR / LF / `[` / `]` validator asks what corrupts the INI FILE and the docker `-e` line -- a different question -- and the section header still carries the name byte-for-byte.
