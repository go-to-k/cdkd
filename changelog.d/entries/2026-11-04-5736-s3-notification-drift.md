- **`cdkd drift` no longer reports a bucket's event notifications as drift after a fresh deploy, and `cdkd drift --revert` no longer deletes them (issue [#5736](https://github.com/go-to-k/cdkd/issues/5736))** -- `src/cli/commands/drift.ts` and its unit tests. CDK's `bucket.addEventNotification(...)` writes the bucket's `NotificationConfiguration` through a `Custom::S3BucketNotifications` resource that runs after the bucket is created, so the bucket's recorded snapshot did not hold the notifications and drift reported them on every fresh deploy. `--revert` then wrote the empty snapshot back, and S3 stopped delivering events. Drift now skips a bucket's `NotificationConfiguration` when a `Custom::S3BucketNotifications` resource in the same stack writes it and the template does not set it on the bucket, which matches CloudFormation's drift detection. Stacks that are already deployed are fixed without a redeploy.
