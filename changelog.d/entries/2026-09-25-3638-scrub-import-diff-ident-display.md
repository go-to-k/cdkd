- **`cdkd scrub`, `cdkd import` and `cdkd diff --recursive` render assembly- and state-chosen names inside a boundary of their own, never raw or inside cdkd's quotes (issues [#3638](https://github.com/go-to-k/cdkd/issues/3638), [#3590](https://github.com/go-to-k/cdkd/issues/3590), [#3617](https://github.com/go-to-k/cdkd/issues/3617))** -- `src/cli/commands/scrub.ts`, `import.ts`, `diff-recursive.ts`. `cdkd scrub` printed stack names, regions, resource and orphan logical ids, output and export names, property paths, secret names and producer stacks into its warnings and refusals with no sanitizer at all (about 60 sites), or inside `'${displaySafe(...)}'`, which passes `'`; a crafted name could write a line or a clause of its own into text a `--dry-run --fail` CI gate prints. `cdkd import --migrate-from-cloudformation`'s nested-stack refusals and parameter-dependence warnings, and `cdkd diff --recursive`'s nested-row refusals, carried the same shape. Each name now renders through `displayIdent` (a stack name through `displayStackName`, an `aws:asset:path` through `displayAssemblyPath`): bare when plain (`Scrub of MyStack could not resolve the Fn::ImportValue in resource Db at MasterUserPassword`), otherwise as one JSON string. A masked value is masked first and bounded after. The shell-quoted remedy commands are unchanged.
