- **`cdkd rollback --revert-failed` warns and exits 2 when a failed CREATE recorded a resource state no longer tracks (issue [#4552](https://github.com/go-to-k/cdkd/issues/4552))** -- `src/deployment/rollback-executor/plan.ts`, `src/deployment/rollback-executor/types.ts`, `src/deployment/rollback-executor.ts`, `src/cli/commands/rollback.ts`. A failed CREATE whose recorded physical id differs from the current state record, with no `cdkd import` mark on its segment (an import by a cdkd older than #4547), was planned as `failed CREATE left nothing to revert`, logged at INFO, and the run exited 0, although the resource the op recorded may still exist, untracked. It now classifies as the new `skip-failed-mismatch`: the plan line names the recorded physical id (masked when secret-derived) as not the resource state tracks and needing manual attention, and the replay warns, records a `ROLLBACK_RESOURCE_SKIPPED` event, and counts a warning, so the run exits 2, like a completed op's `skip-mismatch`. Nothing is deleted and the state record is left as it is. The import-marked (displaced) path and the true no-op (a failed CREATE whose record is already gone, a failed DELETE) are unchanged. Tests: `tests/unit/cli/rollback-imported-ops.test.ts`, `tests/unit/deployment/rollback-executor-skip-events.test.ts`, `tests/unit/deployment/rollback-executor.test.ts`, `tests/unit/deployment/rollback-executor-inline-policy-claims.test.ts`.
