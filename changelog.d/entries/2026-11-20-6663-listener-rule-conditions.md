- **An ELBv2 listener rule with a path or host condition can be updated again, and `cdkd drift --revert` restores it (issue [#6663](https://github.com/go-to-k/cdkd/issues/6663))**. A listener rule is updated through Cloud Control, which applies the patch on top of the model its read handler returns. That model carries each `path-pattern` / `host-header` condition twice, as the legacy `Values` and as the `PathPatternConfig` / `HostHeaderConfig` CDK synthesizes, and `ModifyRule` refuses both together. So every update that did not also change the conditions (a new action, target or priority) failed with `You cannot provide both Values and 'PathPatternConfig'` and rolled back, where CloudFormation updates the rule; `cdkd drift --revert` failed the same way and left the rule half-reverted. The update now always sends the desired conditions, each without a `Values` that only echoes its `*Config` member. No AWS call is added.
