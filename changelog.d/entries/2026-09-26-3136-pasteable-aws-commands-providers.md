- **Provider messages no longer paste a template- or response-borne name or id raw into the `aws ...` command they tell you to run (issue [#3136](https://github.com/go-to-k/cdkd/issues/3136), partial)** -- new `pasteableAwsCommand` / `WITHHELD_AWS_COMMAND` in `src/provisioning/replacement-protection-advice.ts`, sharing `renderDisableCommand`'s gate; call sites in the `dynamodb-delete-budget`, `ecs`, `rds`, `route53`, `elbv2`, `acm-certificate`, `iam-managed-policy`, `sns-topic`, `cloudfront-distribution`, `cognito`, `eventbridge-rule` and `ec2` providers; unit tests in `tests/unit/provisioning/pasteable-aws-command.test.ts` and each provider's existing suite. The recovery, wait and cleanup commands in these messages interpolated the value bare, so a table name, cluster, rule or bus name, DB cluster identifier or policy path carrying `'`, `;` or `$(...)` pasted as extra shell, and a control byte forged terminal lines (and `deployments/*.jsonl` lines, for the thrown Route 53, ACM and ECS messages). Each value is now checked with `displaySafe(asciiOnly)`, then shell-quoted, and the whole command is replaced by a `[command withheld: ...]` note when any value would render differently or the caller's secret masker would change it. The bare `<task-arn>`, `<arn>`, `<name>` and `<group>` placeholders in the ECS, IAM role / instance profile and EventBridge Scheduler messages are quoted too, and the EIP `--no-wait` warning renders its template `InstanceId` display-safe in the sentence as well. **A clean value renders exactly as before.** The IAM role, user, group and instance profile names stay bare: cdkd's name generator already limits them to `[A-Za-z0-9-]`, which their tests now pin. Residuals, held by open PRs: `dynamodb-globaltable`, `rds-dbproxy-targetgroup`, `iam-access-key`, `apigateway`, `servicediscovery`, `glue`.
