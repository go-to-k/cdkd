- **`AWS::S3::Bucket` no longer reads the SDK spellings of four schema-required nested members (issue [#3585](https://github.com/go-to-k/cdkd/issues/3585))** -- `src/provisioning/providers/s3-bucket-provider.ts`, `tests/unit/provisioning/s3-bucket-provider-never-emitted-spellings.test.ts`, `tests/unit/provisioning/s3-bucket-provider-lifecycle-rule-keys.test.ts`, `tests/integration/s3-lifecycle/`. A template spelling `NoncurrentVersionTransitions[].TransitionInDays` as `NoncurrentDays`, or a notification item's `Topic` / `Queue` / `Function` as `TopicArn` / `QueueArn` / `LambdaFunctionArn`, deployed before and is now refused before any AWS call by the nested required-member check ([#3567](https://github.com/go-to-k/cdkd/issues/3567)), with the message naming the missing CFn member. CloudFormation rejects these spellings too: the L1 `CfnBucket` types lack them, and no L2 emits them on `AWS::S3::Bucket`, so only an escape hatch or a hand-written template reaches them. The provider's alias reads and their #1748 record folds are removed. The `Transitions[]` `Days` / `Date` aliases, the notification `Events` list and the inventory string booleans are unchanged, because the check does not refuse them.
