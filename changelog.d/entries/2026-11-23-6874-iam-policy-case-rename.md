- **Renaming an `AWS::IAM::Policy` only in case now lists the new spelling, as CloudFormation does (issue [#6874](https://github.com/go-to-k/cdkd/issues/6874))** -- `src/provisioning/providers/iam-policy/update.ts`, `tests/unit/provisioning/iam-policy-case-rename-6874.test.ts`, `tests/unit/provisioning/iam-policy-provider-target-shape.test.ts`, `tests/integration/iam-role-policies-drift-clean/`. IAM holds one inline policy per name ignoring case, and a put in another case keeps the first spelling, so a `PolicyName` changed from `CasePol` to `casepol` replaced the document but stayed listed as `CasePol` while state and the template held `casepol`. On each role, group and user that held the old spelling, cdkd now deletes it right before putting the new one, the order CloudFormation uses. If that put fails, the old spelling is put back with its recorded document before the error is reported. A rollback does the same in the other direction.
