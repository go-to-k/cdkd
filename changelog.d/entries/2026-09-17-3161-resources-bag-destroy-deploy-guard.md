- **`cdkd destroy` no longer reports SUCCESS having deleted nothing over a record whose `resources` map cannot be read, and `cdkd deploy` no longer re-creates the stack from one (issue [#3161](https://github.com/go-to-k/cdkd/issues/3161))** -- `src/cli/commands/destroy-runner.ts`, `src/deployment/deploy-engine.ts`, `src/provisioning/providers/nested-stack-provider.ts`, `src/state/malformed-resources-bag.ts`, `diff-calculator.ts`, plus three new suites and cases in three others. `parseStateBody` validates nothing inside a record, so `resources` could hold a string, a list, a number, a boolean or `null`, and the destroy routed on `Object.keys(state.resources).length` — which splits three ways, the middle one being the damage: `[]`, a number or a boolean enumerate NO keys, so the count was `0`, the run took the empty-stack fast path, deleted `state.json` with no confirmation, and reported success, leaving every resource it named live in AWS and untraceable. A string enumerated one id per character; `null` and an absent field threw a bare `TypeError`. The deploy read the same map and planned every template resource as a `CREATE`. All three now REFUSE (`STATE_RESOURCES_MALFORMED`, exit `1`) above their first read: the destroy before the prompt AND the lock, and again on the record the fast path re-reads; the deploy before any provider call or state write, **under `--dry-run` too**; a nested CHILD record before the parent counts it. Repairing to `{}` is not the safe half: `[]`, a number and a boolean ARE the repaired case and each reaches the same outcome, driven through the real runner and `DiffCalculator`. The discriminator is the container's SHAPE, not its size, so an empty `{}` still takes the fast path and still deploys. The destroy refusal names `cdkd state orphan` for dropping the record and leaving the resources -- as a template, not a pasteable command, and withheld when the identity does not render exactly. `cdkd diff` and `state show` still repair and warn.
