- **A failed RDS DB proxy target group create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/rds-dbproxy-targetgroup-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker. The same holds for the failed cleanup a create appends when it cannot deregister the targets it registered; the manual `aws rds deregister-db-proxy-targets` command is still printed. A cdkd-authored or transport error keeps its text. The AWS error is still the wrap's `cause`, so an IAM grant that is still propagating is retried as before, and an "already exists" is still stated as such.
