- **The `AWS::DynamoDB::Table` capacity and PITR forwarders read an Integer the way CloudFormation does, instead of forwarding a bare `Number()` reading (issue [#3147](https://github.com/go-to-k/cdkd/issues/3147))** -- `src/provisioning/providers/dynamodb-table-provider.ts`, `tests/unit/provisioning/dynamodb-table-provider-cfn-integer.test.ts`, `.claude/rules/layout-provisioning.md`. Issue [#3135] moved every `toFiniteNumber`-reading DynamoDB forwarder onto `coerceCfnInteger`, CloudFormation's MEASURED grammar (`/^[+-]?\d+$/`, NO trim). That sweep grepped `toFiniteNumber`, so this provider's reads never appeared: they go through `Number()`, wider still. Five sites move: `create()`'s table-level `ProvisionedThroughput`, its twin on `update()`'s BillingMode-flip arm, the per-GSI `readCapacityNumber`, and `recoveryPeriodInDays`. A template spelling `" 7 "` / `"0x9"` / `"1e1"` -- every one rejected by CloudFormation -- reached AWS as `7` / `9` / `10`, and `""` as `0` (not the `?? 5` default: `''` is not nullish). **Per site, a rejected spelling is now ANNOUNCED and DROPPED, never silently defaulted**: the table-level forwarders omit the member so DynamoDB rejects the request naming it -- the arm this type already takes for an absent required capacity -- the per-GSI one keeps its omit-and-warn arm, and an ABSENT member keeps the silent `?? 5` default. `RecoveryPeriodInDays` is dropped with a warning, so PITR enables at DynamoDB's default period rather than failing on `NaN`; warn not throw, since the update path is replay-reachable. The MIRROR predicates `hasUsableTableCapacity` / `hasUsableDeclaredCapacity` move onto the same reader, closing a divergence the other way: `Number(null)` was `0`, so a DECLARED `null` read as unusable and refused the pre-flip index removal while the forwarder's `?? 5` sent 5 and AWS accepted the flip. **Behavior change:** those spellings now fail the deploy at AWS instead of deploying a capacity CloudFormation refuses.
