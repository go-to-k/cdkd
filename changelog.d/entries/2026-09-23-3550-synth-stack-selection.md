- **`cdkd synth MyStack` prints that stack's template, where a multi-stack app previously had no way to get one template onto stdout at all** (issue [#3550](https://github.com/go-to-k/cdkd/issues/3550), PR #3559) -- `src/cli/commands/synth.ts`, `docs/cli-{synth,reference,deploy-tuning}.md`. `synth` declared no positional, so a stack name was silently ignored under `commander@12` and became `error: too many arguments` under `commander@14` (go-to-k/cdkd#3534). That was the visible half. The real gap: the stdout gate read the size of the WHOLE ASSEMBLY, so with several stacks cdkd printed no template and offered no way to narrow -- `cdk synth MyStack` prints one, and piping it into `jq` / `yq` is ordinary use of a drop-in CDK CLI. **Behavior change:** `synth` accepts `[stacks...]` (physical names, CDK display paths, wildcards -- the matcher `diff` uses); a selection of exactly one prints its template; any other prints none and lists the SELECTED ids, matching `cdk`'s `Supply a stack id (...)`; a pattern matching nothing is refused naming what the app holds, and a ZERO-stack assembly is now refused rather than reported as `Found 0 stack(s)` at exit 0. **What a name narrows, stated because the first draft of this entry claimed it narrowed nothing:** annotations (`--strict` / error aborts now scope to the selection), the `--verbose` per-stack template dump, and the summary -- which counts `N of M` when a pattern narrowed, since `Found 1 stack(s)` on a three-stack app is false. **What it does NOT narrow is synthesis itself.** Measured in `aws-cdk@2.1142.0`: `Toolkit.synth` runs `synthAndMeasure(...)` and only then `assembly.selectStacks(...)`, and the context loop reads `assembly.manifest.missing` for the whole assembly -- so a stack argument does not change which `cdk.context.json` lookups run, and a case fences that.
