- **`cdkd synth MyStack` prints that stack's template, where a multi-stack app previously had no way to get one template onto stdout at all** (issue [#3550](https://github.com/go-to-k/cdkd/issues/3550), PR #3558) -- `src/cli/commands/synth.ts`, `docs/cli-synth.md`. `synth` declared no positional, so a stack name was silently ignored under `commander@12` and became `error: too many arguments` under `commander@14` (go-to-k/cdkd#3553). That was the visible half. The real gap: the stdout gate read the size of the WHOLE ASSEMBLY, so with several stacks cdkd printed no template and offered no way to narrow -- `cdk synth MyStack` prints one, and piping it into `jq` / `yq` is ordinary use of a drop-in CDK CLI. **Behavior change:** `synth` accepts `[stacks...]` (physical names, CDK display paths, wildcards -- the same matcher `diff` uses); a selection of exactly one prints its template; any other selection prints none and lists the SELECTED stack ids, matching `cdk`'s own `Supply a stack id (...)` line; a pattern matching nothing is refused naming what the app does hold. **Selection happens AFTER synthesis and narrows nothing else.** Measured in `aws-cdk@2.1142.0`: `Toolkit.synth` runs `synthAndMeasure(...)` and only then `assembly.selectStacks(...)`, and the context-resolution loop takes no selector -- it reads `assembly.manifest.missing` for the whole assembly. So a stack argument does NOT narrow which `cdk.context.json` lookups run, and a case fences that, because "select by synthesizing less" looks identical in every other test and would diverge from `cdk` silently.
