- **An FSx for Lustre file system's `LustreConfiguration.LogConfiguration` now reaches AWS (issue [#5430](https://github.com/go-to-k/cdkd/issues/5430))** -- `src/provisioning/providers/fsx-filesystem-provider.ts`. `AWS::FSx::FileSystem` `LustreConfiguration.LogConfiguration` (`Level`, `Destination`) was never sent on `CreateFileSystem`, so a file system declared with logging was created without it, silently, and a later change to it was refused as immutable. It is now sent on create, and a change is applied in place through `UpdateFileSystem`, as CloudFormation does ("Update requires: No interruption"). `cdkd drift` reads it back, folding the log-stream ARN FSx reports as `Destination` to the declared log-group ARN; a file system that never enabled logging (AWS reports `Level` `DISABLED`) is not reported as drifted against a state record written before this change. Removing it from the template leaves the live setting in place with the same warning as the other Lustre sub-properties (issue #1160); what CloudFormation does on that removal is unmeasured. The `fsx-lustre` integ asserts the create and the in-place update.
