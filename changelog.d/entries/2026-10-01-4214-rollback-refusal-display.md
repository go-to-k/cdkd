- **`cdkd rollback` messages no longer show a journal or state value on a line that also names a command (issue [#4214](https://github.com/go-to-k/cdkd/issues/4214))** -- `src/deployment/rollback-executor.ts` and `src/cli/commands/rollback.ts`. The rollback refusals and notes showed a resource type, a physical id, a role ARN, a nested stack name or a name-collision diagnosis beside `cdkd deploy`, `cdkd rollback`, `--orphan`, `--revert-failed`, `--role-arn` or `--skip-final-snapshot`, and a `$( )` in the value ran when the line was pasted into zsh. A value that is not a plain identifier is now described on that line instead (for example `a resource type that is not a plain identifier`, `a physical id that is not a plain identifier`); a plain ARN, URL or type prints as before, and a described physical id comes with a pointer to the rollback journal and the state record. The name-holder collision refusal prints its diagnosis on its own `Collision diagnosis:` line, and both collision refusals print the provider's text inside JSON quotes on the `Underlying collision:` line. The per-op `Rollback failed for` line, the unrestorable-baseline, redacted-baseline, region-ambiguous secret and unsupported final-snapshot refusals describe the logical id too (the redacted-baseline one printed it raw). The re-create failure and the Retain survivor warning name the fix in words instead of a command.
