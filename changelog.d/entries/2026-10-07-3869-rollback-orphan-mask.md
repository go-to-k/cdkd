- **`cdkd rollback` and a failed deploy's automatic rollback mask a physical name derived from a secret on a journaled orphan's delete lines and in its events (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/cli/commands/rollback.ts`, `src/deployment/deploy-engine/rollback.ts`. A resource a failed CREATE made before failing is recorded only in the rollback journal. Both rollback paths replay it, and `cdkd rollback --revert-failed` replays every other failed op too. That replay ran under no printing bag, so when the resource was named from a secret, its provider's delete lines and the final-snapshot lines printed the name. Its `ROLLBACK_RESOURCE_FAILED` and skip events were masked with the op's own masker only, which holds no name the resource READ from another record (an access key's `UserName`). Both paths now replay under the printing bag `cdkd destroy` uses for the same resources (#4631), judged from each journal entry, and mask each event's text with the bags bound where it is recorded. An event's `physicalId` field stays exact. Tests: `tests/unit/cli/rollback-orphan-secret-name-3869.test.ts`, `tests/unit/deployment/deploy-engine-rollback-orphan-secret-name-3869.test.ts`; integ `secret-derived-immutable-names` gains steps 6c and 6d, a plain `cdkd rollback` and an automatic rollback of a failed-CREATE ECR repository named from the secret.
