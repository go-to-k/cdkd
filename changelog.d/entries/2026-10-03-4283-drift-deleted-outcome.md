- **`cdkd drift` reports a resource deleted outside cdkd as `deleted` and exits 1, instead of as an uncovered type with exit 0 (issue [#4283](https://github.com/go-to-k/cdkd/issues/4283))** -- `src/types/resource.ts` (new `RESOURCE_NOT_FOUND` sentinel), `src/cli/commands/{drift,state,import}.ts`, `src/deployment/deploy-engine/observed-capture.ts`, `src/provisioning/cloud-control-provider.ts`, every SDK provider that reads state back under `src/provisioning/providers/`, `docs/cli-{drift,state,reference}.md`, the `drift-revert` and `ecs-fargate` integ fixtures. A resource AWS reports gone read as `drift unknown` ("provider does not support drift detection yet") with exit 0, so a CI gate on `cdkd drift` stayed green over a missing cluster, bucket or role. A read now returns `RESOURCE_NOT_FOUND` on AWS's own not-found answer (a not-found error name, an empty describe list for the id, or a terminal status such as ECS `INACTIVE`); access-denied, throttled or message-only answers never do. Drift reports such a resource under a new `deleted` outcome: a `- <id> (<type>) — DELETED outside cdkd` line in the drift block and exit 1. **`--json` shape change:** such a resource moves from `notSupported` to a new `deleted` array. Each stack is now read through its own region's clients, so `--stack-region` / `--all` cannot misread another region's resources as deleted. `--revert` and `--accept` refuse it by name, resolve the other drifted resources, and exit 2; a plain deploy does not recreate it, and the message names the remove-then-restore route. `cdkd state refresh-observed` names such a resource and counts it apart from read failures (exit 2), keeping its baseline; deploy and import baseline captures record nothing for it. An S3 Tables namespace is now checked with `GetNamespace`, so `s3tables:GetNamespace` is needed for drift. Not covered: a type with no reader (a nested stack, an Elastic IP) -- #4447.
