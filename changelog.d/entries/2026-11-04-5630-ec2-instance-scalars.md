- **`AWS::EC2::Instance` with `SourceDestCheck` / `Tenancy` / `PlacementGroupName` / `PrivateIpAddress` / `PropagateTagsToVolumeOnCreation` now deploys on the SDK path (issue [#5630](https://github.com/go-to-k/cdkd/issues/5630))** -- `src/provisioning/providers/ec2-provider.ts`, the `AWS::EC2::Instance` replacement rule, the regenerated coverage map, unit tests and the `ec2-instance` integ fixture. Before this change, a template that set any of these properties sent the whole instance through Cloud Control, which is slower and sticky. `PrivateIpAddress`, `Tenancy` and `PlacementGroupName` are now sent on `RunInstances`. `PropagateTagsToVolumeOnCreation` gives the volumes the instance creates the instance's tags. A declared `SourceDestCheck: false` is set right after the launch. Each update behaves as CloudFormation's did on a measured throwaway stack. `SourceDestCheck` changes in place, and removing it sets it back to `true`. A `Tenancy` change to or from `default`, or removing it, replaces the instance, and so does a change to `PlacementGroupName` or `PrivateIpAddress`. A `Tenancy` the state record lacks (an earlier `--prefer-sdk-route` deploy dropped it) is compared with the instance's live tenancy: nothing happens when they match, and the deploy is refused (`--replace` opts in) when they differ. A `dedicated` <-> `host` change is refused, since CloudFormation's behavior for it is unmeasured. `PropagateTagsToVolumeOnCreation` acts only at launch, so changing or removing it later sends nothing. A malformed value is refused before any AWS call. `cdkd drift` reads back `PlacementGroupName` (new), `SourceDestCheck`, `Tenancy` and `PrivateIpAddress`. `PropagateTagsToVolumeOnCreation` has no EC2 attribute to read, so drift does not check it. Resources already recorded as Cloud Control-provisioned stay on Cloud Control. The other `AWS::EC2::Instance` properties listed on #5630 still route through Cloud Control.
