- **A name collision with this stack's own rollback-retained copy now says so (issue [#5143](https://github.com/go-to-k/cdkd/issues/5143))** -- `src/deployment/deploy-engine/replacement.ts`, `src/deployment/kept-in-history.ts`, `src/deployment/deploy-engine.ts`, `docs/cli-rollback-limitations.md`. When a rolled-back deploy keeps a replacement's new copy because of `UpdateReplacePolicy: Retain` (as CloudFormation does), that copy keeps its fixed name. The next deploy that asks for the name is refused, and that is still the outcome. The refusal used to say only "another existing resource already holds the name ... delete it if it is yours". It now reads the stack's event history. When a rolled-back deploy of this stack kept this resource's replacement under that name, it says so, and says to delete the holder only if it is that copy and no longer needed. The read happens only on that refusal, so a successful deploy reads nothing more.
