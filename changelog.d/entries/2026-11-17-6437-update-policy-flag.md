- **`cdkd deploy --update-policy` honors `UpdatePolicy.AutoScalingScheduledAction`, and a `CreationPolicy` now warns (issue [#6437](https://github.com/go-to-k/cdkd/issues/6437))** -- `src/cli/options.ts`, `src/cli/config-loader.ts`, `src/cli/commands/deploy/{types,stack-deploy}.ts`, `src/deployment/deploy-engine/{options,update-policy,update-in-place,provision}.ts`, `src/deployment/deploy-engine/update/finish.ts`, `src/deployment/deploy-engine/update-in-place/replace-fallback.ts`, `src/types/resource/contexts.ts`, `src/provisioning/providers/asg/update.ts`, `docs/supported-features.md`, `docs/cli-deploy.md`, `docs/cli-deploy-tuning.md`. cdkd silently ignored both. A new flag pair `--update-policy` / `--no-update-policy` (and `cdk.json` `context.cdkd.updatePolicy`) opts in; neither still ignores it, and the v1 release flips that default ([#6443](https://github.com/go-to-k/cdkd/issues/6443)). With the flag, an Auto Scaling group whose `AutoScalingScheduledAction.IgnoreUnmodifiedGroupSizeProperties` is `true` is updated without the `MinSize` / `MaxSize` / `DesiredCapacity` values the template did not change, so a size a scheduled action set survives a deploy (SDK route; a Cloud Control-routed update warns that the policy is not honored). Every other `UpdatePolicy` is still ignored. With neither flag nor key, an update of a resource carrying a policy the flag would honor prints a one-line hint. Creating or replacing a resource that declares a `CreationPolicy` logs a warning that cdkd does not wait for `cfn-signal`; the exit code and `--strict` are unchanged.
