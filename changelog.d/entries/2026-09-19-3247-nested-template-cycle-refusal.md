- **`cdkd deploy` refuses a cyclic nested-template tree before any level of it deploys (issue [#3247](https://github.com/go-to-k/cdkd/issues/3247))** -- `nested-stack-provider.ts`, new `src/utils/nested-template-cycle.ts`, tests, `docs/cli-deploy-safety.md`, `nested-stack-deep` integ arm. `NestedStackProvider` followed `Metadata['aws:asset:path']` from one nested template to the next with no check that the path stayed off its own nesting chain, and every level of that walk is a whole child deploy. A hand-modified or non-CDK assembly whose relative path resolved back onto the chain therefore DEPLOYED the same template again and again -- real resources and a `cdkd/<parent>~<Loop>~<Loop>.../state.json` record per level -- until S3's key-length limit stopped it at roughly 190 levels. The read-only `cdkd diff --recursive` twin was fixed in [#3243](https://github.com/go-to-k/cdkd/pull/3243). `create` and `update` now walk the WHOLE subtree under the nested-stack row before the first child engine is built, and refuse with a non-retryable error naming every hop of the cycle. Up front, because refusing at the first repeat would leave every level above it provisioned. The walk refuses a repeat along one root-to-node chain only, so two sibling rows sharing one template still deploy; directories are `realpath`ed, so a cycle spelled through a symlinked directory (whose joined path never repeats as a string) is caught; a row's `Condition` is not evaluated, matching the diff walk. The same walk reports an absolute `aws:asset:path` at any depth before anything deploys, which was previously refused only on reaching that level. Template-controlled text in this provider's own thrown messages now goes through `displaySafe`. Not covered: the parent stack's own resources can already be in flight when its nested-stack row is dispatched, and are unwound by the ordinary rollback; refusing before the root engine starts needs a call in `deploy.ts`.
