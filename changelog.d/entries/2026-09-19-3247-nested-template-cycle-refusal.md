- **`cdkd deploy` refuses a cyclic nested-template tree before any level of it deploys (issue [#3247](https://github.com/go-to-k/cdkd/issues/3247))** -- `nested-stack-provider.ts`, new `src/utils/nested-template-cycle.ts`, tests, `docs/cli-deploy-safety.md`, `nested-stack-deep` integ arm. `NestedStackProvider` followed `Metadata['aws:asset:path']` from one nested template to the next with no check that the path stayed off its own nesting chain, and each level of that walk is a child deploy. A hand-modified or non-CDK assembly whose relative path resolved back onto the chain therefore DEPLOYED the same template again and again -- real resources and a `cdkd/<parent>~<Loop>~<Loop>.../state.json` record per level -- until S3's key-length limit stopped it at roughly 190 levels. `create` and `update` now walk the WHOLE subtree under the nested-stack row before the first child engine is built, and refuse with a non-retryable error naming every hop of the cycle. The walk refuses a repeat along one root-to-node chain only, so two sibling rows sharing one template still deploy; directories are `realpath`ed, so a cycle spelled through a symlinked directory (whose joined path never repeats as a string) is caught; a row's `Condition` is not evaluated, matching the diff walk. The same walk reports an absolute `aws:asset:path` at any depth before anything deploys. Template-controlled text in this provider's thrown messages, skip reason and log lines now goes through `displaySafe`. A tree nested more than 512 levels deep is refused too (no state key could hold it). Residuals: the parent stack's own resources and assets start before its nested-stack row is reached ([#3449](https://github.com/go-to-k/cdkd/issues/3449)); `cdkd diff --recursive` still misses the symlinked-directory spelling ([#3450](https://github.com/go-to-k/cdkd/issues/3450)); one delete-path message still renders the child stack name raw ([#3277](https://github.com/go-to-k/cdkd/issues/3277)).
