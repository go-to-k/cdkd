- **A nested stack's SSM parameter that cdkd created as `/<name>` before #6272 is re-spelled on the first deploy after the upgrade, even when the nested stack did not change (issue [#6282](https://github.com/go-to-k/cdkd/issues/6282))** -- `src/deployment/nested-ssm-name-check.ts`. Once per stack record, the deploy reads each nested child's record (and the records below a child not yet checked itself); a nested stack whose records hold such a name is updated, so its own deploy re-spells it and updates its `grantRead` policy and environment variables (#6274). The stack record then carries `nestedSsmNamesChecked` (state schema: additive, no version bump), and later deploys read no child record for this. The mark is written only by a successful deploy that read every child; a failed read leaves it unset for the next deploy. A stack with no nested stack reads nothing. `cdkd diff` previews the update (`nestedChildHeal` in `--json`). Tests: `tests/unit/deployment/nested-ssm-name-check-6282.test.ts`, `tests/unit/cli/diff-ssm-slashed-name-heal-6274.test.ts`; integ: `tests/integration/ssm-generated-name-grant`.
