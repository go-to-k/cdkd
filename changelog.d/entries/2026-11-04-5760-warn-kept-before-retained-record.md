- **A redeploy now warns about resources that an older cdkd's destroy kept (issue [#5760](https://github.com/go-to-k/cdkd/issues/5760))** -- `src/deployment/deploy-engine/deploy-flow.ts`, its unit tests, `docs/cli-destroy.md` and the `cross-backend-same-stack-migration` integ fixture. When a stack is destroyed and deployed again, the new deploy does not take back a resource the destroy kept (`DeletionPolicy: Retain`). It creates a new one under a new name and warns once, naming `cdkd import`. That warning read only `retained.json`, and a destroy by a cdkd release older than that file wrote none. So after upgrading, the redeploy created a second resource and said nothing, which left the kept one unmanaged with no notice. When `retained.json` is absent, the first deploy now finds what was kept in the stack's earlier `state.json` versions and its deployment history, and gives the same warning. This read happens on the first deploy only, beside the diff. If it fails, the deploy warns nothing and continues.
