- **`cdkd local start-agentcore` and `cdkd local start-cloudfront` now refuse an asset-manifest path that escapes the assembly, like every other `cdkd local` command (issue [#3597](https://github.com/go-to-k/cdkd/issues/3597))** -- `package.json` (`cdk-local` `^0.149.2` -> `^0.149.3`), `src/local/docker-image-builder.ts`, plus tests and `docs/local-emulation.md`. The bundled engine now contains every manifest path it reads. That covers the Docker build context of every image it builds (the `start-agentcore` container arm, a container Lambda behind a `start-cloudfront` function URL origin, the `start-service` / `start-alb` emulator), the `--watch` soft-reload source, which also refuses an absolute value outside the output directory, the AgentCore code bundle, and the `<stack>.assets.json` lookup. It also warns about BuildKit passthrough paths outside the assembly on each image it builds. `start-cloudfront` serves an absolute `BucketDeployment` source (the `cdk synth --no-staging` shape) only from a folder inside your project, with a warning, and never serves its hidden files. The `local invoke` / `start-api` / `invoke-agentcore` builds now hand the engine the app's output directory, so a `cdk.Stage` image's `../asset.<hash>` still builds. A `source.executable` there is now announced once per command line, not twice. cdkd keeps its own pre-engine check until the engine's refusal wording is display-safe ([cdk-local#758](https://github.com/go-to-k/cdk-local/issues/758), [#3652](https://github.com/go-to-k/cdkd/issues/3652)).
