- **An AgentCore Runtime's JWT authorizer private-endpoint tags keep the keys the template declares (issue [#5433](https://github.com/go-to-k/cdkd/issues/5433))** -- `src/provisioning/providers/agentcore-runtime-provider.ts`, `src/provisioning/providers/agentcore-case-convert.ts`. The PascalCase-to-camelCase conversion that shapes `AWS::BedrockAgentCore::Runtime` properties for the SDK also rewrote the keys of user-keyed maps, so a `AuthorizerConfiguration.CustomJWTAuthorizer.PrivateEndpoint.ManagedVpcResource.Tags` key `Env` (and the same map under `PrivateEndpointOverrides[]`) reached AWS as `env`, and `cdkd drift` read a lower-case key back as upper-case. `CreateAgentRuntime` / `UpdateAgentRuntime` now send those tag keys, and the SDK's `AdvertisedScopeMapping` keys, byte-identical, and the readback returns them unchanged. A runtime deployed before this fix with a capitalised tag key holds the lower-cased key in AWS, so `cdkd drift` now reports it (a real drift the old readback hid). A plain `cdkd deploy` sees no template change and does not re-send it; run `cdkd drift --revert`, which re-sends the template's keys through `UpdateAgentRuntime`, or change any Runtime property and deploy.
