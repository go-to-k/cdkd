- **`cdkd local *` STS failure warnings follow cdk-local's render policy (issue [#2300](https://github.com/go-to-k/cdkd/issues/2300))** -- `src/cli/commands/local-aws-failure.ts` (new), `local-invoke.ts`, `local-run-task.ts`, `local-start-api.ts`, `local-invoke-agentcore.ts`. The default-level warn printed when STS `GetCallerIdentity` (for `${AWS::AccountId}`) or `--assume-role`'s `AssumeRole` failed interpolated the SDK error's raw message, which for a `credential_process` failure carries the failed command line. Each of the eight sites now renders through cdk-local's `describeAwsFailureForWarn`: a modeled STS exception keeps its message (`AccessDenied: User ... is not authorized ...`, one line, capped), and any other failure prints `<Class>[ <code>]; N-character message withheld, logged at debug level under --verbose`, with the full text at `debug` through cdkd's own logger. A `CdkdError` (cdkd's own `AssumeRole(<arn>) returned no usable credentials.`) still prints in full. The role ARN still prints. A matcher on the old warn text needs updating. The `--from-state` state-bucket warns and the `src/local/**` relays: [#4857](https://github.com/go-to-k/cdkd/issues/4857).
