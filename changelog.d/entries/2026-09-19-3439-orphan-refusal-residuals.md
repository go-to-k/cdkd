- **`cdkd orphan`'s `properties` refusal: three arms an operator could not act on (issue [#3439](https://github.com/go-to-k/cdkd/issues/3439))** -- `malformed-resources-bag.ts`, tests. Residuals of [#3363](https://github.com/go-to-k/cdkd/issues/3363), all in the legacy region-less arm. An EMPTY `--state-bucket` printed `State bucket: ''` while the sentence promised that line named the bucket, and disagreed with `recoveryCommandFlags`, which emits no `--state-bucket` for `''`; it is now treated as no bucket, and the sentence sends the operator to `cdkd state info`. Like the empty-stack floor beside it this arm is not reachable through the CLI today -- `orphan.ts` calls `verifyBucketExists()`, whose `HeadBucket` throws on `''` before any refusal renders -- and both are kept for the reason the module already records: a later caller inherits the floor rather than the defect. An empty PREFIX keeps its own arm, because it keys a real key space (the object sits directly under `/`). When a RECOVERY fragment was the inexact value, the command printed `--state-prefix '<prefix>'` with nothing saying it was a hole (`identityWithheld` reads the stack name and region only, and the prefix note is suppressed once a prefix is supplied); a new clause names it and says to fill it from the value passed this run, kept separate from the identity clause because that one points at a listing which does not carry a `--profile`. `cdkd state info` is quoted again in the prose, as every fixed command name in this module is: unquoted, selecting and pasting the parenthetical INVOKED the real CLI. The inspect clause also floors an empty stack name, the floor its two siblings carry, and the prefix note is its own sentence rather than a second parenthetical.
