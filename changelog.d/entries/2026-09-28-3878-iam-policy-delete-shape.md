- **`cdkd destroy` no longer removes an inline policy from principals a malformed `AWS::IAM::Policy` record never named (issue [#3878](https://github.com/go-to-k/cdkd/issues/3878))** -- `src/provisioning/iam-policy-targets.ts` (new, `readRecordedPrincipals`), `src/provisioning/providers/iam-policy-provider.ts` (`create`, `update`, `delete`, `readCurrentState`; `POLICY_MALFORMED_TARGET_SKIP_REASON`), `src/cli/commands/export.ts`, `docs/provider-rules.md`, with unit tests in `tests/unit/provisioning/iam-policy-targets.test.ts`, `tests/unit/provisioning/iam-policy-provider-target-shape.test.ts`, `tests/unit/provisioning/provider-delete-skip-outcome.test.ts` and `tests/unit/cli/export-predelete-listing.test.ts`. The delete cast the record's `Roles` / `Groups` / `Users` to a list and iterated it. A string was walked character by character, so `Roles: "AdminRole"` removed a same-named inline policy from any one-letter role and never from `AdminRole`. An object threw after earlier principals were already detached. A present value that is not a list of IAM names (`[\w+=,.@-]`, at most 128 characters) is now refused before any AWS call. On delete it is reported as a skipped delete that keeps the record. On create and update it is an error, checked on both the desired and the recorded side, since a rollback replays an update with a recorded bag as the desired side and a string used to attach the policy to one-letter roles. On drift it reads as unknown. `null` is still read as absent. `cdkd export`'s IAM::Policy pre-delete reads the lists through the same module, so it now also reads a `null` list as absent rather than refusing it.
