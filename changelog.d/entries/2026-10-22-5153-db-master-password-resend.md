- **Updating a DocDB / RDS DB cluster or an RDS DB instance no longer resets its master password when the password did not change (issue [#5153](https://github.com/go-to-k/cdkd/issues/5153))** -- `src/provisioning/providers/docdb-provider.ts`, `rds-provider.ts`, `tests/unit/provisioning/db-master-password-resend-5153.test.ts`, `tests/integration/docdb-neptune/verify.sh`. Before this change, every update of an `AWS::DocDB::DBCluster`, `AWS::RDS::DBCluster` or `AWS::RDS::DBInstance` that declares `MasterUserPassword` sent the password again, even when only another property changed. AWS treats a supplied password as a credential reset, so a DocDB cluster entered `resetting-master-credentials` after, for example, a `PreferredMaintenanceWindow`-only change. cdkd now sends the password only when the template changed it, as CloudFormation does. The check compares the templates as written, so a secret is compared by its `{{resolve:...}}` reference, never by its value: a secret rotated under a reference the template spells literally is not sent again, as in CloudFormation. On RDS, `ManageMasterUserPassword` and the `MasterUserSecret` KMS key are likewise sent only with a master-credential change. A password fed by a `NoEcho` parameter is still sent on every update, because cdkd keeps no value to compare it with.
