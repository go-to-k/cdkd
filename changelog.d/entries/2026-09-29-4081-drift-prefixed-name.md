- **`cdkd drift` no longer reports a phantom name drift on a named IAM or ELBv2 resource deployed with the legacy stack-name prefix (issue [#4081](https://github.com/go-to-k/cdkd/issues/4081))** -- `src/cli/commands/drift.ts` (`canonicalizeDerivedPatternBName`), `src/provisioning/resource-name.ts` (`derivesPatternBName`), `docs/_contents/cli-drift.md`. A record with no `observedProperties` compares its template name (`my-role`), while a stack deployed with `--prefix-user-supplied-names` holds `MyStack-my-role` on AWS, so an IAM Role / User / Group / InstanceProfile / ManagedPolicy or an ELBv2 LoadBalancer / TargetGroup reported its name as drifted on every run and `cdkd drift` exited 1 with nothing changed. Detection now treats the two as equal when the live name is what cdkd derives from the recorded one under either prefix setting, in the stack's own name scope; a live name neither setting derives (another stack's prefix, a different name) is still reported. The name is then neither accepted nor reverted. Tests: `tests/unit/cli/drift-derived-pattern-b-name.test.ts`, `tests/unit/cli/drift-revert-iam-name-scope.test.ts`; integ `drift-revert` step 6f.
