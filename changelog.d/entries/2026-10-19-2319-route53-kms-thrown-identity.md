- **A failed Route 53 (HostedZone, RecordSet) or KMS (Key, Alias) create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/route53-provider.ts`, `kms-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial (and the account id in a KMS alias ARN), and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (`AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, masked where the operation has a secret masker. This also covers the hosted zone's Accelerated Recovery and tag-removal failures and the record set's `HostedZoneName` lookup failure. A cdkd-authored or transport error keeps its text. The AWS error stays as the `cause`, so an IAM grant that is still propagating, or a zone locked during an Accelerated Recovery transition, is retried as before. An occupied name (a duplicate record, a KMS alias that already exists) still says it already exists, so a create-first replacement still recognises the name collision.
