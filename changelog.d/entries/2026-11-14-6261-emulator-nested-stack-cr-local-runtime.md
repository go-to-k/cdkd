- **Under `--aws-emulator`, a custom resource inside a nested stack runs in the official Lambda runtime image too (issue [#6261](https://github.com/go-to-k/cdkd/issues/6261))** -- `src/local/custom-resource-nested-stacks.ts` (new), `src/local/custom-resource-runtime.ts`, unit tests and docs. Before, the local custom-resource runtime looked for the `ServiceToken` function only in the top-level templates, so a custom resource in a `NestedStack` (`autoDeleteObjects`, `AwsCustomResource`, `BucketDeployment`, `cr.Provider`) was reported as "not found in the local cloud assembly", ran in AWS Emulator's own runtime and failed (`Cannot find module 'zlib'` / `'https'`), rolling the deploy back. Now the nested templates the assembly names are read too, each as the child stack cdkd deploys and destroys (`<parent>~<logicalId>`, at any depth), so the function is matched in the custom resource's own nested template, a `cr.Provider`'s handlers and waiter state machine run locally inside a nested stack as well, and a function of the same logical id in the parent (or another child) is never borrowed. Real AWS deploys are unchanged.
