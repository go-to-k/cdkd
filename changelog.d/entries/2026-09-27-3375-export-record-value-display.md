- **`cdkd export` renders values read from a state record with a visible boundary and a length cap, including in the plan printed above its confirmation (issue [#3375](https://github.com/go-to-k/cdkd/issues/3375); refs [#3617](https://github.com/go-to-k/cdkd/issues/3617), [#3420](https://github.com/go-to-k/cdkd/issues/3420))** -- `src/cli/commands/export.ts`, with unit tests in `tests/unit/cli/export-record-value-display.test.ts` and `tests/unit/cli/export-plan-record-display.test.ts`. A record's `physicalId` and its `properties` / `attributes` values are not validated when read back. Several messages printed them raw or inside cdkd's own `'...'`: the import plan and pre-delete listing, the `✓ deleted` lines, the identifier-overlay warning and refusal, and the refusals behind a blocked resource. A planted newline could forge a plan row, and a planted `'` could add a clause. A plain identifier still prints bare. Any other value now prints as one JSON string with every character outside printable ASCII escaped (`←` prints as `\u2190`), so a legitimate UTF-8 id stays readable and distinct. Values are cut at 2048 characters, with the cut marked. Blocked-resource reasons, and the CloudFormation failure reasons cdkd relays from a failed IMPORT or phase-2 UPDATE changeset, are folded to one line and capped at 4096 characters. The nested-stack asset-path refusals no longer wrap the logical id in cdkd's quotes. The `cdkd state orphan` fallback and the drift-baseline hole now point at `cdkd state list --json` instead of `--long`, which trims the name they were recovering.
