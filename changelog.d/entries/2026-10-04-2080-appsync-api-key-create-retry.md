- **An AppSync API key create that hits a 5xx now reports candidate orphans instead of duplicating silently (issue [#2080](https://github.com/go-to-k/cdkd/issues/2080), Plan C: AppSync `CreateApiKey`; #3978 layer (b) for this create)** -- `src/provisioning/providers/appsync-provider.ts`, `docs/_contents/troubleshooting.md`. `CreateApiKey` mints the key's id and carries no idempotency token, so a 5xx whose request had succeeded left a second key on the API with no state record -- and, when the AWS SDK replayed it inside one call, nothing reported it. The create now goes through the same 5xx-refusing client as `CreateGraphqlApi`; the 5xx reaches cdkd's retry, which first lists the keys on the same API with the same description that this deploy did not record and warns, with a read command (`aws appsync list-api-keys --api-id ... --region ...`) and no delete command: a key has no name and no creation time, so nothing attributes one to this create. A key's id is the credential clients send, so the warning names each candidate only by its last four characters and its expiry. Nothing is adopted or deleted. A throttle, a 4xx or IAM propagation triggers no lookup. The lookup needs `appsync:ListApiKeys`; without it cdkd warns and the create proceeds. A reset connection or timeout after the send is still retried inside the SDK and not reported. Tests: `tests/unit/provisioning/appsync-api-key-create-retry-2080.test.ts`.
