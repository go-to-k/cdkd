- **`AWS::Events::Archive` is created through a new SDK provider (issue [#6578](https://github.com/go-to-k/cdkd/issues/6578))** -- `src/provisioning/providers/eventbridge-archive-provider.ts`, `src/provisioning/resource-name/fallback-rules.ts`, registration, docs and unit tests. An EventBridge archive was created through Cloud Control; under `--aws-emulator` that create reported success while the archive never reached the EventBridge API, so `list-archives` was empty and a replay had nothing to read. cdkd now calls CreateArchive / UpdateArchive / DeleteArchive directly, on real AWS too. An archive without `ArchiveName` gets a generated name of at most 48 characters on either route. A create or update that returns `CREATING` / `UPDATING` waits for it to leave that state (skipped under `--no-wait`), and `CREATE_FAILED` fails the deploy and deletes the archive. A property removed from the template is left at its live value with a warning, as CloudFormation leaves it (measured). `cdkd import` adopts an archive by `ArchiveName` only, since archives carry no tags. An archive already recorded on Cloud Control stays there. The provider-coverage refresh this needed also guards a replacement of `AWS::KinesisAnalyticsV2::Snapshot` and `AWS::WellArchitected::AgentOrganizationalProfile` behind `--force-stateful-recreation` (`src/provisioning/stateful-types.ts`).
