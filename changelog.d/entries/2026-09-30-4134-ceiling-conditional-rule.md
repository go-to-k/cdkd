- **A replacement propagated from an upstream resource now honors the reading resource's own conditional replacement rule when the value it reads moves** (`src/deployment/deploy-engine.ts`, `src/analyzer/replacement-rules.ts`, `src/analyzer/diff-calculator.ts`, go-to-k/cdkd#4134). When an upstream resource is replaced or updated in place, the diff raises a replacement ceiling on each resource that reads it. The deploy engine lowered that ceiling only when the resolved value did not move at all. A value that moved in a way the reader's type classifies as in place still replaced it. For a Lambda `EventInvokeConfig` whose `FunctionName` a custom resource re-spelled from the function's name to its ARN, the replacement Put the config and then deleted it from the same function, leaving none (the #4118 shape). The engine now asks the type's conditional rule about a moved value and lowers the ceiling when the rule answers in place. A property with no conditional rule keeps the ceiling as before. Tests: `tests/unit/deployment/deploy-engine-replacement-ceiling.test.ts`; integ `lambda-event-invoke-config-update` phases 2c/2d.
