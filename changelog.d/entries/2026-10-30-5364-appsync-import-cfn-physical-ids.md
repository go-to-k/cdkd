- **`cdkd import --migrate-from-cloudformation` now records cdkd's physical id for every AppSync resource, so a migrated GraphQL API is found and its schema no longer reads as deleted (issue [#5364](https://github.com/go-to-k/cdkd/issues/5364))** -- `src/provisioning/providers/appsync-provider.ts`, and unit tests. CloudFormation identifies `AWS::AppSync::GraphQLApi`, `DataSource`, `Resolver` and `ApiKey` by ARN and `GraphQLSchema` as `<apiId>GraphQLSchema`; the import recorded those verbatim, so the API was reported not found and skipped, the schema's drift read and readback asked AppSync for an API that does not exist, and the children could be neither updated nor deleted. The import now converts each to the id cdkd records itself (`<apiId>`, `<apiId>|<name>`, `<apiId>|<type>|<field>`, `<apiId>|<keyId>`), refusing an ARN from another region. The same conversion applies to an id passed with `--resource`. A schema record migrated before this change is read and updated through its API id; a data source, resolver or API key record migrated before it still holds the ARN, and re-adopting it with `cdkd import --resource <logicalId>=<arn> --force` records cdkd's id. Integration fixture: `tests/integration/import-migrate-appsync`.
