- **`cdkd deploy --update-policy` honors `CodeDeployLambdaAliasUpdate`: a Lambda alias's version change shifts traffic through a CodeDeploy deployment, and a rollback shifts it back (issue [#6437](https://github.com/go-to-k/cdkd/issues/6437))** -- `src/provisioning/cloud-control/codedeploy-alias-update.ts`, `src/provisioning/cloud-control/update.ts`, `src/deployment/deploy-engine/{update-policy,update/resolve-inputs,execute/provision-node}.ts`, `src/analyzer/dag-builder.ts`, unit tests, `docs/supported-features.md`, `docs/cli-deploy*.md`, `docs/wait-modes.md`. Still opt-in; without the flag every deploy is unchanged and makes no new AWS call. With it, an `AWS::Lambda::Alias` update that changes `FunctionVersion` creates a CodeDeploy deployment (current -> new version, the policy's `BeforeAllowTrafficHook` / `AfterAllowTrafficHook`) on the policy's deployment group and waits for it to succeed before applying the alias's other changes; a failed or stopped deployment fails the update, a deployment still running near the resource timeout or on Ctrl-C is stopped with CodeDeploy's rollback, and a deployment group already running one, an alias that cannot be read, or a deployment configuration longer than the resource timeout allows is refused before anything changes. The policy's `Ref`s are resolved and the alias waits for the resources they name. The deployment is waited for under `--no-wait` too, since the deploy can delete the version the alias serves until the shift ends. The rollback revert shifts the alias back through CodeDeploy from the journaled (resolved) policy, clearing a traffic split a stopped deployment left. New dependency: `@aws-sdk/client-codedeploy`, loaded only when a deployment runs. Integ: `tests/integration/codedeploy-lambda-deployment-group/`.
