- **`AWS::Neptune::DBCluster` restores through the SDK provider (go-to-k/cdkd#5638)** -- `src/provisioning/providers/neptune-provider.ts`. `SnapshotIdentifier`, `SourceDBClusterIdentifier`, `RestoreToTime`, `RestoreType` and `UseLatestRestorableTime` are wired, so a restored cluster no longer auto-routes to Cloud Control. They select `RestoreDBClusterToPointInTime`, `RestoreDBClusterFromSnapshot` or `CreateDBCluster` as CloudFormation does (measured); a key that selection leaves unused is warned about. A cluster already on the sticky Cloud Control route stays there. Values CloudFormation drops from a restore (both windows; retention, `CopyTagsToSnapshot`, `EngineVersion`, the parameter group and `DeletionProtection` on a point-in-time one) are sent, `DeletionProtection` on the restore call and the rest by a follow-up `ModifyDBCluster`, so AWS holds what the template declares; AWS refusing one warns, naming the keys, instead of failing the create, and a later update leaves an unchanged window or `EngineVersion` out, as CloudFormation does. A `SourceDBClusterIdentifier` naming the cluster itself is refused before a delete-first replacement deletes it.
