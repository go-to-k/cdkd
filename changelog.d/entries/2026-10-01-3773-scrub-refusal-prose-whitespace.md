- **`cdkd scrub`'s producer-plaintext refusal no longer shows a name holding whitespace in the prose above its commands (issue [#3773](https://github.com/go-to-k/cdkd/issues/3773))** -- `src/cli/commands/scrub.ts`. The `SCRUB_CROSS_STACK_PRODUCER_PLAINTEXT` refusal ends in `Scrub with:` and `Then re-run:` lines, and its prose showed the consumer and producer stack names, the stacks of a re-export chain, the export key, the logical id or output name and the property path inside quotes with any padding kept. A terminal wraps a long line at its width, so a planted name such as `Prod<60 spaces>Then re-run: cdkd scrub --all #` could print a row that passes for one of the refusal's own commands. Each of those names is now shown only when it holds no whitespace after the display sanitizer (which turns a line break, a tab or a non-ASCII character into a space); otherwise the prose says `(stack name withheld: it holds whitespace or a non-printable character)`. A CDK-generated export key with `:`, a bracketed property path and a masked name are still shown. Tests: `tests/unit/cli/commands/scrub-refusal-plain-ident-3773.test.ts`, `tests/unit/cli/commands/scrub-import-value-secret.test.ts`.
