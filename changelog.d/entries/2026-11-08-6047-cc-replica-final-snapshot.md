- **A Cloud Control-routed RDS read replica under `DeletionPolicy: Snapshot` is now deleted without a final snapshot, as CloudFormation does, instead of refused (issue [#6047](https://github.com/go-to-k/cdkd/issues/6047))** -- `src/provisioning/final-snapshot.ts` (`ccRoutedInstanceTakesNoSnapshot`), `src/provisioning/providers/rds/read-replica.ts`, the three refusal sites (`src/cli/commands/destroy-runner/delete-resource.ts`, `src/deployment/deploy-engine/replacement/delete-context.ts`, `src/deployment/rollback-executor/names.ts`), the `cdkd rollback` plan label in `src/cli/commands/rollback/render.ts`, a new unit file, a Cloud Control replica arm in the `rds-dbinstance-backfill` integ, and `docs/cli-destroy-guards.md` / `docs/cli-rollback.md`. Every read replica deployed before go-to-k/cdkd#5640 routed through Cloud Control and stays there, and CDK's `DatabaseInstanceReadReplica` defaults to `DeletionPolicy: Snapshot`, so `cdkd destroy`, a replacement and a rollback refused it; `--skip-final-snapshot`, the only way out, also dropped the source instance's snapshot. Before refusing a Cloud Control-routed `AWS::RDS::DBInstance`, cdkd now reads the instance (`DescribeDBInstances`, in the stack's region): a live replica of an instance or a cluster, or a live cluster member (the handler's other no-snapshot case), goes to Cloud Control's `DeleteResource`, whose handler takes no snapshot of either. A standalone instance (one promoted outside cdkd included), and one the read cannot confirm, is still refused.
