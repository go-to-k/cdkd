- **`cdkd destroy` and a deploy's template-removal delete skip a state record whose logical id is not a plain identifier, instead of handing it to a provider (issue [#4175](https://github.com/go-to-k/cdkd/issues/4175))** -- `src/cli/commands/destroy-runner.ts`, `src/deployment/deploy-engine-delete.ts`. A `state.resources` key comes from the state file, and the provider delete paths printed it raw in their progress lines and errors, so a key such as `X$(touch OWNED)` ran as shell when such a line was pasted. Both delete callers now check the key before any provider sees it. A key that is not a plain identifier (ASCII letters and digits, plus `-`, `_`, `.` or `~` after the first character) is not deleted: the resource is reported as skipped, its state record is kept, and the run exits as for any other skipped delete. Every line that names it, including the destroy plan listing and the Retain line, describes it as "a logical id that is not a plain identifier". `cdkd state orphan`, which calls no provider, still removes the record; delete the resource by hand first if it still exists. CDK-generated logical ids are unaffected. Tests: `tests/unit/cli/destroy-runner-non-plain-logical-id.test.ts`, `tests/unit/deployment/deploy-engine-delete-non-plain-logical-id.test.ts`.
