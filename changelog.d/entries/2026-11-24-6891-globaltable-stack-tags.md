- **A stack's tags (`StackProps.tags`) now reach every replica of a DynamoDB global table (`AWS::DynamoDB::GlobalTable`), as CloudFormation applies them (issue [#6891](https://github.com/go-to-k/cdkd/issues/6891))** -- `src/provisioning/stack-tags.ts`, `src/provisioning/stack-tag-targets.ts`, `tests/unit/provisioning/stack-tags-globaltable-6891.test.ts`, `tests/integration/tags-propagation/`. A global table has no top-level tag property (its tags live in `Replicas[].Tags`), so the stack-tag merge skipped it silently. Measured on CloudFormation, the stack tags are merged into every replica's `Tags`, a replica declaring none included, and a replica's own value wins on a shared key; cdkd now does the same, so **the next deploy of a stack with stack tags updates its global tables in place to add them**. A table whose `Replicas` (or a replica's `Tags`) is an intrinsic cdkd cannot read is left as declared, with one warning.
