- **`cdkd scrub` no longer reports a stack CLEAN when a dynamic reference failed to RESOLVE** — a deleted SSM parameter, a secret with no `SecretString`, a missing `JSON_KEY` or a non-JSON secret each abandon the whole leaf, because the resolver's token loop stops at the first failing token. A real `{{resolve:secretsmanager:...}}` sitting after it was never fetched and recorded no needle, so a legacy plaintext already in `state.json` survived under `No plaintext secrets found`, exit 0. These are now a counted FINDING rather than a silent `debug` line: the rest of the stack is still scrubbed, each abandoned leaf is warned with the stack that owns it, and the run does not report clean — `--dry-run --fail` exits 1. They deliberately do NOT refuse the stack the way a nameless reference does (#2692): scrub resolves with template defaults and takes no `--parameters`, so an `Fn::Sub` that keeps its raw `${Field}` produces one on a perfectly healthy stack. Issue #3160.
