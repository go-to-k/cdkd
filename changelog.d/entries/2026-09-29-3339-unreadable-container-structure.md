- **`cdkd diff` and `cdkd drift` no longer report a state entry keyed `(resources map)` as if the whole `resources` map were unreadable (issue [#3339](https://github.com/go-to-k/cdkd/issues/3339))** -- `src/cli/commands/{diff-recursive,drift}.ts`, `src/state/malformed-resources-bag.ts`. Both commands carried an unreadable container as a stand-in string beside the dropped entries' logical ids, so a hand-edited key spelled like it produced the identical report. **`--json` shape change (`cdkd diff`):** `unreadable` now holds only the ids of dropped `resources` entries; a new `unreadableContainers` lists `"resources"` / `"orphans"` for a container unreadable as a whole, and a new `unreadableOrphans` lists each dropped rollback-orphan record by `logicalId`, `null` for one with no string id (it was `''`, indistinguishable from an entry keyed `''`). The preview renders a container's name from that field and every id through the quoting renderer, so a planted `(resources map)` prints quoted and keeps the "shown above as a create" sentence. **`cdkd drift`:** an unreadable map is reported under a new `notCompared` cause, `unreadableMap` (exit 2, as before), with its own reason text; a dropped entry keeps `unreadableRecord`. Tests: `tests/unit/cli/diff-unreadable-structure-3339.test.ts`, `tests/unit/cli/drift.test.ts`, and the existing diff suites moved to the new fields.
