- **`AWS::DocDB::DBCluster` restores through the SDK provider (go-to-k/cdkd#5628)** -- `src/provisioning/providers/docdb-provider.ts`. `SnapshotIdentifier`, `SourceDBClusterIdentifier`, `RestoreType`, `RestoreToTime` and `UseLatestRestorableTime` are wired, so a template restoring a cluster is no longer refused pre-flight (the type has no Cloud Control route). They select `RestoreDBClusterFromSnapshot`, `RestoreDBClusterToPointInTime` or `CreateDBCluster` as CloudFormation does (measured), and the shapes CloudFormation refuses are refused before any call: both identifiers, a source with no time or with both times, a `RestoreToTime` with no zone, and `StorageEncrypted: true` with no `KmsKeyId` from an unencrypted source. A restore takes port 27017 when none is declared, as CloudFormation does, not the source's. After a snapshot restore a `ModifyDBCluster` sets the parameter group, retention and windows, as CloudFormation does; values CloudFormation drops (the master password, `ManageMasterUserPassword`, and a point-in-time restore's retention and windows) are sent too, and AWS refusing one warns, naming the keys. A key a create leaves unused, and a source user name or engine the restore keeps, is warned about. A delete-first replacement, or a rollback reversing one, refuses a DocDB or Neptune restore from the cluster itself or one of its automated snapshots before its delete.
