- **A rollback restores an explicitly named IAM / ELBv2 resource under the name it had when the prefix setting changed between deploys (issue [#4024](https://github.com/go-to-k/cdkd/issues/4024))** -- `src/deployment/rollback-executor.ts`, `src/deployment/replacement-name-holder.ts`, with unit tests in `tests/unit/deployment/rollback-recreate-original-name.test.ts` and a new phase in the `rollback-explicit-name-rewrite` integ. `cdkd rollback` and a deploy's automatic rollback replayed under the failed deploy's user-supplied-name prefix setting (#4018), but an earlier deploy under the other setting may have created the resource, so a reverse-replacement re-created an IAM Role / User / Group / InstanceProfile / ManagedPolicy or ELBv2 LoadBalancer / TargetGroup under a physical name it never had (`a` instead of `<stack>-a`), and an in-place revert of a role or managed policy could replace it. The rollback now uses whichever setting turns the declared name into the old physical id (for an ARN, its name segment), for the re-create, the name-holder proof before deleting the new resource, and in-place reverts; when neither does, it keeps the failed deploy's setting and warns. The unproven-holder refusal also no longer says "cdkd cannot show" twice.
