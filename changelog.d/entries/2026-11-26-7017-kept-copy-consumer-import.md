- **`cdkd deploy`: a deploy of the producer alone no longer deletes an old copy a rolled-back consumer still uses (issue [#7017](https://github.com/go-to-k/cdkd/issues/7017))** -- `src/deployment/deploy-engine/consumer-held-superseded.ts`, `src/deployment/deploy-engine/nested-cleanup.ts`, `src/deployment/deploy-engine/deploy-flow/no-change.ts`, `src/types/state/stack-state.ts`. After a run whose consumer failed kept the producer's replaced resources (issue [#7012](https://github.com/go-to-k/cdkd/issues/7012)), a later `cdkd deploy Producer` alone deleted them while the rolled-back consumer still named them. Such kept entries are now saved marked `heldForConsumers`, and a later deploy deletes one only once no stack importing the producer's outputs names its physical id or a recorded attribute (an ARN, a name) in its records; otherwise it keeps the entry and names the stack. A record that cannot be read keeps it too. A deploy carrying no such entry reads nothing more. No schema bump: an older cdkd ignores the mark. Tests: `tests/unit/deployment/consumer-held-superseded-7017.test.ts`, `tests/unit/deployment/consumer-cleanup-hold-7012.test.ts`; integ `cross-stack-replace-consumer-rollback` (step 2b).
