- **A PUBLIC `{{resolve:ssm:...}}` reference inside a longer value now keeps the value AWS holds in the drift baseline written by `cdkd state refresh-observed`, `cdkd import` and `cdkd drift --accept` / `--revert` (issue [#2036](https://github.com/go-to-k/cdkd/issues/2036))** -- `src/deployment/public-ssm-proof.ts` (new), `src/deployment/secret-redaction/{mask-only,redact-path,readback-certification}.ts`, `src/deployment/intrinsic-resolver/dynamic-refs.ts`, `src/cli/commands/{state,import}.ts`. With no secrets map these paths could not tell a public `String` parameter from a `SecureString`, so such a leaf always took its `{{resolve:...}}` expression and the baseline disagreed with AWS. A leaf now keeps the readback only when EVERY reference in it is a plain `ssm` one that this record's own pass PROVED public, AND the readback is exactly the source with each proven CURRENT value in place, so a type read today never vouches for a value resolved earlier or in another region. The proof is filed per record, never for the whole process (the cross-region disclosure PR #2415 withdrew). `cdkd drift` gets it from its own resolution of the record. `cdkd state refresh-observed` and `cdkd import` ask `ssm:GetParameter` with `WithDecryption: false` in the stack's region; a nested child whose ancestors' reads are unknown, and a reference import resolved as a secret, get none. Any other answer, an error or a missing permission keeps the expression, as before. The deploy path's unchanged-resource write is unchanged (#2425).
