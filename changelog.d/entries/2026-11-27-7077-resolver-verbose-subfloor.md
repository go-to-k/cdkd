- **`--verbose` resolver lines mask a 1-3 character piece of a value that carries a secret, in `cdkd diff` and `cdkd deploy` (issue [#7077](https://github.com/go-to-k/cdkd/issues/7077))** -- `src/deployment/intrinsic-resolver/display-taint.ts`, `src/deployment/intrinsic-resolver/masking-display.ts`. A nested child's parameter mixing a secret reference with other text (`{"Fn::Join": ["", [{"Ref": "Sep"}, "/", "{{resolve:ssm-secure:/a}}"]]}`), whose other text is a short secret's plaintext, printed that text on the resolver's own debug lines (`Resolved Fn::Select: index 0 resolved to "q7"`, `Fn::Join`, `Fn::FindInMap`, `Fn::Base64`, a grandchild's `Parameter Y: using user-provided value q7`), because the value scan skips a needle under 4 characters. Every operand and result a resolver log line prints now goes through one render, `logOperand`, which prints `***` when the call being resolved reads a parameter with such a provenance: one mixing an unresolved secret reference (`cdkd diff`), one the parent marked as holding a sub-floor secret (`cdkd deploy`), and one whose value is a recorded sub-floor secret (a grandchild fed the piece). Names (logical ids, attributes, conditions) stay readable, and nothing resolved or compared changes. A new resolver log line printing a value any other way fails `resolver-log-operand-population.test.ts`.
