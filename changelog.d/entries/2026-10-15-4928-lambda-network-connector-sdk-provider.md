- **`AWS::Lambda::NetworkConnector` now deploys through an SDK provider; deleting a connector takes about 3 s instead of about 13 s** -- new `src/provisioning/providers/lambda-network-connector-provider.ts`, `src/provisioning/provider-registry.ts`, `src/utils/aws-clients.ts`, new dependency `@aws-sdk/client-lambda-core`. A connector is the VPC egress path Lambda Web Functions and MicroVM images share. Its create still waits until the connector is `ACTIVE` (about 4 minutes, AWS's own provisioning), which cdkd now notices within a second rather than through Cloud Control's report and poll backoff; its delete settles in about 3 s, where Cloud Control took 12.6 s (us-east-1). A configuration change goes through `UpdateNetworkConnector` and waits for the new version, a tags-only change through Lambda's tagging API. Removing `OperatorRole` from a deployed connector's template, or declaring a non-string one, now fails the deploy before any change, naming the cause: the update would send no role, leaving the old one attached. A connector created by an earlier cdkd, recorded on Cloud Control, moves to the SDK provider on the next deploy that changes it. `cdkd drift` and `cdkd import` (by ARN or name) are supported. Issue [#4928](https://github.com/go-to-k/cdkd/issues/4928).
