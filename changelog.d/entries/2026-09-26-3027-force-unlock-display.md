- **`cdkd force-unlock` renders the stack name, the region and S3's error text on one line in its progress lines and its failure summary (issue [#3027](https://github.com/go-to-k/cdkd/issues/3027))** -- `src/cli/commands/force-unlock.ts`, and unit tests in `tests/unit/cli/force-unlock-display.test.ts`. Without `--stack-region`, the command unlocks every region `listStacks()` finds for the name, and it printed each region -- an S3 key segment anyone able to write the state bucket chooses -- raw in `Force-unlocking stack:`, `Lock released for stack:`, `No lock found for stack:` and `Failed to unlock stack`, and again as a row of the multi-line `Failed to release N lock(s):` summary. A newline in the region, the typed name or S3's error text (which echoes the lock key) could forge a line of that output or a row of the summary. The name and region now render through the identifier guard (a plain value prints unchanged, anything else flattened inside double quotes), and the error text through the ASCII allowlist; the absent-lock check still reads the raw text.
