- **An `AWS::Lambda::EventSourceMapping` no longer drops a `Queues` / `Topics` change, a zero `MaximumBatchingWindowInSeconds`, or a tag without a `Value` (issue [#5356](https://github.com/go-to-k/cdkd/issues/5356)).** `UpdateEventSourceMapping` takes neither `Queues` nor `Topics`, so a change to either deployed as a success while AWS kept the old queue or topic. CloudFormation refuses that change, and cdkd now refuses it too before any AWS call (`--replace` deletes and recreates the mapping instead). A declared `MaximumBatchingWindowInSeconds: 0` was left off the create request, so a Kafka, MQ or DocumentDB mapping got AWS's 500 ms default; it is now sent, as CloudFormation sends it. A tag with a `Key` but no `Value`, which the CloudFormation schema allows, was refused; create and update now apply it with an empty value.
