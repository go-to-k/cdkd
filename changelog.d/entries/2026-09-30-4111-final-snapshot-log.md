- **A `DeletionPolicy: Snapshot` delete no longer logs the final-snapshot identifier or the physical id it is built from (issue [#4111](https://github.com/go-to-k/cdkd/issues/4111))** -- `src/provisioning/providers/{rds,docdb,neptune,elasticache}-provider.ts`, `docs/cli-destroy.md`. Deleting an `AWS::RDS::DBInstance`, `AWS::RDS::DBCluster`, `AWS::DocDB::DBCluster`, `AWS::Neptune::DBCluster` or `AWS::ElastiCache::CacheCluster` under a Snapshot policy (in `cdkd destroy`, a rollback or a deploy's delete) printed `with final snapshot <physicalId>-final-<timestamp>` at INFO, so a physical id taken from a `{{resolve:secretsmanager:...}}` value reached default-verbosity output in a lowercased spelling. The line now reads `Deleting <type> <logicalId> with a final snapshot (DeletionPolicy: Snapshot)`, and the debug lines of those five delete paths (the entry line, the `--remove-protection` flip failure, the already-gone skip) name the logical id instead of the physical id. The snapshot is still taken under the same identifier; `docs/cli-destroy.md` shows how to find it by its `<physicalId>-final-` prefix. A masker threaded through the delete context, which the remaining provider lines need, stays with issue [#3869](https://github.com/go-to-k/cdkd/issues/3869). Tests: `tests/unit/provisioning/final-snapshot-delete-log-4111.test.ts`.
