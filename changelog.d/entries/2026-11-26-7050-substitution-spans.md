- **A secret of any length referenced inside `Fn::Join` / `Fn::Sub` is now stored as its `{{resolve:...}}` reference even when a parameter or attribute beside it holds the same text (issue [#7050](https://github.com/go-to-k/cdkd/issues/7050))** -- `src/deployment/secret-redaction/redact-path/substitution-spans.ts` (new), `redact-path/literal-rendering.ts`, `redact-path.ts`, `nested-stack/record-parameter-expressions.ts`, `src/deployment/intrinsic-resolver/parameter-secrets.ts`. A 1-3 character secret (`pg`) beside a value-bearing part holding its text (`Fn::Join ['', [<username reference>, {Ref: Alias}]]` with `Alias` = `pg`) was stored as `pgpg` in plaintext: the redaction searched the value, and no search can tell which `pg` the reference produced. The leaf is now positioned from the resolver's own record of where it substituted each reference, so the reference's plaintext never stays. Text a parameter or an attribute supplies beside it is kept, except the text of a secret the same leaf references, which is written as that reference at any length. That last part is a redaction artifact `cdkd diff` shows as a change, but never a plaintext. A nested stack row's `Parameters` take the same spelling, and so does the child resource that reads the parameter. Tests: `tests/unit/deployment/secret-redaction-substitution-spans-invariant.test.ts` (generated), `secret-redaction-substitution-spans-nested-7050.test.ts`.
