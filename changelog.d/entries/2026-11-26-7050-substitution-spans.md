- **A secret referenced inside an intrinsic is never stored in plaintext beside a parameter, an attribute or another value holding its text: the leaf keeps each reference where the resolver substituted it, or is stored masked (issues [#7050](https://github.com/go-to-k/cdkd/issues/7050), [#7059](https://github.com/go-to-k/cdkd/issues/7059))** -- `src/deployment/secret-redaction/redact-path/substitution-spans.ts` (new), `consumed-references.ts` (new), `redact-path/literal-rendering.ts`, `redact-path.ts`, `nested-stack/*`, `src/deployment/intrinsic-function-resolver.ts`, `src/analyzer/diff-calculator/redaction-masks.ts` (new). A 1-3 character secret (`pg`) beside a value holding the same text was stored as `pgpg`. A reference reached through `Fn::Select` / `Fn::Split` was stored in plaintext too, and so was a nested child's read of such a parameter. Now each reference is written at the span the resolver recorded substituting it. A leaf the resolver cannot account for that way is stored as `***`: a reference consumed without a recorded span, or a parameter or attribute value holding a secret's text. A nested child's read of such a parameter is masked as well. An unchanged template does not plan a masked leaf as a change (the masked-property fingerprints prove it unchanged). A nested child's masked leaf reading a parameter the parent passed as a secret is compared through keyed KMS MACs of its value (as for `NoEcho`): an equal MAC plans no change; a moved value, or no MAC (an older record, no KMS key), plans the change. A masked leaf blocks what any masked value blocks (a rollback replay of that resource, an export of that record).
