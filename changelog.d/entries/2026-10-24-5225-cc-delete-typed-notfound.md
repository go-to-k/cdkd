- **A failed Cloud Control delete is read as "already deleted" only on a typed not-found (issue [#5225](https://github.com/go-to-k/cdkd/issues/5225))** -- `src/provisioning/cloud-control-provider.ts`, `tests/unit/provisioning/cloud-control-provider.test.ts`, a new unit file. Before, the delete's already-deleted check also matched `does not exist`, `not found` or `NotFound` anywhere in the error message. So a live resource's state record was dropped when `DeleteResource` failed with `TypeNotFoundException`, when a FAILED delete's handler message named a missing dependency ("subnet ... not found"), or when the logical id itself spelled `NotFound`. Now only the handler's `ErrorCode: NotFound`, `DeleteResource`'s `ResourceNotFoundException`, and `InvalidVolume.NotFound` on the EBS volume path count. A failure that is kept and whose message still holds one of those phrases is now marked non-retryable. The engine and the destroy runner check that mark before their own message match, so they no longer drop the record either. A failure that is transient for another reason, such as a throttle, is left unmarked and keeps its retry.
