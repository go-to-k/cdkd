- **A replacement that deleted the old resource first is no longer abandoned half-way when another resource of the same deploy fails (issue [#5118](https://github.com/go-to-k/cdkd/issues/5118))** -- `src/deployment/deploy-engine.ts`, `src/deployment/deploy-engine/{replacement,update-replace,update-in-place,deploy-flow}.ts`. `cdkd deploy --replace` (and `--recreate-via-*`, an update the provisioning layer rejects, a resource that went with its re-created parent) can delete a resource first and re-create it under the same name. When the re-create met the service's late release of that name (DynamoDB's `Table already exists` while the old table is still deleting) or a throttle, it retries -- but a failure of any other resource in the same deploy stopped that retry, leaving the stack with neither the old nor the new resource while state still recorded it. Only the user's interrupt (Ctrl+C) stops that retry now, including a Ctrl+C pressed after another resource has already failed; a sibling's failure lets it finish. Ctrl+C now also stops the automatic rollback, which keeps its journal so `cdkd rollback` finishes it.
