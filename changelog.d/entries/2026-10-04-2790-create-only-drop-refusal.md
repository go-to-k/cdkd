- **`cdkd deploy` no longer reports success for a create-only property it never wrote once `--prefer-sdk-route` is removed (issue [#2790](https://github.com/go-to-k/cdkd/issues/2790))** -- `src/provisioning/property-coverage.ts`, `src/types/state.ts`, `src/analyzer/diff-calculator.ts`, `src/cli/commands/diff-recursive.ts`, `src/deployment/deploy-engine/update.ts`, `src/provisioning/provider-registry.ts`. A create-only silent drop accepted with `--prefer-sdk-route` (or `--allow-unsupported-properties`) stays in the state record, so the deploy that dropped the flag compared the same value on both sides, called the resource unchanged, and the property never reached AWS. The record now names such a key in a new optional `acceptedCreateOnlyDrops` field (no state schema bump), and the comparison keeps a named key only while the deploy still accepts the drop; a key the record does not name (an imported resource, or a record an older cdkd wrote, including one created with the flag) keeps the previous behaviour, where `--recreate-via-cc-api` applies it. Without it the change is a replacement, and the deploy refuses it (`CREATE_ONLY_DROP_NEEDS_REPLACEMENT`) before deleting anything, naming the property, `--recreate-via-cc-api <LogicalId>` or `--replace` to replace the resource and apply it, and the `--prefer-sdk-route` entries that keep dropping it. `cdkd diff` previews the flag-less deploy, so it shows the replacement and warns that the deploy refuses it, without changing its exit code. Tests: `tests/unit/provisioning/property-coverage.runtime.test.ts`, `tests/unit/analyzer/diff-calculator-unwritten-create-only.test.ts`, `tests/unit/deployment/deploy-engine-unwritten-create-only.test.ts`; integ arm (phases 7-10) in `tests/integration/sdk-to-cc-autoroute/verify.sh`.
