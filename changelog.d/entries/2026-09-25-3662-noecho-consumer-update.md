- **A consumer of a `NoEcho` custom-resource value is updated when the handler returns a new value (issue [#3662](https://github.com/go-to-k/cdkd/issues/3662))** -- `DeployEngine`'s UPDATE arm, `carriesFreshNoEchoValue` in `src/deployment/secret-redaction.ts`, `DiffCalculator.promoteInPlaceAttributeDependents`, unit tests in `tests/unit/deployment/` and `tests/unit/analyzer/`, and the `custom-resource-noecho-nested` fixture, which drops its `Description` workarounds and gains a phase. The post-resolution no-change check compared the redacted bag with the record, and a `NoEcho` value redacts to `***` on both sides, so a re-minted token was skipped: the deploy exited 0 and the live resource kept the old value. A resolved bag carrying a `NoEcho` value supplied in this deploy no longer takes that skip. An in-place update of a custom resource now promotes every reader of its attributes (its handler's `Data`, which no template property names), so a same-stack reader gets the new value too; the engine still skips a reader whose value did not move. A dependent that reads a persisted `***` is no longer withheld from the diff's speculative promotions (a nested stack's `Outputs.<Key>` reader, later fixpoint rounds): the engine now refuses a redacted read only after the no-change skip, so a reader whose bag equals its record sends nothing instead of failing the deploy. A promoted reader whose other reads moved while its masked value was not re-minted is refused, where it used to be left stale. A promoted reader's replacement is decided on its resolved value: a create-only property whose value did not move no longer replaces the reader when another property changes in the same deploy. A reader recorded as `***` by an earlier cdkd, which used to be refused, is now skipped silently when nothing else moved; force its custom resource to update to supply the value.
