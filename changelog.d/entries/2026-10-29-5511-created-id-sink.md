- **A CREATE that outlives its per-resource deadline after its create call returned is journaled for `--revert-failed` (issue [#5511](https://github.com/go-to-k/cdkd/issues/5511))** -- `src/provisioning/created-resource-sink.ts` (new), `src/deployment/deploy-engine/execute.ts`, the SDK providers that mark `markCreatedBeforeFailure`, `docs/provider-rules.md`. Before this change, the proof that a failed create had made its resource travelled only on the provider's thrown error. When the per-resource deadline fired first (a post-create wait running long), that error was dropped, the failed-CREATE journal recorded no id, and the resource was an orphan that `cdkd rollback --revert-failed` could not see. Now a provider reports the physical id to an engine-owned sink the moment its create call returns, and a failed CREATE (or replacement) whose deadline fired journals it.
