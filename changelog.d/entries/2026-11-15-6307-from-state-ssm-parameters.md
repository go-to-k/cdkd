- **`--from-state` now resolves an environment variable that `Ref`s an SSM-typed CloudFormation parameter (`ssm.StringParameter.valueForStringParameter`), instead of dropping it (issue [#6307](https://github.com/go-to-k/cdkd/issues/6307))** -- `src/local/state-ssm-parameters.ts` (new), `src/local/{s3-local-state-provider,mixed-mode-state,local-state-provider}.ts`, `src/cli/commands/local-state-source.ts`, `src/cli/commands/local-invoke/command.ts`, `src/cli/commands/local-start-api/{state,container-spec}.ts`, `src/cli/commands/local-run-task/{image-context,command}.ts`, `src/local/ecs-task-resolver/container.ts`, `docs/local-emulation-value-resolution.md`, `docs/local-emulation.md`, `docs/aws-emulator.md`. state.json records no parameter values and only cdk-local's `--from-cfn-stack` provider read SSM, so `cdkd local invoke` / `start-api` / `run-task` and the engine `start-*` commands ran the handler without a value `cdkd deploy` had resolved. The `--from-state` provider now reads each referenced SSM-typed parameter with SSM `GetParameters` in the stack's region (CDK's Rules-only `BootstrapVersion` is skipped, as `cdkd deploy` skips it), and `local invoke`, `local start-api` and `local run-task` pass the values into their substitution context, which also fixes the same drop under `--from-cfn-stack` on those three. The read runs as the caller, never a `--role-arn` role, and is routed like a `{{resolve:ssm:...}}` lookup: to AWS Emulator under `--aws-emulator`, and in mixed mode to real AWS only when the workload excepts `SSM`, never because another service is excepted. A parameter SSM does not return keeps the existing warn-and-drop.
