- **`cdkd deploy`, `cdkd destroy`, `cdkd state destroy` and `cdkd rollback` refuse a stack the state bucket also records under another `--state-prefix` (issue [#4705](https://github.com/go-to-k/cdkd/issues/4705))** -- `src/state/cross-prefix-stack-scan.ts`, `src/state/s3-state-backend.ts`, `src/cli/commands/{deploy,cross-prefix-gate,destroy-runner,destroy,state,rollback}.ts`. A stack name is one deployment per account and region, as in CloudFormation: cdkd-generated names derive from the stack name and logical id, so a second deployment of the same stack name under another prefix was handed the first one's SQS queue and log group, and its failed deploy's rollback deleted the queue. A stack's first deploy under a prefix now checks the bucket's other top-level prefixes (started after synth, overlapping asset publishing and the lock; a stack the prefix already records lists nothing) and refuses before any provider call, naming the other prefix and the remedies. Destroy, state destroy and rollback refuse the same pair and point at `cdkd state orphan`. Only a record that can own a resource blocks (resources, orphans, or a journal with a completed operation); a failed first deploy's empty leftover is named in a note instead. A 403 on the check warns and continues. Not detected, and documented as unsupported: another bucket, and a prefix containing `/`. Docs: `docs/state-store.md`, `docs/concepts.md`, `docs/troubleshooting.md`.
