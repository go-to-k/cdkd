- **Removing `EnableDnsHostnames` or `EnableDnsSupport` from an `AWS::EC2::VPC` now resets it to the VPC default, matching CloudFormation (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- A real CloudFormation A/B showed CloudFormation resets a removed attribute: DNS hostnames back to off and DNS support back to on. `ModifyVpcAttribute` changes only the attribute it is sent, so cdkd used to leave the old value live (for example, DNS support kept off after the template stopped declaring it). cdkd now sends the default for each removed attribute, and sends nothing when the removed value already was the default. `cdkd drift --revert` writes no such reset. Changed: `src/provisioning/providers/ec2-provider.ts`, `tests/unit/provisioning/ec2-vpc-dns-removal-1160.test.ts`, `tests/integration/ec2-vpc/`.
