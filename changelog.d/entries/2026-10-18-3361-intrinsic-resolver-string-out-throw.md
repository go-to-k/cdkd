- **A failure that cannot be converted to text no longer turns a best-effort fallback of the intrinsic-function resolver into a hard failure** (`src/deployment/intrinsic-resolver/*`, go-to-k/cdkd#3361). These handlers built their message with `x instanceof Error ? x.message : String(x)`, and `String()` throws for a null-prototype object, so the handler itself threw: a failed CloudFormation `ListExports` / `DescribeStacks` fallback stopped `Fn::ImportValue` / `Fn::GetStackOutput` with a `TypeError` instead of the not-found error; an exports-index lookup failure skipped the state scan, a failed index write-through became an unhandled rejection, and one unreadable producer state stopped the scan instead of being skipped; a condition whose evaluation failed rejected the deploy instead of being assumed false; a failed `Ipv6CidrBlocks` / launch-template version read lost its `[]` / `$Latest` fallback; an `Fn::Sub` variable that failed to resolve stopped the deploy instead of keeping its placeholder, an abandoned dynamic reference stopped it instead of being recorded and reported, and a failed pinned recorded-reference read threw instead of answering `failed`; and `Fn::GetAZs`, the `Fn::GetAtt` refusal for a constructed attribute whose live read failed (`DescribeSecurityGroups`, `DescribeInstances`, `GetNamespace` or the provider read, via `describeFailureObserved`) and the lookup-role denial message replaced the failure they describe with the converter's `TypeError`. Each now goes through `describeAwsFailure(x).detail` (or `safeStringify(x)` for the bare form), byte-identical whenever the value converts (so every message's secret masking reads exactly the text it read before) and a placeholder only when it cannot. Tests: `tests/unit/deployment/intrinsic-resolver-string-outthrow-3361.test.ts`.
