- **A failed Secrets Manager secret, EventBridge bus delete or `DeletionPolicy: Snapshot` final snapshot no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/{secretsmanager-secret,eventbridge-bus}-provider.ts` and `src/provisioning/final-snapshot.ts` unit cases. These failure messages quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker where one is in scope. The AWS error is still the wrap's `cause`, so a grant that is still propagating or a throttle is retried as before, a taken Secrets Manager secret name is still stated as "already exists", and a taken EventBridge bus name now is too. A CodeCommit repository's identity-check failure now masks a secret spelled in the error class. A delete failure whose class is another resource's not-found (for example `KMSNotFoundException`) no longer reads as "already deleted" for the API Gateway authorizer, resource, deployment, stage and method, the five API Gateway V2 types, the Secrets Manager secret, the log group, the IAM role, managed policy, instance profile and access key, the EventBridge bus, the DLM lifecycle policy and the ACM certificate: the state record is kept. An "already exists" from a post-create step of an API Gateway stage or method, IAM role, managed policy, instance profile or access key, or EventBridge bus is no longer restated as the resource's own. The partial-create cleanup warnings of the API Gateway stage and method, ECS service, log group, IAM role, managed policy and instance profile, CodeCommit repository and ACM certificate name an AWS failure by its class too.
