- **`cdkd destroy --remove-protection` / `cdkd state destroy --remove-protection` now clear a deletion-protected resource that only the rollback journal records (issue [#4678](https://github.com/go-to-k/cdkd/issues/4678))** -- `src/cli/commands/destroy-runner.ts`, `src/deployment/rollback-executor.ts`, `src/deployment/rollback-executor/types.ts`. A failed CREATE whose resource carried deletion or termination protection (an EC2 instance with `DisableApiTermination`, a load balancer with `deletion_protection.enabled`) left it journaled. The destroy's sweep of the journal dropped the flag, so AWS refused the delete, the entry stayed and every destroy exited non-zero until the user cleared the protection by hand. The flag now reaches that delete (`RollbackExecutorContext.removeProtection`), run as one final attempt so a failed delete puts the protection back, and the `--remove-protection` prompt counts such a resource when its journaled properties turn protection on. A deploy's automatic rollback, a successful deploy's settle and `cdkd rollback` still never turn protection off; `cdkd rollback --remove-protection` remains open on #4678. Tests: `tests/unit/deployment/journaled-orphan-remove-protection-4678.test.ts`, `tests/unit/cli/destroy-runner-journaled-orphan-remove-protection-4678.test.ts`; integ `remove-protection-journaled-orphan`.
