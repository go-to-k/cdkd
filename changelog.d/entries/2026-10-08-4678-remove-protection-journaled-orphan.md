- **`--remove-protection` now clears a deletion-protected resource that only the rollback journal records, on `cdkd destroy` / `cdkd state destroy` and, new, on `cdkd rollback` (issue [#4678](https://github.com/go-to-k/cdkd/issues/4678))** -- `src/cli/commands/{destroy-runner,rollback}.ts`, `src/deployment/rollback-executor.ts`, `src/deployment/rollback-executor/types.ts`. A failed CREATE whose resource carried deletion or termination protection (an EC2 instance with `DisableApiTermination`, a load balancer with `deletion_protection.enabled`) left it journaled; destroy dropped the flag on the way to the journal's delete and `cdkd rollback` had none, so AWS refused the delete and every run exited non-zero until the user cleared the protection by hand. The flag now reaches that delete (`RollbackExecutorContext.removeProtection`, plus `--revert-failed`'s delete of a state-recorded failed CREATE), as one final attempt so a failed delete puts the protection back. A journaled orphan gets it only when proven to be the resource its CREATE made (a type whose id AWS never reuses, or a live identity equal to the journaled one) and no other stack's state record holds it now; otherwise the protection stays, with a warning when the attempt had turned it on. The destroy prompt counts such a resource. A deploy's automatic rollback and a successful deploy's settle still never turn protection off. Tests: `tests/unit/deployment/journaled-orphan-remove-protection-4678.test.ts`, `tests/unit/cli/{destroy-runner-journaled-orphan,rollback}-remove-protection-4678.test.ts`; integ `remove-protection-journaled-orphan`.
