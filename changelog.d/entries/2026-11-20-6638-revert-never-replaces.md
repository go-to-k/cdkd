- **`cdkd drift --revert` never replaces a resource: it refuses where it used to delete and re-create an SNS subscription, ACM certificate, security group ingress rule, Lambda permission, API Gateway Resource or EC2 Route (issue [#6638](https://github.com/go-to-k/cdkd/issues/6638))** -- new `src/provisioning/revert-no-replace.ts`, `src/provisioning/providers/sns-subscription-provider.ts`, `acm-certificate/update.ts`, `ec2/sg-ingress-update.ts`, `ec2/dispatch.ts`, `lambda-permission-provider.ts`, `apigateway/resource-deployment.ts`, `apigateway/core.ts`, `apigateway-provider.ts`, `ec2/route.ts`, `iam-policy/update.ts`, `src/cli/commands/drift/revert-apply.ts`, and the `sns-subscription-filter`, `recreate-parent-child-permission` and `apigw-restapi-spec` integ fixtures. A revert those providers could reach only by re-creating the resource (FilterPolicy and FilterPolicyScope drifted together, a pending subscription, a changed certificate name, a rule whose identity differs from its record, any permission change, a renamed path part, a route whose bag names another route) used to run it: a new SubscriptionArn, certificate ARN or `sgr-` id, lost messages, a Resource's methods deleted with it. Each now refuses before any AWS call; the resource is reported `could not revert` and the run exits 2 pointing at `cdkd deploy --replace`. The DomainName ACM echoes among the SubjectAlternativeNames no longer reads as a change on a revert, so a tag revert of such a certificate is applied in place. A deploy is unchanged. A revert whose provider still answers `wasReplaced` or another physical id is a failure naming both ids, never reverted; state records what AWS then holds. An IAM policy rename is refused the same way. A legacy `policyName:roleName` IAM policy record, and a Route 53 record set recorded under its bare name, keep their ids on a revert (`iam-policy/update.ts`, `route53/record-set.ts`).
