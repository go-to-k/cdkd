- **An `AWS::EC2::VPC` `InstanceTenancy` change is now applied as CloudFormation applies it (issue [#5449](https://github.com/go-to-k/cdkd/issues/5449))** -- `src/provisioning/providers/ec2-provider.ts`, `src/analyzer/replacement-rules.ts`. The VPC update never sent `InstanceTenancy`, so a change reported success while AWS kept the old tenancy. Measured on a CloudFormation stack: `dedicated` -> `default`, or removing the property from a dedicated VPC, changes the same VPC in place, and cdkd now sends `ModifyVpcTenancy` for it; `default` -> `dedicated` creates a new VPC, and cdkd now replaces it too (a conditional replacement rule; `cdkd drift --revert`, which cannot replace, refuses that direction). An `AWS::EC2::EIP` `Domain` or `PublicIpv4Pool` change is unchanged: CloudFormation also keeps the same address without changing it. The `ec2-vpc` integ fixture changes the tenancy of two VPCs in its removal phase.
