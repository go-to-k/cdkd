- **Rolling back a same-deploy inline policy swap or hand-off no longer removes the name another revert has just put back** (`src/deployment/inline-policy-claims.ts`, `src/deployment/rollback-executor.ts`, `src/provisioning/providers/iam-role-provider.ts`, `src/provisioning/providers/iam-user-group-provider.ts`, go-to-k/cdkd#4225). An `AWS::IAM::Policy` rename is journaled with a new physical id, so a rollback reverses it by re-creating the old policy and deleting the new one. When two policies swapped names on one role, the second reversal's delete removed the name the first one had re-created, and the role ended up with only one of the two policies. When a policy had renamed away from a name the role's own `Policies` took, the role's revert removed the name the policy's reversal had put back. Each rollback removal now asks, as a deploy's has since go-to-k/cdkd#4156, whether another revert of the same rollback has already put that name on that principal, reading what that revert recorded, and keeps the name when it has. This covers the rollback's deletes and updates of an `AWS::IAM::Policy` (a reversed rename or re-adopted replacement, an in-place revert, a rolled-back create, `--revert-failed`) and a role, group or user revert dropping a `Policies` entry. `cdkd rollback` shares one record across failed ops, completed ops and segments. A revert that has not run, failed, came back partial or went through Cloud Control counts for nothing, and neither does one whose record a later op replaced, so the removal proceeds. Rolling back a created policy that took an old policy's name still removes the old policy's grant (go-to-k/cdkd#4408).
