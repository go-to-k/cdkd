- **`AWS::EMR::InstanceFleetConfig` now records `InstanceFleetId` as well as `Id` in its attributes (issue [#4770](https://github.com/go-to-k/cdkd/issues/4770))** -- `src/provisioning/providers/emr-instance-fleet-config-provider.ts`, plus tests. The CFn schema renamed the read-only attribute from `Id` to `InstanceFleetId` ([#4769](https://github.com/go-to-k/cdkd/pull/4769)). Before this change, a template reading the new name got its value only through the physical-ID fallback, with a warning. It was refused under `--strict-getatt`, and `cdkd orphan` could not rewrite it. An aws-cdk-lib regenerated from that schema emits the new name as `attrInstanceFleetId`. `create`, `update` and `getAttribute` now serve both names as the instance fleet id, which is also the physical id. A fleet whose state was written before this change keeps only `Id` until its next update or replacement. Until then, `InstanceFleetId` still resolves through the fallback. The same holds for an `AWS::EMR::InstanceGroupConfig` update that changes nothing mutable: it now records `InstanceGroupId` too, where it previously kept the old attribute bag.
