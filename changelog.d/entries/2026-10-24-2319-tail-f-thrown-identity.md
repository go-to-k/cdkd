- **A failed SSM parameter create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events, and the SSM parameter's Arn-attribute warning, the CloudTrail trail's skipped event-selector reset warning, and the partial-create / best-effort cleanup warnings of the IAM user and group, FSx file system and EMR cluster / instance group / instance fleet providers name an AWS failure by its class (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/{ssm-parameter,kinesis,cloudtrail,iam-user-group,fsx-filesystem,emr-cluster,emr-instance-group-config,emr-instance-fleet-config}-provider.ts` unit cases. The SSM failure message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log through the operation's secret masker; the AWS error is still the wrap's `cause`, so a propagating grant or a throttle is retried as before, and an "already exists" is still stated as such. A cleanup warning shows the class at warn and AWS's text at debug, masked; an EMR cluster that terminated with errors shows the state-change reason's code at warn. An SSM parameter, Kinesis stream, CloudTrail trail or FSx file system delete failure whose class is another resource's not-found no longer reads as "already deleted": the state record is kept. A CloudTrail update whose event-selector reset is denied on a trail whose name contains "advanced event selector" now fails instead of being skipped. A Kinesis stream, CloudTrail trail, IAM user or IAM group whose post-create step fails with "already exists" no longer adds "AWS reports that it already exists", which read as the resource's own name collision.
