- **`cdkd deploy` refuses a custom resource whose properties hold a secure dynamic reference, which CloudFormation does not support (issue [#3976](https://github.com/go-to-k/cdkd/issues/3976))** -- new `src/provisioning/custom-resource-secure-references.ts`, wired into `ProviderRegistry.validateResourceProperties` (`validateCustomResourceSecureReferences`), `tests/unit/provisioning/custom-resource-secure-references.test.ts`, the `custom-resource-masked-service-token` integ fixture and `docs/_contents/troubleshooting.md`. CloudFormation does not support `{{resolve:secretsmanager:...}}` / `{{resolve:ssm-secure:...}}` in custom resources; cdkd resolved them and sent the secret's plaintext in the handler's event, and persisted the reference expression where the delete path later read it (#3960). The pre-flight now refuses such a template before anything is resolved -- including the same-stack CDK shape, whose token is split across `Fn::Join` parts around the secret's `Ref` -- naming each resource and property path (never the reference), with no `--allow-*` escape hatch. A plain `{{resolve:ssm:...}}` is still accepted. BEHAVIOUR CHANGE: a stack that deployed such a custom resource under an earlier cdkd now fails its next deploy until the template passes the secret's name or ARN instead; `cdkd destroy` does not run the check.
