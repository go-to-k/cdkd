- **`CDKD_PHASE_TIMINGS=1` prints where a `cdkd deploy` spent its time, and a deploy that updates many resources writes fewer interim state saves (issue [#5200](https://github.com/go-to-k/cdkd/issues/5200))** -- `src/utils/phase-timings.ts` (new), `src/cli/commands/deploy.ts`, `src/deployment/deploy-engine/deploy-flow.ts`, `src/deployment/deploy-engine/execute.ts`, `src/deployment/deploy-engine.ts`, `src/state/s3-state-backend.ts`, `docs/troubleshooting-slow-deploys.md`, and two new unit files. With the variable set, the deploy ends with a per-phase report: Node startup, synthesis beside the state-bucket preparation, asset builds and publishes, and per stack the lock, the state load, the diff, the resource DAG, each resource's provider call, the interim and final state saves, and the teardown. It makes no AWS call of its own, and unset it costs nothing. Interim state saves after each resource now coalesce: at most one save waits behind the one in flight, and every resource that completes meanwhile joins it, since that save reads the live records when it starts. The saved state after each completion is the same as before; fewer identical writes are queued, so the end of the resource DAG no longer waits for a backlog of them. The account lookup that names the asset destinations now runs beside synthesis instead of after it.
