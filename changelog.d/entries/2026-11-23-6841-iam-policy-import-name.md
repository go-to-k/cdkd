- **An inline `AWS::IAM::Policy` adopted from CloudFormation is recorded under its policy name (issue [#6841](https://github.com/go-to-k/cdkd/issues/6841))** -- `src/provisioning/providers/iam-policy/read-state.ts`, `tests/unit/provisioning/iam-import-physical-id-6841.test.ts`. A migrated or auto-mode import recorded CloudFormation's generated `PhysicalResourceId`, which names no IAM object, so `cdkd drift` reported the policy DELETED and `cdkd state refresh-observed` failed. The record now takes the policy's name, the id a deploy records, once CloudFormation's deployed template names it and IAM confirms one of its roles, groups or users holds an inline policy of that name; otherwise it keeps CloudFormation's id and warns. An id passed with `--resource` is kept as given.
