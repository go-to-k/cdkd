- **A Cloud Control deploy no longer re-sends a Lambda function's unchanged `Code`, which made the Lambda handler call `UpdateFunctionCode` on a configuration update (issue [#6709](https://github.com/go-to-k/cdkd/issues/6709))** -- `src/provisioning/write-only-properties.ts`, `src/provisioning/cloud-control/update.ts`. The Cloud Control update path re-added the write-only properties the template declares, changed or not, because a read handler cannot return one and an omitted one can be lost (issue #809). For `AWS::Lambda::Function` that re-added `Code`, and the handler answered by calling `UpdateFunctionCode`: adding only `FunctionScalingConfig` to four GPU-backed image functions on Lambda Managed Instances made that call for each. Direct Cloud Control probes reproduced it on an image function (188 to 217 s with the unchanged `Code` in the patch, 26 to 28 s without it) and on an inline zip function, which got a new `CodeSha256`; a CloudFormation stack update changing only the scaling setting made no such call. The update now leaves `Code` out for `AWS::Lambda::Function` when it deep-equals the previous value (`getWriteOnlyKeysKeptWhenOmitted`). A changed `Code` is still sent, and the existing handling of the other write-only keys, `PublishToLatestPublished` included, continues.
