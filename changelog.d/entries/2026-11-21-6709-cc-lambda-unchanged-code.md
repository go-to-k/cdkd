- **A Cloud Control update of a Lambda function no longer re-sends its unchanged `Code`, so a configuration-only change stops updating the function code (issue [#6709](https://github.com/go-to-k/cdkd/issues/6709))** -- `src/provisioning/write-only-properties.ts`, `src/provisioning/cloud-control/update.ts`. The Cloud Control update path re-added every write-only property the template declares, changed or not, because a read handler cannot return one and an omitted one is normally lost (issue #809). For `AWS::Lambda::Function` that re-added `Code`, and the handler answered by calling `UpdateFunctionCode`: adding only `FunctionScalingConfig` to four GPU-backed image functions on Lambda Managed Instances made that call for each, and direct Cloud Control probes took 188 to 217 s with the unchanged `Code` in the patch against 26 to 28 s without it; an inline zip function got a new `CodeSha256` the same way. A CloudFormation stack update of the same shape made no such call. An unchanged `Code` now stays out of the patch (`getWriteOnlyKeysKeptWhenOmitted`, a per-type table holding only measured handlers); the handler keeps the code without it. A changed `Code` is still sent, and every other write-only property, `PublishToLatestPublished` included, keeps the re-add.
