- **`cdkd local invoke` / `local run-task` / `local invoke-agentcore` with `--from-state` / `--from-cfn-stack` resolve `${AWS::Region}`, `${AWS::Partition}` and `${AWS::URLSuffix}` for a stack with no `env.region` when the region comes only from the AWS profile (issue [#6325](https://github.com/go-to-k/cdkd/issues/6325))** -- `src/cli/commands/local-invoke/command.ts`, `src/cli/commands/local-run-task/image-context.ts`, `src/cli/commands/local-invoke-agentcore/image.ts`. With no `--region`, `AWS_REGION` or `AWS_DEFAULT_REGION`, these values were dropped with a warning that the region could not be determined, although the state record that resolved the rest of the env names the region the stack was deployed to. They now take that region, as `local start-api` already did; a `local run-task` image `Fn::Sub` naming only pseudo parameters now loads the record for it, and `local invoke-agentcore`'s image context keeps its `${AWS::AccountId}`. A region you name, or the stack's `env.region`, still wins. The same applied under `--aws-emulator` in mixed mode.
