- **A rollback that regenerates a secret restores the secret's readers with the regenerated value (issue [#6591](https://github.com/go-to-k/cdkd/issues/6591))** -- `src/deployment/rollback-executor/regenerated-secrets.ts`, `replay-completed.ts`, `replay-props.ts`, `replay-secrets.ts`, `plan.ts` and unit tests. When a failed deploy had changed a Secrets Manager secret's `GenerateSecretString` and updated a resource reading that secret through a `{{resolve:secretsmanager:...}}` reference (a Lambda environment variable, for example), the rollback restored the reader first, with the password from before the deploy, and then restored the secret, which makes AWS generate a new password. The reader was left holding a password the secret no longer served. The rollback now restores such a secret before the resources whose records depend on it, and resolves their references to the secret's current value, as CloudFormation's rollback does. `cdkd rollback --dry-run` lists the same order.
