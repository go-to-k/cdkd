- **`cdkd deploy --verbose` no longer prints a `NoEcho` custom-resource value on its `Resolved Fn::GetAtt ...` debug lines (issue [#3659](https://github.com/go-to-k/cdkd/issues/3659))** -- `src/deployment/intrinsic-function-resolver.ts` (`resolveGetAtt`, `serveHealedAttribute`), `tests/unit/deployment/intrinsic-getatt-noecho-log-order.test.ts`, and the new `tests/integration/custom-resource-noecho-nested/` fixture, whose `--verbose` log scan found it on real AWS. A value a handler declared sensitive with `NoEcho: true` was already masked in `state.json`, but each `Fn::GetAtt` branch serving it from the recorded attributes logged it before registering it as a secret of the resource reading it. So the debug line printed the plaintext, both for a same-stack read and for a parent reading a nested child's output. The four branches (the flat and nested attribute reads, the Route 53 `NameServers` normalization and the stale-attribute re-read) now register first, so the line shows `***`. Resolved values and state are unchanged. The same fixture adds real-AWS coverage of the cross-stack recovery the `NoEcho` channel relies on (issue [#2460](https://github.com/go-to-k/cdkd/issues/2460)): nested-stack outputs and `Fn::ImportValue` in one `cdkd deploy --all`.
