- **A CREATE whose retry collides after an ambiguous earlier attempt now prints recovery advice instead of only the raw "already exists" (issue [#3984](https://github.com/go-to-k/cdkd/issues/3984))** -- `src/deployment/deploy-engine/name-collision.ts`, `src/deployment/retryable-errors.ts` (new `isReplayedNameCollisionFrom`), `src/provisioning/auxiliary-failure.ts` (`RETRY_AUXILIARY_OWNER`, `isAuxiliaryMarkOf`), `src/deployment/retry.ts`. Since #3978, a collision `withRetry` raises after an attempt that may already have made the resource (a 5xx, a Cloud Control handler failure, an auxiliary-call failure) is withheld from the name-collision verdict so no delete-first site acts on it. The #2902 orphan advice read the same verdict and went silent, in the case it fits best: the holder is most likely this create's own resource, in no state file, so no rollback or `cdkd destroy` removes it. Such a collision on a cdkd-derived name now gets its own line: the earlier attempt ended without a clear verdict, so this create most likely made the resource; confirm it is yours, then `cdkd import` it or delete it. Advice only: the delete-first sites still read the withholding classifier. A provider-marked auxiliary collision and a template-supplied name stay silent, as before.
