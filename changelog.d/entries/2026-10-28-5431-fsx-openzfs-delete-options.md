- **`cdkd destroy` now deletes an FSx for OpenZFS file system with child volumes when the template declares `OpenZFSConfiguration.Options` (issue [#5431](https://github.com/go-to-k/cdkd/issues/5431))** -- `src/provisioning/providers/fsx-filesystem-provider.ts`. `AWS::FSx::FileSystem` `OpenZFSConfiguration.Options` (`DELETE_CHILD_VOLUMES_AND_SNAPSHOTS`) is the delete-time option CloudFormation documents for removing a file system that has child volumes, but cdkd never sent it on `DeleteFileSystem`, so FSx refused the delete; adding it to an existing stack was refused too, as an immutable change. The delete now sends the recorded `Options`, an update that adds, changes or removes it succeeds with nothing sent to AWS (CloudFormation: "Update requires: No interruption"), and `cdkd drift` no longer compares it, since AWS never stores it on the file system. The final backup keeps the `DeleteFileSystem` defaults, as before: the CloudFormation schema has no `SkipFinalBackup` / `FinalBackupTags` property. The `fsx-openzfs` integ adds the option and a child volume made outside the stack before its destroy.
