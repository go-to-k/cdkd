- **`cdkd drift` no longer reports a phantom `GlobalSecondaryIndexes` / `LocalSecondaryIndexes` difference for an `AWS::DynamoDB::Table` whose baseline an older cdkd captured, and a key-order-only `Projection` difference no longer fails an index update (issue [#1812](https://github.com/go-to-k/cdkd/issues/1812))** -- `src/provisioning/providers/dynamodb-table-provider.ts`, `docs/provider-rules.md`.
  - A table declaring indexes, deployed by a cdkd older than the #1767 readback change, recorded each index's raw `DescribeTable` description (`IndexStatus`, `ItemCount`, `IndexArn`, the on-demand `{0, 0}` capacity, a computed `WarmThroughput` with `Status`, ...), and every `cdkd drift` reported the index list as drifted until the next deploy or `--accept`. `canonicalizeDriftProperties` now strips those SDK-only members from both comparison sides. A template or a current readback carries none of them, so nothing it declares stops being reported.
  - `update()` compared an index's recorded and desired `KeySchema` / `Projection` with `JSON.stringify`, so a template-ordered `{NonKeyAttributes, ProjectionType}` against a readback-ordered one (reachable via `cdkd drift --revert`) threw "changed its KeySchema or Projection". The compare now ignores object key order; `KeySchema` element order stays significant.
