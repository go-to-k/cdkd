- **The malformed-record refusals from `cdkd destroy`, `cdkd import`, `cdkd orphan`, `cdkd rollback` and `cdkd state refresh-observed` now print commands that include the run's `--profile`, `--state-bucket` and non-default `--state-prefix` (issue [#3909](https://github.com/go-to-k/cdkd/issues/3909))**. Changed files: `src/state/malformed-resources-bag.ts`, `src/cli/commands/destroy-runner.ts`, `src/cli/commands/import.ts`, `src/cli/commands/state.ts`, `src/cli/commands/rollback.ts`, `src/deployment/nested-child-journal.ts`, `src/provisioning/providers/nested-stack-provider.ts` and `tests/unit/state/malformed-account-flags.test.ts`. Before this change, `cdkd destroy --state-bucket X` refused an unreadable record and then pointed at `cdkd state list --json` and `cdkd state show ...` with no flags. Pasted as printed, those commands read the default profile's bucket, which does not hold the record. Now the `cdkd state show` line and the `cdkd state orphan` template include the flags. When the refusal cannot name the record, the listing is printed on its own `Find the exact name:` line, and that line includes the flags too. Each value goes through the shared paste gate. A value that is not a plain identifier, that does not render exactly, or that begins with `-` is printed as a quoted hole such as `'<profile>'`. The message then states the reason and never repeats the value; this now holds for `cdkd orphan`'s drop, listing and inspect lines too, which used to quote such a value. A run with no `--profile` or non-default `--state-prefix` still carries the resolved `--state-bucket` on every printed command.
