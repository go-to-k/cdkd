- **Removing `SSESpecification` from a DynamoDB table now moves it back to the AWS owned key (issue [#5412](https://github.com/go-to-k/cdkd/issues/5412))** -- `src/provisioning/providers/dynamodb-table-provider.ts`. The removal used to send nothing, so a table whose template dropped its customer managed key stayed on that key while the deploy reported success and `cdkd diff` showed no changes. cdkd now sends `UpdateTable` with `SSESpecification: { Enabled: false }` when AWS reports encryption on, which is what CloudFormation does (measured with a stack update in us-east-1), and nothing when the table is already on the AWS owned key; the next table update waits until the key switch finishes. An `SSEEnabled` that is not a boolean, or a `null` block, is now refused before any call on create and on a change instead of being read as `false`.
