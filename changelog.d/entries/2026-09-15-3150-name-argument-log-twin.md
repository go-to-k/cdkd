- **A 1-3 character secret assembled into an intrinsic's NAME argument no longer prints in the clear on the resolver's log lines and refusals (issue [#3150](https://github.com/go-to-k/cdkd/issues/3150))** -- `src/deployment/intrinsic-function-resolver.ts`, cases in `intrinsic-resolver-name-argument-log-twin.test.ts`. Names (map keys, stack / output / export names, regions, attribute names, dynamic-reference parts) took the needle mask alone, which matches a sub-4-character value only whole, so `env-${P}` printed `env-q7`. The resolver's log masker now prints the pass's registered log twin (go-to-k/cdkd#3100), `***` when the needle mask also changes the raw text, else the needle mask, on log and thrown lines; a string equal to a masked one elsewhere in the pass is masked too. A name parsed out of a dynamic reference takes the token twin's matching part, even if assembled in the same `Fn::Sub`; it prints `***` when the pieces cannot be paired (a mask over `:` or `{{resolve:`) or the reference spells the name twice with different masks, and a refusal prints `***` for an unpairable token. A synthesized default (`AWSCURRENT`, an absent version id) prints as it is, or `***` if non-empty and inside a longer piece of the token. Transformed names take the twin of the raw value: a region lowercased by `canonicalizeRegion`, a nested stack's output name sliced off `Outputs.` (`***` when a mask covers part of that prefix; also in the declared-outputs list), and an invalid region at the `Fn::GetAZs` / `Fn::GetStackOutput` gates, whole `***` whenever it has a twin. A producer-region resolver's region (a secret ARN's too) is masked, stripped and masked again on its creation line, clients line and invalid-region refusal, and prints `***` once two spellings mask differently. A cross-stack `origin` is built from twinned names. No log twin is newly registered: `Fn::Base64` output and resolved values are unchanged. Residual: AWS SDK error text quoting such a name, go-to-k/cdkd#3171.
