- **A 1-3 character secret assembled into an intrinsic's NAME argument no longer prints in the clear on the resolver's log lines and refusals (issue [#3150](https://github.com/go-to-k/cdkd/issues/3150))** -- `src/deployment/intrinsic-function-resolver.ts`, with cases in `tests/unit/deployment/intrinsic-resolver-name-argument-log-twin.test.ts`. Names (map keys, stack / output / export names, regions, attribute names, the parts of a dynamic reference) were masked by the needle mask alone, which matches a value under four characters only as the whole text, so `Fn::Sub` over `env-` plus a two-character secret printed `env-q7`. The resolver's log masker now prints the log twin the pass registered (go-to-k/cdkd#3100), `***` when the needle mask would also change the raw text, or the needle mask alone when no twin exists, on debug lines, default-verbosity `info` / `warn` lines and thrown messages; a string equal to a masked one elsewhere in the pass is masked too. A name parsed out of a dynamic reference takes the matching part of the token's twin, even when assembled in the same `Fn::Sub`; it prints `***` when the pieces cannot be paired (a mask over `:` or part of `{{resolve:`) or the reference spells the name twice with different masks, and a refusal prints the whole token as `***` when the twin holds no token to pair. Transformed names take the twin of the raw value: a region lowercased by `canonicalizeRegion` (also on the producer-region resolver line), a nested stack's output name sliced off `Outputs.` (`***` when a mask covers part of that prefix; also in the declared-outputs list), and an invalid region, whole `***` whenever it has a twin. A cross-stack re-resolution's `origin` is assembled from twinned names. No new log twin is registered, so what `Fn::Base64` persists and every resolved value are unchanged. Residual: AWS SDK error text quoting such a name, go-to-k/cdkd#3171.
