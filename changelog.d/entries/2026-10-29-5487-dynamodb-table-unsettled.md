- **A failed DynamoDB table update now records what it had already started, so the next deploy converges it (issue [#5487](https://github.com/go-to-k/cdkd/issues/5487))** -- `src/provisioning/providers/dynamodb-table-provider.ts`. Each property is marked just before the call that changes it: the billing / throughput / table-class UpdateTable, its pre-flip index deletes, on-demand and warm throughput, SSE, deletion protection, the stream and its members, index adds / updates / deletes, PITR, TTL, the resource policy, Kinesis streaming, Contributor Insights, and tags. An update that fails part way (an ACTIVE / SSE / Kinesis wait, the per-resource deadline, Ctrl-C, or a later call) therefore records the property as unsettled instead of leaving the old value in state, which a redeploy of that template would have diffed as unchanged. For the convergence step (#5496), the table reports template-shaped values: no 0/0 `ProvisionedThroughput` on a PAY_PER_REQUEST table, and the separately-read settings are read strictly. The next deploy also refuses to diff a property while the table, an index, SSE, TTL or a Kinesis destination is still changing.
