- **`cdkd destroy` and `cdkd state destroy` now delete a cross-region stack's nested children in the stack's region, not the CLI's (issue [#4941](https://github.com/go-to-k/cdkd/issues/4941))** -- `src/cli/commands/destroy-runner.ts`, `src/cli/commands/state.ts`, new `tests/unit/cli/destroy-nested-cross-region-scope-4941.test.ts` and integ fixture `destroy-nested-cross-region`. Destroying a stack recorded in a region other than the CLI's switched region for the parent's own resources, but its nested children ran with the provider registry and AWS clients the command had built in the CLI's region. A provider that builds its own SDK client (Kinesis, CodeBuild, CloudTrail, Glue, WAFv2, S3 Tables, ...) captures its region when it is constructed, so a child's resource was deleted by name in the CLI's region: a same-named resource there that cdkd does not manage was deleted irreversibly, and the real one was left behind. A child's `DeletionPolicy: Snapshot` final snapshot also went through the CLI-region clients. Such a stack is now destroyed inside a stack AWS scope for its region, as deploy and rollback run theirs, with a provider registry built in that scope, and its nested children are handed that registry and the stack's clients. `cdkd state destroy --region X` run from a shell in another region also built its registry in the shell's region, so it deleted by name there for a stack recorded in X; it now points the SDK at X first, as `cdkd destroy --region` does. A stack in the CLI's region is otherwise unchanged.
