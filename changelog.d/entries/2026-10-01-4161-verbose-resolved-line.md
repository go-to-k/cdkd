- **A pasted `--verbose` `Resolved …` line no longer redirects into a file the template chose, and a value or name on it no longer runs when pasted (issue [#4161](https://github.com/go-to-k/cdkd/issues/4161))** -- `src/deployment/intrinsic-function-resolver.ts`. The resolver's debug lines for `Ref`, `Fn::GetAtt`, `Fn::FindInMap`, `Fn::Select`, `Fn::Split`, `Fn::Base64`, `Fn::GetAZs` and the condition functions printed cdkd's own ` -> ` right before a bare render, so a pasted line truncated a file named by the value (`Resolved Ref to resource: Thing -> bucket` truncated `./bucket`). They now read `resolved to` (`normalized to` on the legacy `Fn::GetAtt` attribute line); a script grepping the old spelling needs the new one. The values and names on those lines, and on the `Fn::Join`, `Fn::Sub`, `Fn::If` and `AWS::NoValue` lines, were bare too, so a template or state value such as `x>OWNED` still ran or redirected on its own. A value or name now prints only when it is shell-inert with its quotes stripped (a plain identifier or a `***` mask) and is not a shell assignment word (`PATH=.`, `PATH+=:.`); anything else reads `a value that cannot be shown safely here`. A JSON render (a list, an object, a `Fn::Select` / `Fn::Split` result) prints while every string in it is inert, and the `Fn::Split` delimiter follows the same rule. cdkd's own `<redacted>` token is unchanged, and so is masking. Not closed: a plain name that is itself a command word at a clause start (go-to-k/cdkd#4249), and the resolver's other log lines (go-to-k/cdkd#4250). Tests: `tests/unit/deployment/resolver-resolved-line-paste-4161.test.ts`, plus the pins in the resolver suites and the `secrets-dynamic-ref`, `nested-stack-secret`, `nested-stack-3level` and `noecho-parameter-masking` integ fixtures.
