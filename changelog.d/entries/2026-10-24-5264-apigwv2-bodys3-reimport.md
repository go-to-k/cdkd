- **A redeploy that changes an `AWS::ApiGatewayV2::Api`'s `BodyS3Location`, or its `BasePath` / `FailOnWarnings` while the definition comes from `BodyS3Location`, now updates the API in place instead of being refused (issue [#5264](https://github.com/go-to-k/cdkd/issues/5264))** -- `src/provisioning/apigwv2-body-import-patch.ts`, `src/provisioning/cloud-control-provider.ts`, unit cases, and a phase in the `cc-api-fallback` integ. cdkd reads the definition object as the deploy identity, in the bucket's own region. It reads a pinned `Version` as that version, and follows a `301` redirect once to the region S3 names. A template declaring both `Body` and `BodyS3Location` is refused. Then it reimports the text through `ReimportApi`, as it does for an inline `Body`, and re-sends a declared `Description`. A refused read names the failure by its class and the next step: an `AccessDenied` names the `s3:GetObject` grant (plus `s3:GetObjectVersion` for a pinned version and `kms:Decrypt` for an SSE-KMS object), and AWS's own text goes to `--verbose` only. A throttled or failed read is retried as any update is. CloudFormation reads the object with the stack's execution role; cdkd reads it with the deploy identity.
