- **`cdkd local run-task` recognises a FIPS, dual-stack (`on.aws`) or upper-cased ECR host as a cdkd asset image in a region bootstrapped with `cdkd bootstrap --container-repo <name>` (issue [#1846](https://github.com/go-to-k/cdkd/issues/1846))** -- `src/local/ecs-task-resolver.ts`, `src/utils/ecr-uri.ts`, `docs/local-run-task.md`, and unit tests. The host test in front of the marker-named repository match was the case-sensitive substring `.dkr.ecr.`, a third spelling of the ECR host grammar that knew only the plain form. An image such as `<acct>.dkr-ecr.us-east-1.on.aws/<custom-repo>:<hash>` therefore skipped both the bootstrap-marker read and the local `cdk.out` build, and was pulled from ECR instead. The test is now `hasEcrRegistryHostLabels`, built from `ECR_REGISTRY_HOST_FORMS`, so it accepts all four label runs in any case and still accepts a host whose account, region and suffix are unresolved `${AWS::...}` placeholders. It is a shape test only; `parseEcrRegistryHost` still decides which hosts get a `docker login`.
