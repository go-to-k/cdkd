- **A Cloud Control resource whose write-only property holds a create-only value is updated in place again (issue [#4416](https://github.com/go-to-k/cdkd/issues/4416))** -- `src/provisioning/{cloud-control-provider,write-only-properties}.ts`. The update path re-adds every write-only property to the patch (#809), so an `AWS::Cognito::ManagedLoginBranding` (`ClientId` is write-only and create-only) or a Kinesis- / DynamoDB- / Kafka- / MQ-source `AWS::Pipes::Pipe` (write-only `SourceParameters` holding a create-only `StartingPosition` / topic / queue) failed every update with "createOnlyProperties [...] cannot be updated", even when only `Settings` or `Description` changed: Cloud Control refuses any patch bringing a create-only value its read handler cannot return, unchanged or not. A write-only property whose value holds such a path is no longer re-added, so an unchanged one sends no op; an SQS-source pipe's `SourceParameters` is still re-added. Tests: `tests/unit/provisioning/cloud-control-provider.test.ts`; integ: `cc-write-only-create-only`.
