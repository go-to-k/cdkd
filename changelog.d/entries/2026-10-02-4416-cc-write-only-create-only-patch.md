- **A Cloud Control resource whose write-only property holds a create-only value is updated in place again (issue [#4416](https://github.com/go-to-k/cdkd/issues/4416))** -- `src/provisioning/{cloud-control-provider,write-only-properties}.ts`. The update path re-adds every write-only property to the patch (#809), so these failed every update with "createOnlyProperties [...] cannot be updated", even when only an unrelated property changed: an `AWS::Cognito::ManagedLoginBranding` (`ClientId` is write-only and create-only), a Kinesis- / DynamoDB- / Kafka- / MQ-source `AWS::Pipes::Pipe` (write-only `SourceParameters` holding a create-only `StartingPosition` / topic / queue), an `AWS::CodePipeline::CustomActionType` (create-only `Settings` / `ConfigurationProperties` holding write-only leaves). Cloud Control refuses any patch bringing such a value into the model its read handler returns, unchanged or not. An UNCHANGED write-only property whose value holds such a path is no longer re-added, so it sends no op; an SQS-source pipe's `SourceParameters` is still re-added. A CHANGED one still fails: Cloud Control cannot express that update at all (a Kinesis-source pipe's `BatchSize`, issue [#4423](https://github.com/go-to-k/cdkd/issues/4423)). Tests: `tests/unit/provisioning/cloud-control-provider.test.ts`; integ: `cc-write-only-create-only`.
