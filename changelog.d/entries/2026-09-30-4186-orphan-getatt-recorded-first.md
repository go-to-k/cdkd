- **`cdkd orphan` substitutes a sibling's `Fn::GetAtt` from the orphan's recorded attribute instead of a live read by name (issue [#4186](https://github.com/go-to-k/cdkd/issues/4186))** -- `src/analyzer/orphan-rewriter.ts` (`servableRecordedAttribute`), with unit cases in `tests/unit/analyzer/orphan-rewriter.test.ts` and the real-AWS arm `tests/integration/orphan-getatt-takeover/`. The rewrite took every `Fn::GetAtt` value from a live `provider.getAttribute(...)`, which most SDK providers address by the recorded name. After the resource was deleted out of band and another one took its name -- the case `cdkd orphan` is the documented way out of -- the dependents' state received the newcomer's attribute (another role's `RoleId`, another repository's `KmsKeyId`), and a later update could send it on. The rewrite now takes the recorded value wherever cdkd's own `Fn::GetAtt` resolution would serve it, which is the value the dependents were deployed with. It still reads live when the record lacks the attribute, or holds a value that is not the attribute itself: the redaction mask `***`, a `{{resolve:...}}` reference, a stale placeholder ARN, a VPC's `Ipv6CidrBlocks`. A mask is never written into a dependent on the default path; only `--force`'s existing fallback can, with its warning. A credential-named attribute (`AWS::IAM::AccessKey` `SecretAccessKey`) and any custom-resource attribute are never taken from the record, since the rewrite audit prints what it substitutes; they keep their previous outcome.
