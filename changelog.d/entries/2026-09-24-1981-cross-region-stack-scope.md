- **A multi-region `cdkd deploy` no longer lets concurrently deploying stacks issue AWS calls against each other's region (issue [#1981](https://github.com/go-to-k/cdkd/issues/1981))** -- `src/utils/stack-aws-scope.ts` (new), `src/utils/aws-clients.ts` (`runWithStackAwsClients`, `getAwsClients`), `src/utils/aws-client-defaults.ts`, `src/cli/commands/deploy.ts`, and every provider that read `process.env['AWS_REGION']`. `cdkd deploy` used to point the process-global AWS clients and `process.env.AWS_REGION` at each stack's region in turn. At the default `--stack-concurrency` of 4, stacks in two regions overwrote each other's setting, so a provider call made after any `await` could create a resource in the other stack's region, where cleanup keyed by the stack's region never finds it. Each stack now runs inside an `AsyncLocalStorage` scope that carries its own clients and region. `getAwsClients()`, `awsClientDefaults()` (which every SDK client in `src/` is built from) and the new `ambientRegion()` read that scope first. The deploy no longer changes `process.env.AWS_REGION` per stack. Commands that never enter a scope behave as before. `cdkd destroy`, which removes stacks one at a time, keeps its own per-stack switch.
