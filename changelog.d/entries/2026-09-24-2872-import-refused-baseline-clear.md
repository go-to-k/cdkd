- **`cdkd import` now drops the drift baseline of a resource it refuses to capture one for, including a resource a selective import leaves in place (issue [#2872](https://github.com/go-to-k/cdkd/issues/2872))** -- `src/cli/commands/import.ts`, `docs/import.md`, `tests/unit/cli/import-deployed-parameters.test.ts`. When an import refused the `observedProperties` baseline of a record it did not re-import (one preserved by a selective merge, refused by this run or by an earlier one), it skipped the capture but left whatever baseline the record already carried. That baseline was read back against the same `properties` the refusal distrusts, and a record written by an older cdkd could hold a decrypted secret there. Both refusal arms now remove it, so a refused resource always ends with no baseline; `cdkd drift` does not compare it until a deploy that creates or updates it, or a re-import that proves it, restores one.
