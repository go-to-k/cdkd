- **A malformed `Tags` value no longer untags every key a resource holds (issue [#3994](https://github.com/go-to-k/cdkd/issues/3994))** -- `src/provisioning/tag-list.ts` (new), read by most SDK providers that diff `Tags`. Each `Tags` diff read a present-but-malformed value as empty or short (a string walked by character, a non-list read as `{}`, an entry without `Key` or `Value` dropped), and several untagged every recorded key before re-tagging, so on a rollback or `cdkd drift --revert`, which replay a recorded bag, a malformed `Tags` stripped the resource's tags. `undefined` / `null` still reads as no tags; anything else that is not a list of `{Key: non-empty string, Value: scalar}` (a number or boolean `Value` reads as its string, as CloudFormation coerces it; an omitted one as `''` on `AWS::RDS::DBProxy` / `DBProxyEndpoint`; for `AWS::SSM::Parameter`, a map of keys to scalars) is malformed. A malformed desired `Tags`, or one whose key holds a dynamic reference or its mask, is now refused before any AWS call on create and update, naming the property but never its content; a missing, `null` or object `Value` is no longer coerced to `''` (except an omitted one on DBProxy / DBProxyEndpoint). A malformed recorded `Tags` is applied ADD-only: the desired tags are set, nothing is untagged (an S3 bucket keeps the live tags it cannot account for), and cdkd warns. A recorded key holding a dynamic reference or its mask is never untagged, and cdkd warns about it. Updates now send only the tags that changed (an S3 bucket still replaces its whole set). Separately, `AWS::ElastiCache::SubnetGroup` now sends its `Tags` on create and on update applies the missing ones, untagging only recorded keys it holds, and `AWS::ServiceDiscovery::Service` diffs its `Tags` on update; both used to drop them. The Glue and CloudWatch Logs log-group providers follow in [#4073](https://github.com/go-to-k/cdkd/issues/4073). Tests: `tag-list.test.ts`, per-provider `*-malformed-tags-3994.test.ts`.
