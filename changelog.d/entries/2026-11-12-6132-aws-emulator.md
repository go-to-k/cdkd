- **`cdkd local` wires workload containers to local AWS endpoints: `--aws-emulator [url]`, `--ca-bundle <file>`, endpoint forwarding and default-chain credentials (issues [#6129](https://github.com/go-to-k/cdkd/issues/6129), [#6130](https://github.com/go-to-k/cdkd/issues/6130), [#6131](https://github.com/go-to-k/cdkd/issues/6131), [#6132](https://github.com/go-to-k/cdkd/issues/6132))** -- `src/local/local-aws-wiring.ts`, `src/local/docker-runner.ts`, `src/local/ecs-task-runner.ts` + `ecs-task-runner/docker-run-args.ts`, `src/utils/aws-client-defaults.ts`, `src/cli/commands/local-run-task/credentials.ts`, the four cdkd-owned command registrations; cdk-local 0.161.2 owns the decisions. **Behavior changes:** (1) a host `AWS_ENDPOINT_URL` / `AWS_ENDPOINT_URL_<SERVICE>` / profile `endpoint_url` now reaches every workload container (before: never forwarded); a loopback endpoint keeps its URL through a forwarder container sharing the workload's network namespace, so TLS verification and S3 path-style hold; `AWS_IGNORE_CONFIGURED_ENDPOINT_URLS=true` opts out. (2) With no credential flag, Lambda-family containers and the `run-task` metadata sidecar get the host's default credential chain (`AWS_PROFILE`, shared files, SSO), read without its env link under `--role-arn` (before: env-var keys only, or none). (3) Lambda-family containers get one region in BOTH `AWS_REGION` and `AWS_DEFAULT_REGION`: `--region`, then the host region, then the stack's (`invoke` / `start-api`; `invoke-agentcore` without the stack fallback). New: `--ca-bundle` mounts a CA read-only with `AWS_CA_BUNDLE` / `NODE_EXTRA_CA_CERTS` / `REQUESTS_CA_BUNDLE` / `SSL_CERT_FILE` (a host `AWS_CA_BUNDLE` alone sets only the first two); `--aws-emulator` (env `CDKD_AWS_EMULATOR`) probes AWS Emulator's health, points cdkd's own clients (`--from-state`, `{{resolve:...}}`, STS, `--from-cfn-stack`) at it, and gives containers its credentials only.
