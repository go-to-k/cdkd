- **A tag change on an `AWS::EC2::InternetGateway`, `AWS::EC2::RouteTable` or `AWS::EC2::NetworkAcl` is now applied in place (issue [#5448](https://github.com/go-to-k/cdkd/issues/5448))** -- `src/provisioning/providers/ec2-provider.ts`. Every update of the three types was refused as not updatable in place, a no-op included, so a tags-only edit failed the deploy unless `--replace` deleted and recreated the resource. CloudFormation updates `Tags` in place (a change set reads Modify, Replacement False), and cdkd now does too: it diffs the recorded and desired tags into `DeleteTags` / `CreateTags` on the same physical id, as it already did for the VPC, subnet and security group. A `VpcId` change on a route table or network ACL, which only `cdkd drift --revert` can send to update, is still refused. The `ec2-vpc` integ fixture changes and removes a tag on each of the three.
