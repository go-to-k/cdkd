- **`cdkd drift` compares two `AWS::EC2::SecurityGroupIngress` resources that share one rule, instead of reporting both drift unknown (issue [#7198](https://github.com/go-to-k/cdkd/issues/7198))** -- `src/provisioning/providers/ec2/read-state.ts`, `src/provisioning/providers/ec2/sg-support.ts`. An Aurora cluster's `addIngressRule(sg, Port.tcp(3306))` beside a `DatabaseProxy`'s rule on the cluster's `Endpoint.Port` declares the same rule twice; AWS keeps one, and the second create records its `sgr-` id. Each record's read answered nothing (#4492), so since #6696 `cdkd drift` exited 2 on every freshly deployed stack with such a pair. Each record now compares against the shared rule: it reads clean while AWS holds either record's description, and any other description is drift on both, which `--revert` restores in place. A second record recording another id, or none, still leaves the rule unknown. Tests: `tests/unit/provisioning/ec2-provider-readcurrentstate.test.ts`, `tests/unit/cli/drift-revert-sg-ingress-ownership.test.ts`; integ `rds-aurora` Phase 1a.
