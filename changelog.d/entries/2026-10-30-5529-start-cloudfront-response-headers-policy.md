- **`cdkd local start-cloudfront` applies a response headers policy's security, custom and remove headers, not only its CORS config (issue [#5529](https://github.com/go-to-k/cdkd/issues/5529))** -- `package.json` (`cdk-local` `^0.157.0` -> `^0.158.0`), `docs/local-start-cloudfront.md`. Before this change, a cache behavior's `ResponseHeadersPolicy` contributed only its CORS headers, so `Strict-Transport-Security`, `Content-Security-Policy`, `X-Frame-Options` and the other security headers, custom headers and removed headers did not appear on local responses. Now the whole policy is applied to the origin's responses and to responses a Lambda@Edge request stage generates, after the viewer-response function and the Lambda@Edge response stages: the remove list first, then each header honoring its `Override` (replace the origin's header, or add it only when the origin sent none). A header whose value is a CDK token is skipped with a warning, and `ServerTimingHeadersConfig` is not applied.
