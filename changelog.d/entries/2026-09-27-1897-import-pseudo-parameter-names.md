- **`cdkd import` resolves a name built from the account or region before the provider looks it up (issue [#1897](https://github.com/go-to-k/cdkd/issues/1897))** -- `src/cli/commands/import.ts` (`resolvePseudoParameterIntrinsics`, called from `importOne`), with unit tests in `tests/unit/cli/import-prepass-pseudo-parameters.test.ts` and `tests/unit/cli/import.test.ts`, the `route53` integ arm in `tests/integration/route53/verify.sh`, and `docs/_contents/import.md`. On an env-agnostic stack a name such as `` `cdkd-test-${this.account}.internal` `` synthesizes to an `Fn::Join` over `AWS::AccountId`, and `import.ts` pre-substituted only `{Ref: <logicalId>}` before calling a provider, so the provider saw the intrinsic, its `typeof name === 'string'` guard declined, and the documented name route (for example `AWS::Route53::HostedZone` via `ListHostedZonesByName`) answered `skipped-not-found`. Every intrinsic built only from string literals, `Fn::Join`, `Fn::Sub` and `AWS::AccountId` / `AWS::Region` / `AWS::Partition` / `AWS::URLSuffix` is now evaluated for the resource's region before `provider.import()`, with the pseudo-parameter values a deploy uses. Anything else in the intrinsic (a resource or parameter `Ref`, `Fn::GetAtt`, `AWS::StackName`) leaves it unresolved; a result spelling a `{{resolve:...}}` reference is left unresolved and nothing is fetched; and a name needing the account is not resolved when STS could not answer. The properties recorded in state are unchanged. Separately, `substituteOverrideRefs` now keeps a template property key named `__proto__` as an own key of the bag it hands the provider; it used to become the bag's prototype, so its members read as the resource's own properties.
