- **A Secrets Manager secret's replica is re-keyed when its `ReplicaRegions[].KmsKeyId` changes (issue [#5302](https://github.com/go-to-k/cdkd/issues/5302))** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`. Changing, adding or removing the `KmsKeyId` of a region the secret already replicates to used to deploy green while the replica kept its old key, so state disagreed with AWS. `update()` now sends `ReplicateSecretToRegions` for every kept region whose key changed (with no key when it was removed, which re-keys the replica to the AWS managed key), re-encrypting the replica in place without removing it, as a CloudFormation A/B showed CloudFormation does. Test: `tests/unit/provisioning/secretsmanager-secret-provider-replica-rekey-5302.test.ts`.
