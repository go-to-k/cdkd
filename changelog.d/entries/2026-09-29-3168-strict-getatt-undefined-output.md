- **`--strict-getatt` now fails the deploy for a stack Output whose value resolves to nothing, not only for one whose resolution throws (issue [#3168](https://github.com/go-to-k/cdkd/issues/3168))** -- `src/deployment/deploy-engine.ts` (`resolveOutputs`), with unit tests in `tests/unit/deployment/deploy-engine-skipped-outputs.test.ts` and `deploy-engine-stale-attribute-heal.test.ts` (the real resolver on `Fn::GetAtt [Role, RoleId]`). Some `Fn::GetAtt` attributes cdkd cannot construct (`AWS::IAM::Role` `RoleId`, `AWS::DynamoDB::Table` `StreamArn`, `AWS::IAM::Policy` `PolicyId`, a failed Cloud Map `HostedZoneId` lookup) return no value instead of throwing, so such an Output was stored with no value and the deploy exited 0 even under `--strict-getatt`, leaving an `Export.Name` a consumer's `Fn::ImportValue` could not find. Under the flag it now takes the same failure path as a thrown resolution: the deploy fails with `Failed to resolve output <name>: the value resolved to nothing`, and the failure save keeps the previous deploy's outputs. Without the flag nothing changes.
