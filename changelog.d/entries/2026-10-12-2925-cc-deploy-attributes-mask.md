- **A Cloud Control create or update no longer records the whole resource model as the resource's `attributes`, so the first deploy after `cdkd import` keeps the import's narrowing (issue [#2925](https://github.com/go-to-k/cdkd/issues/2925))** -- `src/provisioning/cloud-control-provider.ts` (`maskDeployedNonAttributeKeys`), `src/provisioning/read-only-properties.ts` (`getTopLevelDeployAttributeNames`), the generated `SHAPE_MISMATCHED_GETATT_ATTRIBUTES`, `src/cli/commands/import.ts`, `src/deployment/deploy-engine/masking.ts`. Every model key that is not an `Fn::GetAtt` attribute of the type is now recorded as `***`, key kept, as `cdkd import` already did. Every attribute the CloudFormation resource specification lists stays in the clear, including the writable ones whose value shape differs from the property's (`AWS::DocDB::DBCluster` `Port`, which CDK's `allowDefaultPortFrom` reads), and keys the enrichment computes (`Endpoint.Address`, ...) are never masked; `AWS::SSM::Parameter` `Value` stays clear unless the deploy resolved it from a secret. When the deploy cannot read the schema (no `cloudformation:DescribeType`), it still records the whole model, as before, rather than refusing every `Fn::GetAtt`. A re-import's "produced no value to replace the redaction mask" warning now names only keys the template reads through `Fn::GetAtt` or `Fn::Sub`; other kept masks go to `--verbose`. The masked-attribute refusal's Cloud Control cause no longer says only `cdkd import` writes the mask. Docs: `docs/import-resource-types.md`, `docs/import-after.md`, `docs/import-internals.md`, `docs/cli-export-internals.md`.
