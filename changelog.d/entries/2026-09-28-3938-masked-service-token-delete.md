- **A custom resource whose recorded `ServiceToken` is the redaction mask `***` is now skipped on delete with a named warning instead of being sent to Lambda as a function name (issue [#3938](https://github.com/go-to-k/cdkd/issues/3938))** -- `src/provisioning/providers/custom-resource-provider.ts` (`CR_MASKED_SERVICE_TOKEN_SKIP_REASON`), a new `tests/unit/provisioning/custom-resource-masked-service-token.test.ts` and a new `tests/integration/custom-resource-masked-service-token/` fixture. A dependent custom resource that reads a `NoEcho` value equal to, or contained in, its own `ServiceToken` (a handler echoing `event.ServiceToken` into `Data`, read by a custom resource on the same provider) persists `ServiceToken: "***"`. The delete path guarded only an absent or non-string token, so the mask reached the backing-Lambda `GetFunction` pre-check and the Delete invoke, failing with an AWS error that said nothing about the mask. It now reports `outcome: 'skipped'` like the no-ServiceToken arm: no AWS call, the state record is kept, `cdkd destroy` exits 2, and the warning names the mask and the remedies (tear the resource down by hand and `cdkd state orphan <stack>`, or restore `ServiceToken` in `state.json` while the handler still exists).
