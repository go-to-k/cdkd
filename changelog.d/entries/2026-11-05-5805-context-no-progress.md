- **An app that reports the same missing context key on every synth now synthesizes, as with the AWS CDK CLI, and an absent SSM parameter honours `ignoreErrorOnMissingContext` (issue [#5805](https://github.com/go-to-k/cdkd/issues/5805))** -- `src/synthesis/synthesizer.ts`, `src/synthesis/context-providers/ssm-provider.ts`, `docs/architecture-deploy-pipeline.md`. Before this change, `cdkd synth`, `deploy` and `local` failed with `Context resolution made no progress` for a construct that calls `reportMissingContextKey` on every synth, and an SSM lookup of a parameter that does not exist failed with `UnknownError` even when the lookup supplied a default. Now cdkd uses the synthesis once the same keys stay missing, and the lookup's default is used for an absent parameter. A lookup that fails still fails the command: `synth` and `deploy` through the stack's error annotation (`--ignore-errors` applies), every other command with `Context lookup failed`.
