- **`cdkd destroy --remove-protection` deletes a Cognito user pool whose password policy sets `TemporaryPasswordValidityDays` (issue [#6548](https://github.com/go-to-k/cdkd/issues/6548))** -- `src/provisioning/providers/cognito/shared.ts` (`isUnusedAccountValidityRefusal`, `userPoolDeletionProtectionUpdate`), `cognito/delete.ts` (`sendEchoedDeletionProtection`), a new unit file and the `cognito-remove-protection-temp-password` integ fixture. The flip that turns deletion protection off echoes the pool's settings back, and `DescribeUserPool` returns the deprecated `AdminCreateUserConfig.UnusedAccountValidityDays` on every pool. A pool whose `PasswordPolicy` sets `TemporaryPasswordValidityDays` (CDK `passwordPolicy.tempPasswordValidity`) refuses a write carrying it, so cdkd fell back to the `DeletionProtection`-only write. That write resets the triggers, self sign-up and auto-verified attributes, and on a pool that also requires verification before an attribute update (CDK `keepOriginal`) AWS refused it too: the guard stayed on and the destroy failed. cdkd now re-sends the echo without that one member after AWS refuses it, so the guard goes off with the pool's settings kept, and the re-enable after a failed delete works the same way. A pool configured through the deprecated member alone still gets it echoed, since a write omitting it resets the value there (measured).
