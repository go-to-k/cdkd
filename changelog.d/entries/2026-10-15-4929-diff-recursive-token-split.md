- **`cdkd diff --recursive` no longer reports an unchanged nested child that splits a parent-built parameter on a delimiter inside a secret `{{resolve:...}}` reference's text, such as `:` (issue [#4929](https://github.com/go-to-k/cdkd/issues/4929)).** A child reading `Fn::Select [1, Fn::Split [':', {Ref: Conn}]]` over a parent row `Conn: postgres://{{resolve:...}}:{{resolve:...}}@host` showed a change on every run, and `--fail` exited 1, because the diff cut each reference into fragments (`//{{resolve`) that no deploy persists. The child now keeps whole each reference its parent's deploy replaces with the secret before handing the value down (one in the row's literal, `Fn::Join` or `Fn::Sub`, or one the parent itself received that way), as the deploy's plan does since [#4914](https://github.com/go-to-k/cdkd/issues/4914). Reference text the parent passes down as plain text (a `Ref` to its own parameter, an `Fn::FindInMap` value) is still split as text, as the deploy does. No secret is fetched and no AWS call is added. Source: `src/cli/commands/diff-recursive.ts`, `src/deployment/intrinsic-resolver/string-functions.ts`, `src/deployment/intrinsic-resolver/dynamic-refs.ts`, `src/deployment/intrinsic-resolver/context.ts`.
