- **`cdkd destroy --remove-protection` restores `DisableApiTermination` on the EC2 instances an Auto Scaling group launched when the group's delete then fails terminally (issue [#2204](https://github.com/go-to-k/cdkd/issues/2204))** -- `src/provisioning/providers/asg-provider.ts` and the shared `settleProtectionFlip` in `src/provisioning/providers/deletion-protection-compensation.ts`, with unit tests in `tests/unit/provisioning/providers/asg-instance-remove-protection-compensate.test.ts` and a live arm in the `remove-protection-compensation` integ (the destroy runs under a role denied `UpdateAutoScalingGroup` on the group, so its `prevent-all-deletion` refuses the delete after the instance flip). Before, the group delete turned each launched instance's termination protection off (issue #796) and never put it back, so a failed destroy left the instances live with the guard stripped. Now each instance whose guard a pre-flip `DescribeInstanceAttribute` saw on, and this run turned off, is turned back on before the failure is reported, under the same rules as every other `--remove-protection` site: only on a terminal failure, never once AWS has accepted the group delete, and a failed re-enable is its own log line with a pasteable `aws ec2 modify-instance-attribute` command. The flip now also needs `ec2:DescribeInstanceAttribute`; a refused read leaves the delete running and compensates nothing.
