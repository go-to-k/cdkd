- **`cdkd drift` compares S3 / SQS / SNS / KMS / Secrets Manager resource policies and the Cloud Control IAM inline policies by key union on a resource with no observed baseline, and no longer reports a single-object `Statement` as drift (issue [#6624](https://github.com/go-to-k/cdkd/issues/6624))** -- `src/analyzer/drift-verbatim-paths.ts` (`verbatimEchoDriftKeys` rows, `isVerbatimStatementPath`), `src/analyzer/drift-calculator.ts`, the new `drift-verbatim-readback` integ fixture, and `docs/cli-drift.md` / `cli-drift-internals.md`. A real readback of each type showed the service returns the submitted document with no key of its own. `PolicyDocument` on `AWS::IAM::RolePolicy` / `UserPolicy` / `GroupPolicy` / `AWS::S3::BucketPolicy` / `AWS::SQS::QueuePolicy` / `AWS::SNS::TopicPolicy`, `KeyPolicy` on `AWS::KMS::Key` and `ResourcePolicy` on `AWS::SecretsManager::ResourcePolicy` are now walked by key union on the template-only baseline (`--no-capture-observed-state`, or a failed capture). So a `Condition` added out of band to a `Deny` there is reported, and `--revert` sends the template's document whole. S3, SQS, SNS, KMS, Secrets Manager and IAM's role trust policy return a single-object `Statement` as a one-element list. On that baseline this was drift on a stack nobody had touched, and `--revert` rewrote it on every run. Under these keys the two forms now compare as one value, and the list is still compared whole; a `Version` the service fills in for a template that omits it is not drift. `AWS::ECR::Repository` is not covered, because its readback carries no `RepositoryPolicyText`.
