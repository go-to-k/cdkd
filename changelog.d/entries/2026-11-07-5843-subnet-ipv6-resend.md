- **`AWS::EC2::Subnet`: auto-assign, DNS64 and the AAAA record declared `true` now reach AWS once an `AWS::EC2::SubnetCidrBlock` attaches the block (issue [#5843](https://github.com/go-to-k/cdkd/issues/5843))** -- `src/provisioning/providers/ec2/subnet.ts`, a new unit file and a new `ec2-subnet-dns64` integ phase. A subnet whose IPv6 block comes from a sibling `SubnetCidrBlock` is updated before that block attaches, so the `true` writes EC2 refuses on a block-less subnet were skipped with a warning; the record still said `true`, so no later deploy re-sent them and the live values stayed off. The skipped values are now recorded as the `false` AWS holds, so the next deploy sends them once the block is there, and an update that finds a declared `true` live off with a block present sends it again (healing records written before this fix). CloudFormation fails that deploy instead.
