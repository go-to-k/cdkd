- **Engine and CLI lines and error messages that name a physical id mask an AppSync API key or a wait condition handle's signed URL themselves (issue [#6716](https://github.com/go-to-k/cdkd/issues/6716))** -- `src/provisioning/secret-physical-id.ts`, `src/deployment/deploy-engine/**`, `src/deployment/rollback-executor/**`, `src/deployment/{orphan-adoption,recreate-targets/probe,superseded-resources,type-change-guard,read-only-attribute-healer,nested-child-journal}.ts`, `src/deployment/replacement-name-holder/holder.ts`, `src/deployment/intrinsic-resolver/getatt-{refusals,construct-core,construct-compute}.ts`, `src/cli/commands/{destroy-runner,drift,export,import,rollback,state}/**`, `src/cli/commands/prefix-migration-check.ts`; `scripts/check-secret-physical-id-log.ts` (new). Most of these lines were masked only by the resource's masking scope, which holds the ids cdkd recorded before the line runs and prints the key as `***`. Two kinds of line had no scope and printed the key whole: a nested stack's warning that the replaced resources it could not record were deleted, and the `cdkd rollback` plan and journaled-orphan lines naming a displaced op's id. Each line and error now renders the id as `<apiId>|****last4` (a handle's URL with its query string as `****last4`) wherever it runs, the form the replacement lines already used. A `cdkd export` refusal of a malformed API key id masks it the same way. A CI check now fails a new message that renders a physical id without this mask, and a readback key the CloudFormation schemas show can carry a resolved template value under a name the state redaction does not pair.
