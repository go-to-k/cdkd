- **`cdkd scrub` repairs a nested-stack parent row's `Outputs.<Name>` attribute holding a child-sourced plaintext (issue [#3961](https://github.com/go-to-k/cdkd/issues/3961))** -- `src/cli/commands/scrub.ts`, `docs/cli-scrub.md`, `tests/unit/cli/commands/scrub-nested-child.test.ts`. **Before:** on a parent record older than the redaction of nested-stack outputs (#1899), the parent row's `attributes['Outputs.<Name>']` kept the plaintext of a child output sourced from the child's own `{{resolve:...}}`: the parent is scrubbed before its children and had no needle for it, and `--dry-run --fail` reported the parent clean. **Now:** after each child's scrub, scrub re-reads the parent's record and rewrites such an attribute under the parent's lock (taken only when something is to be rewritten), printing `Scrubbed N nested-stack output attribute(s) in <Parent>`. It rewrites an attribute to the child's scrubbed output only when the attribute is exactly what that output resolves to in this run -- the value the child's next deploy would copy there; an attribute that still holds a recorded plaintext but matches no output exactly is reported, not rewritten. Both count toward `--dry-run --fail`.
