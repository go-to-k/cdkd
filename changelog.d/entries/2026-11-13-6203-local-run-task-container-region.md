- **`local run-task` gives the task containers the region cdkd resolved (issue [#6203](https://github.com/go-to-k/cdkd/issues/6203))** -- `src/local/ecs-task-runner.ts`, unit tests and docs. Before, only `--region` reached a task container's `AWS_REGION` / `AWS_DEFAULT_REGION`: a region from the shell's `AWS_REGION` / `AWS_DEFAULT_REGION` or from `~/.aws/config` was ignored, so the task's first SDK call failed with a missing region. Now the containers get the same order as the Lambda containers (#6200): `--region`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `--stack-region` or the stack's `env.region`, the loaded state record's region, then the profile's `region`. A container's own `Environment` or `--env-vars` entry still wins. `local start-service` / `local start-alb` run cdk-local's service engine and are not changed here ([#6210](https://github.com/go-to-k/cdkd/issues/6210)).
