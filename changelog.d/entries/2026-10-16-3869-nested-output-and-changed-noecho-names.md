- **`cdkd deploy`, `cdkd diff` and `cdkd destroy` now mask two more resource names taken from a secret (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869)).** (1) With `--verbose`, a parent resource reading a nested stack's output with `Fn::GetAtt Child.Outputs.<Key>` printed the name of a child resource taken from a secret, when the child's provider had rewritten or case-folded it (an IAM name with the stack prefix, an RDS identifier), in the `Resolved Fn::GetAtt ... resolved to` line and the reader's own lines. A nested-stack row created or updated by this version records which outputs hold such a name (`ResourceState.secretNamedAttributes`, attribute keys only; no state schema bump), so a later deploy where the row is unchanged masks them too. An existing nested stack is covered after its next update: there is no backfill, which would read the child's state on every no-change deploy. (2) A name taken from a `NoEcho` parameter whose value has since changed (a record written before schema v11 still holds the old value), or from a short value, printed on a replacement's `Deleting old` / `was replaced` lines (shown without `--verbose`) and on `cdkd destroy`'s delete lines. Each record's own value at a position the template fills from a `NoEcho` parameter is now judged as secret. Beyond that key list, print-only: nothing else persisted, and nothing compared or sent, changes.
