- **`cdkd drift --revert` reverts a Secrets Manager rotation schedule, and no longer rotates the secret while doing it (issues [#6497](https://github.com/go-to-k/cdkd/issues/6497), [#6498](https://github.com/go-to-k/cdkd/issues/6498))** -- `src/cli/commands/drift/{baseline-keys,compare,revert-outcome,revert-payload}.ts`. Secrets Manager reads a schedule set as `rate(N days)` (CDK's `automaticallyAfter`) back with `AutomaticallyAfterDays: N` too, and the revert sent both, which Secrets Manager refuses (`You cannot specify both rotation frequency and schedule expression together`). Drift now ignores that echo beside the expression, and the revert sends the expression alone. Separately, a revert through Cloud Control sent none of the template's write-only properties, which no read returns, so Cloud Control applied each default: a schedule's `RotateImmediatelyOnUpdate: false` became `true` and the revert rotated the secret immediately. The revert now sends the declared write-only values, as a deploy does, except one holding a dynamic reference. Existing state needs no redeploy.
