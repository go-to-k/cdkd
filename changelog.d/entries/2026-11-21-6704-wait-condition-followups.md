- **A wait condition handle deployed by an earlier cdkd gets its signal URL on the next deploy, and a wait condition no longer needs `DependsOn` on the instance that signals it (issue [#6704](https://github.com/go-to-k/cdkd/issues/6704))** -- `src/analyzer/dag-builder.ts`, `src/analyzer/diff-calculator/legacy-handle-heal.ts` (new), `src/analyzer/diff-calculator/calculate-diff.ts`, `src/deployment/deploy-engine/update/provision-update.ts`, `src/provisioning/providers/wait-condition-handle-provider.ts`, `src/provisioning/wait-condition-handle-id.ts` (new), `src/provisioning/wait-condition-signal-store.ts`. A handle recorded with the pre-signal-URL placeholder id kept it forever, so a wait condition on it was refused until the handle was renamed; when a resource or an output references such a handle, the deploy now issues its URL and updates the readers in the same run (an unreferenced placeholder handle is left alone). Every resource referencing a wait condition's handle now runs before the wait, so a small `--concurrency` cannot start the wait first and time it out. The handle URL is now valid for 12 hours, CloudFormation's own lifetime, instead of 7 days.
