- **`cdkd rollback --remove-protection` now also deletes a deletion-protected resource whose CREATE the failed deploy completed (issue [#4678](https://github.com/go-to-k/cdkd/issues/4678))** -- `src/deployment/rollback-executor/replay-orphan-delete.ts`, `src/cli/commands/rollback.ts`. The flag reached only a failed CREATE's resource; a protected resource the deploy had created before a later resource failed (an EC2 instance with `DisableApiTermination`, a load balancer with `deletion_protection.enabled`) was deleted without it, AWS refused, and every `cdkd rollback` exited non-zero until the protection was cleared by hand. The rollback's delete of a completed CREATE now carries the flag, as one final attempt so a failed delete puts the protection back. The resource is this stack's own state record, matched to the id the journal recorded, the same trust `cdkd destroy --remove-protection` gives it. A deploy's automatic rollback still never turns protection off. Test: `tests/unit/deployment/completed-create-remove-protection-4678.test.ts`; integ `remove-protection-journaled-orphan`.
