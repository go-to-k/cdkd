- **`cdkd scrub`'s producer-plaintext refusal names a stack in its commands only when the name is a plain identifier, and a resource-timeout message no longer prints a planted logical id or type (issue [#3773](https://github.com/go-to-k/cdkd/issues/3773))** -- `src/cli/commands/scrub.ts`, `src/utils/error-handler.ts`. The `Scrub with:` and `Then re-run:` lines of the `SCRUB_CROSS_STACK_PRODUCER_PLAINTEXT` refusal named a stack whose name was not a plain identifier (one holding `:`, `@`, `,`, `%` or `+`, or starting with `_` or `.`) shell-quoted. These lines are next to other labelled lines, where cdkd names a target only when it is a plain identifier. Such a name is now printed as a quoted `'<stack>'` placeholder. A line above the commands says why: for a name shown masked, that it holds a recorded secret. It points to `cdkd state list --long`. The `ResourceTimeoutError` message (`Resource X (TYPE) ... timed out`, printed whole by `cdkd destroy`'s failure line) printed the logical id and type raw. A line break or padding in either, from a state record or template, could open or wrap into a line that passes for one of cdkd's own. A value without the shape of a real one is now described instead. The `--resource-timeout TYPE=<DURATION>` remedy names only a type that flag accepts (three segments). For any other type, including `Custom::*`, it suggests the global `--resource-timeout <DURATION>`. Tests: `tests/unit/cli/commands/scrub-refusal-plain-ident-3773.test.ts`, `tests/unit/cli/destroy-runner-events.test.ts`.
