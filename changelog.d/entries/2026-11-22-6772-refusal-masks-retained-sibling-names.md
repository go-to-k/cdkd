- **A delete refusal that names a resource the stack retained masks that resource's secret-derived name (issue [#6772](https://github.com/go-to-k/cdkd/issues/6772))** -- `src/provisioning/region-check.ts` (`DeleteContext.maskStackSecretNames`, `holderRefusalMask`), the four refusal sites in `src/provisioning/providers/iam-role/delete.ts`, `iam-user-group/group.ts`, `s3-tables/table-bucket.ts` and `s3-vectors-provider.ts`, the builders in `src/cli/commands/destroy-runner/under-lock-steps.ts`, `src/deployment/deploy-engine/masking.ts` (`stackSecretNameMasker`) and `src/deployment/secret-name-needles.ts` (`stackSecretNamesMasker`), and the `destroy-refusal-stack-secret-names-6772` / `deploy-delete-refusal-stack-secret-names-6772` unit suites. The refusal of an IAM role still in an instance profile, an IAM group with members, and an S3 Tables or S3 Vectors bucket that is not empty names those other resources, masked only with the deleted resource's own secret-derived names. A profile, user, table or index the stack kept under `DeletionPolicy: Retain`, named from a `{{resolve:secretsmanager:...}}` reference, was printed and written to `deployments/*.jsonl` in plaintext. `cdkd destroy`, a deploy's deletes, the automatic rollback, `cdkd rollback` and a nested child's revert now hand every delete a printing masker over the secret-derived names of every record of the stack, retained ones included. It masks printed text only: no provider judges a value secret-derived with it.
