- **A Cloud Control update no longer re-sends an unchanged password, token, canary code or other measured write-only key the handler acts on or refuses (issue [#6788](https://github.com/go-to-k/cdkd/issues/6788))** -- `src/provisioning/write-only-properties.ts`, `src/provisioning/cloud-control/update.ts`, `tests/unit/provisioning/cloud-control-write-only-kept-6788.test.ts`. An unrelated change (such as a tag) re-added every write-only key to the patch, so the handler re-set a Redshift / DocumentDB Elastic / Redshift Serverless / FSx SVM / DMS / ElastiCache / MemoryDB password or token (a Redshift cluster's took 407 s, a VPN connection's tunnel keys 427 s), redeployed a Synthetics canary's code, rebooted an Amazon MQ broker, rewrote a credential provider's secret, or re-ran an Elastic Beanstalk configuration deployment; and the update of a CloudFront KeyValueStore with `ImportSource`, a Connect user with `Password`, a Fargate Batch compute environment with `UpdatePolicy`, a Step Functions alias with `DeploymentPreference` or a Bedrock flow with `DefinitionString` failed. 22 types now leave such a key out while unchanged; a change to it, or to a sibling it is sent with (or a declared write-only sibling), still sends it. Only a plaintext template value benefits: a `{{resolve:...}}` or NoEcho password (CDK's default secret path) never compares equal to its resolved value and is still sent. Remaining refusals: [#6818](https://github.com/go-to-k/cdkd/issues/6818), [#6819](https://github.com/go-to-k/cdkd/issues/6819), [#6820](https://github.com/go-to-k/cdkd/issues/6820), [#6821](https://github.com/go-to-k/cdkd/issues/6821), [#6822](https://github.com/go-to-k/cdkd/issues/6822).
