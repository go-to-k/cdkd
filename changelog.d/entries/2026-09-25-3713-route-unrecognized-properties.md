- **A property absent from cdkd's CFn schema snapshot now routes its resource through Cloud Control instead of being dropped on the SDK route (issue [#3713](https://github.com/go-to-k/cdkd/issues/3713))** -- `src/provisioning/{property-coverage,provider-registry}.ts`, `scripts/gen-property-coverage.ts` (+ regenerated table), `src/deployment/{deploy-engine,recreate-targets}.ts`, `src/analyzer/diff-calculator.ts`, `src/cli/commands/diff-recursive.ts`, `scripts/diagnose-schema-refresh.mjs`, `docs/{provider-rules,troubleshooting}.md`, `docs/design/3713-route-unrecognized-properties.md`. A property AWS published after the snapshot used to be silently dropped on SDK-provider types until the daily refresh PR merged, with only a warn. It now reaches AWS through Cloud Control the same day, like a known silent drop; the check is an offline table lookup, with no runtime `DescribeType`. A misspelled key on a new resource, or one newly added, now fails at Cloud Control with `Unsupported property`, as CloudFormation does; `--prefer-sdk-route <Type>:<Prop>` restores the drop. Unchanged for: a read-only key (CloudFormation ignores one), a type with no Cloud Control route, and a key an existing resource already carries with the same value — existing deployments keep their route. The warn for those now names which reason applies.
