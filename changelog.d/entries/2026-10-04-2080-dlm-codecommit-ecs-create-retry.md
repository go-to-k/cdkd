- **A DLM lifecycle policy or ECS task definition create that hits a 5xx now reports candidate orphans instead of duplicating silently (issue [#2080](https://github.com/go-to-k/cdkd/issues/2080), Plan C: `CreateLifecyclePolicy`, `RegisterTaskDefinition`, CodeCommit `CreateRepository` / `CreateCommit`; the SDK-5xx half of #3978 layer (b) for these creates)** -- `src/provisioning/providers/dlm-lifecycle-policy-provider.ts`, `ecs-provider.ts`, `codecommit-repository-provider.ts`. Neither DLM nor ECS create carries an idempotency token, so a 5xx whose request had succeeded left a second policy (still running its schedule) or an extra ACTIVE revision with no state record, unreported when the AWS SDK replayed it inside one call. Both now refuse the SDK's 5xx retry; cdkd's retry first lists what the failed attempt may have made -- policies with the same description and kind, or revisions of the same family, created in that attempt's window -- and warns with a read command, then a delete / deregister command to run only after confirming. Nothing is adopted or deleted; a throttle or 4xx triggers no lookup, and a failed lookup warns and lets the create proceed. A CodeCommit repository name cannot be duplicated, so its creates get only the 5xx-refusing client: a replayed collision is no longer credited to another holder, and a seed commit whose 5xx had succeeded no longer fails the deploy with `ParentCommitIdRequiredException`. A reset or timeout after the send is still retried inside the SDK. Tests: `tests/unit/provisioning/{dlm,ecs-task-definition,codecommit}-create-retry-2080.test.ts`.
