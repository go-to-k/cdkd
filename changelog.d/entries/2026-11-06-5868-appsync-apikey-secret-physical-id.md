- **An AppSync ApiKey's key no longer prints in deploy, rollback, destroy or `cdkd state` output (issue [#5868](https://github.com/go-to-k/cdkd/issues/5868))** -- `src/provisioning/secret-physical-id.ts` (new), `src/provisioning/providers/appsync/shared.ts`, `src/deployment/secret-name-needles.ts`, `src/deployment/deploy-engine/{replacement,update-replace,update-in-place}.ts`, `src/deployment/rollback-executor/replay-reverse-replacement.ts`, `src/cli/commands/state/{show,resources}.ts`, `docs/cli-state*.md`, `docs/stack-outputs.md`. The physical id of `AWS::AppSync::ApiKey` is `<apiId>|<apiKeyId>` (or the key's ARN on a record imported before #5540), and the key is the bearer credential. A replacement printed it at INFO in `Deleting old` / `Retaining old` / `was replaced: old -> new`, a rollback printed the re-created key, and `cdkd state show` / `state resources` (text and `--json`) printed it. One per-type declaration (`secretPhysicalIdSegment`) now names the key: every line printed under a resource's masking scope shows it as `***`, the engine lines naming an id no scope holds yet show `<apiId>|****last4`, and `cdkd state` shows every copy of a key the record holds as `****last4`, in other resources' properties, outputs, orphans, superseded copies and nested stacks too (a nested child's key in the parent row's outputs through the row's `secretNamedAttributes`, which a row not updated since gets on its next update). The state record and `cdkd export` keep the full key.
