- **`cdkd drift`, `state refresh-observed`, `orphan`, `import` and the `cdkd diff` / `cdkd deploy` attribute heal mask a physical name derived from a secret (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/cli/commands/{drift,state,orphan,import,diff-recursive}.ts`, `src/deployment/deploy-engine/heal.ts`. These hand a record to a provider with no printing bag bound. For a resource named from a secret, such as an IAM role whose `RoleName` is a `{{resolve:secretsmanager:...}}` reference, the provider's `--verbose` lines printed its physical id. So did a failed read's warning quoting AWS's error, and a resource reading the name (an instance profile's `Roles`). Each read now runs under the per-resource printing bag `cdkd drift --revert` and `cdkd destroy` bind: the record's own name spellings and those of each secret-named record it holds. `cdkd drift`'s report, `--json` and accept / revert plans mask such a name in a drifted row's path and its value's leaves and keys, keeping the value's shape; `--accept` still writes the raw value. `cdkd orphan` and `cdkd state orphan --resource` mask it in the rewrite, audit and unresolvable report. `cdkd import` masks a name its template takes from a secret in the read (an id from `--resource`, `--resource-mapping[-inline]` or `--migrate-from-cloudformation`) and the `Import plan:` listing. Display only. Judged from the records (for `import`, the template), so a `NoEcho`-derived name a pre-v11 record holds in plaintext is not recognised. Tests: `tests/unit/cli/*-secret-name-needles-3869.test.ts`, `tests/unit/deployment/deploy-engine-stale-attribute-heal.test.ts`. Integ `secret-derived-immutable-names` step 5k runs `cdkd orphan --dry-run` over a hand-added reference to the secret-named queue and fails when the log names it.
