- **`cdkd diff` shows an RDS Performance Insights key or replica source that is not resolved yet as the replacement CloudFormation makes it (issue [#7052](https://github.com/go-to-k/cdkd/issues/7052))** -- `src/analyzer/replacement-rules/rds-immutability.ts`. Since #7044 the `AWS::RDS::DBInstance` / `AWS::RDS::DBCluster` changes CloudFormation's RDS handler replaces show as replacements, but only when both values were plain strings: a `PerformanceInsightsKMSKeyId` moved to a `kms.Key` created in the same deploy (an unresolved `Fn::GetAtt` at diff time), and an instance whose key, replica source, restore input, zone or global cluster references a resource this deploy replaces, still showed as an update, and the deploy sent the moved value in place. An unresolved value now counts as a new, non-empty value that differs from the recorded one, as it does once resolved, and a reference to a replaced resource is a replacement the deploy lowers to an in-place update when the resolved value did not move. The instance is stateful, so the replacement is refused without `--force-stateful-recreation`. Setting a first key, promoting a read replica and leaving a global cluster stay in place.
