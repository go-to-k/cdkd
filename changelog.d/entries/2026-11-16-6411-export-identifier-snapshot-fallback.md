- **`cdkd export` reads a resource's import identifier from cdkd's offline schema copy when `DescribeType` cannot answer (issue [#6411](https://github.com/go-to-k/cdkd/issues/6411))** -- `src/cli/commands/export/type-schema.ts`. The export takes each resource's identifier from the type's registry schema. When `cloudformation:DescribeType` returned no usable schema, only a short built-in list of types was answered, and every other resource blocked the export. AWS Emulator's registry lacks many common types, so `cdkd export --aws-emulator` refused stacks with an HTTP API, a bucket policy or a layer; on AWS the same happened whenever `DescribeType` was denied. The export now falls back to the schema copy cdkd ships, which `cdkd deploy` already uses for the same gap. The refusal for a type that copy does not hold no longer asks you to edit cdkd's source.
