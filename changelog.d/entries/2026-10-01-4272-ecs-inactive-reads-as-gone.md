- **`cdkd drift` no longer compares a deleted ECS Cluster, Service or TaskDefinition that ECS still describes as `INACTIVE` (issue [#4272](https://github.com/go-to-k/cdkd/issues/4272))** -- `src/provisioning/providers/ecs-provider.ts`. ECS keeps describing a deleted resource for a while under a terminal status, and `readCurrentState` returned its properties whenever the name came back, so `cdkd drift` compared a resource deleted outside cdkd as if it still existed. The read now finds nothing for an `INACTIVE` cluster (the rule `importCluster` already applied), an `INACTIVE` service, and an `INACTIVE` or `DELETE_IN_PROGRESS` task definition revision; every other status (a `DRAINING` service, a `PROVISIONING` cluster, an unknown value) stays present. Drift lists such a resource as not supported rather than as deleted; a distinct "deleted" outcome is [#4283](https://github.com/go-to-k/cdkd/issues/4283). The task definition `import()` applies the same two statuses, so `cdkd import` with an explicit revision, orphan adoption after a rollback, and the stale-attribute heal now treat a deregistered revision as not found instead of adopting it.
