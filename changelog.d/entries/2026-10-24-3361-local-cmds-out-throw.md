- **A teardown failure that cannot be converted to text no longer stops the cleanup of `cdkd local invoke`, `cdkd local invoke-agentcore` or `cdkd local run-task`** (`src/cli/commands/{local-invoke,local-invoke-agentcore,local-run-task}.ts`, go-to-k/cdkd#3361). The cleanup handlers built their message with `x instanceof Error ? x.message : String(x)`, and `String()` throws for a null-prototype object, so the handler itself threw: on `invoke` and `invoke-agentcore` a failed container-log drain skipped the response write and stopped the cleanup before `docker rm -f`, and a failed `docker rm -f` skipped the remaining tmpdir and credentials removals and the stdio flush; on `run-task` a failed `cleanupEcsRun` skipped the credentials-file dispose that covers it, leaving the file behind. Each now goes through `describeAwsFailure(x).detail`, byte-identical whenever the value converts and a placeholder only when it cannot; the same rendering in those commands' `--event` / `--env-vars` read and parse errors and in `cdkd local start-api`'s WebSocket `error` log is converted too. Tests: `tests/unit/cli/{local-invoke-stdout-stream,local-invoke-agentcore-stdout-stream,local-run-task-command-body}.test.ts`.
