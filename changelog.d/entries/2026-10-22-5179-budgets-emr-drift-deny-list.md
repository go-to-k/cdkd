- **`cdkd drift` no longer reports false drift on an unchanged `AWS::Budgets::Budget`, or a permanent read failure on an `AWS::EMR::InstanceFleetConfig` / `InstanceGroupConfig` (issue [#5179](https://github.com/go-to-k/cdkd/issues/5179))** -- `src/analyzer/drift-cc-api-deny-list.ts`, `docs/cli-drift.md`, `tests/unit/cli/drift-per-resource-failure.test.ts`, `tests/integration/budgets/verify.sh`. cdkd has no read-back of its own for these three types, so drift asks Cloud Control. Cloud Control used to have no READ handler for them, and drift reported each one as drift unknown. AWS has since added handlers. For a budget, the response lists notification subscribers in a different order and adds the default `ThresholdType: PERCENTAGE`, so `NotificationsWithSubscribers` showed as drift on every run. For the EMR types, Cloud Control needs the cluster id together with the fleet or group id, and cdkd records only the latter. It refused every read, and drift exited 2. Drift now reports all three as drift unknown again and exits 0 for them.
