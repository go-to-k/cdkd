- **A failure that cannot be converted to text no longer turns a rollback or destroy handler into a crash of the whole run** (`src/deployment/rollback-executor/{replay-reverse-replacement,journaled-orphans,messages}.ts`, `src/cli/commands/destroy.ts`, go-to-k/cdkd#3361). These handlers built their message with `x instanceof Error ? x.message : String(x)` (or a bare `String(x)`), and `String()` throws for a null-prototype object, so the handler itself threw: a reverse replacement whose re-create, delete of the new resource, or delete of what a failed re-create made rejected that way aborted the rollback instead of failing or warning on that one op (and every op's failure line, `rollbackFailureText`, threw the same way); an unreadable rollback journal, or a failed journal rewrite after a successful deploy, threw instead of keeping the journal with a warning; `cdkd destroy --purge-events` threw instead of warning that the event history was not purged; and a synthesis failure in `cdkd destroy` threw a `TypeError` instead of falling back to the state's stack list. Each now goes through `describeAwsFailure(x).detail` (or `safeStringify(x)` for the bare form), byte-identical whenever the value converts and a placeholder only when it cannot. Tests: `tests/unit/deployment/rollback-executor-string-outthrow-3361.test.ts`, `tests/unit/cli/destroy-string-outthrow-3361.test.ts`.
