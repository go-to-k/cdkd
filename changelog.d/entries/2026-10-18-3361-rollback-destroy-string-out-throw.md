- **A failure that cannot be converted to text no longer turns a rollback or destroy handler into a `TypeError`** (`src/deployment/rollback-executor/{replay-reverse-replacement,journaled-orphans,messages}.ts`, `src/cli/commands/{destroy,rollback}.ts`, go-to-k/cdkd#3361). These handlers built their message with `x instanceof Error ? x.message : String(x)` (or a bare `String(x)`), and `String()` throws for a null-prototype object, so the handler itself threw. In a reverse replacement, a failed delete of the new resource after the old one was re-created failed the op instead of warning that the new resource is left untracked; a failed re-create, or a failed delete of what it made, failed the op with `Cannot convert object to primitive value` instead of the AWS failure; and a re-create rejecting that value aborted the whole rollback, because the per-op failure line (`rollbackFailureText`) threw too, as did `cdkd rollback`'s journal-backend error lines (`backendErrorText`). An unreadable rollback journal, or a failed journal rewrite after a successful deploy, threw instead of keeping the journal with a warning; `cdkd destroy --purge-events` threw instead of warning that the event history was not purged; and a synthesis failure in `cdkd destroy` threw instead of falling back to the state's stack list. Each now goes through `describeAwsFailure(x).detail` (or `safeStringify(x)` for the bare form), byte-identical whenever the value converts and a placeholder only when it cannot. Tests: `tests/unit/deployment/rollback-executor-string-outthrow-3361.test.ts`, `tests/unit/cli/destroy-string-outthrow-3361.test.ts`.
