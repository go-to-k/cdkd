- **`cdkd export`'s messages no longer put a state-record or template value inside cdkd's own quotes (issue [#3950](https://github.com/go-to-k/cdkd/issues/3950), partial)** -- `src/cli/commands/export.ts`, with paste cases and a fence in `tests/unit/cli/export-prose-quotes.test.ts`. 96 sites wrapped a stack name, a CloudFormation stack name, a logical id, a template path or a record value in a hand-written `'...'`, raw or through `safeSegment`, which keeps `'`, `$( )` and a space. A value carrying a `'` closed cdkd's quote, so pasting the sentence ran what followed it as shell: the nested-child refusal's head, measured by go-to-k/cdkd#3924's paste case and excluded there by name, was the first confirmed site, and that case now covers the whole message. Two of the 96 are the SSM-typed parameter refusal's stack names, added by go-to-k/cdkd#4058 in the file's existing shape. A plain value keeps its quotes and prints exactly as before, and an empty one still prints as `''`. Any other reads `(not shown: it is not a plain identifier)`. The nested-template read and parse refusals no longer append the underlying error's text: Node's read error echoes the path inside its own `'...'`, and the parser's echoes a snippet of the file. The read refusal prints the fs error code (`ENOENT`), and the parse refusal says the template cannot be parsed. The hand quotes that stay are listed with a reason and a count in the new fence, which scans a quote holding text beside the value too: cdkd's own literals and generated names, a field name from AWS's schema, and values the operator typed on the command line. `record-value-prose-quotes-fence.test.ts` drops `export.ts` from its allow-list.
