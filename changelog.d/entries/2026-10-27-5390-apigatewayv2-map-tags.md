- **`AWS::ApiGatewayV2::Api` and `AWS::ApiGatewayV2::Stage` now get their `Tags`, on create and update (issue [#5390](https://github.com/go-to-k/cdkd/issues/5390))** -- `src/provisioning/providers/apigatewayv2-provider.ts`. Both types take `Tags` as a key -> value map, which is what aws-cdk-lib synthesizes, but cdkd read it only as a `{Key,Value}` list, so every HTTP / WebSocket API and stage deployed untagged and reported success, and an update never tagged or untagged at all. `CreateApi` / `CreateStage` now carry the map, and an update tags new or changed keys and untags dropped ones through `TagResource` / `UntagResource`; removing the whole `Tags` block untags every key, as CloudFormation does (measured). A `Tags` that is neither a map of scalar values nor a `{Key,Value}` list is refused before any call. `cdkd drift` now reads both types' tags back as a map, so they compare against the template instead of reporting a list-versus-map difference. An API or stage deployed before this fix has none of its tags, and a deploy does not add them because the record already matches the template: `cdkd drift` reports them as missing and `cdkd drift --revert` applies them.
