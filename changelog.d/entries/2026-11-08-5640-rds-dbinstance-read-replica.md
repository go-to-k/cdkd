- **The SDK provider creates, promotes and deletes `AWS::RDS::DBInstance` read replicas (`SourceDBInstanceIdentifier`, issue [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds-provider.ts`, a new `src/provisioning/providers/rds/read-replica.ts` and the instance create, update, delete, readback and drift modules beside it, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, a read-replica arm in the `rds-dbinstance-backfill` integ, and `docs/cli-deploy.md`, `docs/provider-rules.md` and `docs/cli-destroy-guards.md`. Before, a read replica (CDK's `DatabaseInstanceReadReplica`) routed through Cloud Control. As CloudFormation's handler does, a create sends `CreateDBInstanceReadReplica` (resent once the source is `available` again when RDS refuses it as busy, as it does for the second of two replicas created together), reading the source's engine when the template names none, and, when the template declares a member that call cannot carry (a backup or maintenance window, `EngineVersion`, ...), sends those in one `ModifyDBInstance` once the replica is `available`, under `--no-wait` too. Removing the source promotes the replica in place (`PromoteReadReplica`); adding or changing it is refused before any change unless the live instance already replicates that source (same name, region and account). On the SDK route a live replica is deleted without a final snapshot, as RDS takes none; one promoted outside cdkd keeps it. A Cloud Control-routed replica under `DeletionPolicy: Snapshot` is still refused ([#6047](https://github.com/go-to-k/cdkd/issues/6047)). `cdkd drift` reads the source back. `SourceRegion` stays unwired.
