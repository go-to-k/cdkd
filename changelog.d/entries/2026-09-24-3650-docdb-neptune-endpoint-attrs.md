- **`Fn::GetAtt` of a DocDB / Neptune cluster or instance endpoint now resolves to the endpoint (issue [#3650](https://github.com/go-to-k/cdkd/issues/3650))** -- `src/provisioning/providers/{docdb,neptune}-provider.ts`, their unit tests, the new `tests/unit/provisioning/docdb-neptune-getatt-names.test.ts`, and `tests/integration/docdb-neptune/`. Both providers recorded only RDS-style dotted keys (`Endpoint.Address`, `Endpoint.Port`, `ReadEndpoint.Address`). CloudFormation names these attributes `Endpoint`, `Port` and `ReadEndpoint` for DocDB and Neptune. So on a normal `cdkd deploy`, `Fn::GetAtt [Cluster, Endpoint]` warned `Unknown attribute` and resolved to the cluster **identifier**. That is what CDK's `clusterEndpoint` reads, so an application got a connection host that is not a hostname. The providers now record the CloudFormation names in `create()`, `update()` and `import()`, and keep the dotted keys. A record written before the fix heals on the next `cdkd deploy`: the miss triggers the stale-attribute re-read ([#1852](https://github.com/go-to-k/cdkd/issues/1852)), which now reports these names. The cluster `import()` also returns these attributes, where it returned none ([#3627](https://github.com/go-to-k/cdkd/issues/3627)).
