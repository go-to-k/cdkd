- **The SDK provider sends the storage, backup, maintenance, option group, certificate and Performance Insights settings of `AWS::RDS::DBInstance` (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and new arms in the `rds-dbinstance-backfill` integ. Before, a DB instance declaring any of `BackupRetentionPeriod`, `PreferredBackupWindow`, `PreferredMaintenanceWindow`, `StorageType`, `Iops`, `StorageThroughput`, `MaxAllocatedStorage`, `MultiAZ`, `AutoMinorVersionUpgrade`, `CopyTagsToSnapshot`, `OptionGroupName`, `CACertificateIdentifier`, `EnablePerformanceInsights`, `PerformanceInsightsKMSKeyId` or `PerformanceInsightsRetentionPeriod` routed through Cloud Control. They now ride `CreateDBInstance`, and `ModifyDBInstance` when the template changes them, following CloudFormation's handler: a removed one keeps its live value, except a removed `MaxAllocatedStorage`, which turns storage autoscaling off. On provisioned-IOPS storage a storage change sends `Iops` with `AllocatedStorage`, and the Performance Insights flag, key and retention travel together as CloudFormation sends them. `AllocatedStorage` is now sent only when it changed: re-sending it on every update failed once autoscaling had grown the storage. `DBParameterGroupName` still routes through Cloud Control: CloudFormation reboots the instance to apply a new parameter group.
