- **A `cdkd destroy` failure that is a value JavaScript cannot stringify is now REPORTED as itself, instead of as a `TypeError` (issue [#3348](https://github.com/go-to-k/cdkd/issues/3348))** -- `src/cli/commands/destroy-runner.ts` (9 sites), `src/deployment/retry.ts` (`withRetry`), `src/deployment/retryable-errors.ts` (`retryClassificationText`), `src/provisioning/final-snapshot.ts` (`errMsg`), `src/types/deployment-events.ts` (`extractDeploymentEventError`). `String(value)` THROWS for a null-prototype object or a hostile / `null` `toString`, and every one of these sites sits inside a catch that is already the LAST handler. They sit in and around the per-resource catch of the `level.map(...)` that `Promise.all` awaits, and its retry loop stringifies first -- so a hostile value became a `TypeError` and the `RESOURCE_FAILED` row named `TypeError: Cannot convert object to primitive value` rather than the AWS failure. Measured: the run is NOT abandoned -- a `TypeError` is an `Error`, so handlers below take the `Error` branch. Guarding any one leaves an earlier one throwing first, which is why all five are here -- and `withRetry` wraps every provider op, so `cdkd deploy` / `rollback` / `import` gain the same honesty. The remaining seven are the lock-release, client-teardown and state-persist arms of the same command, where an out-throw strands a lock or loses the record of what was already deleted. The ternary becomes `describeAwsFailure(err).detail`, byte-identical -- so the "not found means already deleted" prose matcher and every retry classifier read what they read before -- and the two bare forms become `safeStringify(err)`, keeping the error's `name`. A value that cannot be converted is now RECORDED as `a value that could not be converted to text`. The sibling population is tracked by issues [#3361](https://github.com/go-to-k/cdkd/issues/3361) and [#3341](https://github.com/go-to-k/cdkd/issues/3341).
