- **`Fn::Select` now resolves its index, and a state record with a non-string physical id is refused instead of crashing the resolver (issues [#3574](https://github.com/go-to-k/cdkd/issues/3574), [#3576](https://github.com/go-to-k/cdkd/issues/3576))** -- `src/deployment/intrinsic-function-resolver.ts` (`resolveSelect`, new `selectIndexPosition` / `lookupResourceRecord`), comment updates in `src/cli/commands/import.ts` and `src/utils/error-handler.ts`, two new unit files and a new `intrinsics-torture-2` arm. The `Fn::Select` index was used exactly as written: a `Ref` to a parameter or an `Fn::FindInMap` index (both valid CloudFormation) selected `undefined` with no warning, and a non-numeric string read the list's prototype chain (`"constructor"` gave the `Array` function). The index is now resolved and must be a non-negative integer or its decimal string (no leading zero); anything else, a negative index included, is refused with a message naming the value and its source. An integer past the end still warns and yields the `{{Fn::Select:<n>:OutOfBounds}}` placeholder, unless the index came from a secret, which is refused rather than written into that property value; an operand that is not a two-element list is refused rather than destructured. Separately, a hand-edited or foreign-written state record whose `physicalId` is not a string (or that is not an object) made several `Ref` / `Fn::GetAtt` arms throw a bare `TypeError`; the resolver now refuses such a record once, where it reads it, naming the logical id, before any AWS call.
