- **A container-image Lambda function (`PackageType: Image`) declaring `CodeSigningConfigArn` or `RuntimeManagementConfig` is now refused by cdkd before any Lambda call (issue [#1894](https://github.com/go-to-k/cdkd/issues/1894))** -- `src/provisioning/providers/lambda-function-provider.ts` (`refuseImageFunctionUnsupported`, called from `create` and `update`), `tests/unit/provisioning/lambda-image-function-refusal.test.ts`, `tests/unit/provisioning/lambda-function-props-609.test.ts`, and a new phase in `tests/integration/docker-image-asset/`. AWS rejects both properties on an image function with `InvalidParameterValueException`: the image carries its own runtime, and Lambda code signing does not apply to images. cdkd sent them anyway, so the deploy failed on AWS's rejection -- for `RuntimeManagementConfig` on create, only after creating the function and deleting it again. The deploy now fails at once with a message naming the property to remove, on both create and update. This matches the read side, which since #1890 skips the two matching `Get*` calls for an image function: that saves two calls per readback and the two warnings each drift snapshot of an image function used to print. The fixture now runs `cdkd drift` on its image function and expects a clean result with neither warning.
