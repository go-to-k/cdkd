- **Removing a Cognito user pool's MFA factors under `MfaConfiguration: OFF` now clears them (issue [#7128](https://github.com/go-to-k/cdkd/issues/7128))** -- `src/provisioning/providers/cognito/{update,mfa-apply,mfa-request}.ts`. Setting a pool from `mfa: Mfa.OPTIONAL, mfaSecondFactor: { otp: true }` back to `mfa: Mfa.OFF` turned MFA off but left the software-token factor enabled, and `cdkd drift` reported the pool clean. As in CloudFormation, an update that drops every MFA factor, email-OTP message and WebAuthn property while MFA resolves to `OFF` now also sends `SetUserPoolMfaConfig` with `OFF` and no factor block, which resets them while carrying the pool's live WebAuthn configuration (a passkey pool keeps its relying party, as in CloudFormation); the same reset now carries it on the `MfaConfiguration` removal path too. The same applies to a rollback replay and `cdkd drift --revert`. A pool updated by an earlier release keeps the factor, which `cdkd drift` cannot see yet ([#7134](https://github.com/go-to-k/cdkd/issues/7134)).
