- **Subnet `AvailabilityZoneId` and IPAM allocation use the SDK route** (#5632). `EC2Provider` sends `AvailabilityZoneId`, `Ipv4IpamPoolId`, `Ipv4NetmaskLength`, `Ipv6IpamPoolId` and `Ipv6NetmaskLength` on `CreateSubnet`, so a subnet declaring any of them no longer routes through Cloud Control. A subnet may now omit `CidrBlock` when it names an IPv4 pool. A malformed value is refused before any call, a rollback replay included. All five are create-only: `cdkd drift --revert` refuses a change to one. The create records `CidrBlock`, `AvailabilityZoneId` and `VpcId` attributes, so `Fn::GetAtt` on them returns the subnet's values instead of its id, and `cdkd import` records the same. Drift reads back the zone id and each declared netmask; the pool ids are declared unreadable. A string netmask compares equal to its integer, the VPC's too. Deleting a pool-allocated subnet waits for each pool to release its allocation, and an ambiguous pool-allocated create reports the pool's other subnets in the VPC as possible orphans. The `sdk-to-cc-autoroute` fixture's create-only phases move from the subnet's `AvailabilityZoneId` to an EFS access point's `ClientToken`.
