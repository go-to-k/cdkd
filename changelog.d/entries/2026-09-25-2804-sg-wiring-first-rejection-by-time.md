- **A security group whose ingress AND egress wiring both fail now reports the failure that happened first (issue [#2804](https://github.com/go-to-k/cdkd/issues/2804))** -- `src/provisioning/providers/ec2-provider.ts` (`createSecurityGroup`), `tests/unit/provisioning/providers/ec2-provider.test.ts`. The create wires tags, inline ingress and inline egress concurrently and waits for all three before deleting the half-wired group. When two of them failed, cdkd reported whichever came first in its own call list (ingress over egress), not the one that failed first, and the retry classifier read that message too. The create still fails and the group is still deleted; what changes is which of the two genuine errors you see, and so whether the retry classifier treats it as transient.
