- **`cdkd local run-task` / `cdkd local invoke` now refuse secret names that would hijack a podman, nerdctl or finch client, not only a docker one (issue [#2188](https://github.com/go-to-k/cdkd/issues/2188))** -- `src/utils/docker-cmd.ts`, the collision warnings in `src/local/docker-runner.ts` / `ecs-task-runner.ts` / `ecs-network.ts`, `docs/local-run-task.md`, plus tests. `DOCKER_CLIENT_ENV_KEYS` (from #2186) listed only the docker CLI's variables, so under `CDK_DOCKER=podman` a resolved secret named `CONTAINER_HOST` reached the client's environment and could redirect it -- the `DOCKER_HOST` hijack, one binary over. The list now also covers podman / containers tooling (`CONTAINER_HOST`, `CONTAINER_CONNECTION`, `CONTAINER_SSHKEY`, `CONTAINER_PROXY`, `PODMAN_CONNECTIONS_CONF`, `CONTAINERS_SSH_CONF`, `CONTAINERS_CONF`, the registries / storage config files and their `_OVERRIDE`s, `CONTAINERS_POLICY_JSON`, `STORAGE_OPTS`, `CONTAINERS_HELPER_BINARY_DIR`, `REGISTRY_AUTH_FILE`, `DBUS_SESSION_BUS_ADDRESS`, `NOTIFY_SOCKET`), nerdctl (`CONTAINERD_ADDRESS`, `CONTAINERD_NAMESPACE`, `NERDCTL_TOML`, `NERDCTL_LOG_FILE`, `CNI_PATH`, `NETCONFPATH`, `ROOTLESSKIT_STATE_DIR`), finch's Lima layer (`SSH`, which Lima execs in place of `ssh`), the base directories they fall back to (`XDG_CONFIG_HOME`, `XDG_RUNTIME_DIR`, and on Windows `APPDATA`, `PROGRAMDATA`, `PROGRAMFILES`, `LOCALAPPDATA`), and `AWS_ECR_CACHE_DIR`. The JSDoc states the rule for additions; behaviour toggles such as `STORAGE_DRIVER` and `CONTAINERD_SNAPSHOTTER` stay off. A colliding secret is dropped with the existing warning, now worded for any container client; the operator's own value of each variable is untouched.
