- **`cdkd local run-task` / `cdkd local invoke` now refuse secret names that would hijack a podman, nerdctl or finch client, not only a docker one (issue [#2188](https://github.com/go-to-k/cdkd/issues/2188))** -- `src/utils/docker-cmd.ts`, `docs/local-run-task.md`, plus tests. `DOCKER_CLIENT_ENV_KEYS` (from #2186) listed only the docker CLI's variables, so under `CDK_DOCKER=podman` a resolved secret named `CONTAINER_HOST` reached the client's environment and could redirect it to another service -- the `DOCKER_HOST` hijack, one binary over. The list now also covers podman / containers tooling (`CONTAINER_HOST`, `CONTAINER_CONNECTION`, `CONTAINER_SSHKEY`, `PODMAN_CONNECTIONS_CONF`, `CONTAINERS_CONF`, `CONTAINERS_CONF_OVERRIDE`, `CONTAINERS_REGISTRIES_CONF`, `REGISTRIES_CONFIG_PATH`, `CONTAINERS_STORAGE_CONF`, `STORAGE_OPTS`, `CONTAINERS_HELPER_BINARY_DIR`, `REGISTRY_AUTH_FILE`, `DBUS_SESSION_BUS_ADDRESS`), nerdctl (`CONTAINERD_ADDRESS`, `CONTAINERD_NAMESPACE`, `NERDCTL_TOML`, `CNI_PATH`, `NETCONFPATH`, `ROOTLESSKIT_STATE_DIR`), the base directories they fall back to (`XDG_CONFIG_HOME`, `XDG_RUNTIME_DIR`, and on Windows `APPDATA`, `PROGRAMDATA`, `LOCALAPPDATA`), and `AWS_ECR_CACHE_DIR`, where `docker-credential-ecr-login` writes the ECR token. The JSDoc now states the rule for additions. Behaviour toggles such as `STORAGE_DRIVER`, `CONTAINERD_SNAPSHOTTER` and `TMPDIR` are deliberately left off. A colliding secret is dropped with the existing warning; the operator's own value of each variable is untouched.
