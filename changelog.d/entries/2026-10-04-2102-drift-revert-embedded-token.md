- **`cdkd drift --revert` keeps AWS's value at a `{{resolve:...}}` token cdkd cannot resolve when the token is EMBEDDED in a longer string (issue [#2102](https://github.com/go-to-k/cdkd/issues/2102))** -- `src/cli/commands/drift.ts`, `src/deployment/secret-redaction/unresolved-token-frame.ts`. A revert triggered by another drifted key preserved the live value only where a property's WHOLE value was the token; a token inside a longer string (`jdbc:...password={{resolve:...}}`), or beside a secret cdkd resolved, shipped the literal token and overwrote what AWS held. The live string is now kept when it equals the payload at every character outside the unresolved tokens' spans, resolved secrets included, so a secret rotated since the last deploy is never copied into the payload; otherwise the token ships as before. Both drift warnings say so. Also, a resolved secret that `cdkd drift` discards after a later reference on the same resource fails to resolve stays masked in the resource's comparison-failure warning. Tests: `tests/unit/cli/drift-unresolved-token-frame.test.ts`, `tests/unit/cli/drift-masked-leaf-preserve.test.ts`, `tests/unit/cli/drift-secret-redaction.test.ts`.
