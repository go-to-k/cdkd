- **`cdkd drift` now warns on a stack whose state predates the refused-baseline marker (issue [#3011](https://github.com/go-to-k/cdkd/issues/3011))** -- `src/cli/commands/drift.ts`, `tests/unit/cli/drift.test.ts`, `docs/cli-drift.md`. **Bug:** (#2952)'s detection gate keys on `ResourceState.observedBaselineRefused`, which only a v10-or-later binary could have written. The import refusal ((#2842), widened by (#2850)) shipped in released 0.288.x, so a stack adopted by one of those carries the same untrustworthy `properties` with NOTHING marking them -- the gate does not fire, drift compares it, and because a refused record spells no `{{resolve:` for the redaction to key on, the live decrypted value is printed. The marker cannot reach that population by construction, and widening the gate to bare `observedProperties === undefined` would sweep in every pre-observed-capture record. **Fix:** `warnIfPreV10BaselineGap` prints ONE warning per stack when the loaded state is below schema v10 AND some resource drift actually COMPARED has no drift baseline (a `skipped` or `unsupported` resource is never compared, so it cannot carry the disclosure), naming the stack, the region and those resources. **The condition is exact, not a heuristic:** `version < 10` is precisely "cdkd could not have recorded a refusal here, whatever it did"; a v10 record omitting the field is one nothing refused. No behaviour or exit-code change; a version-less record reads as older than v10. **The warning explicitly says it is not a repair signal** -- `saveState` stamps the current version unconditionally, so any write (this run's `--accept` / `--revert`, or a NO_CHANGE deploy whose baseline refresh then refills those resources FROM the untrustworthy properties) silences it while the records stay broken; only a re-import, or a deploy that CHANGES a listed resource, repairs one. **Cost:** one line on a pre-v10 stack never imported -- a warning, not a refusal, which is the direction to err in.
