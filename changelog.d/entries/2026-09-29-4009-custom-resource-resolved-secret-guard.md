- **A custom-resource handler is never sent a secret's plaintext, including on routes the template does not show (issue [#4009](https://github.com/go-to-k/cdkd/issues/4009))** -- `src/provisioning/providers/custom-resource-provider.ts` (`refuseResolvedSecret`), `findResolvedSecretPaths` in `src/provisioning/custom-resource-secure-references.ts`, unit cases, a new `custom-resource-resolved-secret` integ fixture, `docs/troubleshooting.md` and `.claude/rules/provider-custom-resources.md`. The #3976 pre-flight refuses a secure dynamic reference SPELLED in a custom resource's template; three routes still resolved a secret into the handler's event: a plain `{{resolve:ssm:...}}` naming a SecureString parameter, a nested child reading a parent parameter the parent filled from a secret, and a rollback replay re-resolving an older record. `create` / `update` now refuse, non-retryable and before the invoke, when this resource's resolution recorded a secret at all (the bag the deploy engine, the rollback replay and the nested child engine bind), so a derived form such as base64 is refused too, on either side of an update (`cdkd rollback --revert-failed` replays a failed update's attempted properties as `OldResourceProperties`); the error names property paths only. A `NoEcho` value is not a secret here and still reaches a dependent, as in CloudFormation. BEHAVIOUR CHANGE: a stack whose custom resource reads a SecureString through a plain `ssm` reference, or a secret through a nested stack parameter, fails its next create or update of that resource until the handler reads the value itself.
