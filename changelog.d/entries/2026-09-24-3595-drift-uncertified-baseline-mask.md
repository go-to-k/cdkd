- **`cdkd drift` reports a baseline position it could not certify as not compared, not as drift (issue [#3595](https://github.com/go-to-k/cdkd/issues/3595))** -- `src/cli/commands/drift.ts` (new `partitionUncertifiedBaselineChanges`, new `uncertifiedBaseline` cause, the `--accept` refusal wording), `src/deployment/secret-redaction.ts` (new `isUncertifiedBaselineMaskPosition`), `src/analyzer/drift-calculator.ts` (new `equalModuloMask`), `docs/cli-drift.md`, a new unit file and a re-pinned `secrets-array-nested` integ stop. Where the recorded drift baseline holds the redaction mask `***` because cdkd could not pair a secret reference with the value AWS reported (issue #2852), no live value ever equalled it, so the resource read `drifted` (exit 1) on every run. When the mask is the only difference at that position, the resource is now listed under `notCompared` with the cause `uncertifiedBaseline` and a detection-only run exits 2; any other difference there -- an edited neighbouring value, a changed length or order -- and every change elsewhere on the resource are still reported as drift. `--revert` sends AWS's own value at such a position instead of refusing the resource when a real change shares its property. A `NoEcho` custom-resource mask (issue #2274) is unchanged. `--accept`'s refusal of a masked position now says that only a deploy that changes the resource re-captures the baseline, instead of a bare "Re-deploy to refresh it".
