- **`cdkd drift`'s legacy region-less refusal no longer interpolates a state-key stack name into the `cdkd deploy` it tells you to paste (issue [#3307](https://github.com/go-to-k/cdkd/issues/3307))** -- `src/cli/commands/drift.ts`, tests. That refusal built its command from `listStacks`'s stack name -- an S3 KEY -- with no sanitizing, quoting or exactness gate, inside a prose `'...'`. Pasting the span RAN the key: `a; echo INJECTED; #` became a second command, and a name sanitizing ALTERS addresses a different record. A new `stackCommandFor` gates it: sanitize (`asciiOnly`) and compare against the RAW value, refuse an empty one, cap at `STACK_REF_MAX_CODE_POINTS` (a legitimate `Parent~Child~...` still renders), shell-quote, and refuse a name the COMMAND would read as something else -- a leading `-` is an option, `*` / `/` are patterns to `cdkd deploy`. `stackIdentityLine` puts the identity on a gated `Stack:` line rather than in the sentence, since a name carrying a newline printed above a labelled line FORGES one, and `displayIdent`'s JSON quotes would not stop a `$(...)` name either -- double quotes do not close command substitution. Withheld, the message names every reason the gate has and sends the operator to `cdkd state list --json`. **This is the only labelled command line `cdkd drift` prints, deliberately**: the other three pasteable commands sit in blocks that also carry a property path, a resource type or an AWS readback value, which cannot be gated for exactness and still printed -- so a labelled line there would be a trusted shape beside an untrusted one. Those keep their command in prose, and the class, with the criterion, is [#3436](https://github.com/go-to-k/cdkd/issues/3436).
