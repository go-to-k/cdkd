- **`cdkd drift`'s legacy region-less refusal no longer interpolates a state-key stack name into the `cdkd deploy` it tells you to paste (issue [#3307](https://github.com/go-to-k/cdkd/issues/3307))** -- `src/cli/commands/drift.ts`, tests. That refusal built its command from `listStacks`'s stack name -- an S3 KEY -- with no sanitizing, quoting or exactness gate, inside a prose `'...'`. Pasting the span RAN the key: `a; echo INJECTED; #` became a second command, and a name sanitizing ALTERS addresses a different record. A new `stackCommandFor` gates it: sanitize (`asciiOnly`) and compare against the RAW value, refuse an empty one, cap at `STACK_REF_MAX_CODE_POINTS` (a legitimate `Parent~Child~...` still renders), shell-quote, and refuse a leading `-` or, for `cdkd deploy`, a `*` / `/` pattern. `stackIdentityLine` puts the identity on a gated `Stack:` line rather than in the sentence: a name carrying a newline above a labelled line FORGES one, and `displayIdent` would have closed only that half -- it collapses the newline, but a `$(...)` name comes back inside its JSON quotes intact and double quotes do not stop substitution. Withheld, the message states the rule and sends the operator to `cdkd state list --json`. **This is the only labelled command line `cdkd drift` prints, deliberately**: the other three sit in blocks that also carry a property path, a resource type or an AWS readback value, which cannot be gated for exactness and still printed. Those keep their command in prose, and the class, with the criterion, is [#3436](https://github.com/go-to-k/cdkd/issues/3436) -- but they DID change for every user: the stack name came out of the quoted command, so `Run 'cdkd drift MyStack --revert'` is now `Run 'cdkd drift --revert' for this stack` and `cdkd state refresh-observed TestStack` is now `'cdkd state refresh-observed' for this stack`. A grep matching the old spelling breaks; `cdkd drift --revert` with no positional argument auto-detects a single stack.
