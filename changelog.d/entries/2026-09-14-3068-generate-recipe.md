- **`GenerateSecretString` now honours `IncludeSpace` and `RequireEachIncludedType`, draws from the service's punctuation set, and refuses what Secrets Manager refuses (issue [#3068](https://github.com/go-to-k/cdkd/issues/3068))** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`, `tests/unit/provisioning/secretsmanager-secret-provider-update-value-source.test.ts`. The password is minted LOCALLY (never read back -- the premise the #2212 fence protects), so the recipe is whatever cdkd implements, and it diverged from `GetRandomPassword` four ways: two declared members were never read (`IncludeSpace`; `RequireEachIncludedType`, whose service default is TRUE, so a short password could miss a class), the punctuation class was a 26-character subset of the service's 32 (an `ExcludeCharacters` naming `"` `'` `/` `\` backtick `~` was inert), and a fully excluded charset fell back to lowercase the template had excluded. **Now:** one `generateCharset` function serves the member predicate and the generator; the space is admitted under `IncludeSpace` (and taken back by `ExcludeCharacters`); under `RequireEachIncludedType` one character of every included class is PLACED at a random position, so the guarantee holds per draw at any length; draws are uniform (rejection sampling replaces `byte % n`). Three refusals, each measured on CloudFormation rather than read off the docs: `PasswordLength` below the number of required classes (`Password length is too short based on the required types`), a REQUIRED class emptied by `ExcludeCharacters` (`All characters of the desired type have been excluded` -- with `RequireEachIncludedType: false` the same template creates, so the rule is scoped to required classes), and an empty pool (`All characters have been excluded from selection`). On the create path a refusal throws; on the update path it is the same SKIP the other members take, with the previous block retained.
