- **`cdkd drift` compares an `AWS::ECR::Repository`'s `RepositoryPolicyText` and no longer reports `EmptyOnDelete` (issue [#6631](https://github.com/go-to-k/cdkd/issues/6631))** -- `src/provisioning/providers/ecr-provider.ts`, new `src/provisioning/providers/ecr/read-state.ts`, the `ecr-scanning` integ fixture. The repository read never called `GetRepositoryPolicy`, so a policy changed or deleted out of band was never reported and `--revert` did not restore it, and on the template-only baseline (`--no-capture-observed-state`, or a failed capture) an untouched repository reported both keys as drift. When the template declares a policy, the read now returns it JSON-parsed (`RepositoryPolicyNotFoundException` is "no policy"; any other failure fails the read); a policy the template does not declare is not read or compared, since Lambda can write one itself, and `EmptyOnDelete`, a delete-time flag AWS stores nowhere, is never compared. The deploy's post-write capture re-reads a lagging answer as the other policy readers do, and runs its lifecycle, policy and tag reads concurrently. For a repository declaring a policy, a baseline captured before this change has no `RepositoryPolicyText` and keeps not comparing it until the repository is next updated or `cdkd state refresh-observed` re-captures it. Drift now needs `ecr:GetRepositoryPolicy` on a repository whose template declares a policy.
