- **`AWS::RDS::DBCluster`: `DBInstanceParameterGroupName` now deploys on the SDK route (issue [#5639](https://github.com/go-to-k/cdkd/issues/5639))** -- `src/provisioning/providers/rds/cluster-members.ts`. A cluster declaring it no longer goes through Cloud Control. As in CloudFormation's handler, an update sends it with `EngineVersion` and `AllowMajorVersionUpgrade` only when `EngineVersion` changed and the template changed the parameter group too; RDS then applies it to every instance during a major upgrade, and refuses it beside a minor one (`InvalidParameterCombination`), as it refuses CloudFormation's identical request. A create never sends it (CreateDBCluster has no such parameter), and neither does a change without an engine-version change, a removal, or a rollback. A value that is not a string is refused before any call. `cdkd drift` does not compare it: RDS never reports it.
