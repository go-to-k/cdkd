- **A piece of a `NoEcho` parameter's value no longer prints: an `Fn::Split` of it, or a nested child's list parameter split out of it (issue [#4049](https://github.com/go-to-k/cdkd/issues/4049))** -- `src/deployment/intrinsic-function-resolver.ts`, `src/deployment/secret-redaction.ts` (`recordLogOnlySplitFragments`, `carryLogOnlyValuesCarriedBy`). Before, `Fn::Split` over a `NoEcho` value printed each piece on the `--verbose` `Resolved Fn::Split` line, and a resource consuming a piece had it in the clear in its provider's warn and retry lines, the deploy's error, the `deployments/*.jsonl` event and the `cdkd diff` row. A nested child declaring a `CommaDelimitedList` (or other list) parameter fed the parent's `NoEcho` string printed each element the same way. Each piece's share of the value is now masked on those surfaces, like the value itself, including a stored piece `cdkd diff` shows for a property that stopped reading it. A piece shorter than 4 characters is masked only where it is the whole text, and a piece masks any equal text, which can over-mask unrelated values. An `Fn::Split` by an empty delimiter prints its pieces as `***` on its own line, but an `Fn::Join` over them still prints the characters. Nothing cdkd persists changes: `state.json` is byte-identical with or without `NoEcho`. One publication verdict reads these pieces too: an `Export.Name` equal to a piece, or embedding one of 4 or more characters, is refused, as a name holding the whole value already is. Tests: `tests/unit/deployment/noecho-split-fragments-4049.test.ts`, `tests/unit/cli/diff-noecho-split-4049.test.ts`.
