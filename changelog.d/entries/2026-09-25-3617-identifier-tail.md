- **Template-, state- and manifest-chosen names render inside a boundary of their own in the remaining resolver, state, lock, provider, local-run and asset messages (issue [#3617](https://github.com/go-to-k/cdkd/issues/3617))** -- `Fn::GetStackOutput`'s refusals and the region guard that refuses to build AWS clients for an invalid region, `cdkd scrub`'s secret-bearing output-key and Export.Name warnings (a masked key that still carries non-ASCII is now withheld rather than shown), the macro-expansion parameter-type warning, the S3 lifecycle-rule warnings, `cdkd local run-task`'s docker build and re-tag failures and secret refusals, the asset-manifest passthrough warnings, the custom-resource region-correction line, `cdkd orphan --force`'s unreadable-attributes warning, and the state and lock messages printed stack names, output names, regions, rule ids, container names, keys and commands inside cdkd's own `'...'`, through sanitizers that pass `'`; a crafted name could close the quote and write a clause of its own. Each now renders through `displayIdent` (a stack name through `displayStackName`, a command path through `displayAssemblyPath`): bare when plain (`Fn::GetStackOutput: stack Producer not found in region us-east-1`), otherwise as one JSON string. A masked name is masked first and bounded after. The read failures for a nested template (on deploy and on `cdkd diff`), a stack template and a stack metadata file no longer repeat the path inside Node's own `open '...'` text, which is shown as `open '<path>'` since the message already names the path, bounded; a parse failure there reads `invalid JSON` rather than echoing a window of the file's bytes.
