- **`AWS::BedrockAgentCore::Runtime` keeps the SDK route for `CapacityProviderConfiguration`, `FilesystemConfigurations`, `PlatformVersion`, `RequestHeaderConfiguration` and `Tags` (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762)).** A runtime declaring any of them used to go through Cloud Control. The first four ride on `CreateAgentRuntime` / `UpdateAgentRuntime`; `UpdateAgentRuntime` replaces the whole configuration, so removing one from the template clears it, as the runtime's other fields already were. `Tags` (a key -> value map, keys sent verbatim) is sent on create, read back after it and set again with `TagResource` where the new runtime lacks one (AWS was observed dropping create-time tags), and diffed with `TagResource` / `UntagResource` on update, removal included; a malformed `Tags`, or one holding a reserved `aws:` key, is refused before any call. All five are read back for `cdkd drift`; reading `Tags` back needs `bedrock-agentcore:ListTagsForResource`, and changing them needs `bedrock-agentcore:TagResource` / `UntagResource`. Source: `src/provisioning/providers/agentcore-runtime-provider.ts`.
