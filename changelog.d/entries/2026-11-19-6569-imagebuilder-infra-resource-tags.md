- **An Image Builder infrastructure configuration without `resourceTags` now updates (issue [#6569](https://github.com/go-to-k/cdkd/issues/6569))** -- `src/provisioning/cc-read-back-empty-keys.ts`, `src/provisioning/cloud-control/update.ts`, unit tests and the `imagebuilder-infra-update` integ fixture. `AWS::ImageBuilder::InfrastructureConfiguration` goes through Cloud Control, whose read model for a configuration created without `ResourceTags` carries `"ResourceTags": {}`. Cloud Control applies the update patch on top of that model, so every update, on `cdkd deploy` and on `cdkd drift --revert`, sent the empty map and failed with `resourceTags length must satisfy min_items 1`, while CloudFormation updated the same change in place. A Cloud Control update of a type listed in the new per-type table now adds `remove /<key>` for a key the live model holds empty and the desired properties leave out or hold empty, and an `add` / `replace` of an empty value there becomes a `remove`; the live model is read for a listed type only, so no other type's update sends an extra `GetResource`, and a listed type's update whose patch also carries a nested create-only or read-only gap reads it once, not twice ([#6581](https://github.com/go-to-k/cdkd/issues/6581)).
