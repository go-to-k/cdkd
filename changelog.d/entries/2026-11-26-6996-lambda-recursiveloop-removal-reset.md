- **`cdkd deploy`: removing `recursiveLoop` from a Lambda function resets it to `Terminate`, as CloudFormation does (issue [#6996](https://github.com/go-to-k/cdkd/issues/6996))** -- `src/provisioning/providers/lambda-function-provider.ts`. A function deployed with `recursiveLoop: lambda.RecursiveLoop.ALLOW` kept `Allow` after the property was removed from the template, so Lambda's recursive-loop detection stayed off; the deploy only warned that cdkd left the value in place. CloudFormation resets it to `Terminate` (measured on an A/B stack). The Lambda provider now declares `Terminate` as the property's removal default, so the update sends it through `PutFunctionRecursionConfig` and the warning no longer fires. A removal from a function already at `Terminate` sends nothing. Tests: `tests/unit/provisioning/lambda-function-provider.test.ts`; integ `lambda-config-field-removal`.
