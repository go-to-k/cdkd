- **A failed or resumed reader of a regenerated secret is restored with the secret's new value (issue [#6597](https://github.com/go-to-k/cdkd/issues/6597))** -- `src/deployment/deploy-engine/rollback/perform.ts`, `src/deployment/rollback-executor/{regenerated-secrets,replay-completed,replay-failed,replay-failed-checks,replay-secrets,types}.ts`, `src/deployment/deploy-engine/rollback/unsettled-revert.ts`, `src/cli/commands/rollback/replay.ts` and unit tests. Following #6591, two more rollback paths left a resource reading a Secrets Manager secret through a `{{resolve:secretsmanager:...}}` reference with the password from before a deploy that regenerated the secret (`GenerateSecretString` changed): the resource whose own update failed (for example a Lambda update refused after the secret's update), which the automatic rollback reverted before the secret, and a reader that a `cdkd rollback` re-run restored after an earlier run had already restored the secret. The automatic rollback and `cdkd rollback --revert-failed` now revert such a failed update after the secret (unless its attempt used a resource the same deploy created, which the rollback deletes), and both resolve the reference to the secret's current value, as CloudFormation's rollback does.
