- **Docker asset publishing now logs in to the registry it pushes to (issue [#3681](https://github.com/go-to-k/cdkd/issues/3681))** -- `src/assets/docker-asset-publisher.ts`, its unit tests, `docs/architecture.md`. After a push failed auth, the ECR login targeted `GetAuthorizationToken`'s `proxyEndpoint`, which names the CALLER's default registry. That matched the push host only while the push account was the caller's own; a push to any other registry would have logged in to the wrong host and failed again with `no basic auth credentials`. The push URI and the `docker login` endpoint are now built from one registry host, the rule `cdkd local *` already follows on the pull side (#3670). Because the ECR password now goes to that host, a destination region in the asset manifest that is not a single DNS label (`x.example.com`, `us-east-1/x`), or an account id that is not 12 digits, is refused before any AWS or docker call for that destination. The per-process login cache is gone: every login followed a failed push and bypassed it, so it never skipped one; the push-first path and docker's own credential store are what avoid repeat logins.
