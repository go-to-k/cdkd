- **`AWS::S3::Bucket`'s `ObjectLockConfiguration.Rule.DefaultRetention.DefaultEventHold` now reaches AWS (PR [#3002](https://github.com/go-to-k/cdkd/pull/3002))** -- `src/provisioning/providers/s3-bucket-provider.ts`, `package.json`, `tests/fixtures/cfn-schemas/AWS-S3-Bucket.json`, `docs/_generated/nested-key-coverage.{json,md}`, `docs/schema-refresh-runbook.md`, `tests/unit/provisioning/s3-bucket-provider-*.test.ts`, `tests/integration/s3-object-lock/`. **Bug:** the 2026-09-11 CFn schema capture added `DefaultEventHold` (an OBJECT carrying `Days` / `Years`) under `DefaultRetention`, and `applyObjectLockConfiguration` named only `Mode` / `Days` / `Years` -- so a template declaring an event hold had it dropped by the SDK serializer while the deploy reported success, the #1370 silent-drop class. **Fix:** the applier forwards it, and `readObjectLock` emits it back in the same CFn spelling -- without that half a recorded key the readback can never report is permanent phantom drift, re-issued by every `cdkd drift --revert`. **The floor moved:** `@aws-sdk/client-s3` is `^3.1129.0`, up from `^3.0.0`, because the member reaches the wire only where the client's model declares it (3.1126.0 does not). **A malformed `DefaultEventHold` SKIPS the whole Put** (`requireConfigObject`; warn-and-skip on replay-reachable paths, refusal on a template-path create): it is the only OBJECT here, so unlike its scalar siblings it vanishes silently instead of failing at S3, and the Put replaces the entire rule, so retention minus the hold would apply a WEAKER configuration than declared. An unresolved intrinsic is a plain object and still passes -- a residual every `requireConfigObject` site shares, pinned by a test. **On upgrade a hold declared BEFORE this release does not self-apply:** the old binary recorded the declared bag while never sending it, so the next deploy compares equal and reports `NO_CHANGE`. `cdkd drift` surfaces it; `drift --revert` or any edit to the block applies it.
