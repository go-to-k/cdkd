- **cdkd now warns, once per run, when `CDKD_CR_S3_ENDPOINT_URL` is not https on port 443, because CDK's Node.js custom-resource handlers cannot respond to such an endpoint (issue [#5871](https://github.com/go-to-k/cdkd/issues/5871))** -- `src/provisioning/providers/custom-resource-response-endpoint.ts`, `src/provisioning/providers/custom-resource-provider.ts`, and their tests. cdkd signs the response URL for the configured endpoint with its scheme and port intact, but CDK's Node.js handlers (S3 `autoDeleteObjects`, `AwsCustomResource`, the `Provider` framework) send the response with `https.request({ hostname, path })`, dropping both, so against `http://s3:9000` the PUT went to `https://s3:443` and the custom resource waited until it timed out with no hint why. cdkd does not alter the handler asset the template declares; the warning names the remedy (serve the emulator's S3 over TLS on port 443, with a certificate the Lambda runtime trusts, and set `CDKD_CR_S3_ENDPOINT_URL=https://<host>`) and notes that Python `cfnresponse` handlers are unaffected. Docs: `docs/troubleshooting-internals.md`.
