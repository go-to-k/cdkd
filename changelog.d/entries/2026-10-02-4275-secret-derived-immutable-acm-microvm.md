- **An ACM certificate or Lambda MicroVM image whose immutable value comes from a secret is updated in place again (issue [#4275](https://github.com/go-to-k/cdkd/issues/4275))** -- `src/provisioning/providers/{acm-certificate,lambda-microvm-image}-provider.ts`. State keeps a secret-derived value as its `{{resolve:...}}` reference while `update()` receives the resolved value, so an ACM certificate whose `DomainName`, `SubjectAlternativeNames`, `DomainValidationOptions`, `CertificateAuthorityArn` or `KeyAlgorithm` came from a secret was REPLACED on every update (a new certificate requested and the old one deleted), and a MicroVM image whose `Name` did was refused on every update. Both guards now use `unchangedBehindSecretReference`'s masker arm, on create-only keys only: neither physical id carries the value, and both providers' writes address the resource by its ARN. A real change, a recorded `***` and a key the engine does not replace on (`ValidationMethod`) still replace or refuse as before. The MicroVM refusal now masks the resolved name it prints. Tests: `tests/unit/provisioning/secret-reference-immutable-sites-acm-microvm.test.ts`.
