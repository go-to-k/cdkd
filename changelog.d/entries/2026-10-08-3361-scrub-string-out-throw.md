- **`cdkd scrub` no longer turns a failure it is built to report into a different, harder one when the failing call rejects with a value that cannot be converted to text** (`src/cli/commands/scrub.ts`, go-to-k/cdkd#3361). Its handlers built their message with `x instanceof Error ? x.message : String(x)` (or a bare `String(x)`), and `String()` throws for a null-prototype object, so the handler itself threw. In `--all`, the per-stack failure boundary threw while reporting one stack and ended the run there, leaving every later stack unexamined; a nested-record listing failure or an unreadable exports index did the same instead of being recorded and reported after the summary. Inside one stack, a lock release failure after a successful rewrite reported the stack as failed, and a resource property, orphan record, output value, `Export.Name`, parameter, condition, cross-stack read on a suppressed output, producer re-read or consumer-records read that failed aborted the whole stack instead of being logged and skipped. Four refusals (`SCRUB_CROSS_STACK_READ_UNRESOLVED`, `SCRUB_CROSS_REGION_SECRET_UNRESOLVED`, `SCRUB_NESTED_CHILD_UNRESOLVABLE`, `SCRUB_LEGACY_STATE_KEY_UNVERIFIED`) were replaced by the converter's `TypeError`, losing their code and remedy. Each now goes through `describeAwsFailure(x).detail` (or `safeStringify(x)` for the bare form), byte-identical for every value the old expression could render and a placeholder where it threw. Tests: `tests/unit/cli/commands/scrub-string-outthrow-3361.test.ts`, `tests/unit/cli/commands/scrub-nested-string-outthrow-3361.test.ts`.
