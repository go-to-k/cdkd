- **`cdkd import` and `cdkd export` take `--tags KEY=VALUE` and read `cdk.json` `tags`, as `cdkd deploy` does (issue [#6909](https://github.com/go-to-k/cdkd/issues/6909))** -- `src/cli/commands/import.ts`, `src/cli/commands/import/command.ts`, `src/cli/commands/import/locked-import.ts`, `src/cli/commands/export.ts`, `src/cli/commands/export/command.ts`. Both read only the manifest's `StackProps.tags`, so a stack deployed with `--tags` (or with `tags` in `cdk.json`) was imported, or exported to CloudFormation, with other tags than it was deployed with, and the next deploy showed a tag change. They now resolve the stack tags the way a deploy does: `--tags`, else `cdk.json` `tags`, else the manifest's. `--migrate-from-cloudformation` still records the tags the CloudFormation stack holds. `cdk import` has no `--tags`.
