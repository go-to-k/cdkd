- **`cdkd drift --revert` / `--accept` name every cause of a masked baseline, and a pasted plan line redirects nothing (issues [#2881](https://github.com/go-to-k/cdkd/issues/2881), [#4239](https://github.com/go-to-k/cdkd/issues/4239))** -- `src/cli/commands/drift.ts`, `docs/_contents/cli-drift.md`. The `--revert` refusal for a position whose baseline holds only the redaction mask named two causes, a `NoEcho` custom-resource value and a readback position cdkd could not certify. It now also names the `Fn::Base64` encoding of a secret value (issues #2759 / #3119), which no custom resource is behind, and gives each non-`NoEcho` cause its own remedy: a deploy that changes the resource sends a `Fn::Base64` encoding again, and re-captures the baseline for an uncertified position. The `--accept` refusal of the same mask now scopes its re-capture remedy to the uncertified position, and says that no deploy replaces a mask standing for a `NoEcho` value or a `Fn::Base64` encoding, where it used to suggest that a custom-resource update would. The `--accept` / `--revert` plan line now reads `<path>: <from> → <to>`: pasted into a shell, the old ` -> ` was a `>` redirect onto the value after it, so a readback value could truncate a file it named. A value carrying ASCII `->` or a character of the Unicode arrow ranges (`→`, `⟶`, `➔`, `⮕`, `🠒`, `￫`, ...) is quoted, so it cannot read as the separator. The `--accept` refusal's remedy no longer spells a backticked `cdkd deploy`, which a pasted clause of the plan's `SKIPPED` row ran as a command substitution. The export, rollback and deploy messages that omit the `Fn::Base64` cause remain on #2881. Tests: `tests/unit/cli/drift-plan-paste-4239.test.ts`, `drift-plan-sanitize.test.ts`, `drift-secret-redaction.test.ts`, `drift-uncertified-baseline.test.ts`.
