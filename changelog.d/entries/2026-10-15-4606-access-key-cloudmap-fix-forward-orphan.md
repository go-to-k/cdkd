- **A fix-forward deploy now deletes the IAM access key or Cloud Map namespace or service an earlier failed CREATE left behind (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606), access key and Cloud Map slice)** -- `src/provisioning/providers/{iam-access-key,servicediscovery}-provider.ts`. When a `cdkd deploy --no-rollback` made an `AWS::IAM::AccessKey` or an `AWS::ServiceDiscovery::Service` (or a private DNS, public DNS or HTTP namespace), failed on a later call and could not delete it again, and a later deploy created a new one under the same logical id, the successful deploy warned about the earlier one, left it in AWS and exited 2; `cdkd rollback` and `cdkd destroy` kept it the same way. The providers now compare the two: an access key id and a Cloud Map `ns-` / `srv-` id are generated by AWS and never reused, so the earlier resource is a different one once the record's key, namespace (of the record's kind) or service reads back in the stack's region, and it is deleted. An id of another form, a read that fails, or a record that does not read back keeps the warning. No ordinary deploy makes an extra call. Tests: `tests/unit/provisioning/{iam-access-key,servicediscovery}-provider-same-resource-4606.test.ts`; integ: `access-key-cloudmap-fix-forward-orphan`.
