- **An Output that never resolves at deploy is no longer a phantom `ADD` in `cdkd diff --fail` on the unchanged stack (issue [#2740](https://github.com/go-to-k/cdkd/issues/2740))** -- new `src/analyzer/skipped-outputs.ts`, `src/types/state.ts` (`skippedOutputs`, informational, **no schema bump**), `src/deployment/deploy-engine.ts`, `src/analyzer/outputs-diff.ts`, `src/cli/commands/{diff-recursive,import,drift,rollback,scrub,state}.ts`, `src/analyzer/orphan-rewriter.ts`, new `tests/integration/output-never-resolved-diff/`, four new unit suites, docs. **Behavior change:** an output the deploy skipped never reaches `state.outputs`. When the resolver threw inside a SECRET lookup (a JSON key the secret does not hold) the diff could not reproduce it -- `skipDynamicReferences` assembles the reference cleanly -- so `computeOutputsDiff` pushed an `ADD` on every run; the other arm (an unconstructible attribute) dropped the whole Outputs section. The deploy now records each skipped key with a sha256 of its template inputs (every section but `Resources` and `Outputs`), and the diff previews a recorded key whose digest still matches, while still absent from state, as ABSENT: no row, and not a failed section, so a sibling's genuine change still renders. Both sides digest a snapshot taken BEFORE any resolution; the diff also declines the record for an output referencing a resource THIS run changes, since `Resources` is not digested. The no-change path saves on a record difference alone (the upgrade path). Saves that carry the bag forward without re-resolving carry the record (a partial destroy's snapshot too); every writer that rebuilds state outside a deploy (`import`, `drift`, `rollback`, `scrub`, `orphan`, `refresh-observed` once it refreshed anything) DROPS it: an out-of-band rewrite can make a skipped output resolvable with nothing for the diff to un-bind on. Limitation: five repairs stay invisible until the next deploy (one by design: the masked `NoEcho` default).
