- **A skipped DELETE during `cdkd deploy` names a drop command for that one record, not the whole stack (issue [#4602](https://github.com/go-to-k/cdkd/issues/4602))** -- `src/deployment/deploy-engine/delete.ts`, `docs/_contents/cli-deploy-safety.md`. The deploy engine's warning for a delete a provider skipped ended on `Drop the record with: cdkd state orphan <stack> --stack-region <region>`, which drops the record of every resource in the still-deployed stack, so the next deploy re-creates or collides with all of them; it printed this beside the provider's own warning, which since #4609 names the `--resource` form. The line now ends in `--resource <logicalId>` (a logical id that is not a plain identifier prints as a `'<logicalId>'` hole), and the warning says to keep `--resource` on the drop. For a nested stack's `AWS::CloudFormation::Stack` row, where `--resource` refuses while the child has a record, the `Inspect it with:` and `Drop the record with:` lines name the child's own record (`<stack>~<logicalId>`) and the warning says to delete by hand what the child still holds first, after which the next deploy removes the row (an interrupted child is resumed by re-running the deploy instead); a withheld child name prints as `'<child-stack>'`. Tests: `tests/unit/deployment/deploy-engine-delete-skipped-journal.test.ts`; integ: `nested-stack-3level` (Step 4c).
