- **A masked Glue, EFS, Secrets Manager, SSM Parameter or IAM create/update failure is still retried when a secret overlaps AWS's retry wording (issue [#4244](https://github.com/go-to-k/cdkd/issues/4244))** -- `src/deployment/retryable-errors.ts`, `src/provisioning/providers/{glue,efs,secretsmanager-secret,iam-role,iam-user-group,iam-policy,iam-managed-policy,iam-instance-profile,iam-access-key,ssm-parameter}-provider.ts`. These providers mask AWS's error text before joining it into their `Failed to create/update ...` message (#2177). When a recorded secret, or a 3+ character name resolved from one, spelled part of a retryable phrase (`is unable to assume provided role`, `Invalid principal in policy`, `scheduled for deletion`, `does not exist`), the mask cut that phrase out and `withRetry` read the failure as terminal, so the deploy failed where it used to retry. Each wrap now goes through the new `wrapMaskedAwsError`, which stamps `markRedactedCause` when the mask changed the text, so the retry classifiers read the unmasked cause chain. The message is still masked. A wrap the mask left unchanged is not stamped, and cdkd's own template-value refusals are not stamped either. Tests: the `issue #4244` blocks in `tests/unit/provisioning/{glue-providers-masked-warn,efs-provider-masked-log,secretsmanager-secret-provider-masked-log,iam-providers-masked-warn,ssm-parameter-provider-masked-warn}.test.ts` and `tests/unit/deployment/retryable-errors.test.ts`.
