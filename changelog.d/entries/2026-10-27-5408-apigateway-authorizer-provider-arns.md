- **API Gateway REST `Authorizer` `ProviderARNs` and `Method` `AuthorizationScopes` changes are applied in place, and a removed `Authorizer` `AuthorizerUri` is kept (issue [#5408](https://github.com/go-to-k/cdkd/issues/5408))** -- `src/provisioning/providers/apigateway-provider.ts`. Changing an `AWS::ApiGateway::Authorizer`'s user pools, or switching a TOKEN / REQUEST authorizer to `COGNITO_USER_POOLS`, failed the deploy with `BadRequestException: Invalid patch path '/providerARNs' specified for op 'replace'`; changing an `AWS::ApiGateway::Method`'s `AuthorizationScopes` failed the same way. Each pool or scope is now added or removed by value, adds first, so swapping a Cognito authorizer's only pool no longer empties its list. Removing `AuthorizerUri` from the template now leaves the URI on the authorizer, as CloudFormation does (a CloudFormation A/B in us-east-1 kept it on a TOKEN authorizer and on a TOKEN to `COGNITO_USER_POOLS` switch); cdkd used to clear it, or fail the deploy on a TOKEN / REQUEST authorizer, where API Gateway requires a URI.
