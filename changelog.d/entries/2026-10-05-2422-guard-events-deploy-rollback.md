- **`cdkd deploy` and rollbacks persist a pre-flight safety guard that could not reach a verdict (issue [#2422](https://github.com/go-to-k/cdkd/issues/2422))** -- `src/deployment/delete-guard-scope.ts` (new), `src/deployment/deploy-engine/provision.ts`, `src/deployment/deploy-engine/{delete,replacement,update-in-place,update-replace}.ts`, `src/deployment/rollback-executor/messages.ts` and the rollback delete arms, `docs/_contents/deployment-events.md`. A delete whose guard could not answer (for example an `AWS::S3::Bucket` routed through Cloud Control whose `s3:GetBucketLocation` is denied) recorded a `RESOURCE_GUARD_INDETERMINATE` event only under `cdkd destroy` / `cdkd state destroy`; the same delete on the deploy path (template removal, replacement, `--recreate-via-*`, replaced-resource cleanup, update-not-supported fallback) or in a rollback left only the live warning. Both now record the same event, with the destroy runner's payload and `operation: DELETE` even when the delete is a step of an UPDATE. The deploy engine emits it from one place per resource, before the row's outcome event, including when a later step of the same row fails; the rollback executor emits it from the helper every delete arm already calls, before a `'skipped'` outcome is turned into a failure. The physical id and reason are masked with the resource's own secrets. No summary count is added and no `result` changes. Tests: `tests/unit/deployment/deploy-engine-delete-guard-events.test.ts`, `tests/unit/deployment/rollback-executor-delete-guard-events.test.ts`.
