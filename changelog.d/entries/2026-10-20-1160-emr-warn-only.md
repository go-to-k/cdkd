- **`AWS::EMR::Cluster` / `AWS::EMR::InstanceFleetConfig`: the warning for a removed `StepConcurrencyLevel`, `ResizeSpecifications` or `InstanceTypeConfigs` now says CloudFormation keeps the value too (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/emr-cluster-provider.ts`, `src/provisioning/providers/emr-instance-fleet-config-provider.ts`. A CloudFormation A/B on the issue (us-east-1, a fleet cluster with a running TASK fleet; each property removed alone, and `StepConcurrencyLevel` / `ResizeSpecifications` also beside a companion change) showed CloudFormation keeps all three live values and no update fails, although its documented `StepConcurrencyLevel` default is 1. cdkd already kept them, because `ModifyCluster` / `ModifyInstanceFleet` keep a field they are not sent, so the behaviour does not change. The deploy warning used to make no claim about CloudFormation; it now reads `... was removed from the template and keeps its current AWS value, as CloudFormation leaves it; ...`. The rollback wording is unchanged. Tests: `tests/unit/provisioning/providers/emr-cluster-provider-removal-1160.test.ts`, `tests/unit/provisioning/providers/emr-instance-fleet-config-provider-removal-1160.test.ts`; the `emr-cluster` and `emr-instance-fleets` integ fixtures' Phase 2b needles now require the new wording.
