- **An update or delete of an S3 Express directory bucket, an S3 Tables table bucket, namespace or table, or a WAFv2 web ACL, an update of a Glue security configuration, and a delete of any Glue resource cdkd's SDK providers handle (database, table, workflow, security configuration, job, crawler, connection, trigger) is refused when the AWS client's region differs from the region recorded in cdkd state (issue [#2613](https://github.com/go-to-k/cdkd/issues/2613))** -- `src/provisioning/providers/{s3-directory-bucket,s3-tables,wafv2,glue}-provider.ts` (`assertRegionMatch` now runs before any AWS call in these `update()`s and `delete()`s; the directory bucket's update compares both the S3 client its ARN comes from and the S3 Control client its tag writes use), `scripts/check-provider-update-context.ts` (four names leave `OMITS_UPDATE_CONTEXT`, leaving the three CloudFront providers), and unit cases. A run with a client in another region sent its writes there; a delete checked the region only when AWS answered NotFound, so for a name-shaped physical id it deleted a same-named resource cdkd does not manage. A Glue security configuration update failed with a "cannot be updated in place" error pointing at `--replace`, whose replacement would then run in the wrong region. The call now stops first and names both regions. A state record with no region is unchanged.
