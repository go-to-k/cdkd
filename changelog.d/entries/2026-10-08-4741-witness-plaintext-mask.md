- **The first deploy after upgrading to state schema v11 no longer prints a NoEcho parameter's previous value at a position the template still feeds from one (issue [#4741](https://github.com/go-to-k/cdkd/issues/4741))** -- `src/deployment/deploy-engine/update.ts`. A record an older cdkd wrote still holds the plaintext it last sent at each `NoEcho` position. Where that value differs from the one this deploy binds, it is handed to the provider as the previous properties (and to a replacement's delete of the old resource), and nothing masked it: a provider that logs the previous value while reconciling (the Budgets provider's `Deleted subscriber` line under `--verbose`) printed it, as did an error quoting it. The value is now recorded for the duration of the deploy in the resource's print-only bag, the one bound around every line logged for the resource, so its log lines, errors and events print `***` in its place. Nothing that is persisted or decided reads that bag. Where a whole list was compared (its length changed), only the leaves the template no longer holds are recorded. Not covered, and still printed: a previous value at a position this deploy no longer reads from a `NoEcho` parameter, or in a property the template removed, or in a removed list entry when the list no longer holds any `NoEcho` position (a pre-v11 record does not say which of its positions a `NoEcho` parameter fed); and a previous value of exactly `true` / `false` inside a list whose length changed, since recording it would mask every line containing that word. As with every `NoEcho` value, a whole printed text equal to it is masked at any length, and an occurrence inside a longer text only from 4 characters. Tests: `tests/unit/deployment/deploy-engine-noecho-witness-log-4741.test.ts`.
