- **`cdkd orphan` resolves a construct path in a stack under a CDK Stage (issue [#3943](https://github.com/go-to-k/cdkd/issues/3943))** -- `src/cli/commands/orphan.ts`, with unit tests in `tests/unit/cli/orphan.test.ts`. A construct path was split at its FIRST `/` and the head looked up as a stack, so every stack inside a `Stage` -- whose display path is `MyStage/Api`, or `Outer/Inner/Api` for a nested Stage -- was unaddressable: `cdkd orphan MyStage/Api/Bucket` answered `stack 'MyStage' not found in synthesized app. Available: MyStage/Api`, naming the very stack the path started with. The stack is now the one whose display path (or physical name) followed by `/` is the longest prefix of the path, so a nested Stage resolves and `MyStage/Api` never claims `MyStage/ApiV2/...`. A path that is exactly a stack's display path is refused as naming a stack rather than a resource (even when a shorter stack path prefixes it), a trailing `/` is refused at any depth, the malformed-path hint now reads `<StackPath>/<Path/To/Resource>`, and a path no stack prefixes is refused with `does not start with the path of any stack in the synthesized app`, listing the available stack paths. Top-level stacks resolve as before.
