- **A masked `UserData`-style property is now redeployed when an input it reads changes behind unchanged template text: a parameter value, a `Ref` to a resource the deploy replaced, a flipped condition (issue [#4543](https://github.com/go-to-k/cdkd/issues/4543))** -- `src/deployment/masked-property-fingerprints.ts`, `src/deployment/deploy-engine/{update,create,deploy-flow,resolver-context}.ts`, `src/deployment/deploy-engine.ts`, `src/analyzer/diff-calculator.ts`, `src/cli/commands/diff-recursive.ts`, `src/types/state.ts`. The #4451 fingerprint hashed template text only, so these compared `***` with `***` and the deploy kept the old script under a green run, where CloudFormation updates the resource. `maskedPropertyFingerprints` entries are now `inputs-sha256:<hex>+sha256:<hex>`: the template value with each non-secret input resolved, then the text hash. A `NoEcho` parameter, a `{{resolve:...}}` reference, a resource or condition reading either (or a cross-stack value), an input whose resolution read a secret, and a nested stack's parent-supplied values stay in template form, so no secret-derived value is hashed; a new `NoEcho` value is therefore still not sent through the mask. A text-only `sha256:` entry is compared as before and, while its text matches, re-baselined from today's inputs without sending; an older cdkd ignores the new entries. `cdkd diff` compares the inputs for the stack it was given and the text for a nested child.
