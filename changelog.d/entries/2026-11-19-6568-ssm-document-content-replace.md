- **A content change to an SSM document now replaces it under the default `UpdateMethod` (issue [#6568](https://github.com/go-to-k/cdkd/issues/6568))** -- `src/analyzer/replacement-rules/rules.ts`, `src/analyzer/replacement-rules/predicates.ts`, unit tests and the `ssm-document-replace` integ fixture. A change to an `ssm.CfnDocument`'s `content` (or `attachments`, `documentFormat`, `requires`, `targetType`, `versionName`) with no `updateMethod` was planned as an in-place update, `cdkd diff` showed no `[requires replacement]`, and the deploy failed with `Create-Only Property cannot be updated.` and rolled back, while CloudFormation replaces the document. cdkd now replaces it, create-first, when the new template's `UpdateMethod` is absent or `Replace`, and keeps the in-place update that adds a document version under `NewVersion`. A named document under `Replace` is refused on the name collision like any named replacement (CloudFormation refuses it too); `cdkd deploy --replace` deletes it first.
