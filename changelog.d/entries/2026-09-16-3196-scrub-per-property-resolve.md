- **`cdkd scrub` no longer loses a secret reference because an unrelated property in the same resource failed to resolve** — the per-resource pass handed `resolver.resolve` the WHOLE `Properties` bag, and one throw aborts the walk, so an unresolvable `Ref` in property A abandoned the `{{resolve:secretsmanager:...}}` in property B. B recorded no needle, its legacy plaintext was never rewritten, and the stack could still print `No plaintext secrets found` at exit 0. Reachable by accident — `scrubStack` catches `resolveParameters` wholesale and continues with an EMPTY parameter bag, so ONE parameter with no `Default` makes every `{Ref: <param>}` in the stack throw — and, on a repo running `cdkd scrub --all --dry-run --fail` in CI, defeatable on purpose by putting one dangling `Ref` ahead of a secret. The resolve is now scoped per TOP-LEVEL PROPERTY: a failure is confined to the property that caused it and its siblings are still scanned, so the needle is recorded and the plaintext rewritten. Warnings name the property (`resource 'Db' property 'DBSubnetGroupName'`) rather than just the record. Nothing else changes: the context is per-RESOURCE, so every property still accumulates into the same recorded-secret map; `pinCrossRegionSecrets` already walked per-leaf and returns the same shape; a CloudFormation intrinsic references other RESOURCES, never a sibling property; and `resolveCrossStackReads` stays whole-bag because its refusals are per-stack. A non-object bag (array, bare value, `null`) is resolved whole, so the scoping can never drop a unit. **Scoped to the TOP-LEVEL property**: inside one property's value a failing key still stops the keys after it (`Environment.Variables.A` taking out `...B`), because the resolver's own object walk has no per-key `try` — #3218 tracks that.
