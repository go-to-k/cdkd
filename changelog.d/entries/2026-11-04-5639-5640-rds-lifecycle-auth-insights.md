- **The SDK provider sends `EngineLifecycleSupport` and `MasterUserAuthenticationType` for `AWS::RDS::DBCluster` and `AWS::RDS::DBInstance`, and `DatabaseInsightsMode` for `AWS::RDS::DBCluster` (issues [#5639](https://github.com/go-to-k/cdkd/issues/5639), [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and new arms in the `rds-aurora` and `rds-dbinstance-backfill` integs. Before, a cluster or instance declaring any of them routed through Cloud Control. Each now rides `CreateDBCluster` / `CreateDBInstance` as declared. A changed `EngineLifecycleSupport` (changed, added or removed) is refused before any call, as CloudFormation refuses it ("EngineLifecycleSupport cannot be modified."); a declared value the live resource already holds is no change, and `cdkd drift --revert` restores the recorded value. An update sends a changed `MasterUserAuthenticationType` with the declared managed-password settings beside it (RDS ties the two together), and a changed cluster `DatabaseInsightsMode` with the declared Performance Insights settings; removing either leaves the live value, as under CloudFormation. `cdkd drift` reads back `EngineLifecycleSupport` (not for an Aurora cluster member, whose cluster owns it) and the cluster's `DatabaseInsightsMode`; `MasterUserAuthenticationType` is write-only and has no readback. Resources already deployed through Cloud Control stay there.
