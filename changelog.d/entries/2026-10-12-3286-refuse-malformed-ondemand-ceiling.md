- **`AWS::DynamoDB::Table` now refuses an `OnDemandThroughput` ceiling member CloudFormation rejects, before any AWS call, instead of dropping it and deploying green (issue [#3286](https://github.com/go-to-k/cdkd/issues/3286))** -- `src/provisioning/providers/dynamodb-table-provider.ts` (`onDemandCeilingRefusal`, `refusedOnDemandCeilingShape`), `tests/unit/provisioning/dynamodb-table-provider-cfn-integer.test.ts` and the `dynamodb-ondemand` integ fixture (Phase 1.8). A `MaxReadRequestUnits` / `MaxWriteRequestUnits` spelled padded, hex, exponent, decimal, `null`, boolean, array or object, at the table level or in a `GlobalSecondaryIndexes[]` entry, used to be omitted with a warning; both members are optional, so the request succeeded with that half unapplied while state recorded the declared spelling, and `cdkd drift` reported it on every run. `create()` and `update()` now throw naming the resource, the member and the value's TYPE (never the value; an index by position), as CloudFormation refuses the same template. On an update only a pending send is checked: an unchanged block sends nothing and is not refused. Integers, quoted integers and the `-1` "remove the maximum" sentinel deploy as before; a blank string, an integer beyond JavaScript's safe range and a rollback replay keep the previous warn-and-drop, since CloudFormation may accept the first two and a replayed state record cannot be fixed from the template.
