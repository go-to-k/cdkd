- **`cdkd diff --recursive --fail` no longer reports a change on an unchanged nested stack in which one child resource reads a parameter the parent spelled as a literal embedding `{{resolve:...}}` tokens beside a sibling parameter spelling the same secret differently, through an `Fn::If` whose branches resolve to that secret spelled two ways, an `Fn::If` whose other branch is an attribute, a resource or a pseudo parameter, or an array of which only some `Fn::If` elements resolve to `AWS::NoValue` or which holds another intrinsic beside one (issue [#4954](https://github.com/go-to-k/cdkd/issues/4954)).** After upgrading, the first deploy of such a stack shows a change on the child resources reading the literal parameter, because their state now records the parameter's own `{{resolve:...}}` spelling instead of the sibling's; the deployed VALUE is unchanged, and a create-only property is replaced once with an identical value. The resolver now records, per resource, which branch each `Fn::If` took and which array elements dropped out as `AWS::NoValue`, and the state redaction reads those records instead of guessing from the resolved value, so an array element that drops out keeps the rest of the array paired with its template in any stack. An `Fn::Sub` naming a pseudo parameter inside `Fn::Select` ([#4962](https://github.com/go-to-k/cdkd/issues/4962)), and a taken branch reading the parameter through an intrinsic the redaction cannot evaluate, still fall back to the sibling's spelling. Source: `src/deployment/secret-redaction/{nested-stack,redact-path,resolver-outcomes}.ts`, `src/deployment/intrinsic-resolver/{functions,parameter-secrets}.ts`, `src/deployment/intrinsic-function-resolver.ts`.
