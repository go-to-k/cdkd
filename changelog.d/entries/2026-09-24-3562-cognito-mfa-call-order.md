- **Cognito user pools: adding `WEB_AUTHN` with `WebAuthnFactorConfiguration: MULTI_FACTOR_WITH_USER_VERIFICATION` to a pool already at `MfaConfiguration: ON` now deploys (issue [#3562](https://github.com/go-to-k/cdkd/issues/3562))** -- `src/provisioning/providers/cognito-provider.ts`. `update()` used to send `UpdateUserPool` before `SetUserPoolMfaConfig`. AWS refuses to add `WEB_AUTHN` to a pool at `ON` until its factor configuration is `MULTI`, so the edit failed, although CloudFormation deploys it. For that shape alone, the update now reads the live MFA configuration and sends `SetUserPoolMfaConfig` first. If the `UpdateUserPool` behind it then fails, the previous MFA configuration is put back and the original error surfaces. A failed read keeps the usual order. Lowering MFA from `ON` while adding `EMAIL_OTP` still fails, atomically, because CloudFormation rolls that edit back too.
