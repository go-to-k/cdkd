- **`AWS::DynamoDB::GlobalTable` sends `Replicas[].DisassociationProtectionEnabled` on a multi-Region table (issue [#5570](https://github.com/go-to-k/cdkd/issues/5570))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`. DynamoDB takes the member only as an `UpdateTable` of the replica's own table, in its own region, that changes nothing else, and only on a replica of a multi-Region global table. On a single-Region table it answered `false` with `InternalFailure` (HTTP 500) on every retry. A create and an update on a table with two or more replicas now make that call for each replica that declares a value, the deploy-region table included. The call comes after the replica changes, the update that adds the second replica included, and the deploy waits until the value reads back. A replica that already holds the declared value gets no call, so a declared `true` usually costs one read. On a single-replica table, a new or changed `false` is refused before any call. A `true`, which is the default, is skipped, and so is an unchanged `false` on a table that drops to one replica, with a warning in the deploy that drops it. A removed value sends nothing and the replica keeps its setting, with a warning. A rollback whose record has no value turns a `false` that AWS reads back on. `cdkd drift` reports a declared value. A value that is not a boolean is refused. Before this change any declared value was refused. Destroy is unchanged: this protection does not guard a replica removal or the table deletion.
