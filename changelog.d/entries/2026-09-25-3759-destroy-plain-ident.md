- **`cdkd destroy`'s refusals and summaries name a stack, region or logical id beside a pasteable command only when it is a plain identifier (issue [#3759](https://github.com/go-to-k/cdkd/issues/3759))** -- `src/utils/error-handler.ts` (`Retry with:`, `Cascade-delete with:`, `Destroy the child alone with:`), `src/cli/commands/destroy.ts` (`Remove one record with:`), `src/cli/commands/destroy-runner.ts` (`Inspect it with:` / `Drop the record with:`, `Read them with:`, and every summary line), `src/provisioning/providers/nested-stack-provider.ts` (the nested child failure's `Inspect it with:`), new `plainOrDescribed` / `quotedOrDescribed` in `src/utils/pasteable-command.ts`, and unit tests. These messages printed state- or template-sourced names raw in their prose and gated their commands only for shell safety, so a name or region carrying a newline, or padding that wraps on screen, could print a counterfeit labelled row such as `Retry with: cdkd destroy --all --force #`. Each command now also requires a plain identifier (a letter or digit, then letters, digits, `~`, `_`, `.` or `-`) and prints a quoted hole otherwise, the prose names the value only under the same rule, and a sentence before the labelled lines says why a hole was printed. The multi-region refusal's region list, whose regions come from S3 keys, is gated the same way. A child record named like `Prod*` or `Stage/Prod` now also gets a hole in `Destroy the child alone with:`, where it used to be named. A real stack, nested child (`Parent~Child`) or region name is always a plain identifier, so no genuine name loses its command.
