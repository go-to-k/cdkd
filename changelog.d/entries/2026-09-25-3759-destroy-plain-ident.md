- **`cdkd destroy`'s refusals and summaries name a stack, region or logical id beside a pasteable command only when it is a plain identifier (issue [#3759](https://github.com/go-to-k/cdkd/issues/3759))** -- `src/utils/error-handler.ts` (`StackTerminationProtectionError`'s `Retry with:`, `NestedStackChildDirectDestroyError`'s `Cascade-delete with:` / `Destroy the child alone with:`), `src/cli/commands/destroy.ts` (the multi-region refusal's `Remove one record with:`), `src/cli/commands/destroy-runner.ts` (`hintFor`'s `Inspect it with:` / `Drop the record with:`, the guard summary's `Read them with:`), a new `plainOrDescribed` in `src/utils/pasteable-command.ts`, and unit tests. These messages printed state- or template-sourced names raw in their prose and gated their commands only for shell safety, so a name or region carrying a newline, or padding that wraps on screen, could print a counterfeit labelled row such as `Retry with: cdkd destroy --all --force #`. Each command now also requires a plain identifier (a letter or digit, then letters, digits, `~`, `_`, `.` or `-`) and prints a quoted hole otherwise, and the prose beside it names the value only under the same rule, describing it otherwise. The multi-region refusal's region list, whose regions come from S3 keys, is gated the same way. A real stack, nested child (`Parent~Child`) or region name is always a plain identifier, so no genuine name loses its command.
