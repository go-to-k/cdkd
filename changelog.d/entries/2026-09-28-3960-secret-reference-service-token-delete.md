- **A custom resource whose recorded `ServiceToken` holds a `{{resolve:...}}` reference is now skipped on delete with a named warning instead of being sent to Lambda as a function name (issue [#3960](https://github.com/go-to-k/cdkd/issues/3960))** -- `src/provisioning/providers/custom-resource-provider.ts` (`CR_REFERENCE_SERVICE_TOKEN_SKIP_REASON`), `tests/unit/provisioning/custom-resource-masked-service-token.test.ts` and a new arm of the `custom-resource-masked-service-token` integ fixture. cdkd persists a `{{resolve:secretsmanager:...}}` / `{{resolve:ssm-secure:...}}` reference as its expression rather than its value, so a ServiceToken built from one reached the delete path as that expression: it fails `GetFunction`'s name validation as the #3938 mask does (whose pre-fix run left the readiness waiter polling for its full 10 minutes), and the invoke then failed with a message that named neither cause. It now reports `outcome: 'skipped'` before any AWS call, like the #3938 masked-token arm: the record is kept, `cdkd destroy` exits 2, and the warning says CloudFormation does not support secure (secretsmanager / ssm-secure) dynamic references in custom resources and names the remedies (tear the resource down by hand and `cdkd state orphan <stack>`, or restore the ARN while the handler still exists). The reference is not resolved on delete: CloudFormation rejects the shape, so a record like this exists only because cdkd deployed it.
