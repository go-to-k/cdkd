- **An `AWS::RDS::DBProxyTargetGroup` no longer ends up on Cloud Control, whose delete always fails for the type, and its `Tags` are applied by the SDK provider** (`src/provisioning/provider-registry.ts`, `src/provisioning/providers/rds-dbproxy-targetgroup-provider.ts`, go-to-k/cdkd#4087). Cloud Control's delete handler cannot derive `DBProxyName` from the TargetGroupArn identifier and sends it null (go-to-k/cdkd#385, re-measured 2026-09-29), yet the type was not in `STICKY_CC_MIGRATION_EXEMPT`, so a key the SDK provider did not write (such as the `Tags` AWS just published) routed the resource through Cloud Control, recorded `provisionedBy: 'cc-api'`, and made the next `cdkd destroy` fail on it. The type is now a `cc-broken` exemption: a record already pinned to `cc-api` returns to the SDK provider, destroy always runs there, and an unrecognized key keeps the SDK route with a warning. `Tags` is now handled: create tags the target group with `AddTagsToResource` after registering its targets (deregistering them again if tagging fails), update applies the tag difference with `RemoveTagsFromResource` / `AddTagsToResource`, and `cdkd drift` reads them with `ListTagsForResource`. A malformed `Tags` list is refused before any call; a malformed recorded one only suppresses tag removals. The schema-refresh changelog template no longer says a post-snapshot key was dropped before the refresh (`scripts/diagnose-schema-refresh.mjs`). Tests: `tests/unit/provisioning/rds-dbproxy-targetgroup-provider.test.ts`; integ `rds-aurora`.
