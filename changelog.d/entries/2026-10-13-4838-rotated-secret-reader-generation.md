- **A reader that spells a secret is no longer skipped, left on a deleted resource's ID, when the secret-named resource it reads is replaced under the rotated secret (issue [#4838](https://github.com/go-to-k/cdkd/issues/4838))** -- `src/deployment/deploy-engine/update.ts`. When a secret rotated and a create-only change replaced a resource named from it (an SQS queue renamed `sdin-q-1` -> `sdin-q-2`), a reader that also spells the same `{{resolve:...}}` reference (a tag beside `Value: Fn::GetAtt Queue.Arn`) recorded the new name against that reference, so the new ARN redacted to the same `arn:...:{{resolve:...}}` it had stored for the old queue. The no-change re-check compared equal, the reader was not updated, and it kept the deleted queue's ARN in AWS. A resource that reads a resource whose physical ID changed in this deploy is now sent, rather than skipped, whenever the redaction rewrote any of its values. A create-only property the redaction rewrote counts as changed, so a reader such as an event source mapping is replaced rather than updated in place. A reader whose values no secret rewrote, or of a resource replaced under the same physical ID, is still skipped. A reader left stale by an interrupted earlier deploy, a nested child fed by a parameter, and a cross-stack consumer are not covered (issue [#4852](https://github.com/go-to-k/cdkd/issues/4852)).
