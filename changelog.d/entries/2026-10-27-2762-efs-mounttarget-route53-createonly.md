- **`AWS::EFS::MountTarget` and `AWS::Route53::HostedZone` keep the SDK route for their create-only properties (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762)).** A mount target declaring `IpAddress`, `IpAddressType` or `Ipv6Address`, and a hosted zone declaring `DelegationSetId`, used to go through Cloud Control. Each now rides on `CreateMountTarget` / `CreateHostedZone` and is read back for `cdkd drift`. `DelegationSetId` is read back bare, as Cloud Control reports it, unless the template spells the same id as `/delegationset/<id>`. `DescribeMountTargets` does not report `IpAddressType`, so it is derived from which addresses the mount target holds. `Fn::GetAtt [MountTarget, IpAddress]` now resolves to the mount target's IPv4 address. Before, on the SDK route it fell back to the mount target id. To supply it, `cdkd import` of a mount target now calls `DescribeMountTargets`, so it needs `elasticfilesystem:DescribeMountTargets`, and a mount target that no longer exists is not imported. Source: `src/provisioning/providers/efs-provider.ts`, `route53-provider.ts`.
