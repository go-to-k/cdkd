- **A 1-3 character secret in a nested-stack parameter spelled as an `Fn::Join` / `Fn::Sub` around an `ssm` token (or a service left to a `Ref`), or with a `Ref` outside the token, is no longer persisted in plaintext in the child, the parent's row or a grandchild's log lines (issue [#3156](https://github.com/go-to-k/cdkd/issues/3156))** -- `src/deployment/secret-redaction.ts`, `src/deployment/intrinsic-function-resolver.ts`; cases in `tests/unit/deployment/nested-stack-refused-frame-carry.test.ts` and `nested-stack-refused-frame-carry-delegation.test.ts`, a `Framed` arm in the `nested-stack-3level` integ. The sub-floor carry certified an intrinsic frame only on a `secretsmanager:` / `ssm-secure:` spelling the position pass wrote. The resolver now records, per `Fn::Join` / `Fn::Sub` object and pass, each token it replaced with that replacement's own verdict (fresh, cached or from a region-pinned sibling); a second, different resolution of the object poisons the record. The carry certifies a frame when exactly one secret replacement produced the value, and where the position pass wrote the leaf it must have written that spelling. The middle stack's bag then holds the whole value, so the grandchild's `Parameter`, `Ref` and `Fn::Join` lines mask it whole, pass-through and re-wrapped alike; `nested-stack-secret`'s `SubFloorPinSsm` lines now read `***`, not `port:***`. Still refused (listed on `recordNestedStackParameterExpressions`): a public or multiple replacement, a token inside a nested intrinsic part or a used `Fn::Sub` variable, an `Fn::If` around the frame, an affix holding another recorded secret, and two outside-the-token frames of one value through different tokens ([#3306](https://github.com/go-to-k/cdkd/issues/3306)). Resolved values are unchanged.
