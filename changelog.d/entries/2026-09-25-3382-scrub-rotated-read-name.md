- **`cdkd scrub` no longer reports a stack clean when a cross-stack read name still holds a secret's value from before a rotation (issue [#3382](https://github.com/go-to-k/cdkd/issues/3382))** -- `src/cli/commands/scrub.ts`, `docs/cli-scrub.md`. A stored `imports[].exportName`, `outputReads[].sourceStack` or `outputReads[].outputName` written by an older binary around a secret that has since ROTATED matched none of scrub's needles, which are the secret's current value, so the run printed `No plaintext secrets found` and `--fail` exited 0 with the plaintext still in `state.json`. Scrub still cannot repair such a name, but it now reports it: an entry that no read in today's template reproduces, and whose name fits the shape of a secret-bearing read of the same producer and region, is a finding. The warning names the list and index (`state.imports[1]`), never the value; the stack is not called clean and `--fail` exits 1. An ordinary import from the same producer stays green because this run re-read it. Tests: `tests/unit/cli/commands/scrub-rotated-cross-stack-read.test.ts`.
