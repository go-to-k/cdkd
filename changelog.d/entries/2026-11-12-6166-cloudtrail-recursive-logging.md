- **The SDK provider wires `AWS::CloudTrail::Trail` `RecursiveLogging` (issue [#6166](https://github.com/go-to-k/cdkd/issues/6166))** -- `src/provisioning/providers/cloudtrail-provider.ts`, `cloudtrail/core.ts`, `update.ts`, `shared.ts`, `read-state.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, unit tests, the CloudTrail wire case, and the `cloudtrail-trail` integ. Before, a trail declaring `RecursiveLogging` routed through Cloud Control. Now it rides `CreateTrail` and `UpdateTrail` on the SDK route, and `readCurrentState` reads it back from `GetTrail` (AWS's documented default `true` when absent), so `cdkd drift` sees a console-side change. A removal from the template sends nothing, so the trail keeps its live value; whether CloudFormation resets it is unmeasured, so a removed non-default value is named in the update's kept-removal warning, as `IsOrganizationTrail` is. `AWS::CloudTrail::Trail` now has no SDK-unwired property. Resources already deployed through Cloud Control stay there.
