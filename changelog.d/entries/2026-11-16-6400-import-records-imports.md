- **`cdkd import` now records the stack's `Fn::ImportValue` reads, so destroying the producer is refused again (issue [#6400](https://github.com/go-to-k/cdkd/issues/6400))** -- `src/cli/commands/import/resolve-properties.ts`, `src/cli/commands/import/stack-state.ts`, `src/deployment/deploy-engine/deploy-flow/no-change.ts`. A consumer stack brought in with `cdkd import` was written without `state.imports`, and a selective import into an existing record dropped the list the record held. That list is what makes `cdkd destroy <producer>` refuse while a consumer still reads the export, so the destroy went ahead and deleted a resource the consumer depended on. CloudFormation refuses that delete. A later diff-clean deploy did not repair the record either. An import now records the reads its resources and Outputs resolve (`Fn::ImportValue` into `imports`, `Fn::GetStackOutput` into `outputReads`), keeping the ones the record already held. A no-change deploy also saves a read the record is missing, so a record an older import wrote is repaired on its next deploy.
