- **`cdkd deploy` refuses an `Export.Name` holding any `NoEcho: true` parameter's value, whatever reads it and in any declaration order (issue [#4043](https://github.com/go-to-k/cdkd/issues/4043), Phase B)** -- `src/deployment/deploy-engine/outputs.ts`, `src/deployment/outputs-export-alias.ts` (`noEchoParameterValueSeed`), `src/analyzer/outputs-diff.ts`, `src/cli/commands/diff-recursive.ts`. Before, the refusal counted a value only when an output value, or the `Export.Name` of the same or an EARLIER-declared output, read it. So a literal name spelling a value only a resource reads, a name holding a needle only a LATER `Export.Name` recorded (an `Fn::Base64` encoding), and a name reaching this stack's value through an attribute were published as keys of `state.outputs`, `exportNames` and the exports index, in plaintext. Now the verdict is seeded with every `NoEcho` value the stack holds (on a nested child, each parent `NoEcho` value a child parameter carries), and every `Export.Name` is resolved before any alias is decided. A `Number` counts as the operator wrote it too (`0x1F2A`), and a refusal caused only by a `NoEcho` value says so in its warning. The floor is unchanged: a name equal to the value at any length, one containing it at 4 or more characters. An unrelated name that happens to contain a short `NoEcho` value is now refused too, the same bound secrets already take. `cdkd diff` previews the same verdict. Still published: another stack's value through `Fn::ImportValue`, a piece or encoding of the value that a resource computes and an attribute echoes, a nested child's parameter fed a parent value without a `Ref` (which `cdkd diff` refuses), a 1-3 character value inside a longer name, and a failed output's alias carried forward by a deploy with no resource change.
