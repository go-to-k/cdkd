- **A secret assembled into a `{{resolve:...}}` token of a service cdkd does not resolve is no longer sent to AWS or written to state (issue [#2743](https://github.com/go-to-k/cdkd/issues/2743), PR #3475)** -- `intrinsic-function-resolver.ts`, `secret-redaction.ts`, gated arms on the `secrets-dynamic-ref` integ. An `Fn::Sub` / `Fn::Join` that puts a resolved secret where a reference's service name goes (`{{resolve:${Pw}}}` over a `secretsmanager` variable) assembles `{{resolve:<plaintext>}}`. The unsupported-service arm warned and left that token in the value, so a deploy went green while handing it to the provider as the property's value, and redaction's rule for text inside a `{{resolve:...}}` span spared it into `state.json` (`properties`, `observedProperties`, `outputs`, the exports index), the rollback journal and the deploy summary's `Outputs:` lines. **Behavior change:** on the template route such a token is refused with a masked, non-retryable `Refusing to resolve {{resolve:***}}` error. In a resource property the resource fails before its provider is called and the deploy rolls back; in an Output the output is skipped under a warning and the deploy exits 0 (`--strict-getatt` fails it). A token carrying no secret still warns and stays as written, and so does any token in PERSISTED text (`cdkd drift`, the rollback replay, a producer's stored output), which AWS already holds. Independently, state redaction spares text inside a `{{resolve:...}}` span only when it names `secretsmanager`, `ssm` or `ssm-secure`: a recorded plaintext in any other span is replaced by its expression, so `cdkd scrub` heals a record an older release leaked into (the result is unresolvable text, not plaintext; deploy the corrected template first, see `docs/troubleshooting.md`). Cost: a look-alike token whose text coincides with a recorded secret of four or more characters is refused when the secret resolved first, else rewritten in state like other text.
