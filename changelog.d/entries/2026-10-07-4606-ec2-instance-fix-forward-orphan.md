- **A successful fix-forward deploy now deletes the EC2 instance an earlier failed CREATE left under the same logical id (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606))** -- `src/provisioning/providers/ec2-provider.ts`. When an `AWS::EC2::Instance` CREATE failed after `RunInstances` and its cleanup terminate failed too, the instance was journaled as a proven orphan. If a later deploy created a new instance under the same logical id, that successful deploy warned, named the earlier instance, exited `2` and left it running. `EC2Provider` now answers `isSameResource` for instances, using the AWS-generated `i-` instance id. The client must be in the stack's region, and the record's instance must read back live (`pending`, `running`, `stopping` or `stopped`). The earlier instance is then `different`, whether it still runs, is `shutting-down` / `terminated`, or is not found, so the settle terminates it. Equal ids are `same`. Any other id form and a failed read stay `unknown`, which keeps the previous warning and exit `2`. An earlier instance EC2 no longer lists is named in one info line; one still listed as `shutting-down` or `terminated` is settled quietly by the terminate. A termination-protected earlier instance is not deleted: the delete fails, the journal keeps the entry, and the next successful deploy tries again. Tests: `tests/unit/provisioning/ec2-instance-same-resource-4606.test.ts`. Integ `ec2-instance` Phase 1b runs the read against live instances, a terminated instance and an id that never existed.
