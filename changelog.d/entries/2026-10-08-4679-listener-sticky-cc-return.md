- **An ALB listener recorded `provisionedBy: 'cc-api'` now returns to the SDK provider on its next deploy that changes it, so a `ListenerAttributes` key removed from the template is reset instead of keeping its old value** (`src/provisioning/provider-registry.ts`, go-to-k/cdkd#4679). A listener first deployed while tagged, before go-to-k/cdkd#4673 declared its `Tags` handled, was created through Cloud Control, and the sticky routing rule kept that record there. Cloud Control's update sends no `ModifyListenerAttributes` for a removed key, so for example `routing.http.response.server.enabled` stayed `false` after it was dropped. `AWS::ElasticLoadBalancingV2::Listener` is now an `sdk-coverage` sticky exemption: the record moves to the SDK provider in place, with its listener ARN unchanged, and that deploy resets the removed key. `cdkd diff` marks the listener `[returning to SDK provider]`, and `--pin-cc-api <LogicalId>` declines the move for one deploy. A key already removed under Cloud Control by an earlier cdkd is not in the record any more, so nothing resets it: set it to its default value in the template and deploy.
