- **`cdkd scrub` repairs the cross-stack exports index, not only `state.json` (issue [#2667](https://github.com/go-to-k/cdkd/issues/2667))** -- `src/cli/commands/scrub.ts`, `src/state/export-index-store.ts`, `docs/cli-scrub.md`, `docs/state-management.md`, `tests/unit/cli/commands/scrub-export-index.test.ts`, `tests/unit/state/export-index-persisted-read.test.ts`, `tests/unit/deployment/outputs-redaction-idempotence.test.ts`. **What it does now:** after each stack's `state.json` write, scrub reads `{state-prefix}/_index/{region}/exports.json` -- one store per region it touched -- and for every entry whose `producerStack` / `producerRegion` name that stack, rewrites the entry's VALUE to `state.outputs[<entry name>]` where that value carries `{{resolve:` and differs. `patchEntry` per entry: nothing added, nothing removed. **Convergence, not a plaintext match:** scrub's map comes from LIVE resolution, so it holds the secret's value as it is NOW while an entry written before a rotation holds the legacy one; the state record is what a redeploy writes either way. The lookup runs in ONE direction -- an `Export.Name` alias is a key of the outputs bag, and `ExportIndexEntry` carries no output-key field. **`--dry-run` writes nothing and still READS**, so `--dry-run --fail` exits 1 on an index divergence over records that already hold the expression. **Reported, not written:** a refused write or an unreadable index raises `SCRUB_EXPORT_INDEX_INCOMPLETE` (exit 2) naming the remainder, since a swallowed failure leaves the value in a region-wide object readable with `s3:GetObject` and no version id; an owned entry ABSENT from `state.outputs` is warned; an entry whose producer this run did not scrub is coverage and never reddens `--fail`. The resolver still gets no `exportIndex`, so no `patchEntry` fires as a resolution side effect. No new flag, no IAM change, no schema bump. A rewritten entry is SUPERSEDED, not erased -- `docs/cli-scrub.md` covers `exports.json` there too.
