- **The synthesizer's account lookups and the `cdkd local` ECR puller now use explicitly supplied `AwsClients` credentials (issue [#3588](https://github.com/go-to-k/cdkd/issues/3588))** -- `src/synthesis/synthesizer.ts`, `src/local/ecr-puller.ts`; tests in `tests/unit/synthesis/synthesizer-macro-integration.test.ts`, `tests/unit/local/ecr-puller.test.ts` and `tests/unit/utils/ambient-client-defaults-fence.test.ts`. A library caller that installed `AwsClients` with an explicit `credentials` object had the synthesizer's two `GetCallerIdentity` calls (the synth-time account and the macro-expansion default state bucket) and the ECR puller's `GetCallerIdentity`, `AssumeRole` and ECR login sign with the SDK's default credential chain instead. They now go through `ambientClientDefaults()` / `clientDefaultsFor()`, with an assumed `--ecr-role-arn` role still outranking the caller's own credentials on the ECR login. The puller's process-wide caller-account and assumed-role caches are keyed by that identity as well, so a second identity is never told the first one's account or handed the role credentials the first one obtained. Both files leave the fence allow-list. CLI runs are unaffected: no command passes explicit credentials. Three sites held by an open pull request still follow separately.
