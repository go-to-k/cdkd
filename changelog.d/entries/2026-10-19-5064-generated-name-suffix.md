- **New stacks get CloudFormation-style generated names: `{stackName}-{logicalId}-{suffix}` (issue [#5064](https://github.com/go-to-k/cdkd/issues/5064), part 2)** -- `src/provisioning/resource-name.ts`, `src/deployment/deploy-engine/deploy-flow.ts`, `src/deployment/deploy-engine.ts`, the IAM role / managed policy / inline policy and EventBridge rule providers, and the commands that replay provider calls (`cdkd rollback`, `drift --revert`, `state refresh`, destroy). A resource the template does not name, in a stack whose record carries a stack instance id (every stack first deployed by this version), is named `{stackName}-{logicalId}-` plus 12 hex characters derived from that id and the logical id; the `{stackName}-{logicalId}` part is cut so the whole fits the type's limit. The name stays the same for the stack's whole lifetime. After `cdkd destroy`, a redeploy gets a new id and new names, so it no longer collides with, or takes back, a resource a `DeletionPolicy: Retain` (or `cdkd state orphan`) left behind; the first deploy warns once and names `cdkd import` for adopting such a resource. Existing stacks keep their names: a stack whose record predates the id keeps `{stackName}-{logicalId}`, and nothing is renamed or replaced. Declared names never change. An `update()` that re-derives a name keeps the recorded one of an un-named resource rather than replace it.
