- **An `AWS::RDS::DBProxyTargetGroup` whose `DBClusterIdentifiers` / `DBInstanceIdentifiers` is not a list of RDS DB identifiers is refused before any AWS call, instead of being walked character by character** (`src/provisioning/providers/rds-dbproxy-targetgroup-provider.ts`, go-to-k/cdkd#3945). `update()` cast both sides to `string[]`, so a rollback revert or `cdkd drift --revert` replaying a recorded `"prod-cluster"` as the desired side deregistered the real target and registered `p`, `r`, `o`, ..., one-letter identifiers an unrelated DB instance can carry. Both sides are now read as identifier lists first; a malformed one throws, naming the side and property, before the connection pool is touched. A recorded list kept as a dynamic reference or its mask is read from the proxy instead (add-only). Identifiers compare case-insensitively. `create()` refuses the same shapes. `delete()` finishes a record naming no target and one whose proxy or group is already gone, and otherwise skips a malformed list (record kept, exit 2) rather than issuing a Deregister that named no target; a recorded `TargetGroupName` other than `default` is skipped too unless its proxy is gone. `create()`, `update()`, `delete()` and `cdkd drift` read a non-string `DBProxyName` as missing, and `delete()` and `cdkd drift` read a non-string `TargetGroupName` as `default`. `cdkd drift` reads every page of targets, no longer reports a registered cluster's member instances as `DBInstanceIdentifiers`, and reports a case-only match in the recorded spelling. The create and update debug lines mask identifiers. The missing-`DBProxyName` remedy prints its command through `pasteableAwsCommand` and only ever names the `default` group (part of go-to-k/cdkd#3136). Tests: `tests/unit/provisioning/rds-dbproxy-targetgroup-provider.test.ts`.
