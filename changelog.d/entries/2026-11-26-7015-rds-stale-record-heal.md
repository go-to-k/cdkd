- **`cdkd deploy` / `cdkd diff`: an RDS DB instance record left with the pre-modify port, CA or Multi-AZ zone is re-read once (issue [#7015](https://github.com/go-to-k/cdkd/issues/7015))** -- `src/deployment/intrinsic-resolver/getatt-stale-shape.ts`, `src/deployment/intrinsic-resolver/getatt-heal.ts`, `src/deployment/intrinsic-resolver/getatt.ts`, `src/deployment/deploy-engine/attribute-healer.ts`. Before #7006, an in-place update of an `AWS::RDS::DBInstance` changing `Port`, `CACertificateIdentifier` or `MultiAZ` recorded the endpoint port, certificate details or secondary zone from a read that still reported the OLD value, and a later `Fn::GetAtt` reader (a security group rule built from `instance.dbInstanceEndpointPort`) resolved that old value until the resource was next updated. Such a record is now recognised from its own contents (its property disagrees with the attribute that reports it; an Aurora member instance is exempt), and a `Fn::GetAtt` of an affected attribute re-reads it and serves what AWS reports, as CloudFormation's post-update read does. An ordinary deploy issues no extra AWS call. `cdkd deploy` saves the read; if AWS still reports a different value, it records a hash of the compared values in the new optional `attributesReadAfterApply` field so the record is not re-read again until one of them changes. `cdkd diff` serves the same read and writes nothing. Tests: `tests/unit/deployment/getatt-stale-shape-7015.test.ts`.
