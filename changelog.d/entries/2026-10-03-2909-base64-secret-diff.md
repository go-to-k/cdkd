- **`cdkd diff` no longer reports a change on every run for an `Fn::Base64` over a secret reference, so `cdkd diff --fail` can pass for such a stack (issue [#2909](https://github.com/go-to-k/cdkd/issues/2909))** -- `src/deployment/intrinsic-resolver/functions.ts`, `src/deployment/intrinsic-resolver/context.ts`, `src/analyzer/outputs-diff.ts`. The diff leaves a `{{resolve:secretsmanager:...}}` / `{{resolve:ssm-secure:...}}` reference (or a plain `ssm` one to a `SecureString`) unresolved and encoded the reference TEXT, while the deploy encodes the secret and stores `***` for it, so the two never matched: a resource or output holding such a value (the CDK EC2 `UserData` shape) always showed as changed, and the deploy then skipped it. The diff now compares such an `Fn::Base64` as `***`, the value the deploy stores, unless its input also holds a `NoEcho` value supplied in the same deploy, which must still reach AWS. Bound: an edit to the text around, or the target of, a secret reference inside the same `Fn::Base64` is not shown by the diff either (nor is a rotated value); the deploy already did not send it ([#4451](https://github.com/go-to-k/cdkd/issues/4451)). Tests: `tests/unit/deployment/intrinsic-base64-diff-mask-2909.test.ts`, `tests/unit/deployment/deploy-engine-base64-secret-noop.test.ts`, `tests/integration/secrets-dynamic-ref/`.
