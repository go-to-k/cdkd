- **`--recreate-via-cc-api` refuses a resource whose type Cloud Control cannot create, instead of deleting it and failing to recreate it (issue [#3887](https://github.com/go-to-k/cdkd/issues/3887))** -- `src/deployment/recreate-targets.ts` (`blockedNoCcRoute`), `src/cli/commands/deploy.ts`, `src/provisioning/provider-registry.ts`, with unit tests in `tests/unit/deployment/recreate-targets.test.ts`. The recreate deletes the existing resource through its SDK provider and then creates the replacement through Cloud Control. For a type AWS reports as `NON_PROVISIONABLE`, such as `AWS::CodeBuild::Project`, `AWS::IAM::Policy` or `AWS::DocDB::DBCluster`, and for a type whose SDK provider opts out of the Cloud Control fallback, that create fails. The resource was already deleted, the error blamed a missing SDK provider, and a rollback could not bring it back. The deploy now fails before anything is touched (`RECREATE_TARGETS_INVALID`, exit 1) and names each such resource with the reason. There is no bypass flag.
