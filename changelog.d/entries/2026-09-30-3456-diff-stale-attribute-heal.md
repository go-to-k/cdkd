- **`cdkd diff` now previews a `Fn::GetAtt` over a state record that lacks the attribute (or holds a pre-#1681 placeholder ARN) as the value `cdkd deploy` resolves (issue [#3456](https://github.com/go-to-k/cdkd/issues/3456))** -- `src/cli/commands/diff.ts`, `src/cli/commands/diff-recursive.ts`, new `src/deployment/read-only-attribute-healer.ts`, `src/deployment/stale-attribute-heal.ts`, and new unit tests `tests/unit/cli/diff-stale-attribute-heal-3456.test.ts`, `tests/unit/cli/diff-recursive-stale-attribute-heal.test.ts`, `tests/unit/deployment/read-only-attribute-healer.test.ts`. `cdkd deploy` re-reads such a record from AWS through its provider's `import()` ([#1852](https://github.com/go-to-k/cdkd/issues/1852)); `cdkd diff` did not, so it previewed the raw intrinsic or the physical id and could print `No changes detected` for an update the deploy then made -- measured live on an `AWS::Lambda::Url` imported with `--migrate-from-cloudformation`, whose dependent `AWS::SSM::Parameter` the deploy updated. The diff now issues the same read, once per resource per run, in the stack's own region, on every resolver context it builds (the resource diff, conditions, Outputs, and a nested child's `Parameters`). Nothing it reads is written to state; the next deploy records it. A failed read previews as before and does not fail the diff. Custom resources and nested stacks are never re-read. A credential attribute AWS returns unmasked (a Cognito user pool client's `ClientSecret`) is now printed by the diff for such a record, in its rows, `--json` and `--verbose`; before, the diff printed the unresolved reference. The rollback-orphan adoption preview's provider read ([#2943](https://github.com/go-to-k/cdkd/issues/2943)) now also runs in the stack's region rather than the command's. Documented in `docs/_contents/cli-diff.md`.
