- **Eleven more composite keys are encoded rather than separated, so a planted name can no longer make one thing answer for another (issue [#3496](https://github.com/go-to-k/cdkd/issues/3496))** -- `src/state/record-keys.ts` plus nine files across `src/analyzer/`, `src/deployment/`, `src/provisioning/providers/` and `src/state/`, two suites plus one new one. These are the keys OUTSIDE the record class [#3323](https://github.com/go-to-k/cdkd/issues/3323) closed. The consequential ones: `lambda-vpc-deps.ts` dropped a delete-dependency EDGE, so a Lambda could be deleted without waiting on the subnet or security group holding its ENI; `idempotency-token.ts`'s memo key is an IDENTITY, and a collision hands a second create the first's token -- the file documents that failure itself; the resolver's CFn-outputs cache could answer one stack's `Fn::GetStackOutput` with another stack's outputs, `s3-replication-purge-gap.ts`'s warn key joined FREE TEXT; and three provider attribute caches keyed `physicalId` against an attribute name with a PRINTABLE separator, read BEFORE the attribute switch, so one table's or proxy's attribute could answer another's `Fn::GetAtt`. Moving those three keys also had to move their READERS: two RDS providers evict by scanning for a leading `physicalId`, and `injectiveKeyPrefix` derives that prefix from the same encoder so the two cannot drift. Every surviving exemption reason was rewritten as what is CHECKED rather than what a value is expected to be. `secret-redaction.ts`'s two keys stay separated, on REACH rather than layering. Their false justifications are fixed instead: `CROSS_STACK_KEY_SEPARATOR` claimed no AWS name can contain a NUL while its halves are TEMPLATE literals, and what makes it safe is not injectivity but that a collision POISONS the slot into a refusal. The `deploy-engine.ts` rows stay open on the issue -- two PRs held that file.
