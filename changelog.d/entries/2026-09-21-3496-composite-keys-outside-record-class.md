- **Eleven more composite keys are encoded rather than separated, so a planted name can no longer make one thing answer for another (issue [#3496](https://github.com/go-to-k/cdkd/issues/3496))** -- `src/state/record-keys.ts` plus nine files across `src/analyzer/`, `src/deployment/`, `src/provisioning/providers/` and `src/state/`, two suites plus one new one. These are the keys OUTSIDE the record class [#3323](https://github.com/go-to-k/cdkd/issues/3323) closed. The consequential ones: `lambda-vpc-deps.ts` dropped a delete-dependency EDGE, so a Lambda could be deleted without waiting on the subnet or security group holding its ENI; `idempotency-token.ts`'s memo key is an IDENTITY, and a collision hands a second create the first's token -- the file documents that failure itself; the resolver's CFn-outputs cache could answer one stack's `Fn::GetStackOutput` with another stack's outputs, `s3-replication-purge-gap.ts`'s warn key joined FREE TEXT, so it was never injective; and three provider attribute caches keyed `physicalId` against an attribute name with a PRINTABLE separator, read BEFORE the attribute switch, so one table's or proxy's attribute could answer another's `Fn::GetAtt`. Every surviving exemption reason was rewritten as what is CHECKED rather than what a value is expected to be: "CFn logical ids are alphanumeric" is refuted by cdkd's own comment that "nothing enforces that constraint HERE". `secret-redaction.ts`'s two keys are deliberately left separated, on REACH rather than layering: whoever can forge such a coordinate can aim the real one. Their false justifications are fixed instead -- `CROSS_STACK_KEY_SEPARATOR`'s claimed no AWS name can contain a NUL while its halves are TEMPLATE literals, and what makes that key safe is not injectivity but that a collision POISONS the slot and degrades to a refusal. The `deploy-engine.ts` rows stay open on the issue -- two PRs held that file.
