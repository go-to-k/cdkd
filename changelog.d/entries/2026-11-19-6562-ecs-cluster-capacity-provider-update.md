- **A cluster update changing capacity providers and settings together no longer fails with `UpdateInProgressException` (issue [#6562](https://github.com/go-to-k/cdkd/issues/6562))** -- `src/provisioning/providers/ecs/cluster-task-definition.ts`, the new `src/provisioning/providers/ecs/cluster-attachments.ts`, unit tests and the `ecs-cluster-capacity-settings` integ fixture. `PutClusterCapacityProviders` leaves an `AWS::ECS::Cluster`'s attachments `UPDATE_IN_PROGRESS` for a few seconds, and cdkd sent `UpdateCluster` for `ClusterSettings` right after it: ECS refused it, cdkd's retry re-sent the Put into the same busy cluster, and the deploy rolled back, intermittently, where CloudFormation deployed the same change. cdkd now sends `PutClusterCapacityProviders` only when `CapacityProviders` or `DefaultCapacityProviderStrategy` changed (before, every update of a cluster declaring either sent it), waits after every Put for the attachments to leave `UPDATE_IN_PROGRESS` (up to 600s, raised by `--resource-timeout AWS::ECS::Cluster=...`), fails the update when they end `UPDATE_FAILED`, and re-sends a cluster write ECS refuses while they are still updating. An update that sends no Put makes no extra call. Removing both properties from the template now clears both lists, as CloudFormation does; cdkd used to leave the providers attached.
