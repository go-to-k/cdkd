- **BREAKING: `cdkd state destroy --all` is removed (issue [#3865](https://github.com/go-to-k/cdkd/issues/3865))** -- `src/cli/commands/state.ts`, `src/utils/interrupt-signals.ts`, with unit tests in `tests/unit/cli/state-destroy.test.ts` and `tests/unit/cli/state-destroy-command-sigint.test.ts`. `--all` destroyed every stack in the state bucket, and that bucket is shared by every CDK app deployed to the account, so one command deleted stacks across apps. Destroy is now scoped to what you name or to one app, matching the #3839 decision for `cdkd destroy`. Passing `--all` exits 1 with `STATE_DESTROY_ALL_REMOVED` before the bucket is read or anything is prompted, locked or deleted, including when stack names are also given, and the message points at the replacements: name each stack (`cdkd state destroy '<stacks...>'`; `cdkd state list` shows them), or run `cdkd destroy --all` from the CDK app, which destroys only that app's stacks. The option is kept hidden so this message replaces commander's generic unknown-option error. Its batch confirmation prompt went with it, along with the prompt-abort signal and `isPromptAbortError` that only that prompt used. The force-quit notice printed when Ctrl-C lands before a stack's teardown is armed now says "on a multi-stack run" instead of "on an --all run". Docs: `docs/_contents/cli-state.md`, `docs/_contents/cli-destroy.md` (the batch prompt row and its exit-130 row; exit 130 now documents the Ctrl-C force-quit), `docs/_contents/state-store.md`.
