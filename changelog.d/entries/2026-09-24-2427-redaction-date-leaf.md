- **A `Date` in a resource's recorded AWS readback (`LastModified`, `CreationDate`, ...) is persisted as its ISO timestamp instead of `{}` on resources that record a dynamic-reference secret** (issue [#2427](https://github.com/go-to-k/cdkd/issues/2427)) -- `src/deployment/secret-redaction.ts`. The secret-redaction value walk rebuilt every object it visited, and a `Date` has no own entries, so whenever the resource's secrets map was non-empty (a stack that resolved at least one `{{resolve:...}}` reference) the `observedProperties` drift baseline got `{}` at that field: a permanent phantom difference in `cdkd drift`, and a value `cdkd drift --revert` could push. The same walk runs over `properties`, `attributes` and `outputs`, and `cdkd drift --accept` and `cdkd scrub` reach it too. The walk now keeps an unmodified `Date` (exact prototype, a real date value, no own keys) by identity (`isOrdinaryDate`), after scanning its ISO form through the string arms so a recorded secret spelled as a timestamp is still replaced. Every other non-plain object is still rebuilt and scanned, since `JSON.stringify` persists a class instance's own fields and returning one untouched could persist a plaintext the scan would have redacted. A `{}` already persisted is not repaired in place; `cdkd state refresh-observed` re-captures the baseline.
