- **A pasteable `cdkd ...` command no longer names a value that would run as shell with its quotes stripped (issue [#4205](https://github.com/go-to-k/cdkd/issues/4205))** -- `src/utils/pasteable-command.ts`, `src/state/lock-contention-message.ts`, `src/state/malformed-resources-bag.ts`. Before, a recovery command named any printable value shell-quoted (`cdkd state show 'x; touch OWNED; #'`). Quoting holds only while the quote parity before the value is even, and an apostrophe pasted above the command (`this stack's` in cdkd's prose, a `'` in AWS's error text, terminal output) flips it, so a stack name or region planted in the state bucket or a cloud assembly ran on the operator's machine. Now `pasteableCommand` and the `cdkd force-unlock` recovery flags use the same measured predicate [#4198](https://github.com/go-to-k/cdkd/pull/4198) introduced for the `aws ...` remedies, moved to `src/utils/pasteable-command.ts` (`PASTE_ARG_UNSAFE` / `isInertUnquoted`) as the one test: such a value is a quoted hole (`'<stack>'`), a mid-word `#`, `=`, `,` or `~` (`Parent~Child`) is still named, and a force-unlock hint carrying one is suppressed. This retires naming `It's Legacy` exactly in the `cdkd orphan` refusals (#3359 / #3523). Prose in `deploy-engine.ts` and `asset-storage.ts` that printed a raw stack name or region now renders it bounded or described.
