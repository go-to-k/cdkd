- **`cdkd deploy` retries an `AWS::EventsV2::Subscriber` create that EventBridge refuses as a concurrent modification, so parallel Subscribers on one event bus no longer fail and roll back the deploy (issue [#6944](https://github.com/go-to-k/cdkd/issues/6944))** -- `src/deployment/retryable-errors/patterns.ts`, `tests/unit/deployment/retryable-errors.test.ts`. EventBridge serializes Subscriber mutations per bus, and cdkd creates sibling Subscribers in parallel, so a create could fail with "This resource was modified concurrently. Please retry your request." (HTTP 409). The deploy engine did not classify that message as transient, so the deploy failed and rolled back while the AWS CDK CLI deployed the same app. The message now takes the exponential retry cadence, like API Gateway v2's concurrent-modification refusal.
