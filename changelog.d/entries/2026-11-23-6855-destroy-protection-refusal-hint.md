- **`cdkd destroy` now names deletion protection when AWS refuses a delete for it (issue [#6855](https://github.com/go-to-k/cdkd/issues/6855))** -- `src/cli/commands/destroy-runner/protection-refusal-hint.ts`, `src/cli/commands/destroy-runner/delete-resource.ts`, `tests/unit/cli/destroy-protection-refusal-hint.test.ts`, `tests/unit/cli/destroy-runner-protection-hint-6855.test.ts`, `tests/integration/remove-protection/verify.sh`. A destroy of a resource whose deletion protection was on (set in the app or out of band) printed only AWS's error code, such as `InvalidParameterException`, naming neither the cause nor the flag that removes it. For a type `--remove-protection` covers, the failure line is now followed by a cdkd line saying AWS refused for deletion protection and naming `--remove-protection`. It is printed only when an AWS-written error in the failure says so, and never when the flag was already passed.
