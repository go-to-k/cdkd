- **Re-running a destroy after fixing a Firehose delivery stream stuck in `DELETING_FAILED` no longer fails on the stale status** -- `src/provisioning/delete-gone-wait.ts`, `src/provisioning/providers/firehose-provider.ts`, and unit tests. The post-delete wait treated `DELETING_FAILED` as terminal on its very first status read, and a stream still in that status when the re-run's `DeleteDeliveryStream` is accepted can report it on the read straight after. The status is now terminal only once the wait has seen another status or one poll interval has passed. The failure message now also says that cdkd never sends `AllowForceDelete`, so a forced delete has to be done outside cdkd.
