- **A failed create, update or delete of a Glue Database, Table, SecurityConfiguration, Workflow, Job, Crawler, Connection or Trigger no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events, and no longer replaces the failure with a `TypeError` when the thrown value cannot be converted to text (issues [#2319](https://github.com/go-to-k/cdkd/issues/2319), [#3341](https://github.com/go-to-k/cdkd/issues/3341))** -- `src/provisioning/providers/glue-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access-denied error, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (`AccessDeniedException. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log through the operation's secret masker. A cdkd-authored or transport error keeps its text. The AWS error stays as the `cause`, so an IAM grant that is still propagating is retried as before, and an occupied table name is still classified as a name collision.
