- **Removing `Description`, `KmsKeyIdentifier`, `LogConfig` or `DeadLetterConfig` from an `AWS::Events::EventBus` now clears it, matching CloudFormation (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- A real CloudFormation A/B showed CloudFormation clears each removed property: no description, the AWS owned key instead of the customer managed key, `LogConfig` at `OFF` / `NONE`, and no dead-letter queue. `UpdateEventBus` keeps any field it is not given, so cdkd used to leave all four live, including encryption with a key the template no longer names. cdkd now sends the clearing value for each one (`''`, `''`, `OFF` / `NONE`, an empty queue ARN). `cdkd drift --revert` writes no such clear. Changed: `src/provisioning/providers/eventbridge-bus-provider.ts`, `tests/unit/provisioning/eventbridge-bus-removal-1160.test.ts`, `tests/integration/eventbridge/`.
