- **`cdkd drift --revert` no longer removes what a sibling resource of the stack attached to a topic, a cluster, an Auto Scaling group, an EMR cluster or an Elastic IP (issue [#6610](https://github.com/go-to-k/cdkd/issues/6610))** -- `src/provisioning/sibling-owned-members.ts` (new), `src/cli/commands/drift/compare.ts`, `src/cli/commands/drift/revert-outcome.ts`, `src/deployment/deploy-engine/observed-capture.ts`, unit tests, integ fixtures `drift-sns-sibling-subscription` and `drift-ecs-capacity-association`. One table now records every resource type that writes into another resource's property, with each pair's verdict. For the pairs it handles, drift leaves out of both sides the members a sibling record of the same stack writes: an `AWS::SNS::Subscription` on a topic that declares an inline `Subscription` list, an `AWS::AutoScaling::LifecycleHook` on its group, an EMR `InstanceGroupConfig` / `InstanceFleetConfig` task group or fleet on its cluster, the `CapacityProviders` and `DefaultCapacityProviderStrategy` an `AWS::ECS::ClusterCapacityProviderAssociations` attaches to a cluster that declares neither, and the inline `Policies` an `AWS::IAM::Policy` / `RolePolicy` / `UserPolicy` / `GroupPolicy` writes on a Cloud Control-routed principal (owned only under the document the stack recorded) or a baseline recorded before the provider's readback filtered them, and the `InstanceId` an `AWS::EC2::EIPAssociation` sets on a Cloud Control-routed address. Before, drift reported those members and `--revert` removed them, or sent a stale list back (`PutClusterCapacityProviders`). `--revert` now sends the live sibling-owned members, so the provider neither removes nor re-adds them, while a member nothing in the stack writes is still reported and removed. A deploy that removes such a sibling, or changes what it writes, drops what it stopped writing from the parent's recorded baseline in memory, with no AWS call.
