- **`cdkd drift --revert` no longer removes what a sibling resource of the stack attached to a topic's subscriptions, a cluster's capacity providers or a principal's inline policies (issue [#6610](https://github.com/go-to-k/cdkd/issues/6610))** -- `src/provisioning/sibling-owned-members.ts` (new), `src/cli/commands/drift/compare.ts`, `src/cli/commands/drift/revert-outcome.ts`, `src/deployment/deploy-engine/observed-capture.ts`, unit tests, integ fixtures `drift-sns-sibling-subscription` and `drift-ecs-capacity-association`. One table now records every resource type that writes into another resource's property, with the pair's verdict: handled by it, handled by an earlier per-pair fix, or not colliding (the parent's read never returns the child's members). For the pairs it handles, drift leaves out of both sides the members a sibling record of the same stack writes: an `AWS::SNS::Subscription` on a topic that declares an inline `Subscription` list, the `CapacityProviders` and `DefaultCapacityProviderStrategy` an `AWS::ECS::ClusterCapacityProviderAssociations` attaches to a cluster that declares neither, and the inline `Policies` an `AWS::IAM::Policy` / `RolePolicy` / `UserPolicy` / `GroupPolicy` writes on a Cloud Control-routed principal or a baseline recorded before the provider's readback filtered them, and the `InstanceId` an `AWS::EC2::EIPAssociation` sets on a Cloud Control-routed address. Before, drift reported those members and `--revert` unsubscribed the sibling's subscription or sent the cluster's stale list through `PutClusterCapacityProviders`. `--revert` now sends the live sibling-owned members, so the provider neither removes nor re-adds them, while a member nothing in the stack writes is still reported and removed. A deploy that removes such a sibling, or changes what it writes, drops what it stopped writing from the parent's recorded baseline in memory, with no AWS call.
