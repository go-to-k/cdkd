- **`cdkd drift --revert` records a provider narrowing whose value is a non-plain object (a `Date`, a `Uint8Array`) instead of calling it unchanged, and `--accept`'s post-write check no longer calls two such values equal (issue [#2897](https://github.com/go-to-k/cdkd/issues/2897))** -- `src/cli/commands/drift.ts` (`deepEqualUnordered`, consumed by `collectNarrowedTopLevelKeys` and `runAccept`'s "was NOT recorded" check), unit tests. The comparator walked own enumerable keys, so any two `Date`s compared equal (`0 === 0` keys): a narrowing at such a key was hidden and `observedProperties` stayed stale there, and the accept check's warning was suppressed. A non-plain value on either side now compares unequal unless it is the same object -- the guard `secret-redaction.ts`'s `deepEqualJsonValue` already carries -- so the provider's echo is recorded (the truthful answer). The accept warning's wording names both causes. Through the CLI a `Date` readback is flattened by the drift normalisers before either consumer sees it (issue [#2427](https://github.com/go-to-k/cdkd/issues/2427)'s class), so the narrowing pin is at the function level.
