- **An IAM user, group or instance profile delete refuses a resource that took over the recorded name, and a rollback refuses a same-named one someone else created (issue [#6655](https://github.com/go-to-k/cdkd/issues/6655))**. All three are deleted by name, so one re-created under its name outside cdkd was deleted by a destroy, template removal, replacement or rollback. The create, update and import now record the AWS-minted `UserId` / `GroupId` / `InstanceProfileId` from the response they already get, and the `GetUser` / `GetGroup` / `GetInstanceProfile` each delete already made compares it before any detach or removal: a difference still there on a re-read 5 s later refuses, non-retryable, naming the attribute (no value) and the `cdkd state orphan --resource` remedy, record kept. The group delete now makes its existing `GetGroup` first and removes the members that read listed (no extra call). No recorded id: by-name delete as before; a record without one acquires it once from an update or import. The rollback's survivor check lists the three ids beside `RoleId`. A Cloud Control-routed record of the three types is not compared: their Cloud Control model has no such id.
