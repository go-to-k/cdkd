- **An SQS queue policy, SNS topic policy or Lambda permission that cdkd just wrote no longer leaves a drift baseline that `cdkd drift --revert` would undo when the write is not yet visible (issue [#6609](https://github.com/go-to-k/cdkd/issues/6609))** -- `src/provisioning/settle-after-own-write.ts`, `src/provisioning/providers/{sqs-queue-policy,sns-topic-policy,lambda-permission}-provider.ts`, `src/cli/commands/drift/baseline-keys.ts`, unit tests. Right after `SetQueueAttributes` / `SetTopicAttributes` / `AddPermission`, the deploy recorded the first read as the `observedProperties` baseline; a read that still showed the replaced policy, or none, left `cdkd drift` reporting an untouched stack and `drift --revert` restoring the stale value. The capture after cdkd's own write now re-reads an answer that differs from the template (up to 3 more reads, 3.5 seconds at most, only when the first answer differs). If the policy is still missing after that (for a topic, still its default policy), no baseline is recorded, so drift compares against the template; another document is recorded as read, as before. Drift, import and `state refresh-observed` still take the first answer. A baseline written by an earlier cdkd is not compared on the policy while the live resource holds exactly the declared one; the next update of the resource rewrites it.
