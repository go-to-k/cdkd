- **`cdkd orphan`'s `properties` refusal no longer points a legacy region-less record at a region its remedies cannot select, and gates its drop remedy on an exact identity (issues [#3359](https://github.com/go-to-k/cdkd/issues/3359), [#3360](https://github.com/go-to-k/cdkd/issues/3360))** -- `orphan.ts`, `malformed-resources-bag.ts`, `lock-contention-message.ts`, docs, rules, tests. For a lone legacy `<prefix>/<stack>/state.json` listed with no region, `pickStackRegion` loads it under the SYNTHESIZED region, and the refusal ([#3318](https://github.com/go-to-k/cdkd/issues/3318)) printed that region into `cdkd state orphan ... --stack-region <region>` and `cdkd state show ... --json`; both select by the LISTED region, so neither found it. `pickStackRegion` now also returns the record's own region and the refusal takes it: the drop remedy is the bare `cdkd state orphan <stack>`; a record listed under a region keeps `--stack-region`. `cdkd state show` cannot read that shape, so its inspect line names the S3 object instead, on labelled `Object key:` / `State bucket:` lines, only when the name renders exactly. Drop and inspect substitute name and region only when both render exactly at the state-reference cap (a trimmed name named a healthy sibling); otherwise templates plus a pointer to `cdkd state list --json`. Both carry the run's `--profile` / `--state-bucket` / non-default `--state-prefix` via `recoveryCommandFlags`, shared with `cdkd force-unlock`'s hint (an altered value prints as a hole; that hint now also emits an explicit empty prefix). Commands print last, one per labelled line, holes QUOTED -- inside prose quotes a quoted stack name, region (released) or bucket broke out when pasted, and a bare `<stack>` is a shell redirection. Quoting the shared `inspectCommand` template also changes the `Inspect ... with:` line of the destroy, divergent-region and deploy/diff refusals and the diff warning.
