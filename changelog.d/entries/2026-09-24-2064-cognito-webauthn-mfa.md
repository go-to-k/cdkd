- **Cognito user pools: `WebAuthnFactorConfiguration` is supported, and the MFA pre-flight now covers `WEB_AUTHN` and the pool's live sign-in policy (issues [#2064](https://github.com/go-to-k/cdkd/issues/2064), [#2051](https://github.com/go-to-k/cdkd/issues/2051), [#1924](https://github.com/go-to-k/cdkd/issues/1924), [#2675](https://github.com/go-to-k/cdkd/issues/2675))** -- `src/provisioning/providers/cognito-provider.ts`, `package.json` (SDK floor `^3.1135.0`). `WebAuthnFactorConfiguration` is now sent as `WebAuthnConfiguration.FactorConfiguration` and read back; it used to be an unhandled property that routed the pool through Cloud Control. `WEB_AUTHN` as a first auth factor beside `MfaConfiguration: ON` is refused before any AWS call unless it is `MULTI_FACTOR_WITH_USER_VERIFICATION`: AWS rejects that `SetUserPoolMfaConfig` only after `UpdateUserPool` has landed the sign-in policy. When a template does not declare `Policies.SignInPolicy`, the update reads the pool's live list first (`DescribeUserPool`), because an omitted sub-key keeps the live value. So deleting the block while turning MFA ON, with `EMAIL_OTP` / `SMS_OTP` still live, is refused too. A failed read falls back to the template. A bare `EmailAuthenticationMessage` / `Subject` now warns that it enables `EMAIL_OTP` (the block has no enable switch), and the Schema-replacement advice no longer calls `DeletionProtection` unmeasured: omitting it does not reset it (measured).
