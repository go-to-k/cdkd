- **A replacement that deleted the old resource first is no longer abandoned half-way when another resource of the same deploy fails (issue [#5111](https://github.com/go-to-k/cdkd/issues/5111))** -- `src/deployment/deploy-engine/{replacement,update-replace}.ts`. `cdkd deploy --replace` (and `--recreate-via-*`) can delete a resource first and re-create it under the same name. When the re-create met the service's late release of that name (DynamoDB's `Table already exists` while the old table is still deleting), it retries -- but a failure of any other resource in the same deploy stopped that retry, leaving the stack with neither the old nor the new resource while state still recorded it. Only the user's interrupt (Ctrl+C) stops that retry now; a sibling's failure lets it finish.
