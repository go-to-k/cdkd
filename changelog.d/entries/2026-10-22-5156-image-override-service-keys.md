- **`cdkd local start-service` / `start-alb` `--image-override <service>=<dockerfile>` now matches a service by its `ServiceName` (or its construct id when it sets none), logical id or `Stack:LogicalId`, and `--strict-overrides` refuses before any service starts (issues [#5156](https://github.com/go-to-k/cdkd/issues/5156), [#5157](https://github.com/go-to-k/cdkd/issues/5157))** -- `package.json` (`cdk-local` `^0.153.1` -> `^0.153.2`), `docs/local-start-service-image-overrides.md`, `tests/integration/local-start-alb-from-state/`. Before this change, only the exact target string matched as `<service>`. Under `start-alb`, whose services are keyed `Stack:LogicalId`, a key such as `WebService=./Dockerfile` matched nothing: cdkd warned, then pulled and ran the registry image, so local edits never reached the container. The same held for the per-service `--image-build-arg <svc>:K=V`, `--image-build-secret <svc>:id=src` and `--image-target <svc>=stage` forms. Now each of those names matches. A name shared by two registry-image services, or two keys for one service, is refused with an error. `--strict-overrides` used to refuse only after the replicas had booted; it now refuses first. The bump also changes one proxy detail inside the local engine: when every proxy variable set names a scheme it cannot use (for example only `ALL_PROXY=socks5://...`), its AWS clients take the SDK's default handler and the one-time `Unsupported proxy scheme` warning is printed when the client is built. Requests still go direct, as before.
