- **`cdkd deploy` / `cdkd diff`: a resource reading an attribute that an in-place update moves now follows it (issue [#7001](https://github.com/go-to-k/cdkd/issues/7001))** -- `src/analyzer/diff-calculator/shared.ts`, `scripts/gen-in-place-attr-coverage.ts`, `scripts/in-place-attr-classification.ts`. A reader of an attribute that is not a template property (`Fn::GetAtt` / `Fn::Sub`) stayed `NO_CHANGE` and kept the old value after its upstream's in-place update, unless the attribute had a row in the in-place tables. Every read-only attribute of an SDK-provider type is now classified by hand, and the moving ones have rows. Among them: an IAM user's or group's `Arn` after a `Path` change, a CodeCommit repository's `Arn` / `Name` / clone URLs after a rename, a state machine's `StateMachineRevisionId` (a `StateMachineVersion`), a managed policy's `DefaultVersionId`, a WAF web ACL's `Capacity`, a Lambda function's `SnapStartResponse`, an RDS cluster or instance `Endpoint.Port`, an instance's `CertificateDetails` / `SecondaryAvailabilityZone`, a CloudTrail `SnsTopicArn`, a pipe's `CurrentState`. The export-change guard reads the same rows, so a cross-stack export of one now counts as changed. A new `audit:in-place-attr-coverage:check` CI step fails on an unclassified attribute. Cloud-Control-only types are classified by rule, and a committed baseline holds the pairs no rule settles. Tests: `tests/unit/analyzer/diff-calculator-in-place-attr-7001.test.ts`, `tests/unit/scripts/in-place-attr-coverage.test.ts`.
