- **An AWS error that quotes a name assembled around a short secret no longer prints the secret, and two `Fn::GetAtt` arms now refuse a masked persisted value** (issues [#3171](https://github.com/go-to-k/cdkd/issues/3171), [#2936](https://github.com/go-to-k/cdkd/issues/2936)) -- `src/deployment/intrinsic-function-resolver.ts`. When an `Fn::Sub` built a dynamic-reference name or an `Fn::GetAZs` region around a secret shorter than four characters, cdkd printed the name masked in its own words, but the AWS SDK's text quoted the name back in the clear: the rethrown `ParameterNotFound` / `AccessDenied` / staging-label miss from a `{{resolve:ssm:...}}` or `{{resolve:secretsmanager:...}}` lookup, the `--verbose` retry line of a throttled lookup, and the `Fn::GetAZs` describe-failure message. Each now masks the whole name the request carried, through one helper (`namedRequestMasks`) that returns the masked error clone (class, cause chain and retry classification kept), the masked message and the masking retry logger together. Separately, `Fn::GetAtt [<VPC>, CidrBlock]` and `Fn::GetAtt [<Events rule>, Arn]` read a value out of the persisted record without recording a masked read, so a `***` stored there would have been sent to AWS; both now record it, and the deploy refuses the consumer as it does for every other masked attribute. Tests: `tests/unit/deployment/intrinsic-resolver-name-argument-log-twin.test.ts`, `tests/unit/deployment/intrinsic-getatt-noecho-note.test.ts`.
