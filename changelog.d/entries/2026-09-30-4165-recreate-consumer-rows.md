- **The `--recreate-via-cc-api` / `--recreate-via-sdk-provider` confirmation no longer prints a non-plain downstream-consumer value or recorded resource type raw (issue [#4165](https://github.com/go-to-k/cdkd/issues/4165))** -- `src/cli/commands/recreate-downstream-consumers.ts` (`renderDownstreamConsumers`), `src/cli/commands/recreate-confirm-prompt.ts` and `src/deployment/recreate-targets.ts` (the target and refusal rows), with paste cases in `tests/unit/cli/commands/recreate-downstream-consumers-paste.test.ts` and `recreate-resource-type-paste.test.ts`. Each consumer row printed the consumer stack name, its region and the export or output name it reads as they were recorded. The name and region come from the consumer's state key and the export name from its `state.json`, so whoever can write the state bucket chose them. A value could carry a span that ran when the row was pasted into a shell, or a newline that forged an extra consumer row inside the data-loss prompt. A plain value prints exactly as before, a CDK-generated export name carrying `:` included. Any other value is described (`a stack name that is not a plain identifier`, `a region that is not a plain identifier`, `an export whose name is not a plain identifier`, `an output whose name is not a plain identifier`). That includes a redacted `{{resolve:...}}` or `***` name on a row whose producer cdkd cannot name. The target row of the same prompt, and each `--recreate-via-*` refusal row an arbitrary recorded type can reach, printed the STATE record's resource type raw; a non-plain one is now `a resource type that is not a plain identifier`. No refusal `Fix:` line carries a `<...>` hole any more: the old `remove … <id> for these resources`, pasted, redirected into a file named `for`.
