- **`cdkd destroy --remove-protection` no longer fails on a protected RDS / DocDB / Neptune DB cluster or a standalone RDS DB instance that takes a final snapshot (issue [#5155](https://github.com/go-to-k/cdkd/issues/5155))** -- `src/provisioning/providers/rds-provider.ts`, `docdb-provider.ts`, `neptune-provider.ts`, `tests/unit/provisioning/remove-protection-final-snapshot-wait-5155.test.ts`. Before this change, cdkd turned `DeletionProtection` off and sent the delete at once. When the delete took a final snapshot (`DeletionPolicy: Snapshot`, or no `DeletionPolicy`), AWS could refuse it because the resource was still `modifying` from that change ("Can't create a snapshot because the database cluster ... isn't currently in the available state"). The destroy then ended partial and the guard was put back. cdkd now waits until the resource reads protection off and `available` before such a delete. The wait runs only when this destroy turned the guard off and a final snapshot is requested, so no other delete takes longer. If the resource is not `available` within 15 minutes, the delete is not sent, the guard is put back, and the error says to re-run the destroy once it is.
