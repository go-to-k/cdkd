- **`Ref` to a Cloud Control-routed Auto Scaling policy, lifecycle hook or scheduled action, SES receipt rule, Cloud Map instance, GuardDuty filter / IPSet / threat intel set / master / member, Elastic Beanstalk configuration template or application version, EMR instance fleet / group, Glue connection or transit gateway route table propagation now returns CloudFormation's value instead of cdkd's whole `|`-joined physical id (issue [#6612](https://github.com/go-to-k/cdkd/issues/6612))** -- `src/deployment/intrinsic-resolver/ref-values.ts`, `src/deployment/intrinsic-resolver/ref-values/type-refs.ts`, `scripts/gen-ref-segment-coverage.ts` (new), `tests/fixtures/cfn-primary-identifiers.json` (new), `docs/_generated/ref-segment-coverage.{json,md}` (new), unit tests. For example `AlarmActions: [{ Ref: <ScalingPolicy> }]` received `<policyArn>|<dimension>` rather than the policy ARN. A new CI check lists every type whose physical id is several fields joined with `|` and fails when one has no recorded `Ref` decision, with its source (a segment mapping, the docs' or a measured value). A property that received the old joined value shows an in-place update on the next deploy, which then sends the corrected value (no replacement: the usual consumers, such as an alarm's `AlarmActions`, a receipt rule's `After`, an Elastic Beanstalk environment's `TemplateName` / `VersionLabel` and a Glue job's `Connections`, are mutable).
