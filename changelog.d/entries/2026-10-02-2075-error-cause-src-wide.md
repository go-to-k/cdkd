- **The error-cause critic now scans all of `src/`, and four more wrappers keep the AWS / docker error they caught (issue [#2075](https://github.com/go-to-k/cdkd/issues/2075))** -- `scripts/check-provider-error-cause.ts`, `src/utils/error-handler.ts`, `src/assets/docker-asset-publisher.ts`, `src/local/ecr-puller.ts`, `src/local/ecs-task-runner.ts`. The retry classifiers find a throttle or a 5xx by walking an error's `.cause`, so a wrapper that drops the caught error is classified on its message alone. The critic used to check only `src/provisioning/providers`; it now defaults to `src/`. A cause DERIVED on purpose (`redactedDockerCause`, `normalizeAwsError`, `maskSecretsInError`) is accepted only when imported from its own module, and a runtime test proves each one keeps the classifier verdict. The three deliberate omissions (two local file reads, one re-branded cdk-local error) are listed by name with an exact count. Fixed along the way: `normalizeAwsError` now chains the original SDK error under the message it rewrites, so an S3 `Unknown` HTTP 503 on the state bucket reads as transient and keeps its request id; and the `cdkd local` ECR pull / login / AssumeRole and ECS re-tag failures now carry their cause. Tests: `tests/unit/scripts/provider-error-cause.test.ts`, `tests/unit/scripts/cause-composers-classify.test.ts`.
