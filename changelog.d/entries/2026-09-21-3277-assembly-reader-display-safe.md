- **A hand-modified Cloud Assembly can no longer forge terminal lines inside the messages cdkd prints while refusing it (issue [#3277](https://github.com/go-to-k/cdkd/issues/3277))** -- `src/synthesis/assembly-reader.ts` and `src/synthesis/stack-messages.ts`. Every value those two rendered was chosen by whoever wrote the assembly -- a manifest key, a `stackName` property, a template key, a `Metadata['aws:asset:path']` string, a `directoryName` joined into a path, and the `readFileSync` / `JSON.parse` failure text quoting a hand-fed file -- and all of them were interpolated raw. C1 bytes, `U+0085`, the Unicode line terminators and the Trojan-Source bidi overrides pass through ordinary string building, and `formatError` sanitizes only an error's `cause`, never its `message`, so a crafted value appended what read as a second, cdkd-authored line. Synthesis is the FIRST layer the CLI reaches, so the absolute-`aws:asset:path` refusal -- whose own text says the input was hand-modified -- was the message a user was asked to trust. All ten render sites in `assembly-reader.ts` (thrown refusals and `debug` / `warn` lines alike) and the side-file refusal in `stack-messages.ts` now go through `displaySafe`. `displaySafe` and not `displayIdent`: it neither truncates nor quotes, so a legitimate long asset path still renders in full and byte-identically, and no well-formed assembly changes behaviour at all. `processStackMessages`' CDK-annotation display is still raw and is recorded as an OPEN residual on go-to-k/cdkd#3479: an annotation legitimately carries newlines, which `displaySafe` maps to spaces, so it needs a helper that does not exist yet. This is the third copy of the class go-to-k/cdkd#3243 closed in `src/cli/commands/diff-recursive.ts`. Tests: `tests/unit/synthesis/assembly-reader-display-safe.test.ts` (a distinct hostile marker per interpolated value, plus the ordinary-path polarity) and two cases in `tests/unit/synthesis/stack-messages.test.ts`.
