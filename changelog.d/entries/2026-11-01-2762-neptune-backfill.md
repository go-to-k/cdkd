- **`AWS::Neptune::DBCluster` and `AWS::Neptune::DBInstance` stay on their SDK provider for more properties (go-to-k/cdkd#2762)** -- `src/provisioning/providers/neptune-provider.ts`. A cluster that declares `AssociatedRoles`, `AvailabilityZones`, `CopyTagsToSnapshot`, `DBInstanceParameterGroupName`, `EnableCloudwatchLogsExports`, `NetworkType` or `ServerlessScalingConfiguration`, or an instance that declares `AllowMajorVersionUpgrade` or `PubliclyAccessible`, used to be routed through Cloud Control. The provider now sends each one on create and update and reads it back for `cdkd drift`. Role changes are planned against the cluster's live list, and a cluster whose roles change waits for `available` even under `--no-wait`, because attaching a role needs it. A major `EngineVersion` change now sends `AllowMajorVersionUpgrade`, with `DBInstanceParameterGroupName` when declared. A removed `PubliclyAccessible: true` leaves the instance public, as CloudFormation does, and cdkd says so in a warning. Malformed `AssociatedRoles` or `EnableCloudwatchLogsExports` is refused before any call, except on a replayed create, which leaves it out with a warning. `GlobalClusterIdentifier` and the cluster restore properties stay on Cloud Control. A resource already recorded as provisioned by Cloud Control follows the usual sticky routing.
