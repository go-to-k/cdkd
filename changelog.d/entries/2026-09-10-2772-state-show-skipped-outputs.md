- **`cdkd state show` now renders the `skippedOutputs` record, the field that explains a missing `cdkd diff` row (issue [#2772](https://github.com/go-to-k/cdkd/issues/2772))** -- `src/cli/commands/state.ts`, `docs/cli-state.md`, and new cases in the `state show` / `state resources` suites. Issue [#2740](https://github.com/go-to-k/cdkd/issues/2740) added `StackState.skippedOutputs` -- the Outputs keys the last deploy could not resolve, each mapped to a digest of its template inputs -- and `cdkd diff` uses it to preview such a key as ABSENT with no row and no warning, while the record binds and the key is still absent from the stored outputs. That silence is deliberate, and it left the text view with no explanation for a vanished Output. The field was readable through `--json` and in the stored record, and nowhere else. A `Skipped outputs:` block now renders when the map has entries, after `Outputs:` where that section exists at all, one line per key sorted by name, each carrying its digest's first 12 characters and a trailing `…` when the value was cut (the `(unserializable)` sentinel is shown whole), then an explanation at column zero, printed ONCE per render, not per child under `--show-nested`. It is omitted when the field is empty and when it is absent; absence means only that nothing was RECORDED. Exact comparison stays with `--json`, unchanged; the render site says why it truncates. PRE-EXISTING rows changed too, across `state show` and both `state resources` modes: every string either command renders from a state record is now stripped -- name, type, id, dependency list, header -- so none can forge a row in output joined by newlines. The lock row already was, upstream. And a VALUE whose declared type the record got wrong now prints -- as itself, as JSON or as `(unserializable)` -- where it used to empty the whole render. `docs/cli-state.md` carries the per-command detail and go-to-k/cdkd#2947 the shapes still out of reach.
