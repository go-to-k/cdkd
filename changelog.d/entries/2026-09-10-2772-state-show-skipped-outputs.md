- **`cdkd state show` now renders the `skippedOutputs` record, the field that explains a missing `cdkd diff` row (issue [#2772](https://github.com/go-to-k/cdkd/issues/2772))** -- `src/cli/commands/state.ts` (`renderStateBlock`), `docs/cli-state.md`, and new cases in the `state show` suite. Issue [#2740](https://github.com/go-to-k/cdkd/issues/2740) added `StackState.skippedOutputs` -- the Outputs keys the last deploy could not resolve, each mapped to a digest of that output's template inputs -- and `cdkd diff` uses it to preview such a key as ABSENT with **no row and no warning**, while the record binds and the key is still absent from the stored outputs. That silence is deliberate, which left the text view with no explanation for a vanished Output: the field was reachable only through `--json` or the raw `state.json`. A `Skipped outputs:` block now renders when the map has entries, after `Outputs:` where that section exists at all (it is omitted on an empty bag), one line per key sorted by name, each with the first 12 characters of its digest, then an explanation at column zero naming the block it explains, printed ONCE per render rather than per child under `--show-nested`. The key is stripped; the digest goes through the same formatter the Outputs, attribute and property values do, which strips AND tolerates a non-string. A hand-edited number or `null` would otherwise throw and empty the whole render, stack header and resources included. Stripping runs BEFORE truncation, which buys printable characters rather than safety: slicing first strips too, it just spends a slot. A trailing `…` marks a value that was actually cut. A prefix DIFFERENCE is what a reader wants; a match proves nothing, so exact comparison belongs to `--json`, which carries it whole and is unchanged. The block is omitted when the field is empty and when it is absent -- absence meaning only that nothing was RECORDED, since pre-#2740 records carried none and several writers drop it.
