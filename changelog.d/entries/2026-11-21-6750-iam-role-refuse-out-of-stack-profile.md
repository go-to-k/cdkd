- **`cdkd destroy` refuses an IAM role that an instance profile outside the stack still holds, instead of removing the role from that profile (issue [#6750](https://github.com/go-to-k/cdkd/issues/6750), role half)** -- `src/provisioning/providers/iam-role/delete.ts`, `docs/cli-destroy-guards.md`, and `tests/unit/provisioning/iam-role-refuse-out-of-stack-profile-6750.test.ts`. A destroy removed the role from every instance profile that listed it before `DeleteRole`. CloudFormation's delete handler holds no `iam:RemoveRoleFromInstanceProfile`, so there `DeleteRole` fails with `DeleteConflict`, and the stack's own instance profiles are deleted before their role, so the removal only reached a profile the stack did not create (for example one another stack built around the role's name), which was left without its role. On a stack destroy the role is now deleted as is. When `DeleteRole` answers `DeleteConflict`, cdkd lists the role's instance profiles every two seconds until the list has not changed for ten seconds (at most a minute). A role no profile holds by then is deleted again; otherwise the delete fails without a retry, naming the profiles that `GetInstanceProfile` confirms still hold the role (at most five), and the next step. A deploy's delete still removes the role from its profiles, since a same-name re-create relies on that (#4461).
