- **Replacing an ALB listener that has rules now replaces each `AWS::ElasticLoadBalancingV2::ListenerRule` onto the new listener, instead of failing the deploy with `NotFound`** (`src/analyzer/replacement-rules.ts`, go-to-k/cdkd#4689). A `--recreate-via-cc-api` / `--recreate-via-sdk-provider` of the listener, or a change that replaces it (its `LoadBalancerArn`, or a replaced load balancer), planned each rule reading it as an in-place update: the rule's `ListenerArn` is create-only, but the CloudFormation schema also lists it write-only, and cdkd does not replace on a write-only create-only property it cannot read back (go-to-k/cdkd#3803). AWS deletes a listener's rules with it, so that update failed `One or more rules not found` after the listener had already been replaced, and the `--recreate-via-*` pre-flight did not list the rule. The replacement rules now name `ListenerArn` for this type, so the rule is re-created on the new listener, and the pre-flight lists it under "Replaced if the id changes". Tests: `tests/unit/analyzer/diff-calculator-synthetic-create-only.test.ts`, `tests/unit/deployment/recreate-target-readers.test.ts`; integ `alb` Phase 5 (a `--recreate-via-cc-api` of the listener with its rule).
