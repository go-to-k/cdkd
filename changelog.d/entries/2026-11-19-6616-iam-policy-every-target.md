- **`cdkd drift` now reports an out-of-band edit of an `AWS::IAM::Policy` attached to several roles / groups / users, whichever principal's copy was edited (issue [#6616](https://github.com/go-to-k/cdkd/issues/6616))** -- `src/provisioning/providers/iam-policy/read-state.ts`, `src/provisioning/providers/iam-policy-provider.ts`, `src/deployment/read-current-state-context.ts`, `src/types/resource/read-state.ts`, unit tests, integ `iam-role-policies-drift-clean`. `PutRolePolicy` / `PutGroupPolicy` / `PutUserPolicy` write one copy of the document per principal, and the drift read fetched only the FIRST principal's copy: a document widened on any other principal (an `Action` set to `*`) read clean, and `cdkd drift --revert` left it in place. The read now fetches every recorded principal's copy (five at a time) and reports one that differs from the drift baseline (the recorded document when no baseline is recorded), so `--revert` writes the recorded document back to every principal; when the copies differ and the baseline holds a secret reference or mask that no copy can equal, the policy reads as drift unknown rather than clean. A principal whose copy is gone (removed, or the principal deleted) now drops out of the reported `Roles` / `Groups` / `Users` instead of the whole policy reading as deleted; every copy gone still reads as deleted. Each extra principal costs one `Get*Policy` call on a drift read; the deploy's own post-write baseline capture still reads the first principal only, so a deploy makes no extra call, and a single-principal policy makes exactly the one call it made before.
