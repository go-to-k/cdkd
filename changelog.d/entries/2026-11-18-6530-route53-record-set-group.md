- **`AWS::Route53::RecordSetGroup` is now supported (issue [#6530](https://github.com/go-to-k/cdkd/issues/6530))** -- new `src/provisioning/providers/route53/record-set-group.ts`, wired into `Route53Provider` (`route53/core.ts`, `route53/read-state.ts`, `route53/import.ts`), plus a replacement rule in `src/analyzer/replacement-rules/rules.ts`, a `Ref` entry in `src/deployment/intrinsic-resolver/ref-values.ts`, a hand-written schema fixture, unit tests and a `route53` integ fixture arm. The type has no CloudFormation registry schema and no Cloud Control handlers, so cdkd used to refuse it before deploying. Each create, update and delete is now one `ChangeResourceRecordSets` batch, applied all or nothing: an update deletes the records the template dropped (carrying their live values), creates the added ones and upserts the changed ones. Moving the group to another hosted zone replaces it. `cdkd drift` reads every record back, and `cdkd import` adopts a group through `--resource` only. The physical id is `<hostedZoneId>|<groupName>`, and `Ref` returns the group name, `<StackName>-<LogicalId>-<suffix>` as in CloudFormation (#6540).
