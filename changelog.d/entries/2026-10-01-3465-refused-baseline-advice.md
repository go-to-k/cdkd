- **`cdkd state show`, `cdkd state refresh-observed` and `cdkd drift` name the remedy a refused import baseline really has (issue [#3465](https://github.com/go-to-k/cdkd/issues/3465))** -- `src/cli/commands/refused-baseline-remedy.ts`, `src/cli/commands/{state,drift}.ts`, `docs/_contents/cli-state.md`, `docs/_contents/cli-drift.md`. Every message about a resource whose observed baseline a `cdkd import` refused told the user to deploy a change to it. That is false for an `unverifiable-parameter` refusal, which an in-place update keeps: only a replacement or a re-import against a CloudFormation stack that proves the parameter clears it. For a refusal an older cdkd recorded without a reason it holds only when the resource reads no template parameter, which these template-less commands cannot tell. The `state show` row, the `drift` report row, the `--accept` / `--revert` refusals and their plans now read the record's reason and name the right remedy, keeping the deploy advice for the class a deploy does clear; the `refresh-observed` warning counts the refusals a deploy may not clear and points at `state show`. The pre-v10 drift warning now says a deploy does not repair a resource that reads a template parameter. `cdkd export`'s refused-baseline list is not changed here. Tests: `tests/unit/cli/{state-show,state-refresh-observed,drift,drift-plan-sanitize}.test.ts`.
