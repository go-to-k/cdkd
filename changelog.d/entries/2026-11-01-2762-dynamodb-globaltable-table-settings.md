- **`AWS::DynamoDB::GlobalTable` keeps the SDK route for `VectorIndexes`, `WarmThroughput`, `ReadOnDemandThroughputSettings`, `ReadProvisionedThroughputSettings` and `TableType` (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762)).** A table declaring one of them used to go through Cloud Control. Vector indexes and warm throughput are now sent on `CreateTable` and changed through `UpdateTable`, and a replica inherits the indexes. The two table-level read blocks set the table's read ceiling and capacity, and are refused, as CloudFormation refuses them, without `GlobalTableSettingsReplicationMode: ENABLED` on a replica or beside the same block on a replica; `ReadOnDemandThroughputSettings` is also refused on a PROVISIONED table. Removing the table-level `ReadProvisionedThroughputSettings` from a table that stays PROVISIONED, with no replica declaring its own, is refused too. `TableType` has no API member, so nothing is sent for it, and `Regional` is refused on more than one replica. A same-name vector index whose definition changed is refused before any call: rename it so it is dropped and re-created. An unreadable `VectorIndexes` is refused rather than read as none. A destroy and a failed create's cleanup wait out a building vector index. `MultiRegionConsistency`, `GlobalTableWitnesses` and `GlobalTableSourceArn` stay on Cloud Control. Source: `src/provisioning/providers/dynamodb-globaltable-provider.ts`.
