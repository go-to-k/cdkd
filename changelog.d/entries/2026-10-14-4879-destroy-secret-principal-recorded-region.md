- **`cdkd destroy` resolves a region-less secret reference in an IAM principal list in the region its state record names (issue [#4879](https://github.com/go-to-k/cdkd/issues/4879))** -- `src/provisioning/secret-principal-resolution.ts`, `src/cli/commands/destroy-runner.ts`, `src/provisioning/providers/iam-policy-provider.ts`, `iam-user-group-provider.ts`. An `AWS::IAM::Policy` or `AWS::IAM::UserToGroupAddition` whose `Roles` / `Groups` / `Users` names a principal through a `{{resolve:...}}` reference with no region was skipped (record kept, exit 2) when the stack also reads a value from another region, because the reference could have been resolved there. A state schema v12 record says which region resolved it, so `cdkd destroy` and `cdkd state destroy` now resolve it in that region, as the rollback replay, `cdkd drift` and `cdkd scrub` already do, and remove the policy or memberships. A record without that field keeps the skip. The destroy makes no new AWS call to find the region. A nested stack destroyed on its own still skips such a record.
