- **A file asset larger than 5 MiB is uploaded as an S3 multipart upload, as the AWS CDK CLI does (issue [#6162](https://github.com/go-to-k/cdkd/issues/6162))** -- `src/assets/file-asset-publisher.ts`, the new `@aws-sdk/lib-storage` runtime dependency, unit tests. Before, cdkd sent every file asset as ONE `PutObject`. AWS Emulator refuses a request body of 16 MiB or more, so a deploy with `s3deploy.BucketDeployment` (its 22 MB `AwsCliLayer` asset) failed at asset publishing with `write EPIPE` / `read ECONNRESET` while `cdk deploy` published it. An asset of more than 5 MiB, a file or a packaged zip, now goes up in 5 MiB parts, four at a time (lib-storage's `Upload`, the call cdk-assets makes); a failed part aborts the multipart upload. Assets of 5 MiB or less keep the single streamed `PutObject`.
