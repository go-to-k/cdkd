- **A file asset larger than 5 MiB is uploaded as an S3 multipart upload, as the AWS CDK CLI does (issue [#6162](https://github.com/go-to-k/cdkd/issues/6162))** -- `src/assets/file-asset-publisher.ts`, the new `@aws-sdk/lib-storage` runtime dependency, unit tests. Before, cdkd sent every file asset as ONE `PutObject`. AWS Emulator refuses a request body of 16 MiB or more, so a deploy with `s3deploy.BucketDeployment` (its 22 MB `AwsCliLayer` asset) failed at asset publishing with `write EPIPE` / `read ECONNRESET` while `cdk deploy` published it. An asset of more than 5 MiB, a file or a packaged zip, now goes up in 5 MiB parts, four at a time (lib-storage's `Upload`, the call cdk-assets makes); a failed upload aborts the multipart upload, and so does `deploy`'s second Ctrl-C (force-quit, now aborting in-flight uploads before it exits; the first Ctrl-C lets them finish, and an aborted upload is reported as `Interrupted:`, not as a failure) (cdkd sends the abort itself, so a refused `AbortMultipartUpload` never hides the part's own error). Assets of 5 MiB or less keep the single streamed `PutObject`. On real AWS, an asset bucket encrypted with a customer-managed KMS key now also needs `kms:Decrypt` on that key for the caller (S3 requires it for a multipart upload), in addition to `kms:GenerateDataKey`, as cdk-assets does; the CDK bootstrap roles already grant it.
