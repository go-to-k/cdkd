- **`Ref` of an `AWS::EC2::ClientVpnTargetNetworkAssociation` or `AWS::GuardDuty::PublishingDestination` now returns the association / destination id, as CloudFormation does, instead of cdkd's `|`-joined id (issue [#6628](https://github.com/go-to-k/cdkd/issues/6628))** -- `src/deployment/intrinsic-resolver/ref-values.ts`, `scripts/gen-ref-segment-coverage.ts` and its generated `docs/_generated/ref-segment-coverage.{json,md}`, a new unit file. 88 of the 119 compound-identifier types whose `Ref` was unverified were measured on live CloudFormation stacks: 85 return the joined id, which cdkd already returned; these two return the trailing segment; `AWS::EC2::NetworkAclEntry` returns a generated id no segment holds. The 31 left (an Outpost, Identity Center, Organizations, QuickSight, Security Lake, AppRegistry, or a probe the service refused) keep resolving to the joined id, each with the reason recorded.
