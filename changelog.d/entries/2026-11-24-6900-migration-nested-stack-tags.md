- **`cdkd import --migrate-from-cloudformation` records each nested stack's stack tags, so the first deploy after migrating a tagged nested stack no longer re-runs it (issue [#6900](https://github.com/go-to-k/cdkd/issues/6900))** -- `src/cli/commands/import/deployed-properties.ts`, `src/cli/commands/import/locked-import.ts`, `src/cli/commands/import/nested.ts`, `tests/integration/import-nested-stack/`. A migration wrote no `nestedStackTags`, so the next `cdkd diff` / `cdkd deploy` showed every tagged nested stack row as an update and ran its child for tags its resources already held. The parent's record (and each nested stack's, for its own nested stacks) now holds the tags each child was migrated with, and a field carried from an earlier record is replaced.
