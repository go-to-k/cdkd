- **An update of an SQS queue, an S3 bucket policy, an EventBridge event bus or rule, or a Step Functions state machine is refused when the AWS client's region differs from the region recorded in cdkd state (issue [#2613](https://github.com/go-to-k/cdkd/issues/2613))** -- `src/provisioning/providers/{sqs-queue,s3-bucket-policy,eventbridge-bus,eventbridge-rule,stepfunctions}-provider.ts` (`update()` now takes the `UpdateContext` and calls `assertRegionMatch` before any AWS call), `scripts/check-provider-update-context.ts` (five names leave `OMITS_UPDATE_CONTEXT`), and unit cases in each provider's test file. These providers ignored the recorded region on update, so a deploy, rollback or `cdkd drift --revert` run with a client in another region sent its writes there -- for an event bus or rule, to whatever carried the same name in that region, a resource cdkd does not manage (an EventBridge `PutRule` creates the rule when none exists). An SQS queue update instead failed at AWS with a request-signing error naming neither region, because the SDK sends the call to the queue URL's host but signs it for the client's region. The update now stops before the first call and names both regions. An update whose state record has no region is unchanged.
