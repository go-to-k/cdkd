- **`cdkd state show` / `cdkd state resources` refusals can no longer forge a row with the record that caused them (issue [#3003](https://github.com/go-to-k/cdkd/issues/3003))** -- `src/state/s3-state-backend.ts`, `src/state/lock-manager.ts`, `src/cli/commands/state.ts`, `src/cli/commands/export.ts`, `docs/cli-state.md`, cases in four suites. Issue [#2772](https://github.com/go-to-k/cdkd/issues/2772) made every value those views RENDER control-safe, because their rows are joined by newlines and a state record is an unchecked cast anyone with `s3:PutObject` on the state bucket can write. The ERROR paths were not covered, and a refusal is the path a malformed record is MOST likely to take -- so the diagnostic a reader trusts most could invent a row the rendered output no longer can. Five sites now sanitize: `parseStateBody`'s invalid-JSON arm and its unsupported-version refusal, `getLockRecord`'s catch, `resolveSingleRegion`'s three messages, and the nested-stack walker's missing-child and region-mismatch errors. Each takes the class its own file already used here -- `displaySafe(..., { asciiOnly: true })` with the `UNRENDERABLE` stand-in -- so a value stripping to nothing is named rather than leaving an empty slot, and a stack name or region is flattened rather than dropped. Two of the five carry record text through a JSON parser: V8 quotes the offending INPUT in its `SyntaxError`, so an unreadable `state.json` or `lock.json` put bucket bytes on the terminal. `probeLegacyState` had sanitized its own copy since issue [#1926](https://github.com/go-to-k/cdkd/issues/1926); these were the siblings that had not. NOT closed here: a value that throws on STRING COERCION still throws (`displaySafe` coerces with an unguarded `String`), which is issue [#2947](https://github.com/go-to-k/cdkd/issues/2947)'s call, and the `(legacy)` region placeholder stays outside the guard as the command's own literal.
