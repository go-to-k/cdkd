- **A resource named from a `NoEcho` parameter keeps its ARN in state, so its readers redeploy ([#4849](https://github.com/go-to-k/cdkd/issues/4849))** -- `src/deployment/secret-redaction/redact-state.ts`, `src/deployment/deploy-engine/masking.ts`, `src/provisioning/providers/nested-stack-provider.ts`. When a resource's name came from a `NoEcho` template parameter (an SNS topic with `TopicName: !Ref Name`), `state.json` stored its own ARN attribute (`TopicArn`) as `***`, and so did every stack output and export holding that ARN. The next deploy that re-resolved a reader (editing a subscription or a grant using `Fn::GetAtt Topic.TopicArn`) failed with `Cannot resolve Topic.TopicArn ... redaction mask` and rolled back. A consumer stack importing the exported ARN in a later run was refused the same way. AWS publishes a resource's name inside its ARN, and cdkd already keeps the physical id itself as AWS returns it; the ARN attribute, the outputs, the exports and a nested stack's outputs holding a child's id are now kept the same way. An attribute or output that equals the `NoEcho` value itself (`TopicName`) still stays `***`, unless the resource's physical id is that value (then it is stored as the physical id is). A record an earlier cdkd wrote with `***` there is repaired by the next deploy that reads the attribute: cdkd re-reads the resource and replaces the mask only with a value that is the physical id, or an ARN that ends in it with nothing but the ARN's partition, service, region, account and resource type before it (a function's or role's ARN).
