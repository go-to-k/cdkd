- **Destroying an EFS file system that is a replication source deletes its replication configuration first instead of failing (issue [#6751](https://github.com/go-to-k/cdkd/issues/6751))** -- `src/provisioning/providers/efs/file-system.ts`. `DeleteFileSystem` refuses a replication source with `FileSystemInUse` until its replication configuration is deleted and torn down, which CloudFormation's handler does first. cdkd used to send only `DeleteFileSystem`, so a destroy failed where the AWS CDK CLI succeeds. On that refusal cdkd now deletes the configuration the file system is the source of, waits for the teardown, and deletes the file system. A file system that is only a replication destination still gets AWS's refusal.
