- **A nested child resource whose `Fn::Split` delimiter occurs inside a secret `{{resolve:...}}` reference's text, such as `:`, is no longer updated on every redeploy of the child (issue [#4914](https://github.com/go-to-k/cdkd/issues/4914)).** A child splitting a parameter the parent built as `postgres://{{resolve:...}}:{{resolve:...}}@host` on `:` took an UPDATE each time the child deployed (a REPLACEMENT on a create-only property), and `cdkd diff` reported a change on every run for a stack splitting a literal, `Fn::Join` or `Fn::Sub` holding such references. The comparison side cut each reference into fragments (`//{{resolve`) that no deploy persists. It now keeps a reference whole where it splits whenever the real deploy replaces it with its secret before splitting (one in the split's own literal, `Fn::Join` or `Fn::Sub`, or one a nested child's parent resolved), which matches what the deploy persists unless the secret value itself holds the delimiter. Reference text that reaches the split as plain text (a `Ref` to a parameter, an `Fn::FindInMap` value) is still split as text, as the deploy does. `cdkd diff --recursive` still reports the nested-child case ([#4929](https://github.com/go-to-k/cdkd/issues/4929)). After upgrading, a nested child in which one resource reads such a split beside a sibling parameter spelling the same secret differently may show a one-time change (a replacement on a create-only property) on the resources reading the split parameter: their state now records that parameter's own spelling instead of the sibling's. The deployed value is unchanged. No AWS call is added. Source: `src/deployment/intrinsic-resolver/string-functions.ts`, `src/deployment/secret-redaction/nested-stack.ts`.
