- **A `SecurityGroupIngress` duplicate is no longer adopted on the strength of a journal entry a rollback, a later deploy or a partial destroy already undid (issue [#4402](https://github.com/go-to-k/cdkd/issues/4402))** -- `src/deployment/prior-attempt-scope.ts`, `src/state/s3-state-backend.ts`, `src/types/rollback-journal.ts`, `src/deployment/deploy-engine/rollback.ts`. Since #4355, a create that AWS rejects as a duplicate adopts the existing rule when the stack's rollback journal shows the same logical id attempted it. The journal's COMPLETED operations counted too, but a segment can keep them after they were undone: an automatic rollback whose segment cleanup failed, a `cdkd rollback` that failed on another operation, an unsettled nested-stack segment, or a `cdkd destroy` that failed partway. If someone then added the identical rule, the next deploy adopted it and `cdkd destroy` revoked it. Now only a FAILED attempt that no later completed operation of the logical id superseded is evidence: a completed operation's resource was recorded in state, so a later create of that id means it was reverted, destroyed or replaced. Removing a segment (or a successful deploy failing to delete the journal) now leaves its operations' logical ids on the next older segment (`supersededLogicalIds`, an additive journal field), so a reverted adoption no longer lets the attempt it adopted count again.
