- **A Step Functions state machine with an inline definition now gets its `DefinitionSubstitutions` applied (issue [#5298](https://github.com/go-to-k/cdkd/issues/5298))** -- `src/provisioning/providers/stepfunctions-provider.ts`. cdkd applied `DefinitionSubstitutions` only to a `DefinitionS3Location` body and sent an inline `DefinitionString` / `Definition` as written. aws-cdk-lib's `StateMachine` emits a chain or string body as `DefinitionString` with the map in a separate `DefinitionSubstitutions` property, and CloudFormation substitutes into the inline forms too, so a CDK app using `definitionSubstitutions` deployed a state machine holding literal `${name}` placeholders while the deploy reported success. The map is now applied to every definition form, on create and on update, in one pass (an inserted value is not re-scanned). A state machine deployed before this fix keeps its literal placeholders until its next update: an unchanged template produces no diff, and `cdkd drift` compares against the same unsubstituted definition, so change the definition or a substitution value once to have it rewritten. `cdkd drift` on a record with no observed baseline folds the template's inline definition and substitutions into the substituted `Definition` the read-back reports, so the substitution does not read as drift. A secret placed in `DefinitionSubstitutions` stays masked at every `Definition` leaf it lands in, whatever its length (issue [#5332](https://github.com/go-to-k/cdkd/issues/5332)). Unit cases in `tests/unit/provisioning/stepfunctions-provider-definition-substitutions-5298.test.ts` (six fail without the fix); the `stepfunctions-s3-definition` integ fixture gains a machine with the string `DefinitionString` + `DefinitionSubstitutions` pair an L2 chain body synthesizes and one with an inline object `Definition`, plus a redeploy that changes only the substitution values.
