- **A nested-stack row whose logical id collides with `Object.prototype` is followed instead of dropped or silently mis-answered (issue [#3480](https://github.com/go-to-k/cdkd/issues/3480))** -- `src/synthesis/assembly-reader.ts`, `src/cli/commands/{diff-recursive,export,import,diff,deploy}.ts`; two suites. Every nested-template index maps a template logical id to the child template's path, and four of the five builders assigned onto a `{}` literal. `JSON.parse` yields `__proto__` as an ordinary own data property, so a row spelled that way ran `Object.prototype`'s setter: the assignment DROPPED the key, the lookup then answered `Object.prototype`, and `cdkd deploy` / `diff` / `export` / `import` refused, naming `[object Object]` rather than following the row. All four now build onto `nullPrototypeRecord()`, joining `NestedStackProvider.indexGrandchildTemplates`, converted by [#3448](https://github.com/go-to-k/cdkd/issues/3448). **This also WIDENS validation**: a dropped top-level row was invisible to `refuseMalformedNestedTemplateTrees`, so the cycle / absolute-path / containment pre-flight silently skipped that row's whole subtree. **And a second defect is closed**: a `{}` literal also ANSWERS a lookup for a logical id never indexed when the name collides with the prototype (`toString`, `valueOf`, `constructor`), which six readers test with `if (!index[id])` across `NestedStackProvider`, `diff-recursive.ts`, `import.ts` and `export.ts`. An inherited member is truthy there, so a row carrying no `Metadata['aws:asset:path']` lost its "no template path" refusal and failed later and unreadably -- though still CLOSED: `path.join` / `path.resolve` / `readFileSync` each refuse a non-string with `ERR_INVALID_ARG_TYPE`, so `[object Object]` is what the message renders, never what was opened. The `??` fallbacks take a null-prototype record for the same reason. `defineOwnKey` would have left that second half, which is why the issue's prescription was reversed.
