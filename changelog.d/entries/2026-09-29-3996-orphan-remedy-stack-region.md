- **Every `cdkd state orphan` remedy cdkd prints as a template now carries `--stack-region <region>` (issue [#3996](https://github.com/go-to-k/cdkd/issues/3996))** -- `src/provisioning/providers/{cloudwatch-anomaly-detector,custom-resource,iam-policy,iam-user-group,s3-bucket,lambda-permission}-provider.ts`, `src/cli/commands/{destroy,state}.ts`, with the pins in `tests/unit/provisioning/*` and `tests/unit/cli/{destroy,state-destroy}.test.ts`. The provider skip warnings and refusals, and the `cdkd destroy` / `cdkd state destroy` partial-failure summaries, told the operator to clear a record with `cdkd state orphan <stack>`. Without `--stack-region` that command removes the stack name's record in every region, which is wider than the one stack in one region the message describes. The templates now read `cdkd state orphan <stack> --stack-region <region>`; the S3 region-mismatch refusal says the region is the stack's, not the bucket's; the custom-resource caveat scopes "drops EVERY record for the stack" to that region; and the three custom-resource `ServiceToken` refusals quote the commands instead of wrapping them in backticks, which ran them when pasted.
