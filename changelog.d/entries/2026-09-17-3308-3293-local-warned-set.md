- **A damaged producer record is named once per RUN and cannot be hidden by a planted stack name (issues [#3308](https://github.com/go-to-k/cdkd/issues/3308), [#3293](https://github.com/go-to-k/cdkd/issues/3293))** -- `src/state/malformed-resources-bag.ts`, `src/cli/commands/{scrub,local-state-loader}.ts`, `src/local/s3-local-state-provider.ts`, three suites. Both fixes land together because they change the same lines: one changes what the warned-once key IS, the other WHERE the set lives. **#3308**: the two warned-once-per-record sets joined stack and region with a NUL, which narrows a collision without closing it -- a stack name is read out of an S3 key and is as attacker-chosen as the `outputs` bag, so it can carry a NUL too, and this repo already plants one. **Measured**: stack `Evil<NUL>us-east-1` in `ap-northeast-1` and stack `Evil` in region `us-east-1<NUL>ap-northeast-1` produced the SAME key, so whichever was warned about second was silently not warned about at all. Both sites now call one shared `producerRecordKey`, which encodes with `JSON.stringify` (injective over string pairs) instead of separating -- and a fence pins that both sites go through the helper, since a second spelling is the failure it exists to prevent. **#3293**: the set lived in each resolver's closure, so `cdkd local invoke-agentcore` -- whose boot builds TWO resolvers, one for the `fromS3` bundle's bucket intrinsic and one for the container env -- reported one damaged record as two. `S3LocalStateProvider` now owns it and passes it to every resolver it builds, which is the honest scope (a run) and needs no change at the call sites; `buildCrossStackResolver` keeps its own set when no caller supplies one, so `local invoke` and `local run-task` are unchanged. Per provider INSTANCE, never module-global. Consequence in both cases is a dropped warning LINE, never a wrong resolution.
