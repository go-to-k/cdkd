- **A Cloud Control update of a Step Functions alias's `DeploymentPreference`, a Bedrock flow's `DefinitionString` / `DefinitionS3Location` / `DefinitionSubstitutions`, or any property of a Connect user succeeds again (issues [#6818](https://github.com/go-to-k/cdkd/issues/6818), [#6819](https://github.com/go-to-k/cdkd/issues/6819), [#6820](https://github.com/go-to-k/cdkd/issues/6820))** -- `src/provisioning/cc-read-back-exclusive-keys.ts`, `src/provisioning/cc-read-back-default-paths.ts`, `src/provisioning/write-only-properties.ts`, `src/provisioning/cloud-control/update.ts`, `src/deployment/deploy-engine/update/finish.ts`, `tests/unit/provisioning/cc-read-back-exclusive-keys-6818.test.ts`, `tests/unit/provisioning/cloud-control-connect-user-6820.test.ts`. Cloud Control applies the patch on top of its read model, which holds the alias's `RoutingConfiguration` and the flow's `Definition` in place of the write-only key the template declares, so shifting an alias to a new version failed with "Specify exactly one of 'RoutingConfiguration' or 'DeploymentPreference'" and changing a flow's definition with "only specify one of Definition, DefinitionString or DefinitionS3Location". The patch now also removes the read-back key (read live only when the patch writes such a key). A Connect user reads back `VoiceEnhancementConfigs: [{ Channel: "VOICE" }]` without the required mode, so every update failed model validation; that read-back value is now removed from the patch, as the template never declared it. A Connect user's `{{resolve:...}}` `Password` is no longer re-sent after a rotation (the handler refuses any `Password` on update); one re-pointed to another secret is refused before any call.
