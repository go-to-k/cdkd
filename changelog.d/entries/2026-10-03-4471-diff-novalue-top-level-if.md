- **A resource whose TOP-LEVEL property is a condition-false `Fn::If` selecting `AWS::NoValue` (`Fn.conditionIf(cond, x, Aws.NO_VALUE)` on an L1 property) no longer diffs as a perpetual UPDATE (issue [#4471](https://github.com/go-to-k/cdkd/issues/4471))** -- `src/analyzer/diff-calculator.ts` (`resolveBestEffort`), `tests/unit/analyzer/diff-calculator.test.ts`, and a live arm on `tests/integration/conditions-and-if/` (Phase 2b). The diff resolves desired properties one top-level key at a time, so the resolver returned the bare `AWS::NoValue` symbol for such a key instead of dropping it, and the symbol compared unequal to the absent recorded property: `cdkd diff --fail` exited 1 on an unchanged stack and every `cdkd deploy` planned an UPDATE of the resource. The key is now omitted, as the resolver already does for nested object keys and list elements; a key the stack still records is still reported as removed. The replacement decisions read the omission too: an `AWS::Lambda::Function` whose `DurableConfig` such a branch now removes is planned as a REPLACEMENT (it was an in-place UPDATE that kept the live durable config), one with no recorded `DurableConfig` no longer plans a spurious replacement, and a removed container whose record lacks a nested createOnly leaf updates in place instead of being conservatively replaced.
