- **`cdkd drift` reports a Lambda function's layers reordered out of band (issue [#6761](https://github.com/go-to-k/cdkd/issues/6761))** -- `src/analyzer/drift-normalize.ts` (`orderSignificantIdArrayPaths`), `src/analyzer/drift-calculator.ts`, `src/cli/commands/drift/compare.ts`, `src/deployment/unsettled-convergence.ts`, `tests/unit/analyzer/drift-normalize.test.ts`, `tests/unit/analyzer/drift-lambda-layers-order-6761.test.ts`, `tests/integration/lambda-layer-version-update/`. The comparator sorts every list of two or more AWS ids/ARNs on both sides so a set read back in another order is not drift, and `AWS::Lambda::Function` `Layers` is such a list, so a reorder compared equal. Layer order is configuration (Lambda extracts the layers in list order and a later one overwrites a file an earlier one placed at the same path), so `Layers` is now exempt from that sort: a reorder is reported, `--accept` records the live order (it used to record the sorted one), and the post-update unsettled check compares the order too. Other id/ARN lists (`SubnetIds`, ...) stay order-insensitive.
