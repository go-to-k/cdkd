- **A DataSync S3 location created with a same-stack role now deploys on the first try (issue [#6573](https://github.com/go-to-k/cdkd/issues/6573))** -- `src/deployment/retryable-errors/patterns.ts`, unit tests and the `datasync-location-role` integ fixture. `AWS::DataSync::LocationS3` is created through Cloud Control seconds after its bucket access role, and DataSync refused it with `Invalid IAM role ... DataSync service was unable to perform sts:AssumeRole` until IAM had propagated the role. cdkd did not retry that wording, so the deploy failed and rolled back, and a re-run failed the same way with a new role. cdkd now retries it on the IAM-propagation schedule, as it does for Firehose and IoT; the AWS CDK CLI deployed the same template on the first try.
