- **`cdkd diff`, `diff --fail-on destructive` and `deploy --require-approval destructive` show a Route 53 record set whose `Name` changed as a replacement (issue [#6656](https://github.com/go-to-k/cdkd/issues/6656))**. The record set provider deletes the old record and creates the renamed one in one change batch, but the diff showed the change as an update, so an approval missed it. It is now marked `[requires replacement: its Name changed, and Route 53 keys a record on its name; deleted, then created again]`, as CloudFormation reports a rename as a replacement; the deploy itself is unchanged. A `Type` or `SetIdentifier` change takes the same batch and stays an update, as in CloudFormation. A new generator, `scripts/gen-provider-replace-branches.ts` (`vp run gen:provider-replace-branches`, CI `audit:provider-replace-branches:check`), lists every SDK provider `update()` branch that replaces the resource with the property changes that lead into it (`docs/_generated/provider-replace-branches.{json,md}`), and fails CI on one the diff would show as an update. Files: `src/analyzer/diff-calculator/provider-replacement.ts`, `src/provisioning/providers/route53/record-name.ts`, `src/provisioning/providers/route53/shared.ts`, `docs/cli-diff.md`, `tests/unit/analyzer/diff-calculator-provider-replacement-6656.test.ts`, `tests/unit/scripts/gen-provider-replace-branches.test.ts`.
