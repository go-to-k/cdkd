- **`cdkd deploy` now waits for an ECS service to reach steady state by default, and a deployment circuit breaker's verdict fails the deploy (issue [#5571](https://github.com/go-to-k/cdkd/issues/5571), superseding the default chosen in [#1275](https://github.com/go-to-k/cdkd/issues/1275))** -- `src/provisioning/providers/ecs-provider.ts`, `src/cli/options.ts`, `tests/unit/provisioning/ecs-service-full-wait.test.ts`, `tests/integration/ecs-service-update-props/` (phases 2d / 2e), `docs/wait-modes.md`, `docs/cli-deploy.md`, `docs/cli-deploy-waits.md`. Before this change the default returned as soon as `CreateService` / `UpdateService` was accepted, so a service whose tasks crash-looped or whose image could not be pulled deployed with exit 0, and only `--full-wait` waited. The default now waits (600 s floor, raised by `--resource-timeout`) and fails the deploy when the rollout fails. Two circuit-breaker checks run: the deployment this deploy started turning `FAILED` ends the wait at once, and a service that settles on a different deployment (a `Rollback: true` breaker returning to the previous one, which the stability waiter accepts) fails too; even `--full-wait` reported that rollback as success. Both name the circuit breaker and the `aws ecs list-tasks` / `describe-tasks` commands. `--no-wait` now skips the ECS wait, and `--full-wait` covers only CloudFront `Deployed`. The automatic rollback, `cdkd rollback` and `cdkd drift --revert` warn and continue when their ECS update does not settle, so the stack never becomes un-rollbackable.
