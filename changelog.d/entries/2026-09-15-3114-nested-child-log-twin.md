- **`--verbose` no longer prints a 1-3 character secret on a nested-stack child's parameter lines, or on an `Fn::Join` over a value that still spelled a reference after an earlier stage resolved it (issue [#3114](https://github.com/go-to-k/cdkd/issues/3114))** -- `src/deployment/intrinsic-function-resolver.ts`, with cases in `tests/unit/deployment/intrinsic-resolver-nested-child-log-twin.test.ts` and a `SubFloorPinSsm` arm in the `nested-stack-secret` integ. Issue #3100's log twin was looked up only under the pass's own bag, while a child receives, as its inherited bag, the object its parent registered the twin of a built parameter value under (`port:q7` -> `port:***`). The lookup, which also gives `Fn::Split` its piece masks, now reads the inherited bag too, and two different registered twins mask the whole string. The `Parameter X: using user-provided value`, `Resolved Ref to parameter` and four `Fn::GetAtt` value lines now mask through the resolver's leaf mask, and a `Fn::Join` part that is re-resolved starts from its registered twin. It matters where the parent's carry refuses the frame, such as an `Fn::Join` around an `ssm` token. One state effect: `Fn::Base64` over such a value in the child now stores its encoding as `***`, as the parent already does (issue #3119's detector reads the same lookup), so a rollback replay of that child resource refuses the masked baseline as it does the parent's. Residual ([#3156](https://github.com/go-to-k/cdkd/issues/3156)): one level only, since a child hands its nested stack its own resource bag, so no twin registered above the child reaches a grandchild. The resolved values are unchanged. Not changed: an `Fn::Sub` string variable, which is template text its one substitution resolves whole.
