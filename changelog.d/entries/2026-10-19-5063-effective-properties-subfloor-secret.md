- **A 1-3 character secret embedded in a literal no longer reaches `state.json` in plaintext when a provider records its own `effectiveProperties` (issue [#5063](https://github.com/go-to-k/cdkd/issues/5063))** -- `src/deployment/secret-redaction/pairs.ts`, `src/deployment/deploy-engine/record-shape.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/deploy-engine/rollback.ts`, `src/deployment/rollback-executor/replay-retry.ts`, `src/deployment/rollback-executor/replay-secrets.ts`. Nine providers record a spread of the resolved properties they were handed (S3, Kinesis, AppSync, Cognito, the DynamoDB global table, the nested stack, the RDS proxy target group, the Secrets Manager secret, and the EC2 security group ingress), for example a `Tags[].Value` or a `Description`. Such a bag was never given the claim that lets a secret below the value scan's 4-character floor be written as its reference, because a provider may carry a previous value into it. It is now LEAF-certified: the redaction claim holds per leaf, since every arm the claim relaxes accepts a leaf only where it equals this deploy's own rendering of the template, so a carried value keeps its old answer. This applies on the deploy, in the rollback journal, and when a rollback replay restores the record. The v12 reference provenance of such a record is unchanged. Tests: `tests/unit/deployment/deploy-engine-leaf-certified-5063.test.ts`, `tests/unit/deployment/deploy-engine-short-embedded-secret.test.ts`, `tests/unit/deployment/secret-redaction-context-1940.test.ts`; integ `tests/integration/secrets-dynamic-ref` (a Kinesis stream tag).
