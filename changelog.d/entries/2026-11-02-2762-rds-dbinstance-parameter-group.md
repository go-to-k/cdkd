- **The SDK provider sends the parameter group of `AWS::RDS::DBInstance`, and reboots the instance when an update leaves the group `pending-reboot`, as CloudFormation does (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and a new arm in the `rds-dbinstance-backfill` integ. Before, a DB instance declaring `DBParameterGroupName`, such as a CDK `rds.DatabaseInstance` given a `parameterGroup`, routed through Cloud Control. The group now rides `CreateDBInstance`, and `ModifyDBInstance` when the template changes it; a removed one keeps the live group, as CloudFormation keeps it. RDS holds a new group `pending-reboot` until the instance reboots, so after an update that leaves the group in that state cdkd waits for the change to settle, reboots the instance and waits for it to read `in-sync`, as CloudFormation's update handler does; this also applies a static parameter edited in the group when the same deploy updates the instance. Under `--no-wait` it returns once the reboot starts. A rollback that reverts the group beside `EngineVersion` sends neither, since the old group's family does not fit the engine version still running. `cdkd drift` reads the group back.
