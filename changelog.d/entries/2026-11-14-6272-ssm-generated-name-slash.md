- **An SSM parameter without a `Name` is created without a leading `/`, so CDK's `grantRead` / `grantWrite` on it works (issue [#6272](https://github.com/go-to-k/cdkd/issues/6272))** -- `src/provisioning/resource-name/fallback-rules.ts`. cdkd named such a parameter `/<stack>-<logicalId>-<suffix>` and its `Ref` returned that, while CDK builds an auto-named parameter's ARN as `arn:...:parameter/` + Ref (CloudFormation's generated names have no slash), so the grant named `parameter//<name>` and the deployed function was denied. Both the SDK and the Cloud Control route now generate `<stack>-<logicalId>[-<suffix>]`. A parameter created before this keeps its recorded name and `Ref` (Name is create-only; SSM stores a one-level `/x` as `x`, so it is the same parameter); whether to re-spell those is issue [#6274](https://github.com/go-to-k/cdkd/issues/6274). Tests: `tests/unit/provisioning/ssm-parameter-generated-name-6272.test.ts`, `tests/unit/provisioning/generated-name-route-parity-5095.test.ts`; integ: `tests/integration/ssm-generated-name-grant`.
