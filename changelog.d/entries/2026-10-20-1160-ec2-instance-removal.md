- **`AWS::EC2::Instance` property removals now match CloudFormation: a removed `Monitoring` is turned off, and a removed `DisableApiTermination` is refused (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- Two rounds of real CloudFormation A/B decide each case. When `Monitoring` is removed, CloudFormation turns detailed monitoring off. cdkd used to send nothing, so monitoring stayed on; it now calls `UnmonitorInstances`. A removed `MetadataOptions` or `CreditSpecification` keeps its live value, in both. When `DisableApiTermination` is removed (from `true` or `false`), CloudFormation fails the whole update and keeps the value, but it applies an explicit `true` / `false`. cdkd used to drop the removal silently and leave protection on. A deploy that removes it now fails before any AWS call, other changes in the same update included. The error names the instance and says to keep the property declared and set it to `false` to turn protection off. A rollback that restores a state without the property does not refuse: the user cannot edit that state, so the rollback leaves protection as it is and warns when it was on. `cdkd drift --revert` is unchanged. Changed: `src/provisioning/providers/ec2-provider.ts`, `tests/unit/provisioning/ec2-provider-instance-removal-1160.test.ts`, `tests/integration/ec2-instance/`.
