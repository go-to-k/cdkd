- **`cdkd diff` / `cdkd deploy` update a custom resource whose `Timestamp` changed, and `cdkd drift` reports a reordered container argument list (issues [#6853](https://github.com/go-to-k/cdkd/issues/6853), [#6852](https://github.com/go-to-k/cdkd/issues/6852))** -- `src/analyzer/diff-calculator/compare.ts`, `src/analyzer/drift-normalize.ts`, `tests/unit/analyzer/diff-calculator-cr-timestamp-6852.test.ts`, `tests/unit/analyzer/drift-normalization-boundaries-6852.test.ts`, `docs/design/6852-drift-normalization-rules.md`. The diff ignored a top-level `Timestamp` on `AWS::CloudFormation::CustomResource` / `Custom::*`, so a template writing a fresh one to re-run the handler got no change and no handler invocation; CloudFormation sends an Update, and cdkd now does too. Drift sorted every list of two or more ARNs or AWS ids as a set, which also hid a swap of ARN arguments in a container's `Command` / `EntryPoint` / `Args` (Lambda `ImageConfig`, ECS task definitions, Batch job definitions, EMR steps); those lists now compare in order. The audit's rule inventory, with the AWS behavior behind each equivalence and its boundary, is in the design doc.
