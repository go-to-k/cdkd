- **`AWS::Cognito::UserPool` sends `KeyConfiguration` and `IssuerConfiguration` on the SDK route (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762))** -- `src/provisioning/providers/cognito-provider.ts` forwards both on `CreateUserPool` and `UpdateUserPool` and reads them back for drift, so a pool declaring either no longer falls back to Cloud Control. Removing `IssuerConfiguration` keeps the live value and warns, and removing `KeyConfiguration` resets the pool to the AWS owned key, both measured against CloudFormation on the same edit. `--remove-protection` now echoes a customer-managed `KeyConfiguration`: `UpdateUserPool` resets the key when the call omits it, so a delete that then failed left a live pool on the AWS owned key.
