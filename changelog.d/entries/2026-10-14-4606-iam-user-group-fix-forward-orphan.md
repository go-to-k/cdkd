- **A fix-forward deploy now deletes the IAM user or group an earlier failed CREATE left behind (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606), IAM user and group slice)** -- `src/provisioning/providers/iam-user-group-provider.ts`. When a `cdkd deploy --no-rollback` made an `AWS::IAM::User` or `AWS::IAM::Group`, failed wiring it (a permissions boundary, a login profile, a managed or inline policy, or a group membership) and could not delete it again, and a later deploy kept the logical id under another name, the successful deploy warned about the earlier user or group, left it in AWS and exited 2; `cdkd rollback` and `cdkd destroy` kept it the same way. The provider now answers both questions: a user or group name is unique per account, so the earlier one is a different one once the record's reads back (a record holding the same name in another case holds that very user or group, which is never deleted); and the failed CREATE records the `UserId` / `GroupId` its `CreateUser` / `CreateGroup` returned, so the earlier one is deleted only while its name still reads back under that id. One deleted by hand and re-created under the name has another id and is kept, with a warning. Tests: `tests/unit/provisioning/iam-user-group-provider-same-resource-4606.test.ts`; integ: `iam-user-group-fix-forward-orphan`.
