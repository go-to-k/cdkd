- **`cdkd local start-service` / `start-alb` under a loopback AWS endpoint start each task container inside a forwarder that is already up, so its first AWS call no longer races the forwarder (issue [#6152](https://github.com/go-to-k/cdkd/issues/6152))** -- `package.json` (`cdk-local` bumped to ^0.163.0, which carries go-to-k/cdk-local#881); `docs/local-emulation.md`. **Behavior change:** with `--aws-emulator` or a forwarded `AWS_ENDPOINT_URL*` on loopback, cdk-local's service runner starts a namespace-owning forwarder first and the container joins it with `--network container:<forwarder>` (before: the forwarder attached just after `docker run`, so an app calling AWS at once could fail with `connection refused`). For a joined container the IP and published ports are read from the forwarder, and `docker ps --filter network=<name>` lists forwarders, not containers. The "may need a retry" note for `start-service` / `start-alb` is removed from the docs. No cdkd source change: cdkd builds its `EcsRunState` with `createEcsRunState()` and reads no task container's IP, ports or networks itself.
