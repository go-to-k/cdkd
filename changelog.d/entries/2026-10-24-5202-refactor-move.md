- **`cdkd refactor` moves a resource between stacks instead of letting the next deploy replace it (issue [#5202](https://github.com/go-to-k/cdkd/issues/5202))** -- `src/cli/commands/refactor-move.ts` (new), `src/cli/commands/refactor.ts`, `src/state/logical-id-rename.ts` (`removeMovedRecords`, `insertMovedRecords`), `docs/cli-refactor.md`, a new unit file, and the new `refactor-move` integ. Before, a construct moved to another stack made the source's deploy delete the AWS resource and the destination's deploy create a new one, and `cdkd refactor` refused a mapping between two stacks. When a run selects two or more stacks of one account and region, a resource the source no longer declares now moves into the destination stack whose template newly declares one of the same type, when the destination's diff then shows it unchanged; look-alikes are named with `--override-file`. Both stacks are locked; the source is written first, and a failed write puts the destinations back before any source, so a resource is never recorded in two stacks. A named move to a stack with no state yet, and a stack that would both lose and gain a resource in one run, are refused; a stack with no state is never a detected destination. No AWS resource is touched.
