- **The composite-id refusal and the malformed-physicalId message no longer print a non-plain logical id raw (issue [#4107](https://github.com/go-to-k/cdkd/issues/4107))** -- `src/provisioning/composite-id.ts` (`compositeIdSeparatorRefusal`, `compositeIdFormatMessage`), with paste cases in `tests/unit/provisioning/composite-id-logical-id-paste.test.ts`. Both message heads printed the logical id unquoted. On `cdkd destroy` it is a `state.json` resource key, which nothing validates, so whoever can write the state bucket chose it: with `X$(touch OWNED)` as the id, pasting the head ran the substitution, and the delete-skip warning did the same under zsh. A plain logical id (hyphenated ones included) prints exactly as before; any other is described as `a logical id that is not a plain identifier`. The resource type in the refusal head is held to the plain-identifier rule too, so `AWS::Glue::Table` and `Custom::MyThing` print unchanged.
