- **A deploy's cleanup phase no longer deletes a replaced S3 bucket's old name when another bucket now holds it (issue [#6655](https://github.com/go-to-k/cdkd/issues/6655))**. When a deploy replaces a bucket, it deletes the old bucket by name only after the rest of the deploy succeeds. That delete did not check that the name still held the bucket the deploy replaced. Before sending it, the cleanup phase now compares the bucket under that name with the one the deploy read when it deferred the delete (issue [#6621](https://github.com/go-to-k/cdkd/issues/6621)). A bucket of another account or region, or one created at a different time in us-east-1, is left alone with a warning, and cdkd stops tracking the replaced bucket, which is gone. If cdkd cannot read what holds the name, it sends no delete, keeps the old bucket in state, and the next deploy retries. Outside us-east-1 the creation time is not compared, because configuration writes change it there. A deploy that replaces no bucket makes no extra call; a replaced bucket's cleanup makes one more read.
