- **`cdkd deploy --tags KEY=VALUE` (`-t`, repeatable) replaces the stack tags for a deploy, as `cdk deploy --tags` does (issue [#6886](https://github.com/go-to-k/cdkd/issues/6886))** -- `src/cli/options/stack-tags.ts`, `src/cli/commands/deploy/stack-deploy.ts`, `src/cli/commands/diff.ts`, `tests/unit/cli/stack-tags-option-6886.test.ts`, `tests/unit/cli/deploy-outputs-file.test.ts`. With at least one tag, those tags are used in place of every selected stack's own `StackProps.tags` (not merged), so they reach each taggable resource; without the flag, the top-level `tags` of `cdk.json` (`[{"Key": ..., "Value": ...}]`) is used the same way, as the AWS CDK CLI reads it. An argument without `=` is warned about and ignored, and an empty key or value stops the run before any change, since CloudFormation refuses one. `cdkd diff` takes the same flag so its preview matches. The AWS CDK CLI marks the flag deprecated (tags belong in the app); it is here for scripts that still pass it.
