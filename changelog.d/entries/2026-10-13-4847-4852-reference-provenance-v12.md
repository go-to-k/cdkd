- **State schema v12: each stored `{{resolve:...}}` reference records where it was resolved and which secret version it stood for (issues [#4847](https://github.com/go-to-k/cdkd/issues/4847), [#4852](https://github.com/go-to-k/cdkd/issues/4852), part 1 of 3)** -- `src/types/state.ts`, `src/deployment/secret-redaction/reference-provenance.ts`, `src/deployment/reference-provenance-record.ts`, `src/deployment/deploy-engine/provenance-capture.ts`, `src/state/token-free-state.ts`. A resource record gains `referenceProvenance` and the stack `outputReferenceProvenance`: per token, the region that resolved it and the secret's own version ids (a Secrets Manager `VersionId`, an SSM `Version`), read off the lookups cdkd already makes, never a value or a hash. Nothing reads them yet: every command behaves as before, and the fixes that use them follow. The first deploy after upgrading adds them to unchanged records through a one-time capture that sends, updates and replaces nothing (a record it cannot attribute gets an empty entry and one warning; a throttled lookup is retried next deploy); later deploys make no extra AWS call, and a stack holding no reference takes no extra work. `CDKD_SDK_CALL_LOG=<file>` appends, per cdkd process, a line counting every AWS SDK command it sent. Older binaries fail on v12 with "Upgrade cdkd". Integ: `schema-v11-to-v12-migration` (new).
