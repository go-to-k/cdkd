- **An S3 bucket's lifecycle rules that cdkd just wrote no longer leave a drift baseline holding the previous rules, which `cdkd drift --revert` would re-apply (issue [#6609](https://github.com/go-to-k/cdkd/issues/6609))** -- `src/provisioning/providers/s3-bucket/{lifecycle-baseline,read-state}.ts`, `src/provisioning/providers/s3-bucket-provider.ts`, unit tests, the `s3-lifecycle` integ. Right after `PutBucketLifecycleConfiguration` / `DeleteBucketLifecycle`, `GetBucketLifecycleConfiguration` can answer the previous rules, or none, for several seconds, and the deploy recorded that first answer as the `observedProperties` baseline: `cdkd drift` then reported an untouched bucket, and `drift --revert` re-applied an old expiration or deleted the declared rules. The capture after cdkd's own write now re-reads an answer that differs from the template (up to 4 more reads, 7.5 seconds at most, only when the first answer differs). If the declared rules are still not visible after that, the declared rules are recorded, in the shape the read returns; a just-deleted configuration that is still visible records no lifecycle baseline. A rule declared without an `Id` is recorded without one, since S3 generates it. Drift, import and `state refresh-observed` still take the first answer.
