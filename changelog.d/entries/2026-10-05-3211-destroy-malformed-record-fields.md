- **`cdkd destroy` / `cdkd state destroy` no longer hand a resource record's torn `properties` map or missing `physicalId` to the provider's delete (issue [#3211](https://github.com/go-to-k/cdkd/issues/3211), destroy half)** -- `src/cli/commands/destroy-runner.ts`, `src/state/malformed-resources-bag.ts`. A record whose `properties` is absent, `null`, a string, a list, a number or a boolean is now refused before the lock, naming each such resource and ending on a `cdkd state show` command; nothing is deleted or written for the stack. Before, the value reached `provider.delete` as it stood, where it decides the RDS final snapshot and whether an ECR repository is emptied first. A record whose `physicalId` is absent, empty, whitespace-only or not a string (other than a nested stack's, whose delete never reads it) is now skipped per resource with `skipped (state record has no physical id)`, its record kept and state preserved. Before, the provider was called with that value, and a resulting `*NotFound` read as already deleted dropped the record of a resource still live in AWS. The deploy half of the issue stays open. Tests: `tests/unit/cli/destroy-runner-malformed-fields.test.ts`, `tests/unit/cli/destroy-runner-malformed-entries.test.ts`, `tests/unit/state/malformed-resources-bag.test.ts`.
