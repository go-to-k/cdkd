- **A malformed Cloud Control resource model no longer echoes part of itself into a default-verbosity warning (issue [#3290](https://github.com/go-to-k/cdkd/issues/3290))** -- `src/provisioning/cloud-control-provider.ts`. `parseResourceModel`'s failure line promises, in the comment directly above it, that it logs the model's SHAPE and never its body -- the residual of GHSA-p5qg-v9gv-hc7w that issue [#1908](https://github.com/go-to-k/cdkd/issues/1908) closed. It logged `JSON.parse`'s own message, and V8 ECHOES the input around the failure point: `JSON.parse('{"pw": hunter2SuperSecretValue}')` answers ``Unexpected token 'h', "{"pw": hunter2Sup"... is not valid JSON``, so roughly thirty characters of the model reached a `warn` line at DEFAULT verbosity. That matters because a `{{resolve:secretsmanager:...}}` value resolved into a property that is not write-only can round-trip back through a Cloud Control readback, which is precisely the case the comment's promise exists for. The line now logs the failure CLASS through `describeAwsFailure` -- the same instrument the sibling abandonment path uses -- with the full text at `debug`; the existing `Model shape: <n> chars, <keys>` clause already carried the diagnosis the line exists for, namely WHICH document failed to parse, so nothing is lost. Needs a malformed model to reach at all, and never leaves the terminal: the catch returns `{}` rather than throwing, so nothing copies it into the durable `deployments/` store.
