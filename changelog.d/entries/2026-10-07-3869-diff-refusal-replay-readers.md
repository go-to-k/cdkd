- **`cdkd diff`'s adoption refusal and both rollbacks' completed-op replay mask a physical name derived from a secret (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/secret-name-needles.ts`, `src/cli/commands/diff-recursive.ts`, `src/cli/commands/rollback.ts`, `src/deployment/deploy-engine/rollback.ts`, `src/deployment/nested-child-journal.ts`, `src/cli/commands/diff.ts`. `cdkd diff` previews the refusal `cdkd deploy` throws when a resource an earlier rollback kept is recorded by another stack. It printed that resource's physical id in plaintext, in the rendered view and under `--json`, while the deploy's refusal masked it. It is now masked with the same needles (`orphanRecordsPrintingBag`). `cdkd rollback` and a failed deploy's automatic rollback revert the deploy's COMPLETED operations, for example by deleting a resource it created. That revert ran under no printing bag, so a resource named from a secret printed its name on the provider's delete lines. Both now revert under a bag judged from each op's record and the record it replaced, and so does a nested stack's child revert. The orphan-adoption planner's own lines (a vanished record, the existence check) are masked on `cdkd deploy` and `cdkd diff` too. `cdkd rollback` also judges each segment's failed ops against the state as that segment finds it, so it catches a name a newer segment's revert put back. An event's `physicalId` field stays exact.
