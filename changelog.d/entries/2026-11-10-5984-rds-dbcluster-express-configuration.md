- **The SDK provider creates and deletes `AWS::RDS::DBCluster` with `WithExpressConfiguration` (issue [#5984](https://github.com/go-to-k/cdkd/issues/5984))** -- `src/provisioning/providers/rds-provider.ts`, a new `src/provisioning/providers/rds/express-writer.ts`, the RDS cluster create, update and delete modules, the regenerated property-coverage map, a new unit file, the RDS wire cases, a new `rds-express-cluster` integ, and the destroy docs. Before, an Aurora PostgreSQL cluster created with express configuration routed through Cloud Control. The flag now rides `CreateDBCluster`, and the create waits for the `<cluster>-instance-1` writer RDS creates with it to be `available` (skipped under `--no-wait`). The delete removes that writer first, without a final snapshot, then the cluster, as CloudFormation's delete does. cdkd deletes no other instance: a cluster that still has one not already being deleted, or whose writer is not the one recorded when cdkd created it, is refused before anything is deleted. A value that is not `true` or `false` is refused before any call. Resources already deployed through Cloud Control stay there.
