- **`cdkd rollback` no longer re-adopts a replaced resource's old copy that a later deploy already deleted (issue [#6399](https://github.com/go-to-k/cdkd/issues/6399))** -- `src/deployment/rollback-executor/replay-reverse-replacement.ts`. A failed deploy keeps a replaced resource's old copy until its cleanup phase, and its journal segment says so. A later deploy can delete that copy through its own cleanup and then fail too. Replaying the older segment, `cdkd rollback` re-adopted the old copy whenever AWS could not answer whether it still existed (a type with no read, or a failed read). It pointed state at a deleted resource and deleted the live new one. It now re-adopts on such a read only while state still lists the old copy as awaiting its delete, and refuses otherwise, deleting nothing. A nested stack's revert gets the same check.
