- **`cdkd local invoke` / `start-api` / `run-task` / `invoke-agentcore` under `--aws-emulator` run a region-pinned stack in its own region (issue [#6270](https://github.com/go-to-k/cdkd/issues/6270))** -- `src/utils/emulator-default-region.ts` (new), `src/cli/aws-emulator.ts`, `src/local/local-aws-wiring.ts` (`resolveContainerRegion`), `src/cli/commands/local-invoke/template-env.ts`, `src/cli/commands/local-start-api/{command,state}.ts`, `src/cli/commands/local-invoke-agentcore/{image,sigv4}.ts`, `src/cli/commands/local-run-task/image-context.ts`, `src/cli/commands/local-state-loader.ts`, `docs/aws-emulator.md`. When the shell names no region, `--aws-emulator` copies the region in the emulator run's `config` into `AWS_REGION`. The `cdkd local` region chains read that copy as a region the user named, above the stack's `env.region` and the state record's region, so a stack with `env: { region: 'us-west-2' }` that `cdkd deploy --aws-emulator` put in the emulator's `us-west-2` ran under `local invoke` / `local start-api` with `AWS_REGION=us-east-1`, and its first call failed with `ResourceNotFoundException`. The copy is now a default: `--region`, a region the shell sets, the stack's region and the state record's region come first, as on real AWS. An environment-agnostic stack still gets the run's region. Real AWS is unchanged. The cdk-local engine commands (`start-service`, `start-alb` and the other `start-*` commands) still rank the copy first (go-to-k/cdk-local#963). Tests: `tests/unit/local/emulator-default-region-6270.test.ts`.
