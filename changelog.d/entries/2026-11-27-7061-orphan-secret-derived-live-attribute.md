- **`cdkd orphan` no longer writes a secret-derived attribute into the referring resources' state (issue [#7061](https://github.com/go-to-k/cdkd/issues/7061))** -- `src/analyzer/orphan-rewriter/**`. When a sibling's `Fn::GetAtt` pointed at the orphaned resource and the record held that attribute as secret-derived (masked, a secret dynamic reference, a `NoEcho` declaration, a secret-derived name, a credential-named leaf, or a credential-named or secret-valued attribute), `cdkd orphan` and `cdkd state orphan` wrote the value, live or recorded, into the sibling's persisted record. The orphaned record, which is what masks that value for every later reader, was dropped at the same time. The record's provenance now refuses the substitution before any read: the site is reported unresolved with what to do, and `--force` leaves the intrinsic in place. Two more cases are refused the same way. One is an attribute the record does not hold, on a record that carries a secret anywhere, since the record cannot tell whether it embeds one. The other is any `Ref` or `Fn::GetAtt` of a resource whose identifier is itself a credential (an AppSync API key, a wait condition handle's pre-signed URL).
