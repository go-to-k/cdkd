- **The EFS providers mask secret-resolved values in their own log lines and failure messages (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), EFS family slice)** -- `src/provisioning/providers/efs-provider.ts`; unit tests in `tests/unit/provisioning/efs-provider-masked-log.test.ts`. `create()` and `update()` of `AWS::EFS::FileSystem`, `AWS::EFS::MountTarget` and `AWS::EFS::AccessPoint` used to write their debug and warning lines through a logger no deploy-engine mask reaches. They now route every line through the deploy's masker: the `BackupPolicy` `Status` and `ReplicationOverwriteProtection` values (masked before they join the sentence, so a secret shorter than four characters is caught too), the transient-retry and read-back retry lines, the rollback-failure warning and the adoption read-back failure, each of which can carry AWS text quoting a request value back. The AWS error text a create or update failure message wraps is masked before it is joined. A short secret embedded in AWS error text is not caught. The `delete()` path still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
