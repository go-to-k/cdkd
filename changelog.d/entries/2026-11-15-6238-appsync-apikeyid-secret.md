- **`cdkd local run-task` names a container `Command` / `EntryPoint` / health-check element reading an `AWS::AppSync::ApiKey`'s `ApiKeyId` as a secret read, as it already did for `ApiKey` (issue [#6238](https://github.com/go-to-k/cdkd/issues/6238))** -- `src/utils/stringify.ts`. `ApiKeyId` is CloudFormation's second name for the same `x-api-key` value, so it now joins the secret-valued attributes that `cdkd local`'s argv guard and `cdkd orphan --force`'s cached-value fallback refuse to place. No record cdkd writes holds `ApiKeyId` today, so before this the element was already refused, as one that could not be resolved from state; the change keeps a future record from putting the key on the `docker run` command line. The five `Fn::GetAtt` values the issue reported already match CloudFormation (#6273, #6278, #6304). Tests: `tests/unit/local/ecs-task-resolver-command-intrinsics.test.ts`, `tests/unit/analyzer/orphan-rewriter.test.ts`.
