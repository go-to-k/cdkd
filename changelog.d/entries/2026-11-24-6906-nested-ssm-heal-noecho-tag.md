- **A nested stack whose resource records a `NoEcho` parameter's value (in its `Tags` or `Parameters`) no longer leaves a pre-#6272 SSM parameter name in its child un-healed (issue [#6906](https://github.com/go-to-k/cdkd/issues/6906))** -- `src/deployment/nested-ssm-name-check.ts`, cases in `tests/unit/deployment/nested-ssm-name-check-6282.test.ts`. The one-time check of #6282 updates a nested stack whose child still holds such a name, but deferred one whose record holds a masked value, since updating it could read a value cdkd stores masked, and still marked the stack checked, so the heal waited for a deploy that changed that nested stack. Since #6896 a nested stack's record keeps its `Tags`, so a `NoEcho`-sourced tag (`***`) deferred it too. A mask at a `noEchoLeaves` coordinate whose template reads only a `NoEcho` parameter (no `Fn::GetAtt`, cross-stack read or dotted `Fn::Sub` variable) is resolved afresh by the update, so such a row is now updated and healed; any other mask still defers.
