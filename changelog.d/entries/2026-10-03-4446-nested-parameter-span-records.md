- **A nested-stack child resource whose embedding leaf has several parts the template cannot state, or is an `Fn::If` selecting an `Fn::Sub` / `Fn::Join`, no longer reports an UPDATE on every deploy when a sibling `{Ref}` parameter resolves to the same plaintext (issues [#4446](https://github.com/go-to-k/cdkd/issues/4446), [#4469](https://github.com/go-to-k/cdkd/issues/4469))** -- `src/deployment/intrinsic-resolver/string-functions.ts`, `src/deployment/intrinsic-function-resolver.ts`, `src/deployment/secret-redaction/pairs.ts` (`IntrinsicLeafResolution.parameterSpans`), `src/deployment/secret-redaction/positions.ts`, `tests/unit/deployment/secret-redaction-nested-parameter-spans.test.ts`, and a live arm on `tests/integration/nested-stack-secret/` (`HandoffSpans` / `HandoffSpansIf`, their own `spans` JSON key). The #2320 arm aligned the template against the resolved leaf, so it refused a leaf like `postgres://` + `{Ref: User}` + `:` + `{Ref: A}` + `@` + an attribute, and never read an `Fn::If`; the leaf fell to the value scan and took the sibling parameter's expression, a perpetual UPDATE (a REPLACEMENT on a create-only property). The resolver now records, while it substitutes them, where each parameter `Ref` landed on an `Fn::Sub` / `Fn::Join` output, through nested parts and an `Fn::If`'s selected branch, and drops that record when a later dynamic-reference pass rewrites the text; a part that places no span it can vouch for (a string-selected `Fn::If` such as CDK's `Fn.conditionIf(c, '-prod', '')`) is a gap rather than a reason to drop the others. The persist path reads those spans first: each certified span takes that parameter's own expression, every other stretch is kept verbatim only where the value scan would leave it alone, and the #2320 straddle and final re-scan guards still apply. Any refusal falls back to the template parse, then the value scan.
