- **`cdkd scrub` no longer reports a stack CLEAN when a NAMELESS dynamic reference aborted the scan** — `{{resolve:ssm-secure}}` with no parameter name, and `{{resolve:secretsmanager}}` / `{{resolve:secretsmanager:}}` with no secret id, each raise a bare `Error` that fell through scrub's typed-refusal test into a `debug` line. The resolver's token loop has no per-token `try`, so either one abandons every remaining `{{resolve:...}}` token in the leaf: a real secret reference after it is never fetched and records no needle, so a legacy plaintext already sitting in `state.json` survived under `No plaintext secrets found`, exit 0. Both spellings now re-raise at all four best-effort catches. The four sibling RESOLUTION failures in the same loop are deliberately NOT re-raised — scrub resolves with template defaults and no `--parameters`, so an `Fn::Sub` that keeps its raw `${Field}` reaches them on a healthy stack; they are tracked separately as #3160.
