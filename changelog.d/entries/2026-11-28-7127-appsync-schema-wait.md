- **An AppSync GraphQL schema create or change now waits until AppSync applies it (issue [#7127](https://github.com/go-to-k/cdkd/issues/7127))** -- `src/provisioning/providers/appsync/{schema-wait,children,update-children}.ts`, `src/cli/commands/drift/baseline-keys.ts`. cdkd returned as soon as `StartSchemaCreation` did, while AppSync still served the previous schema: the drift baseline recorded that previous schema, so `cdkd drift` reported an untouched stack and `cdkd drift --revert` pushed the old schema back (AppSync then deleted the resolvers of the fields it lacks), and a schema AppSync refuses deployed with exit 0. As in CloudFormation, a create, an update, a rollback and a `drift --revert` of `AWS::AppSync::GraphQLSchema` now poll `GetSchemaCreationStatus` until it leaves `PROCESSING`, in every wait mode (`--no-wait` included), and a `FAILED` schema fails the resource (AWS's reason is in the `--verbose` output). A baseline an earlier cdkd recorded this way is not reported while the live schema is the declared inline `Definition`.
