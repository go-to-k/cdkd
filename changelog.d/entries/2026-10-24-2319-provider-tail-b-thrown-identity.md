- **A failed ELBv2 load balancer, target group or listener, Firehose delivery stream, CloudWatch alarm or anomaly detector, CloudFront origin access control, S3 Express directory bucket, S3 vector bucket, Kinesis stream consumer, or Bedrock AgentCore runtime, evaluator, default browser or default code interpreter no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/{elbv2,firehose,cloudwatch-alarm,cloudwatch-anomaly-detector,cloudfront-oac,s3-directory-bucket,s3-vectors,kinesis-streamconsumer,agentcore-runtime,agentcore-evaluator,agentcore-browser,agentcore-code-interpreter}-provider.ts` and unit cases. The create, update and delete failure messages quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker. A cdkd-authored or transport error keeps its text, masked. The AWS error is still the wrap's `cause`, so an IAM grant that is still propagating, or a throttle, is retried as before, a `--remove-protection` load balancer delete still decides between retrying and restoring the guard on AWS's text, and an "already exists" is still stated as such.
