- **`cdkd drift` no longer reports, and `drift --revert` no longer pushes back, a stale schema baseline on an AppSync schema sourced from `DefinitionS3Location` (issue [#7139](https://github.com/go-to-k/cdkd/issues/7139))** -- `src/provisioning/providers/appsync/read-state.ts`, `src/provisioning/providers/appsync-provider.ts`. A cdkd before #7127 recorded an `AWS::AppSync::GraphQLSchema` baseline while AppSync still served the schema the deploy replaced. The #7127 heal skipped such a baseline only for an inline `Definition`, so an L1 `CfnGraphQLSchema` with `definitionS3Location` reported `Definition` on an untouched schema, and `drift --revert` pushed the previous schema back (AppSync then dropped the resolvers of the fields it lacks). Drift now reads the declared S3 object (one `GetObject`, only when the recorded and live schemas differ) and takes the live schema as the baseline when it is that object's body. A live schema other than the declared body, or an object it cannot read, is still reported.
