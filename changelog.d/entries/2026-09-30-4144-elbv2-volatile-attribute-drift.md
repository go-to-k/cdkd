- **`cdkd drift` no longer reports an undeclared ELBv2 attribute that AWS stopped returning (issue [#4144](https://github.com/go-to-k/cdkd/issues/4144))** -- `src/provisioning/providers/elbv2-provider.ts` (`canonicalizeDriftPair`, `ATTRIBUTE_BAG_BY_TYPE`), `src/types/resource.ts`, `docs/_contents/provider-rules.md`, `docs/_contents/cli-drift.md`, `tests/unit/provisioning/elbv2-attribute-bag-volatile-key-4144.test.ts`. The observed baseline of a load balancer, target group or listener records every attribute AWS returns. When AWS later stopped returning one the template never declared (`ddos_protection.syn_cookie.mode` on an ALB), `cdkd drift` reported the whole attribute list as drifted, and `--revert` sent the key back. The drift pair pass now drops, from the baseline only, an entry whose key is undeclared AND absent from the readback: no ELBv2 attribute call removes a key, so that absence is not an out-of-band change. Still reported: a declared key that changed or vanished, an undeclared key whose value changed, and a key only the readback holds. `--revert` sends the trimmed baseline, so it no longer writes the dropped key. The pass leaves the baseline unchanged when the readback bag is missing or empty, or the declared bag cannot be read.
