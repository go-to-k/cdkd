- **A resource reading a nested stack's output is now updated when that output changes (issue [#3631](https://github.com/go-to-k/cdkd/issues/3631))** -- `src/analyzer/diff-calculator.ts` (`promoteInPlaceAttributeDependents`, `extractGetAttRefs`), `tests/unit/analyzer/diff-calculator-nested-output-promotion.test.ts`, `tests/unit/deployment/deploy-engine-nested-output-reader-promotion.test.ts`, and a new phase-3 arm of the `tests/integration/custom-resource-noecho-nested/` fixture. The parent's diff runs before the child deploys, so a resource reading `Fn::GetAtt [Child, 'Outputs.<Key>']` compared the child's previous output against its own record, diffed NO_CHANGE, and kept the old value on AWS under a green deploy. An in-place update of an `AWS::CloudFormation::Stack` now promotes every reader of its `Outputs.*` attributes. The deploy re-resolves each one against the output the child deploy returned and skips the provider call when it did not move, so an unchanged output still sends no update. `cdkd diff` lists those readers as updates. The two promotion passes now run until nothing more is promoted, so a sibling nested stack fed by the moved output, a reader of THAT stack's outputs, and a promotion that turns into a replacement all propagate as well. The string form `Fn::GetAtt: "Child.Outputs.Key"` is recognised as a reference too. A reader with any read of a value stored as the `***` mask (a `NoEcho` custom resource's) is not promoted this way, since the deploy would refuse that read; lifting that goes with issue [#3662](https://github.com/go-to-k/cdkd/issues/3662).
