- **`AWS::Connect::Instance` is created through a new SDK provider, so `--no-wait` skips most of its `ACTIVE` wait (issue [#6912](https://github.com/go-to-k/cdkd/issues/6912))** -- `src/provisioning/providers/connect-instance-provider.ts`, the `Fn::GetAtt` arm in `src/deployment/intrinsic-resolver/getatt-construct-app.ts`, registration, docs and unit tests. Through Cloud Control the instance create returned only at `ACTIVE`, about 60-85 s after `CreateInstance`, and `--no-wait` could not shorten it. cdkd now calls `CreateInstance` directly and waits until the instance accepts dependent calls (about 20 s in, still `CREATION_IN_PROGRESS`). When the template declares `Attributes` members besides `InboundCalls` / `OutboundCalls`, it also waits for the instance to turn on its own default attributes (about 40 s), since a write before them is overwritten, and then writes the declared ones with `UpdateInstanceAttribute`. By default it then waits for `ACTIVE` and writes again any declared attribute a late default overwrote. Under `--no-wait` it returns before the `ACTIVE` wait, so storage configs, contact flows and integrations that reference the instance are created earlier. A `Fn::GetAtt` of `ServiceRole` still waits for `ACTIVE`, because the role exists only then. `CREATION_FAILED` fails the deploy and deletes the instance. An `Attributes` member removed from the template is left at its live value with a warning. `cdkd import` adopts an instance by `InstanceAlias` or by `--resource <id>=<instanceArn>`. An instance already recorded on Cloud Control stays there.
