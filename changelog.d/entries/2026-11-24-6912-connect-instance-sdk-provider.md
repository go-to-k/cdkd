- **`AWS::Connect::Instance` is created through a new SDK provider, so `--no-wait` skips most of its `ACTIVE` wait (issue [#6912](https://github.com/go-to-k/cdkd/issues/6912))** -- `src/provisioning/providers/connect-instance-provider.ts`, the `Fn::GetAtt` arm in `src/deployment/intrinsic-resolver/getatt-construct-app.ts`, registration, docs and unit tests. Through Cloud Control the instance create returned only at `ACTIVE`, about 60-85 s after `CreateInstance`, and `--no-wait` could not shorten it. cdkd now calls `CreateInstance` directly, waits until the instance accepts dependent calls (about 20-25 s in, still `CREATION_IN_PROGRESS`), applies the `Attributes` members `CreateInstance` does not take with `UpdateInstanceAttribute`, and then waits for `ACTIVE`. Under `--no-wait` it returns before that last wait, so storage configs, contact flows and integrations that reference the instance are created about 35-55 s earlier. A `Fn::GetAtt` of `ServiceRole` still waits for `ACTIVE`, because the role exists only then. `CREATION_FAILED` fails the deploy and deletes the instance. An `Attributes` member removed from the template is left at its live value with a warning. `cdkd import` adopts an instance by `InstanceAlias` or by `--resource <id>=<instanceArn>`. An instance already recorded on Cloud Control stays there.
