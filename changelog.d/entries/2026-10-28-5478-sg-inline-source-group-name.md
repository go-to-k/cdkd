- **An inline `AWS::EC2::SecurityGroup` ingress rule that names its peer with `SourceSecurityGroupName` now reaches AWS with that peer (issue [#5478](https://github.com/go-to-k/cdkd/issues/5478))** -- `src/provisioning/providers/ec2-provider.ts`. The rule builder read only `SourceSecurityGroupId`, so such a rule (a default-VPC group referenced by name) went out with no peer while the deploy succeeded and state recorded it as declared. It is now sent as `UserIdGroupPairs[].GroupName`, as CloudFormation sends it (measured in a default VPC: the rule was created with the named group as its peer), on create and on an update, where a renamed peer revokes the old rule and authorizes the new one. An id given beside the name still wins. The standalone `AWS::EC2::SecurityGroupIngress` is unchanged: CloudFormation refuses the member there.
