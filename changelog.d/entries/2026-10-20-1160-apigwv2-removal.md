- **`AWS::ApiGatewayV2::*`: the remaining properties removed from the template now follow CloudFormation (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/apigatewayv2-provider.ts`. A real CloudFormation A/B on the issue measured each one, removed alone and beside another change. A removed Authorizer `IdentitySource` is now cleared (`UpdateAuthorizer` gets `[]`); before, cdkd left it in place. As in CloudFormation, AWS refuses that clear for a JWT authorizer or a REQUEST authorizer with caching on. A forward deploy that removes an Integration `IntegrationSubtype` without declaring an `IntegrationUri` is now refused before any call, because CloudFormation fails that update. Before, cdkd reported success and kept the subtype. When the same update declares an `IntegrationUri`, the update is sent without the subtype and the integration becomes URI-based, as it does in CloudFormation. A rollback replay keeps the subtype and warns. Every other removable property (Api `RouteSelectionExpression`; Stage `Description` / `DefaultRouteSettings`; Integration `IntegrationUri` / `IntegrationMethod` / `PayloadFormatVersion` / `TimeoutInMillis` and the other #609 fields; Route `Target` / `ModelSelectionExpression` / `RouteResponseSelectionExpression`; Authorizer `AuthorizerUri` / `EnableSimpleResponses` / `JwtConfiguration`) is kept, as before. Also fixed: an update to an `EventBridge-PutEvents` service integration that did not change its `RequestParameters` (a `Description`-only change, for example) failed with `requires enabling passthrough, or defining all of the following parameters`. AWS re-validates the parameter mapping on every update, so cdkd now sends it beside the subtype. Tests: `tests/unit/provisioning/apigatewayv2-provider-roundtrip.test.ts`, `apigatewayv2-integration-props.test.ts`; the `apigatewayv2-update-removal` integ fixture gains a cleared `IdentitySource`, kept #609 fields, a `Description`-only service-integration change and a refused subtype removal (phase 2c).
