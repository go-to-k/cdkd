- **`AWS::ApiGatewayV2::*`: the remaining properties removed from the template now follow CloudFormation (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/apigatewayv2-provider.ts`. A removed Authorizer `IdentitySource` is now cleared (`UpdateAuthorizer` gets `[]`); before, cdkd left it in place. As in CloudFormation, AWS refuses that clear for a JWT authorizer or a REQUEST authorizer with caching on. A forward deploy that removes an Integration `IntegrationSubtype` without declaring an `IntegrationUri` is now refused before any call, because CloudFormation fails that update. Before, cdkd reported success and kept the subtype. Declared beside an `IntegrationUri`, it is sent without the subtype, as CloudFormation does. A rollback replay keeps a subtype the live integration still has, and warns. Every other removable property (Api `RouteSelectionExpression`; Stage `Description` / `DefaultRouteSettings`; Integration `IntegrationUri` / `IntegrationMethod` / `PayloadFormatVersion` / `TimeoutInMillis` and the other #609 fields; Route `Target` / `ModelSelectionExpression` / `RouteResponseSelectionExpression`; Authorizer `AuthorizerUri` / `EnableSimpleResponses` / `JwtConfiguration`) is kept, as before. Also fixed: an update to an `EventBridge-PutEvents` service integration that did not change its `RequestParameters` (a `Description`-only change, for example) failed with `requires enabling passthrough, or defining all of the following parameters`. AWS re-validates the parameter mapping on every update, so cdkd now re-sends the declared map beside the subtype; a declared map missing a required key still fails, as it does in CloudFormation, and a redacted secret stand-in in it refuses instead of being sent. Tests: `apigatewayv2-provider-roundtrip.test.ts`; integ `apigatewayv2-update-removal` phases 2, 2b, 2c.
