- **An IoT topic rule created with a same-stack role now deploys on the first try (issue [#6559](https://github.com/go-to-k/cdkd/issues/6559))** -- `src/deployment/retryable-errors/patterns.ts`, unit tests and the `iot-topic-rule-role` integ fixture. `AWS::IoT::TopicRule` is created through Cloud Control seconds after its action role, and IoT refused it with `AWS IoT (iot.amazonaws.com) is unable to assume role (sts:AssumeRole)` until IAM had propagated the role. cdkd did not retry that wording, so the deploy failed and rolled back, and a re-run failed the same way with a new role. cdkd now retries it on the IAM-propagation schedule, as it does for Firehose and Glue; the AWS CDK CLI deployed the same template on the first try.
