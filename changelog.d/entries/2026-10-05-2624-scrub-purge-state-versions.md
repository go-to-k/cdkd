- **`cdkd scrub` purges the earlier versions of every `state.json` and exports index it rewrites, and `--purge-history` purges every examined record's (issue [#2624](https://github.com/go-to-k/cdkd/issues/2624))** -- `src/cli/commands/scrub.ts`, `docs/_contents/cli-scrub.md`. On a versioned state bucket, scrub's `PutObject` used to leave the pre-scrub body readable by `VersionId`. A real run now purges the noncurrent versions of each `state.json` it rewrites, including a nested child's record, a parent row repaired for a child output, and a pre-region-layout record, which is now migrated (it used to fail the rewrite) with its old key's history purged (a surviving or unverifiable old key fails the stack). It also purges `{state-prefix}/_index/{region}/exports.json` once per region whose entries it rewrote. The purge reuses the state backend's fail-soft `purgeNoncurrentVersions` (missing version grants or a replicated bucket only warn, above the summary). The purge also runs after an ambiguous or SDK-retried write failure, never after a definite refusal on the first attempt. The `Done: scrubbed ...` line says the earlier versions were purged "unless a warning above says otherwise". A record scrub did not rewrite keeps its history unless the new `--purge-history` flag is passed, which purges every examined record's earlier versions (each target and nested stack with a readable record, never a refused one) and is refused with `--dry-run`, which purges nothing. A plain `cdkd deploy` never purges, because those versions are the state-recovery history; the docs now say its implicit scrub leaves earlier versions that may hold the plaintext, removed by `cdkd scrub --purge-history`. Tests: `tests/unit/cli/commands/scrub-purge-state-versions.test.ts`, `tests/unit/cli/commands/scrub-export-index.test.ts`, `tests/unit/cli/commands/scrub-all-refusal-boundary.test.ts`, `tests/unit/cli/commands/scrub-nested-child.test.ts`.
