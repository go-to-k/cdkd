- **`AWS::ElastiCache::CacheCluster` is replaced when a memcached cluster moves from `AZMode: single-az` to `cross-az` with the same node count, as CloudFormation does (issue [#7045](https://github.com/go-to-k/cdkd/issues/7045))** -- `src/analyzer/replacement-rules/predicates.ts`, `src/provisioning/providers/elasticache/cache-cluster-update.ts`. A real CloudFormation update from a 2-node `single-az` cluster with no zone list to `cross-az` with `PreferredAvailabilityZones` naming two zones replaced the cluster with one spanning both zones. Before this change cdkd showed an in-place update, sent no zone change (ModifyCacheCluster carries `AZMode` only beside nodes to add), and the cluster stayed in one zone with a warning. Now `cdkd diff` shows the replacement and the deploy creates the new cluster (a stateful type, so the deploy needs `--force-stateful-recreation`). The same move with a previous zone list, a one-zone list, or a changed node count was not measured and stays an in-place update; its warning no longer says CloudFormation leaves the cluster unchanged.
