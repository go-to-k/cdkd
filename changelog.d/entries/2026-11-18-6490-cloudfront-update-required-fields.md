- **An `AWS::CloudFront::Distribution` update no longer fails with `InvalidArgument` when the template leaves a custom origin's `OriginSSLProtocols` or a cache behavior's `Compress` unset (issue [#6490](https://github.com/go-to-k/cdkd/issues/6490))** -- `src/provisioning/providers/cloudfront-distribution/update-config.ts`. `UpdateDistribution` requires both members, though `CreateDistribution` and CloudFormation accept a template without them, so every SDK-route update of such a distribution was refused ("The parameter OriginSslProtocols is required", then "The parameter Compress flag is required"). This hit distributions cdkd created as well as ones moved from Cloud Control. Templates from CDK's L2 `Distribution` and `HttpOrigin` set both members and were not affected. An omitted `OriginSSLProtocols` now keeps the value the origin of the same `Id` already holds, so the update changes nothing on AWS. When the previous template declared it, a warning says the live value was kept. CloudFormation's `SSLv3, TLSv1` default is not used, because it would re-enable SSLv3 on an origin created without it. A custom origin new in the update gets what CloudFront records at create: `TLSv1`, `TLSv1.1` and `TLSv1.2`. An omitted `Compress` is sent as `false`, CloudFormation's default. Declared values are sent as declared.
