- **`cdkd events prune --all` and `cdkd destroy --purge-events` now purge every earlier version under the stack's `deployments/` prefix, including streams an earlier delete left behind a delete marker (issue [#2624](https://github.com/go-to-k/cdkd/issues/2624), site 3 residue)** -- `src/state/s3-noncurrent-version-purge.ts` (`purgeNoncurrentVersionsUnderPrefix`), `src/state/s3-state-backend.ts`, `src/state/deployment-events-store.ts`, `src/cli/commands/events.ts`, `src/cli/commands/destroy.ts`, `docs/deployment-events.md`, `docs/cli-destroy.md`, `docs/cli-events.md`, `docs/ci-per-pr.md`, `docs/state-management.md` and the plugin skill doc (plugin 0.7.9). Before, the purge acted only on the keys a run deleted, found by an ordinary listing, so a stream deleted by an earlier release or by a purge that warned stayed readable with a `VersionId` and the output was scoped to "the deleted keys". Because `--all` empties the whole directory, it now walks every version under the exact `<state-prefix>/<stack>/<region>/deployments/` prefix, keeping each key's current version, and runs even when nothing current is listed. Region discovery reads current keys only, so for a region where none of the stack's history is current any more, `cdkd events prune` needs `--stack-region`, and its "No deployment-event history found" error now says so. `--stack-region` is now lower-cased like every other command's, and when nothing current is left the summary claims a purge only if the sweep removed an earlier version with content (not just a delete marker), says none were found in that region if it removed nothing, and says the versions could not be purged if it failed. The trailing `/` keeps a stack whose name extends this one's out of the sweep, and a prefix without one is refused. `--keep` / `--older-than` and the writer's self-bounding prune are unchanged and still purge only the keys they delete. Without `s3:ListBucketVersions` / `s3:DeleteObjectVersion` it still succeeds and warns.
