- **Every command starts about a quarter faster from the second run: cdkd enables Node's compile cache (issue [#4521](https://github.com/go-to-k/cdkd/issues/4521))** -- `src/cli/index.ts`, `src/cli/compile-cache.ts`. The entry calls `module.enableCompileCache()` before importing the command tree, so V8 reuses compiled code for cdkd's chunks and the externalised `@aws-sdk/*` packages instead of compiling them on every run (`cdkd --help`: ~890 ms to ~680 ms wall-clock with a warm cache). The cache lives in the user's own cache directory (`$XDG_CACHE_HOME/cdkd/compile-cache` or `~/.cache/cdkd/compile-cache`), never Node's default under the shared OS temp dir, where another local user could plant entries Node validates only by checksum; with no home directory it stays off; `NODE_DISABLE_COMPILE_CACHE=1` turns it off and `NODE_COMPILE_CACHE` moves it (CLI Reference, "Startup compile cache"). The `--version` fast path is unchanged. Tests: `tests/unit/cli/version.test.ts`, `tests/unit/cli/compile-cache.test.ts`.
