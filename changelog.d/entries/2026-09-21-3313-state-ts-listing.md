- **`cdkd state`'s two S3 listings take `EncodingType` too, closing the last site of issue [#3313](https://github.com/go-to-k/cdkd/issues/3313)** -- `src/cli/commands/state.ts`, one suite. [#3331](https://github.com/go-to-k/cdkd/issues/3331) fixed nine of the ten listings; this one was deferred because another PR held the file, and that PR has merged. Both listings here READ the key they return: the state-file walk collects keys every later `getState` addresses, and the bootstrap-marker walk SLICES the key into a region name and hands it back to `GetObject` -- so a carriage return turned into a line feed by the XML round trip names the wrong region and reads the wrong object. The marker key is decoded BEFORE its defensive `startsWith` re-check, or the guard would test a different string from the one that gets used. The suite's `HELD_BY_ANOTHER_PR` list, which recorded this deferral with an assertion that FAILED once the site was wired, is now empty and asserted empty: a deferral stays legitimate while another PR holds a file, but it must name that PR and come out when it merges, rather than becoming a permanent exemption wearing a temporary label. Removing the entry also promotes `state.ts` into the per-file loop, so it now carries a real positive case.
