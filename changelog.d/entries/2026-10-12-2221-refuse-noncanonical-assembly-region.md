- **cdkd now reads the region of a cloud assembly's stack environment exactly as the AWS CDK CLI does, and refuses the ones it refuses, such as `aws://<account>/US-EAST-1` (issue [#2221](https://github.com/go-to-k/cdkd/issues/2221))** -- `src/types/assembly.ts` (`parseEnvironment`), `src/synthesis/assembly-reader.ts`. cdkd used to take any text after `aws://<account>/` as the region. For `US-EAST-1` the deploy succeeded against the lowercase region, because its AWS clients fold the region they sign with, but recorded the stack's state under the raw spelling (`cdkd/<stack>/US-EAST-1/state.json`), which a later deploy from the correctly spelled assembly does not read. A region carrying a line break fell back to the command's own region. The region is now the longest run of lowercase letters, digits and `-` after the `/`, the rest ignored, which is how the AWS CDK CLI reads it: `us-east-1/extra`, `us-east-1 ` and a region followed by a line break all read as `us-east-1`. Where no such run starts right after the `/` (`US-EAST-1`, ` us-east-1`), reading the assembly fails, naming the stack and the region, as the AWS CDK CLI fails with `Unable to parse environment specification`. The message tells you which spelling to re-synthesize with. For a spelling that differs only in case, it also warns that state an earlier cdkd recorded under the raw spelling is not found by the corrected deploy, and that `cdkd state show` and `cdkd state orphan` still reach that record with `--stack-region` given the exact raw spelling. The account part of the environment and the `unknown-*` sentinels are unchanged.
