- **`cdkd deploy` no longer plans a CREATE for a resource whose state row cannot be read (issue [#3314](https://github.com/go-to-k/cdkd/issues/3314))** -- `src/analyzer/diff-calculator.ts`, `src/state/malformed-resources-bag.ts`, `src/deployment/deploy-engine.ts`, plus `diff-calculator-malformed-properties.test.ts`, `deploy-engine-malformed-entries-refusal.test.ts` and cases in `malformed-resources-bag.test.ts`. The change calculation looked each template resource up by logical id and treated any falsy row as "not in state". So a `null` (or any non-object) entry in `resources`, from a hand edit or a torn write, was planned as a CREATE of a resource cdkd already manages: a named resource then failed on a name collision with a message that did not mention the record, and an unnamed one was created a second time with the first copy orphaned. A row with no `resourceType` was planned as a type-change replacement. `cdkd deploy` now refuses such rows by name (`STATE_RESOURCES_MALFORMED`, exit `1`) at its state load, before any resource is created, updated or deleted and before any state is written, under `--dry-run` too; `calculateDiff` refuses them as well. A default deploy used to die before the diff on a bare `TypeError` (in the prefix-migration check, or in the observed-state auto-refresh walk), so the refusal sits at the load, which runs before both. `cdkd diff` still previews the rest of the stack without those rows and warns, as before.
