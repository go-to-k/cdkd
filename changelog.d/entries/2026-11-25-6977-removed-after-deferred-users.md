- **`cdkd deploy`: a replaced resource's old copy that still uses a resource removed from the template is deleted before that resource (issue [#6977](https://github.com/go-to-k/cdkd/issues/6977))** -- `src/deployment/deploy-engine/replacement/deferred-deletes.ts`, `src/deployment/deploy-engine/execute.ts`, `docs/cli-deploy-safety.md`. Renaming a Lambda function that has a `currentVersion` and an alias replaces the alias and removes the old version. cdkd deleted the removed version first, while the old alias, waiting for the cleanup phase, still pointed at it: Lambda refused the delete, the deploy waited about 5 minutes, kept the version's record and exited `2`. CloudFormation's cleanup phase deletes both kinds in one dependency order. cdkd now deletes such an old copy, and the old copies using it, right before the removal deletes, dependents first. Every other old copy still waits for the cleanup phase. When a removed resource itself uses one of those old copies, the order is unchanged. Tests: `tests/unit/deployment/deploy-engine-removed-after-deferred-users-6977.test.ts`.
