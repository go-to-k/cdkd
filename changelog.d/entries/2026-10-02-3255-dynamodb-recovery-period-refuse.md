- **`AWS::DynamoDB::Table` refuses a `PointInTimeRecoverySpecification.RecoveryPeriodInDays` CloudFormation rejects, before any AWS call (issue [#3255](https://github.com/go-to-k/cdkd/issues/3255))** -- `src/provisioning/providers/dynamodb-table-provider.ts`. A period spelled `" 7 "`, `"0x9"`, `"1e1"`, `null` or an unresolved intrinsic used to be dropped with a warning: `UpdateContinuousBackups` then succeeded at DynamoDB's default period while cdkd state kept the declared value, so `cdkd drift` reported a difference on every run and `cdkd drift --revert` re-sent the same call forever. `create()` and `update()` now refuse such a value, and one outside the API's 1-35 range, with a message naming the property, before any call, so no table is created only to be deleted and nothing is recorded to drift against. A non-object `PointInTimeRecoverySpecification`, which was read as "PITR disabled", is refused the same way. The AWS CDK CLI cannot deploy these templates either. A rollback replay or `drift --revert` keeps the warn-and-drop, since their properties come from cdkd state rather than the template; an unchanged block an older cdkd recorded is not refused, since nothing is sent for it. Tests: `tests/unit/provisioning/dynamodb-table-provider-cfn-integer.test.ts`.
