- **Destroying an `AWS::DynamoDB::GlobalTable` now waits for the table to be gone in every replica region (issue [#5699](https://github.com/go-to-k/cdkd/issues/5699))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`, its unit tests, and `docs/cli-deploy-waits.md`. cdkd reported the global table deleted once the source table stopped listing each replica and the source table itself was gone, while each replica region's copy was still `DELETING` for minutes. A dependent such as a replica-region KMS key could be deleted under a live copy, and a check right after the destroy still found the table. The delete now waits for each replica region's copy to read `ResourceNotFound`, the regions in parallel, as it already does for an `AWS::DynamoDB::Table`. The wait is capped at about 12 minutes and the shared delete budget; a wait that runs out, a Ctrl-C, or a copy cdkd cannot read warns and moves on, since AWS has already accepted the delete. Removing a replica on a deploy still does not wait.
