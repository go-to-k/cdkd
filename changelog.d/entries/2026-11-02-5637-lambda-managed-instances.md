- **Lambda Managed Instances functions deploy through the SDK provider (go-to-k/cdkd#5637)** -- `src/provisioning/providers/lambda-function-provider.ts`. `AWS::Lambda::Function` now wires `CapacityProviderConfig`, `FunctionScalingConfig` and `PublishToLatestPublished`, which used to send the whole function through Cloud Control. The capacity provider itself stays the separate `AWS::Lambda::CapacityProvider` resource: the function only takes its ARN. Measured against CloudFormation: a create always publishes `$LATEST.PUBLISHED` and waits for it (minutes, as the capacity launches), an update publishes unless `PublishToLatestPublished` is false, scaling applies to `$LATEST.PUBLISHED`, and removing the scaling block resets it to Lambda's default. Removing `CapacityProviderConfig` from a function AWS holds it on is refused, as are `FunctionScalingConfig` and `PublishToLatestPublished` without one, as on CloudFormation. Under `--prefer-sdk-route`, `PublishToLatestPublished` on a plain function used to deploy with nothing sent, and is now refused. These waits run under `--no-wait` too. A destroy waits for the asynchronous `DeleteFunction` before the capacity provider's delete. `cdkd drift` reads both properties back. A function already on Cloud Control stays there.
