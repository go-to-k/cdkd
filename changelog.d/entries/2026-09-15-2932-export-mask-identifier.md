- **`cdkd export` refuses a resource whose CloudFormation import identifier would be the redaction mask, whatever produced it -- and does NOT block the Cloud-Control-imported records whose masked attributes it never reads (issue [#2932](https://github.com/go-to-k/cdkd/issues/2932))** -- `src/cli/commands/export.ts` (`buildImportPlan` choke point, `resolveIdentifierValue`, `maskedIdentifierAttributeReason`), `tests/unit/cli/export-composite-identifier.test.ts`, `docs/cli-export.md`. The #2274 blocker tested `properties` only, while `CloudControlProvider.import` writes the mask into `attributes` for every model key it cannot certify read-only (#2847), and the export's two attribute-reading resolvers refused a mask only because each happens to test a prefix. The guarantee now sits where the identifier map is built: a resolved `resourceIdentifier` or overlay equal to `***` -- a masked identifier attribute, a masked physical id, a splitter or backfill answer, a future resolver without a shape test -- blocks the resource with a mask-specific reason, and a `COMPOSITE_PHYSICAL_ID_IDENTIFIERS` resolver failing on a masked `attributes.<field>` names the mask and the real remedy (re-import with `cloudformation:DescribeType`; a re-deploy re-masks) instead of "re-deploy so cdkd records it". Deliberately NOT a whole-bag test: that would make every Cloud-Control-imported record permanently unexportable, and a unit row pins that population still exports. **Behavior change:** none for records that exported before; a masked identifier that a resolver already refused gets a different message.
