- **`cdkd drift` reports `readFailed` when a property's own read fails, instead of leaving the property uncompared (issue [#6759](https://github.com/go-to-k/cdkd/issues/6759), part of [#6696](https://github.com/go-to-k/cdkd/issues/6696))** -- `src/provisioning/providers/{dynamodb-table/read-current-state,dynamodb-globaltable/read,dynamodb-globaltable/read-support,cognito/read-state,cloudfront-distribution/read-state,route53/read-state,route53/resolve,route53/record-set-group,s3-tables/read-state,s3-tables/tags,servicediscovery/read-state,appsync/read-state}.ts`. Several readbacks make an extra AWS call for one property (DynamoDB PITR / TTL / ResourcePolicy / Kinesis / Contributor Insights / stream policy and tags, GlobalTable replica settings, tags, TTL and Application Auto Scaling, Cognito MFA, CloudFront and Route 53 zone tags, Route 53 query logging, S3 Tables configuration, maintenance and tags, Cloud Map service attributes and tags, AppSync environment variables). When that call failed with anything but its own not-found code (an `AccessDenied`, a throttle), the property was left out -- or set to `[]` / `{}`, which read as a removal -- at deploy time and again at drift time, so it was never compared and the run reported no drift. That failure now fails the resource's read: `cdkd drift` reports it `readFailed` (exit 2), and a deploy records no drift baseline for it, as for any failed read. A Route 53 `RecordSet` / `RecordSetGroup` whose `HostedZoneName` listing fails, and an S3 Tables table recorded by its ARN whose `GetTable` fails, now report `readFailed` with the cause instead of drift unknown. The not-found answers keep their results, and a GlobalTable replica AWS is not serving (`CREATION_FAILED`, `REGION_DISABLED`, ...) keeps the tolerant reads.
