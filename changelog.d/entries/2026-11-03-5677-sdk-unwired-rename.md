- **The internal "silent drop" vocabulary is renamed to `sdkUnwired` (issue [#5677](https://github.com/go-to-k/cdkd/issues/5677))** -- `scripts/gen-property-coverage.ts` -> `src/provisioning/property-coverage.generated.ts` (the `PropertyCoverage.silentDrop` key is now `sdkUnwired`), `src/provisioning/property-coverage.ts` (`findSdkUnwiredProperties`, `findActionableSdkUnwired`, `withoutSdkUnwiredProperties`, `withoutUnwrittenSdkUnwiredProperties`, `withoutAcceptedSdkUnwiredProperties`), `src/provisioning/provider-registry.ts` (`reportSdkUnwiredDecisions`, `buildUnroutableSdkUnwiredMessage`), `scripts/diagnose-schema-refresh.mjs` (`parseSdkUnwiredByType`, `sdkUnwiredRemoved`), the five `*silent-drop*` unit files (now `*sdk-unwired*`), the integ env var `CDKD_INTEG_USE_SILENT_DROP` (now `CDKD_INTEG_USE_SDK_UNWIRED`), the integ fixtures that read the generated key, and prose in comments, fixtures, `docs/**` and `.claude/rules/**`. A property the SDK provider does not wire is not dropped: the resource auto-routes through Cloud Control and the value reaches AWS ([#614](https://github.com/go-to-k/cdkd/issues/614)). Where the SDK route really does not write it (`--allow-unsupported-properties` / `--prefer-sdk-route`), the prose now says "left unwritten". Places where "silent drop" means a real lost value (a nested key the serializer discards, a refusal instead of a silent drop) keep the phrase. `ProviderRegistry`, which `src/index.ts` exports, now has the library method `reportSdkUnwiredDecisions` in place of `reportSilentDropDecisions`. User-facing text was already renamed by [#5668](https://github.com/go-to-k/cdkd/issues/5668); no behavior changes.
