- **Six more resource types recorded `provisionedBy: 'cc-api'` return to their SDK provider (issue [#6454](https://github.com/go-to-k/cdkd/issues/6454), batch 4)** -- `src/provisioning/provider-registry/sticky-exempt.ts` and the new `cc-to-sdk-reroute-common-types-4` integ. `AWS::Events::EventBus`, `AWS::ServiceDiscovery::PrivateDnsNamespace`, `AWS::ServiceDiscovery::Service`, `AWS::Glue::Workflow`, `AWS::Glue::Crawler` and `AWS::ElasticLoadBalancingV2::LoadBalancer` are now `'sdk-coverage'` members of `STICKY_CC_MIGRATION_EXEMPT`. A resource of one of these types on Cloud Control moves to the SDK provider in place on the next deploy that changes it; `--pin-cc-api <LogicalId>` declines that. Both layers record the same id for each type, observed on live resources together with an identity witness, so nothing is replaced. `cdkd diff` annotates the move `[returning to SDK provider]`.
