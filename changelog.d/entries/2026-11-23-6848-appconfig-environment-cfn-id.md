- **`cdkd import --migrate-from-cloudformation` now adopts an `AWS::AppConfig::Environment` (issue [#6848](https://github.com/go-to-k/cdkd/issues/6848))** -- `src/provisioning/providers/appconfig-environment-provider.ts`, `tests/unit/provisioning/appconfig-environment-provider.test.ts`. CloudFormation reports this type's PhysicalResourceId as the bare EnvironmentId, while cdkd records `<ApplicationId>|<EnvironmentId>` and refused the bare id, so migrating (or auto-importing from a CloudFormation stack) failed for it. Import now completes a bare id with the resolved `ApplicationId` and records the composite id.
