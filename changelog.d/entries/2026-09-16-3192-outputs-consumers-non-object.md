- **`cdkd orphan`, `import` and `scrub` refuse a state record whose `outputs` bag is not an object instead of saving a rebuilt one over it, and the shared export-set predicate fails closed (issue [#3192](https://github.com/go-to-k/cdkd/issues/3192))** -- `src/types/state.ts`, `src/state/{malformed-resources-bag,export-index-store}.ts`, `src/cli/commands/{orphan,import,scrub,diff-recursive}.ts`, four `docs/` pages, `docs/design/3192-outputs-consumers.md`, cases in five suites and a new `tests/unit/state/importable-outputs-malformed.test.ts`. Sibling sweep of [#3189](https://github.com/go-to-k/cdkd/issues/3189), which guarded `cdkd diff` alone. Two WRITE paths, both confirmed by execution: `cdkd orphan` rebuilt `outputs: 'abcdef'` into `{"0":"a",..,"5":"f"}` and SAVED it (`null` laundered to `{}`), replacing the only signal the record was damaged; and a string bag published one fabricated export per character into the shared `exports.json` every consumer's `Fn::ImportValue` binds against. `cdkd scrub` and `cdkd import` launder the same record two other ways. All now REFUSE at the LOAD (`STATE_RESOURCES_MALFORMED`), naming the broken container; scrub keeps its exit-2 class and its `--dry-run` audit arm, whose finding reaches a non-zero exit so `--dry-run --fail` cannot report a clean run. A tenth site is the `exportNames` FIELD: a hand-edited non-array killed `cdkd diff` with a raw `TypeError`, and now reads as an EMPTY export set, never as the pre-v9 every-key rule that would re-open [#2193](https://github.com/go-to-k/cdkd/issues/2193)'s shadowing. Guarding both inside `importableOutputKeys` also covers the deploy resolver's state scan and the `cdkd local` loader. The exports-index rebuild drops such a producer and WARNS rather than refusing. An ABSENT `outputs` field stays exempt; a healthy or empty bag is untouched and silent. The per-site table and the five consumers left unguarded, each in a real-AWS gate scope, are in `docs/design/3192-outputs-consumers.md`.
