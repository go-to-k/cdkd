- **A CodeCommit repository update or delete now refuses a repository under the recorded name whose id is not the recorded one (issue [#4157](https://github.com/go-to-k/cdkd/issues/4157))** -- `src/provisioning/providers/codecommit-repository-provider.ts`, `src/provisioning/region-check.ts` (`DeleteContext.recordedAttributes`), `src/types/resource.ts`, and every `delete()` caller: `src/cli/commands/destroy-runner.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/rollback-executor.ts`. An update that did not rename, and `delete()`, addressed the repository by NAME alone, so after the recorded repository was deleted outside cdkd and another created under the same name, a deploy overwrote that repository's description, key, tags and triggers, and `cdkd destroy` deleted it. Both now read the repository first and compare its id with the recorded `RepositoryId`: a mismatch is refused, non-retryable, with nothing sent to it and the record kept, naming `cdkd orphan` to drop the record. A repository already gone is still a delete success, a throttled read is retried, and a read that cannot answer (a denied `GetRepository`) proceeds with the delete and reports a `codecommit-delete-repository-identity` guard. A record from before `RepositoryId` was recorded keeps the by-name update and delete. The rename path's own check is unchanged, and its remedy, like the new ones, now says a repository created again needs a `RepositoryName` no repository holds.
