- **A 1-3 character secret a parent embeds in a nested-stack `Parameters` value through a LITERAL frame (`Pin: 'port:{{resolve:...:pin::}}'`) now reaches the child's `state.json` as `port:{{resolve:...}}` instead of `port:q7` (issue [#2745](https://github.com/go-to-k/cdkd/issues/2745), its last site)** -- `src/deployment/secret-redaction.ts` (`recordNestedStackParameterExpressions`), unit tests, `tests/integration/nested-stack-secret/` (`PinParam`). The child's carry matches an inherited pair whole at any length or as a substring at/above `MIN_NEEDLE_LENGTH`; the framed value was neither. The parent's recorder now positions a MARKED copy of the row's resolved `Parameters` and records the framed value as a WHOLE-VALUE entry of the parent's own bag under five conditions: the pass certified the leaf; the value scan is silent on it; the frame's token is the map's survivor for its middle; no other parameter of the row spells the value through a different frame or without this pass's pair; no other leaf of the row would be rewritten by the entry. Every consumer (the child's carry and persist, `redactParametersForDiff`, `cdkd diff --recursive`, the rollback replay) reads it floorless through existing arms. No pair and no pin are recorded for the entry. Residuals (recorder docstring): over one middle with two tokens the CHILD gets the survivor's frame for both leaves when the frames match and plaintext for the loser when they differ (the parent record stays per leaf); the framed value is a substring needle in child resources that consumed the parameter; an over-long frame (`MAX_SKELETON_CANDIDATE_LENGTH`) sends the resource's intrinsic-sourced leaves to the value scan; a child OUTPUT carrying it re-resolves in the parent to plaintext; a child record persisted before this carry keeps the plaintext until the child is next redeployed (`cdkd scrub` cannot repair it); an `Fn::Join` / `Fn::Sub` parameter source is issue [#3062](https://github.com/go-to-k/cdkd/issues/3062).
