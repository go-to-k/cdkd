- **`--aws-emulator` no longer lets an `enforceSSL` resource policy deny every request (issue [#6574](https://github.com/go-to-k/cdkd/issues/6574))** -- `src/provisioning/emulator-secure-transport.ts`, `src/provisioning/providers/{sqs-queue,s3-bucket,sns-topic}-policy-provider.ts`, unit tests and `docs/aws-emulator.md`. AWS Emulator does not evaluate `aws:SecureTransport` (aws/aws-emulator#369), so the `Deny` statement CDK's `enforceSSL: true` emits matched every request there, and EventBridge deliveries to such a queue were dropped silently. While `--aws-emulator` is active, the `AWS::SQS::QueuePolicy`, `AWS::S3::BucketPolicy` and `AWS::SNS::TopicPolicy` providers now leave a `Deny` statement conditioned on `Bool` / `BoolIfExists` `aws:SecureTransport` = `false` out of the document they send, warning once per resource. On AWS that statement never matches an HTTPS request, so no access decision changes. The state record keeps the templated policy, so `cdkd diff` stays clean, and deploys to AWS send the document unchanged.
