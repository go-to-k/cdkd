- **The API Gateway (v1) provider masks secret-resolved values in its own log lines and failure messages (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), API Gateway slice)** -- `src/provisioning/providers/apigateway-provider.ts`; unit tests in `tests/unit/provisioning/apigateway-provider-masked-log.test.ts`. `create()` and `update()` of `AWS::ApiGateway::Account`, `Authorizer`, `Resource`, `Deployment`, `Stage` and `Method` used to write their debug and warning lines through a logger no deploy-engine mask reaches. They now route every line through the deploy's masker: the Stage name, the Method's `RestApiId` / `ResourceId` / `HttpMethod` and a Resource's old and new `PathPart` (each masked before it joins the sentence, so a secret shorter than four characters is caught too), the post-create cleanup warnings of a Stage and a Method (including the pasteable `delete-method` command), the IAM propagation retry warning and a Resource replacement's orphan warning and reason. The AWS error text a create or update failure message wraps is masked before it is joined. A Stage whose previous `StageName` in state is a secret reference or the redaction mask `***` has its recorded name masked too, including inside the stage ARN the tag lines print, which covers a rotated secret whose old plaintext is in no bag of this deploy. Apart from a secret-derived Stage name, a secret shorter than four characters embedded in AWS error text is not caught. The `delete()` path still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
