- **EMR Cluster / InstanceFleetConfig: a property removed from the template that cdkd leaves in place is now named in a warning instead of being silently dropped, and no longer issues an empty `ModifyCluster` / `ModifyInstanceFleet` (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/emr-cluster-provider.ts`, `src/provisioning/providers/emr-instance-fleet-config-provider.ts`. Both APIs keep a field they are not sent, and cdkd sends no reset for these removals. Before, removing a cluster's `StepConcurrencyLevel`, or a fleet's `ResizeSpecifications` or `InstanceTypeConfigs`, reported a successful update while AWS kept the old value, and when the removal was the only change cdkd still sent the Modify call (for a fleet, followed by a resize wait). Now the provider sends nothing for such a removal and names it in one warning per resource after a successful update, with no claim about what CloudFormation would do (both types declare `removalHandledInUpdate`, so the shared caller adds no second line). A removed fleet capacity is still sent as 0, and the cluster's other removals (`VisibleToAllUsers`, the scaling and auto-termination policies, `Tags`) are applied as before. Tests: `tests/unit/provisioning/providers/emr-cluster-provider-removal-1160.test.ts`, `tests/unit/provisioning/providers/emr-instance-fleet-config-provider-removal-1160.test.ts`.
