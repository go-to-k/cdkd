- **`cdkd drift` now reports an `AWS::S3::BucketPolicy` statement whose principal S3 shows as a bare IAM user unique id, instead of reading it as the template's CloudFront OAI grant (issue [#6854](https://github.com/go-to-k/cdkd/issues/6854))** -- `src/provisioning/providers/s3-bucket-policy-provider.ts` (`normalizeOaiPrincipals`; its OAI helpers move to the new sibling `s3-bucket-policy-oai.ts`, the provider being at the source size cap). S3 shows an OAI grant as a bare `AIDA…` id for a few seconds after the policy is written, and cdkd replaced such an id with the matching template statement's `CanonicalUser`. S3 also shows a grant to a deleted IAM user as that user's `AIDA…` id, and keeps showing it, so a statement whose principal was moved to a user who was later deleted read as the template's OAI grant and drift reported nothing. The replacement now applies only to the read that follows cdkd's own write (the deploy's baseline capture and the create path's own-leftover check). On a drift read, `cdkd state refresh-observed` or import, the id is compared as read.
