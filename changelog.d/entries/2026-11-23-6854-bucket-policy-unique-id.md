- **`cdkd drift` now reports an `AWS::S3::BucketPolicy` statement whose principal S3 shows as a bare IAM user unique id, instead of reading it as the template's CloudFront OAI grant (issue [#6854](https://github.com/go-to-k/cdkd/issues/6854))** -- `src/provisioning/providers/s3-bucket-policy-provider.ts` (`normalizeOaiPrincipals`; its OAI helpers move to the new sibling `s3-bucket-policy-oai.ts`, the provider being at the source size cap). S3 shows an OAI grant as a bare `AIDA…` id for a few seconds after the policy is written, and cdkd replaced such an id with the matching template statement's `CanonicalUser`. S3 also shows a grant to a deleted IAM user as that user's `AIDA…` id, and keeps showing it, so a statement whose principal was moved to a user who was later deleted read as the template's OAI grant and drift reported nothing. The replacement now applies only to the read that follows cdkd's own write (the deploy's baseline capture, and a create retrying over its own attempt). Any other read (drift, `cdkd state refresh-observed`, import) re-reads the policy for up to 9 s while it shows such an id, so a fresh OAI grant settles to its user ARN, and then compares what remains as read. A create treats a policy holding such an id as an earlier deploy's leftover only once a re-read shows the OAI user ARN.
