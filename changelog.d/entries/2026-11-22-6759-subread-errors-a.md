- **`cdkd drift` reports a resource not compared when one of its extra property reads fails, instead of skipping or defaulting that property (Refs [#6759](https://github.com/go-to-k/cdkd/issues/6759))** -- `src/provisioning/providers/{cloudtrail,kms,efs,ssm-parameter,logs-loggroup,lambda-eventsource,elbv2,asg}/read-state.ts`, `src/provisioning/providers/ec2/{read-instance-state,instance-ssm}.ts`, `tests/unit/provisioning/subread-errors-6759a.test.ts`. These readbacks make a second AWS call for some properties (CloudTrail logging status, selectors, Insights, tags and aggregation; KMS key policy, rotation and tags; EFS lifecycle, backup and file system policies and mount target security groups; SSM parameter metadata and tags; log group data protection and field index policies; event source mapping tags; ELBv2 capacity reservation, attributes, targets and tags; EC2 instance volume details, attributes, credit specification and SSM associations; Auto Scaling group lifecycle hooks, traffic sources and notifications) and swallowed any failure of it, an `AccessDenied` or a throttle included. The property was left out, so it was never compared, or recorded as `[]` / `''`, which reads as "none" and could report a removal for `--revert` to act on. The run said no drift. Now such a failure fails the read, so `cdkd drift` reports the resource `readFailed` and exits 2. The call's own not-found or not-configured answer behaves as before. A Gateway Load Balancer's capacity read is still best-effort, as are a non-STANDARD log group's policy reads on `InvalidParameterException`. In a deploy's post-write capture, a failed read leaves the resource with no observed baseline, as any failed capture does. That includes the `IamInstanceProfile` read of an EC2 `--no-wait` capture.
