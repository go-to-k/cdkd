- **Deleting an `AWS::DynamoDB::GlobalTable` whose local table or a cross-region replica has deletion protection on now refuses before it changes anything, instead of dropping the other regions' replicas first (issue [#6367](https://github.com/go-to-k/cdkd/issues/6367))** -- `src/provisioning/providers/dynamodb-globaltable/{delete,protection-preflight}.ts`, plus the new `globaltable-delete-protection-preflight` integ. Without `--remove-protection`, the delete removed every cross-region replica and only then sent `DeleteTable`. AWS refused that call for a protected local table, or refused a protected replica's own removal partway through, and the table was left in fewer regions than state recorded. This was reachable from `cdkd destroy` and from a replacement's delete when the protection was turned on outside the template. The delete now reads every copy's flag first, and refuses naming the protected regions. `cdkd destroy` names `--remove-protection`. A flag it cannot read (for example a missing permission) does not block the delete.
