- **`cdkd diff` no longer previews an export alias `cdkd deploy` refuses when an intrinsic `Export.Name` carries a plain `{{resolve:ssm:...}}` to a `SecureString` parameter, and no longer prints a secret's plaintext stored by an older cdkd beside, or instead of, its reference (issues [#4056](https://github.com/go-to-k/cdkd/issues/4056), [#4101](https://github.com/go-to-k/cdkd/issues/4101))** -- `src/analyzer/outputs-diff.ts`, `src/cli/commands/diff-recursive.ts`, `.claude/rules/layout-analyzer.md`, `docs/_contents/architecture.md`, `docs/_contents/cli-diff.md`. The Outputs preview refused an intrinsic alias only for a `secretsmanager:` / `ssm-secure:` spelling, but its `skipDynamicReferences` pass also keeps a plain `ssm` token for a `SecureString`, so the alias the deploy refuses was an `[export]` ADD on every run and `cdkd diff --fail` never went green. A surviving token of a service the deploy resolves now refuses the alias; another service's token still publishes. The legacy-record check reads that token too, so a record from before issue #1901 holding a `SecureString`'s plaintext is withheld instead of printed as a MODIFY row's `old:` side. A stored secret token now excuses its key only as one whole token or under exactly the desired value's literal text, never beside other text: an older deploy stored `{{resolve:secretsmanager:A}}-<plaintext>` for a joined reference, and the plaintext printed; the same shape rule decides whether a stored value proves the record redacted, and a value failing it is withheld per key whatever else the record holds; the no-change merge preview takes a whole token only. Fail-closed cost: when the text beside a secret reference changes (even a public parameter's value) or that output is condition-skipped, previous values are withheld until the next deploy. Tests: `tests/unit/analyzer/outputs-diff-ssm-export-name-4056.test.ts`, `tests/unit/analyzer/outputs-diff.test.ts`, `tests/unit/cli/diff-recursive.test.ts`.
