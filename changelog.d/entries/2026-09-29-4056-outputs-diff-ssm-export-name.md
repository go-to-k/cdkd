- **`cdkd diff` no longer previews an export alias that `cdkd deploy` refuses when an intrinsic `Export.Name` carries a plain `{{resolve:ssm:...}}` reference to a `SecureString` parameter, and no longer prints such a parameter's plaintext from a record an older binary wrote (issue [#4056](https://github.com/go-to-k/cdkd/issues/4056))** -- `src/analyzer/outputs-diff.ts`, `.claude/rules/layout-analyzer.md`. The Outputs preview refused an intrinsic alias only for a `secretsmanager:` / `ssm-secure:` spelling, but its `skipDynamicReferences` pass also keeps a plain `ssm` token for a `SecureString` (a `String` parameter resolves to its value). The alias the deploy refuses was previewed as an `[export]` ADD on every run, so `cdkd diff --fail` never went green. A surviving token of a service the deploy resolves (`secretsmanager`, `ssm`, `ssm-secure`) now refuses the alias; a token of any other service is left as written on both paths and still publishes. The same reading now applies to the legacy-record check: a record from before issue #1901 that stored a `SecureString`'s plaintext is withheld like a `secretsmanager` one instead of printing it as the `old:` side of a MODIFY row, and a stored `ssm` token is read as that output's expression -- when it is the whole stored value or sits under the resolved value's literal text, never beside text that may be plaintext -- so a current record keeps its previous values, in the no-change merge preview too (`src/cli/commands/diff-recursive.ts`). The raw-template and stored-bag signals keep the spelling-only rule. Tests: `tests/unit/analyzer/outputs-diff-ssm-export-name-4056.test.ts`, `tests/unit/analyzer/outputs-diff.test.ts`.
