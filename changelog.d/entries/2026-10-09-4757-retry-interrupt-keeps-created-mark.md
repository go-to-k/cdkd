- **A `--no-rollback` deploy that stops while a create waits to retry now still records the resource that create made (issue [#4757](https://github.com/go-to-k/cdkd/issues/4757))** -- `src/deployment/retry.ts`. When a resource's create call succeeded at AWS and a later step of the same create failed with an error cdkd retries (a permission or throttling error, say), and another resource then failed and stopped the deploy while this one was waiting to retry, the failed CREATE was journaled without the resource's id. `cdkd rollback --revert-failed`, `cdkd destroy` and a fix-forward deploy then had nothing to act on, and the resource stayed in AWS untracked. The stop now keeps the record of what the create made, so the journal names the resource as it does when the retry runs. Tests: `tests/unit/deployment/retry-interrupt-carries-created-mark-4757.test.ts`, `tests/unit/deployment/deploy-engine-rollback-journal.test.ts`.
