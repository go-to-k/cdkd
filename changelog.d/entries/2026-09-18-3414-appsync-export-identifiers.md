- **`cdkd export` resolves the AppSync identifiers AWS re-declared in September 2026, and `cdkd import` records a GraphQL API's `Arn` (issue [#3414](https://github.com/go-to-k/cdkd/issues/3414))** -- `src/cli/commands/export.ts`, `src/provisioning/providers/appsync-provider.ts`. AWS moved `AWS::AppSync::GraphQLApi`'s `primaryIdentifier` from `ApiId` to `Arn` (issue #3327), and re-published `AWS::AppSync::ApiKey` as `FULLY_MUTABLE` with a read handler and the composite `[ApiId, ApiKeyId]` where it had been the single `ApiKeyId`. Before: the API took the single-key path and shipped its bare `apiId` to CloudFormation IMPORT as `Arn`, which the changeset rejects; the key, no longer refused by the IMPORT pre-flight, hit the `add an entry to COMPOSITE_ID_SPLITTERS` throw and aborted the whole export. After: the API is a `COMPOSITE_PHYSICAL_ID_IDENTIFIERS` member resolved from the `Arn` attribute `create()` records (empty overlay, `Arn` is read-only), tolerating a registry that still reports `ApiId` via the new `physicalIdIsIdentifierFor` field -- cdkd's physicalId IS that value, so the plain single-key path is taken rather than a schema-change refusal; the key has a splitter decoding `<apiId>|<apiKeyId>`, the key ARN, and a bare pre-flip `<apiKeyId>` (parent from `properties.ApiId`), overlay narrowed to `ApiId`. `AppSyncProvider.import` now records `ApiId` / `Arn` / `GraphQLUrl` for an adopted API (it recorded `attributes: {}`, which blocked that API's export until its next update). Live: the `export` fixture gained a GraphQL API + key and pins both plan lines and CloudFormation's post-IMPORT `PhysicalResourceId`s; the `appsync` fixture asserts an `export --dry-run` names `AWS::AppSync::GraphQLSchema` (still no read handler) as the ONLY blocker. No flag, dependency or state-schema change.
