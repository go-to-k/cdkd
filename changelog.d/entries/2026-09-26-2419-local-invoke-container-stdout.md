- **`cdkd local invoke` and `cdkd local invoke-agentcore` no longer put the container's own stdout ahead of the response payload (issue [#2419](https://github.com/go-to-k/cdkd/issues/2419))** -- `src/local/docker-runner.ts`, doc comments in `src/cli/commands/local-invoke.ts`, `src/cli/commands/local-invoke-agentcore.ts` and `src/utils/logger.ts`, `docs/local-invoke.md`, `docs/local-invoke-agentcore.md`, `docs/cli-reference.md`, the `local-invoke` integ fixture, and unit tests. The Lambda runtime emulator puts `START` / `END` / `REPORT` and every handler log line, `console.error` included, on the container's stdout, and `streamLogs` piped that straight into cdkd's stdout, so `cdkd local invoke MyStack/Fn | jq` failed on any handler that printed. The container's stdout now follows the same stdout reservation that already routes cdkd's own logger and `docker pull` progress: on these two commands it joins the container's stderr on cdkd's stderr, moved rather than dropped. `cdkd local start-api`, `local run-task` and `local start-service` reserve nothing, so their stdout still carries the container logs as before. A ZIP Lambda's stdout is now the payload alone; a container-image target cdkd builds still prints `Building container image (platform=...)` on stdout, so `| tail -1` is still needed there ([#2429](https://github.com/go-to-k/cdkd/issues/2429)).
