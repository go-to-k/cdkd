- **A failed Lambda function or Kinesis stream update now records what it had already started, so the next deploy converges it (issue [#5487](https://github.com/go-to-k/cdkd/issues/5487))** -- `src/provisioning/providers/{lambda-function,kinesis}-provider.ts`, `src/deployment/unsettled-convergence.ts`. Both providers now mark each property just before the call that changes it (`UpdateContext.markUnsettled`, from #5380), so an update that fails part way (the `LastUpdateStatus` / `UPDATING` wait, the per-resource deadline, Ctrl-C, or a later call) records the property as unsettled instead of leaving the old value in state. Before this, a deploy back to the recorded template diffed empty and the resource kept the half-applied value. Before the removal step, the next deploy replaces each unsettled property's previous value with what AWS holds now (`src/deployment/unsettled-convergence.ts`, used by deploy, rollback reverts and `drift --revert`), so the provider sends only what differs (Kinesis refuses same-value calls) and a property AWS gained but no template declares is reset. A property AWS is still changing refuses the update, `Tags` keep CloudFormation's merge semantics, and a name clears only once AWS shows the template's value. `cdkd drift --accept` / `--revert` keep a property while the function reads `InProgress` / `Pending` or the stream reads `UPDATING`.
