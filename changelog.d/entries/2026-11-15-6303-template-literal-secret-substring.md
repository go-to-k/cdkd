- **A short secret value inside an ordinary template string no longer turns that string into a `{{resolve:...}}` reference in state, so an Aurora PostgreSQL cluster with CDK's default username `postgres` no longer plans a replacement (issue [#6303](https://github.com/go-to-k/cdkd/issues/6303))** -- `src/deployment/secret-redaction/redact-path/template-literal.ts`, `redact-path.ts`, `rules.ts`, `redact-state/scrub-record.ts`, `src/deployment/deploy-engine/update/compare-record.ts`, `src/cli/commands/scrub/stack-rewrite.ts`. The state redaction replaced every occurrence of a resolved secret's text, so `Engine: aurora-postgresql` was stored as `aurora-{{resolve:secretsmanager:...:username::}}ql`, and the next `cdkd diff` / `cdkd deploy` reported `Engine: [requires replacement]`. A value that is exactly the template's own string is now stored as written; positions the template fills from a reference, and a template string equal to a secret value, still store the reference. `cdkd scrub` no longer re-scans the properties it has just matched to the template. **Already-affected state:** an unchanged-template `cdkd deploy` repairs it without sending anything to AWS, and `cdkd scrub` repairs it without a deploy; `cdkd diff` keeps reporting the change until one of them runs. `cdkd state refresh-observed`, `cdkd import` and `cdkd drift --accept` check the AWS readback against the record, not the template, so they can still write the old spelling into `observedProperties` (not `properties`, and `cdkd drift` shows no drift); `cdkd scrub` puts it back. Tests: `tests/unit/deployment/secret-redaction-template-literal-6303.test.ts`, `deploy-engine-template-literal-legacy-repair-6303.test.ts`, `tests/unit/cli/commands/scrub-template-literal-6303.test.ts`; integ `secret-substring-literal`.
