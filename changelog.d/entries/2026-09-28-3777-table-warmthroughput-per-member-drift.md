- **`cdkd drift` no longer compares an `AWS::DynamoDB::Table` `WarmThroughput` member cdkd never sent (issue [#3777](https://github.com/go-to-k/cdkd/issues/3777))** -- `src/provisioning/providers/dynamodb-table-provider.ts` (`readCurrentState`, `reverseMapSecondaryIndex`, new `canonicalizeDriftPair`), with unit tests in `tests/unit/provisioning/dynamodb-table-provider-warm-throughput-per-member.test.ts` and a `dynamodb-gsi-update` integ phase. A declared `WarmThroughput` with one usable member (`{ReadUnitsPerSecond: 6000}`, or a second member that does not resolve to a number) sends only that member, but the readback emitted AWS's value for both, so the unsent member was reported as drift against the template, or against a captured value once AWS raised it. The readback now emits only the members cdkd sends, table-level and per GSI; a member recorded as a `{{resolve:...}}` reference counts as sent. A drift baseline that still carries the unsent member, such as one captured by an earlier cdkd, is trimmed to the members the template sends before comparing, so an untouched table compares clean after upgrading. A change to a member cdkd sends is still reported, and a block that declares both members is compared in full as before.
