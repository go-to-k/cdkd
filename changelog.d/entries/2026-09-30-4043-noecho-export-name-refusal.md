- **`cdkd deploy` refuses an `Export.Name` that equals or embeds a `NoEcho: true` parameter's value (issue [#4043](https://github.com/go-to-k/cdkd/issues/4043))** -- `src/deployment/outputs-export-alias.ts` (`exportNameSecretExposure`), `src/analyzer/outputs-diff.ts`, `src/cli/commands/diff-recursive.ts`. Before, such a name was published as a key of `state.outputs`, `exportNames` and the exports index, so the value sat in plaintext where any stack's reader could list it; a key cannot be masked. Now the alias is skipped with the same warning as a secret-bearing name, the value masked or the name withheld, and the next deploy that re-resolves the outputs drops an alias an earlier deploy published: a consumer's `Fn::ImportValue` on that name stops resolving, a deliberate CloudFormation-parity divergence. The value counts when an output value, or the `Export.Name` of the same or an earlier-declared output, reads it through a `Ref` or `Fn::Sub`. The name is refused when it equals the value, or contains it at 4 or more characters, full-width and other NFKC spellings included. `cdkd diff` previews the same verdict, so the refused alias is no phantom addition. Still published: a value only a resource or a later `Export.Name` reads, one reaching the name through an attribute, an import or an `Fn::Select` fragment, a 1-3 character value inside a longer name, and a failed output's alias carried forward by a deploy with no resource change. Earlier versions of `state.json` and of the exports index keep a previously published value; rotate it.
