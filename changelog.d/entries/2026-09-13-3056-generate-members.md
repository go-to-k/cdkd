- **A malformed MEMBER of `GenerateSecretString` is refused on create and SKIPPED on update, instead of minting a wrong secret or throwing (issue [#3056](https://github.com/go-to-k/cdkd/issues/3056))** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`, `src/provisioning/config-shape.ts`, `tests/unit/provisioning/secretsmanager-secret-provider-update-value-source.test.ts`. The container half shipped in [#3048](https://github.com/go-to-k/cdkd/issues/3048); its members were still read by cast. **Bug:** `PasswordLength: 'abc'` (truthy) reached `new Uint8Array('abc')` and minted an EMPTY password; `ExcludePunctuation: 'false'` (truthy) EXCLUDED punctuation; a `SecretStringTemplate` that did not parse fell into a `catch` and the bare password went out RAW where the template declared a JSON document -- as the new `AWSCURRENT`, silently; and `ExcludeCharacters: null` THREW from `update()`, the #1544 hazard one level below the container. **Fix:** every member is read through the shared `config-shape.ts` predicate for its type -- the new `configIntegerRefusal` / `coerceCfnInteger` pair for `PasswordLength` (a CFn `"32"` coerces; `0` / `3.5` / `'abc'` / `null` refuse), `configBooleanRefusal` + `coerceCfnBoolean` for the four `Exclude*` flags (`"true"` / `"false"` coerce), `configStringRefusal` for `ExcludeCharacters` / `GenerateStringKey` / `SecretStringTemplate` -- plus a PAIR rule: key and template are declared together or not at all, and the template must parse to a JSON object. On the create path a refusal throws (template-borne); on the update path `generateSecretString` hands the message to the same `onUnusable` skip the container takes, so the value is SKIPPED, announced once, and the previously-applied block is retained via `effectiveProperties`. Two schema members the local recipe never reads, `IncludeSpace` and `RequireEachIncludedType`, are a fidelity gap tracked as [#3068](https://github.com/go-to-k/cdkd/issues/3068).
