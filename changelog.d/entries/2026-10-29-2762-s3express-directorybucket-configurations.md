- **`AWS::S3Express::DirectoryBucket` keeps the SDK route for `BucketEncryption`, `LifecycleConfiguration`, `MetricsConfigurations` and `InventoryConfigurations` (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762)).** A directory bucket declaring any of them used to go through Cloud Control. They are now sent with the S3 bucket-configuration calls right after `CreateBucket`, and converged on update: a changed configuration is put again, a configuration removed from the template is deleted (removed encryption returns the bucket to SSE-S3), and each metrics or inventory configuration is put or deleted by its own `Id` (one already gone counts as deleted, so a retried update does not fail on it). An update that fails after one of these writes went through leaves that property unsettled, so the next deploy converges it. All four are read back for `cdkd drift`. A malformed value is refused before any call. When a configuration write fails after the bucket was created, the bucket is recorded for `cdkd rollback --revert-failed`. Deploying them needs the `s3express:Put*Configuration` permissions for each, and reading them back needs `s3express:GetEncryptionConfiguration`, `s3express:GetLifecycleConfiguration`, `s3express:GetMetricsConfiguration` and `s3express:GetInventoryConfiguration`; `cdkd drift` of a directory bucket by a role without them now fails with an error naming the missing action. Source: `src/provisioning/providers/s3-directory-bucket-provider.ts`.
