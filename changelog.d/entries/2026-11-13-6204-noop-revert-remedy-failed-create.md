- **A failed CREATE with no physical id no longer advises `--revert-failed` (issue [#6204](https://github.com/go-to-k/cdkd/issues/6204))** -- `src/deployment/deploy-engine/rollback/applied-nothing.ts`, `src/deployment/deploy-engine/rollback/settle.ts`, `src/deployment/deploy-engine/execute/rollback-after-failure.ts` and `src/deployment/deploy-engine/deploy-flow/journal-at-start.ts`. Before, when a CREATE failed without recording a physical id (for example a custom resource whose handler threw), the automatic rollback printed `Revert it with: cdkd rollback <stack> --revert-failed`, and the next deploy printed the same command in its "A previous deploy ... failed" note. That revert can only skip such an operation, so it did nothing and ended in a `PartialFailureError`. When every kept failed operation is one the revert would only skip, neither the command nor the next-deploy note is printed; instead the deploy names the manual check the revert itself gives (`if it was partially created in AWS, delete it manually`). A failed DELETE (its resource is still in place, so the revert also only skips it) is treated the same way. A failed CREATE the revert can act on (a recorded or recovered physical id, or an abandoned Cloud Control request) still gets the command. The record itself is still journaled, as before.
