- **A CloudFront distribution origin's `OriginHttpVersion`, and a Route 53 hosted zone's `HostedZoneConfig.HostedZoneTier` or `HostedZoneFeatures.ChangeGuardrails` / `ChangeHistory` / `EnablePublicDNSFallback`, now reach AWS instead of being silently dropped (PR [#6690](https://github.com/go-to-k/cdkd/pull/6690))** -- `src/provisioning/sdk-unmodelled-nested-paths.ts` (new), `src/provisioning/property-coverage.ts` (`findValueRoutedProperties`), `src/provisioning/provider-registry/report.ts`. The AWS SDK clients, the latest 3.1173.0 included, do not model these nested members yet, so the SDK provider deployed such a template "successfully" without them. A resource whose properties carry one now routes through Cloud Control, which forwards the full property map, and the deploy says why (`routing via Cloud Control API (<property>: <path> is not modelled by the AWS SDK client ...)`); `--prefer-sdk-route <Type>:<Property>` keeps the old behavior. An existing SDK-provisioned resource moves on the deploy that adds the member, on the same physical id; once the member is gone from both the template and the record, the next change returns it to the SDK provider. The same report now also names the reason for the `aws-cn` cross-region read-replica route (#5640), which it did not print before. Integ: `sdk-unmodelled-nested-route`.
