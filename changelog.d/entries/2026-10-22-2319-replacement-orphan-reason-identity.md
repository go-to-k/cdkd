- **A failed IAM role, IAM managed policy, Budgets budget or Lambda network connector create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/iam-role-provider.ts`, `iam-managed-policy-provider.ts`, `budgets-budget-provider.ts`, `lambda-network-connector-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (`AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, masked through the operation's secret masker where the provider has one. This also covers the `partial` reason a renamed IAM role or managed policy records when the old one could not be deleted, the budget `Arn` attribute read, and a network connector that AWS reports as FAILED, update Failed or DELETE_FAILED: its status reason stays out of the message, which names the reason code instead. A cdkd-authored or transport error keeps its text. The AWS error stays as the `cause`, so an IAM grant that is still propagating is retried as before, a role or policy name that is taken still reads as a name collision, and a role already gone at delete time still reads as not found.
