- **`cdkd diff` previews a rollback-orphan adoption, and `cdkd scrub` scans the records** (issue [#2943](https://github.com/go-to-k/cdkd/issues/2943)). Both commands were blind to `StackState.orphans`, the field [#2934](https://github.com/go-to-k/cdkd/issues/2934) added. Design rationale — why the preview renders before reporting a refusal, why the scrub needles are a union of two sources, and the residual neither covers — in [docs/design/2943-diff-scrub-orphan-records.md](https://github.com/go-to-k/cdkd/blob/main/docs/design/2943-diff-scrub-orphan-records.md).
  - **`cdkd diff`** ran no adoption pre-pass, so it reported a CREATE for a resource `cdkd deploy` re-adopts and UPDATES. It now runs the same pre-pass, at the same point (after condition pruning, before the diff), at every node including nested children. An adopted row is annotated `[adopted from a rollback orphan]`. It does not mutate the state record it is handed.
  - **New exit code `3`**: the preview completed AND `cdkd deploy` would refuse to start. Reasons print under `Blocking (cdkd deploy will refuse):` after the full preview. Distinct from `--fail`'s `1` and from `2`. `--json` gains `blocking` and `adoptedOrphans` per node.
  - **`cdkd scrub`** walked `resources` and `outputs` only, so `No plaintext secrets found` was silent about a field carrying a whole `ResourceState`, and `orphans` rode the persist spread unscrubbed. It now derives needles per record from the record's own `{{resolve:...}}` expressions, unioned with every secret the run learned elsewhere, and writes the scrubbed records back.
  - `readSiblingPhysicalIds` moved from a private `DeployEngine` method to `makeSiblingClaimReader` in `src/deployment/orphan-adoption.ts`, shared by both commands.
  - Changed: `src/cli/commands/{diff,diff-recursive,scrub}.ts`, `src/deployment/{orphan-adoption,deploy-engine}.ts`. Docs: `docs/cli-{diff,scrub,reference}.md`.
