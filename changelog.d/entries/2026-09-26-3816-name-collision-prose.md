- **A create failure whose message quotes "already exists" from a template value no longer deletes a resource as if it were a name collision (issue [#3816](https://github.com/go-to-k/cdkd/issues/3816))** -- `src/deployment/retryable-errors.ts` (`isNameCollisionErrorFrom`), `.claude/rules/name-collision-classification.md`, with unit tests in `tests/unit/deployment/retryable-errors.test.ts` and `tests/unit/deployment/rollback-executor-name-collision-route.test.ts` and shared fixtures in `tests/unit/_aws-sdk-error.ts`. The collision classifier read the "already exists" phrase in any top-level error message. A cdkd refusal that quotes a property value carrying it therefore sent the rollback's reverse replacement to delete the live NEW resource first, with no flag, and sent `--replace` to delete the old one before a re-create that failed the same way. The phrase is now credited only when an AWS SDK error in the cause chain states it AND the top-level message relays it, so a provider that rewords a collision it knows a delete cannot clear (Glue's occupied table name) stays unclassified. The async Cloud Control collision is now read from its `AlreadyExists` handler code rather than its text. A thrown string or non-`Error` value no longer classifies. An AWS error that echoes a template value carrying the phrase still does.
