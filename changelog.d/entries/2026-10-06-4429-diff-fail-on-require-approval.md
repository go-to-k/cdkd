- **`cdkd diff --fail-on` and `cdkd deploy --require-approval`, ported from the AWS CDK CLI (issue [#4429](https://github.com/go-to-k/cdkd/issues/4429))** -- `src/analyzer/destructive-changes.ts` (new), `src/deployment/deployment-approval.ts` (new), `src/cli/commands/{diff,diff-recursive,deploy,require-approval,confirm-prompt,prefix-migration-check}.ts`, `src/cli/config-loader.ts`, `src/deployment/deploy-engine/{options,deploy-flow}.ts`, `src/deployment/resource-deadline.ts`, `src/utils/live-renderer.ts`. Port of aws/aws-cdk-cli#2020, #2011 and #2021. `cdkd diff --fail-on=never|any-change|destructive` picks which change exits 1; `--fail` / `--no-fail` alias `any-change` / `never`, combining either with `--fail-on` or repeating it is refused, default `never`. `destructive` fails only on a replacement (`will` / `may be replaced`), deletion or orphaning (`Retain` / `RetainExceptOnCreate` removal), always walks nested stacks, and lists them; `--json` carries `destructiveChanges` per stack. `cdkd deploy --require-approval=never|any-change|destructive` (also `requireApproval` in cdk.json, default `never`) asks after the diff and before any provider call, counts a `--recreate-via-*` target as a replacement, fails without a terminal unless `--yes`, and serializes prompts across parallel stacks (the prefix-migration prompt too). A nested stack asks when its row is reached, with the row's `--resource-timeout` paused meanwhile. CDK's `broadening` is not offered (no security diff); cdk.json's `broadening` is ignored with a warning. Tests: `tests/unit/analyzer/destructive-changes.test.ts`, `tests/unit/cli/{diff-fail-on,require-approval}.test.ts`, `tests/unit/deployment/{deployment-approval,deploy-engine-require-approval,resource-deadline}.test.ts`; integ `diff-fail-on-destructive`.
