- **`cdkd diff --fail-on` and `cdkd deploy --require-approval`, ported from the AWS CDK CLI (issue [#4429](https://github.com/go-to-k/cdkd/issues/4429))** -- `src/analyzer/destructive-changes.ts` (new), `src/cli/commands/{diff,diff-recursive,deploy,require-approval}.ts`, `src/cli/config-loader.ts`, `src/deployment/deploy-engine/{options,deploy-flow}.ts`, `src/utils/live-renderer.ts`. Port of aws/aws-cdk-cli#2020, #2011 and #2021. `cdkd diff --fail-on=never|any-change|destructive` picks which change exits 1; `--fail` / `--no-fail` are aliases for `any-change` / `never`, combining either with `--fail-on` or repeating `--fail-on` is refused, and the default stays `never`. `destructive` fails only on a replacement (`will` / `may be replaced`), a deletion or an orphaning (`DeletionPolicy: Retain` / `RetainExceptOnCreate` removal), nested stacks included under `--recursive`, and lists them; `--json` carries `destructiveChanges` per stack. `cdkd deploy --require-approval=never|any-change|destructive` (also `requireApproval` in cdk.json, default `never`) asks after the diff and before any provider call, lists the destructive changes, serializes prompts across parallel stacks, fails without a terminal unless `--yes`, and a nested stack asks for its own changes. CDK's `broadening` is not offered (cdkd has no security diff); cdk.json's `broadening` is ignored with a warning. Tests: `tests/unit/analyzer/destructive-changes.test.ts`, `tests/unit/cli/{diff-fail-on,require-approval}.test.ts`, `tests/unit/deployment/deploy-engine-require-approval.test.ts`.
