- **`AWS::DynamoDB::Table` now REFUSES a per-GSI `OnDemandThroughput` on a PROVISIONED table before any call, and REMOVES a dropped ceiling at both of the property's positions (issues [#3392](https://github.com/go-to-k/cdkd/issues/3392) and [#3373](https://github.com/go-to-k/cdkd/issues/3373))** -- `src/provisioning/providers/dynamodb-table-provider.ts`. DynamoDB accepts `OnDemandThroughput` only on a PAY_PER_REQUEST table, and `applyGsiUpdates`' THREE per-index send sites all ride one `GlobalSecondaryIndexUpdates` array -- so AWS rejected the whole request, took a co-resident capacity edit with it, AFTER the flip had landed. `update()` now walks `GlobalSecondaryIndexes[]` pre-flight and throws, naming every offending index. The gate reads the EFFECTIVE mode (`billingOrThroughputChanged ? billingMode : liveBillingMode`): the desired mode alone falsely refuses a live on-demand table omitting `BillingMode`, and falsely accepts a live PROVISIONED one whose record says PAY_PER_REQUEST. It downgrades to a warning when the desired bag is not template-borne (`replayingState` / `desiredFromAwsReadback`): unlike the table-level twin, a VALID record can carry this shape. BEHAVIOUR CHANGE: a PROVISIONED table carrying an UNCHANGED per-index ceiling used to deploy green and now fails pre-flight. Separately, an absent member used to KEEP whatever maximum the table carried, so dropping a ceiling deployed green and was recorded as applied while the live maximum stayed in force forever; cdkd now sends `-1`, the reset sentinel, PER MEMBER, at the table level AND per index. It fires only for a member the record holds in a spelling cdkd SENT, that the template does not declare raw (so a rejected spelling cannot clear the ceiling it was setting), that `DescribeTable` OBSERVES live, and only when this update does not flip to PROVISIONED (the snapshot predates the flip). `-1` is live-verified at both positions (#1434; #1423 plus PR #1433 at `UpdateGlobalSecondaryIndexAction`).
