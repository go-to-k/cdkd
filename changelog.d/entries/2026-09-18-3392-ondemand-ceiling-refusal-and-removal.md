- **`AWS::DynamoDB::Table` now REFUSES a per-GSI `OnDemandThroughput` on a PROVISIONED table before any call, and REMOVES a dropped ceiling at both of the property's positions (issues [#3392](https://github.com/go-to-k/cdkd/issues/3392) and [#3373](https://github.com/go-to-k/cdkd/issues/3373))** -- `src/provisioning/providers/dynamodb-table-provider.ts`. DynamoDB accepts `OnDemandThroughput` only on a PAY_PER_REQUEST table, and `applyGsiUpdates`' THREE per-index send sites all ride one `GlobalSecondaryIndexUpdates` array -- so AWS rejected the whole request, took a co-resident capacity edit with it, and did so AFTER the BillingMode flip had landed. `update()` now walks `GlobalSecondaryIndexes[]` pre-flight and throws, naming every offending index. The gate reads the EFFECTIVE mode (`billingOrThroughputChanged ? billingMode : liveBillingMode`): the desired mode alone falsely refuses a live on-demand table whose template omits `BillingMode`, and falsely accepts a live PROVISIONED table whose record says PAY_PER_REQUEST. Under `UpdateContext.replayingState` it downgrades to a warning: unlike the table-level twin, a VALID record can carry this shape. BEHAVIOUR CHANGE: a PROVISIONED table carrying an UNCHANGED per-index ceiling used to deploy green and now fails at pre-flight. Separately, an absent member used to KEEP whatever maximum the table already carried, so dropping a ceiling deployed green and was recorded as applied while the live maximum stayed in force forever; cdkd now sends `-1`, DynamoDB's reset sentinel, PER MEMBER, at the table level AND per index. It fires only for a member the record holds in a spelling cdkd actually SENT, that the template does not declare raw (so a rejected spelling cannot clear the ceiling it was setting), and that `DescribeTable` OBSERVES live -- the last also keeping a doomed `-1` off a PROVISIONED table. `-1` is live-verified at both positions (#1434, and #1423's probe of `UpdateGlobalSecondaryIndexAction`).
