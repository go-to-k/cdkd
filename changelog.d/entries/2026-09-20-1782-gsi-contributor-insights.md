- **`AWS::DynamoDB::Table`: a GSI's per-index `ContributorInsightsSpecification` is now applied and read back, instead of being dropped on the wire (issue [#1782](https://github.com/go-to-k/cdkd/issues/1782))** -- `dynamodb-table-provider.ts`, new `dynamodb-contributor-insights.ts`. The SDK's `GlobalSecondaryIndex` has no such member, so a template asking for per-index Contributor Insights deployed green with the feature OFF, with no drift read-back. **Write:** once the index is ACTIVE, cdkd calls `UpdateContributorInsights` with `IndexName` for each index whose block changed (at create, index added, `Enabled` flip, `Mode` change). A block REMOVED from an index that stays is DISABLED (the rule the table-level block already follows); an index the update removes gets no call. A rollback restores the previous setting. **Read:** `cdkd drift` issues one `DescribeContributorInsights` per index, ONLY for an index whose template entry declares the block, and reports `Mode` only when the template declares one, so an undeclared index and AWS's default mode are never phantom drift. `ENABLING` / `DISABLING` read as their target (the deploy does not wait for the toggle); `FAILED` or a failed read omits the block. An out-of-band toggle of a declared index is reported as `GlobalSecondaryIndexes` drift and `drift --revert` undoes it. **Also fixed, table level:** the block is now read by the same reader, so `Enabled: 'false'` (a CloudFormation-legal string) no longer ENABLES the feature, and an unreadable block (either level) is refused before `CreateTable` and, on an update, announced and left alone -- never read as a default. **Also:** `GlobalSecondaryIndexes` / `LocalSecondaryIndexes` are now compared as unordered sets (leaf-only, so each index's `KeySchema` stays order-significant). Real AWS returned a `[giA, giB]` template as `[giB, giA]`, which a `properties` baseline reported as whole-list drift; the phantom pre-dates this change.
