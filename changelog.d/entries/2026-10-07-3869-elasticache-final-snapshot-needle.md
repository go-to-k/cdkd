- **`cdkd deploy` masks an ElastiCache final-snapshot name cut from a secret-derived id (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/secret-name-needles.ts`, `src/provisioning/final-snapshot.ts`. A final-snapshot name for an ElastiCache cache cluster or replication group keeps only the first 28 characters of the physical id. When the id was judged from plaintext, the masker had only the whole id or the secret as needles. Those plaintexts are a name resolved this deploy, a `NoEcho` parameter value, or a secret embedded in the id. If one of them ran past character 28, the snapshot name held only a fragment of it. No needle matched that fragment, so the fragment printed in the clear. That covers the `Creating final snapshot` and `ready` lines of a template-removal or replacement delete, and AWS's `SnapshotAlreadyExistsFault` text quoting the name. The derived-name judge now adds the snapshot's `<base>-final-` prefix as a needle whenever the cut splits one of its needles, and, for any snapshot-capable type, the folded spelling (lowercased, outside characters mapped to `-`) of a needle the base folds but carries whole. A state record still spelling a `{{resolve:` reference already had this prefix. Tests: `tests/unit/deployment/derived-name-needle-3869.test.ts`, `tests/unit/provisioning/final-snapshot.test.ts`. The `noecho-parameter-masking` integ gains Phases 4a and 4b: a replication group named `rg-<NoEcho value>` under `DeletionPolicy: Snapshot` is removed, and its snapshot line must print no fragment of the name.
