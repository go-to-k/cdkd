- **IAM ManagedPolicy, InstanceProfile, User and UserToGroupAddition refuse a principal list that is not a list of IAM names before any call (issues [#3906](https://github.com/go-to-k/cdkd/issues/3906), [#3888](https://github.com/go-to-k/cdkd/issues/3888))** -- `src/provisioning/iam-policy-targets.ts`, `src/provisioning/providers/iam-managed-policy-provider.ts`, `iam-instance-profile-provider.ts`, `iam-user-group-provider.ts`, with unit tests in `tests/unit/provisioning/iam-principal-list-shape.test.ts`. `AWS::IAM::ManagedPolicy` `Groups` / `Roles` / `Users`, `AWS::IAM::InstanceProfile` `Roles`, `AWS::IAM::User` `Groups` and `AWS::IAM::UserToGroupAddition` `Users` were cast and iterated, so a string was walked by character. A rollback revert or `cdkd drift --revert`, whose desired side is a recorded bag, attached a managed policy to one-letter principals or swapped an instance profile's role for a one-letter one. A delete removed one-letter users from a group and never the recorded one. Each list is now read through the shared reader `AWS::IAM::Policy` uses. On create and update, a malformed desired or recorded list throws with no AWS call, bar the secret-derived recorded list below. On a UserToGroupAddition delete it is skipped, keeping the record. A recorded list holding a dynamic reference or its mask cannot be repaired in state, so with a well-formed desired side that kind is read from IAM instead: ADD-only for ManagedPolicy and User (IAM's list also holds attachments made elsewhere, so nothing is removed on its evidence; a warning names the kind when IAM lists a principal the template does not), a full diff for InstanceProfile, whose roles only the profile sets. UserToGroupAddition has no live source and names its way out, never a `state.json` edit.
