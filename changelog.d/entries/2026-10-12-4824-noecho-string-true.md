- **A template parameter declared `NoEcho: "true"` (the string form) is masked like `NoEcho: true` (issue [#4824](https://github.com/go-to-k/cdkd/issues/4824))** -- `src/deployment/noecho-declared.ts` (new), `src/deployment/intrinsic-resolver/parameter-secrets.ts`, `src/deployment/deploy-engine/{masking,noecho}.ts`, `src/deployment/outputs-export-alias/secret-scan.ts`, `src/deployment/condition-verdicts.ts`, `src/deployment/masked-property-fingerprints.ts`, `src/deployment/noecho-delete-reresolution.ts`, `src/deployment/intrinsic-resolver/support.ts`, `src/analyzer/skipped-outputs.ts`, `src/cli/commands/import-deployed-parameters.ts`. CloudFormation accepts the string as well as the boolean, as a hand-written template or one brought in with `CfnInclude` spells it. Several readers tested only the boolean. With the string form, the value printed on `cdkd deploy`'s log lines (the resolver's `--verbose` lines, the diff's lines), was missing from the value needle, so a copy no template position marks was persisted unmasked, and was not seen by the export-name secret scan. It also fed a recorded condition verdict and the skipped-output digest. Every reader now asks one predicate, `isNoEchoDeclared`, which accepts the boolean and the string `"true"` in any case. Tests: `tests/unit/deployment/noecho-string-form-4824.test.ts`. Integ: `noecho-parameter-masking` declares a parameter with the string form and fails when its value reaches the deploy or diff logs or state.
