- **A template parameter declared `NoEcho: "true"` (the string form) is masked like `NoEcho: true` (issue [#4824](https://github.com/go-to-k/cdkd/issues/4824))** -- `src/deployment/noecho-declared.ts` (new), `src/deployment/intrinsic-resolver/parameter-secrets.ts`, `src/deployment/deploy-engine/{masking,noecho}.ts`, `src/deployment/outputs-export-alias/secret-scan.ts`, `src/deployment/condition-verdicts.ts`, `src/deployment/masked-property-fingerprints.ts`, `src/deployment/noecho-delete-reresolution.ts`, `src/deployment/intrinsic-resolver/{support,refs}.ts`, `src/analyzer/skipped-outputs.ts`, `src/cli/commands/diff-recursive.ts`. CloudFormation accepts the string as well as the boolean (a hand-written or `CfnInclude` template). Several readers tested only the boolean. With the string form, the value printed on `cdkd deploy`'s log lines (the resolver's `--verbose` lines and its diff lines). The export-name secret scan did not see it, and it fed a recorded condition verdict and the skipped-output digest. These readers now ask one predicate, `isNoEchoDeclared` (the boolean or exactly `"true"`). `cdkd diff` also masks a property's stored copy. A string-declared value copied into a leaf that does not read the parameter still persists in plaintext until the migration witness covers such records (issue [#4831](https://github.com/go-to-k/cdkd/issues/4831)): masking it now would replace a create-only resource. A stack whose `Export.Name` spells a string-declared value loses that export on its next deploy, as a boolean one always did. Tests: `tests/unit/deployment/noecho-string-form-4824.test.ts`, `tests/unit/cli/diff-noecho-string-form-4824.test.ts`, `tests/unit/deployment/noecho-string-form-replacement-4824.test.ts`. Integ: `noecho-parameter-masking` declares a parameter with the string form and fails when its value reaches the deploy logs, events or state.
