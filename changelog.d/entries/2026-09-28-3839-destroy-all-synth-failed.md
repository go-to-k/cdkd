- **`cdkd destroy --all` and wildcard patterns are refused when the app cannot be synthesized (issue [#3839](https://github.com/go-to-k/cdkd/issues/3839))** -- `src/cli/commands/destroy.ts`, with unit tests in `tests/unit/cli/destroy.test.ts`. When synthesis failed (a mistyped `--app`, a broken app, a missing dependency) or no app was configured, `cdkd destroy --all`, `cdkd destroy '*'` and any other wildcard fell back to every stack record in the state bucket, other apps' stacks included, with the synth failure logged only at debug level. They now exit 1 before reading any stack record or prompting, name the selector, and print the synthesis error as `Caused by:`. The hint points at fixing the app or naming each stack exactly (`cdkd destroy '<stack>'`, `cdkd state destroy '<stack>'`). An exact physical stack name still resolves from state without a working app. The `Could not determine which stacks belong to this app` refusal no longer advises `--all` after a failed synth, and now also prints the synthesis error.
