- **`cdkd deploy`'s own messages flatten each value they interpolate to one line, so a logical id, physical id, type or name cannot forge an output line (issue [#2676](https://github.com/go-to-k/cdkd/issues/2676))** -- `src/deployment/deploy-engine/*.ts` (except `update.ts`, which follows after [#4852](https://github.com/go-to-k/cdkd/issues/4852)). The logger sink strips terminal control characters but keeps newlines, so a newline in a value from the template or the state file started a line cdkd never wrote. The deploy engine's log lines and thrown errors now build their text with `safeMsg`, which keeps cdkd's own newlines and colours and turns each interpolated value's newline or tab into a space. The rule: only the values the deploy engine interpolates are flattened; an error message embedded in a wrapping message (the per-resource `Failed to <op> <id>:` line, `Failed to resolve output <key>:`, the replacement failures, the state-save warnings) prints as before, masked where it was masked before but not flattened (`asIsMessage` in `src/utils/display-safe.ts`), so a remedy command it ends in keeps its own last line. Under `--strict-getatt`, the output failure now reads `Failed to resolve output <key> (--strict-getatt ...): <message>`, with the message last. Where a message is masked for secrets, each value is masked before it is flattened, and the printing maskers (`src/deployment/secret-redaction/`) also match a secret's flattened spelling. The CodeCommit, S3 Tables, Glue, Cloud Control and provider-registry refusals now flatten the logical id, physical id or property they name. `tests/raw-log-interpolation-baseline.json` drops these files, so a new raw interpolation in them fails `audit:raw-log-interpolation:check`.
