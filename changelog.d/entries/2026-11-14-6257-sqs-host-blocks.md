- **`cdkd local invoke` / `start-api` / `run-task` / `invoke-agentcore` and the custom resource runtime under `--aws-emulator` no longer let an SQS call with a queue URL read at run time reach real SQS (issue [#6257](https://github.com/go-to-k/cdkd/issues/6257))** -- `package.json` (`cdk-local` `^0.166.1` -> `^0.166.3`, with go-to-k/cdk-local#953), `src/local/docker-runner.ts`, `src/local/ecs-task-runner/docker-run-args.ts`, `src/local/local-aws-wiring.ts`, `src/cli/commands/local-invoke/command.ts`, `src/cli/commands/local-invoke-agentcore/command.ts`. cdkd assembles its own `docker run`, so it got cdk-local's env queue URL rewrite but not its SQS host blocks: a real queue URL the handler read from SSM Parameter Store, Secrets Manager or its event still sent `SendMessage` to real SQS (in mixed mode, signed with the real identity). Every container whose SQS goes to AWS Emulator now gets `--add-host <real-sqs-host>:127.0.0.1` for each real SQS host name (on the namespace owner for an ECS container that joins one), so such a call fails with a refused connection instead; a container whose SQS is excepted to real AWS gets none. An env value that is exactly a real queue URL is rewritten to the emulator queue, and on the host network it is re-pointed from the SQS sidecar to the emulator. `local invoke` and `local invoke-agentcore` print the mixed-mode line once the target is resolved, naming that workload's exceptions only. Tests: `tests/unit/local/local-aws-wiring.test.ts`.
