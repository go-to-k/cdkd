- **The composite-id refusal and malformed-id messages, the replacement name-collision refusal and the S3 `UnknownError` rewrites no longer put a record or template value inside cdkd's own quotes (issue [#3950](https://github.com/go-to-k/cdkd/issues/3950), partial)** -- `src/provisioning/composite-id.ts`, `src/deployment/replacement-name-holder.ts`, `src/utils/error-handler.ts`, with paste cases in `tests/unit/provisioning/composite-id-prose-quotes.test.ts`, `tests/unit/deployment/replacement-name-holder-prose-quotes.test.ts` and `tests/unit/utils/error-handler.test.ts`. The composite-id messages and the bucket rewrites quoted the value RAW, and the collision refusal quoted a `displaySafe` render, which keeps `"`, `$( )` and a backtick. A value carrying a quote closed cdkd's, so pasting the sentence ran what followed it as shell. A plain value keeps its quotes and prints exactly as before, and so do a composite segment carrying the `|` separator, a masked `***` segment and a blank id. Any other value is described (`a bucket whose name is not a plain identifier`). A `replacement-name-holder.ts` entry no longer sits in `record-value-prose-quotes-fence.test.ts`'s allow-list.
