- **A masked Service Discovery or API Gateway (v1) create/update failure is still retried when a secret overlaps AWS's retry wording (issue [#4259](https://github.com/go-to-k/cdkd/issues/4259))** -- `src/provisioning/providers/{servicediscovery,apigateway}-provider.ts`. These providers mask AWS's error text before joining it into their `Failed to create/update ...` message (#2050, #2063, #2177). When a recorded secret, or a secret-derived Stage name, spelled part of a retryable phrase (for example `does not exist`), the mask cut that phrase out and `withRetry` read the failure as terminal, so the deploy failed where it used to retry. Each wrap now goes through `wrapMaskedAwsError` (the #4244 helper), which stamps `markRedactedCause` when the mask changed the text, so the retry classifiers read the unmasked cause chain. The message is still masked, and a wrap the mask left unchanged is not stamped. Tests: `tests/unit/provisioning/servicediscovery-provider-masked-retry.test.ts` and the `issue #4259` block in `tests/unit/provisioning/apigateway-provider-masked-log.test.ts`.
