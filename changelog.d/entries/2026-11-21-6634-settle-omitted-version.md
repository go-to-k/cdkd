- **A policy document declared without `Version` no longer makes the deploy warn that its post-write read never showed it (issue [#6634](https://github.com/go-to-k/cdkd/issues/6634))** -- `src/provisioning/settle-after-own-write.ts`, `src/analyzer/drift-verbatim-paths.ts`. S3, SQS, SNS, KMS, Secrets Manager and IAM's role trust policy write `Version: 2008-10-17` (what an omitted `Version` means) into a document submitted without one. The settle that re-reads a policy right after cdkd writes it did not take that read as the declared document, so a deploy of, for example, an `AWS::KMS::Key` whose `KeyPolicy` has no `Version` re-read for about 3.5 s and then warned to run `cdkd state refresh-observed`, which was not needed. A read `2008-10-17` now matches a declared document with no `Version`; a read `2012-10-17` there, or any change to a declared `Version`, still differs. The drift baseline heal compares the same way.
