- **`cdkd drift` no longer reports `Replicas` drift for an `AWS::DynamoDB::GlobalTable` on the AWS managed key when the record has no observed baseline (issue [#5790](https://github.com/go-to-k/cdkd/issues/5790))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts` and its unit tests. A template on the AWS managed key declares only the top-level `SSESpecification` (`SSEEnabled: true`, `SSEType: KMS`), which is what CDK's `TableEncryptionV2.awsManagedKey()` renders. The read-back, though, names each replica's key ARN. A record a rollback rebuilt, or a pre-v3 record, is compared through its template properties, so the whole `Replicas` list differed. The comparison now takes the live replica key only when KMS `DescribeKey` reports it `KeyManager: AWS`, reading each key in its own region. If the replica uses a customer managed key, or the template names a replica key, drift still reports. If the key cannot be read (no `kms:DescribeKey` permission, a throttle), the comparison takes nothing and drift still reports.
