- **An Auto Scaling group whose template enables ALL group metrics no longer drifts forever on a legacy record (issue [#4021](https://github.com/go-to-k/cdkd/issues/4021))** -- `src/provisioning/providers/asg-provider.ts` (`ALL_GROUP_METRICS`, `canonicalizeDriftPair`, `holdsAllKnownMetrics`), with unit tests in `tests/unit/provisioning/asg-provider-metrics-all-4021.test.ts` and an arm in the `drift-revert-vpc` integration fixture. A `MetricsCollection` entry that lists no metrics (CDK `GroupMetrics.all()`) enables every group metric, but AWS reports enabled metrics one by one, so a resource whose drift baseline is its template (one deployed before observed-capture) never matched and `cdkd drift` reported it on every run. The drift comparison now reads an ALL baseline as "every metric AWS reports, which must include every metric cdkd knows ALL enables" (25, observed on AWS; the SDK documents 20): a readback holding them all, or more, compares clean, and one missing any of them reports drift for exactly the missing ones. Disabling a metric cdkd does not yet know is not reported. `cdkd drift --revert` re-enables them by enabling ALL (no metric list) and disables nothing. On create and update, a `MetricsCollection` entry that explicitly lists every known metric is also sent as ALL, so it enables metrics AWS adds later too, where CloudFormation would send the explicit list.
