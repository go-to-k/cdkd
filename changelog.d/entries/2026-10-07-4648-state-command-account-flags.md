- **More pasteable `cdkd state` commands now carry the run's `--profile`, resolved `--state-bucket` and non-default `--state-prefix` (issues [#4648](https://github.com/go-to-k/cdkd/issues/4648), [#4159](https://github.com/go-to-k/cdkd/issues/4159))**. Changed files: `src/state/malformed-resources-bag.ts` (exports `accountArgs` / `withheldAccountClause`), `src/deployment/deploy-engine/delete.ts`, `src/cli/commands/{destroy,destroy-runner,state,gc}.ts`, `src/utils/error-handler.ts` and `src/provisioning/providers/nested-stack-provider.ts`. Before this change these messages printed their commands without the flags, so on a non-default bucket or profile a pasted command acted on the default profile's bucket. Some of those commands drop records or delete resources. The messages are: a deploy's delete-skip warnings (`Inspect it with:` / `Drop the record with:`), `cdkd destroy`'s multi-region `cdkd state orphan`, its nested-child refusal (`cdkd destroy <parent>` / `cdkd state destroy <child>`) and its termination-protection `Retry with:` line, `cdkd state orphan`'s `Destroy with:` line, the partial-destroy hints, `cdkd state orphan --resource`'s child drop, a nested child's destroy failure, the deploy-path refusal of a nested child's unreadable outputs (the last #4159 site), and `cdkd gc`'s unreadable-state-file `cdkd state show` line, which names the prefix of the key the file was found under. Each value goes through the same gate as #3909's: a refused one prints as a quoted hole with its reason. Still without the flags: the `cdkd export` and `cdkd drift` commands, including `cdkd state refresh-observed`, which #4648 tracks.
