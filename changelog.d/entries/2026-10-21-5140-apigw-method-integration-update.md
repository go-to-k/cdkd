- **Changing an `AWS::ApiGateway::Method`'s `Integration` or `MethodResponses` now reaches AWS (issue [#5140](https://github.com/go-to-k/cdkd/issues/5140))** -- `src/provisioning/providers/apigateway-provider.ts`. An update patched only the Method's own fields: a changed integration (for example its `Uri`, after the Lambda function behind a `LambdaIntegration` was replaced) was recorded in state but never sent, so the API kept invoking the old target, or answered `500` once it was deleted, after a green deploy. An update now puts the integration and its integration responses, and adds, changes or removes method and integration responses, in the order API Gateway accepts: `PutIntegration` replaces the integration and drops its integration responses, so they are put again, and a changed method response is deleted before it is put. Nothing extra is called when neither changed.
