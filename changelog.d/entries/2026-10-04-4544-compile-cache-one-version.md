- **The startup compile cache no longer grows with every cdkd upgrade (issue [#4544](https://github.com/go-to-k/cdkd/issues/4544))** -- `src/cli/compile-cache.ts`. Node never removes a compile-cache entry, so each release cdkd ran added its newly compiled chunks to `~/.cache/cdkd/compile-cache` (or `$XDG_CACHE_HOME/cdkd/compile-cache`) and kept the old ones forever. The cache now lives in a per-version subdirectory, and a run deletes every other entry under the cache directory (older versions' subdirectories and the version-less layout 0.294.8 wrote) synchronously, so a command that exits at once still finishes the cleanup. Steady-state startup is unchanged; the delete costs time only on the first run after an upgrade.
