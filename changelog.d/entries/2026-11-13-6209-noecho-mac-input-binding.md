- **A write-only property that reads a `NoEcho` parameter and also a resource attribute is no longer re-sent on every deploy (issue [#6209](https://github.com/go-to-k/cdkd/issues/6209))** -- `src/deployment/noecho-value-macs.ts`, `src/deployment/masked-property-fingerprints/input-walk.ts`. Before this change, an `AWS::ApiGateway::RestApi` `Body` with an `Fn::GetAtt` / `Fn::Sub ${Fn.Arn}` Lambda integration repeated the "cannot compare" warning on every deploy whose `NoEcho` value had not changed, and an RDS-style write-only key beside a resource attribute was re-sent every deploy. Now the property's NoEcho value MAC entry also records the input fingerprint the value was sent with, and an unchanged value with unchanged, fully resolved inputs is not sent again. An input cdkd cannot resolve and hash (a custom resource attribute, a secret-reading resource, a `{{resolve:...}}` reference an intrinsic joins to another value) keeps the previous behaviour. `cdkd diff` now also shows a property whose other inputs all resolve when its NoEcho value changed. No state schema bump.
