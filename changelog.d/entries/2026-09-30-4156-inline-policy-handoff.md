- **Handing an inline policy name from one resource to another on the same principal in one deploy no longer removes the receiving resource's grant** (`src/deployment/inline-policy-claims.ts`, `src/deployment/deploy-engine.ts`, `src/provisioning/providers/iam-policy-provider.ts`, go-to-k/cdkd#4156). An `AWS::IAM::Policy` update removes its old name from the principals it recorded, and a delete removes its name from all of them. When another resource of the same deploy took that name on the same role, group or user, the removal stripped the other resource's live policy, and the next deploy saw no diff. That happened with two policies swapping names or handing one name over, with a policy dropped while a new one takes its name, and with a policy renamed away from a name the principal's own `Policies` now declares. Before each such removal, the deploy now asks whether another resource of the same deploy has ALREADY written that name onto that principal, reading what that resource recorded after its create or update completed, and keeps the name when it has (names compare case-insensitively, as IAM does). A resource that has not run yet, is still running, or failed counts for nothing: the removal proceeds, and its later put restores the name. Only a write through the SDK provider counts, and for a role, group or user only a create or an update that changed its own `Policies`. So a swap or hand-off between two policies is fixed when one depends on the other; with no dependency they run concurrently and the removal can still strip the name (go-to-k/cdkd#4227). A rollback revert, `cdkd drift --revert` and `cdkd destroy` remove as before (go-to-k/cdkd#4225).
