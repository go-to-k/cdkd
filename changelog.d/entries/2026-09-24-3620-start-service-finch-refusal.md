- **`cdkd local start-service` / `start-alb` now refuse to forward secrets under `CDK_DOCKER=finch` on macOS / Windows unless `CDKD_ALLOW_SECRETS_ON_ARGV=1` is set, via cdk-local 0.149.2 (issue [#3620](https://github.com/go-to-k/cdkd/issues/3620))** -- `package.json`, `pnpm-lock.yaml`, `docs/local-run-task.md`, `docs/local-start-service.md`. Both commands run on the bundled cdk-local engine, so [#3600](https://github.com/go-to-k/cdkd/issues/3600)'s refusal did not reach them and their containers' ECS secrets went onto the `limactl` command line without notice. cdk-local 0.149.2 (go-to-k/cdk-local#750) applies the same refusal and the credential warning, checked for each service when its first replica boots; with several targets the services booted before the refused one are already running, and the run then exits and tears everything down. The opt-in is read under cdkd's own `CDKD_` prefix, the name `run-task` uses.
