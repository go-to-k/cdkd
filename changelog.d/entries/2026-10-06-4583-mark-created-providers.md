- **`cdkd rollback --revert-failed` now deletes the resource SDK providers made before their create failed, not only Kinesis's (issue [#4583](https://github.com/go-to-k/cdkd/issues/4583), follow-up of [#1710](https://github.com/go-to-k/cdkd/issues/1710))** -- `src/provisioning/providers/*.ts` (among them EC2, ELBv2, Auto Scaling, IAM, Lambda, ECS, RDS, DynamoDB, S3, SNS, EFS, EMR, ACM, FSx, Pipes), `docs/_contents/provider-rules.md`, `docs/_contents/cli-rollback.md`. A follow-up call (tags, policies, a wait) failing after the create returned left the resource unrecorded. Providers now mark the thrown error with the id `delete()` takes (`markCreatedBeforeFailure`), so the failed CREATE is journaled with it and `--revert-failed` deletes it. A provider that already deletes its own resource in the catch marks only when that cleanup failed; a resource the create adopted or found held, the create call's own failure and a pre-flight refusal are never marked. `AWS::IAM::Policy` instead removes the policy from the principals it had already written and warns with the commands when that fails; `AWS::SNS::TopicPolicy` and `AWS::SQS::QueuePolicy` mark only the topics or queues they had written; an `AWS::ElasticLoadBalancingV2::Listener` create, and an `AWS::ECS::Service` create under `--full-wait`, first read whether the port or service name was already taken, and such a resource is neither cleaned up nor marked; `AWS::S3Express::DirectoryBucket` resolves its ARN before `CreateBucket`. Limits: a failed CREATE journals one id, so a retried create with an AWS-generated id names only its last resource; no id returned (a Cloud Map operation that never finished, CreateTrail / CreatePolicy / RegisterStreamConsumer with none) means no mark. A nested stack is marked when reading its deployed child back fails (issue [#4595](https://github.com/go-to-k/cdkd/issues/4595)). Tests: `tests/unit/provisioning/*-created-before-failure-4583.test.ts`, plus cases in the S3 bucket and SNS topic cleanup tests.
