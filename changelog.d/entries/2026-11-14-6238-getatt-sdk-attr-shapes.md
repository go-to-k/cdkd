- **`Fn::GetAtt` of `AWS::AutoScaling::AutoScalingGroup.AutoScalingGroupARN`, `AWS::WAFv2::WebACL.Capacity`, `AWS::AppSync::ApiKey.ApiKeyId` and `AWS::S3Tables::Table.WarehouseLocation` / `VersionToken` now returns CloudFormation's value (issue [#6238](https://github.com/go-to-k/cdkd/issues/6238))** -- the ASG, WAFv2, AppSync and S3 Tables providers, `src/deployment/intrinsic-resolver/getatt-refusals.ts`, `scripts/gen-sdk-attr-coverage.ts`, unit tests and a new `getatt-sdk-attr-shapes` integ fixture. Before, each resolved to the resource's physical id with only a warning: the group name, the web ACL ARN, or the composite `<apiId>|<key>` / `<bucketArn>|<namespace>|<table>` id. The providers now record them, and `Capacity` is read again after a web ACL update, so it follows the rules. A web ACL, API key or table deployed by an older cdkd is healed the first time a deploy reads one of these attributes; an ASG is healed by its next update. An attribute name ending in upper-case `ARN` / `URL` now gets the same check as `Arn` / `Url`: when cdkd can only fall back to a physical id that is not an ARN / URL, the reference is refused instead of resolved to the wrong value. Until its next update, an ASG deployed by an older cdkd therefore refuses `Fn::GetAtt AutoScalingGroupARN`.
