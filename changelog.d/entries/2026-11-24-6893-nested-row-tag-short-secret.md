- **A 1-3 character secret or `NoEcho` value embedded in a nested-stack row's `Tags` value no longer reaches state in plaintext (issue [#6893](https://github.com/go-to-k/cdkd/issues/6893))** -- `src/deployment/secret-redaction/nested-stack/row-tag-spellings.ts`, `src/provisioning/providers/nested-stack/row-tags.ts`, `tests/unit/provisioning/nested-stack-row-tags-short-secret-6893.test.ts`, and a row-tag arm in the `nested-stack-secret` integ. Since #6871 a row's resolved `Tags` become its child's stack tags, and the provider turned a secret back into its `{{resolve:...}}` expression by substring, which cannot be done below `MIN_NEEDLE_LENGTH` (4): `tag:{{resolve:...:pin::}}` resolving to `tag:w4` reached every child resource as `tag:w4` and was persisted there. As #2745 did for a row's `Parameters`, the parent's recorder now certifies each tag value's spelling by position (a literal source rendered with this pass's pairs, or an `Fn::Join` / `Fn::Sub` source's own resolution record), and the provider hands the child that spelling. A value with no certified spelling that still holds a secret at any length (a `NoEcho` value, a secret the certificate refuses) is withheld from the child's tags with a warning, and a value carried only as a mask is withheld too, where it used to tag the child's resources with `***`. The parent's `nestedStackTags` record now leaves a row unrecorded (it re-runs its child each deploy) when its resolved tags hold any secret at any length, where a 1-3 character `NoEcho` value embedded in a longer value was recorded. Residual: a short secret that coincides with other text in an uncertified tag value withholds that tag (the fail-closed direction).
