- **`AWS::Lambda::NetworkConnector` now deploys `ElasticIpConfiguration` instead of refusing it (issue [#6567](https://github.com/go-to-k/cdkd/issues/6567))** -- `src/provisioning/providers/lambda-network-connector-provider.ts`, `package.json` (`@aws-sdk/client-lambda-core` 3.1170.0, the first release that models the member). A template that declared `Configuration.VpcEgressConfiguration.ElasticIpConfiguration` was refused before any AWS call, because the installed SDK could not send it; CloudFormation declares it again since the 2026-11-18 schema. cdkd now sends it on create and update and reads it back for `cdkd drift`. Measured: `ServiceManaged` can be set on an existing connector (the update takes about 4 minutes), and the operator role needs EC2 Elastic IP permissions or AWS refuses the call. An `UpdateNetworkConnector` that omits the member keeps the live value, so a template that removes it now sends `Type: None`. A connector reset to `None` reads back with the member while one that never had it reads back without it, so drift treats `None` and absent as the same, while a declared `None` against a live `ServiceManaged` still drifts. A malformed value (not an object whose `Type` is `None` or `ServiceManaged`) is refused before any AWS call on the template path; a rollback replay or `cdkd drift --revert` omits it with a warning.
