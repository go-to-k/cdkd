- **`AWS::ElastiCache::CacheCluster`: moving `PreferredAvailabilityZones` to zones the previous list does not name now replaces the cluster, as CloudFormation does (issue [#5458](https://github.com/go-to-k/cdkd/issues/5458))** -- `src/analyzer/replacement-rules.ts` and `src/provisioning/providers/elasticache-provider.ts`, with unit tests in `tests/unit/analyzer/replacement-rules-elasticache-paz.test.ts` and a zone-move phase in the `cache-streaming` integ fixture. cdkd updated the cluster in place, sending `NewAvailabilityZones` with no node added, which AWS refuses, so the deploy failed where CloudFormation replaced the cluster. Real CloudFormation change-set executions replaced it whenever the new list shared no zone with the previous template list (even when the live node already sat in the new zone) and updated it in place otherwise, including when either list is absent. `cdkd diff` now marks that change `[requires replacement]`, and the deploy replaces the cluster once `--force-stateful-recreation` confirms the loss of its cached data (the type is in the stateful-recreate guard set).
