- **A deploy that changes a custom resource's `ServiceToken` is now refused, as CloudFormation refuses it, instead of being sent as an `Update` to the new handler (issue [#4749](https://github.com/go-to-k/cdkd/issues/4749))** -- `src/deployment/custom-resource-service-token.ts`, `src/deployment/deploy-engine/{deploy-flow,update}.ts`, `src/cli/commands/diff-recursive.ts`. The old handler never received a `Delete`, so whatever it created was orphaned silently. Two different ARNs are refused before anything is provisioned (`--dry-run` too), with no request to either handler and state unchanged; `cdkd diff` reports it under `Blocking` and exits `3`. A token that reads a resource the same deploy replaces or creates (a renamed backing Lambda) is refused once it resolves, before the handler is invoked, and the deploy rolls back; `cdkd diff` warns about it. A recorded token cdkd cannot compare (missing, `***`, a `{{resolve:...}}` reference) is refused when the template moves it; a token fed by a `NoEcho` parameter, recorded as `***`, is still updated as before, since cdkd keeps no value to compare. The message names the remedy: a new logical id, which creates the new resource through the new handler and deletes the old one through its old handler. A `--recreate-via-cc-api` target is not refused. Docs: `docs/{cli-deploy,cli-diff,troubleshooting,state-management}.md`. Tests: `tests/unit/deployment/{custom-resource-service-token,deploy-engine-cr-service-token-4749}.test.ts`, `tests/unit/cli/diff-recursive.test.ts`.
