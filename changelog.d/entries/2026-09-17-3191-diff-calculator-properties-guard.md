- **`cdkd deploy` no longer REPLACES a live resource because of an unreadable `properties` map in state (issue [#3191](https://github.com/go-to-k/cdkd/issues/3191))** -- `src/analyzer/diff-calculator.ts`, `src/state/malformed-resources-bag.ts`, `src/cli/commands/diff-recursive.ts`, plus `diff-calculator-malformed-properties.test.ts`, `diff-recursive-malformed-properties.test.ts`, `deploy-engine-malformed-properties-refusal.test.ts` and cases in `malformed-resources-bag.test.ts`. `parseStateBody` validates nothing inside a record, so a resource's `properties` could be a string, a list, a number or `null` -- from a hand edit, a torn write, or anyone holding `s3:PutObject` on the state bucket -- and the change calculation read it with no check. A non-object compares unequal to every declared property, so the whole template read as absent-in-current: measured, an `AWS::S3::Bucket` declaring `BucketName` against a stored `"abcdef"` reached `requiresReplacement: true`, a DELETE + CREATE of the live bucket. `calculateDiff` now REFUSES (`STATE_RESOURCES_MALFORMED`, exit `1`) before provisioning or writing state, naming up to five damaged records then a count -- **under `--dry-run` too**, because the plan a dry run prints is built from that same comparison. Repairing to `{}` is no safer and is not offered: a stored `[]` and a stored `5` enumerate no keys -- they ARE the repaired case -- and each reached the same verdict. The refusal names NO stack or region (the only pair in reach is the record's own unvalidated self-report, which would aim the remedy at a healthy stack), and it renders each logical id through `displayIdent`, so a padded `"Bucket "` no longer prints as a bare `Bucket` indistinguishable from a healthy sibling. `cdkd diff` still previews: it repairs those maps to empty and warns, naming the records and the caller's own stack, at its load AND again after splicing adopted rollback orphans in. An absent `properties` is refused; an empty `{}` is healthy.
