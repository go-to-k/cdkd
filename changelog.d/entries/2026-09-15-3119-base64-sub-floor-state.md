- **A 1-3 character secret that an `Fn::Join` / `Fn::Sub` embeds in a longer string under `Fn::Base64` (`cdk.Fn.base64('port:' + secret.secretValueFromJson('pin'))`, the CDK UserData shape) is no longer persisted to `state.json` in its base64 form (issue [#3119](https://github.com/go-to-k/cdkd/issues/3119))** -- `src/deployment/intrinsic-function-resolver.ts` (`resolveBase64`), a unit case in `tests/unit/deployment/intrinsic-resolver-sub-floor-log-mask.test.ts`, and a `Base64Pin` arm in the `secrets-dynamic-ref` integ. Issue #2759's mask-only detector at that site asked the needle mask alone ("did masking change the input?"), which cannot see a plaintext below `MIN_NEEDLE_LENGTH` (4) unless it is the whole text, so the encoding of `port:q7` reached the persist path in the clear -- decodable in one command -- while the `Resolved Fn::Base64:` debug line beside it was already masked by position since issue #3100. The detector now also asks the position mask (`logTextOfLeaf`, the pass registry #3100 introduced), and registers the encoding mask-only whenever either fires, so every persistence reader (state, the rollback journal, the outputs bag, `cdkd diff`) stores `***` for it, as it already did for a 4+ character secret. The resolved value handed to AWS is unchanged. Residual: a value the position mask over-masks (a template literal equal to a string a secret was written into) also has its encoding masked -- the direction `logTwinOfProduct` accepts, since such a string carries the secret's text.
