- **A rollback that adopts the live new resource records what AWS holds, so the next deploy re-applies the template (issue [#6731](https://github.com/go-to-k/cdkd/issues/6731))** -- `src/deployment/rollback-executor/replay-reverse-replacement/finish.ts`, `docs/cli-rollback.md`; `tests/integration/sns-subscription-update` (phase 2r). When a rollback reversed a replacement whose re-create returned the live new resource (a name-idempotent create), it skipped the delete and adopted that resource, but rebuilt its state record from the pre-deploy properties. AWS kept the failed deploy's properties, the next `cdkd deploy` diffed no change, and `cdkd drift`, whose baseline the rollback re-reads from AWS, reported none. An SNS subscription the deploy re-created to add a `FilterPolicy` with a `FilterPolicyScope` is one: SNS answers the rollback's `Subscribe` with the live subscription, which kept filtering messages the template no longer filtered. The rollback now keeps the live resource's record, with the failed deploy's properties, so the next deploy applies the template's (the subscription's filter is cleared in place), and its warning says so.
