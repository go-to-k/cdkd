- **A malformed `AWS::AppSync::GraphQLApi` `EnvironmentVariables` value no longer strands a template-path update or blocks a rollback (issue [#3781](https://github.com/go-to-k/cdkd/issues/3781))** -- `src/provisioning/providers/appsync-provider.ts`.
  - A per-key value that is not a string, number or boolean (an object, array or `null`) is now refused on a template-path `cdkd deploy` update BEFORE any write, when the map changed. It used to throw after `UpdateGraphqlApi` had already applied the other changed fields.
  - The rollback revert arms (`replayingState`) and `cdkd drift --revert` (`desiredFromAwsReadback`) now warn instead of failing. They send no `PutGraphqlApiEnvironmentVariables`, because that call replaces the whole map and would delete the skipped key. State records the map AWS still holds, or no map when the previous one is unusable too.
  - The reverse-replacement create (`CreateContext.replayingState`) warns, then puts every usable key. State records the keys it put. The same record now also covers a malformed `EnvironmentVariables` container on these paths.
  - A template-path create still refuses, and rolls the new API back. Warnings name the key and the value's type, never the value.
