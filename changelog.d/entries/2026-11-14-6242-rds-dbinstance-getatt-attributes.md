- **`Fn::GetAtt` of an RDS DB instance's `DbiResourceId`, `Endpoint.HostedZoneId`, `ListenerEndpoint.*` and `CertificateDetails.*` now returns the value CloudFormation returns (issue [#6242](https://github.com/go-to-k/cdkd/issues/6242), first slice)** -- `src/provisioning/providers/rds/instance-attributes.ts`, the instance create / update / import paths, `src/deployment/intrinsic-resolver/getatt-construct-app.ts`, unit tests and a new `rds-dbinstance-getatt-attributes` integ fixture. Before, an instance cdkd's SDK provider created recorded none of these, so each resolved to the DB instance identifier with only a warning. CDK's `instanceResourceId` is `DbiResourceId`, so `grantConnect` granted `rds-db:connect` on a resource id that does not exist. An instance routed through Cloud Control was not affected. They are now recorded on create, update and `cdkd import`; an instance deployed earlier has them read back on the next deploy that references them, and a value cdkd cannot read fails the deploy instead of becoming the identifier. `CertificateDetails.ValidTill` is rendered as CloudFormation renders it (`2027-11-13T18:54:24Z`).
