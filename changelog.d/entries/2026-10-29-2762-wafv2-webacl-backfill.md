- **`AWS::WAFv2::WebACL` keeps the SDK route for `DataProtectionConfig`, `OnSourceDDoSProtectionConfig`, `ApplicationConfig` and `MonetizationConfig` (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762)).** A web ACL declaring any of them used to go through Cloud Control. All four now ride on `CreateWebACL` and `UpdateWebACL` and are read back from `GetWebACL` for `cdkd drift`. `UpdateWebACL` replaces the web ACL whole, so removing `DataProtectionConfig`, `OnSourceDDoSProtectionConfig` or `MonetizationConfig` from the template clears it on AWS. `ApplicationConfig` is the exception: AWS keeps it when an update leaves it out and refuses any change to it. cdkd sends it on an update only when the template changed it, so an unchanged one is never re-sent, and removing it from the template leaves the stored value in place. A `false` that AWS reports for a data protection's `ExcludeRuleMatchDetails` or `ExcludeRateBasedDetails` is not reported as drift when the template left that key out, because `false` is the documented default. Source: `src/provisioning/providers/wafv2-provider.ts`.
