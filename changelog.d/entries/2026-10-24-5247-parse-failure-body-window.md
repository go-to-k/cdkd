- **A corrupt `state.json` or rollback journal no longer prints a window of the file in its error (issue [#5247](https://github.com/go-to-k/cdkd/issues/5247))** -- `src/utils/json-parse-failure.ts` (new: `describeJsonParseFailure`, `utf8ByteLength`), `src/state/s3-state-backend.ts`, `src/types/rollback-journal.ts`, `src/state/export-index-store.ts`, `src/cli/commands/gc.ts`, `docs/troubleshooting-locks-state.md`. Before, `State file for stack <S> is not valid JSON: ...` and `Rollback journal for '<S>' is not valid JSON: ...` carried Node's `JSON.parse` error text, which quotes about 30 characters of the body. Before `cdkd scrub`, that can be a plaintext property or output value, and it reached the terminal and CI logs at default verbosity -- twice for the state file, whose `Caused by:` line repeated it. Both messages now read `invalid JSON[ at code-unit position N]; <bytes> byte(s) read`, the form the exports index already used, and neither the state refusal nor `cdkd gc`'s corrupt-state abort (which printed the same window on its `Caused by:` line) attaches the parse error as its cause. Node's full text, ASCII-sanitized, is logged at `--verbose` only.
