- **`cdkd orphan` refuses the rest of a record it could not read, instead of saving it (issues [#3350](https://github.com/go-to-k/cdkd/issues/3350), [#3345](https://github.com/go-to-k/cdkd/issues/3345), [#3344](https://github.com/go-to-k/cdkd/issues/3344), [#3388](https://github.com/go-to-k/cdkd/issues/3388))** -- `src/cli/commands/orphan.ts`, `src/state/malformed-resources-bag.ts`, `src/analyzer/orphan-rewriter.ts`. Before, only the resource map, `outputs` and each surviving resource's `properties` were checked. A surviving resource entry that was not an object was saved reshaped (`"abcdef"` as per-character keys, a number as a record with no physical id). An unreadable `attributes` map, or an unreadable `orphans` list or record, was saved as it was. All of these are now refused at the load, `--dry-run` included, with the same ways out as the `properties` refusal. A sibling's `Ref`, `Fn::GetAtt` or `Fn::Sub` of an orphaned record that cannot be read is now reported as unresolvable. Before, it was resolved to `undefined` or `x-undefined`. `--force` no longer reads an unreadable `attributes` cache, where a list or string used to supply values for keys it did not hold. The state and outputs refusals now name the region the record is listed under, and for a legacy record listed with no region they name its S3 object instead of a `cdkd state show` command that cannot read it.
