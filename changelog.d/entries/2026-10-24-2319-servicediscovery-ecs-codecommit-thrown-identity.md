- **A failed Cloud Map namespace or service, ECS cluster, task definition or service, or CodeCommit repository create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/servicediscovery-provider.ts`, `ecs-provider.ts`, `codecommit-repository-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (`AccessDeniedException. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, masked through the operation's secret masker. This also covers a Cloud Map operation that AWS reports as FAIL (the message names its `ErrorCode` when AWS reports one), the ECS service `--full-wait` steady-state failure (the SDK waiter's result, which lists every DescribeServices answer and failure text, is reduced to its state), the CodeCommit trigger put beside kept live triggers, and the free-text detail of a DescribeClusters failure during an ECS cluster name lookup. A cdkd-authored or transport error keeps its text. The AWS error stays as the `cause`, so an IAM grant that is still propagating is retried as before, a name that is taken still reads as a name collision, and a CodeCommit delete refused for a missing KMS key (`EncryptionKeyNotFoundException`) is never read as an already-deleted repository.
