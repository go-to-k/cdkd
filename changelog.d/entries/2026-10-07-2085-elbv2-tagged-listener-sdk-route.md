- **A tagged ALB / NLB listener now deploys through cdkd's ELBv2 provider, so removing a `ListenerAttributes` key resets it in AWS (issue [#2085](https://github.com/go-to-k/cdkd/issues/2085))** -- `src/provisioning/providers/elbv2-provider.ts`, `src/provisioning/property-coverage.generated.ts`. An `AWS::ElasticLoadBalancingV2::Listener` carrying `Tags` (any CDK app that tags its stack, e.g. `cdk.Tags.of(stack).add(...)`) was routed through Cloud Control with "cdkd's SDK Provider does not yet wire Tags", although the provider already sent the tags on create, diffed them on update and read them back. On that route, dropping a key from `ListenerAttributes` (e.g. `routing.http.response.server.enabled`) left the old value live in AWS. `ELBv2Provider` now declares `Tags` handled for the listener, so a new tagged listener stays on the SDK route, where a removed key is reset to its documented default. A listener already recorded as provisioned through Cloud Control stays there for now. Tests: `tests/unit/provisioning/elbv2-listener-tags-route-2085.test.ts`; integ `alb` (the listener attribute removal assertion).
