- **A Cloud Control update that reports success while AWS keeps the previous value is no longer recorded as applied (issue [#7099](https://github.com/go-to-k/cdkd/issues/7099))** -- `src/provisioning/cloud-control/unapplied-update.ts`, `src/provisioning/cloud-control/update.ts`. After a Cloud Control update, cdkd compares the model it already reads back with the previous and desired values. Before this, a changed top-level property that still held its previous value on AWS was recorded with the new value, so the deploy reported success over a resource that never changed. A generic type now gets a `[cc-silent-noop]` warning, and the record keeps the previous value, so the next deploy sends the change again. The measured silent no-ops (an `AWS::EC2::NetworkInterface` `PrivateIpAddresses` change, and an `AWS::EKS::Cluster` `KubernetesNetworkConfig` load-balancing toggle sent on its own) fail the update instead.
