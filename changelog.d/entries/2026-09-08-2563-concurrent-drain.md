- **A concurrent intrinsic resolution now drains every part before a rejection surfaces, so a sibling's secret is recorded before the caller sees the failure (issue [#2563](https://github.com/go-to-k/cdkd/issues/2563))** -- `src/deployment/intrinsic-function-resolver.ts` (`allSettledKeepingFirstRejection`, wrapping `resolveJoin`'s parts and `resolveValue`'s array arm), new `src/deployment/drain-budget.ts` (the shared budget + opener), and the four callers that hoist one over a locked resolve loop (`deploy-engine.ts`, `scrub.ts`, `import.ts`, `export.ts`), a new unit file, `.claude/rules/layout-deployment.md` and `.claude/rules/layout-deployment-secrets.md`. A secret dynamic reference records `plaintext -> expression` into `context.recordedSecretValues` just before its promise settles, and `Promise.all` surfaces a rejection AT ONCE, so a caller's `catch` / `finally` ran while a sibling was in flight. `DeployEngine`'s `Export.Name` block copies its private `nameSecrets` map into the pass map in such a `finally`: a later recording reached nothing, leaving a plaintext the pass did not know as a needle. The drain keeps `Promise.all`'s error, the EARLIEST REJECTION IN TIME, where scanning `Promise.allSettled` for the first rejected ENTRY selects by input order. Both sites are wrapped: a list nested in a join part rejects through the array arm. **The wait is capped at 60 s once a rejection is in hand**: `resolveOutputs` runs after every resource exists, before `saveState`, with the lock held. One drain-wait budget covers a resolution, and each caller hoists one over its whole loop, so neither nesting depth nor loop length multiplies it; the timer is NOT `unref`'d, since an unref'd cap lets Node exit 0 mid-deploy. **Residuals**: [#2805](https://github.com/go-to-k/cdkd/issues/2805), earliest-in-time holds per invocation, so a NESTED failure can lose to a shallower one; [#2814](https://github.com/go-to-k/cdkd/issues/2814), a drain arming on a spent budget waits not at all.
