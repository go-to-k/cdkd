- **`Fn::GetAtt` of a VPC's `DefaultNetworkAcl` / `CidrBlockAssociations` and a managed policy's `PolicyId` / `DefaultVersionId` now returns the value CloudFormation returns (issue [#6232](https://github.com/go-to-k/cdkd/issues/6232))**. Changed: `src/deployment/intrinsic-resolver/getatt-construct-core.ts`, `src/provisioning/providers/ec2/vpc.ts`, `src/provisioning/providers/iam-managed-policy/*`, unit tests, and a new `getatt-vpc-managed-policy` integ fixture.
  - Before, all four resolved to the resource's physical ID with only an `Unknown attribute` warning. `vpc.vpcDefaultNetworkAcl` gave the VPC ID, so a `NetworkAclEntry` on it failed to create. `Fn.select(0, vpc.vpcCidrBlockAssociations)` failed because the value was a string. A managed policy's `attrPolicyId` / `attrDefaultVersionId` gave its ARN.
  - A VPC create now records its default network ACL. A VPC deployed earlier has its ACL read from AWS when referenced, and so do the CIDR block associations, which a later `VPCCidrBlock` can extend.
  - A managed policy's create, update and `cdkd import` now record the `PolicyId` and current `DefaultVersionId`. A policy deployed earlier has them read back on the next deploy that references them.
  - If cdkd cannot read one of these values, the deploy now fails with a clear error. It no longer substitutes the physical ID.
