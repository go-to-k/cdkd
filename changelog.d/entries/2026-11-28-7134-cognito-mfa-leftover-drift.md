When the template declares no MFA factor, email-OTP message or WebAuthn property and resolves MFA to `OFF`, a drift baseline whose `EnabledMfas` holds only `SOFTWARE_TOKEN_MFA` now compares as no factor: `cdkd drift` reports the live factor, and `cdkd drift --revert` clears it through the #7128 reset, keeping the pool's WebAuthn configuration. A pool the fixed release updated holds no factor and stays clean. `--accept` records the live list as read, which the baseline cannot tell from the pre-fix capture, so an accepted factor keeps being reported (the template cannot declare it under `OFF`), and `--accept` now warns that it will, naming the property (`src/cli/commands/drift/accept.ts`).
