- **The Lambda function provider masks secret-resolved values in its own log lines and failure messages (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), Lambda family slice)** -- `src/provisioning/providers/lambda-function-provider.ts`; tests in `tests/unit/provisioning/lambda-function-provider-masked-log.test.ts`. `create()` / `update()` of `AWS::Lambda::Function` logged through a logger no deploy-engine mask reaches; only the `RuntimeManagementConfig` line was masked. Every line now goes through the deploy's masker: the function name, `RecursiveLoop`, `ReservedConcurrentExecutions` and `CodeSigningConfigArn` are masked before they join the sentence, so a secret under four characters is caught too, and so is a function name recorded from a rotated `{{resolve:...}}` secret. Tag lines name the function, not its ARN. The post-create warning, the cleanup error and the AWS text a create, update or update-wait failure wraps are masked before they are joined, and such a failure still retries on AWS's wording. A secret's JSON-escaped spelling (the 4 KB environment refusal prints the variables as JSON) is masked in the message; the AWS error kept as its cause is not rewritten. A failed update or Active wait no longer relays the waiter's payload, the whole `GetFunction` response with plaintext environment variables and a presigned code URL; the message carries only the waiter state, status fields, an error acceptor's name and message, the latest observed status lines, and counts of the omitted and withheld ones. A failed wait's unmasked, payload-free status text is kept deeper in the error's cause chain, for the retry classifiers only; no deploy output prints it. Not caught: a secret under four characters inside AWS error text, and a recorded function name of one or two characters that AWS quotes back. `delete()` still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
