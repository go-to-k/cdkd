- **A refused name check before a create or a replacement no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/deployment/deploy-engine/replacement.ts`, `create.ts`, and unit cases. For a type whose create API hands back or overwrites an existing resource of the same name, cdkd looks the name up first and refuses when the lookup fails; that refusal ("cdkd could not check whether another resource already holds it") quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the same secret masker. A cdkd-authored or transport error keeps its text, masked. The same holds for the two `--replace` delete-first fallback failures ("Failed to delete old resource ..." and "Failed to re-create ... Cause: ...") when the provider let an AWS SDK error through. The AWS error is still the `cause`.
