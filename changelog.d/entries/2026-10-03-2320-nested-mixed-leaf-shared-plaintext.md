- **A nested-stack child resource that embeds one parameter (`Fn::Sub` / `Fn::Join`) beside a whole-value `{Ref}` to a second parameter resolving to the same plaintext no longer reports an UPDATE on every deploy (issue [#2320](https://github.com/go-to-k/cdkd/issues/2320))** -- `src/deployment/secret-redaction/positions.ts` (`positionByParameterPlaceholders`), `src/deployment/secret-redaction/redact-path.ts`, `tests/unit/deployment/secret-redaction-nested-parameter-placeholders.test.ts`, and a live arm on `tests/integration/nested-stack-secret/` (`HandoffMixed`, its own `mixed` JSON key). The resource's secret bag holds one expression per plaintext -- whichever `Ref` resolved last -- so the embedded leaf was persisted with the sibling parameter's expression while the diff side rendered its own: a perpetual UPDATE, and a REPLACEMENT every run on a create-only property. The persist path now answers each placeholder of an `Fn::Sub` / `Fn::Join` over the child's parameters (a placeholder a 2-arg `Fn::Sub` map binds to a `Ref`, and a nested `Fn::Sub` / `Fn::Join`, included) from that parameter's own association, the same one a bare `{Ref}` leaf uses, and accepts the result only when the template's literals and those plaintexts reassemble the resolved leaf exactly; at most one other part (a pseudo parameter, an intrinsic, an unassociated parameter) is allowed, kept verbatim only where the value scan would leave it alone, and a recorded secret crossing a placeholder's edge refuses. A leaf with two or more such parts, or one the reassembly refuses, keeps the old value-scan answer (residual: [#4446](https://github.com/go-to-k/cdkd/issues/4446), since closed).
