- **The API Gateway V2 provider masks secret-resolved values in its own log lines and failure messages (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), API Gateway V2 slice)** -- `src/provisioning/providers/apigatewayv2-provider.ts`; unit tests in `tests/unit/provisioning/apigatewayv2-provider-masked-log.test.ts`. `create()` and `update()` of `AWS::ApiGatewayV2::Api`, `Stage`, `Integration`, `Route` and `Authorizer` used to write their debug and warning lines through a logger no deploy-engine mask reaches, and only the Integration `ResponseParameters` warning was masked. They now route every line through the deploy's masker, including the Stage name (masked before it joins the sentence, so a secret shorter than four characters is caught too), the `TlsConfig` warning and the `ExecuteApiArn` warnings. The AWS error text a create or update failure message wraps is masked before it is joined; when the mask changed that text, the failure is stamped so the retry classifiers still read AWS's unmasked wording (the issue [#4244](https://github.com/go-to-k/cdkd/issues/4244) class), so a secret overlapping retry wording does not turn a transient failure terminal. A Stage whose recorded `StageName` is a secret reference or the redaction mask `***` has its name masked too, which covers a rotated secret whose old plaintext is in no bag of this deploy. Apart from a secret-derived Stage name, a secret shorter than four characters embedded in AWS error text is not caught. The `delete()` path still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
