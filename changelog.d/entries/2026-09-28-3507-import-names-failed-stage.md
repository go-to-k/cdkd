- **`cdkd import` names a CDK Stage that failed to load when stack selection comes back empty (issue [#3507](https://github.com/go-to-k/cdkd/issues/3507))** -- `src/cli/commands/import.ts`, with unit tests in `tests/unit/cli/import.test.ts`. A stack under a Stage whose manifest could not be read is dropped from the synthesized app, so `cdkd import MyStage/MyStack` answered `Stack 'MyStage/MyStack' not found in synthesized app`, and an app whose only stacks sit under such a Stage answered `Multiple stacks found: .` with no argument. import now raises the message `deploy`, `diff`, `list`, `publish-assets`, `scrub` and `synth` print: `No stacks matching <arg> found in assembly. Available: <stacks>` (or `The assembly has no stacks`, or `No stacks found in assembly` with no argument), plus the failed-Stage note naming the targeted Stage or listing every failed Stage behind `Possibly unrelated:`. The `Multiple stacks found` list now shows each stack's display path beside its physical name, rendered through the same sanitizer. Exit codes are unchanged. The argument is still matched exactly, and an argument containing `*` is told so, since the shared wording reads as a pattern match.
