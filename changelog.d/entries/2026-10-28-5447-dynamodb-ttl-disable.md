- **A DynamoDB `TimeToLiveSpecification` of `{ Enabled: false }` without an `AttributeName` now disables TTL (issue [#5447](https://github.com/go-to-k/cdkd/issues/5447))** -- `src/provisioning/dynamodb-ttl.ts`, `src/provisioning/providers/dynamodb-table-provider.ts`, `dynamodb-globaltable-provider.ts`. The CFn schema requires only `Enabled`, but `AWS::DynamoDB::Table` sent nothing for a name-less disable, so the deploy succeeded with TTL still enabled. Both table types now disable TTL on the attribute the previous deploy enabled, or, when none was recorded, on the one `DescribeTimeToLive` reports. A disabled spec no longer sends a disable that AWS refuses as `TimeToLive is already disabled`: creating a table (or global table) with `{ AttributeName, Enabled: false }` used to fail, as did removing a spec that was already disabled. On `AWS::DynamoDB::Table`, AWS's refusal of a second TTL change within its rate-limit interval is now reported as such instead of a bare `ValidationException`.
