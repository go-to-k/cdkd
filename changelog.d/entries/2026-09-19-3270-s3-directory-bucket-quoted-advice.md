- **The S3 directory-bucket not-empty refusal no longer pastes an UNQUOTED state-borne bucket name into a recursive-delete command (issue [#3270](https://github.com/go-to-k/cdkd/issues/3270))** -- `src/provisioning/providers/s3-directory-bucket-provider.ts`, `tests/unit/provisioning/providers/s3-directory-bucket-provider.test.ts`, `tests/integration/s3-directory-bucket/verify.sh`. When `cdkd destroy` refuses a non-empty `AWS::S3Express::DirectoryBucket` that has no auto-empty opt-in, the thrown message advised `aws s3 rm s3://<name> --recursive` with the name interpolated BARE. That name is the state-borne physical id (TEMPLATE-chosen), so one carrying `;`, a backtick, `$(...)` or a newline APPENDED a command to a recursive delete when pasted, in a THROWN message that also lands in `deployments/*.jsonl`. The command now renders through the shared `renderDisableCommand` (`displaySafe(asciiOnly)`, then `shellQuote`, then SUPPRESS the whole command when sanitizing CHANGED the value, since a command naming the sanitized name would empty a DIFFERENT bucket). The quoted unit is the ASSEMBLED `s3://<name>` argument, because `aws s3 rm` has no `--bucket` form. Two suppressions are specific to this site: a name containing `/` (`s3://a/b` addresses bucket `a`, and survives both sanitizing and quoting) and an empty name. A suppressed command becomes advice to use the console. The PROSE copy of the name in the same message is display-sanitized too, so a control byte cannot forge lines in the events store even when the command is suppressed. **A clean name renders BARE**, so the message for a well-formed bucket is byte-identical to before. No `maskSecrets` is passed: `DeleteContext` carries no masker by contract ([#2007](https://github.com/go-to-k/cdkd/issues/2007)). Residuals: the remaining bare-interpolating provider advice sites are [#3136](https://github.com/go-to-k/cdkd/issues/3136), provider-warning prose is [#3269](https://github.com/go-to-k/cdkd/issues/3269).
