- **The S3 directory-bucket not-empty refusal no longer pastes an UNQUOTED state-borne bucket name into a recursive-delete command (issue [#3270](https://github.com/go-to-k/cdkd/issues/3270))** -- `src/provisioning/providers/s3-directory-bucket-provider.ts`, `tests/unit/provisioning/providers/s3-directory-bucket-provider.test.ts`, `tests/integration/s3-directory-bucket/verify.sh`. The refusal for a non-empty `AWS::S3Express::DirectoryBucket` with no auto-empty opt-in advised `aws s3 rm s3://<name> --recursive` with the name interpolated BARE. That name is the state-borne physical id (TEMPLATE-chosen), so one carrying `;`, a backtick, `$(...)` or a newline APPENDED a command to a recursive delete when pasted, in a thrown message that also lands in `deployments/*.jsonl`. The command now renders through the shared `renderDisableCommand` (sanitize, `shellQuote`, SUPPRESS the whole command when sanitizing CHANGED the name, since the sanitized name is a DIFFERENT bucket). The quoted unit is the ASSEMBLED `s3://<name>` argument, because `aws s3 rm` has no `--bucket` form. Site-specific suppressions: a name containing `/` (`s3://a/b` addresses bucket `a`) and an empty name. A suppressed command becomes console advice. The PROSE copy of the name goes through `displayIdent`, so a control byte cannot forge lines in the events store. The refusal is now marked NON-RETRYABLE: `delete()` wraps it with the LOGICAL id, and the destroy and replacement-delete paths read `NotFoundException` / `NotFound` in a message as already deleted, so a logical id containing one had its non-empty bucket treated as gone. **A clean name renders BARE**: a well-formed bucket's message is byte-identical. No `maskSecrets`: `DeleteContext` has no masker ([#2007](https://github.com/go-to-k/cdkd/issues/2007)). Residuals: the other bare-interpolating advice sites are [#3136](https://github.com/go-to-k/cdkd/issues/3136), provider-warning prose is [#3269](https://github.com/go-to-k/cdkd/issues/3269).
