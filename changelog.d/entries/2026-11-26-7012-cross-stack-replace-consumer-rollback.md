- **`cdkd deploy`: a producer whose outputs another stack of the same run imports keeps its replaced resources until that stack has deployed (issue [#7012](https://github.com/go-to-k/cdkd/issues/7012))** -- `src/cli/commands/deploy/consumer-cleanup-hold.ts`, `src/cli/commands/deploy/{command,stack-deploy}.ts`, `src/deployment/deploy-engine/nested-cleanup.ts`, `src/deployment/nested-cleanup-scope.ts`. In `cdkd deploy Producer Consumer`, a producer that replaced an exported resource (a renamed queue) deleted the old copy at the end of its own deploy. When the consumer then failed, its rollback restored the old imported values, which named the deleted resource, so the consumer stayed broken. A producer whose outputs a stack of the run imports (`Fn::ImportValue`, `Fn::GetStackOutput`) now holds its cleanup phase until every such stack has deployed. If all of them succeed, the old copies are deleted as before. If one fails, is cancelled or never runs, the old copies stay recorded in the producer's state, one line says so, and the next deploy deletes them. A single-stack deploy, and a producer with nothing to delete, keep today's timing and make no extra AWS or S3 call. Tests: `tests/unit/deployment/consumer-cleanup-hold-7012.test.ts`, `tests/unit/cli/deploy-consumer-cleanup-hold-7012.test.ts`; integ `cross-stack-replace-consumer-rollback`.
