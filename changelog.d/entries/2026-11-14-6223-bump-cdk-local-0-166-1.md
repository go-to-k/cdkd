- **`cdkd local start-service` / `start-alb` with a bare `--assume-role` / `--assume-task-role` under `--from-state` now assume the deployed task role (issue [#6223](https://github.com/go-to-k/cdkd/issues/6223))** -- `package.json` (`cdk-local` `^0.166.0` -> `^0.166.1`). Before this change, the bare flag on an environment-agnostic stack assumed `role/<LogicalId>` (the synth-time form) instead of the deployed `role/<Stack>-<LogicalId>-<suffix>` recorded in state, so the role-permission emulation failed with `NoSuchEntity` and the service did not start. Now the bare flag resolves the deployed task role from the state source, as `run-task` already did.
