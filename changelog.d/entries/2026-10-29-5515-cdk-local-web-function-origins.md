- **`cdkd local start-web-function` serves a revision whose code key is selected from an `extract: false` `BucketDeployment`, and `cdkd local start-cloudfront` runs Lambda Web Function endpoint origins (issues [#5515](https://github.com/go-to-k/cdkd/issues/5515), [#5516](https://github.com/go-to-k/cdkd/issues/5516))** -- `package.json` (`cdk-local` `^0.156.0` -> `^0.157.0`), `src/cli/commands/local-start-cloudfront.ts` (doc comment and `--from-state` help), `src/cli/commands/local-start-web-function.ts` (doc comment), `docs/local-start-cloudfront.md`, `docs/local-start-web-function.md`, `docs/local-emulation.md`. Before this change, `start-web-function` refused a revision whose `CodeConfig.S3Object.Key` was `Fn::Select [i, Fn::GetAtt [<BucketDeployment>, SourceObjectKeys]]` as not a literal string. Now, when that deployment sets `extract: false`, the key resolves to the deployment's i-th source asset in `cdk.out`; an extracting deployment, a `destinationKeyPrefix`, `outputObjectKeys: false` or an index past the sources is refused with its own message. `start-cloudfront` used to warn and answer `502` for an origin whose `DomainName` is `Fn::GetAtt [<WebFunctionEndpoint>, DomainName]`. Now it runs that endpoint's revision in a container, as `start-web-function` does (the revision the endpoint weights pick, its `ServiceConfig` environment, its code from `cdk.out`), and forwards the origin requests to it, so the viewer-response function and the response headers policy apply to its responses. The OAC signing is skipped, as for the other origin types. An unreachable server answers `502`, one slower than the origin's read timeout `504`. Such a distribution now needs Docker and fails at startup without it; `--origin <id>=<dir>` stands in for the origin.
