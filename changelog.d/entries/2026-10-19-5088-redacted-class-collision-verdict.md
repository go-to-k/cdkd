- **A redacted AWS failure whose class name contains `AlreadyExists` is no longer retried as a name collision when AWS's own message describes something else (issue [#5088](https://github.com/go-to-k/cdkd/issues/5088))** -- `src/deployment/retryable-errors/name-collision.ts`. A provider wrap that withholds AWS's text reduces the failure to its class, such as `HostedZoneAlreadyExists. Re-run with --verbose for AWS's own message.` The delete-then-re-create retry filter read that class as an "already exists" collision. Route 53's `HostedZoneAlreadyExists` reports a reused caller reference, not a taken name, and S3's `BucketAlreadyExists` reports a name held by another account. Both were retried for about 64 seconds before failing. For a wrap marked as withholding text, the filter now ignores the class in that reduced message and reads AWS's own message on the `cause` chain, plus any "AWS reports that it already exists." sentence the provider restated. Genuine collisions and name cooldowns are still retried. Tests: `tests/unit/deployment/redacted-already-exists-class-5088.test.ts`.
