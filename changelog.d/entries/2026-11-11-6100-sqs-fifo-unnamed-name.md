- **An un-named FIFO SQS queue, or SNS topic, now deploys (issue [#6100](https://github.com/go-to-k/cdkd/issues/6100))** -- `src/provisioning/resource-name/fallback-rules.ts`, `src/provisioning/resource-name/fallback.ts` and `src/provisioning/providers/sqs-queue-provider.ts`, plus a new `sqs-fifo-unnamed` integ. Before, `new sqs.Queue(this, 'Q', { fifo: true })`, which synthesizes `FifoQueue: true` and no `QueueName`, failed to deploy with `InvalidParameterValue`: cdkd sent its standard generated name, and SQS refuses a FIFO queue whose name does not end with `.fifo`. A replacement onto such a queue failed the same way, as did an L1 `CfnTopic` with `FifoTopic: true` and no `TopicName` (`src/provisioning/providers/sns-topic-provider.ts`; CDK names an L2 FIFO topic itself). Like CloudFormation, cdkd now ends the generated name of a FIFO queue or topic with `.fifo`, counted within the 80-character (queue) or 256-character (topic) limit and kept when a long name is truncated. `FifoQueue` / `FifoTopic` given as the string `'true'` counts too. The name-collision lookup, the Cloud Control route and the replacement-name checks derive the same name as the create. A `FifoQueue` or `FifoTopic` given as an intrinsic (`Ref`, `Fn::If`) has its name looked up at the create, once it resolves; `src/deployment/generated-name-guard.ts` derives the name again from the resolved properties and refuses a create whose name differs from the one it checked.
