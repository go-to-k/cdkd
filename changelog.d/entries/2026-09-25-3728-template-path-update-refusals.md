- **A template-path update now refuses five malformed values that it used to deploy with a warning (issue [#3728](https://github.com/go-to-k/cdkd/issues/3728))** -- `src/provisioning/providers/{dynamodb-table,cognito,route53,s3-bucket,ec2}-provider.ts`, `docs/provider-rules.md`.
  - Refused on `cdkd deploy`, before any write to AWS: a per-index `ProvisionedThroughput` of `{0, 0}` on an `AWS::DynamoDB::Table` whose index capacity changes or is new; a malformed `AWS::Cognito::UserPool` `MfaConfiguration`; a changed, malformed `AWS::S3::Bucket` `VersioningConfiguration.Status` or `LoggingConfiguration` member; an `AWS::Route53::RecordSet` update that renames the record into a name containing `|`; and an `AWS::EC2::Route` declaring more than one destination.
  - Each used to warn and continue on every update, because `update()` could not tell a template deploy from a rollback or `cdkd drift --revert` replaying a state record. The rollback revert arms (`replayingState`) and `drift --revert` (`desiredFromAwsReadback`) still take the warning: their properties are not editable from the template.
  - Kept as a warning on every path: the `|` separator check on an `AWS::Route53::RecordSet` whose recorded name already contains it, and on an `AWS::EC2::Route` (both segments are create-only). The only template fix there is a different resource.
  - The Glue `DatabaseInput` arm is not part of this change.
