- **Eleven more SDK-provider types with no Cloud Control handlers keep an unrecognized property on the SDK route instead of failing mid-deploy on Cloud Control (issue [#3871](https://github.com/go-to-k/cdkd/issues/3871))** -- `src/provisioning/unsupported-types.ts` (`SDK_PROVIDER_NON_PROVISIONABLE_TYPES`, `hasNoCloudControlHandlers`), `src/provisioning/provider-registry.ts`, `src/provisioning/property-coverage.ts`, `src/provisioning/property-coverage.generated.ts`, `scripts/gen-property-coverage.ts`, `scripts/diagnose-schema-refresh.mjs`, with unit tests in `tests/unit/provisioning/non-provisionable-unrecognized-route-3871.test.ts` and `tests/unit/provisioning/property-coverage-cc-fallback-binding.test.ts`. AWS reports `AWS::AppSync::GraphQLSchema`, `AWS::BedrockAgentCore::Browser`, `AWS::BedrockAgentCore::CodeInterpreter`, `AWS::Budgets::Budget`, `AWS::CloudFormation::WaitConditionHandle`, `AWS::EC2::NetworkAclEntry`, `AWS::Glue::Table`, `AWS::IAM::Policy`, `AWS::IAM::UserToGroupAddition`, `AWS::SNS::TopicPolicy` and `AWS::SQS::QueuePolicy` as `NON_PROVISIONABLE`. Even so, a template key cdkd's schema snapshot does not know routed the resource to Cloud Control, which failed with an opaque `UnsupportedActionException`. The resource now stays on its SDK provider and the deploy warns that the key has no Cloud Control route. The decision is per resource type, so types sharing a provider with these, such as `AWS::EC2::NetworkAcl` or `AWS::Glue::Database`, keep their Cloud Control route. For the eight such types that already refused, a refusal now names `ProvisioningType: NON_PROVISIONABLE` as the reason.
