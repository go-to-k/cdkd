- **The SDK provider sends the network type, license model, promotion tier, Database Insights mode, dedicated log volume, `AllowMajorVersionUpgrade` and `CertificateRotationRestart` of `AWS::RDS::DBInstance`, and an unchanged `EngineVersion` is no longer re-sent (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and new arms in the `rds-dbinstance-backfill` and `rds-aurora` integs. Before, a DB instance declaring any of `NetworkType`, `LicenseModel`, `PromotionTier`, `DatabaseInsightsMode`, `DedicatedLogVolume`, `AllowMajorVersionUpgrade` or `CertificateRotationRestart` routed through Cloud Control; the writer and reader instances of a CDK `rds.DatabaseCluster`, which emit `PromotionTier`, among them. The first five now ride `CreateDBInstance`, and each of the seven `ModifyDBInstance` when the template changes it, `CertificateRotationRestart` only beside a changed `CACertificateIdentifier`, as CloudFormation sends it; a removed one keeps its live value, as CloudFormation keeps it. An update re-sent the template's `EngineVersion` on every deploy, which RDS refused as a downgrade once AWS had auto-upgraded the minor version; it now goes out only when the template changes it, and never on a rollback replay. `AllowMajorVersionUpgrade` is now the template's own value: a major-version change with no `AllowMajorVersionUpgrade: true` is refused by RDS, as it is under CloudFormation, where cdkd used to add the flag itself. `cdkd drift` reads the five back.
