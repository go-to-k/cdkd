- **Glue table update / destroy / drift decode the recorded id by its `DatabaseName` (issue [#1672](https://github.com/go-to-k/cdkd/issues/1672))** -- `src/provisioning/providers/glue-provider.ts`, `tests/unit/provisioning/composite-id-provider-guards.test.ts`. An `AWS::Glue::Table` id is `<databaseName>|<tableName>` with an unescaped `|`. A table name containing `|` (recorded by a state-replay create, or by binaries before the create-time refusal) was split into two segments, so `cdkd destroy` deleted a different table, `update` targeted it, and `cdkd drift` read it. The three decode sites now anchor on the `DatabaseName` recorded in state and take the rest of the id as the table name. Without a usable `DatabaseName`, an id with more than one `|` is treated as malformed, the same as an empty segment: destroy skips it and keeps the record, update fails, and drift reads nothing. The record format is unchanged, and `createTable` / `import` still refuse a `|` in either name, because the `Ref` resolver still returns the segment after the last `|`.
