- **A rollback that re-creates an old resource the failed deploy had already deleted says its contents do not come back (issue [#6713](https://github.com/go-to-k/cdkd/issues/6713))** -- `src/deployment/rollback-executor/early-deleted-old.ts` (new), `src/deployment/rollback-executor/replay-reverse-replacement.ts`, `src/cli/commands/rollback/render.ts`. Where cdkd still deletes a replaced resource's old copy before the deploy succeeds (the delete-first routes, a new resource keeping the old id and type), reversing the replacement re-creates the old copy from its recorded properties only. That was reported only for a stateful type; for any other (an SQS queue's messages, an SNS topic's subscriptions made outside the stack) the rollback re-created it silently. The rollback now prints an advisory line for it, and the `cdkd rollback` plan's `reverse-replace` row names the same consequence. Inline IAM policies, whose record restores the whole document, are exempt; the stateful line is unchanged, and neither line changes the exit code.
