- **A `NoEcho` custom-resource value EMBEDDED in a longer string no longer reaches `state.json` (issue [#2453](https://github.com/go-to-k/cdkd/issues/2453))** -- `redactSecretsForState`, `carriesFreshNoEchoValue`, `freshNoEchoLeafPositions` and `mergeResolvedPairs` in `src/deployment/secret-redaction.ts`, the `Fn::GetAtt` and `Fn::Base64` registrations in `src/deployment/intrinsic-function-resolver.ts`, unit tests in `tests/unit/deployment/`, and the `custom-resource-getatt-data` fixture, which gains an embedded dependent, an embedding output and a rotated-token phase. A dependent property or stack output built around the value (`postgres://user:${cr.getAttString('Password')}@host`) was persisted in the clear, because the mask replaced only a leaf EQUAL to the value; the same held for the `Fn::Base64` encoding of a secret inside a longer leaf. Such a leaf is now persisted as `***` WHOLE -- not with an inline mask, which nothing downstream could recognise -- so `cdkd drift --revert` / `--accept` and the rollback replay refuse it as they refuse any masked value, and the next deploy that re-runs the handler still updates the dependent. An occurrence that lies inside a `{{resolve:...}}` reference's own text leaves the leaf alone. A value EQUAL to text state already holds in the clear (the region, the stack name, a literal template property of the custom resource, its `ServiceToken` or one of that ARN's `:`-separated parts, such as the account id) is not matched inside a longer leaf, so a handler echoing it under `NoEcho` does not mask every ARN of its dependents. The cost: the public text around the value is gone from the record, and any leaf of the same resource that happens to contain the value is masked too. A record an earlier cdkd wrote keeps the plaintext until the handler runs again and the consumer is rewritten.
