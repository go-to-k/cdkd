- **`cdkd local start-api` / `local invoke` bracket an IPv6 host in the URLs they print and fetch (issue [#2338](https://github.com/go-to-k/cdkd/issues/2338))** -- `src/utils/url-authority.ts` (new), `src/cli/commands/local-start-api.ts`, `src/local/rie-client.ts`, `src/utils/proxy-routing-agent.ts`, their unit tests. Before, `--host ::` printed `Server listening on http://:::3000`, which no URL parser accepts, and the per-API route-table header had the same defect. An IPv6 `--container-host` on either command also broke the RIE readiness probe and the Lambda invoke, because `fetch('http://::1:<port>/...')` throws `Invalid URL` before sending. Every one of these sites now composes its authority through `formatAuthority`, which brackets an IPv6 literal (`http://[::]:3000`) and drops a zone id, which no URL parser accepts. IPv4 and hostname output is byte-identical. This follows go-to-k/cdk-local#599; the `start-alb` / `start-service` / `start-cloudfront` / `start-agentcore` banners already carry that fix through the cdk-local dependency.
