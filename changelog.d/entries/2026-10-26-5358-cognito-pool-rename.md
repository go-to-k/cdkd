- **`AWS::Cognito::UserPool` update now renames the pool, and refuses a change it cannot apply (issue [#5358](https://github.com/go-to-k/cdkd/issues/5358))** -- `src/provisioning/providers/cognito-provider.ts`. `update()` never sent `PoolName`, so a changed `UserPoolName` deployed successfully while AWS kept the old name; it is now sent, and the pool is renamed in place under the same id, as CloudFormation does. A template that drops `UserPoolName` still sends nothing and keeps the live name, which is also what CloudFormation does. A change to `UsernameAttributes`, `AliasAttributes` or `UsernameConfiguration` (removals included) was dropped the same way, because `UpdateUserPool` has no member for them. CloudFormation refuses those changes ("Updates are not allowed for property"), and cdkd now refuses them before any call with the typed not-updatable error. The error points to `--replace --force-stateful-recreation`. A rollback revert or `cdkd drift --revert` warns instead and leaves the live value. Covered by `tests/unit/provisioning/cognito-update-pool-name-5358.test.ts` and a rename phase plus a refused-change phase in the `cognito-custom-attribute-add` integ.
