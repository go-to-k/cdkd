- **State schema v13: a stack records the id of its current lifetime (issue [#5064](https://github.com/go-to-k/cdkd/issues/5064), part 1)** -- `src/types/state.ts`, `src/state/stack-instance-id.ts`, `src/state/s3-state-backend.ts`, `src/deployment/deploy-engine/deploy-flow.ts`, `src/cli/commands/import.ts`. A stack's first state write (its first deploy, the partial save of a failed first deploy, or `cdkd import` creating the record) records `stackInstanceId`, a random id kept until the record is deleted; a recreated stack gets a new one. A first deploy writes it ahead to `stack-instance.json` beside `state.json`, before any resource is created, so a re-run after a crash reuses it; the object is deleted once `state.json` carries the id, and with the record on destroy, `state orphan`, export and a rolled-back first deploy. A stack that already has a record keeps no id (legacy) and its deploys make no extra AWS call; a first deploy adds one read and one write, `--dry-run` none. Nothing reads the id yet: resource names are unchanged. Older binaries fail on v13 with "Upgrade cdkd".
