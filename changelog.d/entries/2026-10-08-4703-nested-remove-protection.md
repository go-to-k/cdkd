- **`cdkd rollback --remove-protection` now reaches a deletion-protected resource the failed deploy created inside an existing nested stack (issue [#4703](https://github.com/go-to-k/cdkd/issues/4703))** -- `src/deployment/nested-child-journal.ts`, `src/cli/commands/rollback.ts`. A nested stack's row is reverted by replaying that child's own journal, and that replay never received the flag: a protected resource whose CREATE completed in the child before a later parent resource failed (a load balancer with `deletion_protection.enabled`, an EC2 instance with `DisableApiTermination`) was deleted without it, AWS refused, and `cdkd rollback --remove-protection` exited non-zero until the protection was cleared by hand. The flag now travels into the child's replay, where a completed CREATE is the child's own state record, deleted as the stack's is; a foreign-holder scan scoped to the child travels with it. A deploy's automatic rollback still never turns protection off. Test: `tests/unit/deployment/nested-child-remove-protection-4703.test.ts`; integ `remove-protection-journaled-orphan`.
