- **A Step Functions secret is no longer written to `observedProperties` in plaintext by `cdkd state refresh-observed` or the deploy-start auto-refresh (issue [#5315](https://github.com/go-to-k/cdkd/issues/5315))** -- `src/deployment/secret-redaction/readback-certification.ts`. A state machine whose `DefinitionSubstitutions` value (or whose definition body) carries a `{{resolve:secretsmanager:...}}` / `{{resolve:ssm-secure:...}}` reference or a `NoEcho` value reads back as `Definition` with the value substituted. With no resolved secrets in hand (those two paths, and `cdkd import`'s observed capture), nothing paired that key with the reference, so the resolved secret was persisted to the state file. Every string leaf of a read-back `Definition` / `DefinitionString` that the record's own definition does not spell, with its substitutions applied as written, is now stored as `***`, and so is a number or boolean it does not spell (a `${name}` outside quotes reads back as a JSON number); state names, types and non-secret substituted values are kept, and a leaf the walk already redacted to its expression keeps it. The same rule applies to the `cdkd drift --accept` / `--revert` baselines, where a leaf already redacted to its expression is kept when the record holds the definition body. For a `DefinitionS3Location` definition, whose body the record does not hold, every string, number and boolean leaf other than a whole substitution value is masked. The deploy's own capture, which resolves the secret, now also replaces a numeric substituted secret in `Definition` with its expression. `cdkd drift` reports such a mask as `uncertifiedBaseline` (exit 2) rather than as drift. A record written before this fix keeps the plaintext until `cdkd state refresh-observed` is run again.
