- **`AWS::DocDB::DBCluster`: removing `Port` from the template now resets the cluster to 27017, as CloudFormation does (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/docdb-provider.ts`, `src/provisioning/providers/neptune-provider.ts`. A CloudFormation A/B on the issue (us-east-1, 2026-10-27) removed a declared non-default port from each cluster type. CloudFormation reset the DocDB cluster to 27017 and kept the Neptune cluster's `DBPort`. Before, cdkd sent nothing for a removed DocDB `Port`, so the old port stayed. A removal whose previous value already was 27017 still sends nothing. A DocDB cluster update that changes the port now waits until the cluster reports the new one, so `Fn::GetAtt <cluster>.Port` reads it in the same deploy (`--no-wait` skips the wait). A removed Neptune `DBPort` (or legacy `Port`) still sends nothing, which matches CloudFormation. Tests: `tests/unit/provisioning/docdb-provider-port-removal-1160.test.ts`, `tests/unit/provisioning/neptune-provider-update-removal.test.ts`. The `docdb-neptune` integ's removal phase also drops both clusters' non-default ports.
