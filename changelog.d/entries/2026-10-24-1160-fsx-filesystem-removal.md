- **`AWS::FSx::FileSystem`: the warning for a removed `StorageCapacity`, `StorageType` or `NetworkType` now says CloudFormation keeps the value too (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/fsx-filesystem-provider.ts`. A CloudFormation A/B on the issue (us-east-1, 2026-10-23) removed each property in its own update. Every update completed in place, with the same file system and no FSx administrative action. An OpenZFS `SINGLE_AZ_1` file system kept `NetworkType` `DUAL`, `StorageCapacity` and `StorageType` `SSD`. A Lustre `PERSISTENT_1` file system kept `StorageType` `HDD` and `StorageCapacity`. cdkd already left these values in place, so only the warning changes: it now reads `... and keeps its current AWS value, as CloudFormation leaves it; ...`. The claim is made only for the file system types measured (Lustre and OpenZFS, and `NetworkType` on OpenZFS only), and never for an `INTELLIGENT_TIERING` file system. A warning that names an unmeasured property, such as a Windows or ONTAP removal or a Lustre `NetworkType`, keeps its old wording. Tests: `tests/unit/provisioning/providers/fsx-filesystem-provider.test.ts`; the `fsx-openzfs` integ gains a phase that removes all three.
