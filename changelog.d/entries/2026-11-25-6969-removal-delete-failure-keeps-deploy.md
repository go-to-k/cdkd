- **`cdkd deploy`: a removed resource whose delete AWS refuses no longer rolls back the whole deploy (issue [#6969](https://github.com/go-to-k/cdkd/issues/6969))** -- `src/deployment/deploy-engine/execute.ts`, `src/deployment/deploy-engine/execute/removal-delete-kept.ts`, `docs/cli-destroy-skipped.md`. CloudFormation deletes a removed resource in its cleanup phase and ends `UPDATE_COMPLETE` when that delete fails. cdkd now keeps the resource's state record instead of failing: it warns, counts it under `Skipped (not deleted)` (exit `2`, `0` with `--allow-unaddressed`), keeps the deploy's other changes, keeps every resource the failed one depends on, and the next deploy retries the delete. A bucket that still holds objects, or a Lambda version an alias still routes to, no longer undoes the rest of the deploy. An interrupted delete, or one past its `--resource-timeout`, still fails it. Tests: `tests/unit/deployment/deploy-engine-removal-delete-failure-6969.test.ts`.
