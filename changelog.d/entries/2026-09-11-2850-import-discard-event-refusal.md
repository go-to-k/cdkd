- **`cdkd import`'s observed-baseline refusal now detects DISCARD events, not just lost opener counts (issue [#2850](https://github.com/go-to-k/cdkd/issues/2850))** -- `src/cli/commands/import.ts`, `tests/unit/cli/import-observed-baseline-refusal-matrix.test.ts`, `docs/import.md`, `.claude/rules/layout-deployment-secrets.md`. **Bug:** the success-arm refusal compared `{{resolve:` opener COUNTS over the raw property bag, so a reference the bag never spelled was persisted DECRYPTED into `observedProperties` -- the GHSA-p5qg-v9gv-hc7w direction. Measured leaking shapes: a downgraded `Fn::If` dropping one reference while a parameter-`Default`-sourced one is ADDED elsewhere (totals balance); a reference sourced from a parameter `Default` or `Mappings` then dropped (both counts zero, no warn); multi-key dispatch sibling drops; and, from review, `Fn::FindInMap`'s LAZY 4-arg `DefaultValue` (discarded unresolved on a lookup hit) plus non-literal lookup keys, and `Fn::Select`'s RAW-consumed index (a non-static index discards the eagerly-decrypted list). **Fix:** a third refusal arm, `resolveDiscardsNonInertSubtree`, statically detects those discard events on the raw bag and refuses a baseline when any discarded subtree is not provably inert (pure literals, no opener text, no intrinsic-shaped key; `{Ref: 'AWS::NoValue'}` counts inert -- it cannot produce a value). Source-blind but fail-closed, so reference sources need no enumeration; the walk itself fails closed -- a bag too deep to traverse REFUSES rather than aborting the import mid-write. Additive: refusal only widens. **Cost:** an `Fn::If` (or keyed lookup) discarding a benign intrinsic loses its drift baseline until that resource's next deploy; pure-literal discards stay admitted. **Not closed:** placeholder-`Default` value divergence ((#2854)), readback-only secrets ((#2868)), refused baselines refilled by later writers ((#2944)); option (b) priced and deferred on the issue thread.
