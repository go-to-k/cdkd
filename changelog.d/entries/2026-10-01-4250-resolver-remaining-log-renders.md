- **A value on the resolver's other log lines no longer runs when the line is pasted (issue [#4250](https://github.com/go-to-k/cdkd/issues/4250))** -- `src/deployment/intrinsic-function-resolver.ts`. go-to-k/cdkd#4161 bounded the `Resolved …` debug lines; the rest still printed a template-, state- or AWS-chosen value bare, several at default verbosity: the `Resolved Fn::ImportValue` / `Fn::GetStackOutput` lines and their `Resolving` twins, the undeclared- and failed-condition warns, the `Unknown attribute` / stale-record fallback warns, the `VPC Ipv6CidrBlocks` and `DescribeLaunchTemplates` lines, the state-scan lines, the `Parameter …` lines, the dynamic-reference `Resolving` lines, the `Fn::Cidr` lines, the `Fn::Sub` keep-placeholder and `Ref` not-found warns, and the CloudFormation-fallback warns. Each value now follows the same rule: printed when it is shell-inert, otherwise `a value that cannot be shown safely here`, also where AWS's message beside it echoes the value. A name cdkd quotes is quoted only when inert. A value the display sanitizer would alter (padding, a control or bidi character) is described rather than printed trimmed, and a NAME holding non-ASCII is too (`ProdЖ` could pass for `Prod`); an inert non-ASCII value such as `café` still prints. A JSON render (`Fn::Cidr`, `Ipv6CidrBlocks`, a list parameter) prints while it still parses after masking with inert strings, so a secret that ate a `"` no longer unbalances it. The `Fn::GetStackOutput` log lines, its DescribeStacks warn and its malformed-record refusal now describe a non-inert stack, output or region instead of JSON-quoting it, and the cross-stack origin in `Re-resolving dynamic reference(s) in …` names its producer the same way. Ordinary and masked values print as before. Tests: `tests/unit/deployment/resolver-remaining-log-paste-4250.test.ts`, plus the pins in the resolver suites.
