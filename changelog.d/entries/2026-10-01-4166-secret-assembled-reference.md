- **A secret substituted into the name of a `secretsmanager` / `ssm` / `ssm-secure` reference is no longer persisted in `state.json` inside that reference (issue [#4166](https://github.com/go-to-k/cdkd/issues/4166))** -- `src/deployment/intrinsic-function-resolver.ts`, `src/deployment/secret-redaction.ts`, `docs/troubleshooting.md`; cases in `tests/unit/deployment/intrinsic-resolver-secret-assembled-reference.test.ts`. A token such as `{{resolve:ssm:/app/${Name}}}` with `Name` a secret resolved, and the resolver recorded the assembled token as the expression of its secret result, so every state writer (the frame, skeleton, whole-value and substring arms) wrote the other secret's plaintext into state inside the reference. Such a token, with a secret in its name or in any other field (a JSON key, a version stage), is now refused with a masked, non-retryable `Refusing to resolve` once it has resolved to a secret, before anything is recorded or cached, on the template route only; the detector is the one the unsupported-service refusal uses (issue [#2743](https://github.com/go-to-k/cdkd/issues/2743)), except that a four-or-more-character secret found in the token's text counts only when a parent stack passed it in (a secret this stack's deploy resolved, coinciding with a literal token, does not). A secret whose value is itself reference text, resolved again, is refused too (`Refusing to resolve ***`), and `cdkd import` warns with the refusal. **Behaviour change:** a resource property holding such a token now fails the deploy, which went green before; a stack Output holding one is skipped with a warning, as any failed output is (it fails the deploy under `--strict-getatt`). A public or empty result, a failed lookup, and persisted text (`cdkd drift`, the rollback replay) are unchanged. `cdkd scrub` leaves text inside a resolvable reference as written, so a record written before this change keeps the other secret until the template is fixed and redeployed.
