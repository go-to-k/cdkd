- **A fix-forward deploy now deletes the CloudWatch Logs log group an earlier failed CREATE left behind (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606), log group slice)** -- `src/provisioning/providers/logs-loggroup-provider.ts`. When a `cdkd deploy --no-rollback` made an `AWS::Logs::LogGroup`, failed configuring it (its retention, data protection or index policy, or bearer-token setting) and could not delete it again, and a later deploy kept the logical id under another name, the successful deploy warned about the earlier log group, left it in AWS and exited 2; `cdkd rollback` and `cdkd destroy` kept it the same way. The provider now answers both questions: a log group name is unique per account and region and cannot be changed, so the earlier one is a different one once the record's reads back (two names equal ignoring case are never compared); and the failed deploy records the log group's ARN and the `creationTime` CloudWatch Logs reports for it, so the earlier one is deleted only while its name still reads back with that creation time. One deleted by hand and re-created under the name has another creation time and is kept, with a warning. No ordinary deploy makes an extra call: the creation time is read only when a failed CREATE is journaled. Tests: `tests/unit/provisioning/logs-loggroup-provider-same-resource-4606.test.ts`; integ: `logs-loggroup-fix-forward-orphan`.
