- **The SDK provider sends `EngineMode` and `AvailabilityZones` for `AWS::RDS::DBCluster` (issue [#5639](https://github.com/go-to-k/cdkd/issues/5639))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and a new arm in the `rds-aurora` integ. Before, a cluster declaring either routed through Cloud Control. Both now ride `CreateDBCluster` as declared, as CloudFormation's create sends them. `EngineMode` is create-only, so a change replaces the cluster. An update sends no `AvailabilityZones`: `ModifyDBCluster` has no such member and CloudFormation's update sends none, so a changed or removed list completes in place and the cluster keeps its zones. A list that is not all Availability Zone names is refused before any call. An empty list sends nothing, so RDS picks the zones. `cdkd drift` reads back neither, because nothing can change them after the create, and skips both, with `ClusterScalabilityType` and `MasterUserAuthenticationType`, when its baseline is the recorded template (an import whose readback failed). `ScalingConfiguration` is now marked as unwired by design: it applies only to Aurora Serverless v1, which AWS has retired, and a template declaring it still routes through Cloud Control. Resources already deployed through Cloud Control stay there.
