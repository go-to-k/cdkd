- **`Fn::GetAtt` of an attribute CloudFormation defines no longer silently resolves to the resource's physical ID (issue [#6242](https://github.com/go-to-k/cdkd/issues/6242))** -- `src/deployment/intrinsic-resolver/getatt-refusals.ts`, `scripts/gen-sdk-attr-coverage.ts`, unit tests and docs. When cdkd's SDK provider created a resource and neither its state record nor a resolver rule can answer an attribute CloudFormation defines for the type (a read-only attribute of its schema), the deploy now fails with an error naming the resource and the attribute, instead of warning `Unknown attribute ..., returning physical ID` and passing the physical ID on. Measured against CloudFormation, the physical ID was the wrong value for almost every such attribute; the ones whose value really is the physical ID are still served: the resource's own identifier (such as a secret's `Id`), its own ARN when the physical ID is that ARN, and a few measured ones (an API Gateway account's, a budget's, an EFS mount target's and an SQS queue policy's `Id`). A resource provisioned through Cloud Control keeps the warning. Under `--no-wait`, a reference to a value AWS has not reported yet (a creating DB instance's `Endpoint.Address`) now fails rather than receiving the instance identifier; deploy again once the resource is available. `cdkd diff` shows a reference it cannot resolve this way as a change, since the deploy would refuse it. `docs/_generated/sdk-attr-coverage.md` lists most of the attributes cdkd cannot answer yet.
