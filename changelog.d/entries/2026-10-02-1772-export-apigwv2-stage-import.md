- **`cdkd export` imports an HttpApi's `AWS::ApiGatewayV2::Stage` in place instead of deleting it and letting CloudFormation re-create it (issue [#1772](https://github.com/go-to-k/cdkd/issues/1772))** -- `src/cli/commands/export.ts`, `docs/cli-export.md`, the `export` integ fixture and the export unit tests. The stage sat in `IMPORT_UNSUPPORTED_RECREATABLE_TYPES` because CloudFormation once refused it in IMPORT changesets, so every export of a stack with an `HttpApi` (CDK auto-emits a `$default` stage) pre-deleted the stage between the two phases and left the API serving no stage for roughly ten seconds until phase 2 re-created it. The registry now reports the type `FULLY_MUTABLE` with a `read` handler and a `[ApiId, StageName]` primary identifier, and AWS's import-support table lists it as importable, so the stage leaves that list and its pre-delete handler, and joins `COMPOSITE_ID_SPLITTERS`: the bare `StageName` the SDK provider records is paired with the recorded `ApiId`, and Cloud Control's `<apiId>|<stageName>` is split. Neither field is read-only, so the whole identifier map is overlaid. `--no-recreate-import-unsupported` no longer applies to the stage, and the by-hand recovery after a failed pre-delete no longer prints `aws apigatewayv2 delete-stage`.
