- **Deleting an `AWS::ElastiCache::CacheCluster` no longer fails when it takes more than ten minutes (issue [#4029](https://github.com/go-to-k/cdkd/issues/4029))** -- `src/provisioning/providers/elasticache-provider.ts`. cdkd waited at most ten minutes for a cache cluster to be gone, while a Redis delete can take longer; the delete then failed with `Timed out waiting for CacheCluster ... to be deleted`, and every retry failed again because AWS refuses a second delete of a cluster that is already `deleting`. The wait now uses the same 60-minute limit as the Cloud Control route, and a cluster that is already `deleting` is waited on instead of failing. Found by the new `cc-final-snapshot-handlers` integration fixture.
