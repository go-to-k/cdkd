- **`cdkd destroy` masks a physical name derived from a secret on a journaled orphan's delete lines and in its deployment events (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/secret-name-needles.ts`, `src/deployment/rollback-executor/journaled-orphans.ts`, `src/cli/commands/destroy-runner.ts`. A resource a failed deploy created before failing is recorded only in the rollback journal, and `cdkd destroy` deletes it from there. When its name came from a secret, that delete's provider lines and final-snapshot lines printed the name: they ran under no printing bag. They now run under one judged from the journal entry itself (its type, recovered physical id and attempted properties), plus the names the entry read from a state record. The same deletes also run when a successful deploy acts on its journal. Separately, the `reason` and error message of each destroy event (`RESOURCE_FAILED`, `RESOURCE_SKIPPED`, `RESOURCE_GUARD_INDETERMINATE`, and a journaled orphan's rollback events, on the deploy-success path too) were stored verbatim in `deployments/*.jsonl`, while the log line beside them was masked. They are now masked with the same needles. An event's `physicalId` field stays exact. Tests: `tests/unit/cli/destroy-journaled-orphans-secret-name-3869.test.ts`, `tests/unit/deployment/secret-name-needles-3869.test.ts`; integ `secret-derived-immutable-names` gains step 6b, which destroys a failed-CREATE ECR repository named from the secret.
