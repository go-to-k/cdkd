- **A Lambda Managed Instances app whose `AWS::Lambda::CapacityProvider` has no `CapacityProviderName` deploys, instead of failing with `Resource Handler Internal Failure` (issue [#3174](https://github.com/go-to-k/cdkd/issues/3174))** -- `src/provisioning/resource-name.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/retryable-errors.ts`. The type has no SDK provider, and a Cloud Control create without the name fails although the schema does not require it. It now has a `FALLBACK_NAME_RULES` entry, so cdkd generates `<stack>-<logicalId>` (140-character cap) on the create; a template-supplied name is kept. The generated name is no longer sent on a Cloud Control UPDATE, for every type in that table: the recorded bag never holds it, so each update patch used to `add` it -- a refused change for a resource running under another name where the name is create-only, a rename where the type accepts it (`AWS::Cognito::UserPool`'s `UserPoolName`). The create is also retried as IAM propagation when it fails with "The operator role is invalid or doesn't have sufficient permissions": CDK creates that role in the same stack, and the first deploy failed on it single-shot (measured: rejected 8s after the role's policy was attached, accepted at 23s). The entry admits the type to rollback-orphan re-adoption (go-to-k/cdkd#2934); a create under an existing name fails with `AlreadyExists` (measured). Live coverage: `tests/integration/lambda-capacity-provider-default-name/`.
