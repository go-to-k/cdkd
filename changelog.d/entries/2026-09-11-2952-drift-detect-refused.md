- **`cdkd drift` no longer prints the live secret for a resource whose observed baseline `cdkd import` refused (issue [#2952](https://github.com/go-to-k/cdkd/issues/2952))** -- `src/cli/commands/drift.ts`, `tests/unit/cli/drift.test.ts`, `docs/cli-drift.md`, `docs/state-management.md`. **Bug:** detection picked `observedProperties ?? properties`, so a refused record (schema v10's `observedBaselineRefused`, (#2944)) was compared against the recorded `properties` -- which after a downgraded `Fn::If` hold the WRONG-BRANCH LITERAL while AWS holds the secret the deployed branch resolved. Both masking inputs are EMPTY for such a record, for the same reason: `secretPaths` comes from RESOLUTION and its offline fallback scans for where `{{resolve:` strings ARE, and a refused record spells none. So nothing marked the path secret-bearing and the decrypted value rendered as the AWS side of an ordinary drift row -- human report, `--json`, and both plans. Reachable since (#2828) introduced the refusal; (#2944) only made it detectable. **Fix:** a fourth `NotComparedCause`, `baselineRefused`. Detection reports such a resource `notCompared` rather than `drifted`, and the gate sits BEFORE the provider lookup, so cdkd does not read the resource back from AWS at all -- the plaintext never enters the process. `notCompared` rather than `clean`: a silent `clean` is the "report a resource cdkd never compared as a pass" failure the cause enumeration exists to prevent. **Exit code:** the new cause inherits `outcomeExitSignal`'s non-zero side, which that switch already defaults a new member to -- correct here, since a refusal is CLEARABLE by deploying a change to the resource. **Consequence:** the (#2944) `--accept` / `--revert` refusals become a second layer, since a marked resource no longer becomes `drifted` at all. **Not closed:** a baseline refused by a PRE-v10 binary carries no marker, so none of these guards fire for it — (#3011).
