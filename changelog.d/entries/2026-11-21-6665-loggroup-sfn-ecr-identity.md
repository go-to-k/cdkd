- **A CloudWatch Logs log group, Step Functions state machine or ECR repository delete refuses one re-created under the recorded name, and a rollback refuses a same-named one someone else created (issue [#6665](https://github.com/go-to-k/cdkd/issues/6665))**. All three are deleted by name, so one created again under the name outside cdkd was deleted by a destroy, removal, replacement or rollback. The create, update and import now record when it was created: `LogGroupIdentity` (`<logGroupArn>@<creationTime>`), `CreationDate`, `CreatedAt` (ISO UTC, whole seconds). A record holding one makes one `DescribeLogGroups` / `DescribeStateMachine` / `DescribeRepositories` before the delete: a difference still there 5 s later refuses, non-retryable, naming the attribute (no value) and `cdkd state orphan --resource`, record kept. A failed read is retried; a denied one refuses, naming the permission to grant; neither falls back to a by-name delete. So a log group AWS re-created (Lambda writing to `/aws/lambda/<fn>` after it was deleted) now stops destroy instead of being deleted; the refusal names `cdkd import --force` to adopt it, deleting it by hand, or `cdkd state orphan`. No recorded value: no read, by-name delete; an update or import fills it. Cost: one read per such delete; log group create and update read `DescribeLogGroups` instead of STS. The rollback survivor check lists the three types, and a failed repository create journals `CreatedAt` for its orphan.
