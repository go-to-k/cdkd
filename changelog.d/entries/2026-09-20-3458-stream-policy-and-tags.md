- **`AWS::DynamoDB::Table`: `StreamSpecification.ResourcePolicy` and `StreamSpecification.Tags` are now applied and read back, instead of being dropped on the wire (issue [#3458](https://github.com/go-to-k/cdkd/issues/3458))** -- `dynamodb-table-provider.ts`, new `dynamodb-stream-members.ts`. The SDK's `StreamSpecification` has neither member, so a template granting access to a table's stream deployed green with NO policy attached and no tags, and drift saw neither. **Write:** once the stream exists, cdkd tags the STREAM arn and then calls `PutResourcePolicy` against it -- at create, on an update-time enable, when either member changes, and AGAIN after a `StreamViewType` change, which replaces the stream: both go to the newly minted `LatestStreamArn`, and the deploy fails loudly if only the replaced stream's arn can be read. A member REMOVED from a block whose stream stays is removed, as CloudFormation does; a policy that changes together with the tags is deleted before the first tag call and put back after the last; a disabled stream gets no call. A rollback restores the previous policy and tags. A block whose view type the live stream already has no longer re-sends `UpdateTable`. **Unreadable member** (unresolved intrinsic, wrong shape): refused by position, before `CreateTable` and before any call of an update; a rollback replay or `drift --revert` warns and keeps the live setting instead. **Read:** `cdkd drift` calls `GetResourcePolicy` / `ListTagsOfResource` on the current stream arn, each ONLY when the template declares that member, dropping `aws:` tags and re-asking a not-yet-consistent answer for a few seconds. An out-of-band policy delete or untag is reported under `StreamSpecification`, and `drift --revert` restores it. **New IAM actions on the stream arn, needed only by a template declaring the member:** `dynamodb:PutResourcePolicy`, `GetResourcePolicy`, `DeleteResourcePolicy`, `TagResource`, `UntagResource`, `ListTagsOfResource`.
