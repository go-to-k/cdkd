- **A force-exit from `cdkd local run-task` / `start-api` now NAMES the credentials file it leaves behind (issue [#3410](https://github.com/go-to-k/cdkd/issues/3410))** -- `src/cli/commands/local-profile-credentials-file.ts`, `local-run-task.ts`, `local-start-api.ts`. **Bug:** with `--profile <p>` both commands write a mode-0600 AWS credentials file to a tmpdir and bind-mount it into every container. A double-`^C` reaches `process.exit(130)`, which runs no `finally` and awaits nothing, so the cleanup disposing that tmpdir never fires. The message named only the CONTAINERS -- the artifact `docker ps` already finds -- and nothing about the one nothing reports. The file holds live credentials, `$TMPDIR` is not somewhere anyone looks, and one accumulates per force-quit. **Fix:** both force-exit arms now append a remedy sentence naming the path. `local-start-api.ts` was NOT named by the issue and was found by sweeping the class -- its force-exit arm already told the operator about orphan containers and had the same gap. The sentence comes from one shared builder that the `--detach` notice adopts too, so the three sites cannot drift into three wordings. A run with no `--profile` gets no extra sentence. The path is read from a hook the writer fires at `mkdtemp` time rather than from the resolved file, so a `^C` landing inside the write itself still names the directory it strands. `cdkd local invoke` and `local invoke-agentcore` need none: their second `^C` re-enters the same single-flight cleanup and the file is disposed. **Why NAME rather than `rmSync`:** every path that reaches this notice leaves the containers running with the file bind-mounted, which is the premise the `--detach` arm already records for not disposing it there; removing a mount those containers are still reading rests on behaviour this repo has not measured, while the file being INVISIBLE is the part an operator can act on. Recorded at the builder.
