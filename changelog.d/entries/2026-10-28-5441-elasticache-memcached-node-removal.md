- **`AWS::ElastiCache::CacheCluster`: lowering a Memcached cluster's `NumCacheNodes` no longer fails the deploy (issue [#5441](https://github.com/go-to-k/cdkd/issues/5441))** -- `src/provisioning/providers/elasticache-provider.ts`, with unit tests in `tests/unit/provisioning/elasticache-provider-node-removal-5441.test.ts` and a Memcached scale-in phase in the `cache-streaming` integ fixture. The update sent the lower `NumCacheNodes` alone, which AWS refuses without `CacheNodeIdsToRemove`. cdkd now names the nodes to remove the way CloudFormation does (measured: it keeps the nodes with the highest ids, and first removes any node in a zone the desired `PreferredAvailabilityZones` no longer lists), and waits until they are gone. Two decreases are refused before any change, each with a message naming the way out: one on a cluster whose live node count differs from the recorded one (the removal would delete nodes the template change does not account for), and one that would also need a node in a zone no live node occupies (CloudFormation replaces the cluster for a move to disjoint zones, which cdkd does not do yet, issue [#5458](https://github.com/go-to-k/cdkd/issues/5458)).
