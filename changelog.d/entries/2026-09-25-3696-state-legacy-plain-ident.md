- **`cdkd state`'s legacy-record refusals and `state orphan`'s warning name a stack in a pasteable command only when it is a plain identifier (issue [#3696](https://github.com/go-to-k/cdkd/issues/3696))** -- `src/cli/commands/state.ts` (`legacyRecordRefusal`, shared by `state resources` / `state show`; `refresh-observed`'s legacy refusal; `state orphan`'s `Destroy with:` line), `withheldTargetClause`'s docblock in `src/utils/pasteable-command.ts`, and unit tests in `tests/unit/cli/state-{refresh-observed,resources,show,orphan}.test.ts`. The `Migrate with: cdkd deploy ...` and `Destroy with: cdkd destroy ...` lines used the command gate alone, which names any exactly-rendering value, so a stack name with interior spaces and a `:` could wrap on screen into a counterfeit labelled row such as `Migrate with: cdkd destroy --all --force #`. Each now also requires a plain identifier (a letter or digit, then letters, digits, `~`, `_`, `.` or `-`, the rule `cdkd drift` already applies). Any other name prints a quoted `'<stack>'` hole with a sentence saying why, and `refresh-observed`, whose name comes from an S3 key, no longer shows such a name in its refusal message either; `cdkd state list --long` shows it. A CloudFormation stack name is always a plain identifier.
