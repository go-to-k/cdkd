- **A 1-3 character secret embedded in a literal beside a public `ssm` reference no longer reaches `state.json` in plaintext (issue [#5056](https://github.com/go-to-k/cdkd/issues/5056))** -- `src/deployment/secret-redaction/positions.ts`, `src/deployment/deploy-engine/update.ts`. Such a secret is below the value scan's 4-character floor, so only its position can redact it. Before, a literal such as `postgres://{{resolve:ssm:/db/host}}:5432/?pin={{resolve:secretsmanager:...}}` was persisted with the pin in plaintext: the position arm refused the whole leaf because the public token has no secret pair. A deploy now persists the secret span as its reference and the public span as its resolved value, where this deploy's own lookup proved the parameter public and the leaf is exactly that rendering; any leaf the value scan would answer differently keeps its old form. A record an older cdkd wrote with the plaintext spelling is rewritten on the next deploy without an UPDATE when the template is unchanged. A rollback replay can now state the same generation claim as the deploy for a provider bag the provider marked; no provider marks one on a replay today, so a provider's `effectiveProperties` echoing such a secret keeps the residual (issue [#5063](https://github.com/go-to-k/cdkd/issues/5063)). Tests: `tests/unit/deployment/secret-redaction-subfloor-5056.test.ts`, `tests/unit/deployment/deploy-engine-mixed-literal-legacy-repair-5056.test.ts`, `tests/unit/deployment/secret-redaction-context-1940.test.ts`.
