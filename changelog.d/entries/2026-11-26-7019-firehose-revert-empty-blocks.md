- **`cdkd drift --revert`: a Firehose delivery stream with an S3 destination is reverted instead of failing (issue [#7019](https://github.com/go-to-k/cdkd/issues/7019))** -- `src/provisioning/providers/firehose/s3-destination.ts`, `src/provisioning/providers/firehose/update.ts`, `src/provisioning/providers/firehose/describe-to-cfn.ts`, `src/provisioning/providers/firehose-provider.ts`. Reverting any drift on such a stream (the CDK L2 `S3Bucket` destination, or the legacy `S3DestinationConfiguration`) failed with `InvalidArgumentException` (`Bucket ARN is required for S3 destination`), because the read-back's empty `S3BackupConfiguration`, `ProcessingConfiguration`, `DataFormatConversionConfiguration` and `DynamicPartitioningConfiguration` blocks were sent back as written. An empty block now sends nothing, or `{ Enabled: false }` for processing or data format conversion that the live stream has enabled (a revert to the unset state). `cdkd drift` also reads a block AWS reports as disabled with only its own defaults (`Processors: []`, `RetryOptions.DurationInSeconds: 300`) as the never-set block, so a stream whose processing was switched off no longer reports drift that no revert can clear. Tests: `tests/unit/provisioning/firehose-revert-empty-blocks-7019.test.ts`; integ `drift-revert-firehose`.
