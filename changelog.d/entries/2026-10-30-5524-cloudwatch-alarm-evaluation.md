- **`AWS::CloudWatch::Alarm` keeps the SDK route for `EvaluationWindow`, `EvaluationCriteria` and `EvaluationInterval` (issues [#5524](https://github.com/go-to-k/cdkd/issues/5524), [#2762](https://github.com/go-to-k/cdkd/issues/2762)).** An alarm declaring any of them used to go through Cloud Control. All three now ride on `PutMetricAlarm` as declared, so a PromQL alarm (`EvaluationCriteria` + `EvaluationInterval`) is provisioned by the SDK provider too, and all three are read back for `cdkd drift`. A PromQL alarm's readback carries none of the metric members (`Dimensions`, `MetricName`, `Period`, ...), which `PutMetricAlarm` refuses beside `EvaluationCriteria`, so `cdkd drift --revert` can send it back. The default sliding window (`EvaluationWindow: { SlidingWindow: {} }`) is not reported as drift whether AWS answers it or omits it. Source: `src/provisioning/providers/cloudwatch-alarm-provider.ts`.
