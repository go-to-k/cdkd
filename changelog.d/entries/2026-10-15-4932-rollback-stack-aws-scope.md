- **`cdkd rollback` now runs its providers in the rolled-back stack's region, not the CLI's ambient `AWS_REGION` (issue [#4932](https://github.com/go-to-k/cdkd/issues/4932))** -- `src/cli/commands/rollback.ts`, new `tests/unit/cli/rollback-stack-aws-scope-4932.test.ts`. A standalone `cdkd rollback` resolved the stack's region from its journal or state key and pinned the global `getAwsClients()` set to it, but never entered the stack AWS scope that deploy uses. Providers that build their own SDK client read the region from `ambientRegion()`, which outside a scope is `process.env.AWS_REGION`. So a rollback of a stack recorded in a region other than the shell's could delete, re-create or update a same-named resource in the ambient region, which cdkd does not manage. The provider registry and the whole replay now run inside `runWithStackAwsClients` for the stack's region, so every provider captures that region when it is constructed and when it builds a client. A nested child's revert is also handed the stack's clients, which its destroy takes final snapshots through, as deploy does. `process.env.AWS_REGION` is left unchanged.
