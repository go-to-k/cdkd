- **`cdkd rollback` (plain and `--revert-failed`) and the automatic rollback no longer hand a provider a `physicalId` that is absent, empty, whitespace-only or not a string (issue [#4628](https://github.com/go-to-k/cdkd/issues/4628))** -- `src/deployment/rollback-executor.ts`, `src/deployment/rollback-executor/{messages,replay-revert,replay-reverse-replacement,replay-orphan-delete}.ts`. Every replay arm that addresses AWS by a record's or journaled op's id -- the revert of a completed UPDATE, the `--revert-failed` force-revert of a failed one, the delete of a completed or partially-created CREATE, and both replacement reversals -- now skips such an op before any provider call: a `Cannot ... -- its state record has no non-empty string 'physicalId'` warning, a `ROLLBACK_RESOURCE_SKIPPED` event, exit 2, and the state record left as it is. Before, `cdkd rollback --revert-failed` (the remedy a failed deploy prints) sent `provider.update` a blank id for an UPDATE `cdkd deploy` had refused over such a record, a delete could read the provider's `*NotFound` as already deleted and drop the record, and a replacement reversal could re-create the old resource before its delete of the new one failed. Re-adopting a retained old resource (`UpdateReplacePolicy: Retain`) fails instead (journal kept), since only the journal names that resource. A failed CREATE no state record holds is named for manual deletion. A nested-stack record is exempt, as on `cdkd deploy`, unless it or the arm's route is Cloud Control. A replacement whose new copy is retained (`UpdateReplacePolicy: Retain`) sends nothing by that id and is unchanged. Tests: `tests/unit/deployment/rollback-executor-unaddressable-physical-id-4628.test.ts`.
