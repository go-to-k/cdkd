- **`cdkd local` Docker build-context refusals now come from the bundled engine alone, and a path with a blank-drawing mark prints escaped (issues [#3652](https://github.com/go-to-k/cdkd/issues/3652), [#3656](https://github.com/go-to-k/cdkd/issues/3656))** -- `package.json` (`cdk-local` `^0.149.3` -> `^0.149.4`), `src/local/docker-image-builder.ts`, `src/assets/docker-build.ts`, `src/cli/commands/local-start-{service,alb}.ts`, the deleted `src/cli/commands/emulator-docker-context.ts`, and `src/utils/assembly-path.ts`. cdk-local 0.149.4 renders the value an assembly chose display-safe in its refusals (go-to-k/cdk-local#758), so cdkd drops its own copy of the check in front of `local invoke` / `start-api` / `invoke-agentcore` / `start-service` / `start-alb`. An escaping `source.directory` is still refused before anything is built, and the refusal now reads `Docker image asset has source.directory=../victim which resolves to ...` instead of cdkd's `Refusing to build the container image: ...`. `start-service` / `start-alb` check each image when it is built rather than every stack's images at startup, so the network and metadata sidecar are created before a refusal, and an image the run never builds is not checked. With `--no-build`, the engine reuses the cached tag and never opens the directory, so it no longer refuses. `<link>/..` is now built from the lexical path, which stays inside the assembly, instead of being refused. The engine's `source.executable` warning now says `cdkd runs it`. Separately, `displayAssemblyPath` escapes a default-ignorable mark (U+034F, U+17B4, U+180B, the variation selectors) even directly after a letter, so `/home/me/.ss\u034fh` no longer prints like `/home/me/.ssh`.
