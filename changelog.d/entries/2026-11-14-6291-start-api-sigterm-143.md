- **`cdkd local start-api` exits `143` on SIGTERM instead of `0` (issue [#6291](https://github.com/go-to-k/cdkd/issues/6291))** -- `src/cli/commands/local-start-api/command.ts`, `docs/cli-reference-exit-codes.md`, `docs/local-start-api.md`. Every other `cdkd local` command that holds containers already exits `143` on SIGTERM and `130` on Ctrl-C; `start-api` alone exited `0`. The cleanup is unchanged and SIGINT still exits `130`, and so does the immediate exit on a second signal of either kind. **Behaviour change:** a script that stops `start-api` with SIGTERM (`kill`, `timeout`, a process supervisor) and treats exit `0` as success now sees `143` and must accept it. Tests: `tests/unit/cli/local-start-api-sigterm-exit-6291.test.ts` and the `local-start-api` integ fixture's SIGTERM step.
