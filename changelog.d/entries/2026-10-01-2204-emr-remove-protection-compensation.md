- **`cdkd destroy --remove-protection` restores termination protection on an EMR cluster whose terminate then failed terminally (issue [#2204](https://github.com/go-to-k/cdkd/issues/2204), partial)** -- `src/provisioning/providers/emr-cluster-provider.ts`, with unit tests in `tests/unit/provisioning/providers/emr-cluster-remove-protection-compensate.test.ts`. Before, the `SetTerminationProtection(false)` flip was never undone, so a failed destroy left the cluster live with its guard silently stripped. Now `TerminationProtected` is turned back on before the failure is reported, under the rules the other `--remove-protection` sites follow: only a guard the delete's pre-check `DescribeCluster` saw ON and this run turned off, only on a terminal failure, never once AWS has accepted the `TerminateJobFlows`, and a failed re-enable is its own log line with a pasteable `aws emr modify-cluster-attributes --termination-protected` command. EC2 and the Cloud Control generic path stay open under #2204.
