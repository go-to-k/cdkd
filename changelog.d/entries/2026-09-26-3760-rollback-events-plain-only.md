- **`cdkd rollback` and `cdkd events` no longer print a padded stack name, region or run field in the output that ends in their labelled `Re-run with:` / `Read one run's events with:` lines (issue [#3760](https://github.com/go-to-k/cdkd/issues/3760))** -- `src/cli/commands/rollback.ts`, `src/cli/commands/events.ts`, `docs/deployment-events.md`, and unit tests. Folding control characters closed the newline route, but interior spaces survived. A stack name or region planted in a journal or event S3 key, or a field in the event index, could therefore be padded to wrap on screen into a counterfeit labelled row, such as `Re-run with: cdkd destroy --all --force #`, above the genuine one. Beside those lines cdkd now names a stack or region only when it is a plain identifier (a letter or digit, then letters, digits, `~`, `_`, `.` or `-`), and otherwise describes it, as in "a stack name that is not a plain identifier". This covers `cdkd rollback`'s multi-journal candidate list (with a pointer to `cdkd state list --long`) and its lock-release warning, and the `Deployment runs for` header of `cdkd events`. The failed-persist, failed-strip and lock-release warnings of `cdkd rollback` no longer show the state backend's error text when the stack name or region is not plain: that text re-spells the name, so it cannot be cleaned piecemeal. Each `cdkd events` run-list field is printed only as one token, otherwise as `<unrenderable>` or `?`. Ordinary output is unchanged.
