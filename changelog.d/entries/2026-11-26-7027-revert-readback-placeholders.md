- **`cdkd drift --revert`: an AppSync GraphQL API without logging, a Glue job and a Glue trigger are reverted instead of failing (issues [#7027](https://github.com/go-to-k/cdkd/issues/7027), [#7028](https://github.com/go-to-k/cdkd/issues/7028), [#7029](https://github.com/go-to-k/cdkd/issues/7029); part of [#7025](https://github.com/go-to-k/cdkd/issues/7025))** -- `src/provisioning/providers/appsync/create-update.ts`, `src/provisioning/providers/appsync-provider.ts`, `src/provisioning/providers/glue/{job,trigger,shared}.ts`. Reverting any drift on these failed, because the read-back's placeholders for members AWS reports none of were sent back as written: `LogConfig: {}` (`cloudWatchLogsRoleArn is invalid`), a job's `ExecutionClass: ''`, `MaintenanceWindow: ''`, `SecurityConfiguration: ''` and `NotifyDelayAfter: 0`, and a trigger's `EventBatchingCondition: {}` (`BatchSize` 0). A revert now sends nothing for them (`UpdateJob` and `UpdateTrigger` replace the whole definition, so a member left out is unset), and a job's revert sends its workers without the `MaxCapacity` / `AllocatedCapacity` AWS computes from them (`Please set only Allocated Capacity or Max Capacity`). An empty `LogConfig` disables the logging the live API has, as an absent one does, and `cdkd drift` reads the `FieldLogLevel: NONE` an API keeps after its logging is switched off as no logging. A template deploy sends what it declares, as before. Tests: `tests/unit/provisioning/revert-readback-placeholders-7027-7029.test.ts`; integ `drift-revert-readback-placeholders`.
