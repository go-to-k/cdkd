- **A failure that cannot be converted to text no longer turns a best-effort deploy step into a hard failure** (`src/deployment/orphan-adoption.ts`, `src/deployment/nested-child-journal.ts`, `src/deployment/work-graph.ts`, `src/deployment/recreate-targets/probe.ts`, go-to-k/cdkd#3361). Handlers that report a failure and carry on built their message with `x instanceof Error ? x.message : String(x)`, and `String()` throws for a null-prototype object. The handler itself then threw: the orphan-adoption pre-pass rejected, and the deploy with it, instead of keeping a record it could not route or verify; the sibling-claim scan rejected instead of skipping an unreadable sibling or answering an empty set; the nested-journal sweep after a successful deploy, documented as never throwing, rejected and skipped the child's own journal delete; a failed state save after a nested child's revert, documented as a warning, failed the revert; a stack or asset node failing that way became an unhandled rejection in `WorkGraph.execute` that exited `cdkd deploy` / `cdkd publish-assets` with the converter's `TypeError` instead of the failure summary; and the `--recreate-via-*` stateful probe rejected instead of answering fail-open for a bucket or fail-closed for a log group. Each now goes through `describeAwsFailure(x).detail`, byte-identical for an `Error` and a placeholder otherwise. Tests: `tests/unit/deployment/deployment-string-outthrow-3361.test.ts`.
