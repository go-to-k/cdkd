- **`cdkd diff`, `import`, `scrub`, `export` and `destroy` no longer print a physical name derived from a secret (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/secret-name-needles.ts` (new, the judge shared with `deploy`), `src/deployment/deploy-engine/masking.ts`, `src/deployment/intrinsic-resolver/{context,getatt,masking}.ts`, `src/cli/commands/{diff-recursive,import,scrub,export,destroy-runner}.ts`. `cdkd deploy` already masked a resource NAMED from a secret (its record spells the name as a `{{resolve:` reference) wherever another resource read it. The commands that resolve against state did not. Under `--verbose`, `cdkd diff`, `import`, `scrub` and `export` printed that name, or an ARN or URL embedding it, on the resolver's `resolved to` line for a `Ref` / `Fn::GetAtt` to it. `cdkd destroy` printed it on the resource's own delete lines, on a deleted reader's lines (an access key's `UserName`, an instance profile's `Roles`, a role detaching a policy whose path came from a secret) and on the final-snapshot lines. These commands now record those reads into a print-only bag, so nothing they persist or decide changes, and each destroy delete runs under a printing bag of its own needles and those it read. `cdkd drift` resolves no `Ref` / `Fn::GetAtt` to a resource, so it is unchanged. `docs/deployment-events.md` now says an event's `physicalId` field is stored as AWS returned it. Tests: `tests/unit/deployment/secret-name-needles-3869.test.ts`, `tests/unit/cli/{destroy,diff,import,export}-secret-name-needles-3869.test.ts`, `tests/unit/cli/commands/scrub-secret-name-needles-3869.test.ts`; integ `secret-derived-immutable-names` gains a `cdkd diff --verbose` step and destroy assertions.
