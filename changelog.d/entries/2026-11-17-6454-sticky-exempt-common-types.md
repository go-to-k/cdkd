- **Ten more common resource types recorded `provisionedBy: 'cc-api'` return to their SDK provider (issue [#6454](https://github.com/go-to-k/cdkd/issues/6454))** -- `src/provisioning/provider-registry/sticky-exempt.ts` (the exemption table, moved out of `provider-registry.ts`) and the new `cc-to-sdk-reroute-common-types` integ. `AWS::EC2::SecurityGroup`, `AWS::EC2::RouteTable`, `AWS::ElasticLoadBalancingV2::TargetGroup`, `AWS::KMS::Key`, `AWS::SecretsManager::Secret`, `AWS::Lambda::EventSourceMapping`, `AWS::IAM::Role`, `AWS::IAM::ManagedPolicy`, `AWS::SQS::Queue` and `AWS::SSM::Parameter` are now `'sdk-coverage'` members of `STICKY_CC_MIGRATION_EXEMPT`. A resource of one of these types that was sent to Cloud Control (for example by a property its SDK provider did not write yet) used to stay there and keep paying Cloud Control's polled updates. The next deploy that changes it now moves it to the SDK provider in place; `--pin-cc-api <LogicalId>` declines that. Both layers record the same id for each type, observed on live resources together with an identity witness (the AWS-minted id, or the RoleId, PolicyId, queue CreatedTimestamp or parameter Version), so nothing is replaced. `cdkd diff` annotates the move `[returning to SDK provider]`.
