- **`AWS::EMR::Cluster` with `MonitoringConfiguration` or `SessionEnabled` now deploys (issue [#5824](https://github.com/go-to-k/cdkd/issues/5824))** -- `src/provisioning/providers/emr-cluster-provider.ts`, the regenerated coverage map, unit tests and the `emr-cluster` integ fixture. Before this change, the SDK provider did not send either property, and because `AWS::EMR::Cluster` has no Cloud Control route, a template setting one was refused before any AWS call. Both are now sent on `RunJobFlow`: `MonitoringConfiguration.CloudWatchLogConfiguration` with all five members (`Enabled`, `LogGroupName`, `LogStreamNamePrefix`, `EncryptionKeyArn`, `LogTypes`), and `SessionEnabled` (Spark Connect sessions). A key under `MonitoringConfiguration` that CloudFormation does not define is refused before any AWS call. A boolean this provider reads (`SessionEnabled`, `VisibleToAllUsers`, `Instances.TerminationProtected`, ...) spelled `"True"` is now read as true, as CloudFormation reads it. Both are create-only, so a change replaces the cluster, as CloudFormation does. `cdkd drift` reads both back when `DescribeCluster` reports them but does not compare them: no EMR API changes either after the cluster is created, and AWS fills in log settings the template omits.
