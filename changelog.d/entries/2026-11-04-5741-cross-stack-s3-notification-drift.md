- **`cdkd drift --revert` no longer deletes S3 event notifications that another stack added to a bucket (issue [#5741](https://github.com/go-to-k/cdkd/issues/5741))** -- `src/cli/commands/drift.ts` and its unit tests. When a second stack imports a bucket with `s3.Bucket.fromBucketName(...)` and calls `addEventNotification(...)`, the `Custom::S3BucketNotifications` resource lives in that second stack. `cdkd drift` on the bucket's own stack reported those notifications as drift, and `--revert` wrote the bucket's recorded snapshot back, which deleted them. Drift now never compares an `AWS::S3::Bucket`'s `NotificationConfiguration` unless the template sets it on the bucket, whichever stack or tool writes it. This matches CloudFormation's drift detection, which also does not report a console edit to those notifications. A `NotificationConfiguration` that the template sets on the bucket is still compared. Stacks that are already deployed are fixed without a redeploy.
