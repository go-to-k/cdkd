- **`AWS::RDS::DBCluster` / `AWS::RDS::DBInstance`: the rows whose verification needs dedicated infrastructure are now unhandled by design (issues [#5639](https://github.com/go-to-k/cdkd/issues/5639), [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds-provider.ts`, `src/provisioning/providers/rds/provider-base.ts`. DBCluster `Domain` / `DomainIAMRoleName`, and DBInstance `Domain`, `DomainAuthSecretArn`, `DomainDnsIps`, `DomainFqdn`, `DomainIAMRoleName`, `DomainOu`, `TdeCredentialArn`, `TdeCredentialPassword`, `ReplicaMode`, `CustomIAMInstanceProfile`, `DBSystemId` and `BackupTarget` stay on the Cloud Control route, as before. The only change is the reason `cdkd` reports for the route: it was "not yet implemented", and now it names the infrastructure that verifying the row needs (a Directory Service or self-managed Active Directory domain, an Oracle HSM key store, an Oracle Enterprise Edition BYOL source, RDS Custom, RDS on Outposts). The maintainer ruled these rows out of scope for the backfill campaign. `RDSProvider`'s wait delegators moved to the base class `RDSProviderBase`, which keeps `rds-provider.ts` under the source-file size cap.
