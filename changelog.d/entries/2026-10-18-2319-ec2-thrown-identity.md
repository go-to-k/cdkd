- **A failed EC2 create, update or delete (VPC, Subnet, InternetGateway, EIP, VPCGatewayAttachment, NatGateway, RouteTable, Route, SubnetRouteTableAssociation, SecurityGroup, SecurityGroupIngress, Instance, NetworkAcl, NetworkAclEntry or SubnetNetworkAclAssociation, for each operation the type supports) no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/ec2-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an `UnauthorizedOperation`, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (`UnauthorizedOperation. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log. A cdkd-authored or transport error keeps its text. The AWS error stays as the `cause`, so an IAM grant that is still propagating is retried as before; a security group whose name is taken still says it already exists, so a custom-named group's replacement is still handled as a name collision; and a create denied both with and without tags still says so.
