- **A failed ElastiCache subnet group or cache cluster, CloudTrail trail, CloudFront distribution or IAM access key create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/elasticache-provider.ts`, `cloudtrail-provider.ts`, `cloudfront-distribution-provider.ts`, `iam-access-key-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (`AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, masked through the operation's secret masker. This also covers a CloudFront distribution update whose tag change failed, and the IAM access key warnings about a denied key listing or a key cleanup that failed: they keep their remedy and command, with the class in place of AWS's text. A cdkd-authored or transport error keeps its text. The AWS error stays as the `cause`, so an IAM grant that is still propagating is retried as before. A name that is already taken still says it already exists, so a create-first replacement still recognises the name collision.
