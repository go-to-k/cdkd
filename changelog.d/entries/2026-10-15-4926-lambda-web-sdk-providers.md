- **`AWS::Lambda::WebFunctionRevision` and `AWS::Lambda::WebFunctionEndpoint` now deploy through SDK providers, about 5 s faster per Web Function code change** -- new `src/provisioning/providers/lambda-web-function-revision-provider.ts`, `lambda-web-function-endpoint-provider.ts` and `lambda-web-function-arns.ts`, `src/provisioning/provider-registry.ts`, `src/utils/aws-clients.ts`, new dependency `@aws-sdk/client-lambda-web`. A code change creates a new revision, moves the endpoint's `RevisionWeights` to it and deletes the old revision; through Cloud Control those three steps took about 12 s, and through the Lambda Web API about 7 s (median of three, us-east-1). A revision created by an earlier cdkd, recorded on Cloud Control, moves to the SDK provider on the next deploy that changes it, and so does an endpoint. Both providers support `cdkd drift` and `cdkd import`. `AWS::Lambda::WebFunction` stays on Cloud Control: the public `CreateWebFunction` refuses a function without a first revision and endpoint, which only CloudFormation's handler may create. Issue [#4926](https://github.com/go-to-k/cdkd/issues/4926).
