- **A Route 53 hosted zone's declared `HostedZoneFeatures.EnableAcceleratedRecovery` now reaches AWS, and the deploy waits for it to settle as CloudFormation does (issue [#5465](https://github.com/go-to-k/cdkd/issues/5465))** -- `src/provisioning/providers/route53-provider.ts`, a new unit file, the Route 53 provider suites, and the `route53` integ fixture. The provider read `HostedZoneFeatures.AcceleratedRecoveryStatus`, the GetHostedZone read-side status, which no template declares; the CloudFormation member `EnableAcceleratedRecovery` (what `CfnHostedZone`'s `enableAcceleratedRecovery` emits) was never read, so a deploy succeeded with the feature left disabled and a later change to it was not sent either. Create and update now read `EnableAcceleratedRecovery` (`true` or `"true"`), and removing `HostedZoneFeatures` disables the feature, as CloudFormation does. A create or update that toggles it returns only once the zone reads `ENABLED` / `DISABLED` (CloudFormation measured ~4 min to enable, ~3.5 min to disable), since Route 53 refuses every record change on the zone until then; a `*_FAILED` status or the `CDKD_R53_ACCEL_RECOVERY_POLL_TIMEOUT_MS` timeout (default 600 s) fails the deploy with the next step. A deploy that does not toggle it pays nothing. `cdkd drift` now reads the feature back as `{ EnableAcceleratedRecovery: <boolean> }`, the shape CloudFormation's drift detection reports. **A zone deployed before this fix with `EnableAcceleratedRecovery: true` is still disabled** and a redeploy sees no change: deploy once without `HostedZoneFeatures`, then once with it, to enable it.
