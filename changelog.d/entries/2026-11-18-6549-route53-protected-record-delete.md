- **Destroying a protected Route 53 record set fails instead of dropping it from state (issue [#6549](https://github.com/go-to-k/cdkd/issues/6549))** -- `src/provisioning/providers/route53/record-set.ts`, `route53/core.ts`. The `AWS::Route53::RecordSet` delete treated every `InvalidChangeBatch` refusal as "already deleted". Route 53 also answers `InvalidChangeBatch` for a record set under a resource record set protection (`CreateResourceRecordSetProtections`, which has no CloudFormation property), so `cdkd destroy` reported the record deleted and dropped its state record while it stayed live. The delete now reads only Route 53's not-found text as already deleted, so a protected record fails, as it does in CloudFormation. That failure, and a hosted zone delete refused with `HostedZoneInUse` for the same reason, now says the protection is the cause and to remove it with `DeleteResourceRecordSetProtections`; before, a run without `--verbose` showed only the error class. `--remove-protection` does not remove these protections, because the template does not declare them.
