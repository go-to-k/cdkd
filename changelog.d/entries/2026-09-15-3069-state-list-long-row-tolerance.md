- **`cdkd state list --long` no longer loses the whole listing to one stack it cannot read (issue [#3069](https://github.com/go-to-k/cdkd/issues/3069))** -- `src/cli/commands/state.ts` (`stateListCommand`, new `readOrFailure`), `docs/cli-state.md`, unit tests. Each row read its state record and lock inside one unguarded `Promise.all`, so the first rejection (an unreadable body, an unsupported schema version, an AWS read failure) made the command exit 1 with no rows. The two reads are now guarded separately. A row whose record failed shows `Resources: unknown (...)` and keeps its lock; a row whose lock failed keeps its real counts and shows `Lock: unknown (...)`. `--long --json` adds `stateReadError` and `lockReadError`, and sets `resourceCount` / `locked` to `null` on the failed side instead of `0` / `false`. The reason text is a fixed string, never the caught message: the invalid-JSON refusal quotes bytes of the state body, which whoever can write the bucket chooses. A stderr warning counts the degraded rows; the exit code stays 0. Also closed in this view: a `lastModified` outside the `Date` range (`1e300`) no longer throws past the guard; a `resources` that is neither a JSON object nor `null` shows an unknown count instead of one counted per character or element, and under `--json` sets `resourceCount: null` with its own `stateReadError` reason; and the plain listing and the `--long` / `--tree` text rows print the stack name and region through the ASCII display sanitizer, since an S3 key segment can carry a newline or ESC (`--json` is unchanged). `--tree` (`state-list-tree.ts`) no longer empties on a non-string `parentStack` / `parentRegion` and drops such a link whole, and a parent loop's stacks land at the root instead of vanishing. Residual: a legacy `version: 1` reference with no resolved region is still not read by this view and renders zero resources with no reason attached.
