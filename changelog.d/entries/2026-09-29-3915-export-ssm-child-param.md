- **A nested `cdkd export` hands a child the value stored under a parent's SSM-typed Parameter, not the SSM parameter's name (issue [#3915](https://github.com/go-to-k/cdkd/issues/3915))** -- `src/cli/commands/export.ts`, with unit tests in `tests/unit/cli/export.test.ts` and `tests/unit/cli/export-nested-failure-render.test.ts`, and an arm in the `export-nested-stack` integ. When a parent passed one of its `AWS::SSM::Parameter::Value<...>` Parameters to a nested child, the child's IMPORT changeset was submitted the SSM parameter's NAME, so the migrated standalone child held the path as a literal value, and the IAM::Policy pre-delete check blocked a policy whose role came through it. cdkd now reads the value with `ssm:GetParameter` (without decryption) and submits it to the child, as CloudFormation hands a nested stack the resolved value; the parent's own changeset still submits the name. A list type is a list to the child row's `Ref` (so `Fn::Join` / `Fn::Select` over it resolve) and is handed over comma-joined, and only a parameter the child's row mentions is read. `cdkd export` therefore needs `ssm:GetParameter` on such a parameter: an unreadable one, or one whose type is not `String` or `StringList` (such as a `SecureString`, which CloudFormation does not accept for an SSM-typed Parameter), refuses before any nested stack's lock or any changeset; `--dry-run` warns instead and plans without the nested stacks' Parameter values.
