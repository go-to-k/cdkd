- **`cdkd import` masks the resolver error text it logs, so an assembled secret plaintext no longer reaches stderr (issue [#2803](https://github.com/go-to-k/cdkd/issues/2803))** -- `src/cli/commands/import.ts`, `src/cli/commands/scrub.ts`, `tests/unit/cli/import-resolver-error-masking.test.ts`. **Bug:** `resolveImportedProperties` declared its per-resource `recordedSecretValues` INSIDE the `try` that calls `resolver.resolve(...)`, so the `catch` could not name it and interpolated `err.message` verbatim into a `logger.warn` printing at default verbosity. `cdkd import` sets no `skipDynamicReferences`, so the resolve decrypts, and the resolver's throws interpolate what they were handed -- `key '<jsonKey>' not found in secret '<id>'` carries a plaintext whenever a later reference's secret id or JSON key was ASSEMBLED from an earlier one through `Fn::Sub` / `Fn::Join`, in the command whose contract is to persist the `{{resolve:...}}` expression and never the value. State was unaffected; this was a log exposure. **Fix:** hoist the declaration above the `try` and wrap the message in `maskSecretsInText`, the shape `rollback-executor.ts` and `drift.ts` already document at their declarations.
