- **A secret AWS echoes under a property the template does not set is now stored masked, and `cdkd drift` reports it as not compared (`maskedEcho`, exit `0`) instead of as drift; a custom resource attribute whose name holds a secret is no longer stored (issues [#7158](https://github.com/go-to-k/cdkd/issues/7158), [#7152](https://github.com/go-to-k/cdkd/issues/7152), [#7153](https://github.com/go-to-k/cdkd/issues/7153))** -- `src/deployment/secret-redaction/{off-template-echo,secret-attribute-keys}.ts`, `src/deployment/deploy-engine/state-persist.ts`, `src/cli/commands/drift/{compare,redaction,outcome}.ts`. A `NoEcho` value or an `ssm-secure` / `secretsmanager` plaintext that a readback echoed under a key the template lacks was kept in `state.json` (`observedProperties`) in plaintext when no needle covered it: a 1-3 character value embedded in a longer one, any value on an unchanged resource, a reference inside a list, or two references with one value. Every readback writer (deploy, `cdkd state refresh-observed`, `cdkd import`, `cdkd state scrub`, rollback, `cdkd drift --accept` / `--revert`) now masks it and records the position in a new optional field, `observedMaskedLeaves` (no schema bump; an older binary ignores it and reports such a position as drift). A public `ssm` value, the region, the stack name and a value the physical id contains are never learned as a secret. An existing record is masked on its next save. A custom resource attribute whose KEY contains a secret is dropped unless a template `Fn::GetAtt` spells it; a later `Fn::GetAtt` of it finds no attribute until the resource runs again. Tests: `tests/unit/deployment/off-template-echo-7158.test.ts`, `tests/unit/cli/drift-masked-echo-7158.test.ts`.
