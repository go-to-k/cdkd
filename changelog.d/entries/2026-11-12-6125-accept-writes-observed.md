- **`cdkd drift --accept` on a record with no observed baseline no longer rewrites its template properties (issue [#6125](https://github.com/go-to-k/cdkd/issues/6125))** -- `src/cli/commands/drift/accept.ts`, `src/cli/commands/drift/redaction.ts`, `src/cli/commands/drift/plan.ts`. **Behavior change:** a record without `observedProperties` (state written by an older cdkd) now gets one, seeded from its `properties` plus the accepted values; `properties` stay as the last deploy wrote them (before: the readback was written INTO `properties`, the previous side of the next deploy's diff, so an accepted list entry that exists only in AWS read as a removal on the next deploy -- for RDS `AdditionalStorageVolumes`, a `SetForDelete` of the accepted volume). Accepting a scalar on such a record now means what it means on every other record: the AWS value is tolerated, and the next deploy of an unchanged template does not push the template value back. The seeded baseline is redacted with the fail-closed baseline rules, so a position the secret walk cannot certify is written as `***` and reported "was NOT recorded".
