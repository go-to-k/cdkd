- **A copy of a string-declared `NoEcho` value is now stored masked, as a boolean one is (issue [#4831](https://github.com/go-to-k/cdkd/issues/4831))** -- `src/deployment/intrinsic-resolver/parameter-secrets.ts`. For a parameter declared `NoEcho: "true"` (the string form CloudFormation accepts), a leaf that held the value without reading the parameter by position (a literal, or a copy in another property) was persisted in plaintext in `state.json`. The value was recorded only as a log-only needle, unlike `NoEcho: true`, because masking that copy would have replaced a create-only resource on the next unchanged deploy. Now that the migration witness also reads a record another `NoEcho` source already marked (#4836), the value is a mask-only needle too. A record written before is masked on its next deploy without being replaced, and the leaf is named in `noEchoLeaves`. The `--verbose` log lines that print a resolved value holding it now mask the WHOLE value, as for `NoEcho: true` (`Resolved Fn::Sub: ***` rather than `Resolved Fn::Sub: str-***`). Tests: `tests/unit/deployment/noecho-string-value-arm-4831.test.ts`. Integ: `noecho-parameter-masking` Phase 4v deploys an isolated stack with @go-to-k/cdkd@0.297.0, then redeploys it unchanged with this binary, and fails if the topic is replaced, its name prints, or the copy stays in plaintext.
