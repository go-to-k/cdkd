- **A malformed template, `--env-vars` file, event payload, Cloud Control model, lock, manifest or config file no longer prints a window of itself in its error (issue [#5254](https://github.com/go-to-k/cdkd/issues/5254))** -- `src/utils/json-parse-failure.ts`, `src/cli/yaml-cfn.ts`, `src/cli/commands/{import,state,local-invoke,local-invoke-agentcore,local-run-task,local-start-api}.ts`, `src/cli/config-loader.ts`, `src/state/lock-manager.ts`, `src/synthesis/{assembly-reader,context-store,macro-expander}.ts`, `src/synthesis/context-providers/cc-api-provider.ts`, `src/provisioning/{create-only,write-only}-properties.ts`, `src/assets/{asset-manifest-loader,asset-publisher,asset-redirect,asset-storage}.ts`. These are the siblings of [#5247](https://github.com/go-to-k/cdkd/issues/5247). Each site put Node's `JSON.parse` error text into a thrown message, a `Caused by:` line or a warning, and that text quotes about 30 characters of the body, which can be a plaintext secret. Each now reads `invalid JSON[ at code-unit position N]; <bytes> byte(s) read`. A cause that a reader classifies (the bootstrap marker, `manifest.json`) is a `SyntaxError` carrying that text, and the others attach none. A YAML template's error names the `yaml` library's error code, line and column instead of its code frame, which quoted the source. `cdkd state refresh-observed` prints only `SyntaxError` for a readback that failed to parse. Node's full text, ASCII-sanitized, is logged at `--verbose` only. `src/provisioning/cloud-control-provider.ts`'s `readCurrentState` is not changed here.
