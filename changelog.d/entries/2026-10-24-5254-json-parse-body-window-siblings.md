- **A malformed template, Cloud Control model, lock, manifest or config file no longer prints a window of itself in its error (issue [#5254](https://github.com/go-to-k/cdkd/issues/5254))** -- `src/utils/json-parse-failure.ts` (new: `jsonParseFailureDebugDetail`, `jsonParseFailureStandIn`), `src/cli/yaml-cfn.ts`, `src/cli/commands/import.ts`, `src/cli/commands/state.ts`, `src/cli/config-loader.ts`, `src/state/lock-manager.ts`, `src/synthesis/assembly-reader.ts`, `src/synthesis/context-store.ts`, `src/synthesis/macro-expander.ts`, `src/synthesis/context-providers/cc-api-provider.ts`, `src/cli/commands/local-invoke.ts`, `src/cli/commands/local-invoke-agentcore.ts`, `src/cli/commands/local-run-task.ts`, `src/cli/commands/local-start-api.ts`, `src/provisioning/create-only-properties.ts`, `src/provisioning/write-only-properties.ts`, `src/assets/asset-manifest-loader.ts` (new: `parseAssetManifestBody`), `src/assets/asset-publisher.ts`, `src/assets/asset-redirect.ts`, `src/assets/asset-storage.ts`, `scripts/check-provider-error-cause.ts`. These are the siblings of issue [#5247](https://github.com/go-to-k/cdkd/issues/5247). Each site put Node's `JSON.parse` error text into a thrown message, a `cause` (printed on the `Caused by:` line) or a warning, and that text quotes about 30 characters of the body. A template, a Cloud Control resource model, a `cdkd local` `--env-vars` file or an event payload can hold a plaintext value there. The sites are the CFn template parse (`Template is not valid JSON`), `cdkd import`'s `--resource-mapping` and nested-stack template parses, the Processed-stage template of macro expansion, the `cc-api-provider` context lookup, the `--env-vars` file and event payload of `cdkd local invoke` / `invoke-agentcore` / `run-task` / `start-api`, the DescribeType registry schema behind the create-only and write-only property warnings, `lock.json`, `manifest.json`, `<stack>.assets.json`, the bootstrap marker, `cdk.json` and `cdk.context.json`. Each now reads `invalid JSON[ at code-unit position N]; <bytes> byte(s) read`. A `cause` that a reader classifies (the bootstrap marker, `manifest.json`) is a `SyntaxError` with that text instead of Node's, and the others attach no cause. A YAML template's error now names the `yaml` library's error code and line and column instead of its code frame, which quoted the source lines. `cdkd state refresh-observed` prints only `SyntaxError` for a readback whose body failed to parse. Node's full text, ASCII-sanitized, is logged at `--verbose` only. `src/provisioning/cloud-control-provider.ts`'s `readCurrentState` still rethrows the raw parse error and is left to a follow-up.
