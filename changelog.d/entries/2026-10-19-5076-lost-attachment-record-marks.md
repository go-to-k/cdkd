- **A 1-3 character secret embedded in a literal no longer reaches `state.json` in plaintext when a failed deploy trims a lost attachment's record (issue [#5076](https://github.com/go-to-k/cdkd/issues/5076))** -- `src/deployment/deploy-engine/execute.ts`, `src/deployment/deploy-engine/record-shape.ts`, `src/deployment/secret-redaction/pairs.ts`. When a deploy fails after re-creating an IAM principal under the same name, cdkd keeps the record of a resource that lost its attachment, with the re-created principal dropped from its lists. The rebuilt record was a plain copy that lost the marks the original record carried. A resource whose record this deploy had already written (a Cloud Control update that sent nothing) was then saved without the claim that lets a secret below the value scan's 4-character floor be stored as its reference. The copy now carries exactly the marks the original had, and adds none it lacked. Tests: `tests/unit/deployment/deploy-engine-lost-attachment-marks-5076.test.ts`.
