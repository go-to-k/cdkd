- **A fix-forward deploy now deletes the Lambda function an earlier failed CREATE left behind (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606), Lambda function slice)** -- `src/provisioning/providers/lambda-function-provider.ts`. When a `cdkd deploy --no-rollback` made an `AWS::Lambda::Function`, failed configuring it (`RecursiveLoop`, `ReservedConcurrentExecutions` or `RuntimeManagementConfig`) and could not delete it again, and a later deploy kept the logical id under another function name, the successful deploy warned about the earlier function, left it in AWS and exited 2; `cdkd rollback` and `cdkd destroy` kept it the same way. The Lambda function provider now answers both questions: a function name is unique per account and region and cannot be changed, so the earlier function is a different one once the record's function reads back; and the failed CREATE records the function's ARN and the `LastModified` its `CreateFunction` returned, so the earlier function is deleted only while its name still reads back under both. A function deleted by hand and re-created under the name has another `LastModified` and is kept, with a warning; so is one a later code or configuration update changed. A successful `PutRuntimeManagementConfig` moves `LastModified` too, so a failure after it journals a live read instead of the create's token. Tests: `tests/unit/provisioning/lambda-function-provider-same-resource-4606.test.ts`; integ: `lambda-fix-forward-orphan`.
