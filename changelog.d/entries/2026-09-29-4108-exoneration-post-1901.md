- **`cdkd diff` no longer prints a deleted output's `SecureString` plaintext when the stored record also holds a correctly redacted `secretsmanager` reference (issue [#4108](https://github.com/go-to-k/cdkd/issues/4108))** -- `src/analyzer/outputs-diff.ts`, `src/deployment/no-change-outputs-merge.ts`, `.claude/rules/layout-analyzer.md`, `.claude/rules/no-change-outputs-merge.md`, `docs/_contents/architecture.md`, `docs/_contents/cli-diff.md`. A stored secret expression exonerated the whole record, so a deleted output's value printed on its REMOVE row. But a `secretsmanager` / `ssm-secure` expression proves only a write after the GHSA fix, and a cdkd before issue #1901 stored a `SecureString` parameter's plaintext beside it. Only a stored plain `ssm` reference, which only a cdkd after #1901 writes, now exonerates the record, and `cdkd deploy`'s no-change Outputs merge counts that token as a first secret expression, so it keeps the previous bag whole rather than write one beside a carried pre-#1901 plaintext. Fail-closed cost: in a stack whose only secret is `secretsmanager`, a deleted output's previous value is withheld while the template still references a secret. Tests: `tests/unit/analyzer/outputs-diff.test.ts`, `tests/unit/analyzer/outputs-diff-ssm-export-name-4056.test.ts`, `tests/unit/deployment/no-change-outputs-merge.test.ts`, `tests/unit/deployment/deploy-engine-skipped-outputs.test.ts`.
