- **A malformed `resources` bag no longer kills `cdkd diff`, `import`, `orphan`, `rollback` or `scrub` with a raw `TypeError`** — a hand-edited or truncated `state.json` whose resource map is absent, `null`, or some other non-object used to abort each of those commands from the first `Object.keys` / `in` / index read, naming no stack, no key and no remedy, from exactly the commands a user reaches for WHEN the state is broken. `cdkd diff` now reports on the record with an empty resource set and warns that its output describes zero resources, which is not the same as the stack having none. The commands that can WRITE state — `scrub` on a real run, `import`, `orphan`, `rollback` — instead REFUSE by name (`STATE_RESOURCES_MALFORMED`) rather than repairing: `scrub` saves whenever anything changed, an Outputs change alone included, so repairing would save a well-formed `resources: {}` over the only evidence that the record is broken, after which the next `deploy` re-creates the whole stack and the next `destroy` orphans every live resource. `cdkd scrub --dry-run` is the one exception — its write gate carries `!opts.dryRun`, so it audits the record and then exits non-zero rather than reporting `No plaintext secrets found`, which would make the documented `--dry-run --fail` CI gate pass over resources it never read. Every message names the record to inspect and states that `deploy` / `destroy` must not be run against it. `deploy` and `destroy` themselves are unchanged and are tracked as #3161: they abort on a `null` or absent bag, but an `[]` or a number reads to them as an EMPTY stack, so destroy takes its empty-stack fast path and deletes the record while every resource stays live. The remaining null-ENTRY shape (`{"resources": {"R": null}}`) stays on #3018. Issue #3018.
