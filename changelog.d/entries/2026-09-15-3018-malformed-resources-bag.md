- **A malformed `resources` bag no longer kills `cdkd diff`, `import`, `orphan` or `scrub` with a raw `TypeError`** — a hand-edited or truncated `state.json` whose resource map is absent, `null`, or some other non-object used to abort each of those commands from the first `Object.keys` / `in` / index read, naming no stack, no key and no remedy, from exactly the commands a user reaches for WHEN the state is broken. `cdkd diff` now reports on the record with an empty resource set and warns that its output describes zero resources, which is not the same as the stack having none. The three commands that can WRITE state — `scrub`, `import`, `orphan` — instead REFUSE by name (`STATE_RESOURCES_MALFORMED`, exit 1) rather than repairing: `scrub` saves whenever anything changed, an Outputs change alone included, so repairing would save a well-formed `resources: {}` over the only evidence that the record is broken, after which the next `deploy` re-creates the whole stack and the next `destroy` orphans every live resource. Every message names the record to inspect and states that `deploy` / `destroy` must not be run against it. `deploy` and `destroy` themselves are unchanged and still abort. Issue #3018.
