- **The `--remove-protection` help now names `AWS::EMR::Cluster` and `AWS::DynamoDB::GlobalTable` (issue [#2660](https://github.com/go-to-k/cdkd/issues/2660))** -- `src/provisioning/remove-protection-types.ts`, `src/cli/options.ts`, `src/cli/commands/state.ts`, plus `remove-protection-types.test.ts` and `cc-protection-doc-coverage.test.ts`. Both providers flip their protection off under the flag, but `cdkd destroy --help` and `cdkd state destroy --help` each carried a hand-written list that left them out, so a user with a protected EMR cluster or global table would conclude cdkd could not bypass it. Both help strings now render from one list, `SDK_REMOVE_PROTECTION_TYPES` followed by the Cloud Control protection registry. A unit test binds that list to the provider files that read `removeProtection`, in both directions. The `docs/cli-destroy.md` type table still lacks the two rows; that half follows once the open PR holding the page merges. The destroy confirm prompt's protected-resource count does not yet include a protected EMR cluster ([#3676](https://github.com/go-to-k/cdkd/issues/3676)).
