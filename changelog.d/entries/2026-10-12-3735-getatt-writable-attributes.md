- **`cdkd import` through Cloud Control no longer masks a `Fn::GetAtt` attribute that is also a writable property (issue [#3735](https://github.com/go-to-k/cdkd/issues/3735))** -- `src/provisioning/read-only-properties.ts` (new `getTopLevelAttributeNames`), `src/provisioning/cloud-control-provider.ts`, the new generated `src/provisioning/getatt-attributes.generated.ts` and its generator `scripts/gen-getatt-attributes.ts` (`vp run gen:getatt-attributes`, `vp run audit:getatt-attributes:check`, chained into `gen:all-matrices`), and `src/deployment/deploy-engine/masking.ts`. The import kept only the type's registry `readOnlyProperties` and recorded every other model key as `***`, but CloudFormation also accepts some writable properties in `Fn::GetAtt` (`AWS::EC2::Subnet` `VpcId` / `CidrBlock` / `AvailabilityZone`, `AWS::SQS::Queue` `QueueName`, ...). A later deploy reading one from an imported resource was refused, and the printed remedy (`cdkd import --force`) masked the same key again. The import now also keeps the writable properties the CloudFormation resource specification lists as attributes with the same value shape, from a table generated from the pinned `@aws-cdk/aws-service-spec` devDependency (no new runtime dependency). Other writable properties stay masked (so does `AWS::SSM::Parameter` `Value`), and an unresolvable schema still masks the whole model. Docs: `docs/import-resource-types.md`.
