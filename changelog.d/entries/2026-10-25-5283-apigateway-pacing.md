- **A wide API Gateway REST API deploys and destroys without `TooManyRequestsException` (issue [#5283](https://github.com/go-to-k/cdkd/issues/5283))** -- `src/utils/apigateway-pacing.ts`, `src/utils/aws-clients.ts`, `src/provisioning/providers/apigateway-provider.ts`. cdkd sent up to 52 `CreateResource` and 74 calls per second against API Gateway's per-account limits of 5 and 10, and the SDK gave up after 3 attempts. The API Gateway clients now take a token before every attempt, retries included, from token buckets with a burst: 30 refilled at 8 per second overall, and 5 refilled at 4 per second for `CreateResource` and `DeleteResource`. A call waits for its operation's own bucket first and takes a shared token only as it is sent, so other operations are not queued behind a `CreateResource` backlog, and time is counted on a monotonic clock. A small API fits in the burst and is not delayed; a wide one settles at the steady rate. One pacer per Region, and the SDK attempts go from 3 to 8 for other callers of the same account. Measured on a 122-resource stack: deploy and destroy succeed (they failed before), throttled `CreateResource` calls 348 to 13. A `Method` whose cleanup `DeleteMethod` still fails is left behind and the replay still fails with `Method already exists for this resource`; that is tracked in [#5294](https://github.com/go-to-k/cdkd/issues/5294). Cloud Control-routed `AWS::ApiGateway::*` types and API Gateway v2 are not paced. Unit cases in `tests/unit/utils/apigateway-pacing.test.ts`, including a real SDK client against a stub handler.
