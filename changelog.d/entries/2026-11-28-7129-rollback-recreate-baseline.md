- **A resource a rollback re-creates now gets a drift baseline, and a Route 53 record's `TTL` no longer drifts as `300 -> 300` (issue [#7129](https://github.com/go-to-k/cdkd/issues/7129))** -- `src/deployment/rollback-executor/replay-observed-refresh.ts`, `replay-reverse-replacement/finish.ts`, `replay-failed-replaced-deleted.ts`, `src/provisioning/providers/route53/read-state.ts`. When a rollback reversed a replacement (for example a renamed Route 53 record in a deploy that then failed), the re-created resource was recorded without `observedProperties`, so `cdkd drift` compared the template's spelling with AWS's and reported a record's `TTL` as drifted with the same value on both sides (exit 1). The automatic rollback and `cdkd rollback` now read the re-created resource back once, as a deploy does after a create (skipped under `--no-capture-observed-state`, for a create that declares `NoEcho` attributes, and for a re-create that returned the live new resource). Drift also compares a Route 53 record's `TTL`, `Weight` and `GeoProximityLocation.Bias` (and each `RecordSetGroup` member's) as numbers on both sides, which covers records that have no baseline for another reason.
