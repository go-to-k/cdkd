- **`cdkd local start-alb` / `local start-cloudfront` Lambda targets run container-image Lambdas built on a non-AWS base image, and an init-wrapped image keeps its own emulator (issue [#6027](https://github.com/go-to-k/cdkd/issues/6027))** -- `package.json`, `src/local/rie-mount.ts`. The `cdk-local` dependency moves to 0.160.1, whose front-door Lambda runner mounts the Lambda Runtime Interface Emulator the way `local invoke` / `local start-api` already do. cdkd's own mount now leaves an image alone when ANY word of its `ENTRYPOINT` + `CMD` starts an `aws-lambda-rie*` binary (an init wrapper such as `["/tini", "--"]` starting the RIE from the `CMD` used to get a second emulator that could not bind `:8080`), and the missing-binary warning is printed once per architecture instead of once per process.
