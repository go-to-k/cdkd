- **`cdkd drift --accept` / `--revert` no longer print a state- or readback-derived value raw in their plan (issue [#3949](https://github.com/go-to-k/cdkd/issues/3949))** -- `src/cli/commands/drift.ts` (`printAcceptPlan`, `printRevertPlan`, new `reportPath` / `reportPlanChangeLine`), new `tests/unit/cli/drift-plan-sanitize.test.ts`. The plan printed before the confirmation prompt (and under `--dry-run`) interpolated each heading's stack name and region, each resource's logical id and type, each change's path and both values, and the readback tag keys and paths the revert plan lists, straight into its output, so a newline, an escape sequence or a bidi override in a hand-edited state record or an AWS value set outside cdkd could invent or erase a plan row right above the prompt that asks the operator to confirm AWS writes. They now go through the same rules as the human report ([What the human report does to a malformed value](https://github.com/go-to-k/cdkd/blob/main/docs/cli-drift.md#what-the-human-report-does-to-a-malformed-value), #3232): identifiers sanitized and capped, values JSON-quoted when a control character or edge whitespace would otherwise hide a difference. A plan value containing the plan's own ` -> ` separator is quoted too. A readback key is masked for secrets before it is capped, so the cut cannot leave part of a secret unmasked. The report and the plans now also quote a value carrying an unpaired surrogate, which a terminal otherwise shows exactly like the replacement character; `src/utils/display-safe.ts` exports the character set `safeMsg` alters (`SAFE_MSG_ALTERED_CHAR`) so the quoting rule reads it rather than a copy. An ordinary plan renders byte-for-byte as before.
