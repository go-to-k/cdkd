- **`cdkd drift` reports a resource not compared when its Tags read fails, instead of never comparing its Tags (issue [#6759](https://github.com/go-to-k/cdkd/issues/6759), part of [#6696](https://github.com/go-to-k/cdkd/issues/6696))** -- `src/provisioning/providers/agentcore-evaluator-provider.ts`, `agentcore-runtime/read-state.ts`, `cloudwatch-alarm-provider.ts`, `wafv2/read-state.ts`, `rds-dbproxy-targetgroup/read-state.ts`, `rds/calls.ts`, `elasticache/read-state.ts`, `neptune/read-state.ts`, `docdb-shared.ts`, `kinesis/read-state.ts`, `firehose/read-state.ts`, `kinesis-streamconsumer-provider.ts`, `rds-dbproxy/read-state.ts`, `rds-dbproxy-endpoint-provider.ts`, `s3-vectors-provider.ts`, `ecs/read-state.ts`, `tests/unit/provisioning/providers/subread-tags-errors-6759.test.ts`. These readbacks caught any failure of their tag read (`ListTagsForResource` and its per-service spellings) and then left `Tags` out, or recorded `Tags: []`. An `AccessDenied` or a throttle on that call left the tags out of the deploy-time baseline and out of the drift read alike, so the run said no drift for them, and a recorded `[]` could report every tag removed. Now only the call's own not-found answer keeps the old result. Any other failure makes the read fail, and `cdkd drift` reports the resource `not compared` (exit 2) with the AWS error. An ECS cluster, service or task definition whose describe call fails with anything but its not-found error now reports that error the same way, where it used to come back as a bare `unknown`.
