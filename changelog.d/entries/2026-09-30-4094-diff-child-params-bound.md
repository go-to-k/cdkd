- **`cdkd diff --recursive` resolves a nested stack's input parameters against the parent's bound parameters and conditions (issue [#4094](https://github.com/go-to-k/cdkd/issues/4094))** -- `src/cli/commands/diff-recursive.ts`. A nested row's `Parameters` were resolved only against the values handed to the parent (none at the top-level stack). A `Ref` to a parent template parameter bound from its `Default` or an SSM-typed lookup stayed unresolved, and an `Fn::If` in the row took its false branch, so the child showed a phantom UPDATE on every run and `--fail` never exited 0. The row now resolves against the parent's bound parameters and evaluated conditions, as `cdkd deploy` does. A list-typed value is joined with `,` as the deploy passes it to the child. Tests: `tests/unit/cli/diff-recursive-child-params-4094.test.ts`; the `nested-stack-3level` fixture gains a `Default`-bound root parameter and restores its `MidPinIf` row.
