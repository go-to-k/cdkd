- **A resolvable Output added beside a persistently failing one now lands on a no-change deploy, so `cdkd diff --fail` stops showing a real `ADD` for it forever (issue [#2771](https://github.com/go-to-k/cdkd/issues/2771))** -- `src/deployment/no-change-outputs-merge.ts` (new), `src/deployment/deploy-engine.ts` (no-change branch), `src/analyzer/outputs-diff.ts`, `docs/cli-diff.md`, `docs/state-management.md`, `docs/architecture.md`, with cases in `tests/unit/deployment/no-change-outputs-merge.test.ts`, `deploy-engine-outputs-only-change.test.ts`, `deploy-engine-skipped-outputs.test.ts` and `deploy-engine-outputs-generation-rules.test.ts`. Any unresolved output used to keep the previous outputs bag whole. The no-change path now persists a merge: a resolved key writes its value, a failed key keeps its stored value (and its literal export alias when the previous record published it) or stays absent, and a key this pass did not produce is removed. The export set and exports index follow the merged bag. Two shapes still keep the whole previous bag, with a warning naming why: a failed output WITH a stored value whose `Export.Name` is intrinsic, and a merge that would carry a value into a bag it gives its first secret-bearing expression, re-checked on the bag as the save redacts it, after the observed-state drain. The save no longer positions a carried key, or a bag kept whole, by today's template, which could persist a reference the stored value never came from. `computeOutputsDiff` reads its secret-expression predicate from the merge module.
