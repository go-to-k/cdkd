- **A Lambda function's `RuntimeConfig` (a customer-managed runtime and alias) stays on the SDK route** (Refs #6352). The `AWS::Lambda::Function` SDK provider did not send `RuntimeConfig`, so a function declaring it moved to Cloud Control, and stayed there. The provider now sends it on `CreateFunction` and `UpdateFunctionConfiguration`, applies an alias change in place, and reads it back from `GetFunction` for drift. Removing it together with a `Runtime` change away from `custom` clears it, as AWS does. Dropping it while `Runtime` stays `custom` is now refused before any call: AWS would keep the live value and refuses a `custom` function without one. A rollback replay warns instead. The `@aws-sdk/*` group moves to 3.1169.0, the first `@aws-sdk/client-lambda` that models the field; the new Cognito `UpdateUserPool` member `DcrConfiguration` is measured kept when omitted, so `--remove-protection` does not echo it. `AcceleratorConfig` is still sent through Cloud Control: no published Lambda SDK models it yet. Adds unit coverage and a `lambda-runtime-config` integration fixture.
