- **`Fn::GetAtt` on an `AWS::SNS::Subscription`'s `Arn` is answered from the recorded attribute instead of the physical-id fallback (issue [#3329](https://github.com/go-to-k/cdkd/issues/3329))** -- `src/provisioning/providers/sns-subscription-provider.ts`, `scripts/gen-sdk-attr-coverage.ts`. The provider recorded `attributes: {}` and let `guardedPhysicalIdFallback` answer off the physical id, which IS the subscription ARN. That worked on the ordinary path -- so the type held the tree's only `SDK_ATTR_ALLOW_LIST` entry rather than being reported as a gap -- and left three edges: a CONSTRUCTED `<topicArn>:<logicalId>` when `Subscribe` returns no ARN (ARN-shaped, so the resolver's guard passes a fabricated value), an imported `PendingConfirmation` id (where it refuses), and `--strict-getatt` (which throws on any fallback). `create` now records `Arn` from the response, answering the first and third from cache. The rule, and why each half of it, is on the two call sites: cache the ARN AWS returned, or cache nothing -- never the constructed fallback, never an imported id. `update` delegates to `create`, so a replacement carries it. The allow-list entry is DELETED, which is what verifies the caching (`classifyType` reads `cachedKeys` first, so one left behind goes inert while the matrix still reports a carve-out); probed by reverting the caching, which makes `audit:sdk-attr-coverage:check` name the gap again. The list is empty, its green state since [#1824](https://github.com/go-to-k/cdkd/issues/1824).
