- **An Athena workgroup's configuration update deploys instead of failing on the read-only `EngineVersion.EffectiveEngineVersion` (issue [#6561](https://github.com/go-to-k/cdkd/issues/6561))** -- `src/provisioning/cloud-control/update.ts`, `src/provisioning/cc-nested-create-only-patch.ts`. Any update to an `AWS::Athena::WorkGroup` whose template does not declare `WorkGroupConfiguration.EngineVersion` sent the template's `WorkGroupConfiguration` without the `EngineVersion` AWS filled in, and Cloud Control refused it with `readOnlyProperties [/properties/WorkGroupConfiguration/EngineVersion/EffectiveEngineVersion] cannot be updated`. When an object holding a nested read-only member is absent from both the previously deployed and the desired properties, the update now carries the live object as AWS holds it, as CloudFormation leaves it untouched. Removing a declared `EngineVersion` failed the same way; the update now sends `EngineVersion` as `{ SelectedEngineVersion: AUTO }` plus the live read-only `EffectiveEngineVersion`, the state CloudFormation leaves (measured); nothing the template removed is written back. That removal case is handled only for paths measured against CloudFormation, today this one; on other types it is refused by Cloud Control as before. The live read runs only for such an op, as before.
