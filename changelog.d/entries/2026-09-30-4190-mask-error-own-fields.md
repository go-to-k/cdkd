- **A masked error no longer keeps a secret in an AWS SDK exception's own error-body fields (issue [#4190](https://github.com/go-to-k/cdkd/issues/4190))** -- `src/deployment/secret-redaction.ts`. `maskSecretsInError` masked each link's `message` and `stack` and copied every other own field of the error unchanged, so an AWS SDK exception's own copy of its error body (an IAM / STS / SNS exception's `Error: { Type, Code, Message }`, or the modeled `Message` many other services' exceptions carry) kept a recorded secret that AWS echoed, and any reader that walks the error object (`util.inspect`, `JSON.stringify`, the CLI's `Fatal error:` dump) printed it. Every own field is now masked too: a string, and every string reachable through plain objects and arrays, into a copy (the original error is never written), including a `cause` that is not an `Error`. A secret held ONLY in such a field now also produces a masked copy. The fields retry classification compares exactly (`name`, `code`, `Code`, `__type`, `ccErrorCode`, `ccOperation`) are copied unchanged, and so are the retry markers and any field holding no recorded value (`$metadata`), so retry classification is unaffected. Not entered: class instances (the SDK's `$response`), accessors, and anything past 20 levels. The IAM `Policy` / `UserToGroupAddition` delete path's local copy of this masking (#4150) now uses the shared one. Tests: `tests/unit/deployment/secret-redaction-error-own-fields-4190.test.ts`.
