- **`cdkd drift` no longer reports an `AWS::EC2::VolumeAttachment`'s volume as drift on its instance (issue [#6384](https://github.com/go-to-k/cdkd/issues/6384))** -- `src/cli/commands/drift/baseline-keys.ts`, `src/provisioning/providers/ec2/read-instance-state.ts`, `src/provisioning/providers/ec2/drift.ts`. `DescribeInstances` lists a volume attached after launch under the instance's `BlockDeviceMappings`, while the drift baseline holds only the launch-time devices, so a stack with an instance and a VolumeAttachment read as drifted on every run, and `cdkd drift --revert` printed `reverted` while changing nothing. An instance whose template does not declare `BlockDeviceMappings` (the CDK `ec2.Instance` default) no longer has the list compared, as CloudFormation drift does not; a declared list is compared over its declared devices only, so an out-of-band change to one of them is still reported.
