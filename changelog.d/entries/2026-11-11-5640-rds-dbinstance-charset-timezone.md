- **The SDK provider sends `CharacterSetName`, `NcharCharacterSetName` and `Timezone` for `AWS::RDS::DBInstance` (issue [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds-provider.ts`, `src/provisioning/providers/rds/instance-create.ts` and `read-state.ts` beside it, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and a new `rds-dbinstance-charset-timezone` integ. Before, an instance declaring any of them, such as a CDK `rds.DatabaseInstance` given `characterSetName` or `timezone`, routed through Cloud Control. All three now ride `CreateDBInstance` as declared, as CloudFormation's create sends them; RDS itself still refuses one its engine does not take (a time zone outside SQL Server and Db2, an NCHAR character set outside Oracle). A read replica's create carries none of them, as under CloudFormation: it inherits its source's. All three are create-only, so a changed value replaces the instance, as under CloudFormation (a stateful replacement, refused without `--force-stateful-recreation`). `cdkd drift` reads each back. Resources already deployed through Cloud Control stay there.
