- **`Fn::GetAtt` of the remaining read-only RDS DB instance / DB cluster and DocumentDB cluster attributes now returns the value CloudFormation returns (issue [#6242](https://github.com/go-to-k/cdkd/issues/6242))** -- `src/provisioning/providers/rds/instance-attributes.ts`, a new `src/provisioning/providers/rds/cluster-attributes.ts`, `src/provisioning/providers/docdb/shared.ts`, `src/deployment/intrinsic-resolver/getatt/flat-object-attributes.ts`, `getatt.ts`, `getatt-heal.ts`, `getatt-construct-app.ts`, `src/provisioning/cloud-control/enrich.ts`, unit tests and a new `getatt-rds-docdb-attributes` integ fixture. Before, cdkd refused these with a clear error. A DB instance now records `DBInstanceStatus`, `InstanceCreateTime`, `LatestRestorableTime`, `IsStorageConfigUpgradeAvailable` (a boolean), `StatusInfos` / `ReadReplicaDBInstanceIdentifiers` / `ReadReplicaDBClusterIdentifiers` (`[]` when there are none), and, when RDS reports them, `SecondaryAvailabilityZone`, `AutomaticRestartTime`, `ResumeFullAutomationModeTime`, `PercentProgress` and `StorageOperation*`. The status-like ones are recorded only from an `available` instance the operation waited for, so not under `--no-wait` unless the operation waited anyway (a restore or replica create waits even under `--no-wait`). A DB cluster records `StorageEncryptionType` (also on the Cloud Control route, which now records the SDK provider's map), and a DocumentDB serverless v2 cluster `ServerlessV2PlatformVersion`. The whole `Endpoint` / `ListenerEndpoint` / `CertificateDetails` (instance) and `Endpoint` / `ReadEndpoint` (cluster) objects are served by assembling the dotted members cdkd already records, with string members as CloudFormation serves them, so a record written earlier serves them too; a record missing a member re-reads the resource on the next deploy that references it. A value AWS does not report stays refused, as CloudFormation refuses it.
