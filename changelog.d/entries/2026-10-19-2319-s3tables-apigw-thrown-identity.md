- **A failed S3 Tables (TableBucket, Namespace, Table), API Gateway (Account, Authorizer, Resource, Deployment, Stage, Method) or API Gateway v2 (Api, Stage, Integration, Route, Authorizer) create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/s3-tables-provider.ts`, `apigateway-provider.ts`, `apigatewayv2-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an `AccessDeniedException`, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (`AccessDeniedException. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, masked where the operation has a secret masker. A cdkd-authored or transport error keeps its text. The AWS error stays as the `cause`, so an IAM grant that is still propagating is retried as before, and an occupied name (`ConflictException ... already exists`) still says it already exists, so a create-first replacement still recognises the name collision.
