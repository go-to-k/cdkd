- **`cdkd drift` reads a Kinesis stream's `ShardCount` as its OPEN shard count, so a resharded stream no longer reports, records or reverts a wrong count (issue [#6933](https://github.com/go-to-k/cdkd/issues/6933))** -- `src/provisioning/providers/kinesis/read-state.ts`, `tests/unit/provisioning/kinesis-provider-readcurrentstate.test.ts`, `tests/integration/kinesis-stream-mode-switch/verify.sh`. The read counted `DescribeStream`'s `Shards` list, which also holds every closed parent shard a reshard leaves for the retention period and stops at 100 entries. After a reshard, drift reported counts such as `1 -> 4` on a one-shard stream, a deploy recorded the inflated count as the drift baseline, and `drift --revert` sent that count to `UpdateShardCount`. The count now comes from `DescribeStreamSummary`'s `OpenShardCount`, which the read already fetched, so no AWS call is added.
