- **`AWS::DynamoDB::GlobalTable` replicas now get their point-in-time recovery, Contributor Insights, Kinesis stream and resource policies (issue [#5365](https://github.com/go-to-k/cdkd/issues/5365))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`, `src/provisioning/dynamodb-replica-settings.ts`. A replica's `PointInTimeRecoverySpecification`, `ContributorInsightsSpecification`, `KinesisStreamSpecification`, `ResourcePolicy` and `ReplicaStreamSpecification.ResourcePolicy` were never sent, for the local table or a cross-region replica, on create or update, so a `TableV2` with `pointInTimeRecoverySpecification`, `contributorInsightsSpecification`, `kinesisStream`, `resourcePolicy` or `streamResourcePolicy` deployed without them and reported success. Each is now set through the replica's own region once the replica is active (`UpdateContinuousBackups`, `UpdateContributorInsights`, `Enable` / `Disable` / `UpdateKinesisStreamingDestination`, `PutResourcePolicy` on the replica's table or stream). Removing one resets it as CloudFormation does (measured): point-in-time recovery and Contributor Insights are turned off, streaming to the previous Kinesis stream is disabled, and the policy is deleted. An update also checks each declared setting the template did not change against AWS, so a table deployed before this fix gets them on its next update; that correction is best-effort and reported if it fails. A block cdkd cannot read is refused before any change, and a `ResourcePolicy` on a replica created in the same deploy is refused, as CloudFormation refuses it (on a create with a cross-region replica, every replica's; on an update, an added replica's).
