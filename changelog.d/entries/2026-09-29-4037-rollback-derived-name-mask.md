- **A rollback no longer prints a physical id that spells a secret-derived name (issue [#4037](https://github.com/go-to-k/cdkd/issues/4037))** -- `src/deployment/rollback-executor.ts`, `src/deployment/replacement-name-holder.ts`. The rollback masked its lines with the secrets it resolved, matching each plaintext literally, so a name taken from `{{resolve:secretsmanager:...}}` still reached the log in two shapes: the spelling an IAM / ELBv2 provider derives from it (`alice@example.com` sent as `MyStack-alice-example-com`, in `Rollback: R replacement reversed (old resource re-created as ...)` at INFO, the delete-new-first line, the retry lines and the failure line), and the id of a record whose name is still a reference this op never resolves (the replacement's new copy, the `UpdateReplacePolicy: Retain` re-adopt line and survivor warning, a `DeletionPolicy: Snapshot` rollback's pre-delete snapshot lines; the RDS / DocDB / Neptune / ElastiCache provider lines are [#4111](https://github.com/go-to-k/cdkd/issues/4111)). Every line, error, retry line and event reason a replay renders now goes through one per-op masker that adds, via the providers' `withDerivedNameMasks`, the physical ids (and their lowercased, snapshot-name and name-segment spellings) of every record whose name, or any `...Name` / `...Identifier` property (plus an allow-listed name spelled otherwise, such as ElastiCache's `ReplicationGroupId` or an ECS `Family`), is secret-derived and the names a rewriting provider derives from it under both prefix settings. An event's `physicalId` field stays exact. The unreproduced-name warning now names only the value it could not read. Tests: `tests/unit/deployment/rollback-executor-derived-name-mask.test.ts`, `tests/unit/deployment/rollback-recreate-original-name.test.ts`.
