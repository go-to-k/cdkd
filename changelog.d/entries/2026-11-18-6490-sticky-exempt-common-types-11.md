- **An `AWS::CloudFront::Distribution`, `AWS::RDS::DBProxy` or `AWS::RDS::DBProxyEndpoint` recorded `provisionedBy: 'cc-api'` returns to its SDK provider (issue [#6490](https://github.com/go-to-k/cdkd/issues/6490), batch 11)** -- `src/provisioning/provider-registry/sticky-exempt.ts` and the new `cc-to-sdk-reroute-cloudfront-distribution` and `cc-to-sdk-reroute-common-types-11` integs. The three types are now `'sdk-coverage'` members of `STICKY_CC_MIGRATION_EXEMPT`, so such a resource on Cloud Control moves to the SDK provider in place on the next deploy that changes it; `--pin-cc-api <LogicalId>` declines that. Both layers record the same id for each (the distribution Id, the proxy name, the endpoint name), observed on live resources, so nothing is replaced. `cdkd diff` annotates the move `[returning to SDK provider]`.
