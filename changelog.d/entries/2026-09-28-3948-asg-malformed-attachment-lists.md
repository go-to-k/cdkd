- **An Auto Scaling group update no longer reads a malformed list as empty and detaches every load balancer or target group (issue [#3948](https://github.com/go-to-k/cdkd/issues/3948))** -- `src/provisioning/providers/asg-provider.ts` and `src/provisioning/providers/firehose-provider.ts`, with unit tests in `tests/unit/provisioning/asg-provider-malformed-lists-3948.test.ts` and `tests/unit/provisioning/firehose-provider-malformed-tags-3948.test.ts`. Each list diff read a present-but-malformed value as an empty list. On a rollback or `cdkd drift --revert`, where the desired side is a recorded bag, a hand-edited `TargetGroupARNs: {}` or `LoadBalancerNames: "my-elb"` detached every attachment and took the group out of service. The same held for `Tags`, `MetricsCollection`, `LifecycleHookSpecificationList`, `TrafficSources` and `NotificationConfigurations`, and for a Firehose delivery stream's `Tags`. A malformed desired list is now refused before any AWS call, as is one in `create()`. A malformed recorded entry list is refused too, with a state.json repair (or `set it to []` for a secret-derived value); a recorded entry whose key came from a secret is read, and never deleted by that key. An absent (`undefined` / `null`) list still reads as empty. A recorded `LoadBalancerNames` / `TargetGroupARNs` holding any malformed value (for example a dynamic reference, or an unresolved intrinsic `cdkd import` recorded) is read from the live group instead, but only when every desired list and every other recorded list is well-formed. That read is ADD-only: a target group or load balancer the template no longer names stays attached, with a warning.
