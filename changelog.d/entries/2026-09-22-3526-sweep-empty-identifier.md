- **Every message in the malformed-state module now treats an empty stack name or region as ABSENT rather than rendering it as `<unrenderable>` (issue [#3526](https://github.com/go-to-k/cdkd/issues/3526), PR #3531)** -- `malformed-resources-bag.ts`. go-to-k/cdkd#3520 fixed five builders and recorded the other thirteen in its fence as `KNOWN_UNFIXED`, each asserted to still be broken so the list could not drift. This sweeps them: that list is now empty. **Behavior change:** a builder handed `''` renders the no-identity clause and the hole template instead of `State for '<unrenderable>' ('<unrenderable>')` and `--stack-region '<unrenderable>'`, a flag that selects no record at all. No caller can deliver `''` today (`cdkd state` throws on a falsy region, `cdkd export` normalises at its call, `namedCliRegion` floors it), so this finishes stating a contract rather than fixing an output anyone sees. Each builder stopped spelling its own `State for ${shellQuote(safeStackName(...))}` clause and its own `cdkd state show ...` tail, taking `stackClause` and `inspectCommand` instead: byte-identical for a present identity, and the absent form for `''`. `stackClause` gained an optional KIND qualifier for the one message whose subject is not a plain stack (`State for nested stack child '<name>'`), so its word order is unchanged and the no-identity arm keeps a single spelling. `namedEntriesClause` was widened the same way. The fence is per builder and per AXIS, so a half-swept builder -- one that normalised the region and not the stack name -- reds by name and axis rather than passing.
