- **A message line that shows an untrusted name no longer also offers a command to paste (issue [#3950](https://github.com/go-to-k/cdkd/issues/3950))** -- `src/state/lock-contention-message.ts`, `src/cli/commands/{rollback,events,state,destroy,scrub,import}.ts`, `src/deployment/rollback-executor.ts`, `src/provisioning/providers/ssm-parameter-provider.ts`, `src/provisioning/cc-import-identifier.ts` and `src/provisioning/composite-id.ts`. These lines showed a stack name, logical id, resource type or ARN beside a `cdkd` / `aws` command or a `--flag`, and shell in the value ran when the line was pasted: a `;` under bash on the `cdkd import` lines, a `$( )` or backtick under both shells at the composite-id refusal heads, and under zsh past a following `(` on the others. A value that is not a plain identifier is now described on that line instead, each message in its own words (for example `a stack name that is not a plain identifier` in `cdkd rollback` and `state destroy`, `(logical id not shown: it is not a plain identifier)` in `cdkd import`'s composite-id refusals, `a resource whose logical id is not a plain CloudFormation logical id` in a rollback replay's refusals). The lock-contention refusal and the SSM ARN-adopt refusal withhold their `cdkd force-unlock` / `aws ssm get-parameter` command for such a value. `cdkd import`'s `Failed to import` line and plan rows describe it too, and its not-found hint prints `--resource '<logicalId>'='<physicalId>'` for such a value (a plain one stays named, with the `'<physicalId>'` hole now quoted). A rollback collision refusal prints the provider's error on its own `Underlying collision:` line. `cdkd events` and the destroy / scrub versioning notes name cdkd's commands in prose rather than as a command. A plain name prints as before. The rest of this rule is tracked in [#4214](https://github.com/go-to-k/cdkd/issues/4214) and [#4226](https://github.com/go-to-k/cdkd/issues/4226).
