- **`cdkd local invoke` / `start-api` / `run-task` / `invoke-agentcore` no longer hand an emulated function or task a `--role-arn` assumed role through the process environment (issue [#3130](https://github.com/go-to-k/cdkd/issues/3130))** -- `src/utils/caller-credentials.ts` (new), `src/utils/aws-client-defaults.ts`, `src/utils/role-arn.ts`, `src/cli/commands/local-invoke.ts`, `src/cli/commands/local-start-api.ts`, `src/cli/commands/local-invoke-agentcore.ts`, `src/local/ecs-network.ts`, `src/local/docker-runner.ts`, `docs/cli-reference.md`, plus their unit fences. `--role-arn` overwrites the `AWS_*` credential triple with the role's, and each command copied it into the container, so `cdkd local invoke --role-arn <deploy-role> MyFn` ran the user's own handler AS THE DEPLOY ROLE, normally the more privileged identity. A `--profile`-flag overlay masked it; an EXPORTED `AWS_PROFILE`, or no profile at all, did not. The caller's own triple is now snapshotted before the assume and restored on the way in; `--sigv4` host signing reads the same snapshot. **When the caller has no static credentials to restore -- SSO, an instance role, a container role -- the triple is STRIPPED rather than inherited**, and the container falls back to its own resolution (for a bare `cdkd local invoke` that is nothing, so its first AWS call fails loudly; pass `--profile` or `--assume-role`). A run with no `--role-arn` is unchanged. **The four long-running `local start-*` commands are NOT covered** -- `start-service`, `start-alb`, `start-cloudfront` and `start-agentcore` hand off to an emulator that assumes the role itself, so the role's triple still reaches the containers of the last three, and the ECS task secrets of the first two are still fetched with it; pass the `--profile` FLAG alongside `--role-arn` there (issue [#3240](https://github.com/go-to-k/cdkd/issues/3240)). Mechanism and both channels: `.claude/rules/local-caller-identity.md`.
