- **`AWS::DynamoDB::Table` now SENDS a per-GSI `OnDemandThroughput` change (issue [#3287](https://github.com/go-to-k/cdkd/issues/3287))** -- `src/provisioning/providers/dynamodb-table-provider.ts`, `tests/unit/provisioning/dynamodb-table-provider-cfn-integer.test.ts`, `tests/integration/dynamodb-ondemand/`. `UpdateGlobalSecondaryIndexAction.OnDemandThroughput` exists in the SDK model and NEITHER per-index update arm set it, while `updateHasMember` was set only by the capacity and warm arms -- so a template whose only edit was a live index's ceiling fired no op at all, deployed GREEN and was recorded as applied, losing the edit permanently with nothing warned. Both arms (the same-name `Update` and the adopted-index repair) now carry it through `coerceOnDemandCeilingsForSend`, the reader the other four send sites use, taking the ceiling-member count from four sites to six. A live-`DescribeTable` idempotency guard withholds an op AWS already applied (the #1630 class, fail-open on anything unreadable); the change detector narrows both sides only when NOTHING was dropped, falling back to a RAW compare otherwise so a still-malformed template keeps being announced; and a block with no surviving GRAMMAR member emits no op -- and WARNS -- rather than an action AWS rejects for carrying only `IndexName`. The billing-mode question these arms share with the pre-existing `Create` arm is filed as issue [#3392](https://github.com/go-to-k/cdkd/issues/3392): AWS accepts `OnDemandThroughput` only on PAY_PER_REQUEST, and the right shape is a pre-flight refusal rather than a mid-update skip. Removing a ceiling stays a no-op at both positions, tracked as issue [#3373](https://github.com/go-to-k/cdkd/issues/3373). The RECORD side is untouched: an `effectiveProperties` + `canonicalizeDesiredProperties` fold was written for this change and WITHDRAWN, so issue [#3286](https://github.com/go-to-k/cdkd/issues/3286) stays open and now carries the evidence and a revised estimate.
