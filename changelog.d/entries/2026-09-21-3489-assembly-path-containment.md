- **An assembly-supplied path can no longer escape the assembly directory (issue [#3489](https://github.com/go-to-k/cdkd/issues/3489))** -- new `src/utils/assembly-path.ts`, applied at 19 sites across `src/synthesis/`, `src/assets/`, `src/local/`, `src/provisioning/providers/nested-stack-provider.ts` and `src/cli/commands/` (`diff-recursive`, `import`, `export`, `synth`, `local-invoke`, `local-start-api`, `local-invoke-agentcore`). Every path cdkd built from a Cloud Assembly was joined onto a directory and used unchecked, and `cdkd deploy -a <dir>` consumes a PRE-SYNTHESIZED assembly, so nothing upstream validated one. A `templateFile` of `../../../home/<user>/.aws/credentials` was read from outside the assembly and, where it parsed, became the template cdkd deploys. The sharpest case was the asset manifest, which names the DESTINATION bucket too: a `source.path` of `../../../home/<user>/.aws` was zipped and uploaded with the caller's own credentials. A `Handler` of `../../x.handler` wrote the inline `Code.ZipFile` body to an arbitrary host path. `resolveAssemblyPath` refuses a candidate resolving outside, lexically and through `realpath(3)`; its doc comment carries the rest. The absolute-path tripwire is KEPT and worded apart, and every refusal renders values through `displaySafe` (go-to-k/cdkd#3277). Asset paths RESOLVE against the manifest's directory but are CONTAINED within the app's outdir -- at `deploy`, `publish-assets`, `local run-task` and `local invoke-agentcore` alike: `cdk synth` stages a Stage's assets into the app root, so `source.path` is `../asset.<hash>` by design, and binding to the manifest's own directory refused every Stage asset. Residuals: go-to-k/cdkd#3494, go-to-k/cdkd#3497, go-to-k/cdkd#3482. `cdkd synth --verbose` also `lstat`s the path it writes, refusing a symbolic link. Tests: eleven new files, cases in eight existing ones, and a new `stage-assets` integ fixture.
