- **`cdkd diff` prefetches the create-only schema lookups, a lookup the diff waits on no longer queues behind the prefetch, and a failed lookup uses cdkd's bundled schema snapshot instead of missing create-only changes (issue [#3718](https://github.com/go-to-k/cdkd/issues/3718))** -- `src/provisioning/create-only-properties.ts`, `src/provisioning/describe-type.ts`, `src/utils/concurrency-limiter.ts`, `src/provisioning/create-only-paths.ts`, the generated `src/provisioning/create-only-snapshot.generated.ts` (from `scripts/gen-property-coverage.ts`), `scripts/refresh-cfn-schemas.mjs` and a new `createOnlyPropertyPaths` field in every `tests/fixtures/cfn-schemas/*.json`, `src/cli/commands/diff-recursive.ts`, `src/deployment/deploy-engine.ts`, with unit tests. `cdkd diff` used to run one `cloudformation:DescribeType` lookup at a time, about 0.6 s each. It now warms the types of the rows each stack's state already records (a first diff issues none), nested children included. The deploy-start prefetch sent every lookup at once: on a 134-type template the diff's own lookups waited about 18 s behind the throttled burst, and roughly 90 lookups ran out of retries, each silently missing that resource's create-only changes. All `DescribeType` calls now share a cap of 20 in flight, and a lookup the diff waits on is sent ahead of queued prefetches (measured: 0.8 s, 9-23 exhausted). A prefetch is withdrawn once its diff is done, so it never delays the command's exit. A failed lookup (missing permission, throttling) uses the committed snapshot's create-only paths for the type, which covers every type with an SDK provider, and warns; other types keep the fallback to cdkd's own rules. The fallback is not cached, so a live answer wins when it returns.
