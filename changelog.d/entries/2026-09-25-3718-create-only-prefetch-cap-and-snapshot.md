- **`cdkd diff` prefetches the create-only schema lookups, a lookup the diff waits on no longer queues behind the prefetch, and a failed lookup uses cdkd's bundled schema snapshot instead of missing create-only changes (issue [#3718](https://github.com/go-to-k/cdkd/issues/3718))** -- `src/provisioning/create-only-properties.ts`, `src/provisioning/describe-type.ts`, `src/utils/concurrency-limiter.ts`, `src/provisioning/create-only-paths.ts`, the new generated `src/provisioning/create-only-snapshot.generated.ts` (from `scripts/gen-property-coverage.ts`), `scripts/refresh-cfn-schemas.mjs` and a new `createOnlyPropertyPaths` field in every `tests/fixtures/cfn-schemas/*.json`, `src/cli/commands/diff-recursive.ts`, `src/deployment/deploy-engine.ts`, with unit tests in `tests/unit/provisioning/`, `tests/unit/utils/`, `tests/unit/cli/` and `tests/unit/deployment/`. `cdkd diff` used to run one `cloudformation:DescribeType` lookup at a time, for each resource with an unclassified change, at about 0.6 s each. It now warms every type of each stack it diffs, nested children included, while the state read runs. The deploy-start prefetch sent every lookup at once. On a 134-type template the diff's own lookups waited about 18 s behind the throttled burst, and roughly 90 lookups ran out of retries, each silently missing that resource's create-only changes. All `DescribeType` calls now share a cap of 20 in flight, and a lookup the diff waits on is sent ahead of queued prefetches (measured: 0.8 s, and 9-23 lookups exhausted). When a lookup still fails (missing permission, throttling, another error), cdkd uses the create-only paths from its committed schema snapshot for the type and warns that it did. The snapshot covers every type with an SDK provider, and a type without one keeps the old fallback to cdkd's own rules. The fallback is not cached, so the next resource of that type retries the live lookup, and a live answer always wins.
