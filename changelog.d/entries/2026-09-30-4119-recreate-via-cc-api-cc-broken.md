- **`--recreate-via-cc-api` now refuses a resource whose type cdkd keeps off Cloud Control, instead of deleting and recreating it on the SDK route while announcing a migration** (`src/deployment/recreate-targets.ts`, `src/deployment/deploy-engine.ts`, `src/provisioning/provider-registry.ts`, go-to-k/cdkd#4119). For a type whose Cloud Control handler cannot manage it (`AWS::Scheduler::Schedule`, `AWS::RDS::DBProxyTargetGroup`, `AWS::Lambda::EventInvokeConfig`), routing ignores the flag. The deploy deleted the resource, created it again through the SDK provider, and logged `--recreate-via-cc-api flag (mid-life SDK→CC migration)`. It now fails before anything is touched (`RECREATE_TARGETS_INVALID`, exit 1), naming each such resource and the reason. The deploy engine carries the same refusal for a caller that skips the pre-flight. `--recreate-via-sdk-provider` is unaffected. Tests: `tests/unit/deployment/recreate-targets.test.ts`, `tests/unit/deployment/deploy-engine-recreate-via-cc-api.test.ts`.
