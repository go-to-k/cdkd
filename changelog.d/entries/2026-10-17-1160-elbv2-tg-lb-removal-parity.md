- **Removing a property from an `AWS::ElasticLoadBalancingV2::LoadBalancer` or `TargetGroup` now does what a CloudFormation update does (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- A real CloudFormation A/B decided each case. A removed load balancer `IpAddressType` now resets to `ipv4`; before, it stayed `dualstack`. A removed `HealthCheckPort` on a GENEVE target group now resets to `traffic-port` like every other protocol; before, it kept its value. A key removed from `LoadBalancerAttributes` or `TargetGroupAttributes` now keeps its live value, because CloudFormation leaves it in place; before, cdkd reset it to a documented default or an empty value, and warned for a target group key it had no default for. A kept `access_logs.s3.*` / `connection_logs.s3.*` / `health_check_logs.s3.*` key prints one warning naming the keys, since the load balancer may keep delivering logs to the bucket they name. `ListenerAttributes` still resets. `drift --revert` writes no `IpAddressType` reset for a value its recorded baseline lacks. Changed: `src/provisioning/providers/elbv2-provider.ts`, `tests/unit/provisioning/elbv2-tg-lb-removal-1160.test.ts` and the existing ELBv2 suites, `tests/integration/alb/`.
