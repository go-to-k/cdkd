- **`cdkd deploy`'s `--replace` collision refusals and its per-resource failure line no longer show a template or state value beside a command (issues [#4291](https://github.com/go-to-k/cdkd/issues/4291), [#4308](https://github.com/go-to-k/cdkd/issues/4308))** -- `src/deployment/deploy-engine-update.ts`, `src/deployment/deploy-engine-name-collision.ts`, `src/deployment/deploy-engine.ts`, and the shared `src/deployment/collision-text.ts`. The create-first collision refusals printed the logical id, resource type, recorded physical id, the name-holder diagnosis and the provider's collision text on the line that names `cdkd deploy --replace`, and wrapped that command in backticks, which run as command substitution when pasted. A `$( )` in such a value ran when the line was pasted. The refusals now name the resource only when it is plain and describe it otherwise. The diagnosis goes on its own `Collision diagnosis:` line, and the provider text, JSON-quoted, on its own `Underlying collision:` line, as `cdkd rollback`'s twin already does. The command is printed without backticks. The `Failed to <op> <id>: <message>` line and the failure's head describe a logical id that is not plain, so a provider refusal naming `--resource-timeout` no longer sits beside a raw id. A plain id, type and physical id print as before.
