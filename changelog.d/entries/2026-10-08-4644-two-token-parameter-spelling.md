- **`cdkd diff --recursive --fail` no longer reports a change on an unchanged nested stack whose parent passes a parameter embedding `{{resolve:...}}` tokens beside a same-value sibling (issue [#4644](https://github.com/go-to-k/cdkd/issues/4644))** -- `src/deployment/secret-redaction/positions.ts`, `nested-stack.ts`, `placeholder-positions.ts`. A literal such as `postgres://{{resolve:...user}}:{{resolve:...password}}@host` had no positioning arm, so state held the map's survivor per plaintext: when a sibling parameter spelling the same password differently resolved last, the parent's own `Parameters` row, the child's `{Ref}` leaf and the deploy's diff side all held the sibling's spelling, while `cdkd diff --recursive` rendered the parameter's own literal. A literal leaf with several tokens now persists its own spelling when rendering it with the plaintexts this pass resolved each token to reproduces the resolved value exactly, its literal text holds no secret, and the value scan would rewrite only those plaintexts. The parent records that spelling per parameter -- for a one-token literal too -- and the child's diff side, its `{Ref}` leaves and its leaves embedding the parameter (`Fn::Join` / `Fn::Sub`) read it, re-checking the render. An `Fn::Join` / `Fn::Sub` source with several tokens, and a literal holding a public `ssm` token, keep the old behaviour. A child resource that persisted the sibling's spelling takes one UPDATE (a replacement on a create-only property) on its first deploy after upgrading. Tests: `tests/unit/deployment/secret-redaction-nested-parameter-fallthrough.test.ts`, `secret-redaction-embedded-span.test.ts`; integ `nested-stack-secret` gains `FallthroughPairReversed` and `FallthroughEmbedReversed`.
