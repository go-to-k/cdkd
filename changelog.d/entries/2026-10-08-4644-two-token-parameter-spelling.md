- **`cdkd diff --recursive --fail` no longer reports a change on an unchanged nested stack whose parent passes a parameter built from two or more `{{resolve:...}}` tokens beside a same-value sibling (issue [#4644](https://github.com/go-to-k/cdkd/issues/4644))** -- `src/deployment/secret-redaction/positions.ts`, `src/deployment/secret-redaction/nested-stack.ts`. A literal such as `postgres://{{resolve:...user}}:{{resolve:...password}}@host` had no positioning arm, so state held the map's survivor per plaintext: when a sibling parameter spelling the same password differently resolved last, the parent's own `Parameters` row, the child's `{Ref}` leaf and the deploy's diff side all held the sibling's spelling, while `cdkd diff --recursive` rendered the parameter's own literal. A literal leaf with several tokens now persists its own spelling when rendering it with the plaintexts this pass resolved each token to reproduces the resolved value exactly, its literal text holds no secret, and the value scan would rewrite only those plaintexts; the parent records that spelling per parameter and the child's diff and persist sides read it, re-checking the render. Anything else keeps the previous redaction. An `Fn::Join` / `Fn::Sub` source with several tokens, and a literal holding a public `ssm` token, keep the old behaviour. Tests: `tests/unit/deployment/secret-redaction-nested-parameter-fallthrough.test.ts`, `tests/unit/deployment/secret-redaction-embedded-span.test.ts`; integ `nested-stack-secret` gains the reversed-order arm `FallthroughPairReversed`.
