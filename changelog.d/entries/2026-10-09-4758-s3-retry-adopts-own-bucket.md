- **A retried S3 bucket create with an explicit `BucketName` no longer refuses the bucket its own first attempt made (issue [#4758](https://github.com/go-to-k/cdkd/issues/4758))** -- `src/provisioning/providers/s3-bucket-provider.ts`. When a create made the bucket, then failed on a configuration call that cdkd retries (a permission or throttling error, say), and could not delete the bucket again, the retry met that bucket: S3 answered `BucketAlreadyOwnedByYou` (or, in us-east-1, the pre-flight found it), and the explicit-name refusal (issue [#4684](https://github.com/go-to-k/cdkd/issues/4684)) failed a deploy the retry would have finished. The failed attempt now records the bucket's identity (name, region and the `CreationDate` this account's `ListBuckets` reports), and the retry of the same create takes the bucket as its own only while it still has that identity; any other holder of the name is refused as before. A generated name is unaffected. Tests: `tests/unit/provisioning/providers/s3-bucket-retry-own-bucket-4758.test.ts`.
