- **`Fn::GetStackOutput` no longer prints a producer stack name or region in the clear when the state read fails (issue [#3234](https://github.com/go-to-k/cdkd/issues/3234))** -- `src/deployment/intrinsic-function-resolver.ts`, `src/deployment/secret-redaction.ts`, cases in `intrinsic-resolver-name-argument-log-twin.test.ts`. The resolver masked every name it printed itself, then handed the RAW `StackName` and `Region` to the state read -- they are state-key segments -- and `S3StateBackend` quoted them back through an ASCII sanitizer, not a masker. The read was uncaught, so that sentence reached `evaluateConditions`' default-verbosity warn and every other caller with a 1-3 character secret, assembled into the name by `Fn::Sub` or `Fn::Join`, still readable. The read is now wrapped and the failure re-thrown as a masked CLONE of the whole cause chain rather than a new wrapper: `formatError` renders `Caused by: <cause>`, so masking only a fresh top-level message would print the original one link down. The clone keeps the class and every own descriptor, so `markNonRetryable`'s marker, `$metadata`, `Code` and `name` still reach the retry classifiers, and `stack` is masked too. `maskSecretsInError` takes an optional text transform for this: the bags mask by VALUE and a sub-floor secret is below `MIN_NEEDLE_LENGTH`, so only the frame holding both the raw name and its masked log text can substitute one for the other. It runs BEFORE the bag pass, and contributes the `displaySafe`-sanitized spelling too, since that is what the reader is shown. The `DescribeStacks` fallback warn, reached from the same caller, takes the same pass, since a real `AccessDenied` quotes the stack ARN back at default verbosity. Residuals: a name the state backend LOGS directly rather than throwing (its legacy-layout warn) cannot be reached from the caller's catch at all, and the `Fn::ImportValue` sibling masks its caught message with the bags alone, so the positional half is still open there.
