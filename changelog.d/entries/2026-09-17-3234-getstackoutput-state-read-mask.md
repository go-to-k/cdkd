- **`Fn::GetStackOutput` no longer prints a producer stack name or region in the clear when the state read fails (issue [#3234](https://github.com/go-to-k/cdkd/issues/3234))** -- `src/deployment/intrinsic-function-resolver.ts`, `src/deployment/secret-redaction.ts`, cases in `intrinsic-resolver-name-argument-log-twin.test.ts`. The resolver masked every name it printed itself, then handed the RAW `StackName` and `Region` to the state read -- they are state-key segments -- and `S3StateBackend` quoted them back through an ASCII sanitizer, not a masker. The read was uncaught, so that sentence reached `evaluateConditions`' default-verbosity warn, and every other caller as a throw, with an `Fn::Sub`-assembled 1-3 character secret readable. The read is now wrapped and the failure re-thrown as a masked CLONE of the whole cause chain rather than a new wrapper: `formatError` renders `Caused by: <cause>`, so masking a fresh top-level message alone would print the original one link down. The clone keeps every own descriptor, so `markNonRetryable`'s marker, `$metadata`, `Code` and `name` still reach the retry classifiers. `maskSecretsInError` takes an optional text transform for this, since a bag masks by VALUE and cannot see a sub-floor secret embedded in a longer name; it substitutes the `displaySafe`-sanitized spelling as well, that being what the reader is shown. The `DescribeStacks` fallback warn takes the same pass, since a real `AccessDenied` quotes the stack ARN back at default verbosity. Residuals: a name the state backend LOGS directly rather than throwing (its legacy-layout warn) cannot be reached from the caller's catch at all; the `Fn::ImportValue` sibling masks its caught message with the bags alone, so the positional half is still open there; and a log twin keeps the template's literal parts verbatim, so the resolver's own lines can still print a control character a name carried -- `maskSecretsForLog` masks, it does not sanitize.
