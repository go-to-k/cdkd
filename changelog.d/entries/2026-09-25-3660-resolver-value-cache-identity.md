- **The resolver's account-identity, dynamic-reference and availability-zone caches are keyed by the credential identity (issue [#3660](https://github.com/go-to-k/cdkd/issues/3660))** -- `src/deployment/intrinsic-function-resolver.ts`; tests in `tests/unit/deployment/resolver-value-cache-identity.test.ts`. A library caller that installed `AwsClients` for one account, resolved, then installed `AwsClients` with other explicit credentials in the same process was answered from the first identity's caches: `AWS::AccountId` (and every ARN built from it), `{{resolve:...}}` values on a reused resolver, and `Fn::GetAZs` lists all came back as the first account's. Each cache now also keys on the active credential fingerprint (profile plus access key id, never a secret), and the account cache keeps its short fabricated-answer window, single in-flight lookup and reset invalidation per identity. CLI runs are unaffected: one process has one identity. The masked-output recovery store is tracked separately in [#3691](https://github.com/go-to-k/cdkd/issues/3691).
