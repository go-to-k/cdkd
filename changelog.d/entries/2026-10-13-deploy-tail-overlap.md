- **A deploy finishes sooner after its last resource** -- `src/provisioning/providers/dynamodb-table-provider.ts`, `src/state/lock-manager.ts`, `src/cli/commands/deploy.ts`. A deploy whose last resource was a DynamoDB table waited for six serial reads of that table (tags, point-in-time recovery, TTL, resource policy, Kinesis destination, contributor insights) before saving state; they now run concurrently, in the same result key order. `cdkd deploy` also no longer waits for the lock's old-version purge before its events flush: the lock is still deleted before the deploy returns, and the purge finishes beside the flush, before the command exits. Other commands release their lock as before. Tests: `tests/unit/provisioning/dynamodb-table-provider-readcurrentstate.test.ts`, `tests/unit/state/lock-noncurrent-version-purge.test.ts`.
