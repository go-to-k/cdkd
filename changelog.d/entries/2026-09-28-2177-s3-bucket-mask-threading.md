- **The S3 bucket provider masks secret-derived bucket names in its own log lines (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), S3 bucket slice)** -- `src/provisioning/providers/s3-bucket-provider.ts`; unit tests in `tests/unit/provisioning/s3-bucket-provider-mask-threading.test.ts`. A `BucketName` resolved from a `{{resolve:secretsmanager:...}}` reference used to reach most of the provider's own debug and warning lines in plaintext (every `Applied ... to bucket`, `Deleted ... on bucket` and region-guard line), since those lines pass through no deploy-engine mask. `create()` and `update()` now run every configuration step on a per-call view whose logger routes each line through the deploy's masker, and each bucket name, configuration Id, lifecycle rule Id and storage class is masked before it joins the sentence, so a value that IS a secret shorter than four characters is caught too. On `update()` the recorded bucket name is masked as well when the previous `BucketName` in state is a secret reference, which covers a rotated secret whose old plaintext is in no bag of this deploy. The `delete()` path still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
