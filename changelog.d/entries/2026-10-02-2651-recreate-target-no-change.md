- **`--recreate-via-cc-api` / `--recreate-via-sdk-provider` now recreate a target whose template did not change (issue [#2651](https://github.com/go-to-k/cdkd/issues/2651))** -- new `src/deployment/recreate-target-promotion.ts`, `src/deployment/deploy-engine/{deploy-flow,update}.ts`, `docs/cli-deploy-safety.md`. Moving a resource between provisioning layers is not a template edit, so the diff called the target NO_CHANGE and never dispatched it: the deploy printed the consented recreate plan, then "No changes detected", and exited 0 with the record still on the old layer. A target the diff calls NO_CHANGE is now made an UPDATE before the deploy counts its changes, and the UPDATE arm's post-resolution no-op skip no longer applies to a target, so the destroy + recreate runs and the summary counts it as an update. A target this deploy deletes instead (a `Condition` now false), or one it has no row for, is not recreated and is warned about by name. Also documents (issue [#2666](https://github.com/go-to-k/cdkd/issues/2666)) that `--force-stateful-recreation` reaches nested child stacks, where it both clears the stateful guard and empties a replaced S3 bucket or ECR repository. Tests: `tests/unit/deployment/{recreate-target-promotion,deploy-engine-recreate-target-no-change}.test.ts`; the `cc-to-sdk-reroute` integ gains an unchanged-template recreate phase.
