- **`cdkd state destroy` refuses a stack deployed with `terminationProtection: true` (issue [#5238](https://github.com/go-to-k/cdkd/issues/5238))** -- `src/types/state.ts` (`terminationProtection`, carried by `stackInstanceIdCarriedFrom`), `src/deployment/deploy-engine/deploy-flow.ts`, `src/deployment/deploy-engine/options.ts`, `src/cli/commands/deploy.ts`, `src/cli/commands/state.ts`, `src/cli/commands/destroy.ts`, `src/utils/error-handler.ts`, `docs/cli-destroy.md`, `docs/cli-state-writing.md`, a new unit file. Before, `cdkd state destroy` (no CDK app) could not see the setting and deleted a protected stack after the ordinary prompt. Each deploy now records the synthesized stack's setting in its state (root stacks only; a deploy that changes nothing else still saves a toggle), and `cdkd state destroy` refuses such a stack with `STACK_TERMINATION_PROTECTION` (exit 2) unless `--remove-protection` is given. `cdkd destroy` also honors the recorded setting, so code that dropped the protection protects nothing only once it is redeployed, as in CloudFormation. The field is additive, so no schema bump; a record an earlier version wrote is unprotected until its next deploy.
