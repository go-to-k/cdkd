- **A failure that cannot be converted to text no longer turns a best-effort handler in `cdkd deploy` or `cdkd diff` into a hard failure, nor replaces a provider's rejection with a `TypeError`** (`src/deployment/deploy-engine/{create,delete,deploy-flow,execute,observed-capture,outputs,provision,replacement,rollback,update-in-place,update-replace}.ts`, `src/cli/commands/diff-recursive.ts`, go-to-k/cdkd#3361). These handlers built their message with `x instanceof Error ? x.message : String(x)` (or its `x.message || x.name` variant), and `String()` throws for a null-prototype object, so the handler itself threw: a failed per-resource, post-rollback or post-output-failure state save, a failed lock release, and a failed rollback-journal write, pop or delete stopped the deploy instead of warning; a failed observed-properties readback failed the deploy before its final state save; a failed output resolution off `--strict-getatt` failed instead of skipping the output; a failed final snapshot or old-resource delete during a replacement lost its handling; a failed DELETE was replaced by a `TypeError` before the not-found check and the per-resource failure report could read it; and `cdkd diff`'s partial parameter binding and condition evaluation fallbacks failed the diff. Each now goes through `describeAwsFailure(x).detail` (`safeStringify(x)` on the output handler's `String` arm), byte-identical whenever the value converts and a placeholder only when it cannot. Tests: `tests/unit/deployment/deploy-engine-string-outthrow-3361.test.ts`.
