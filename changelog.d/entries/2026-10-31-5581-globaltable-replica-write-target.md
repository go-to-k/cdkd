- **`AWS::DynamoDB::GlobalTable` deregisters the scalable targets a removed replica leaves in its region (issue [#5581](https://github.com/go-to-k/cdkd/issues/5581))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`. When a replica is added to an autoscaled PROVISIONED global table, DynamoDB itself registers Application Auto Scaling targets for the replica's table in the replica's region, the write dimension included. Removing the replica, by an update or by `cdkd destroy`, deregistered only the read target. The write target (and any index target) stayed registered after the table was gone, and a later table of the same name in that region took it over. After a replica is dropped, by an update, a destroy, or the cleanup of a failed create, cdkd now reads the replica's table in its region. Once that table reads `DELETING` or not found, cdkd lists the region's DynamoDB scalable targets and deregisters each one for `table/<name>` or `table/<name>/index/<index>`. A table that reads any other state keeps its targets, and so does a failed read or list. Each of those cases logs a warning with the command to run. The delete path's existing auto-scaling teardown warnings now mask recorded secret values as well.
