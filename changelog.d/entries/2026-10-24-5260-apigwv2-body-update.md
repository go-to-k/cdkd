- **A redeploy that edits an `AWS::ApiGatewayV2::Api`'s inline OpenAPI `Body` now updates the API in place instead of failing with "Redundant fields [...] provided when either Body or BodyS3Location is not empty" (issue [#5260](https://github.com/go-to-k/cdkd/issues/5260))** -- `src/provisioning/apigwv2-body-import-patch.ts`, `src/provisioning/cloud-control-provider.ts`, unit cases, and a two-edit phase in the `cc-api-fallback` integ. Such an API is routed through Cloud Control, which applies an update to the model it reads back. That model carries `Name`, `ProtocolType` and four more keys that API Gateway refuses beside `Body`, and no Cloud Control patch can leave them out: removing the create-only `ProtocolType` is itself refused. So cdkd now sends a change to `Body`, `BasePath` or `FailOnWarnings` through `ReimportApi`, as the import path does, and sends any other changed property through Cloud Control without the import keys. A `Tags` or `Description` change on such an API goes through Cloud Control with the import keys left out, including the write-only `Body` every Cloud Control update re-adds. A declared `Description` is re-sent after the reimport, since a definition holding `info.description` overwrites it. A change to a `BodyS3Location` definition, or to `BasePath` / `FailOnWarnings` on an API defined by one, is refused with a message naming the two ways out (inline `Body`, or a replacement), since `ReimportApi` takes the definition's text only; CloudFormation accepts that change.
