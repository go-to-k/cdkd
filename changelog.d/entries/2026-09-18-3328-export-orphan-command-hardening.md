- **`cdkd export`'s refusals no longer build a pasteable `cdkd state orphan` line out of a record-derived stack name, and no longer render one raw (issue [#3328](https://github.com/go-to-k/cdkd/issues/3328), review rounds 3-4)** -- `src/cli/commands/export.ts`, `tests/unit/cli/export.test.ts`. `walkCdkdStateStackTree` mints each nested child's stack name as `${parent}~${logicalId}` from the record's own `resources` keys -- body content anyone able to write one state key chooses -- and RECURSES, so from depth 2 the name a refusal prints is itself record-derived. Three messages then suggested `cdkd state orphan <that name>`: the missing-nested-child refusal sanitized it but did not SHELL-QUOTE, so `'`, `;`, `|` and backticks reached a line an operator pastes into a shell; the missing-asset-path refusal and the CFn-migration state-deletion warn rendered it RAW, so a newline in a logical id forged whole lines around a DELETE command. All three now go through `orphanCommandFor`, which applies both halves of the rule `malformed-resources-bag.ts` records: sanitize THEN shell-quote, and GATE the substituted form on the identity rendering EXACTLY -- `displaySafe` trims, so a record keyed `'prod-api '` renders byte-identically to a healthy `prod-api`, and an operator filling the template with the name printed above it would orphan the intact record. When it does not render exactly the message names no target and sends the reader to `cdkd state list --long`. Its `region` is required: omitting `--stack-region` drops the record for that name in EVERY region. The migration's failure SUMMARY -- a multi-line `  - cdkd/<stack>/<region>/state.json: <reason>` block ending on "orphan each record listed" -- sanitizes every field too, since a planted newline forges a row there naming a healthy stack; the free-form SDK reason takes `safeDetail`, not the identifier helper. `safeSegment`'s truncation marker is `displayIdent`'s counted form rather than a forgeable bare `[cut]`.
