- **A cross-stack secret read EMBEDDED in a longer string now persists its OWN `{{resolve:...}}` expression, not a sibling's (issue [#2298](https://github.com/go-to-k/cdkd/issues/2298))** -- `src/deployment/secret-redaction/placeholder-positions.ts`. A leaf such as `Fn::Sub 'jdbc:...password=${Child.Outputs.Pw}'`, or an `Fn::Join` / bound `Fn::Sub` variable over an `Fn::ImportValue` / `Fn::GetStackOutput` / nested-stack `Fn::GetAtt`, was redacted by the plaintext-keyed value scan. When another leaf of the same resource resolved to the same plaintext (one secret at two version-stage spellings), the embedded leaf was persisted with the OTHER reference, which a rollback or `cdkd drift --revert` would re-resolve and push to AWS as the wrong secret version. No plaintext was exposed. Each embedded reference is now answered from the association the resolver recorded for that reference, and only when the template's literal text plus those values rebuild the resolved string exactly; anything else falls back to the value scan as before. A resource whose record holds the sibling's expression can take one UPDATE on the first deploy after upgrading (a replacement if the property is create-only), even though the value sent is unchanged. Tests: `tests/unit/deployment/secret-redaction-cross-stack-embedded.test.ts`; integ arm `EmbedSecretPair` in `tests/integration/nested-stack-secret/`.
