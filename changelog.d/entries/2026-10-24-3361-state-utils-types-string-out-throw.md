- **A corrupt exports index no longer prints its contents, and the last state / utils / types catches stop out-throwing an unconvertible value (issue [#3361](https://github.com/go-to-k/cdkd/issues/3361))** -- `src/state/export-index-store.ts`, `src/state/s3-state-backend.ts`, `src/state/s3-replication-purge-gap.ts`, `src/utils/role-arn.ts`, `src/utils/assembly-path.ts` and `src/types/rollback-journal.ts`, with a new unit file and the replication-check suite. When the exports index failed to parse, the `Exports index corrupt (...)` warning quoted the JavaScript parser's message, which repeats part of the index body, and the index holds resolved Output values. It now reports only the size, plus the position when the parser states one, as the read-only path already did. Separately, these catches and the helpers they call built their message with `x instanceof Error ? x.message : String(x)`, which throws for a value that cannot be converted to text (a null-prototype object), so the failure being reported was replaced by an unrelated `TypeError`. That cost the corrupt-index rebuild, and the replication check's own report on a failed probe. These now print a fixed placeholder for such a value. Text for every other value is unchanged.
