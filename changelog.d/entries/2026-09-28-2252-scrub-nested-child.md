- **`cdkd scrub` now repairs nested-stack child records (issue [#2252](https://github.com/go-to-k/cdkd/issues/2252))** -- `src/cli/commands/scrub.ts`, `docs/_contents/cli-scrub.md`, `tests/unit/cli/commands/scrub-nested-child.test.ts`, `tests/integration/scrub-nested-child/`. **Before:** scrub visited only synth stacks, so a `{parent}~{Child}` record a cdkd older than the nested-parameter redaction (#1903) wrote with the decrypted secret was never examined, and `cdkd scrub --dry-run --fail` exited 0 over it. A redeploy never rewrote it either while the child's resources stayed unchanged. **Now:** scrubbing a stack scrubs every nested stack under it, at any depth, right after its parent and under the child's own lock. The child's needles come from the parent's resolution of the `Parameters` block it passes, threaded in the way a deploy threads them to the child engine, so an object-spelled parameter (#3062's frame carry) is repaired too. A child whose record exists but whose parameters scrub cannot derive -- including a `<parent>~...` record no template or state row reaches, found by listing the parent's region -- is refused with `SCRUB_NESTED_CHILD_UNRESOLVABLE` (exit 2), never reported clean; a cyclic or escaping nested template tree refuses its stack with `SCRUB_NESTED_TEMPLATE_TREE_MALFORMED`. A child state name passed as a stack argument is answered with the parent to name instead. As for any stack, the pre-scrub body survives as a noncurrent version on a versioned bucket; scrub does not purge it.
