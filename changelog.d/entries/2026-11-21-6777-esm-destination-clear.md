- **Removing an event source mapping's on-failure destination now clears it on AWS, and `cdkd drift --revert` works on a stream mapping without one (issue [#6777](https://github.com/go-to-k/cdkd/issues/6777))** -- `src/provisioning/providers/lambda-eventsource/update.ts` (`holdsDestination`, `destinationConfigForUpdate`), `tests/unit/provisioning/lambda-eventsource-provider.test.ts`, and the `dynamodb-stream-filter` integ fixture. A `DestinationConfig` removed from the template (or declared as `{}`) was sent as `{}`, which Lambda ignores: the destination stayed live while state recorded none, and `cdkd drift` reported nothing. CloudFormation clears it. When the previous side names a destination, cdkd now sends `{ OnFailure: { Destination: '' } }`, the measured clearing shape. A mapping without a destination reads back `{ OnFailure: {} }`, which Lambda refuses ("The Destination field is required for an OnFailure configuration"), so a drift revert of any member of such a mapping failed; a desired value naming no destination is now omitted when there is nothing to clear. A declared destination is sent as before, with no extra AWS call. `ScalingConfig: {}` and `MetricsConfig: { Metrics: [] }` were measured to reset and are unchanged. A destination an earlier release left live stays invisible to drift (the observed baseline recorded it); clear it with `aws lambda update-event-source-mapping --uuid <id> --destination-config '{"OnFailure":{"Destination":""}}'`, then `cdkd drift <stack> --accept`.
