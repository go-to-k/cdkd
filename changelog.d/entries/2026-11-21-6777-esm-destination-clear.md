- **Removing an event source mapping's on-failure destination now clears it on AWS, and `cdkd drift --revert` works on a stream mapping without one (issue [#6777](https://github.com/go-to-k/cdkd/issues/6777))** -- `src/provisioning/providers/lambda-eventsource/update.ts` (`clearedDestinationConfig`, `destinationConfigForUpdate`), `tests/unit/provisioning/lambda-eventsource-provider.test.ts`, and the `dynamodb-stream-filter` integ fixture. A `DestinationConfig` removed from the template was sent as `{}`, which Lambda ignores: the destination stayed live while state recorded none, `cdkd drift` reported no drift and the next deploy no changes. CloudFormation clears it. The removal now sends `{ OnFailure: { Destination: '' } }`, the measured clearing shape. A mapping without a destination reads back `DestinationConfig: { OnFailure: {} }`, which Lambda refuses to be sent ("The Destination field is required for an OnFailure configuration"), so a drift revert of any member of such a mapping failed; a desired `OnFailure` without a `Destination` is now sent as the clearing shape. A declared destination is sent as before, and an ordinary deploy makes no extra AWS call. `ScalingConfig: {}` and `MetricsConfig: { Metrics: [] }` were measured to reset and are unchanged.
