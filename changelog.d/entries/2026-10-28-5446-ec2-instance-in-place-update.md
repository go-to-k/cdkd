- **An `AWS::EC2::Instance` update now applies `InstanceType`, `UserData`, `IamInstanceProfile` and `SecurityGroupIds` as CloudFormation does (issue [#5446](https://github.com/go-to-k/cdkd/issues/5446))** -- `src/provisioning/providers/ec2-provider.ts`, `src/analyzer/replacement-rules.ts`, `src/analyzer/diff-calculator.ts`. These changes used to deploy "successfully" while the instance kept its old values. Now, matching CloudFormation (measured): an `InstanceType` / `UserData` change stops the instance, modifies it and starts it again (one stop for both); `IamInstanceProfile` is associated, replaced or disassociated with no interruption; `SecurityGroupIds` changes in place when the instance has a `SubnetId` (a removal moves it to the VPC's `default` group) and replaces the instance when it has none. A `BlockDeviceMappings` change replaces the instance, except a `DeleteOnTermination`-only change, which is applied in place. A removed `UserData` is cleared; a removed `InstanceType` is refused, as CloudFormation fails it. An instance-store-backed instance, which cannot be stopped, is refused with a pointer to `--replace`.
