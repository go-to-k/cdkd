- **A failed Neptune DB subnet group, DB cluster or DB instance, or DocumentDB DB subnet group, DB cluster or DB instance create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/neptune-provider.ts`, `docdb-provider.ts`, `docdb-subnet-group-provider.ts`, `docdb-shared.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker. This includes a failure after `CreateDBCluster` / `CreateDBInstance` returned (a denied status read while waiting for `available`), which still names the cluster or instance left behind for `cdkd rollback --revert-failed`. A cdkd-authored or transport error keeps its text, masked. The AWS error is still the wrap's `cause`, so an IAM grant that is still propagating is retried as before, and an "already exists" is still stated as such.
