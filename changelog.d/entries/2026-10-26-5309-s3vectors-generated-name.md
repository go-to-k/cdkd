- **An `AWS::S3Vectors::VectorBucket` without `VectorBucketName` is now created under a generated name instead of being refused (issue [#5309](https://github.com/go-to-k/cdkd/issues/5309))** -- `src/provisioning/providers/s3-vectors-provider.ts`, `src/provisioning/resource-name.ts`. The CloudFormation schema leaves the name optional and CloudFormation generates one, but the SDK provider failed the create with `VectorBucketName is required`. The type now has a generated-name rule (63 characters, lowercase), so a nameless bucket is named `{stack}-{logicalId}-{suffix}`, lowercased, like the other generated names. A legacy stack's Cloud Control create still leaves the name to the handler, and the type is not admitted to orphan adoption. Unit cases in `tests/unit/provisioning/providers/s3-vectors-provider.test.ts`; the `s3-vectors` integ fixture deploys, updates and destroys a nameless bucket.
