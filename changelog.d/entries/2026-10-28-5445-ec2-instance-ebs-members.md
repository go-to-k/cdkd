- **An `AWS::EC2::Instance` EBS volume declared `Encrypted` / with a `KmsKeyId` is now created encrypted with that key (issue [#5445](https://github.com/go-to-k/cdkd/issues/5445))** -- `src/provisioning/providers/ec2-provider.ts`. `BlockDeviceMappings` sent only `DeviceName` and `Ebs.{VolumeSize,VolumeType,DeleteOnTermination}` to `RunInstances`, so `Ebs.Encrypted`, `Ebs.KmsKeyId`, `Ebs.Iops`, `Ebs.SnapshotId`, `VirtualName` and `NoDevice` were silently dropped: a volume declared encrypted was encrypted only if the account's EBS encryption-by-default said so, and never with the declared customer managed key. Every member CloudFormation declares is now sent (`NoDevice: {}` as the SDK's `""`), and so is `NetworkInterfaces[].EnaSrdSpecification` (ENA Express), which was dropped the same way. An `Ebs.Encrypted` that reads as neither `true` nor `false` now fails the create instead of being dropped. Instances deployed before this fix keep their volumes as created: `cdkd drift` does not report them when state holds the snapshot AWS reported after the launch (the default) and a redeploy changes nothing. To find them, compare `aws ec2 describe-volumes` (`Encrypted`, `KmsKeyId`) for the instance's volumes with the template; fixing one means replacing the instance (#5446 tracks update handling).
