- **`--aws-emulator`: every remaining printed `cdkd ...` remedy keeps the run's typed flags (issue [#6262](https://github.com/go-to-k/cdkd/issues/6262))** -- `src/utils/pasteable-command.ts` (`cdkdRemedy`, `pasteableCommand`) callers across `src/cli/commands/**`, `src/provisioning/providers/**`, `src/deployment/**`, `src/state/**` and `src/assets/**`. Follow-up to #6245: the remedies cdkd still spelled as fixed text (`cdkd orphan`, `cdkd bootstrap`, `cdkd drift --accept` / `--revert`, `cdkd import`, `cdkd rollback --revert-failed`, `cdkd destroy`, `cdkd refactor`, `cdkd force-unlock`, `cdkd state ...`, `cdkd scrub`, `cdkd export` and others) printed without `--aws-emulator`, `--profile`, `--state-bucket` or `--state-prefix`, so one pasted under an emulator run reached real AWS. They now carry those flags as typed; with no flag typed the text is unchanged, except that a bare `<placeholder>` in a command (`cdkd force-unlock <stack-name>`, `cdkd orphan <construct path>`) is now printed quoted (`'<stack-name>'`), since a bare one is a shell redirection that would swallow the appended flags. A remedy the sentence wraps in quotes or backticks (`Re-run 'cdkd bootstrap' for this region`) keeps the wrapper only when the printed command holds no quote character; once it does — a quoted hole such as `--role-arn '<role-arn>'` or `--profile '<profile>'`, a quoted placeholder, or a shell-quoted stack name — the command is printed unwrapped, since the wrapper would turn the hole back into a bare redirection. The Firehose `Re-deploy with cdkd deploy --replace.` refusal no longer ends in a double period. Tests: `tests/unit/utils/pasteable-run-flags.test.ts` (a fence that fails on a new literal remedy), `tests/unit/utils/pasteable-remedies-6262-*.test.ts`.
