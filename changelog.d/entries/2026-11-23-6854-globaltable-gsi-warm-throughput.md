- **`cdkd drift` now compares an `AWS::DynamoDB::GlobalTable` index's `WarmThroughput` when the template declares it, as it does for `AWS::DynamoDB::Table` (issue [#6854](https://github.com/go-to-k/cdkd/issues/6854))** -- `src/provisioning/providers/dynamodb-globaltable/drift.ts` (`canonicalizeIndexWarmThroughput`, now in `canonicalizeDriftPair`), `dynamodb-globaltable/read.ts`. The per-index value was stripped from both drift sides even when declared, so a declared value that differed from the live one was never reported. Now an index whose template entry declares `WarmThroughput` compares the declared members, and an index declaring none (or a record with no template) is still not compared, since AWS reports a computed value for every index. A value AWS grew with traffic reports as drift, as CloudFormation drift does; `drift --revert` skips the decrease AWS would refuse and warns, as for the table type. While a raise is still `UPDATING`, the read-back reads the declared value, so a deploy's baseline does not freeze the old one. A baseline an earlier cdkd captured while a declared raise was still `UPDATING` holds the old value and reports the raise once; `cdkd drift --accept` or the next deploy records the current value.
