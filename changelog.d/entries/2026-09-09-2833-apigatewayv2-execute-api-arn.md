- **`AWS::ApiGatewayV2::Api` resolves `ExecuteApiArn` instead of hard-failing the deploy (issue [#2833](https://github.com/go-to-k/cdkd/issues/2833))** -- `src/provisioning/providers/apigatewayv2-provider.ts`, `src/deployment/intrinsic-function-resolver.ts`, `scripts/gen-sdk-attr-coverage.ts`, `tests/unit/provisioning/apigatewayv2-execute-api-arn.test.ts`, `tests/unit/deployment/intrinsic-functions.test.ts`. **Bug:** AWS published this read-only attribute in the schema capture refreshed by issue [#2821](https://github.com/go-to-k/cdkd/issues/2821); the provider recorded only `ApiId` / `ApiEndpoint` and `constructAttribute` had no handler for the type. A cross-resource `Fn::GetAtt` reads the CACHED `resource.attributes[<CFnName>]` and never calls `getAttribute`, so it reached `guardedPhysicalIdFallback`, which HARD-THROWS for a `*Arn` whose fallback is not `arn:`-shaped -- the physical id is a bare api id. Broken deploy, not a wrong value (the [#1179](https://github.com/go-to-k/cdkd/issues/1179) class). **Fix, two halves.** `CreateApi` returns no ARN, so `buildExecuteApiArn` constructs `arn:<partition>:execute-api:<region>:<account>:<apiId>` on create, on `import()`, and as an update HEAL -- partition DERIVED rather than hardcoded, region canonicalized, a FABRICATED account refused with a warning rather than persisted, and a build failure never failing the create. The heal writes only when EVERY member is in hand: the engine REPLACES attributes, so a partial map would ERASE an ARN an earlier deploy recorded. That still leaves every record whose API is unchanged, since NO_CHANGE runs no provider -- so `constructAttribute` gained the type too, covering pre-existing, CC-routed and cross-binary records with no property change required. **Not allow-listed:** a `knownGap` entry would have turned the critic green in one line; the `carries no KNOWN GAP entries` fence refuses that, and deleting an entry is what verifies a fix, since `classifyType` tests `cachedKeys` first.
