- **`cdkd deploy` of a stack whose custom resource feeds an imported export goes through when the handler returns the same value (issue [#6865](https://github.com/go-to-k/cdkd/issues/6865))** -- `src/deployment/export-change-guard.ts`, `src/deployment/deploy-engine/deploy-flow/plan-checks.ts`, `src/deployment/deploy-engine/execute.ts`, `src/utils/error-handler/deploy-errors.ts`, `tests/unit/deployment/export-change-guard.test.ts`, `tests/unit/deployment/deploy-engine-cr-export-deferred-6865.test.ts`, `tests/integration/cross-stack-export-in-use/`. Any in-place update of a custom resource whose attribute or `Ref` an export reads was refused up front with `ExportInUseError` while a stack outside the run imported the export, even when the handler returned the same value; with a `Timestamp` that changes every deploy, that was every deploy. As in CloudFormation, the export is now checked after the custom resource is updated: the same value deploys, and a changed value fails the deploy, which rolls back by re-running the handler with the previous properties (`--no-rollback` keeps the update for `cdkd rollback`). Every other resource type keeps the check before any change.
