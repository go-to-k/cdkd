- **Changing a Cloud Map service in an HTTP namespace no longer fails the deploy (issue [#6484](https://github.com/go-to-k/cdkd/issues/6484))** -- `src/provisioning/providers/servicediscovery/service.ts` and the new `servicediscovery-http-namespace-update` integ. AWS refuses `UpdateService` for a service in an HTTP (API-only) namespace, so a deploy changing such a service's `Description`, `DnsConfig` or `HealthCheckConfig` failed, and failed again on every later deploy. CloudFormation reports that update as applied while changing nothing. cdkd now lets the deploy go on, warns that the change was not applied, and keeps the value AWS holds in the state record, so `cdkd drift` stays clean. Replace the service to change those fields. A `ServiceAttributes` or `Tags` change in the same deploy is still applied.
