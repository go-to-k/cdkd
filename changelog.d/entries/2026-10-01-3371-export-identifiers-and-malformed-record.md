- **`cdkd export` no longer prints a template- or CLI-derived name raw, and refuses a record whose `properties` map it cannot read, in its own words (issues [#3371](https://github.com/go-to-k/cdkd/issues/3371), [#4181](https://github.com/go-to-k/cdkd/issues/4181), [#3315](https://github.com/go-to-k/cdkd/issues/3315))** -- `src/cli/commands/export.ts`, `src/state/malformed-resources-bag.ts`. Regions, the plan summary, cross-stack rows, CLI values (`--stack-region`, `--parameter`, `--cfn-child-stack-name`), template Parameter names and the state bucket rendered raw or kept `'`, `$` and `(`; each now prints quoted when it is a plain identifier inert on a command line and as "(not shown: it is not a plain identifier)" otherwise (`(us-east-1)` becomes `('us-east-1')`). A non-plain logical id or type in a list row (import plan, phase-2 CREATE rows, pre-delete progress, import-failure summary, overlay texts) and a named id in the `properties` refusal are described the same way. A recorded value beside a recovery command (the `AWS::EC2::Route` refusal and warning, the pre-delete row and failure) is described unless inert, so a `$default` Stage id reads "(not shown ...)" there; elsewhere a value holding `$`, `|` or `*` (`$LATEST`) is JSON-quoted. The by-hand phase-2 `create-change-set` and the next-steps `cdk diff` / `cdk deploy` commands go through the shared command gate, so such a value becomes a quoted hole; an `aws` `--stack-name` the AWS CLI itself would act on (`file://`, `@=`) is a hole too. A `properties` map that is not an object is refused by name at the load and over every nested child, under `--dry-run` too. The unreadable-`resources` refusal now says what export does: it deletes the record after migrating, so removing the record is no way out, and a legacy record's text no longer says it was listed.
