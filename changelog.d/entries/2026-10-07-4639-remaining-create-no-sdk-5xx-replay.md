- **Seven more token-less creates no longer let the AWS SDK replay a 5xx inside one call (issue [#4639](https://github.com/go-to-k/cdkd/issues/4639), remaining-sites slice)** -- the `cloudfront-oac`, `ssm-parameter`, `codebuild`, `budgets-budget`, `asg`, `wafv2` and `efs` providers. CloudFront `CreateOriginAccessControl`, SSM `PutParameter` (`Overwrite: false`), CodeBuild `CreateProject`, Budgets `CreateBudget`, Auto Scaling `CreateAutoScalingGroup`, WAFv2 `CreateWebACL` and EFS `CreateMountTarget` carry no idempotency token and were sent through a client whose SDK retry replays a 5xx even when AWS completed the request. The replay collided with what the first request made, the deploy engine credited that "already exists" to another holder, and the create failed leaving a resource in no state record for every re-run to collide with. Each now goes through a dedicated client that refuses the SDK's 5xx retry, built in the same region and with the same identity as the provider's shared client, so the 5xx reaches the deploy engine, which marks the later collision as possibly this create's own. Nothing is adopted on that collision. The Budgets create / update and Auto Scaling group create failure messages, which a surfaced 5xx now reaches more often, quote AWS's text through the secret masker. AgentCore `CreateAgentRuntime` / `CreateEvaluator`, the Cloud Map namespace and service creates, Lambda `CreateMicrovmImage` and Secrets Manager `CreateSecret` are unchanged: each carries an idempotency token the SDK fills once per call, so its replay inside that call repeats the same token. Tests: `tests/unit/provisioning/remaining-create-retry-4639.test.ts`.
