- **An API Gateway stage moved to a replaced API is replaced instead of refused (issue [#7072](https://github.com/go-to-k/cdkd/issues/7072))** -- `src/deployment/type-change-guard.ts`. An `AWS::ApiGateway::Stage` or `AWS::ApiGatewayV2::Stage` has its bare stage name as its physical id, so when the API it belongs to was replaced (for example an HTTP API under a new logical id, its `$default` stage following it), the new stage came back under the old id and the deploy refused it as a name-idempotent create; CloudFormation replaces the stage. Two readable, different `RestApiId` / `ApiId` values now name two stages: the new one is kept and the old one is deleted from the old API. Every registered SDK type is now classified by whether its physical id can name two resources across a replacement (`tests/unit/deployment/equal-id-population.test.ts`), so a new provider type cannot skip the question. Integ: `apigw-stage-api-replacement`.
