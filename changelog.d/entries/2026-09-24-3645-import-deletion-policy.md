- **`cdkd import` now records the template's `DeletionPolicy` / `UpdateReplacePolicy` on each imported record (issue [#3645](https://github.com/go-to-k/cdkd/issues/3645))** -- `src/cli/commands/import.ts` (`buildStackState`), `tests/unit/cli/import-build-state-policies.test.ts`, and the new `tests/integration/import-retain-destroy/` fixture. `cdkd destroy` reads `DeletionPolicy` from state only, and an imported record carried none. So a `cdkd destroy` run after `cdkd import` and before the first `cdkd deploy` **deleted** resources the template declares `DeletionPolicy: Retain`, and deleted `Snapshot` resources without their final snapshot. CDK retains stateful resources by default, so the data-bearing resources were the ones exposed. Measured live on v0.291.14: `import --migrate-from-cloudformation` then `destroy --force` deleted a `Retain` SSM parameter. The first deploy after an import also no longer reports a metadata-only policy update. State imported by an earlier version gets the policies on its next `cdkd deploy`, or by re-running `cdkd import` for those resources. Until then, do not run `cdkd destroy` on it.
