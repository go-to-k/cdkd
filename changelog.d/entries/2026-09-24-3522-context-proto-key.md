- **A context key named `__proto__` is resolved and saved instead of ending in a no-progress refusal** (issue [#3522](https://github.com/go-to-k/cdkd/issues/3522)) -- `src/synthesis/context-providers/index.ts`, `src/synthesis/context-store.ts`, `src/cli/options.ts`. The manifest's `missing` list is `JSON.parse`d, so a row keyed `__proto__` arrives as an ordinary key. `ContextProviderRegistry.resolve` wrote its answers onto a `{}` literal, where that assignment ran `Object.prototype`'s setter and DROPPED the value (success, unknown-provider and failure arms alike); `ContextStore.save` merged into the parsed `cdk.context.json` object the same way, so the key never reached the file either. The app then asked for the same key again and synthesis refused with "Context resolution made no progress", advice that could not help for a lookup that had succeeded. The registry now collects onto `nullPrototypeRecord()` and the store merges with `defineOwnKey`, so the key is stored, written and passed back to the app as an own key. `parseContextOptions` (`src/cli/options.ts`) had the same `{}` literal, so `-c __proto__=x` was silently dropped too; it now builds onto `nullPrototypeRecord()` as well. CDK never emits this key itself, so the manifest path takes a hand-edited or hostile assembly.
