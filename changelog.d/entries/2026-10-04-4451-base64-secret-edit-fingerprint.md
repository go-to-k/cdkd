- **An edit around a secret reference inside one `Fn::Base64` (the EC2 `UserData` shape) is now deployed, and `cdkd diff` reports it (issue [#4451](https://github.com/go-to-k/cdkd/issues/4451))** -- `src/deployment/masked-property-fingerprints.ts`, `src/deployment/deploy-engine/update.ts`, `src/analyzer/diff-calculator.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/deploy-engine/record-shape.ts`, `src/deployment/deploy-engine/deploy-flow.ts`, `src/types/state.ts`. State persists such a property as `***`, and the edited script resolved to `***` too, so the diff and the deploy's no-change skip compared equal: a change to the script around `{{resolve:...}}`, or a retarget of the reference, was skipped under a green deploy and the resource kept the old script. Each record now carries `maskedPropertyFingerprints` (optional, no schema bump): per property it holds as `***`, a sha256 over the UNRESOLVED template value, never over a resolved one. A moved fingerprint is a change; a rotated secret behind an unchanged template is not, matching CloudFormation. A record written by an older cdkd has no fingerprint and is compared as before; the first deploy under this version records one from the template it deploys, so an edit made in that same deploy is still not sent, and every later one is.
