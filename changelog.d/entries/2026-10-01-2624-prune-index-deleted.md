- **`cdkd destroy --purge-events` and `cdkd events prune --all` no longer report removing deployment-event history that never existed (issue [#2624](https://github.com/go-to-k/cdkd/issues/2624))**: `src/state/deployment-events-store.ts`. A purge always reported the `deployments/index.json` key as deleted, because S3's `DeleteObjects` also succeeds for a key that does not exist. As a result, `cdkd destroy --purge-events` printed `Purged deployment-event history for <stack>` for a stack with no recorded events, and `cdkd events prune <stack> --all --stack-region <region>` printed `Removed the empty deployment-event index` when there was no index. A prune now reports the index as removed only when the index was present in the listing the prune already makes, so in both cases above the message no longer appears. The same fix covers a `--keep`/`--older-than` prune that removes every run. The objects deleted are the same as before. Tests: `tests/unit/state/deployment-events-store.test.ts`, `tests/unit/cli/destroy-purge-events.test.ts`, `tests/unit/cli/commands/events.test.ts`.
