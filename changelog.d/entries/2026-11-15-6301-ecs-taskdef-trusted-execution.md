- **`AWS::ECS::TaskDefinition` `TrustedExecutionConfiguration` is now wired on the SDK route (issue [#6301](https://github.com/go-to-k/cdkd/issues/6301))** -- `src/provisioning/providers/ecs/cluster-task-definition.ts`, `src/provisioning/providers/ecs/read-state.ts`, `src/provisioning/providers/ecs-provider.ts`. A task definition declaring the property used to auto-route through Cloud Control, and that route stays with the resource afterwards. Now `RegisterTaskDefinition` sends `IsolationMode` and `AttestationPolicy`, and `cdkd drift` reads the block back. A value that is not an object is refused before any AWS call. The `@aws-sdk/client-ecs` floor is raised to 3.1165.0, the first release that has the member. The schema lists the property as updatable, but a revision cannot change on AWS. So cdkd refuses a change to it with the `--replace` hint, as it does for every other property except `Tags`. CloudFormation's handler, measured through Cloud Control, reports success on that change and leaves the live value as it was. AWS takes the property only on `MANAGED_INSTANCES` task definitions. A resource already recorded as `provisionedBy: cc-api` stays on Cloud Control. Tests: `tests/unit/provisioning/ecs-provider-roundtrip.test.ts`, `tests/unit/provisioning/sdk-wire-cases-12.ts`; integ `ecs-taskdef-tags-launch-type`.
