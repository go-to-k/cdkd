- **`cdkd state`'s `--json` output no longer carries terminal-active characters raw, and `state list --long --json` rows gain `stateReadErrorKind`** (`src/utils/display-safe.ts` `stringifyJsonPayload`, `src/cli/commands/state.ts`, go-to-k/cdkd#3163). `JSON.stringify` escapes only C0, `"`, `\` and lone surrogates, so a stack name, region or record value planted by anyone who can write the state bucket reached `state list --json` / `--long --json` / `--tree --json`, `state resources --json`, `state show --json` (with or without `--show-nested`) and `state info --json` with DEL, the C1 range (`U+009B` is a live CSI), `U+2028` / `U+2029`, the bidi overrides and the zero-width characters verbatim. Every control, format, line-separator and paragraph-separator character is now written as a `\uXXXX` escape: the output is still valid JSON, it parses back to exactly the same values, and a plain payload is byte-identical. `--long --json` rows also carry `stateReadErrorKind` (`read-failed` / `resources-malformed` / `null`), so a consumer can tell a possibly transient read failure from a persistent malformed record without matching the `stateReadError` text. The other commands' `--json` payloads are go-to-k/cdkd#4045. Tests: `tests/unit/utils/display-safe-json-payload.test.ts`, `tests/unit/cli/state-{list,show,resources,info}.test.ts`.
