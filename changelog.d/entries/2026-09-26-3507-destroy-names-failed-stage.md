- **`cdkd destroy` names a CDK Stage that failed to load when stack selection comes back empty (issue [#3507](https://github.com/go-to-k/cdkd/issues/3507))** -- `src/cli/commands/destroy.ts`, with unit tests in `tests/unit/cli/destroy.test.ts`. A stack under a Stage whose manifest could not be read is dropped from the synthesized app, so `cdkd destroy MyStage/MyStack` answered `No matching stacks found in state` for a stack that was still in state. The two empty-selection messages (`No matching stacks found in state`, `No stacks found in state`) and the `Could not determine which stacks belong to this app` refusal now append the same failed-Stage note `deploy`, `diff`, `list`, `publish-assets` and `synth` print, naming the targeted Stage or listing every failed Stage behind `Possibly unrelated:`. Those exit codes are unchanged, and when synthesis itself fails the messages are unchanged. `cdkd destroy --all` over an app that synthesized but yielded no stacks is now refused (exit 1) rather than falling back to every stack in the state bucket, other apps' stacks included. `cdkd scrub` is not covered yet.
