- **Nineteen commands now REFUSE an extra operand they used to ignore** (issue [#3534](https://github.com/go-to-k/cdkd/issues/3534), PR #3545) -- `package.json`, `pnpm-lock.yaml`, `src/cli/region-options.ts`. cdkd moved to `commander@^14` because `cdk-local@0.149.0` requires it, and commander 13 flipped `allowExcessArguments` to false. The split is by ARITY, not by whether a positional is declared: only a VARIADIC one absorbs extras. The six taking NONE -- `synth`, `bootstrap`, `gc`, `state list`, `state info`, `state migrate` -- now answer `error: too many arguments for 'synth'. Expected 0 arguments but got 1.`; the thirteen taking EXACTLY ONE (`rollback`, `events`, `events prune`, `import`, `export`, the two `state` read commands, and six `local` ones) reject a SECOND; the fourteen variadic ones, `deploy` / `destroy` / `diff` / `list` among them, are unaffected. **The one-argument half is the likelier trip**: `cdkd deploy A B` IS valid, so passing several stack names is trained behaviour, and `cdkd state show A B` now fails where it used to silently answer about `A` alone. The extra word was never read in any of these, so the new error is the correct behaviour and the old silence was the bug -- but `cdk synth MyStack` IS valid upstream, and that parity gap, masked by commander 12 rather than created here, is tracked in [#3550](https://github.com/go-to-k/cdkd/issues/3550). Re-derive the sets by walking `buildProgram()` for `registeredArguments` and each argument's `variadic` flag, NOT by descending only to leaves: `events` carries a positional AND a subcommand, so a leaf-only walk reports twelve. Also verified against the 34 option builders: no multi-char short flag (which commander 13 throws on at construction), no `storeOptionsAsProperties`, no `Help` subclass, no `allowUnknownOption` / `passThroughOptions`; `--concurrency -5` parsed the same on both majors.
