- **Six commands now REFUSE a stack name they used to ignore -- `cdkd synth`, `cdkd bootstrap`, `cdkd gc`, `cdkd state list`, `cdkd state info` and `cdkd state migrate`** (issue [#3534](https://github.com/go-to-k/cdkd/issues/3534), PR #3545) -- `package.json`, `pnpm-lock.yaml` only; no `src/**` change. cdkd moved to `commander@^14` because `cdk-local@0.149.0` requires it, and commander 13 flipped `allowExcessArguments` to false. Those six are exactly the commands declaring no positional (measured by walking `buildProgram()`, not by reading the source), so `cdkd synth MyStack` answers `error: too many arguments for 'synth'. Expected 0 arguments but got 1.` and exits 1 where it previously synthesized the WHOLE app and said nothing. **The new behaviour is the correct one and the old one was the bug**: the stack name was never a selector on these commands, so a script passing one has been getting an unfiltered result it did not ask for. It is still a break, and `cdk synth MyStack` IS valid upstream -- the parity gap is real, was masked by commander 12's permissiveness rather than created by the bump, and is tracked in [#3550](https://github.com/go-to-k/cdkd/issues/3550). Every other command declares its positional and is unaffected. Also verified against the 34 option builders: no multi-char short flag (which commander 13 throws on at construction), no `storeOptionsAsProperties`, no `Help` subclass, no `allowUnknownOption` / `passThroughOptions`; `--concurrency -5` parsed the same on both majors.
