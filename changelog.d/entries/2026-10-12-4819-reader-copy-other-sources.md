- **A reader's copy of a secret-named resource's physical id read from another stack, or named from a `NoEcho` parameter, is no longer stored as `{{resolve:...}}` or `***` (issue [#4819](https://github.com/go-to-k/cdkd/issues/4819))** -- `src/deployment/intrinsic-resolver/cross-stack.ts`, `src/deployment/secret-redaction/fresh-noecho.ts`. Since go-to-k/cdkd#4810 a copy read with `Ref` / `Fn::GetAtt` in the same stack stays as the id is. A queue policy whose `Queues` imports another stack's secret-named queue URL with `Fn::ImportValue` / `Fn::GetStackOutput`, and whose document spells the secret reference literally, still had the URL rewritten into `https://sqs.../{{resolve:...}}` by the save, so `cdkd destroy` of that stack failed with `InvalidAddress`. A value a same-account producer stored in plaintext is now recorded as a copy where it is read; a value read across an account boundary is not. A queue named from a `NoEcho` parameter, read by a reader that also reads the parameter, had its URL copy flattened to `***`; the `NoEcho` containment arm now keeps a copy's spans too, and still masks the value anywhere else. A copy read through a nested stack's parameter is not covered yet.
