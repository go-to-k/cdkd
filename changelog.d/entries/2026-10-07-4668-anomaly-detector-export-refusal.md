- **`cdkd export` refuses an `AWS::CloudWatch::AnomalyDetector` before locking the stack (issue [#4668](https://github.com/go-to-k/cdkd/issues/4668))** -- `src/cli/commands/export.ts`. AWS gave the type Cloud Control handlers and the registry identifier `AnomalyDetectorId`, so the import-support pre-flight no longer blocked it. The single-key path would then have sent cdkd's descriptor-derived physicalId as `AnomalyDetectorId`, an opaque identifier the CloudWatch API never returns, and the IMPORT changeset would have failed after the stack was locked. The type is now blocked up front with the other export refusals, including under `--skip-import-support-preflight`. Tests: `tests/unit/cli/export-composite-identifier.test.ts`.
