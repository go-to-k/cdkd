- **Two secret values that overlap inside one property value no longer leave part of a secret in state (issue [#4986](https://github.com/go-to-k/cdkd/issues/4986))** -- `src/deployment/secret-redaction/redact-state.ts`. When two recorded secret plaintexts overlapped in one string (`us-east-1pw12` and `pw12-str4ddle-4973` inside `us-east-1pw12-str4ddle-4973`), the redaction replaced the first and persisted the rest of the second in plaintext. Overlapping matches now take one rule: where their `{{resolve:...}}` references render the overlapping run exactly (one match spanning it, or matches meeting end to start) those references are persisted; otherwise, or where a match cuts a fresh `NoEcho` value or the `Fn::Base64` encoding of a secret, the whole value is persisted as the redaction mask (`***`). A record holding the old partial spelling is repaired by the resource's next deploy, which `cdkd scrub` does not do: where it equals what the old walk stored for today's value, it is rewritten to the mask with nothing sent (`src/deployment/deploy-engine/update.ts`), and a real template change is sent as usual. Earlier versions of `state.json` in the versioned state bucket keep the partial value: `cdkd scrub --purge-history` deletes them, and the exposed secret should be rotated. A rollback to a baseline holding that mask refuses as it does for the other masks, and the refusals (rollback, `Fn::GetAtt` of a masked attribute, `cdkd export`) now name this case and its remedy. The same union-of-overlaps masking now applies to a Cloud Control call's withheld-identifier scrub (`src/provisioning/cloud-control-provider.ts`) and to the masked display of a secret-bearing export name or state key (`src/deployment/outputs-export-alias/secret-scan.ts`), which could print the tail of one of two overlapping values.
