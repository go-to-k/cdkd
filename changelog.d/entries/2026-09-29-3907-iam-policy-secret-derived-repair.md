- **An `AWS::IAM::Policy` whose recorded `Roles` / `Groups` / `Users` is secret-derived is no longer met with "repair it in state.json"** (`src/provisioning/providers/iam-policy-provider.ts`, go-to-k/cdkd#3907). cdkd keeps a secret dynamic reference (or its `***` mask) in state by design, so the `update()` refusal and the `delete()` skip told the user to write a secret-derived principal name into state.json. Both now name a secret-derived kind apart from a plainly malformed one: the update refusal says IAM has no call listing the principals holding an inline policy, so the attachment change is made by hand (plus removing the old-named policy when the change renames it) and the record dropped with `cdkd orphan <constructPath>` for the next deploy to re-attach it; the delete skip says cdkd will keep skipping the record, to remove the policy by hand, and when `cdkd state orphan` clears it. A plainly malformed kind keeps the state.json repair, except beside a secret-derived one, where that repair alone would still be refused. The desired-side refusal now also says where that side comes from: the template on a deploy, the recorded value being restored on a rollback revert or `cdkd drift --revert`, and a desired side holding an unresolved reference or mask is sent back to the template. Tests: `tests/unit/provisioning/iam-policy-provider-target-shape.test.ts`, `provider-delete-skip-outcome.test.ts`, `iam-policy-targets.test.ts`.
