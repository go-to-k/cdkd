- **A `--recreate-via-cc-api` / `--recreate-via-sdk-provider` target's same-stack readers now follow the id the recreate mints (issue [#4383](https://github.com/go-to-k/cdkd/issues/4383))** -- `src/analyzer/diff-calculator.ts`, `src/deployment/recreate-target-promotion.ts`, `src/deployment/recreate-target-readers.ts`, `src/deployment/deploy-engine/deploy-flow.ts`, `src/cli/commands/deploy.ts`, `src/cli/commands/recreate-confirm-prompt.ts`. For a type whose physical id AWS assigns (an `AWS::EC2::SecurityGroup`, an `AWS::ApiGateway::RestApi`), a `Ref` / `Fn::GetAtt` reader the template did not touch kept the deleted resource's id in AWS and in state after a green deploy, also when the target had an in-place change. The diff now promotes the stack's own targets' readers as for a property-driven replacement (never a nested child's or another stack's), and the counts and `--dry-run` include them. A reader holding the target in a create-only property is replaced; the confirmation prompt lists those as "Replaced if the id changes" (**DATA LOSS** for a stateful one) instead of saying sibling resources are unaffected, and a stateful one without `--force-stateful-recreation` is now refused before anything is touched rather than after the target was recreated. Tests: `tests/unit/analyzer/diff-calculator-recreate-target-dependents.test.ts`, `tests/unit/deployment/deploy-engine-recreate-target-dependents.test.ts`, `tests/unit/deployment/recreate-target-readers.test.ts`, `tests/unit/cli/deploy-recreate-replaced-readers-preflight.test.ts`.
