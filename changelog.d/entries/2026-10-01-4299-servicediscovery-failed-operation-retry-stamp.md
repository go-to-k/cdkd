- **A masked FAILED Service Discovery (Cloud Map) operation keeps the retry classification its unmasked message gets (issue [#4299](https://github.com/go-to-k/cdkd/issues/4299))** -- `src/provisioning/providers/servicediscovery-provider.ts`. Cloud Map reports a create/update rejection as a FAILED operation, and `pollOperation` masks its `ErrorMessage` before raising `Operation failed for <id>: ...` (#2063). That error carried no `cause`, so when a recorded secret spelled part of a retryable phrase (for example `does not exist`), the mask cut the phrase out and `withRetry` read the failure as terminal, where the same failure without the secret is retried. The raw `ErrorMessage` now rides as the unmasked `cause` and the error goes through `wrapMaskedAwsError`, so a message the mask changed is stamped and the retry classifiers read that chain. The message is still masked, and a message the mask left unchanged is not stamped. Tests: `tests/unit/provisioning/servicediscovery-provider-masked-retry.test.ts`.
