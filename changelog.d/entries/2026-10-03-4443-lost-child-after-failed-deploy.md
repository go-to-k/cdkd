- **A deploy that fails after re-creating a resource under the same physical id no longer leaves the sub-resources stored inside it lost for good (issue [#4443](https://github.com/go-to-k/cdkd/issues/4443))** -- `src/deployment/child-of-recreated-parent.ts`, `src/deployment/deploy-engine/execute.ts`, `src/deployment/deploy-engine/update.ts`, `src/deployment/deploy-engine.ts`. Since #4411 the deploy re-creates a child that went with such a parent (a bucket's `BucketPolicy`, a function's `Permission`). When the deploy failed or was interrupted before reaching it, the child's record survived (the rollback keeps an equal-id parent as done) and every later deploy diffed it unchanged, so the child stayed missing in AWS while state recorded it: a bucket policy's deny of plain HTTP, or an IAM policy's Deny, silently absent. The failure path now drops the record of each such child the deploy did not restore, when its recorded value still names the re-created parent, with a warning naming it; the next deploy creates it again. Tests: `tests/unit/deployment/child-of-recreated-parent.test.ts`, `tests/unit/deployment/deploy-engine-lost-child-after-failed-deploy.test.ts`.
