- **FSx FileSystem: a property removed from the template is now named in a warning instead of being silently dropped, and no longer issues an empty `UpdateFileSystem` (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/fsx-filesystem-provider.ts`. `UpdateFileSystem` keeps a field it is not sent, and cdkd sends no reset for these removals. Before, removing `StorageCapacity`, `StorageType`, `FileSystemTypeVersion`, `NetworkType` or a mutable `<Variant>Configuration` sub-property (Lustre `DataCompressionType` / `AutoImportPolicy`, a Windows `FsrmConfiguration`, ...) reported a successful update while AWS kept the old value, and when the removal was the only change cdkd sent an `UpdateFileSystem` carrying no update field. Now the provider names every such removal, top-level and sub-property, in one warning per resource after a successful update, sends none of them, and makes no claim about what CloudFormation would do (the type declares `removalHandledInUpdate`, so the shared caller adds no second line). A removed `RouteTableIds` is still applied as a `RemoveRouteTableIds` delta, and a removed `Tags` still untags. Tests: `tests/unit/provisioning/providers/fsx-filesystem-provider.test.ts`.
