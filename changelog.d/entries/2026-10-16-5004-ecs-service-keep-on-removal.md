- **Removing `PlatformVersion`, `HealthCheckGracePeriodSeconds`, `PropagateTags`, `EnableECSManagedTags`, `EnableExecuteCommand`, `CapacityProviderStrategy`, `PlacementConstraints` or `PlacementStrategies` from an `AWS::ECS::Service` template no longer resets them (issue [#5004](https://github.com/go-to-k/cdkd/issues/5004))** -- `src/provisioning/providers/ecs-provider.ts` (`removalDefaults` is now empty; `updateService` sends nothing for these members), `tests/unit/provisioning/ecs-provider.test.ts`, and the `ecs-service-update-props` integ fixture (now asserts the live value is retained). A real CloudFormation A/B showed CloudFormation KEEPS the live value of all eight on removal, while cdkd (issue #1160) reset them to a default, so a removal changed a running service where CloudFormation would not. `ServiceConnectConfiguration` removal still resets to disabled, which the same A/B confirmed CloudFormation does; `VolumeConfigurations` and `VpcLatticeConfigurations` were not measured and are unchanged.
