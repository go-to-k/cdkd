- **`cdkd import` no longer records a decrypted secret as a drift baseline when a template parameter was DEPLOYED with a secret reference over a placeholder `Default` (issue [#2854](https://github.com/go-to-k/cdkd/issues/2854))** -- `import.ts`, new `import-deployed-parameters.ts`, `docs/import.md`, new `import-deployed-parameter-secret` integ. `cdkd import` takes no parameter values, so a parameter is recorded at its `Default`; a stack deployed with `--parameters DbPassword='{{resolve:secretsmanager:...}}'` over `Default: CHANGEME` (the ordinary `--migrate-from-cloudformation` shape, and what a nested stack receives from its parent) left no reference in any template the import read, so the AWS readback -- the decrypted value -- was written to `observedProperties` in `state.json` with no warning. When a CloudFormation stack backs the import (the migration source, each nested child, or on any other import a stack with the cdkd stack's name) cdkd now reads its deployed parameter values with `DescribeStacks` and compares them with what it bound. Every resource whose properties depend on a parameter it cannot PROVE equal -- a different value, a literal reference, any `NoEcho` parameter, one missing from the response, a failed call -- through `Ref`, `Fn::Sub`, any nested intrinsic, a (transitive) condition or the resource's own `Condition`, plus every resource reading an attribute (`Fn::GetAtt`) of such a resource, gets no baseline and the `observedBaselineRefused` marker, and one warning per stack names the parameters. The deployed values are compared only: never bound, logged or persisted. New IAM requirement: `cloudformation:DescribeStacks` (only when something in the template references a declared parameter); without it the import succeeds, warns with the error name, and refuses every parameter-dependent baseline. Not closed here: an import with no CloudFormation stack of that name (#2868), and the NEXT deploy of such a resource, which clears the marker (#3462).
