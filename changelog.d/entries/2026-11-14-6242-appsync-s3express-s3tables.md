- **`Fn::GetAtt` of an AppSync API key's `ApiKeyId`, a GraphQL API's `GraphQLDns` / `RealtimeDns`, an S3 Express directory bucket's `AvailabilityZoneName` and an S3 Tables table's `WarehouseLocation` / `VersionToken` now returns the value CloudFormation returns (issue [#6242](https://github.com/go-to-k/cdkd/issues/6242), third slice)** -- `src/deployment/intrinsic-resolver/getatt-construct-app.ts`, the AppSync GraphQL API and S3 Tables table create / import paths, unit tests and a new `getatt-appsync-s3express-s3tables` integ fixture. Before, each resolved to the resource's physical id with only an `Unknown attribute` warning: `<apiId>|<keyId>` for the key id, the API id for its host names, the bucket name for its Availability Zone, and the table's composite id. Now the key id is read out of that composite; the host names are recorded from AppSync's response (they are under an endpoint id of AppSync's own, not the API id), with `GraphQLDns` read from the recorded `GraphQLUrl` for an API deployed earlier; the Availability Zone name is looked up from the zone ID in the bucket name; and the table's warehouse location and version token are read with `GetTable` when the table is created or imported. A value cdkd cannot read fails the deploy instead of becoming the physical id.
