- **Every `cdkd` command cdkd tells you to paste is now built and printed the same way, and a source fence keeps it that way (issues [#3436](https://github.com/go-to-k/cdkd/issues/3436), [#3307](https://github.com/go-to-k/cdkd/issues/3307))** -- new `scripts/check-pasteable-command-shapes.ts` + its test, `src/cli/commands/{deploy,destroy,drift,export,state}.ts`, `src/deployment/deploy-engine.ts`, `src/provisioning/providers/s3-tables-provider.ts`, `src/state/malformed-resources-bag.ts`. [#3499](https://github.com/go-to-k/cdkd/pull/3499) gave the repo one command BUILDER; nothing stopped the next site being written by hand, and a grep for the builder's NAME cannot find a site that spells its gate differently (measured: `gc.ts` is returned by neither of that issue's two greps while carrying a real pasteable command). The fence keys on the SHAPE instead: a `cdkd` verb and an interpolation inside a prose `'...'` span, a span assembled from two or more holes, or a bare `<placeholder>` with words after it. It found sixteen sites and all are fixed, so the tree reports ZERO and the test asserts that -- a new one fails by name. What changes for users: a bare `<stack>` followed by a flag is two shell REDIRECTIONS, so pasting `cdkd events prune <stack> --all` in a directory holding a file named `stack` exited 0, did nothing asked, and created a file called `--all`; those placeholders are quoted now. `cdkd drift`'s three remaining prose remedies and its untracked-properties plan note give the stack AND the region on a labelled line, gated by one predicate shared with the rest -- closing #3307's last three sites and its `--stack-region` requirement. `state.ts`'s three `Usage:` lines and `cdkd destroy --help` now spell arguments the way Commander does.
