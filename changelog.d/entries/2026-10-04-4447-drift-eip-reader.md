- **`cdkd drift` reads an Elastic IP back, so one released outside cdkd reports `deleted` and exits 1 (issue [#4447](https://github.com/go-to-k/cdkd/issues/4447))** -- `src/provisioning/providers/ec2-provider.ts`, `src/analyzer/drift-cc-api-deny-list.ts`, `docs/cli-drift.md`. `AWS::EC2::EIP` had no arm in `EC2Provider.readCurrentState`, so it read as `drift unknown` (exit 0) whether it existed or not. It is now read with `DescribeAddresses`: `InvalidAllocationID.NotFound` / `InvalidAddress.NotFound` report the address deleted, and `Domain`, `InstanceId`, `NetworkBorderGroup`, `PublicIpv4Pool` and `Tags` are read back, so a change to a value the baseline holds (a declared `InstanceId` or `Tags`) reports as drift. A deploy now also captures an EIP's drift baseline, leaving out an `InstanceId` the template does not declare. A nested `AWS::CloudFormation::Stack` row still reads as `drift unknown`: no CloudFormation stack exists to read, and its resources are compared as the `<parent>~<child>` stack; `cdkd drift <parent>` not including that stack is [#4533](https://github.com/go-to-k/cdkd/issues/4533).
