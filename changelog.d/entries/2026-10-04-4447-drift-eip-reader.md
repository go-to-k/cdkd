- **`cdkd drift` reads an Elastic IP back, so one released outside cdkd reports `deleted` and exits 1 (issue [#4447](https://github.com/go-to-k/cdkd/issues/4447))** -- `src/provisioning/providers/ec2-provider.ts`, `src/analyzer/drift-cc-api-deny-list.ts`, `docs/_contents/cli-drift.md`. `AWS::EC2::EIP` had no arm in `EC2Provider.readCurrentState`, so it read as `drift unknown` (exit 0) whether it existed or not. It is now read with `DescribeAddresses`: `InvalidAllocationID.NotFound` / `InvalidAddress.NotFound` report the address deleted, and `Domain`, a declared `InstanceId`, `NetworkBorderGroup`, `PublicIpv4Pool` and `Tags` are read back, so a change to one the baseline holds reports as drift. A deploy now also captures an EIP's drift baseline. A nested `AWS::CloudFormation::Stack` row still reads as `drift unknown`: no CloudFormation stack exists to read, and its resources are compared as the `<parent>~<child>` stack; `cdkd drift <parent>` not including that stack is [#4533](https://github.com/go-to-k/cdkd/issues/4533). A standalone `AWS::EC2::SecurityGroupIngress` whose `Description` was edited out of band, or a same-account SG-to-SG rule (the template omits the peer owner AWS reports), read as `drift unknown` because the reader matched the whole rule; it now falls back to the rule's identity when the record's own rule id still names that rule and no other record declares it, so the edit reports as drift and `drift --revert` can restore it.
