- **`cdkd scrub`'s "No plaintext secrets found" lines now say what they cover, and a secret set out of band is documented as recorded by design (issue [#2868](https://github.com/go-to-k/cdkd/issues/2868))** -- `src/cli/commands/scrub.ts`, `docs/{import,state-management,cli-scrub,cli-drift,getting-started}.md`, `SECURITY.md`. The drift baseline (`observedProperties`) records what AWS returns. That includes a value the template never references, such as a password an operator set in the console over a placeholder literal, or any key of a Cloud Control model. Secret redaction works only where the template spells a `{{resolve:...}}` reference, so such a value is stored as AWS returned it. That is by design, and for a property the template sets, CloudFormation's drift detection likewise reports the actual value. Scrub learns a secret's value only by resolving a reference, so it cannot see such a value. Its per-stack and summary no-finding lines used to read as a clean bill for the whole record. They now end with `(scrub checks only values the template names through a {{resolve:...}} reference)`, and the `--fail` help text says the same. `docs/import.md` documents the population, why `state.json` is sensitive by construction, and how to remove such a value: rotate it through a reference and deploy, or edit the record by hand, then run `cdkd scrub <stack> --purge-history`. Tests: `tests/unit/cli/commands/scrub-all-refusal-boundary.test.ts`, `tests/unit/cli/commands/scrub-nested-child.test.ts`.
