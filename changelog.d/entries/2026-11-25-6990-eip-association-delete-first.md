- **`cdkd deploy`: an Elastic IP association is replaced delete-first, so replacing the instance it is attached to succeeds (issue [#6990](https://github.com/go-to-k/cdkd/issues/6990))** -- `src/deployment/delete-first-replacement-types.ts`. When an `ec2.Instance` holding an Elastic IP through an `AWS::EC2::EIPAssociation` was replaced (a new AMI from `MachineImage.latestAmazonLinux2023()`, or changed user data with `userDataCausesReplacement`), the association was replaced too, and cdkd created the new association first. AWS allows one association per Elastic IP, so the deploy failed (`resource eipalloc-... is already associated`) and rolled back. cdkd now deletes the old association before creating the new one, as CloudFormation does; a failed re-create is rolled back by re-creating the old association. `cdkd diff` and the approval prompt say the old one is deleted first. Tests: `tests/unit/deployment/deploy-engine-delete-first-association-6958.test.ts`; integ `ec2-association-replace` phase 4b.
