- **`Fn::GetAtt` of a managed policy's `AttachmentCount` / `PermissionsBoundaryUsageCount` / `IsAttachable` / `CreateDate` / `UpdateDate`, a WAFv2 web ACL's `Capacity`, an S3 Vectors bucket's `CreationTime` and a Bedrock AgentCore evaluator's `EvaluatorType` / `Provider` now returns the value AWS reports, where it failed the deploy before (issue [#6242](https://github.com/go-to-k/cdkd/issues/6242))**. Changed: `src/provisioning/providers/iam-managed-policy/*`, `src/provisioning/providers/wafv2/*`, `src/provisioning/providers/s3-vectors-provider.ts`, `src/provisioning/providers/agentcore-evaluator-provider.ts`, `src/provisioning/attribute-timestamp.ts`, `src/deployment/intrinsic-resolver/getatt-construct-core.ts`, unit tests, and a new `getatt-iam-waf-s3vectors-evaluator` integ fixture.
  - Each value is recorded from AWS's answer when cdkd creates, updates or imports the resource. A resource deployed earlier has it read back on the next deploy that references it.
  - A managed policy's `AttachmentCount` is the count after this deploy's attachments: a policy attached to a role reports 1. Its dates are IAM's ISO text (`2026-11-14T07:49:22Z`); CloudFormation answers `Optional[2026-11-14T07:49:22Z]` for both, which cdkd does not copy.
  - The counts and booleans are numbers and booleans, as CloudFormation passes them.
  - A managed policy whose attachments or document change, a web ACL whose rules change, and every create of a vector bucket or an evaluator make one extra read call. An update that leaves those alone makes none.
  - A Bedrock AgentCore evaluator update no longer drops the recorded `CreatedAt`.
