- **`cdkd diff` reports an SNS subscription update that the deploy carries out by re-creating the subscription (issue [#6509](https://github.com/go-to-k/cdkd/issues/6509))** -- `src/analyzer/diff-calculator/provider-replacement.ts`, `src/provisioning/providers/sns-subscription/attribute-plan.ts`, `src/analyzer/destructive-changes.ts`, `src/cli/commands/diff-recursive/{render,json}.ts`. The provider re-creates an `AWS::SNS::Subscription` (delete, then subscribe again) when a new `FilterPolicy` and a `FilterPolicyScope` change arrive in one deploy, which is what switching CDK's `filterPolicyWithMessageBody` and `filterPolicy` produces, and when `DeliveryPolicy`, `ReplayPolicy` or `SubscriptionRoleArn` is removed. The diff showed these as plain updates, so a user reading it was not told that the subscription would get a new ARN, miss the messages published in between, and need an email or HTTP(S) endpoint to confirm again. The diff now prints `[requires replacement: <reason>; deleted, then created again]` under the resource, `--json` carries `providerReplacement`, and `cdkd diff --fail-on destructive` and `cdkd deploy --require-approval destructive` count it as a replacement. The deploy itself is unchanged: the provider plans with the same code against the live subscription.
