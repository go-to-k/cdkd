- **`cdkd import`'s remaining lines and the provider import refusals no longer print a template value beside a command to paste (issue [#4226](https://github.com/go-to-k/cdkd/issues/4226))** -- `src/cli/commands/{import,retire-cfn-stack}.ts`, `src/provisioning/import-helpers.ts` and the `route53`, `s3-bucket-policy`, `sns-topic-policy` and `sqs-queue-policy` providers. These lines showed a logical id raw or inside cdkd's own `'...'`, and some also a resource type, a supplied physical id, a template `Bucket` / `Topics` / `Queues` / `HostedZoneName` value (JSON-quoted, where a shell still expands `$( )`), a recorded hosted zone id, the cloud assembly's stack name or region, or the template ids listed after a mistyped `--resource`, on the same line as a `cdkd` command or a `--resource` fragment. A `'`, `;` or `$( )` in the value ran when the line was pasted. Each such value is now shown only when plain and described otherwise (for example `a logical id that is not a plain identifier`, `(not shown: it is not a plain identifier)`), a `--resource` fragment names the logical id only when plain and uses the `'<logicalId>'` hole otherwise, and every `<...>` placeholder in these fragments is quoted. The unresolved-intrinsics warning prints the resolver's message on its own line, and the CloudFormation lookup warning and the Route 53 NameServers warning print AWS's message on its own line, so the remedies start the next line. A plain value prints as before, except that these three warnings now span two lines and the policy refusals and the unresolved-intrinsics warning no longer put hand quotes around a plain logical id.
