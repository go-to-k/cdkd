- **`cdkd local` no longer emulates an execution role that has a permissions boundary (issue [#6220](https://github.com/go-to-k/cdkd/issues/6220))** -- `src/local/role-permission-emulation.ts`, unit tests and docs. Before, the refused-role emulation added in [#6201](https://github.com/go-to-k/cdkd/issues/6201) passed only the role's policies as session policies, so a role whose boundary denies something its policies allow was emulated with more permissions than the deployed workload has. A boundary cannot be added as one more session policy (STS combines session policies as a union). Now cdkd reads the role with `iam:GetRole` and, when it has a permissions boundary, warns naming the boundary and keeps the command's previous behaviour for a refused AssumeRole: `local invoke` and `local invoke-agentcore` run with your own credentials, and `local start-api` and `local run-task` stop with the AssumeRole error. Also, an inline policy document of the role that is not valid JSON now fails the emulation with fixed text, so no part of the document reaches the `--verbose` debug line.
