- **A masked ELBv2 or CloudWatch Logs log group create/update failure is still retried when a secret overlaps AWS's retry wording (issue [#4259](https://github.com/go-to-k/cdkd/issues/4259))** -- `src/provisioning/providers/{elbv2,logs-loggroup}-provider.ts`. These providers mask AWS's error text before joining it into their `Failed to create/update ...` message (#2050, #2063). When a recorded secret spelled part of a retryable phrase (for example `does not exist`), the mask cut that phrase out and `withRetry` read the failure as terminal, so the deploy failed where it used to retry. The six ELBv2 wraps (LoadBalancer create, the `update()` outer wrap, TargetGroup and Listener create/update) and the two log group wraps now go through `wrapMaskedAwsError` (the #4244 helper), which stamps `markRedactedCause` when the mask changed the text, so the retry classifiers read the unmasked cause chain. The message is still masked, and a wrap the mask left unchanged is not stamped. Tests: `tests/unit/provisioning/elbv2-provider-masked-retry.test.ts` and `tests/unit/provisioning/logs-loggroup-provider-masked-retry.test.ts`.
