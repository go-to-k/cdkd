- **Respelling a principal name only in case no longer drops its membership or policy attachment (issue [#6774](https://github.com/go-to-k/cdkd/issues/6774), part of [#6655](https://github.com/go-to-k/cdkd/issues/6655))**. IAM role, user and group names ignore case, but an `AWS::IAM::UserToGroupAddition`'s `Users`, an `AWS::IAM::User`'s `Groups`, an `AWS::IAM::ManagedPolicy`'s `Roles` / `Users` / `Groups` and an `AWS::IAM::InstanceProfile`'s `Roles` were diffed case-sensitively: changing `my-user` to `My-User` added the new spelling (a no-op for IAM) and removed the old one, so the user left the group (or the policy was detached) after a successful deploy. These lists now compare ignoring case: a case-only respelling sends no add, remove, attach or detach, and is recorded in the template's spelling; a `UserToGroupAddition` whose `GroupName` changes only in case no longer removes and re-adds every user. A managed policy whose recorded lists are secret-derived matches the attachments IAM lists ignoring case too, and a read right after a write no longer waits for a declared role or attachment IAM lists in another case.
