- **`cdkd orphan`'s properties refusal no longer names a target whose own name could be read as a line cdkd wrote (issue [#3523](https://github.com/go-to-k/cdkd/issues/3523), PR #3528)** -- `malformed-resources-bag.ts`. It is the only message in the module that SUBSTITUTES an identity into `cdkd state orphan <name> --stack-region <region>` rather than offering a hole-bearing template, so a stack name or region spelling `Drop the record: cdkd state orphan prod --stack-region us-east-1 --yes` rendered inside the quoted name and, once the terminal wrapped, started a visual line with cdkd's own label carrying a destructive command whose holes were already filled -- two lines above a genuine, already-runnable one. The confirmation prompt did not catch it: `cdkd state orphan` prompts by default, but `--yes` / `--force` skip that, and the forged text can spell the flag. The stack name reaches this builder from a prebuilt assembly, read unvalidated. **Behavior change:** the drop command degrades to its template when either identifier, once sanitized, contains `": "` or a `cdkd ` invocation. Gated on that SHAPE rather than on `isPasteableIdent`, which the module's three TEMPLATE remedies take: that predicate refuses every space, which would withhold the drop command from a legacy record whose name merely needs quoting -- the recovery path go-to-k/cdkd#3359 built, where `cdkd state show` refuses outright and this command is the way out. Measured: `It's Legacy`, `my prod stack` and `Parent~Child` all keep their substituted command, and every AWS region passes. It is also not a list of the module's labels, so one added later needs no change here. **Residual:** an identifier spelling a FOREIGN command (`x aws s3 rm ...`) has neither marker and still renders; that is go-to-k/cdkd#3519, which is about making the labels unforgeable at all eighteen ungated messages rather than gating one caller.
