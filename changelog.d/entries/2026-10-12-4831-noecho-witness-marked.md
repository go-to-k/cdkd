- **Declaring an existing template parameter `NoEcho` no longer replaces a create-only resource that reads it, and the value is then stored masked (issue [#4831](https://github.com/go-to-k/cdkd/issues/4831))** -- `src/deployment/secret-redaction/noecho-leaves.ts`, `src/deployment/deploy-engine/{update,noecho}.ts`, `src/deployment/deploy-engine.ts`. A record written while a parameter was ordinary stores its value in plaintext. Once the template declares the parameter `NoEcho`, the deploy compares what it would store (`***`) with that plaintext. The migration witness reconciles the two only when the record carries no `noEchoLeaves` at all. A record another `NoEcho` source had already marked read the leaf as moved: `cdkd diff` and `cdkd deploy` reported a create-only change and replaced the resource (a fixed-name topic, bucket or table), and `cdkd diff` printed the stored plaintext as the old value. The witness now covers every record. A leaf whose stored plaintext equals today's value reads as unchanged. The save stores `***` there and adds the leaf to `noEchoLeaves`. A different value is still a change, shown as `(previous NoEcho value)`. When the same deploy updates another property in place, the provider is now handed that leaf's value as the previous one rather than `***`, so it no longer reads a create-only change there (an ACM certificate was re-created inside its update). Tests: `tests/unit/deployment/noecho-witness-marked-4831.test.ts`, `tests/unit/cli/diff-noecho-witness-marked-4831.test.ts`. Integ: `noecho-parameter-masking` Phase 4w declares the parameter behind a fixed-name SNS topic `NoEcho` with its value unchanged, and fails if the topic is replaced or the name prints.
