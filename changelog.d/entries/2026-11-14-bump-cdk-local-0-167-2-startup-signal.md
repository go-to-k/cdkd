- **A Ctrl-C or SIGTERM during the start-up of `cdkd local start-service` / `start-alb` / `start-cloudfront` (and `start-api --warm`) no longer leaves the containers it already started behind** -- `package.json` (`cdk-local` `^0.167.1` -> `^0.167.2`, with go-to-k/cdk-local#975, #974, #968 and #971). The shutdown handler is now armed before the containers boot, so a signal while the images are pulled or the containers start removes the ones that had started; before, they kept running until removed by hand. The same bump makes an ECS `Command` / `EntryPoint` element that embeds a masked cross-stack value mid-element, or that names a cross-stack value's attributes, refused instead of run (go-to-k/cdk-local#968), and the `cdkd local invoke` container is now named `cdkl-invoke-<pid>-<rand>` with its shutdown armed before synth (go-to-k/cdk-local#974). No cdkd source change.
