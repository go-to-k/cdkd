- **A re-deploy no longer fails with `Method already exists for this resource` after an API Gateway `Method` was left behind (issue [#5294](https://github.com/go-to-k/cdkd/issues/5294))** -- `src/provisioning/providers/apigateway-provider.ts`. When a `Method`'s wiring (`PutIntegration`, `PutMethodResponse`, `PutIntegrationResponse`) failed after `PutMethod` and the cleanup `DeleteMethod` failed too, the method stayed in API Gateway with no state record, and every later deploy of the stack failed on `PutMethod` until it was deleted by hand. Now, when `PutMethod` answers `ConflictException` "already exists", the provider checks the stack's rollback journal: if a failed earlier attempt of the same logical id put the same `(RestApiId, ResourceId, HttpMethod)`, the method is that attempt's leftover, so it is deleted and put again with the template's wiring (a warning names it). Without that evidence, an unreadable journal, or a concurrent-modification `ConflictException`, AWS's refusal is kept, so a method another owner created is never touched. Unit cases in `tests/unit/provisioning/apigateway-method-left-behind-5294.test.ts`.
