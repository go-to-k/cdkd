- **A nested stack whose child failed to destroy keeps its state row whatever its logical id spells, and terminal intrinsic-resolution failures are declared non-retryable (issue [#1889](https://github.com/go-to-k/cdkd/issues/1889))** -- `src/provisioning/providers/nested-stack-provider.ts`, `src/deployment/intrinsic-function-resolver.ts`, `src/deployment/intrinsic-resolver/{getatt,params-conditions,functions,cross-stack,dynamic-ref-lookups,stack-output,stack-state,string-functions}.ts`. The resolver's plain-`Error` refusals that no retry can change (an unsupported intrinsic, a malformed `Fn::GetAtt` / `Fn::Join` / `Fn::Select` / `Fn::Base64` / `Fn::Cidr` / `Fn::And` / `Fn::Or` / `Fn::Not` argument, a missing `Fn::FindInMap` mapping or key, an invalid `Fn::GetAZs` region or an empty zone list, every `Fn::GetStackOutput` argument check and a missing output of a producer it read, a dynamic reference whose secret or parameter has no usable value, a required parameter with no value) are now marked non-retryable. Several quote a template value, so a name containing a retryable pattern such as `DependencyViolation` read as transient to cdkd's retry classifiers; no retry loop wraps resolution today, so this is a declaration rather than a change a deploy shows. A relayed AWS failure stays retryable, and so do the cross-stack "export / stack not found" errors, which can follow a swallowed transient lookup failure. `AWS::CloudFormation::Stack`'s child-failure error is now marked on both arms, not only when interrupted: previously a child logical id containing `NotFoundException` made `cdkd destroy` and a deploy that removes the nested stack read the failure as "already deleted" and drop the parent's row while the child's state survived. Tests: `tests/unit/deployment/intrinsic-terminal-bare-throws-non-retryable.test.ts`, `tests/unit/provisioning/nested-stack-provider.test.ts`, `tests/unit/provisioning/nested-stack-provider-cycle.test.ts`.
