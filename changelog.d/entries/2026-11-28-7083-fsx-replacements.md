- **FSx file system changes that CloudFormation replaces on are now planned as replacements, behind `--force-stateful-recreation` (issue [#7083](https://github.com/go-to-k/cdkd/issues/7083))** -- `src/analyzer/replacement-rules/evidence.ts`, `src/analyzer/replacement-rules/spec-replacement-properties.generated.ts`. These are Lustre `CopyTagsToBackups`, `DeploymentType`, `DriveCacheType`, `ExportPath`, `ImportPath` and `ImportedFileChunkSize`; OpenZFS `DeploymentType`, `EndpointIpAddressRange`, `PreferredSubnetId` and every `RootVolumeConfiguration` member; ONTAP `DeploymentType`, `EndpointIpAddressRange` and `PreferredSubnetId`. Before this, cdkd's diff planned each as an in-place update, which the FSx provider then refused ("... is immutable on AWS — UpdateFileSystem cannot change it after creation"). CloudFormation was measured replacing the file system on each change. File systems are stateful, so the deploy now refuses the replacement before any call unless `--force-stateful-recreation` is passed, and `cdkd diff` shows it. The refusal names the measured member (`src/deployment/deploy-engine/update-replace/preflight.ts` now matches a nested measured row too). Lustre `PerUnitStorageThroughput` stays in place, as measured.
