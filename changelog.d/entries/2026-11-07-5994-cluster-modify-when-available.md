- **An RDS, DocumentDB or Neptune DBCluster update now waits out a cluster AWS refuses to modify while it is busy (issue [#5994](https://github.com/go-to-k/cdkd/issues/5994))** -- `src/provisioning/providers/{rds,docdb,neptune}/cluster-update.ts`, `src/provisioning/providers/db-instance-modify-retry.ts`. Each update sent its `ModifyDBCluster` once, so an update made while the cluster was `backing-up` (an Aurora cluster's first automated backup after create) failed with `InvalidDBClusterStateFault: DB cluster isn't available for modification with status backing-up.` and rolled back. CloudFormation waits until the cluster can be modified. cdkd now waits for the cluster to read `available` and resends the same request, within 30 minutes or what the resource timeout leaves. A terminal status, and any other refusal, still fails at once. The RDS update also waits out `This cluster could not be modified. Please try again`, as its destroy-time protection flip already does.
