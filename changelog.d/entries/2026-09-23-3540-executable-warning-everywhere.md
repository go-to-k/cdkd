- **`cdkd local start-service` and `cdkd local start-alb` now announce a Docker asset's `source.executable` before running it, instead of executing an assembly-chosen command line silently** (issue [#3540](https://github.com/go-to-k/cdkd/issues/3540), PR #3553) -- `package.json`, `pnpm-lock.yaml`, `docs/{cli-deploy-safety,local-emulation}.md`. Those two build their ECS container assets through the bundled `cdk-local` engine, several layers past any cdkd-side boundary, so go-to-k/cdkd#3539's warning could not reach them and `docs/cli-deploy-safety.md` named the gap explicitly. Fixed upstream in cdk-local 0.149.1 (go-to-k/cdk-local#747) at `buildDockerImage`, which is the ONE spawn point every path shares -- so `start-agentcore` and `studio`, which this issue did not name, are covered too, and `cdkl` users get the line rather than only cdkd's. **Behavior change:** one warning at default verbosity, never a refusal, naming `executable[0]` and the argument COUNT; the full argv stays at `--verbose`, because a build script is not `docker build` and its own `--token` / `--password` matches no argv masker's flag shapes -- rendering them at warn level would be a NEW leak introduced by a warning about leaks. Announced once per distinct command per run rather than once per build: a `DesiredCount: 3` service rebuilds per replica and again per crash-loop restart, and repeating a ~450-character paragraph that often buries it. The key is the command AND its working directory, since `./build.sh` under two asset directories is two different scripts. Deduping the line does not dedupe the work -- every spawn still happens.
