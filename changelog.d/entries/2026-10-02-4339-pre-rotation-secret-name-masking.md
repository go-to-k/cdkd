- **A refusal or update log no longer prints a resource name taken from a secret that has since been rotated (issue [#4339](https://github.com/go-to-k/cdkd/issues/4339))** -- `src/provisioning/providers/{asg,elbv2,iam-managed-policy,logs-loggroup,s3-vectors,rds-dbproxy,rds-dbproxy-endpoint,kinesis-streamconsumer}-provider.ts`, `src/provisioning/replacement-protection-advice.ts`. After a secret rotation under an unchanged `{{resolve:...}}` reference, the recorded physical id names the PRE-rotation value, which this deploy's masker never resolved. The AutoScalingGroup and ELBv2 LoadBalancer deletion-protection remedies pasted it as the command's identifier, the LogGroup class-change refusal pasted the log group name with no masker at all (so even an unrotated secret-derived name printed), and the ASG / LogGroup / TargetGroup updating lines, the IAM ManagedPolicy replacement line (its ARN carries the old `Path`) and that replacement's inner delete lines printed it at debug level; the S3 Vectors create-only refusal and the DBProxy / DBProxyEndpoint / StreamConsumer update lines and failure texts named it too. Each site now pairs the physical id (or the name / path its ARN carries) with the recorded reference through `withDerivedNameMasks`, so the pasted command is withheld (the console route stays) and the lines mask it. The DynamoDB GlobalTable remedy already did this (#2177); the Cognito and EMR remedies name AWS-minted ids. Tests: `tests/unit/provisioning/recorded-secret-identifier-masking-4339.test.ts`.
