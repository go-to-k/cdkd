- **Rollback-orphan adoption notices, refusals and logs no longer print state-chosen text raw (issue [#3642](https://github.com/go-to-k/cdkd/issues/3642))** -- `src/deployment/orphan-adoption.ts`, `src/deployment/deploy-engine.ts`, `src/cli/commands/diff-recursive.ts`. The pre-deploy adoption pass interpolated an orphan record's logical id, resource type and physical id, the provider's returned physical id and a caught error's text straight into the notices `cdkd deploy` prints, the refusal it throws, the `Adopting ...` line and its debug lines -- and `cdkd diff --json` carried the same refusals in its `blocking` field unsanitized (its terminal render already stripped them). `state.json` is hand-editable, so a newline, an escape sequence or a bidi override in one of those fields could forge a log line or reorder the terminal. They now render through the same display helpers as the other orphan messages: the logical id and resource type are JSON-quoted when they are not plain identifiers, the physical id has control and bidi characters replaced by spaces (a long or non-ASCII physical id is never cut or rewritten), and error text is sanitized and bounded. `cdkd diff`'s "resource(s) to adopt from a previous rollback" line quotes a non-plain logical id the same way. An ordinary logical id, resource type and physical id render exactly as before.
