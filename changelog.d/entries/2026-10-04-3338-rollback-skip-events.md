- **A rollback op cdkd skips is now recorded, and the automatic rollback keeps its journal over one; a create refused onto another owner's name is no longer journaled (issues [#3338](https://github.com/go-to-k/cdkd/issues/3338), [#4356](https://github.com/go-to-k/cdkd/issues/4356))** -- `src/deployment/rollback-executor.ts`, `src/deployment/rollback-executor/{messages,names,types,replay-revert,replay-reverse-replacement,replay-orphan-delete}.ts`, `src/deployment/deploy-engine/{execute,rollback,create}.ts`, `src/types/deployment-events.ts`. A rollback op the replay declined (a deleted resource it cannot re-create, a missing record or `properties` baseline, a physical id a later attempt changed, a failed op with nothing to revert to) printed one warning and recorded no event, and the automatic rollback then dropped the rollback journal, so `cdkd events` showed a finished rollback naming nothing left unreverted. Each such op now records a `ROLLBACK_RESOURCE_SKIPPED` event with its reason, and an automatic rollback that skipped any keeps the journal and says so. A reverse-replacement whose re-create adopted the live new resource now gives its `ROLLBACK_RESOURCE_SUCCEEDED` event a reason. A create refused with `NAMED_CREATE_COLLISION` (or any create refused before anything was applied that recorded no physical id) is no longer journaled as a failed op, so `cdkd rollback --revert-failed` no longer advises deleting the resource holding that name. An automatic rollback whose own journal segment could not be written no longer removes an older attempt's segment. Tests: `tests/unit/deployment/rollback-executor-skip-events.test.ts`, `deploy-engine-rollback-journal.test.ts`, `deploy-engine-create-name-takeover-4180.test.ts`; integ arms in `tests/integration/{rollback-command,s3-lifecycle,sg-circular-dependency}/verify.sh`.
