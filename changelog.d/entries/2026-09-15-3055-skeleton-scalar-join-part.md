- **A number or boolean `Fn::Join` part now counts as literal text when cdkd positions a secret reference in `state.json` (issue [#3055](https://github.com/go-to-k/cdkd/issues/3055))** -- `src/deployment/secret-redaction.ts` (`intrinsicSkeletonSegments`, new `joinPartLiteralText`), unit tests. The resolver joins such a part as `String(part)` (`8080`, `true`), but the parser read only a string part as literal, so a number or boolean became an unknowable part. The skeleton arm then wildcarded that position: two recorded references differing only there both matched, positioning refused, and the leaf persisted the collapsed map's surviving reference instead of its own. The frame arm read it as a placeholder in the frame and refused, leaving a 1-3 character middle in plaintext, and a nested-stack parameter spelled that way was not carried to the child. The parser now takes the part as `String(part)`, so the frame is written and carried. A `null`, array or object part stays unknowable, and a number delimiter is still refused. Residual, stated in `joinPartLiteralText`'s docstring: a source that left two candidates matching can now leave one, so the skeleton arm's existing wrong-reference residual (an unclassifiable or public `ssm` leaf) is reachable in a few more cases. No L2 construct is known to emit such a part: a synth probe found a TypeScript number interpolated or `Token.asString(8080)` folded into a literal string, and a non-string part only from a hand-written `Lazy.any` inside `Fn.join`.
