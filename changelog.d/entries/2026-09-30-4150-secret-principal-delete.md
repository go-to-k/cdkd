- **`cdkd destroy` / `cdkd state destroy` now delete an `AWS::IAM::Policy` or `AWS::IAM::UserToGroupAddition` whose principals come from a secret, instead of skipping it on every run** (`src/provisioning/secret-principal-resolution.ts`, `iam-policy-provider.ts` / `iam-user-group-provider.ts` `delete()`, `destroy-runner.ts`, go-to-k/cdkd#4150). State keeps such a `Roles` / `Groups` / `Users` entry as its `{{resolve:...}}` expression, which the delete skipped as malformed (exit 2). A destroy now resolves it to the names the secret holds now, under rollback replay's region rules, and removes the policy or membership (a membership is first read, which needs `iam:ListGroupsForUser`). Printed names and the thrown error chain are masked, except a name under 4 characters inside an AWS error message. An unresolvable reference keeps the skip, which says resolution was attempted; a `***` mask is never attempted. A deploy never resolves: its template-removal delete runs after every create, so a logical-id move would lose the new grant. After a secret change, a principal the new value names that lacks the policy or membership makes the delete skip and keep the record (also after an interrupted earlier run, never for its own retry), since one only the old value named may still hold it (remove it by hand, then `cdkd orphan` or `cdkd state orphan`); one only the new value names loses a same-named grant it held from elsewhere, undetectably. While a resolvable such record remains after a partial destroy, the stack keeps its `imports` / `outputReads`, so a producer's destroy is refused until it is gone. A nested child destroyed alone (`cdkd state destroy '<parent>~<child>'`) misses its parent's regions, so it skips: destroy it through the parent. Not covered: a stack whose earlier partial destroy dropped those records, where a region-less reference resolves in the stack's region. Tests: `secret-principal-delete-4150.test.ts`; fixture: `iam-secret-derived-principals`.
