- **A provider failure whose thrown value cannot be converted to text now reports that failure instead of `TypeError: Cannot convert object to primitive value` (issue [#3341](https://github.com/go-to-k/cdkd/issues/3341)).** About 250 catch blocks under `src/provisioning/providers/` that rethrow as a `ProvisioningError` read the caught value with a bare `String(err)`, which throws for a null-prototype object or a hostile `toString` and replaced the real AWS failure (and the text persisted to `deployments/{runId}.jsonl`). They now read it through `describeAwsFailure(err).detail` or `safeStringify(err)`, byte-identical for every value that converted before. Enforced by a shrink-only ratchet in `tests/unit/provisioning/provider-swallowing-catch-out-throw.test.ts`; files held by open PRs are swept by their owners.
