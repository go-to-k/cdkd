- **`cdkd deploy` heals a state record that lacks an attribute a `Fn::GetAtt` asks for, instead of refusing forever (issue [#1852](https://github.com/go-to-k/cdkd/issues/1852))** -- `intrinsic-function-resolver.ts`, `deploy-engine.ts`, new `stale-attribute-heal.ts`, the RDS / DocDB / Neptune providers' `import()`, `docs/troubleshooting.md`, new `stale-attribute-heal` integ. A record written before its provider recorded an attribute (`AWS::SSM::Parameter` `Arn`, `AWS::RDS::DBSubnetGroup` `DBSubnetGroupArn`), written under `--no-wait` while a `DBInstance` had no `Endpoint.Address` / `Endpoint.Port` (go-to-k/cdkd#3077), or holding a pre-#1681 placeholder AppSync ARN, was never rewritten by a deploy that changed none of that resource's properties -- so an added `param.attrArn` output hit the `*Arn` refusal on every deploy, with a false "not enriched ... file an issue" message. Now, when a resolution is about to fall back to the physical ID (or refuse a placeholder ARN or a DBProxy `VpcId`), the deploy re-reads that resource's attributes ONCE through its provider's read-only `import()` (routed by the record's `provisionedBy`), serves the value, and merges it into the record at the state save: only keys the record lacks are added, an empty value is never recorded, nothing else changes, and the resource is not updated. A reference that resolves from state costs no AWS call; a record this deploy (re)wrote, a custom resource and a nested stack are never re-read. A failed read degrades to the previous outcome, and the refusal now names the stale record, the error class and HTTP status (AWS's text stays behind `--verbose`) and the real remedy. `--dry-run` reads but writes nothing; `cdkd diff` / `drift` / `export` never re-read and point at `cdkd deploy`. `cdkd import` of a `DBInstance` now records `Endpoint.*` and `Arn`. Design: [docs/design/1852-stale-attribute-heal.md](https://github.com/go-to-k/cdkd/blob/main/docs/design/1852-stale-attribute-heal.md).
