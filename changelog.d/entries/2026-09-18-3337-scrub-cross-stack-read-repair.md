- **`cdkd scrub` now repairs a cross-stack read name an older binary persisted in plaintext, instead of reporting the record clean.** go-to-k/cdkd#3289 closed the WRITE side — `imports[].exportName`, `outputReads[].sourceStack` and `outputReads[].outputName` are redacted back to their `{{resolve:...}}` expression at the persist choke point — but both lists rode `scrubStack`'s `...carriedState` spread untouched, so a record already on disk kept its plaintext and `cdkd scrub --fail` exited 0 over it. The same three template-derived names are now matched against this run's recorded plaintexts and rewritten; `sourceRegion` and `imports[].sourceStack` are deliberately left verbatim, the second because `cdkd destroy` matches its producer refusal on that literal key and redacting it would drop a destroy-blocking record. A repaired record is counted, so `--dry-run --fail` reddens on it as a standing CI gate. **Population, stated rather than implied by a clean verdict:** this closes the NEVER-AGAIN case — a reference no later deploy re-resolves, which is the ordinary shape for a stable stack. It does NOT close ROTATED, and does not claim to: scrub derives its needles by re-resolving the live template, so it holds the secret's CURRENT value while the stored name holds the one it had when the record was written, a value nothing in the run can see.
