- **A `cdkd deploy` that changes nothing now clears a masked drift-baseline position the resource's own secret references can certify (issue [#3595](https://github.com/go-to-k/cdkd/issues/3595))** -- `src/deployment/masked-baseline-recapture.ts` (new), `src/deployment/deploy-engine.ts` (`kickOffAutoRefreshObservedProperties`, `kickOffMaskedBaselineRecapture`, `drainObservedCaptures`), `src/cli/commands/drift.ts` (the `--accept` refusal wording), `docs/cli-drift.md`, `docs/cli-state.md`, `docs/import.md`, and the `secrets-array-nested` integ. Where cdkd could not pair a secret reference with the value AWS reported, the recorded baseline holds the mask `***` there (issue #2852), and `cdkd drift` reports that position as not compared (exit 2). Only a deploy that changed the resource cleared it. The automatic refresh at the start of every deploy now also handles such a resource: it resolves the references in the resource's own recorded properties, reads it back, and replaces a mask with the reference wherever AWS holds exactly the value it resolves to. Every other position of the baseline is left as it was. The baseline is left alone if a reference fails to resolve, if two references resolve to the same value, or if the resource no longer reads back as its baseline records, so a re-capture never takes in drift. A secret rotated since the resource was deployed keeps its mask. A `NoEcho` custom-resource mask is unchanged, and so is `cdkd state refresh-observed`.
