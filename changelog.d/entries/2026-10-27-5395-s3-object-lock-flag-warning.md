- **`AWS::S3::Bucket` now warns when a change to the top-level `ObjectLockEnabled` of an existing bucket is not applied (issue [#5395](https://github.com/go-to-k/cdkd/issues/5395))** -- `src/provisioning/providers/s3-bucket-provider.ts`. The flag reaches S3 only when a bucket is created. CloudFormation finishes such an update without enabling Object Lock (or, when the flag is removed, without disabling it, which S3 cannot do), and cdkd does the same, but the deploy used to report success without saying anything. It now prints a warning once S3 confirms the bucket still differs: turning the flag on names `ObjectLockConfiguration.ObjectLockEnabled: Enabled` (versioning required) as the way to enable Object Lock on the existing bucket, and removing it says Object Lock stays enabled. A failed read is reported as unconfirmed. Also, a versioning suspend on such a bucket is no longer skipped because the never-applied top-level flag is declared: the suspend is skipped only when the bucket really holds Object Lock.
