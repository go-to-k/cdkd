- **Refusals that send you to `cdkd state list --json` for a name they could not print now say to decode the value before shell-quoting it (issue [#3908](https://github.com/go-to-k/cdkd/issues/3908))** -- `src/state/malformed-resources-bag.ts` (`JSON_LISTING_HOLE_VALUE`, the shared listing pointer, `inspectClause`, `withheldIdentityClause`) and `src/cli/commands/export.ts`, with cases in `tests/unit/cli/state-list.test.ts` and the message suites. The shared pointer said the listing "writes each name raw", and every message filling a quoted identity hole from it -- the `cdkd destroy` withhold arms, the other refusals and warnings in that module, and `cdkd export`'s withheld-record notes -- said to fill the hole "with the shell-quoted value". The listing is JSON: it escapes `"` and `\`, and since [#3163](https://github.com/go-to-k/cdkd/issues/3163) the control, format and separator characters as `\uXXXX`. Those names are the ones the withhold arms exist for, so shell-quoting the value as printed named a record that does not exist. The messages now say the listing prints each name as a JSON string, escaped but never trimmed or sanitized, and to fill each hole with the value decoded from its JSON string, then shell-quoted. A new test drives the `--json` output path: a padded name survives beside its trimmed sibling, and an escaped name decodes back to the stored one. `docs/_contents/cli-destroy.md` now says that `--json` is the withhold arm's pointer while the exact arm keeps `--long`, that the region printed is the key's (#3328), and to leave `--stack-region` out for a record listed with `"region": null`. `docs/_contents/cli-diff.md` now says the `properties` refusal comes when the deploy computes its diff, not when it loads the record.
