- **A Lambda `EventInvokeConfig` recorded `provisionedBy: 'cc-api'` now returns to the SDK provider, whose update works, instead of staying on Cloud Control, whose update always fails for the type** (`src/provisioning/provider-registry.ts`, go-to-k/cdkd#4091). Cloud Control's read handler returns empty `DestinationConfig.OnSuccess` / `OnFailure` objects that its own model then rejects, so every update of a resource pinned there (a record from before the SDK provider existed) failed with `required key [Destination] not found`. The type is now a `cc-broken` sticky exemption: such a record moves to the SDK provider on its next deploy with its physical id (`<FunctionName>|<Qualifier>`) unchanged. `cdkd drift` on such a record no longer reports the empty `DestinationConfig.OnSuccess` / `OnFailure` members Cloud Control's read injected into its baseline as drift. Of the providers documented as working around a broken Cloud Control handler, the CloudFront origin access identity, EventBridge rule and AppSync GraphQL API notes were re-measured stale and are corrected; the AgentCore runtime's documented failure is a create-time race, which records nothing and so cannot pin a resource to Cloud Control.
