- **Every pasteable `aws ...` command cdkd prints now carries the run's explicit `--profile` (issue [#3959](https://github.com/go-to-k/cdkd/issues/3959))** -- new `src/utils/pasteable-aws-profile.ts`, `src/cli/program.ts` (the `preAction` hook records `--profile`), `src/provisioning/replacement-protection-advice.ts` (`pasteableAwsCommand` and `renderDisableCommand` insert it after every `aws` command word), and the hand-built commands in `cloud-control-provider.ts`, `scheduler-schedule-provider.ts`, `efs-provider.ts`, `dynamodb-globaltable-provider.ts`, `state/s3-replication-purge-gap.ts`, `cli/commands/import.ts` and `cli/commands/export.ts`. Before, a remediation command such as the `--remove-protection` compensation's `aws rds modify-db-cluster ... --deletion-protection` line never named a profile, so after `cdkd destroy --profile prod` a pasted copy resolved the operator's DEFAULT profile: at best a NotFound, at worst a change to a same-named resource in another account. Now it reads `aws --profile prod rds modify-db-cluster ...`. Only an explicit `--profile` is rendered; an inherited `AWS_PROFILE` is not, and a run with no profile prints exactly what it did before. A profile holding whitespace or a shell-active character, or one that cannot be printed exactly, becomes the quoted `'<profile>'` hole, and a run that also assumed a role via `--role-arn` / `CDKD_ROLE_ARN` prints `'<role-profile>'`, since the base profile's principal is not the one cdkd ran as. The `dynamodb-globaltable-provider.ts` cleanup, live-only-index and auto-scaling commands now go through `pasteableAwsCommand`, so their table name is shell-quoted and a name that cannot be printed exactly withholds the command.
