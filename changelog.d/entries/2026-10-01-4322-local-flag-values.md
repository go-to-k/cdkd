- **The remaining `cdkd local` lines that printed a template value beside a flag now describe it when it is not plain (issue [#4322](https://github.com/go-to-k/cdkd/issues/4322))** -- `cdkd local invoke-agentcore`'s `--no-verify-auth` and `--sigv4` warnings (runtime logical id); the dropped-env-var warning's `--env-vars` example in `local invoke-agentcore`, `local invoke` and `local start-api` (variable name, cdk path, logical id); `local start-api`'s `--from-state` substitution lines, `--from-cfn-stack` tip (stack name) and `--stage` miss (API logical id); `local invoke`'s `--tmpfs` lines (logical id); and the `--ecr-role-arn` ECR-fallback line in `local invoke` and `local start-api` (image URI). A value that would change a pasted line (`$( )`, a backtick, a leading `~` or `-`) is now described (`a logical id that is not a plain identifier`) or, inside the `--env-vars` JSON example, replaced by `<cdk path or logical id>` / `<variable name>`. A plain value prints as before. `local start-api`'s `--from-state` "could not substitute" warning now gives the resolver's reason on a line of its own, apart from the `--env-vars` remedy, and withholds a reason that itself names a flag beside template text.
