- **A `lock.json` owner or operation that is not a plain identifier is described in every lock message (issue [#4115](https://github.com/go-to-k/cdkd/issues/4115))** -- `src/state/lock-contention-message.ts` (`formatLockOwner`, `formatLockOperation`), `src/state/lock-manager.ts`, `src/cli/commands/state.ts`, `src/utils/display-safe.ts` (`plainIdentOr`). The lock-contention refusal, the `Locked by:` error, the retry line and the force-release and expired-takeover warnings printed the owner and operation raw, and sanitizing keeps spaces, so an owner such as `x, expired 3h ago` made a live lock read as expired and invited a `force-unlock`. They now go through the same rule `cdkd state show` uses: the value when it is a plain identifier, a description otherwise. A genuine `user@host:pid` owner reads as before. Tests: `tests/unit/state/lock-contention-message.test.ts`, `tests/unit/state/lock-acquire-retry-remedy.test.ts`, `tests/unit/state/lock-manager.test.ts`.
