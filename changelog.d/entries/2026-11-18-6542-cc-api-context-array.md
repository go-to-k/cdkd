- **`ec2.PrefixList`, `iam.Role`, `ecr.Repository`, `rds.DatabaseInstance` and `rds.DatabaseCluster` `fromLookup()` now synthesize under cdkd (issue [#6542](https://github.com/go-to-k/cdkd/issues/6542))** -- `src/synthesis/context-providers/cc-api-provider.ts`, `src/synthesis/synthesizer.ts` and unit tests. The `cc-api-provider` context lookup returned a bare object when exactly one resource matched, while the AWS CDK CLI always returns an array with one object per match, each carrying `Identifier`; aws-cdk-lib reads `response[0]` or `response.length`, so those lookups failed with `UnexpectedResponseReceivedContextProvider` or `Cannot read properties of undefined (reading 'Arn')`, and the object was saved to `cdk.context.json`. The provider now follows the CDK CLI: it always returns the array, returns only `propertiesToReturn` plus `Identifier`, leaves an unset `expectedMatchCount` unvalidated (a `propertyMatch` lookup with no match returns `[]`), returns `dummyValue` under `ignoreErrorOnMissingContext` for a missing `exactIdentifier`, passes `resourceModel` to `ListResources`, and refuses the query shapes the CDK CLI refuses. An object an older cdkd stored in `cdk.context.json` for one of these lookups is no longer passed to the app: cdkd looks the value up again and overwrites the entry with the array, so the same checkout synthesizes under `cdk synth` again too.
