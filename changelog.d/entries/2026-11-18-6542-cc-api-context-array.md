- **`ec2.PrefixList`, `iam.Role`, `ecr.Repository`, `rds.DatabaseInstance` and `rds.DatabaseCluster` `fromLookup()` now synthesize under cdkd (issue [#6542](https://github.com/go-to-k/cdkd/issues/6542))** -- `src/synthesis/context-providers/cc-api-provider.ts` and its unit tests. The `cc-api-provider` context lookup returned a bare object when exactly one resource matched, while the AWS CDK CLI always returns an array with one object per match, each carrying `Identifier`; aws-cdk-lib reads `response[0]` or `response.length`, so those lookups failed with `UnexpectedResponseReceivedContextProvider` or `Cannot read properties of undefined (reading 'Arn')`, and the object was saved to `cdk.context.json`. The provider now follows the CDK CLI: it always returns the array, returns only `propertiesToReturn` plus `Identifier`, leaves an unset `expectedMatchCount` unvalidated (a `propertyMatch` lookup with no match returns `[]`), returns `dummyValue` under `ignoreErrorOnMissingContext` for a missing `exactIdentifier`, passes `resourceModel` to `ListResources`, and refuses the query shapes the CDK CLI refuses. A `cdk.context.json` entry written by an older cdkd for these lookups holds the object and must be removed with `cdk context --remove <key>` (or `cdkd context --reset`).
