- **AWS Emulator mixed mode on `cdkd local`: under `--aws-emulator`, keep chosen services on real AWS with `"real-aws"` (issue [#6150](https://github.com/go-to-k/cdkd/issues/6150))** -- `src/cli/aws-emulator.ts`, `src/local/local-aws-wiring.ts`, `src/local/mixed-mode-state.ts`, `src/cli/commands/local-state-source.ts`, `src/local/ecs-task-runner/`, `src/utils/aws-client-defaults.ts` (`cdk-local` bumped to ^0.164.0). `--aws-emulator` sends every AWS call to the emulator; `"AWS_ENDPOINT_URL_<SERVICE>": "real-aws"` in the `--env-vars` file (under `Parameters` or one resource's section) keeps that service on real AWS, and an unmarked service stays on the emulator (fail closed). A container keeping an exception gets your real identity; the others get the emulator's keys only, and their calls go through a re-signing sidecar. cdkd's own calls follow the same routing per workload (`{{resolve:...}}`, ECS task secrets, `--from-state` / `--from-cfn-stack` names; STS identity hops stay real, deployed artifacts stay on the emulator). With exceptions and `--from-state`, deploy the stack to both sides. Under `--aws-emulator` with no state source, one hint follows the dropped-variable warnings. **Behavior change:** the `"aws-emulator"` value is refused with a migration message; `"real-aws"` without the flag is a no-op; a value on the bare `AWS_ENDPOINT_URL` or a misspelled variable is refused.
