- **The automatic rollback now reverts a Cloud Control resource still settling from the update it undoes (issue [#6843](https://github.com/go-to-k/cdkd/issues/6843))** -- `src/deployment/rollback-executor/replay-retry.ts`, `tests/unit/deployment/rollback-unsettled-revert-retry-6843.test.ts`, `tests/integration/cc-write-only-secret-version/verify.sh`. A deploy that changed an `AWS::RedshiftServerless::Namespace` password and then failed on a later resource could not be rolled back automatically: the password change keeps the namespace `MODIFYING` for minutes, and the revert, sent right away, failed with Cloud Control `NotStabilized` ("Exceeded attempts to wait", no `UpdateNamespace` sent) or `ResourceConflict`, leaving the new password live and the journal for a manual `cdkd rollback`. A rollback revert that Cloud Control fails with either code is now re-sent after a wait (30 s, then 60 s, up to four re-sends, none started after 15 minutes, each announced); CloudFormation's own rollback stops `UPDATE_ROLLBACK_FAILED` here; any other failure, and the last one, surfaces as before. The deploy path is unchanged.
