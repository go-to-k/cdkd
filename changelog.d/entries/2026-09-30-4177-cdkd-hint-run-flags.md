- **Every pasteable `cdkd ...` hint now carries the run's typed `--profile`, `--state-bucket` and `--state-prefix` (issue [#4177](https://github.com/go-to-k/cdkd/issues/4177))** -- new `src/utils/pasteable-run-context.ts`, `src/utils/pasteable-command.ts` (`pasteableCommand` appends them), `src/cli/program.ts` (the `preAction` hook records them and reads which options each subcommand parses off the Commander tree), `src/cli/options.ts`, `src/cli/commands/{events,deploy}.ts`, `src/deployment/rollback-executor.ts` and `src/synthesis/macro-expander.ts`. Before, a hint such as `cdkd state orphan MyStack --stack-region us-east-1` or `Retry with: cdkd destroy MyStack`, printed after `cdkd destroy MyStack --profile prod --state-bucket b`, resolved the DEFAULT profile and bucket when pasted, so a destructive hint could act on a same-named record in another account or bucket. Now it reads `cdkd state orphan MyStack --stack-region us-east-1 --profile prod --state-bucket b`. Only flags typed on the command line are rendered, each only where the hinted subcommand parses it and never twice. A value that is not inert in a shell prints as a quoted hole, and a run that passed `--role-arn` prints `--role-arn '<role-arn>'`, which cdkd refuses until filled in. `--state-prefix` now refuses a value holding `<` or `>`, so a pasted `'<prefix>'` placeholder fails instead of deploying into an empty key space; `cdkd events` / `cdkd events prune` now apply `--role-arn`, which they declared and silently ignored; the Ctrl-C `cdkd force-unlock` line and a stack-less `cdkd rollback --orphan` line carry the flags too. The two macro-expansion cleanup hints (`aws cloudformation delete-stack`, `aws s3 rm`) moved out of prose quotes onto their own line and now carry the run's `--profile` and the client's `--region` ([#3959](https://github.com/go-to-k/cdkd/issues/3959)).
