- **Destroy removes what CloudFormation clears first: an EFS replication source's replication configuration, and an EMR TASK group's automatic scaling policy (issue [#6751](https://github.com/go-to-k/cdkd/issues/6751))** -- `src/provisioning/providers/efs/file-system.ts`. `DeleteFileSystem` refuses a replication source with `FileSystemInUse` until its replication configuration is deleted and torn down, which CloudFormation's handler does first. cdkd used to send only `DeleteFileSystem`, so a destroy failed where the AWS CDK CLI succeeds. On that refusal cdkd now deletes the configuration the file system is the source of, waits for the teardown, and deletes the file system. A file system that is only a replication destination still gets AWS's refusal. Deleting an `AWS::EMR::InstanceGroupConfig` TASK group that declares an `AutoScalingPolicy` now removes the policy before scaling the group to 0 (`src/provisioning/providers/emr-instance-group-config/remove-scaling-policy.ts`), as the handler does; before, the policy's CloudWatch alarm and Application Auto Scaling target outlived the group.
