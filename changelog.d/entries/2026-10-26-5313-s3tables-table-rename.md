- **Changing an `AWS::S3Tables::Table`'s `TableName` or `Namespace` now renames the table on AWS (issue [#5313](https://github.com/go-to-k/cdkd/issues/5313))** -- `src/provisioning/providers/s3-tables-provider.ts`. The update path only applied `Tags`, so the deploy succeeded and the state recorded the new name while AWS kept the old one. CloudFormation updates both properties in place (`Replacement: False`) and keeps the table's ARN; cdkd now does the same with one `RenameTable` call, sent after any tag change, and records the new `<tableBucketARN>|<namespace>|<name>` physical id (a row holding a bare table ARN keeps it). The rename is planned from the physical id, so a table an earlier cdkd left under its old name is renamed by its next update. A non-string or empty `TableName` / `Namespace` is refused before any call. A replayed rename whose first answer was lost (the old name is gone) is accepted only when the table now at the new name carries the recorded `TableARN`. cdkd resolves a Table's `Ref` to its name, so a resource reading `Ref` (or `${Table}` in `Fn::Sub`) is now re-provisioned when the name changes (`src/analyzer/diff-calculator.ts`). Unit cases in `tests/unit/provisioning/providers/s3-tables-provider.test.ts` and `tests/unit/analyzer/diff-calculator-nested-output-promotion.test.ts`; the `s3-tables` integ gains a phase renaming the table, moving it to a second namespace, and checking that an SSM parameter reading its `Ref` follows.
