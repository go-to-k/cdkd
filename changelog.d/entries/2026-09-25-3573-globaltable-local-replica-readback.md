- **`cdkd drift` now reads back the local replica of a multi-region `AWS::DynamoDB::GlobalTable` (issue [#3573](https://github.com/go-to-k/cdkd/issues/3573))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`, `src/cli/commands/drift.ts`, `src/types/resource.ts`; tests in `tests/unit/provisioning/dynamodb-globaltable-provider-local-replica-readback.test.ts` and `tests/unit/cli/drift.test.ts`. On a table with a cross-region replica, `DescribeTable` in the deploy region lists only the other regions, so the readback left the deploy-region entry out of `Replicas`. Drift on that replica's tags, point-in-time recovery, contributor insights and read ceilings was invisible, and after a reverse-replacement rollback `cdkd drift` reported `Replicas` on every run. The readback now appends the local entry, and `Replicas` is compared as a set (the registry schema declares it unordered), so a template listing the deploy region first still matches. A record captured by an earlier version lacks that entry, so a new optional provider hook, `canonicalizeDriftPair`, sees both comparison bags at once: when the baseline has no local entry, it is completed with the readback's. `cdkd drift --revert` applies the same completion to the bag it sends, so reverting another replica leaves the local table's tags and read auto-scaling alone, and `--accept` stores the full readback. State is not otherwise rewritten; the next deploy captures the new shape.
