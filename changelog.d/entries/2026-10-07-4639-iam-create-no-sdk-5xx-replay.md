- **IAM creates no longer let the AWS SDK replay a 5xx inside one call (issue [#4639](https://github.com/go-to-k/cdkd/issues/4639), IAM slice)** -- `src/provisioning/providers/iam-create-client.ts` and the `iam-role`, `iam-user-group`, `iam-instance-profile`, `iam-managed-policy` and `iam-access-key` providers. `CreateRole`, `CreateUser`, `CreateGroup`, `CreateInstanceProfile`, `CreatePolicy` and `CreateAccessKey` carry no idempotency token and were sent through the shared IAM client, whose SDK retry replays a 5xx even when IAM completed the request. For the name-unique creates the replay failed `EntityAlreadyExists` against the entity the first request made, the collision was credited to another holder, and the entity was left in no state record for every re-run to collide with. For `CreateAccessKey` the replay minted a second key and returned it, leaving the first as a live, unrecorded credential in one of the user's two key slots. They now go through a dedicated client that refuses the SDK's 5xx retry (the CodeCommit / EC2 pattern), so the 5xx reaches the deploy engine, which marks a later collision as possibly this create's own, and, for an access key, the provider's failed-attempt reconcile, which deletes the key that attempt minted when `ListAccessKeys` already shows it (the list is eventually consistent; a key it does not show yet is neither deleted nor reported, and the retry mints a second one). Tests: `tests/unit/provisioning/iam-create-retry-4639.test.ts`.
