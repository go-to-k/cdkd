- **`cdkd local invoke` / `start-api` / `run-task` / `invoke-agentcore` now pull a FIPS or dual-stack ECR image (issue [#1855](https://github.com/go-to-k/cdkd/issues/1855))** -- `src/local/ecr-puller.ts`, `tests/unit/local/ecr-puller.test.ts`, `docs/local-run-task.md`, `tests/integration/local-run-task-from-state/`. An image on `<acct>.dkr.ecr-fips.<region>.<suffix>`, `<acct>.dkr-ecr.<region>.on.aws` or `<acct>.dkr-ecr-fips.<region>.on.aws` failed with `no basic auth credentials`. `docker login` always targeted the plain `<acct>.dkr.ecr.<region>.<suffix>` host that `GetAuthorizationToken` reports as `proxyEndpoint`, while `docker pull` targeted the host the template named, and Docker keys its credential store on the hostname verbatim. The login now targets the pull reference's own host. The plain form is unchanged and still prefers the reported `proxyEndpoint`. The ECR token authenticates on all four host forms. The image host's case fold is now ASCII-only: a full Unicode fold turned a Kelvin sign (U+212A) into `k` before the region guard ran, so `<acct>.dkr.ecr-fips.us-<U+212A>east-1.amazonaws.com` parsed as the region `us-keast-1`; it is now refused. `start-service` / `start-alb` / `start-agentcore` pull through cdk-local's puller and are tracked in [#3655](https://github.com/go-to-k/cdkd/issues/3655).
