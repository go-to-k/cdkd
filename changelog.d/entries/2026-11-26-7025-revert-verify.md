- **`cdkd drift --revert`: a revert AWS accepted without applying now fails instead of reporting success (issue [#7025](https://github.com/go-to-k/cdkd/issues/7025), step 6)** -- `src/cli/commands/drift/revert-verify.ts`, `src/cli/commands/drift/revert.ts`, `src/cli/commands/drift/revert-apply.ts`, `src/cli/commands/drift/command.ts`. A resource was counted `reverted` as soon as its update call returned, so a service that accepted the call but kept the live value (as Lambda did with `DestinationConfig: {}`, #6777) left the drift in place while the run exited 0. After the updates, each stack with a reverted resource is now re-detected with the same comparison `cdkd drift` runs, once its lock is released; a property the revert sent that still differs, and where AWS does not hold the value sent, is read again up to twice over about 13 seconds, then reported as `not applied by AWS` with the paths that differ, and the run exits 2. A re-read that cannot compare the resource prints a `could not verify` warning and keeps the exit code. Drift on a property the revert did not send does not fail it. The re-read writes nothing and runs only on `drift --revert` (not under `--dry-run`). Tests: `tests/unit/cli/drift-revert-verify-7025.test.ts`.
