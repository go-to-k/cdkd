- **`cdkd local start-microvm` runs AWS Lambda MicroVMs locally (issue [#5330](https://github.com/go-to-k/cdkd/issues/5330))** -- `package.json` (cdk-local 0.156.0), `src/cli/commands/local-start-microvm.ts`, `local-invoke.ts`. The new subcommand builds an `AWS::Lambda::MicrovmImage`'s `Dockerfile` from its staged asset in `cdk.out`, starts `--count` containers, drives each one's `/ready` / `/validate` / `/run` hooks in the cloud's order, and serves each MicroVM on its own local URL: requests route by `X-aws-proxy-port`, then a `lambda-microvms.port.N` WebSocket subprotocol, then 8080, with the `X-aws-proxy-*` headers and MicroVM subprotocols stripped, and a `/_cdkl/microvm` control endpoint (refusing cross-origin requests with 403) suspends, resumes and terminates it; `--auto-resume` holds requests to a suspended MicroVM through one resume. SIGTERM / ^C calls `/terminate` and removes the containers. The image's environment resolves through cdkd's `--from-state` / `--state-bucket` / `--state-prefix` or cdk-local's `--from-cfn-stack`; `--assume-role` takes an explicit ARN, since the execution role is not in the template. Guide: `docs/local-start-microvm.md`.
