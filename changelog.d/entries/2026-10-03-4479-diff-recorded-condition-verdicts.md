- **`cdkd diff` reuses the condition verdict the last deploy recorded, so an `Fn::If` on a condition over a secret-fed parameter no longer always takes FALSE (issue [#4479](https://github.com/go-to-k/cdkd/issues/4479))** -- `src/deployment/condition-verdicts.ts` (new), `src/deployment/deploy-engine/deploy-flow.ts`, `src/cli/commands/diff-recursive.ts`, `src/types/state.ts`. A condition that reads a parameter fed a secret `{{resolve:...}}` reference has no verdict at plan time. An `Fn::If` on one took its FALSE branch, so a stack whose last deploy took the TRUE branch diffed as a perpetual UPDATE, and `cdkd diff --fail` exited 1 on an unchanged stack. The deploy, which evaluates against the real value, now records each such verdict in state (`conditionVerdicts`, an additive field with no schema bump) with a sha256 fingerprint of the condition's definitions, transitively through `{Condition: X}`, and of the parameter inputs they read: a secret-fed one as its expression, never its value. The diff reuses a verdict only when its own fingerprint is equal, for both `Fn::If` and pruning. Every slot is then compared against the deployed verdict, so a branch swap, an edited condition or a different secret reference is still reported. A deploy's final save and its no-change save write the record; a child an older binary deployed gains it on the next deploy that changes it. No record (an older binary, a failed deploy), a different fingerprint (the diff warns), an unbound or parent-supplied plain parameter, or a shape outside `Fn::And` / `Or` / `Not` / `Equals` over string literals and declared scalar parameters keeps the FALSE branch. The diff still assumes the value behind an unchanged secret reference is unchanged, as it does for every secret-bearing property. Tests: `tests/unit/cli/diff-recorded-verdicts-4479.test.ts`, `tests/unit/deployment/condition-verdicts.test.ts`, `tests/unit/deployment/deploy-engine-condition-verdicts-4479.test.ts`.
