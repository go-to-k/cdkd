- **Four `AWS::DynamoDB::GlobalTable` settings that deployed green with nothing applied now reach AWS, or are refused, as CloudFormation handles them (issue [#5489](https://github.com/go-to-k/cdkd/issues/5489))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`, `src/provisioning/dynamodb-replica-settings.ts`, `src/provisioning/dynamodb-contributor-insights.ts`, `src/analyzer/replacement-rules.ts`, new `tests/unit/provisioning/dynamodb-globaltable-provider-replica-settings-5489.test.ts`, `tests/integration/dynamodb-globaltable-replica-settings/`. Each follows a CloudFormation A/B. `Replicas[].GlobalSecondaryIndexes[].ContributorInsightsSpecification` now goes out as `UpdateContributorInsights` with the `IndexName`, in each replica's region; a removed block (or a removed replica index list) disables it. On an update it is sent after the index changes, so an index the same deploy adds exists first. `Replicas[].ReplicaStreamSpecification.Tags` is diffed onto each replica's stream with `TagResource` / `UntagResource`. A declaration that a deploy made before this fix never applied is checked against AWS on the next update and set. `Replicas[].GlobalTableSettingsReplicationMode` rides `CreateTable`, and a change goes out in its own `UpdateTable`, with `DISABLED` for a removal. It is refused before any call on a table with more than one replica, as CloudFormation refuses it. A declared mode that a pre-fix deploy never sent is set on the next update when `DescribeTable` reports another one. A `LocalSecondaryIndexes` list removed as a whole now REPLACES the table, as CloudFormation does (a new `AWS::DynamoDB::GlobalTable` replacement rule in `src/analyzer/replacement-rules.ts`; the type is stateful, so `--force-stateful-recreation` still gates it). An added list is refused before any call, like a changed entry already was, because CloudFormation fails that update. Before, both directions deployed green.
