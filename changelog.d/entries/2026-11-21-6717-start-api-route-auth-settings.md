- **`cdkd local start-api` enforces `AuthorizationScopes` and `IdentityValidationExpression`, answers a rejected Cognito token with the deployed API's status, resolves a REST v1 `CognitoUserPoolsAuthorizer`'s pool from `--from-state` / `--from-cfn-stack`, and warns per route for every auth setting it does not enforce (issue [#6717](https://github.com/go-to-k/cdkd/issues/6717))** -- `src/cli/commands/local-start-api/{command,state}.ts`, cdk-local 0.169.2. A REST v1 Cognito authorizer names its pool as `Fn::GetAtt <Pool>.Arn`; with a state source tokens are now verified against the deployed pool's JWKS (without one the route still serves, warned per route). HTTP API JWT routes check `AuthorizationScopes` against the token's `scope` / `scp` claim (403); REST v1 Cognito methods apply the deployed token-type rule (an ID token without scopes, an access token carrying one of them with scopes); `IdentityValidationExpression` must match the whole value (401). A rejected Cognito token answers 401 `Unauthorized`, 401 `The incoming token has expired`, or 403 `Access Denied` for a bad signature, as deployed, instead of 403 for every case, and the `Bearer ` prefix is optional. Intrinsic scopes and expressions resolve from state, which is loaded for them even when no Lambda in the stack is routed. `ApiKeyRequired`, a RestApi `Policy`, and a scope or expression that stays unresolved warn per route at startup instead of being ignored silently.
