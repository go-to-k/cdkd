- **A malformed `Targets`, `NotificationsWithSubscribers` / `ResourceTags` or `Triggers` / `Tags` list no longer removes every entry an ELBv2 target group, budget or CodeCommit repository holds (issue [#3989](https://github.com/go-to-k/cdkd/issues/3989))** -- `src/provisioning/providers/elbv2-provider.ts`, `budgets-budget-provider.ts` and `codecommit-repository-provider.ts`, with unit tests in `tests/unit/provisioning/elbv2-targetgroup-malformed-targets-3989.test.ts`, `budgets-budget-provider-malformed-lists-3989.test.ts` and `providers/codecommit-repository-provider-malformed-lists-3989.test.ts`. Each list read a present-but-malformed value (a string, an object, an entry with no identifying member) as empty, and each update derives its removals from the gap between the desired and the recorded list, so a malformed desired side -- reachable on a rollback or `cdkd drift --revert`, which replay a recorded bag -- deregistered every target, deleted every budget notification or untagged every key, and `PutRepositoryTriggers` cleared every trigger. A malformed desired list is now refused before any AWS call, on every path, naming the property but never its content; a create refuses it too instead of dropping entries. A malformed recorded list (for example an unresolved intrinsic a `cdkd import` left) is applied ADD-only: the target group's registered targets and the repository's triggers are read from AWS and nothing is deregistered or cleared, notifications and tags are added without deleting any, and cdkd warns about what it left in place. `undefined` / `null` still reads as the empty list. Separately, a budget update that adds a notification which already exists now creates the desired subscribers on it instead of skipping them. The secret-derived check these lists share with the Auto Scaling group, Firehose and IAM principal-list reads now treats cdkd's `***` mask only as a whole value, so a legitimate key such as `a***b` is read as an ordinary name there too.
