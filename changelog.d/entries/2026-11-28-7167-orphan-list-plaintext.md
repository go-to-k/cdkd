- **An orphan or superseded record whose stored readback holds a secret's plaintext inside a list, where its own properties hold the reference, no longer keeps that plaintext on a deploy save or in `cdkd scrub` (issue [#7167](https://github.com/go-to-k/cdkd/issues/7167))** -- `src/deployment/secret-redaction/{stored-reference-positions,off-template-echo}.ts`, `src/deployment/deploy-engine/state-persist.ts`, `src/cli/commands/scrub/{stack-resolve,stack}.ts`, `src/cli/commands/state/refresh-observed-stack.ts`. A record an older version wrote can hold the plaintext at `Users[0].Password` beside `{{resolve:ssm-secure:...}}` in `properties`. A deploy resolves nothing for such a record, and its walk does not enter an unkeyed list by position, so the plaintext was saved again. The deploy save now pairs the list element by a shared identity field, by position when every element lines up, or by the one readback element that lines up, and puts the reference back. Where the pairing is ambiguous, it masks every element that could hold the value, unless the list already holds the reference. `cdkd scrub` already repaired an orphan record, which it resolves. It did not resolve a superseded record's own references, so a plaintext only that record knew was kept at any position; those references are now resolved too. Tests: `tests/unit/deployment/orphan-list-plaintext-7167.test.ts`.
