- **`cdkd local run-task --from-state` keeps a secret another stack exports off the `docker run` command line (issue [#6337](https://github.com/go-to-k/cdkd/issues/6337))** -- `src/local/cross-stack-secrets.ts` (new), `src/cli/commands/local-state-loader.ts`, `src/local/ecs-task-resolver/cross-stack.ts`, `docs/local-run-task.md`. The argv secret check read the consumer stack's own state only, so a producer's exported `AWS::AppSync::ApiKey` (or another secret it records in plaintext, such as an `AWS::IAM::AccessKey`'s `SecretAccessKey`) read through `Fn::ImportValue` / `Fn::GetStackOutput` went on the command line as plaintext, where `ps` and `docker inspect` show it. The resolver cdkd builds for `--from-state` now also says whether a value it served holds a secret of the producer's state, beside cdk-local's `CrossStackResolver` contract, which is unchanged. The exports-index fast path reads the producer's record for this, once per record; no index or state schema change. Such a value is refused in a `Command` / `EntryPoint` / health-check element, passed value-less (`-e KEY`) in `Environment`, where CloudFormation accepts it, and dropped as a `Secrets` `ValueFrom` with a warning naming no value. A value whose producer record cannot be read is refused on the command line too (fail closed). `--from-cfn-stack`'s resolver is cdk-local's and is not checked. Tests: `tests/unit/local/{cross-stack-secrets,ecs-task-resolver-command-intrinsics}.test.ts`, `tests/unit/cli/local-state-loader-cross-stack.test.ts`.
