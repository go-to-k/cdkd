- **A relative symlink inside a Lambda Layer no longer arrives dangling in the local container (issue [#3106](https://github.com/go-to-k/cdkd/issues/3106), found in the [#3105](https://github.com/go-to-k/cdkd/pull/3105) review)** -- `src/cli/commands/local-invoke.ts` (`materializeLambdaLayers`), `src/cli/commands/local-start-api.ts` (the `start-api` layer merge), unit tests, the `local-invoke-layers` fixture. Both layer merges copy each layer's asset directory into one tmpdir with `fs.cpSync`, whose `verbatimSymlinks` defaults to `false` in every Node release: a RELATIVE link such as `bin/rel-link -> real.sh` (the shape a layer build tool emits for a shared binary) was rewritten to the ABSOLUTE host path of the source asset, so `/opt/bin/rel-link` resolved to a path that does not exist inside the container and a handler executing through it failed with `ENOENT`. The copies now pass `verbatimSymlinks: true`; the comment above each call had claimed the opposite since the #241 backlog. Only the multi-layer merge path was affected (a single layer is bind-mounted directly); absolute symlinks and dereferenced files are unchanged. Measured live: the `local-invoke-layers` fixture now execs `/opt/bin/rel-link` and returns `real-via-link`, and fails with `spawnSync /opt/bin/rel-link ENOENT` on the pre-fix binary. cdk-local carries the same fix ([#727](https://github.com/go-to-k/cdk-local/issues/727)).
