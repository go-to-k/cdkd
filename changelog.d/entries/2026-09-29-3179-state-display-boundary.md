- **`cdkd state` renders every stack name and region in a visible boundary, and its two confirmation prompts describe a value that is not a plain identifier (issues [#3179](https://github.com/go-to-k/cdkd/issues/3179), [#3027](https://github.com/go-to-k/cdkd/issues/3027), [#3617](https://github.com/go-to-k/cdkd/issues/3617), [#3760](https://github.com/go-to-k/cdkd/issues/3760), [#3950](https://github.com/go-to-k/cdkd/issues/3950))** -- `src/cli/commands/state.ts`, `src/utils/display-safe.ts`, with unit tests in `tests/unit/cli/state-*.test.ts`. A stack name or region read from an S3 key or a state record reached the refusals, log lines and rows of `state resources` / `show` / `list --long` / `orphan` / `destroy` / `refresh-observed` / `info` raw, through an allowlist that kept spaces beside cdkd's own ` (region)` annotation, or inside cdkd's own `'...'`, which a `'` in the value closed so a pasted sentence ran the rest. Each now renders through `displayIdent`: a plain value prints unchanged, anything else JSON-quoted. The `state orphan` and `state refresh-observed` prompts, printed beside a labelled `Destroy with:` / `Migrate with:` line, show a name or region only when it is a plain identifier and describe it otherwise, so a padded value can no longer wrap into a counterfeit labelled row, and a bare `,` can no longer add an entry to a joined list. Every line of a `state orphan` run describes such a value the same way, including a lock owner or operation in the live-lock warning that does not render as itself; the prompts, the skip and no-record lines, and under `--yes` / `--force` the removal line add `'cdkd state list --long' shows the records as stored.` when they described a value. A refusal whose name is not followed by ` (region)` puts its remedy on its own line, and the `--stack-region` remedy quotes its `'<region>'` placeholder; `cdkd rollback <stack>` shares both refusals.
