- **Text the template spells is no longer stored as a secret's `{{resolve:...}}` reference, whatever secret it equals or contains, so a PostgreSQL `rds.DatabaseInstance` with CDK's generated username `postgres` updates in place (issue [#7037](https://github.com/go-to-k/cdkd/issues/7037))** -- `src/deployment/secret-redaction/redact-path/template-literal.ts`, `redact-path/literal-rendering.ts` (new), `redact-path.ts`, `src/deployment/deploy-engine/update/compare-record.ts`. `Engine: postgres` was stored as the username reference (the whole-value case #6303 left out), so the next deploy that changed anything else read an `Engine` change and refused a stateful replacement. A leaf equal to the template's plain literal is now stored as written, and an `Fn::Join` / `Fn::Sub` / `Fn::If` built only from template text and `{{resolve:...}}` references keeps its text and its references; any part supplied by a parameter (a `NoEcho` one included), an attribute or an import is still redacted. **Already-affected state:** the next `cdkd deploy`, with or without other changes, repairs the record without sending the repaired property, and `cdkd scrub` repairs it without a deploy. `cdkd diff` cannot tell the reference from the literal without reading the secret, which it never does, so it keeps showing the old row until one of the two runs.
