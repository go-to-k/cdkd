- **A nested stack whose resource carries `Tags` no longer fails to deploy (issue [#6893](https://github.com/go-to-k/cdkd/issues/6893))** -- `src/provisioning/providers/nested-stack-provider.ts`, `src/provisioning/property-coverage.generated.ts`, `tests/unit/provisioning/nested-stack-row-tags-handled-6893.test.ts`. `Tags` on an `AWS::CloudFormation::Stack` row was listed as a property cdkd does not handle, and that type has no Cloud Control route, so the deploy was refused before it started (`Child: AWS::CloudFormation::Stack uses properties cdkd's SDK Provider does not handle`). CDK synth writes a stack's `StackProps.tags`, and tags added with `Tags.of(...)`, onto every `NestedStack`'s row, so any app combining stack tags with a nested stack was refused. Since #6871 cdkd applies a row's `Tags` to the nested stack's resources, as CloudFormation does, so `Tags` is now handled: the row deploys, its `Tags` are recorded in the parent's state like any handled property (a secret-derived value redacted as usual), and a tag change is an in-place update of the nested stack. An existing record without `Tags` updates the nested stack once, in place; it is never replaced.
