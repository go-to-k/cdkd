- **`cdkd deploy`: a `TableV2` stream view type change is applied instead of failing with "Table already has an enabled stream" (issue [#7000](https://github.com/go-to-k/cdkd/issues/7000))** -- `src/provisioning/providers/dynamodb-globaltable/update-table.ts`. Changing `dynamoStream` on an `AWS::DynamoDB::GlobalTable` (for example `NEW_IMAGE` to `NEW_AND_OLD_IMAGES`) sent the new view type to the enabled stream, which DynamoDB refuses, so every such deploy failed and rolled back. cdkd now disables the live stream, waits for the table to be `ACTIVE` again and enables the new view type, as CloudFormation does, and drops its cached `StreamArn` for the table so a reader of the new stream resolves the new ARN. Tests: `tests/unit/provisioning/dynamodb-globaltable-stream-view-type-7000.test.ts`; integ `globaltable-stream-view-type`.
