- **A reader of a Cloud Control resource's update timestamp, or of an EC2 gateway route table association's id, follows an in-place update of it (issue [#7007](https://github.com/go-to-k/cdkd/issues/7007))** -- `scripts/gen-in-place-attr-coverage.ts`, `scripts/in-place-attr-classification.ts`, `src/analyzer/diff-calculator/in-place-cc-derived-attrs.generated.ts`, `src/analyzer/diff-calculator/shared.ts`, `src/deployment/export-change-guard.ts`. A resource reading `Fn::GetAtt` of a Cloud-Control-routed type's last-update time (`UpdatedAt`, `LastModifiedTime`, `LastUpdatedTime` and the like, 372 attributes) stayed `NO_CHANGE` after an in-place update of that resource and kept the old value; it is now re-resolved. An export of such an attribute is judged after the update, so an imported one is refused only when its value moved, as CloudFormation does. An `AWS::EC2::GatewayRouteTableAssociation` `RouteTableId` change mints a new `AssociationId`, which the audit called fixed; its reader now follows it too. The in-place attribute audit gains two rules that settle Cloud Control attributes as never moving: an identity-shaped, unversioned CFn primary-identifier member (the handler contract fixes it across an update), and an own ARN whose documented template names only fixed values. The unclassified baseline shrinks from 3204 to 2323 pairs.
