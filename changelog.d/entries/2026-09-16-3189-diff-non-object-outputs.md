- **`cdkd diff` no longer invents Outputs `REMOVE` rows from a stored `outputs` bag that is not an object (issue [#3189](https://github.com/go-to-k/cdkd/issues/3189))** -- `src/cli/commands/diff-recursive.ts`, `src/analyzer/outputs-diff.ts`, `src/state/malformed-resources-bag.ts`, `docs/cli-diff.md`, `tests/unit/cli/diff-recursive-malformed-outputs.test.ts`, `tests/unit/analyzer/outputs-diff.test.ts`, `tests/unit/state/malformed-resources-bag.test.ts`. A state record is read as an unchecked cast, so `computeOutputsDiff` admitted the stored bag on a bare `?? {}` -- which covers `null` and `undefined` only. `Object.entries` then walked a string or a list as readily as a map: measured at `aced052a`, `'abcdef'` produced six `REMOVE` rows named `"0"`..`"5"`, each carrying one character of the record as its `old:` side, `[1,2,3]` produced three, and `cdkd diff --fail` exited 1 on them. The bag is now repaired AT THE LOAD (`loadStateOrEmpty`), through the `isReadableBag` predicate the `resources` guard already used, with `malformedOutputsWarning` naming the stack, the container and what continuing empty means -- judged per node, so a healthy parent can sit above a malformed nested child. The load dominates every consumer: `resolveTemplateOutputs`'s stored-key lookups for issues [#2740](https://github.com/go-to-k/cdkd/issues/2740) and [#1942](https://github.com/go-to-k/cdkd/issues/1942) answered `hasOwnProperty` TRUE on a string for `'0'` / `'length'` and THREW outright on `null`, one call above the walk. `computeOutputsDiff` takes the same predicate as a second line of defence. Reading the bag as EMPTY rather than refusing keeps the preview usable: every resolved output is reported as an `ADD` and no stored key as a `REMOVE`. An ABSENT `outputs` field is exempt -- inert on this path, and a record cdkd itself writes. A healthy or empty bag is untouched and silent; `cdkd diff` writes no state, so the repair is in memory.
