- **Removing nine `AWS::AutoScaling::AutoScalingGroup` properties from a template no longer resets them, matching CloudFormation (issue [#5004](https://github.com/go-to-k/cdkd/issues/5004))** -- A real CloudFormation A/B showed CloudFormation keeps the live value of a removed `HealthCheckType`, `HealthCheckGracePeriod`, `Cooldown`, `TerminationPolicies`, `NewInstancesProtectedFromScaleIn`, `CapacityRebalance`, `DesiredCapacityType`, `DefaultInstanceWarmup` or `DeletionProtection`, while cdkd reset each to a default (for example `HealthCheckType` back to `EC2`). cdkd now sends nothing for them, so the live value stays. `InstanceMaintenancePolicy`, `MaxInstanceLifetime`, `CapacityReservationSpecification` and `AvailabilityZoneDistribution` still reset, as CloudFormation does. Changed: `src/provisioning/providers/asg-provider.ts`, `docs/provider-rules.md`, `tests/unit/provisioning/asg-provider-update-removal.test.ts`, `tests/integration/launchtemplate-asg-inplace/verify.sh`.
