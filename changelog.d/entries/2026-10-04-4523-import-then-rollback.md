- **`cdkd rollback` no longer deletes a resource `cdkd import` adopted after the failed deploy (issue [#4523](https://github.com/go-to-k/cdkd/issues/4523))** -- `src/cli/commands/import.ts`, `src/state/s3-state-backend.ts`, `src/types/rollback-journal.ts`, `src/cli/commands/rollback.ts`, `src/deployment/nested-child-journal.ts`. The import did not touch the rollback journal. If a kept journal segment held a completed CREATE of an explicitly named resource, and the user then re-created that name by hand and imported it under the same logical id, the replay saw a physical id equal to the imported record's and deleted the resource the user had just adopted. Before it writes state, the import now records each adopted logical id in a new additive `importedLogicalIds` field on every segment that holds an operation for it, and marks the id superseded on the newest segment. `cdkd rollback` leaves those operations alone, including failed ones under `--revert-failed`, and lists them in its plan as `adopted by cdkd import after this deploy`. The nested-child replay does the same. Segments that later deploys add carry no mark and replay as before. The import now refuses, and writes no state, when it cannot read or write the journal.
