- **A Cloud Control update sends every declared property as the template declares it (issue [#6676](https://github.com/go-to-k/cdkd/issues/6676))**. Cloud Control applies an update patch on top of the model its read handler returns, so a property the patch did not touch reached the update API in the read handler's spelling, and a service that refuses that spelling failed every update that did not change the property (#4910, #6663 were two such types, each fixed alone). When an update changes anything, cdkd now also adds every other top-level property the template declares, with its declared value, as CloudFormation hands its update handler the template's model. Properties holding a create-only, read-only or write-only path keep their own handling, an unchanged secret-derived create-only value and a CodeDeploy-shifted alias `FunctionVersion` stay out, undeclared properties are never touched, and nothing is re-sent when the type's schema could not be read. No AWS call is added: the exclusions come from the `DescribeType` response the update already fetched.
