- **A plain `{{resolve:ssm:...}}` reference to a `SecureString` that AWS echoes under a property the template does not set is now stored masked on an unchanged resource too, and `cdkd scrub` drops a custom resource attribute whose name holds a secret an older version stored (issues [#7160](https://github.com/go-to-k/cdkd/issues/7160), [#7161](https://github.com/go-to-k/cdkd/issues/7161))** -- `src/deployment/secret-redaction/{off-template-echo,secret-attribute-keys,stored-record-finish}.ts`, `src/deployment/deploy-engine/state-persist.ts`, `src/cli/commands/scrub/stack-rewrite.ts`, `src/cli/commands/state/refresh-observed-stack.ts`. The echo masking (#7158) learned only from `ssm-secure` / `secretsmanager` references, so a plain `ssm` one to a `SecureString` (which CloudFormation refuses and cdkd resolves) stayed in plaintext under a template-absent key on a deploy that left the resource unchanged, inside a list or shared with a second reference. A plain `ssm` token still in a stored record now counts as secret, since a `String` parameter is stored resolved; a token `cdkd state refresh-observed` proves public at the value AWS holds teaches nothing. Orphan and superseded records now get the echo masking and the attribute-key drop on every deploy save and in `cdkd scrub`. An unchanged custom resource's key holding a secret is dropped by `cdkd scrub`, which resolves its references; a deploy that leaves it unchanged resolves none. Tests: `tests/unit/deployment/off-template-echo-7158.test.ts`, `tests/unit/cli/commands/scrub-secret-attribute-keys-7161.test.ts`, `tests/unit/cli/state-refresh-observed.test.ts`.
