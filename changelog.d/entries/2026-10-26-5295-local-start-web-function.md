- **`cdkd local start-web-function` serves an AWS Lambda Web Function locally (issue [#5295](https://github.com/go-to-k/cdkd/issues/5295))** -- `package.json` (cdk-local 0.155.0), `src/cli/commands/local-start-web-function.ts`, `local-invoke.ts`. The new subcommand resolves a `AWS::Lambda::WebFunction` / `WebFunctionEndpoint` / `WebFunctionRevision` target to one revision (an endpoint serves its highest-weight revision; `--revision` overrides), runs its code bundle from `cdk.out` in a Docker container whose server listens on `AWS_LAMBDA_HTTP_ENDPOINT`, and publishes it on a local port with the revision's `ServiceConfig` environment. It takes cdkd's `--from-state` / `--state-bucket` / `--state-prefix` alongside cdk-local's `--from-cfn-stack`, and under either a bare `--assume-role` assumes the revision's `ServiceConfig.ExecutionRoleArn` resolved from deployed state; `--no-assume-role` opts out. Guide: `docs/local-start-web-function.md`.
