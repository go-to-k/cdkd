- **A failed EventBridge Pipe, Glue trigger or crawler, or EMR instance group update now records what it had already started, so the next deploy converges it (issue [#5487](https://github.com/go-to-k/cdkd/issues/5487))** -- `src/provisioning/providers/{pipes,glue,emr-instance-group-config}-provider.ts`, `src/types/resource.ts`, `src/cli/commands/drift.ts`. Each property is now marked just before the call that changes it: `UpdatePipe` and its settle wait, `UpdateTrigger` / `UpdateCrawler`, `ModifyInstanceGroups` and its resize wait, the autoscaling policy, and tags. An update that fails part way therefore records the property as unsettled instead of leaving the old value in state, which a redeploy of that template diffed as unchanged. The next deploy's convergence step (#5496) compares each unsettled property with what AWS holds now, where the EMR group's value is its running count. While the pipe, trigger or group is still moving, the next deploy refuses to diff the property instead of clearing it; a pipe or group at rest in a failed state is updated again (UpdatePipe / the resize is re-sent), which is what recovers it. Unsettled tags re-send the template's tags and leave tags cdkd never recorded. `cdkd drift --accept` / `--revert` keep a property while the pipe is UPDATING, the trigger is ACTIVATING / DEACTIVATING, or the group is RESIZING. `ResourceProvider.unsettledInTransition` now also receives the record's properties.
