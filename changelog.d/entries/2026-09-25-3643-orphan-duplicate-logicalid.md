- **Two rollback-orphan records sharing a `logicalId` are now refused where a command can write, and dropped where it cannot (issue [#3643](https://github.com/go-to-k/cdkd/issues/3643))** -- `src/state/malformed-resources-bag.ts`, `src/cli/commands/diff-recursive.ts`. The row check #3500 added asked only that each record's `logicalId` be a string, so two healthy records carrying the same one (the empty string included) both passed and then collapsed: the rollback save merges `orphans` by `logicalId` and kept only the last, and the deploy's adoption pass adopted only one. The other record's resource stayed live in AWS with nothing tracking it. No cdkd command writes such a record, so it takes a hand edit or a damaged file. **Behavior change:** every record whose `logicalId` another record also carries is now treated like any other unusable record -- `cdkd deploy`, `cdkd destroy` (both reads), `cdkd rollback`, `cdkd import`, `cdkd orphan` and a real `cdkd scrub` refuse the record naming each of them (`STATE_RESOURCES_MALFORMED`); `cdkd scrub --dry-run` and `cdkd diff` drop them and warn by name, and `cdkd diff --fail` counts them. Repair by keeping one record per `logicalId`.
