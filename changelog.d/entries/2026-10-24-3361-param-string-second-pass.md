- **A failure value that cannot be converted to text no longer replaces the Cloud Map partial-create failure or the Lambda create failure** (`src/provisioning/providers/{servicediscovery,lambda-function}-provider.ts`, go-to-k/cdkd#3361). These helpers took the caught value as a PARAMETER, where the catch-scoped sweep did not look, and rendered it with `String()`, which throws for a null-prototype object. So a `TypeError: Cannot convert object to primitive value` replaced the ServiceAttributes failure a Cloud Map create rethrows when its cleanup `DeleteService` rejected with such a value, and replaced the Lambda create failure. `describeAwsFailure` (`src/utils/aws-failure-text.ts`) itself threw the same way for an AWS-authored error whose `name` cannot be converted, since its summary interpolated the `name`; it now renders a placeholder there. Converted as defence in depth, with no path known to hand them such a value today: ACM's in-use classifier (`delete()` always hands it an `Error`) and Cognito's echo-refusal predicate and "left on" warn, which read a failure's `name` (`src/provisioning/providers/{acm-certificate,cognito}-provider.ts`). Each now goes through `describeAwsFailure(x).detail` or `safeStringify(x)`, byte-identical for every value `String()` converts and a placeholder otherwise.
