- **A failure value that cannot be converted to text no longer replaces the Cloud Map partial-create failure or the Lambda create failure, nor drops the Cognito `--remove-protection` "left on" warn** (`src/provisioning/providers/{servicediscovery,lambda-function,cognito}-provider.ts`, go-to-k/cdkd#3361). These helpers took the caught value as a PARAMETER, where the catch-scoped sweep did not look, and rendered it with `String()`, which throws for a null-prototype object. So a `TypeError: Cannot convert object to primitive value` replaced the ServiceAttributes failure a Cloud Map create rethrows when its cleanup `DeleteService` rejected with such a value, replaced the Lambda create failure, and, when Cognito refused the settings echo with such a `name`, threw out of the best-effort flip so the warn naming why DeletionProtection stayed on was never printed; the Cognito MFA-configuration read and restore did the same with the failure's `name`, losing the read's fail-open answer and the restore warn. That `--remove-protection` warn now also masks the failure text it prints when AWS gave no answer, which is the raw message. `describeAwsFailure` (`src/utils/aws-failure-text.ts`) itself threw the same way for an AWS-authored error whose `name` cannot be converted, since its summary interpolated the `name`; it now renders a placeholder there (unchanged for a string `name`). ACM's in-use classifier (`src/provisioning/providers/acm-certificate-provider.ts`) is converted as defence in depth: `delete()` always hands it an `Error` today. Each now goes through `describeAwsFailure(x).detail` or `safeStringify(x)`, byte-identical for every value `String()` converts and a placeholder otherwise.
