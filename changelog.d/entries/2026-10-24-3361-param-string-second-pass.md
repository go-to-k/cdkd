- **A failure value that cannot be converted to text no longer replaces the Cloud Map partial-create failure, the Cognito remove-protection refusal or the Lambda create failure** (`src/provisioning/providers/{servicediscovery,cognito,lambda-function}-provider.ts`, go-to-k/cdkd#3361). These helpers took the caught value as a PARAMETER, where the catch-scoped sweep did not look, and rendered it with `String()`, which throws for a null-prototype object. So a `TypeError: Cannot convert object to primitive value` replaced the ServiceAttributes failure a Cloud Map create rethrows when its cleanup `DeleteService` rejected with such a value, replaced the delete's own refusal when Cognito's settings echo failed with such a `name`, and replaced the Lambda create failure. ACM's in-use classifier (`src/provisioning/providers/acm-certificate-provider.ts`) is converted as defence in depth: `delete()` hands it an `Error` today. Each now goes through `describeAwsFailure(x).detail` or `safeStringify(x)`, byte-identical for every value `String()` converts and a placeholder otherwise.
