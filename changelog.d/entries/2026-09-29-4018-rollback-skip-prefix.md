- **`cdkd rollback` re-creates a resource under the physical name its deploy used (issue [#4018](https://github.com/go-to-k/cdkd/issues/4018))** -- `src/cli/commands/rollback.ts`, `src/deployment/deploy-engine.ts`, `src/deployment/nested-child-journal.ts`, `src/types/rollback-journal.ts`, with unit tests in `tests/unit/cli/commands/rollback-skip-prefix-4018.test.ts` and a new `rollback-explicit-name-rewrite` integ. `cdkd deploy` derives the name of an explicitly named IAM Role / User / Group / InstanceProfile / ManagedPolicy or ELBv2 LoadBalancer / TargetGroup under its user-supplied-name prefix setting, but `cdkd rollback` replayed with no setting in scope, so it asked AWS for `<stack>-<name>` where the deploy had created `<name>`: a reverse-replacement restored the old resource under a name it never had, and an in-place revert of such a role or managed policy became a replacement. Each journal segment now records the setting (`skipPrefix`, additive, no `journalVersion` bump; a non-boolean is refused) and the rollback, including a nested child's revert, replays each segment under it. A segment written by an older cdkd falls back to `CDKD_PREFIX_USER_SUPPLIED_NAMES` / `cdk.json` / the default (no prefix) with a warning. Follow-ups: #4023 (`drift --revert` scope), #4024 (a flag flipped between deploys).
