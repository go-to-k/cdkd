- **A planted `rollback-journal.json` can no longer hand a provider a string where a property bag belongs, or flip the replacement arm with a non-boolean flag (issue [#3149](https://github.com/go-to-k/cdkd/issues/3149))** -- `src/types/rollback-journal.ts`. Issue [#3140](https://github.com/go-to-k/cdkd/issues/3140) refused an operation's own scalar fields; the NESTED records were still unchecked casts, so a `previousState` of `"x"` lost the whole desired bag — every arm coalescing with `?? {}` — and a patch provider applies that by removing every property; a `properties` of `"abc"` (on the operation or inside `previousState`) reached a provider verbatim, a non-string `previousState.physicalId` was rendered, compared AND written back into `state.json`, and `oldResourceRetained: "no"` selected the readopt arm through `??` -- skipping the re-create and re-pointing state at the old physical id. `parseRollbackJournal` refuses each, by index and TYPE with the value never echoed. The rule is **refuse what no handling can make correct, tolerate what the state boundary tolerates**: every check is TYPE-when-present, since `previousState` is forwarded verbatim from a state record `parseStateBody` deliberately does not validate, and `provisionedBy` is not refused at all -- an unrecognised value only routes to the SDK provider, so refusing it would lock `cdkd rollback` out of a journal cdkd itself wrote. The `state.json` half of the issue was refused against the placement decision `parseStateBody` records, and its remainder tracked as issues [#3018](https://github.com/go-to-k/cdkd/issues/3018) / [#3191](https://github.com/go-to-k/cdkd/issues/3191) / [#3211](https://github.com/go-to-k/cdkd/issues/3211); an absent `properties` still reaches an arm that coalesces it to an empty desired bag, which is [#3203](https://github.com/go-to-k/cdkd/issues/3203).
