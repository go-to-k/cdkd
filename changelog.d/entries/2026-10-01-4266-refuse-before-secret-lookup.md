- **A `secretsmanager` / `ssm-secure` reference whose name was assembled from a secret is refused before cdkd looks it up (issue [#4266](https://github.com/go-to-k/cdkd/issues/4266))** -- `src/deployment/intrinsic-function-resolver.ts`, `docs/troubleshooting.md`; cases in `tests/unit/deployment/intrinsic-resolver-secret-assembled-reference.test.ts`. The issue [#4166](https://github.com/go-to-k/cdkd/issues/4166) refusal ran only after the lookup returned a secret, so the Secrets Manager / SSM request had already carried the assembled id, with the other secret inside it, to AWS, where CloudTrail records it in `requestParameters`. Both services are secret by spelling, so the token is now refused before the lookup, on the template route only. A plain `ssm` reference is still looked up first, to learn its parameter type. **Behaviour change:** such a token whose lookup would have failed now reports the masked `Refusing to resolve` refusal instead of the lookup error, and one whose secret value is empty is refused too. Persisted text (`cdkd drift`, the rollback replay) and the diff comparison path are unchanged.
