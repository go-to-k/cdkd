- **Turning `autoDeleteObjects` off on a bucket with no other tags no longer fails the deploy (issue [#6422](https://github.com/go-to-k/cdkd/issues/6422))** -- `src/provisioning/providers/custom-resource/s3-auto-delete-untagged.ts`. That change removes the bucket's only tag and the `Custom::S3AutoDeleteObjects` resource together. CDK's handler then reads the bucket's tags, S3 answers `NoSuchTagSet` for a bucket with none, and the handler reported FAILED, so `cdkd deploy` exited 2 until a second deploy dropped the record. CloudFormation never hits this, because its buckets keep their `aws:cloudformation:*` tags. When this handler answers FAILED, for any reason, cdkd now reads the bucket's tags itself. The handler's failure text is never interpreted. If S3 confirms there are none, the bucket was not tagged for auto-delete and there was nothing to empty, so the delete is counted as done. The objects are kept either way. Every other FAILED Delete, from this type or any other, is still kept as unaddressed.
