- **`AWS::EC2::Instance` with `Affinity`, `HostId`, `HostResourceGroupArn`, `KernelId`, `RamdiskId` or `EnclaveOptions` now deploys on the SDK path (issue [#5630](https://github.com/go-to-k/cdkd/issues/5630))** -- `src/provisioning/providers/ec2/`, the replacement rules, the regenerated coverage map, unit tests and the `ec2-instance` integ fixture. Before this change, any of them sent the whole instance through Cloud Control; every writable `AWS::EC2::Instance` property is now wired. All six are sent on `RunInstances`. `EnclaveOptions` and `HostResourceGroupArn` are create-only, so a change replaces the instance, as in CloudFormation. `Affinity`, `HostId`, `KernelId` and `RamdiskId` change in place with a stop and a start (`ModifyInstancePlacement`, `ModifyInstanceAttribute`), which is CloudFormation's documented update behavior ("Some interruptions"); a value the instance already has costs no stop. Removing one of these four is refused before any AWS call: EC2 has no call that clears it, and CloudFormation does not document what a removal does. Only `EnclaveOptions` is verified against real AWS; the other five need a Dedicated Host or a paravirtual AMI and are unit-tested only. `cdkd drift` reads all six back. Resources already recorded as Cloud Control-provisioned stay on Cloud Control.
