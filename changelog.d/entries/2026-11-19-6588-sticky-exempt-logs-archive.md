- **An `AWS::Events::Archive`, `AWS::Logs::DeliverySource`, `AWS::Logs::DeliveryDestination` or `AWS::Logs::Delivery` recorded `provisionedBy: 'cc-api'` returns to its SDK provider (issue [#6588](https://github.com/go-to-k/cdkd/issues/6588))** -- `src/provisioning/provider-registry/sticky-exempt.ts` and the new `cc-to-sdk-reroute-common-types-12` integ. Before 0.357.0 these types had no SDK provider, so every such resource was created through Cloud Control, and its record kept it there on later deploys. The four types are now `'sdk-coverage'` members of `STICKY_CC_MIGRATION_EXEMPT`, so such a resource moves to the SDK provider in place on the next deploy that changes it; `--pin-cc-api <LogicalId>` declines that. Both layers record the same id for each (the archive name, the source name, the destination name, the AWS-minted delivery id), observed on live resources, so nothing is replaced. `cdkd diff` annotates the move `[returning to SDK provider]`. For an `AWS::Logs::Delivery` to a log group this also ends a failure: Cloud Control's update handler refuses every update of such a delivery, a tag-only change included ("Provided delivery configuration is invalid for the destination type", measured), so before this every deploy that changed one failed; with `--pin-cc-api` it still does.
