- **The Secrets Manager secret provider masks a secret-derived name in its own log lines and failures (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), Secrets Manager slice)** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`; unit tests in `tests/unit/provisioning/secretsmanager-secret-provider-masked-log.test.ts`. An `AWS::SecretsManager::Secret` whose `Name` was resolved from a `{{resolve:secretsmanager:...}}` reference used to print that name in plaintext inside the secret's ARN on the provider's own debug lines, which pass through no deploy-engine mask, and a name shorter than four characters also survived the engine's mask on a failure message. `create()` and `update()` now route every line that names the secret through the deploy's masker and the shared derived-name masks: the ARN renders as `***` at any name length, AWS error text is masked with the deploy's secrets first, and a secret name is then also masked where an AWS error quotes it back (a name of three or more characters anywhere, a shorter one where it is quoted inside an ARN). Where a recorded secret crosses or contains a name of four or more characters, or a shorter name quoted inside an ARN, the AWS error text is withheld as `***` rather than printed around it; a recorded secret crossing a bare three-character name can still leave up to two of its characters. On `update()` the recorded ARN is masked as well when the previous `Name` in state is a secret reference or the redaction mask `***`, which covers a rotated secret whose old plaintext is in no bag of this deploy. This covers message text only: the error's `physicalId` field and the engine's own lines still carry the raw name or ARN (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869)), and the `delete()` path still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
