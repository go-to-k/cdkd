- **The Secrets Manager secret provider masks a secret-derived name in its own log lines and failures (issue [#2177](https://github.com/go-to-k/cdkd/issues/2177), Secrets Manager slice)** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`; unit tests in `tests/unit/provisioning/secretsmanager-secret-provider-masked-log.test.ts`. An `AWS::SecretsManager::Secret` whose `Name` was resolved from a `{{resolve:secretsmanager:...}}` reference used to print that name in plaintext inside the secret's ARN on the provider's own debug lines, which pass through no deploy-engine mask, and a name shorter than four characters also survived the engine's mask on a failure message. `create()` and `update()` now route every line through the deploy's masker and mask the ARN and any AWS error text before it joins the sentence, so the ARN renders as `***` at any name length, and a secret name of three or more characters is masked where an AWS error quotes it back. On `update()` the recorded ARN is masked as well when the previous `Name` in state is a secret reference or the redaction mask `***`, which covers a rotated secret whose old plaintext is in no bag of this deploy. The `delete()` path still has no masker (issue [#2007](https://github.com/go-to-k/cdkd/issues/2007)).
