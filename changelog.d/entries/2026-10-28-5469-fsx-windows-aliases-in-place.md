- **An FSx for Windows `Aliases` change now applies in place instead of being refused (issue [#5469](https://github.com/go-to-k/cdkd/issues/5469))** -- `src/provisioning/providers/fsx-filesystem-provider.ts`. Adding, removing or dropping DNS aliases on an `AWS::FSx::FileSystem` `WindowsConfiguration` used to fail `cdkd deploy` with a `--replace` pointer, and replacing the file system loses its data. CloudFormation updates `Aliases` with no interruption. cdkd now diffs the names (case-insensitively, since FSx stores them lowercased), sends `DisassociateFileSystemAliases` and then `AssociateFileSystemAliases`, and waits until the aliases read back as declared. Removing the property disassociates every alias. `ActiveDirectoryId` and `PreferredSubnetId` stay refused: the CloudFormation reference lists them as "No interruption", but no FSx API changes either one.
