- **Refusals and warnings no longer quote an assembly-chosen stack name or logical id in quotes of cdkd's own (issue [#3617](https://github.com/go-to-k/cdkd/issues/3617))** -- `src/utils/display-safe.ts` (new `displayStackName`), plus the call sites in `src/synthesis/` (`assembly-reader`, `synthesizer`), `src/utils/nested-template-cycle.ts`, `src/provisioning/providers/nested-stack-provider.ts`, `src/assets/` (`asset-manifest-loader`, `docker-build`), `src/local/lambda-resolver.ts`, `src/state/export-index-store.ts` and `src/cli/commands/` (`orphan`, `emulator-docker-context`, `synth`, `local-invoke-agentcore`, `local-start-api`); an asset's free-form display name renders through `displayAssemblyPath` instead, so non-ASCII stays readable. A stack name, a nested-stack or Lambda logical id, an asset id, a region read back from the exports index, and a template-chosen parameter or attribute name were printed inside `'...'`, and the sanitizer passes `'`, so a crafted value could close the quote and write a clause of its own. `cdkd orphan`'s target line, confirmation prompt and success line also bound the stack name and region, which they printed with no boundary at all. Each now renders through `displayIdent`: a plain identifier bare (`Stack MyStack has no templateFile property`), anything else as one JSON string, with non-ASCII characters blanked. The sites in `src/cli/commands/import.ts`, `export.ts`, `scrub.ts` and `diff-recursive.ts`, and the same shape in other identifier families (macro parameter keys, S3 lifecycle rule ids, ECS container names), are the remainder, tracked on #3617.
