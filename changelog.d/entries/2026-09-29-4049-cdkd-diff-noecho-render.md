- **`cdkd diff` no longer prints a `NoEcho` template parameter's value (issue [#4049](https://github.com/go-to-k/cdkd/issues/4049))** -- `src/cli/commands/diff-recursive.ts`, and unit cases. Before, the diff resolved a `Ref` to a `NoEcho` parameter to its plaintext and printed it in a property row's `old:` / `new:` lines, in `--json`'s `propertyChanges` and `outputChanges`, in an Outputs row, and on `--verbose`'s `requires replacement (<old> -> <new>)` line and the resolver's debug lines. Each of these now shows `***`, as a CloudFormation change set shows `****`. The printed values are masked with a per-stack corpus made of three parts: every `NoEcho` parameter's value, what the diff resolver records while it resolves (for example an `Fn::Base64` of the value), and, for a nested child, the parent's corpus. The old side is withheld as `***` whenever the new side carries a masked value, because state keeps the previous value in the clear. An export row whose name embeds the value prints masked. A `NoEcho` parameter fed a SECRET `{{resolve:...}}` reference still prints as that expression, as every secret reference does in `cdkd diff`. The limits are listed in `docs/cli-diff.md`. The change is still reported, so `--fail` is unchanged, and nothing is written: `cdkd diff` persists nothing, and the state record it reads is left byte-identical. Tests: `tests/unit/cli/diff-noecho-render-4049.test.ts`.
