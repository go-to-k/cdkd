- **The malformed-state texts describe a logical id that is not a plain identifier instead of quoting it (issue [#4253](https://github.com/go-to-k/cdkd/issues/4253))** -- `src/state/malformed-resources-bag.ts`, `src/utils/pasteable-command.ts` (`ASSIGNMENT_WORD`); cases in `tests/unit/state/malformed-resources-bag.test.ts`. The texts for a torn `properties` map (the `cdkd deploy` refusal, the `cdkd diff` warning, the `cdkd orphan` refusal, the `cdkd drift` refusal and warning), for an unreadable resource entry (the `deploy`, `destroy`, `import`, `scrub`, `orphan`, `drift`, `state` and `cdkd local` texts and the `cdkd diff` warning), for a torn `attributes` map, and for unreadable `orphans` rows named each damaged record by its logical id in JSON quotes, on a message ending in a pasteable `cdkd state show` or `cdkd state orphan`. A logical id is a key of the state record, and JSON quotes still run a `$( )` or a backtick when that text is pasted into a shell, or when an unpaired `'` or `"` pasted above it flips the quoting. Such an id, a padded, cut, unrenderable or missing one, and one shaped like a shell assignment (`PATH=.`, `HISTFILE=x`, which pasted on its own changes the operator's shell), now prints as `(not shown: it is not a plain identifier)`, as the `cdkd export` text has since [#4245](https://github.com/go-to-k/cdkd/pull/4245); a plain id is still named. The `cdkd state show` command each text ends on shows the record's real keys.
