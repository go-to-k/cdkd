- **An ACM certificate validated by hosted zone (CDK `CertificateValidation.fromDns(zone)`) is created on a clean domain name, with its DNS validation record written, as CloudFormation does (issue [#5281](https://github.com/go-to-k/cdkd/issues/5281))** -- `src/provisioning/providers/acm-certificate-provider.ts`, `src/utils/aws-clients.ts`, `docs/troubleshooting-deploy.md`. The provider sent each `DomainValidationOptions` entry as `{ DomainName }` plus `ValidationDomain` when set; the ACM API requires both, so ACM answered `Value null at 'domainValidationOptions.1.member.validationDomain'` before any certificate existed. An entry without `ValidationDomain` is now left out, and `DomainValidationOptions` is sent only when some entry sets one. For DNS validation, the poll that first carries a domain's `ResourceRecord` now UPSERTs that CNAME (TTL 300) into the entry's `HostedZoneId`, once, so a first deploy no longer waits 10 minutes and retires the certificate. A refused write fails the create naming `route53:ChangeResourceRecordSets`. No call is added without a `HostedZoneId`, and delete leaves the record, as CloudFormation does (it is shared by every certificate for the domain). Adds a Route 53 client to `AwsClients`. Unit cases in `tests/unit/provisioning/acm-certificate-provider.test.ts`.
