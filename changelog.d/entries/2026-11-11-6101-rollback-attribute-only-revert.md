- **A rollback now reverts a deploy's `DeletionPolicy` / `UpdateReplacePolicy`-only changes (issue [#6101](https://github.com/go-to-k/cdkd/issues/6101))** -- `src/deployment/rollback-executor/plan/classify.ts`, `src/deployment/rollback-executor/replay-completed.ts`, `src/deployment/rollback-executor/types.ts`, `src/cli/commands/rollback/render.ts` and `src/cli/commands/rollback/preview.ts`, plus a new `rollback-attribute-only-revert` integ. Before, when a deploy changed only a resource's removal policy (for example `RemovalPolicy.RETAIN` to `DESTROY`) and another resource then failed, the automatic rollback and `cdkd rollback` treated that resource as already reverted. State kept the failed deploy's policies while cdkd reported the pre-deploy state restored, so a later `cdkd destroy` deleted a resource the last successful template retained, or left behind one it deleted. Like CloudFormation's rollback, which restores the previous template's policies, cdkd now writes the previous `DeletionPolicy` and `UpdateReplacePolicy` back into the record. It makes no AWS call, because the deploy made none for that change. The `cdkd rollback` plan lists such a resource as `revert ... [DeletionPolicy / UpdateReplacePolicy only, in state; no AWS call]`, and a second run skips it.
