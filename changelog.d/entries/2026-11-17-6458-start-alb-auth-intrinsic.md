- **`cdkd local start-alb` keeps an `authenticate-cognito` / `authenticate-oidc` guard whose config is an intrinsic, and resolves it from `--from-state` (issue [#6458](https://github.com/go-to-k/cdkd/issues/6458))** -- `package.json` (cdk-local `^0.168.8`, go-to-k/cdk-local#1005), `docs/local-start-alb.md`, `tests/unit/cli/local-start-alb-auth-from-state-6458.test.ts`, the `local-start-alb-cognito-from-state` integ fixture. `ListenerAction.authenticateCognito({ userPool, userPoolClient, ... })` writes the pool ARN as `Fn::GetAtt` and the client id as `Ref`. The guard was dropped with a warning, and the route was served to anyone. The pool ARN and client id now resolve from `--from-state` or `--from-cfn-stack`; under `--from-state` the client id is the bare id, not cdkd's `<poolId>|<clientId>` record. Without a state source the guard is kept with a warning: a request without a Bearer token gets `401`, and a token is admitted unverified. A listener rule that carries an authentication action and that cdkd cannot fully determine answers `503` instead of falling through to an unguarded rule.
