- **A rotated `NoEcho` parameter value feeding a create-only property replaces the resource again, where AWS is proven to report that property exactly (issue [#4656](https://github.com/go-to-k/cdkd/issues/4656))** -- `src/deployment/deploy-engine/{noecho,update,create,update-replace,update-in-place}.ts`, `src/types/state.ts`, `docs/state-management.md`. Since schema v11 (#4043) such a property was never replaced on a readback that differed: it warned on every deploy and named `--recreate-via-*`, because a provider that normalizes what it reports would read `differs` on an unchanged value. A record now carries `noEchoExactEchoLeaves` (optional, no schema bump): the coordinates at which a readback, handed the record with `***` there, reported exactly the string cdkd sent. It is set at the deploy that creates or replaces the resource, at the migration deploy of a pre-v11 record (against a copy with the stored plaintext pre-masked), and by any later readback that holds the value; a differing readback never changes it, and a failed or unreadable one leaves it absent. Only a whole string leaf under a create-only property, reached by object keys, is eligible. Where the flag is set and the readback reports a different string, the deploy replaces the resource through the existing create-first path and its stateful and named-collision guards; without the flag the warning now says the provider is not known to report the property exactly. Under `--require-approval=destructive` / `any-change` with an approver, which asked about a diff that showed no replacement, cdkd still does not replace and the warning says so. Tests: `tests/unit/deployment/deploy-engine-noecho-v11.test.ts`, `noecho-v11-nested-child.test.ts`, `tests/unit/cli/import-noecho-v11-field-carry.test.ts`; integ `schema-v10-to-v11-migration`.
