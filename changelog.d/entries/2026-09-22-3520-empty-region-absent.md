- **An empty stack name or region in a malformed-`resources` message is now treated as ABSENT rather than rendered as `<unrenderable>` (issue [#3520](https://github.com/go-to-k/cdkd/issues/3520), PR #3524)** -- `malformed-resources-bag.ts`. `safeStackName('')` and `safeRegion('')` both yield the `<unrenderable>` stand-in, so a builder handed `''` rendered `State for 'S' ('<unrenderable>')` in the clause and `--stack-region '<unrenderable>'` in the command it tells the reader to paste -- a flag that selects no record at all, in a message whose whole job is to send them to the damaged one. `undefined` was always handled correctly: the region clause and the flag are both dropped, which is right for a legacy `version: 1` record predating the region-prefixed key layout. **No caller can reach this today** -- `cdkd state`'s sites sit below an `if (!ref.region) throw`, a falsy test that rejects `''` too, and `cdkd export` normalises at its own call -- so this is a stated contract rather than a fixed output. **Behavior change:** every exported builder that accepts an optional identifier now normalises `'' -> undefined` once at its boundary, so `''` renders identically to `undefined`. Normalised at the boundary and not inside `stackClause` / `inspectCommand`, because `malformedOrphanResourcePropertiesRefusalMessage` already measured the per-helper fix as a half-fix: guarding one helper left the others rendering the placeholder. The fence is per builder for the same reason -- an aggregate case stays green for a fix applied to only some -- and the builder list is derived from the source, so one that later gains an optional identifier fails the derivation instead of joining the ungated side silently.
