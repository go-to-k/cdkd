- **A fix-forward deploy now deletes the IAM role an earlier failed CREATE left behind (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606), IAM role slice)** -- `src/provisioning/providers/iam-role-provider.ts`. When a `cdkd deploy --no-rollback` made an `AWS::IAM::Role`, failed wiring it (a managed policy, an inline policy or its tags) and could not delete it again, and a later deploy kept the logical id under another role name, the successful deploy warned about the earlier role, left it in AWS and exited 2; `cdkd rollback` and `cdkd destroy` kept it the same way. The IAM role provider now answers both questions: a role name is unique per account and cannot be changed, so the earlier role is a different one once the record's role reads back (a record holding the same name in another case holds that role, which is never deleted); and the failed CREATE records the `RoleId` its `CreateRole` returned, so the earlier role is deleted only while its name still reads back under that `RoleId`. A role deleted by hand and re-created under the name has another `RoleId` and is kept, with a warning. Tests: `tests/unit/provisioning/iam-role-provider-same-resource-4606.test.ts`; integ: `iam-role-fix-forward-orphan`.
