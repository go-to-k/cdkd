- **`cdkd diff` no longer tells the user that cdkd tried to heal a stale state record when its read-only re-read of the record fails (issue [#4163](https://github.com/go-to-k/cdkd/issues/4163))** -- `src/deployment/intrinsic-function-resolver.ts` (`staleRecordRemedy`), `src/deployment/stale-attribute-heal.ts` (`StaleAttributeHealer.readOnly`) and `src/deployment/read-only-attribute-healer.ts`, with cases in `tests/unit/deployment/stale-attribute-heal.test.ts`. Since [#3456](https://github.com/go-to-k/cdkd/issues/3456), `cdkd diff` re-reads a state record that lacks an attribute a `Fn::GetAtt` asks for, and a denied or missing read reached the deploy's remedy text: "cdkd tried to re-read the attributes from AWS to heal the record ... cdkd retries the read on every deploy until the record is healed". The diff heals nothing and writes nothing. Its healer is now marked `readOnly`, and the remedy reads "This preview re-read the attributes from AWS, but ...", then says that `cdkd deploy` issues the same read and records the attribute once the read returns it. That covers the warn line of a non-`*Arn` physical-id fallback and the refusal for an `*Arn` / `*Url` attribute. A `not-attempted` outcome in the preview no longer says the record "was written by this deploy". `cdkd deploy`'s wording is unchanged. Documented in `docs/troubleshooting.md`.
