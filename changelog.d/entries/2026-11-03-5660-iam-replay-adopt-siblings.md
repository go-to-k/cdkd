- **A create replay finishes the IAM user, group, instance profile or managed policy its own throttled attempt left behind (go-to-k/cdkd#5660)** -- `src/provisioning/providers/iam-replay-adopt.ts`, `iam-user-group-provider.ts`, `iam-instance-profile-provider.ts`, `iam-managed-policy-provider.ts`, `iam-role-provider.ts`. These four types failed `EntityAlreadyExists` as the role did before go-to-k/cdkd#5656. The replay now reads the entity and, when its `UserId` / `GroupId` / `InstanceProfileId` / `PolicyId` is the one that attempt's create returned, re-runs the wiring on it: a role the profile already holds is not added again, and a login profile the attempt left is set to the declared one. A same-named entity with another id is left untouched and the create fails as before, as does a later deploy, which holds no such proof. The role shares the new helper. Tested in `iam-replay-adopt-5660.test.ts`.
