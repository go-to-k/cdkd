- **`local invoke`, `local start-api` and `local invoke-agentcore` give the container the region cdkd resolved, on both credential paths (issue [#6200](https://github.com/go-to-k/cdkd/issues/6200))** -- `src/local/local-aws-wiring.ts` (`resolveContainerRegion`), `src/cli/region-options.ts`, `src/cli/commands/local-invoke/{command,credentials}.ts`, `src/cli/commands/local-start-api/container-spec.ts`, `src/cli/commands/local-invoke-agentcore/env.ts`, unit tests and docs. Before, with an environment-agnostic stack and the region only in `~/.aws/config` (no `--region`, `AWS_REGION` or `AWS_DEFAULT_REGION`), the container got no `AWS_REGION`, so the handler's first SDK call failed with `Region is missing`. The `--assume-role` path also ignored the stack's own region. Now both paths use one order: `--region`, `AWS_REGION`, `AWS_DEFAULT_REGION`, the stack's `env.region`, the loaded state record's region (`--from-state` / `--from-cfn-stack`), then the profile's `region` (the value `cdkd deploy` uses). The `--assume-role` STS call uses the same region. The profile is read only when nothing earlier answers. With no region anywhere, the container still gets none.
