- **`cdkd scrub` no longer reports a stack clean over a `{{resolve:...}}` reference an `Fn::Sub` placeholder left unresolvable (issue [#2166](https://github.com/go-to-k/cdkd/issues/2166))** -- `src/deployment/intrinsic-resolver/sub.ts`, `src/deployment/intrinsic-resolver/dynamic-refs.ts`, `src/deployment/intrinsic-resolver/context.ts`, `src/cli/commands/scrub.ts`. A leaf such as `Fn::Sub '{{resolve:secretsmanager:${Typo}-db:SecretString:password}}'`, where `Typo` names no resource or parameter of the template, keeps its `${Typo}` with a `keeping placeholder` warning, so the reference is never looked up and nothing throws. Scrub recorded nothing for it and printed `No plaintext secrets found`, and `--dry-run --fail` exited 0, over a record that could still hold the plaintext an older deploy wrote. `resolveSub` now remembers such a placeholder and the dynamic-reference pass reports it as a `placeholder` unit in the abandoned-resolution bag once the assembled string (that `Fn::Sub`, or an enclosing `Fn::Join` / `Fn::Sub`) puts it inside a reference; scrub counts it as an abandoned scan: the stack is not printed clean and `--fail` exits 1. Fix the template (declare or rename the variable, or escape it as `${!Typo}`) to clear it. Scrub also binds every parameter that has a `Default` when another parameter has none; it used to leave them all unbound, so a reference assembled from a defaulted parameter was never looked up and its plaintext never rewritten. A placeholder naming a `Default`-less parameter still only warns ([#4559](https://github.com/go-to-k/cdkd/issues/4559)); one naming a declared resource only warns by design. A deferred reference whose lookup FAILS was already counted the same way. `cdkd deploy` is unchanged, since it collects no abandoned units.
