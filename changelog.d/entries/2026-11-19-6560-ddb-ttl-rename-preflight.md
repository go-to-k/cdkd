- **A DynamoDB table update that renames its active TTL attribute is now refused before anything is changed (issue [#6560](https://github.com/go-to-k/cdkd/issues/6560))** -- `src/provisioning/providers/dynamodb-table/update-preflight.ts`, `update.ts`, `update-settings.ts`, `indexes.ts`, unit tests and the `dynamodb-ttl-attr-change` integ fixture. cdkd refused a `TimeToLiveSpecification.AttributeName` change between two enabled specs only after the same deploy's tag, billing, SSE, stream, GSI and point-in-time-recovery changes had gone out. With a `StreamViewType` change in the same deploy, the rollback reverted the view type, which gives the table a new stream, and the Lambda event source mapping reading it was left `Disabled` on the deleted stream. The refusal, with its message unchanged, now runs before the first AWS call of the update, as CloudFormation refuses the rename before touching the stream. The same now holds for a GSI change DynamoDB cannot apply in place (a same-name `KeySchema` / `Projection` change, or a new index without `KeySchema`), and the tag diff now runs after the `OnDemandThroughput`-under-PROVISIONED refusals.
