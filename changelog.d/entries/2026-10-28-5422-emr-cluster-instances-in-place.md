- **`AWS::EMR::Cluster`: the `Instances` changes CloudFormation applies to a running cluster are now applied in place (issue [#5422](https://github.com/go-to-k/cdkd/issues/5422))** -- `src/provisioning/providers/emr-cluster-provider.ts`, with unit tests in `tests/unit/provisioning/providers/emr-cluster-provider.test.ts`, wire cases in `tests/unit/provisioning/sdk-wire-cases-10.ts` and an in-place phase in the `emr-cluster` integ fixture. A change to a core or task instance group's `InstanceCount` or `AutoScalingPolicy`, a core or task instance fleet's `TargetOnDemandCapacity` / `TargetSpotCapacity`, or `UnhealthyNodeReplacement` failed the deploy, because the provider applied only `TerminationProtected`, while CloudFormation updates the running cluster. cdkd now resizes the group or fleet (`ModifyInstanceGroups` / `ModifyInstanceFleet`, waiting until it reaches the new size), puts or removes the auto-scaling policy, and calls `SetUnhealthyNodeReplacement`. A task group or fleet is found by its `Name` (a task group without one by its instance type), and an ambiguous match, or a `Name` (or that instance type) given as a secret reference, is refused before anything is changed. Removing `UnhealthyNodeReplacement` is refused, because CloudFormation fails that update too; declare it explicitly instead. A member whose only difference is its recorded `{{resolve:...}}` reference resolved no longer hides an in-place change made beside it.
