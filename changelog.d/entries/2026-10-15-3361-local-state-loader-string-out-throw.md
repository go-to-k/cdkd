- **A state read rejecting with a value that cannot be converted to text no longer defeats a `--from-state` fallback of `cdkd local`** (`src/cli/commands/local-state-loader.ts`, go-to-k/cdkd#3361). Six handlers that log a failed S3 read at debug and carry on built their message with `x instanceof Error ? x.message : String(x)`, and `String()` throws for a null-prototype object, so the handler itself threw: a failed state-bucket resolution or bootstrap-marker read failed `cdkd local run-task` instead of falling back to the conventional asset-repo names; a failed exports-index lookup skipped the per-stack scan, and one unreadable stack during that scan stopped it, so an `Fn::ImportValue` a later stack could answer was dropped from the env, and failed `cdkd local invoke-agentcore` when it named a `fromS3` code bucket; and a failed stack listing or `Fn::GetStackOutput` state read dropped its entry with the converter's `TypeError` as the reason. Each now goes through `describeAwsFailure(x).detail`, byte-identical whenever the value converts and a placeholder only when it cannot. Tests: `tests/unit/cli/local-state-loader-string-outthrow-3361.test.ts`.
