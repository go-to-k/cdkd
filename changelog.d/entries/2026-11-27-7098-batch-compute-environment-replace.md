- **A Batch compute environment now replaces on a `ComputeResources` change that needs an infrastructure update, unless the template sets `ReplaceComputeEnvironment: false` (issue [#7098](https://github.com/go-to-k/cdkd/issues/7098))** -- `src/analyzer/replacement-rules/batch-compute-environment.ts`, `src/analyzer/replacement-rules/rules.ts`. Before this, a change to `InstanceTypes`, `Type`, `LaunchTemplate`, `InstanceRole`, `Tags` or the other infrastructure members was sent as an in-place update, which Batch refuses (`NotUpdatable`) unless `ReplaceComputeEnvironment` is `false`, so `cdkd deploy` failed where CloudFormation replaces the environment. With `ReplaceComputeEnvironment: false` (the CDK L2 default) the change still updates in place, and `Subnets`, `SecurityGroupIds` and vCPU counts always do.
