- **`cdkd diff --recursive` now names the cycle when a nested template's asset path closes one, instead of failing ~190 levels later on an S3 key (issue [#3239](https://github.com/go-to-k/cdkd/issues/3239))** -- `src/cli/commands/diff-recursive.ts`, `docs/cli-diff.md`, `tests/unit/cli/diff-recursive.test.ts`. The TEMPLATE arm of the recursive walk located each nested child through its `Metadata['aws:asset:path']` with no visited set and no self-reference check: `indexNestedChildTemplates` refuses an ABSOLUTE path while a RELATIVE one was joined unconditionally. A path resolving back onto the same nesting chain therefore walked the cycle, appending one `~<childLogicalId>` segment to the nested state key per level, until the state read failed with `Your key is too long` against a ~190-segment stack name that does not exist -- roughly 190 pointless S3 reads, no diff printed, and an error naming neither the cycle nor the asset path. So that arm was always bounded, by the same 1024-byte key limit as the state-only arm; what it lacked was a diagnosis. `buildDiffTree` now threads the resolved absolute template paths of the ancestor chain down the walk and REFUSES a repeat, naming the logical id, the owning stack and the path that closed the cycle, and exits 1. It catches the first repeat, except for a cycle returning to the stack's own top-level template -- reached by name rather than by a nested asset path -- which is caught one level further down. A refusal rather than a depth cap, and an ancestor chain rather than a global visited set, so two sibling rows naming one template still diff and nesting depth is never limited; the reasoning for both is at the guard. All three interpolations in that refusal go through `displaySafe`, and so do the two in the sibling absolute-path refusal, since every one of those values comes from the hand-modified assembly those messages exist for.
