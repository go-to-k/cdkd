- **A resource its SDK provider created now updates through Cloud Control under the identifier Cloud Control addresses it by (issue [#6976](https://github.com/go-to-k/cdkd/issues/6976))** -- `src/provisioning/cc-identifier-from-sdk.ts`, `src/deployment/deploy-engine/update-in-place.ts`, `src/deployment/rollback-executor/replay-revert.ts`. A template that adds a property the SDK provider does not handle moves the resource to Cloud Control. For a type whose Cloud Control identifier joins several fields (`AWS::ApiGateway::Deployment`'s `<DeploymentId>|<RestApiId>`, `AWS::Glue::Table`'s `<CatalogId>|<DatabaseName>|<Name>`, an EMR instance fleet or group), cdkd sent the SDK provider's id, which is one of them, and the update failed. It now builds the identifier from the record's properties and attributes (field order from the type's registry schema), sends it, and records it; a rollback of that update addresses the resource the same way. A record that cannot supply the fields keeps the old id and the existing remedy. Tests: `tests/unit/provisioning/cc-identifier-from-sdk-6976.test.ts`, `tests/unit/deployment/deploy-engine-sdk-to-cc-identifier-6976.test.ts`, `tests/unit/deployment/rollback-revert-cc-identifier-6976.test.ts`; integ `sdk-to-cc-identifier`.
