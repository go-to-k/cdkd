- **An AWS call rejecting with a value that cannot be converted to text no longer turns a best-effort step of `cdkd import`, `cdkd state`, `cdkd orphan`, `cdkd gc` or `cdkd force-unlock` into a hard failure** (`src/cli/commands/{import,state,retire-cfn-stack,orphan,gc,force-unlock}.ts`, go-to-k/cdkd#3361). Handlers that log a failure and carry on built their message with `x instanceof Error ? x.message : String(x)`, and `String()` throws for a null-prototype object, so the handler itself threw: a failed lock release after a successful import, state orphan, refresh or `cdkd orphan` failed the command; one resource whose import or `readCurrentState` failed aborted every other resource; a failed template-parameter, condition or intrinsic resolution aborted the import it was degrading; a failed transient-template delete failed a `--migrate-from-cloudformation` retire after CloudFormation had succeeded, and a mid-walk nested-template failure lost the uploads it should have carried out for deletion; a failed `DescribeStackResources` lookup aborted the import instead of falling back to per-resource lookups; `cdkd gc`'s purge warning replaced its `GC_DELETE_FAILED` error, and its delete failure lost that code; and `cdkd force-unlock` stopped at the first such failure instead of attempting every remaining stack. Two throwing sites lost what they throw: the import's rollback-journal refusal and a retire's failed `UpdateStack` surfaced as the converter's `TypeError`. Each now goes through `describeAwsFailure(x).detail`, byte-identical for an `Error` and a placeholder otherwise. Tests: `tests/unit/cli/*-string-outthrow-3361.test.ts`.
