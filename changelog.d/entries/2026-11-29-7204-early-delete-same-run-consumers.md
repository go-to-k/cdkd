- **`cdkd deploy`: a producer no longer deletes an old copy early while a same-run consumer still uses it (issue [#7204](https://github.com/go-to-k/cdkd/issues/7204))** -- `src/deployment/deploy-engine/nested-cleanup.ts`, `src/deployment/deploy-engine/consumer-held-superseded.ts`, `src/deployment/deploy-engine/replacement/deferred-deletes.ts`, `src/deployment/deploy-engine/execute.ts`. A replaced resource's old copy that still uses a resource removed from the template is deleted before that removal (issue [#6977](https://github.com/go-to-k/cdkd/issues/6977)), but this ignored the cleanup hold for stacks of the same run that import the producer's outputs (issue [#7012](https://github.com/go-to-k/cdkd/issues/7012)). A consumer that then failed rolled back onto a deleted resource. When such a consumer's records name the old copy's physical id or a recorded attribute (or a record cannot be read), the old copy now waits for the held cleanup, and the removal it uses is kept for the next deploy (exit 2, issue [#6969](https://github.com/go-to-k/cdkd/issues/6969)). A producer with no same-run consumer reads nothing more. Tests: `tests/unit/deployment/deploy-engine-removed-after-deferred-users-6977.test.ts`.
