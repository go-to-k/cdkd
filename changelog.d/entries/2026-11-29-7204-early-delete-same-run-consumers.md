- **`cdkd deploy`: a producer (or its nested child) no longer deletes an old copy early while a same-run consumer may still use it (issue [#7204](https://github.com/go-to-k/cdkd/issues/7204))** -- `src/deployment/deploy-engine/nested-cleanup.ts`, `src/deployment/deploy-engine/consumer-held-superseded.ts`, `src/deployment/deploy-engine/replacement/deferred-deletes.ts`, `src/deployment/deploy-engine/execute.ts`, `src/deployment/deploy-engine/execute/removal-delete-kept.ts`, `src/deployment/deploy-engine/carried-users-of-removals.ts`, `src/cli/commands/deploy/{command,stack-deploy,consumer-cleanup-hold}.ts`. A replaced resource's old copy that still uses a resource removed from the template is deleted before that removal (issue [#6977](https://github.com/go-to-k/cdkd/issues/6977)), but this ignored the cleanup hold for stacks of the same run that import the producer's outputs (issue [#7012](https://github.com/go-to-k/cdkd/issues/7012)). A consumer that then failed rolled back onto a deleted resource. When such a consumer's records name the old copy's physical id or a recorded attribute (or a record cannot be read, or the old copy has no superseded record to check), the old copy now waits for the held cleanup (a nested child of such a producer asks the top-level stack's consumers), and each removed resource it uses is kept without its delete being sent, for the next deploy (exit 2, issue [#6969](https://github.com/go-to-k/cdkd/issues/6969)); before, that delete was sent and retried until AWS refused it. An old copy an earlier deploy kept for a consumer that still names it holds the removals it uses the same way. This run's old copies and unmarked kept rows are checked against the run's consumer stacks only; a kept row held for consumers (issue [#7017](https://github.com/go-to-k/cdkd/issues/7017)) is checked against every stack, as its cleanup check already reads. A deploy whose old copies use no removed resource reads nothing more.
