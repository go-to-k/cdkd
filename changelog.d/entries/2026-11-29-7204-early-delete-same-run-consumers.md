- **`cdkd deploy`: a producer (or its nested child) no longer deletes an old copy early while a same-run consumer may still use it (issue [#7204](https://github.com/go-to-k/cdkd/issues/7204))** -- `src/deployment/deploy-engine/{nested-cleanup,consumer-held-superseded,carried-users-of-removals,execute}.ts`, `src/deployment/deploy-engine/execute/removal-delete-kept.ts`, `src/deployment/deploy-engine/replacement/deferred-deletes.ts`, `src/cli/commands/deploy/{command,stack-deploy,consumer-cleanup-hold}.ts`. The early delete of an old copy that uses a removed resource (issue [#6977](https://github.com/go-to-k/cdkd/issues/6977)) ignored the hold for stacks of the same run importing the producer's outputs (issue [#7012](https://github.com/go-to-k/cdkd/issues/7012)), so a consumer that failed rolled back onto a deleted resource. When such a consumer's records name the old copy (or cannot be read, or the old copy has no state record to check), the old copy now waits for the held cleanup, and each removed resource it uses is kept without its delete being sent, for the next deploy (exit 2, issue [#6969](https://github.com/go-to-k/cdkd/issues/6969)); before, that delete was retried until AWS refused it. An old copy an earlier deploy kept is handled the same way. Only the run's consumer stacks are read, except for a kept row held for consumers (issue [#7017](https://github.com/go-to-k/cdkd/issues/7017)), which is checked against every stack as its cleanup already does; a deploy whose old copies use no removed resource reads nothing more. Tests: `tests/unit/deployment/{deploy-engine-removed-after-deferred-users-6977,consumer-held-superseded-7017,carried-users-of-removals-run-7076}.test.ts`, `tests/unit/cli/deploy-consumer-cleanup-hold-7012.test.ts`; integ `cross-stack-early-delete-consumer`.
