- **`cdkd local run-task` resolves an intrinsic element of a container's `Command`, `EntryPoint` or health-check command against deployed state, and refuses the run when one cannot be resolved (issue [#6271](https://github.com/go-to-k/cdkd/issues/6271))** -- `src/local/ecs-task-resolver/{container,cross-stack,needs,types}.ts`, `src/cli/commands/local-run-task/{command,image-context}.ts`, `src/utils/stringify.ts`, `docs/local-run-task.md`, `docs/local-emulation-value-resolution.md`. Each element was read as a plain string and a non-string one was dropped without a warning, even under `--from-state`, so a CDK `command: ['s3api', 'head-bucket', '--bucket', bucket.bucketName]` ran `--bucket` with no value. Each element is now substituted against the state source as `Environment` is (`Ref`, `Fn::GetAtt`, `Fn::Sub`, `Fn::Join`, pseudo parameters, and `Fn::ImportValue` / `Fn::GetStackOutput` through the cross-stack resolver), and an element alone now makes the run load state. An element that still does not resolve (no state flag, a resource missing from state, a producer output not deployed, a `{{resolve:...}}` reference, or a secret attribute such as `AWS::IAM::AccessKey`'s `SecretAccessKey`, which would land on the `docker run` command line) stops the run before any container starts, naming the container, the field and the element index. In AWS Emulator mixed mode an element follows the container's own routing. Tests: `tests/unit/local/ecs-task-resolver-command-intrinsics.test.ts`, `tests/unit/cli/local-run-task-mixed-mode-names.test.ts`, `tests/unit/cli/local-run-task-image-override.test.ts`, and the `local-run-task-from-state` integ fixture.
