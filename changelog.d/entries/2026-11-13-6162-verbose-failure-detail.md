- **A `--verbose` run no longer tells you to re-run with `--verbose`, and prints what a failed asset upload or stack actually carried (issue [#6162](https://github.com/go-to-k/cdkd/issues/6162))** -- `src/utils/aws-failure-text.ts`, `src/utils/logger.ts`, `src/deployment/work-graph.ts`, the pointer sites in `src/provisioning/providers/s3-bucket/create.ts`, `create-identity.ts`, `src/provisioning/dynamodb-index-busy-delete.ts` and `src/deployment/intrinsic-resolver/getatt-refusals.ts`, unit tests. Before, an AWS failure was summarized as `<Class>. Re-run with --verbose for AWS's own message.` even on a `--verbose` run, and for a response with an empty error body (AWS Emulator's `413` for an oversized `PutObject`) the only text anywhere was the SDK's placeholder `UnknownError`. On a `--verbose` run the pointer is now dropped, and every failed node logs a `Failure detail for <node>:` debug line with the HTTP status, error name, `Code`, message, fault side, request ids, attempts, response `content-length` and `cause` chain, ending with `AWS returned no error message` when the response carried none, or `No AWS response was received` for a failure before AWS answered (a socket `EPIPE`).
