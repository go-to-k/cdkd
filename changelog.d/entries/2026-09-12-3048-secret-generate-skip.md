- **A malformed `GenerateSecretString` no longer strands a secret un-rollbackable, nor poisons its state record (issue [#3048](https://github.com/go-to-k/cdkd/issues/3048))** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`, `tests/unit/provisioning/secretsmanager-secret-provider-update-value-source.test.ts`. **Bug:** `changedSecretValue` passed the container straight to `generateSecretString`, which reads `ExcludeCharacters` through `readConfigString` -- so once [#3032](https://github.com/go-to-k/cdkd/issues/3032) widened that guard to the unresolved-intrinsic shape, a malformed container THREW on the update path, which `cdkd drift --revert` and the rollback executor's revert arms reach with a cdkd STATE record the user cannot edit (the #1544 hazard). **Fix:** the value is SKIPPED (`UpdateSecret` goes out with no `SecretString`, so AWS's merge semantics keep the live value) **and the previously-applied block is RETAINED in the recorded bag** via `effectiveProperties`. The second half is load-bearing: recording the malformed desired bag would overwrite the usable one, the next deploy would compare equal, take the `unchanged` early return, and leave the secret un-regenerated with NO warning -- a loud repeating failure turned silent, and a record the reverse-replacement replay-create then refuses. The previous side runs the SAME predicate the wire does, and the key is DROPPED when it is absent or itself unusable. **Deliberately NOT an `onUnusable` downgrade**, because proceeding is the harm: a malformed container indexes every member to `undefined`, minting a bare default-charset password and returning it RAW instead of the declared JSON document -- as the new `AWSCURRENT`. **`create()` keeps REFUSING** (no live secret to fall back to), the guard being scoped to `changedSecretValue`; a test reds if it leaks. The container gate is now `!= null` rather than truthy, so a falsy malformed block no longer falls through to the literal read in silence.
