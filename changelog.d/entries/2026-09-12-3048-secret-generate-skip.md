- **A malformed `GenerateSecretString` no longer strands a secret un-rollbackable (issue [#3048](https://github.com/go-to-k/cdkd/issues/3048))** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`, `tests/unit/provisioning/secretsmanager-secret-provider-update-value-source.test.ts`. **Bug:** `changedSecretValue` passed the `GenerateSecretString` container straight to `generateSecretString`, which reads `ExcludeCharacters` through `readConfigString` -- so once [#3032](https://github.com/go-to-k/cdkd/issues/3032) widened that guard to the unresolved-intrinsic shape, a malformed container THREW on the update path. `update()` is reached by the rollback executor's revert arms and by `cdkd drift --revert` with a cdkd STATE record as the desired bag, which the user cannot edit from the template -- so such a record could not be rolled back (the #1544 hazard). **Fix:** the value is SKIPPED -- `changedSecretValue` returns `undefined`, the `UpdateSecret` goes out without a `SecretString`, and AWS's merge semantics leave the live value untouched. **Deliberately NOT an `onUnusable` downgrade**, because at this site PROCEEDING is the harm: `generateSecretString` reads every member off the container, so a malformed one indexes them all to `undefined`, mints a bare default-charset password and -- with `GenerateStringKey` / `SecretStringTemplate` gone too -- returns it RAW instead of the JSON document the template declared. That value would become the new `AWSCURRENT`, breaking every consumer reading `{"username":...}`. **The guard is scoped to `changedSecretValue`, never the shared helper:** `create()` calls `generateSecretString` too and has no live secret to fall back to, so it must keep refusing -- a test pins that split and reds if the skip leaks into create. A second test tells a SKIPPED value from an UNCHANGED one by its warning: both return `undefined` and send no `SecretString`, so a regression that always skips would otherwise look correct on the wire.
