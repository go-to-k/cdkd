- **A malformed `GenerateSecretString` no longer strands a secret un-rollbackable, nor poisons its state record (issue [#3048](https://github.com/go-to-k/cdkd/issues/3048))** -- `src/provisioning/providers/secretsmanager-secret-provider.ts`, `tests/unit/provisioning/secretsmanager-secret-provider-update-value-source.test.ts`. **Bug:** `changedSecretValue` passed the container straight to `generateSecretString`, which reads `ExcludeCharacters` through `readConfigString` -- so once [#3032](https://github.com/go-to-k/cdkd/issues/3032) widened that guard to the unresolved-intrinsic shape, a malformed container THREW on the update path, which the rollback executor's revert arms reach with a cdkd STATE record the user cannot edit (the #1544 hazard; `drift --revert` never hands this key over). **Fix:** the value is SKIPPED (`UpdateSecret` goes out with no `SecretString`, so AWS's merge semantics keep the live value) **and the previously-applied block is RETAINED in the recorded bag** via `effectiveProperties`. The second half is load-bearing: recording the malformed desired bag would overwrite the usable one, the next deploy would compare equal, take the `unchanged` early return, and leave the secret un-regenerated with NO warning. The previous side runs the SAME predicate the wire does; when it is absent or itself unusable the key is DROPPED, and the drop is WARNED, since a record with no value source later reaches the replay-create. **Deliberately NOT an `onUnusable` downgrade**, because proceeding is the harm: a malformed container indexes every member to `undefined`, minting a bare default-charset password, returned RAW as the new `AWSCURRENT`. **`create()` keeps REFUSING** (no live secret to fall back to), now through the same `requireConfigObject` guard, and WARNS when the bag carries no value source at all (a secret with no version). Both container gates are `!= null` rather than truthy (a falsy malformed block no longer falls through to the literal read).
