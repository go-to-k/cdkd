- **Renaming an IAM role, user or group inline policy only in case no longer deletes it (issue [#6874](https://github.com/go-to-k/cdkd/issues/6874))** -- `src/provisioning/providers/iam-role/update.ts`, `src/provisioning/providers/iam-user-group/group.ts`, `src/provisioning/providers/iam-user-group/user-update.ts`, `src/provisioning/providers/iam-role-provider.ts`, `tests/unit/provisioning/iam-inline-policy-case-rename-6874.test.ts`, `tests/integration/iam-role-policies-drift-clean/`. IAM holds one inline policy per name ignoring case. A template that respelled one only in case (`CasePol` to `casepol`) made cdkd put the new spelling, which replaced the document, and then delete the old spelling, which removed the policy; the deploy reported success. cdkd now deletes the old spelling first and then puts the new one, as CloudFormation does, so the policy is held under the new spelling with the new document; a rollback does the same in the other direction. `cdkd drift` also recognizes a sibling `AWS::IAM::Policy`'s inline policy whatever the case of its name or of the principal it names, so `drift --revert` does not remove it from the principal.
