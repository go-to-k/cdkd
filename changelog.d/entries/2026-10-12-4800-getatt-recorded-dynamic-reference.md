- **A reader of a resource named from a secret is no longer sent the unresolved `{{resolve:...}}` spelling when that resource is unchanged (issue [#4800](https://github.com/go-to-k/cdkd/issues/4800))** -- `src/deployment/intrinsic-resolver/getatt.ts` (`reresolveRecordedReferences`), `refs.ts`. State stores a secret-derived attribute with the secret's expression in place of its value, so an SQS queue named from a secret records its `Arn` as `arn:aws:sqs:...:{{resolve:secretsmanager:...}}`. A deploy that left the queue unchanged served that record to a reader's `Fn::GetAtt Queue.Arn` and sent the spelling to AWS: an `AWS::SSM::Parameter` refused it and the deploy rolled back, while an `AWS::SQS::QueuePolicy` accepted it and its `Resource` matched nothing. A value an `Fn::GetAtt` or `Ref` serves from a stored record's attributes now resolves the references it carries first, when the resource's own template spells each one literally and reads no other stack's value anywhere in its properties, and when the resource's physical id holds the value each resolves to. Otherwise it is served as stored: a name assembled by an intrinsic or read from another stack (issue [#4805](https://github.com/go-to-k/cdkd/issues/4805)), and, with a warning, any value the physical id does not hold: a secret rotated since the resource was deployed (it still carries the old name), but also a value that is not part of the name (a custom resource's `Data`, an `AWS::S3Tables::Table` `TableName` on the Cloud Control route) and a name shorter than four characters. The reader's record stores the expression back. A reader that stored the plaintext ARN after an update of the queue is updated once more, with the resolved ARN; that extra update is issue [#4802](https://github.com/go-to-k/cdkd/issues/4802).
