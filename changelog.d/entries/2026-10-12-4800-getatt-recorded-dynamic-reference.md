- **A reader of a resource named from a secret is no longer sent the unresolved `{{resolve:...}}` spelling when that resource is unchanged (issue [#4800](https://github.com/go-to-k/cdkd/issues/4800))** -- `src/deployment/intrinsic-resolver/getatt.ts` (`reresolveRecordedReferences`), `getatt-construct-app.ts`, `getatt-construct-core.ts`, `refs.ts`. State stores a secret-derived attribute with the secret's expression in place of its value, so an SQS queue named from a secret records its `Arn` as `arn:aws:sqs:...:{{resolve:secretsmanager:...}}`. A deploy that left the queue unchanged served that record to a reader's `Fn::GetAtt Queue.Arn` and sent the spelling to AWS: an `AWS::SSM::Parameter` refused it and the deploy rolled back, while an `AWS::SQS::QueuePolicy` accepted it and its `Resource` matched nothing. Every value an `Fn::GetAtt` or `Ref` serves from a stored record (a flat or nested attribute, an Events rule `Arn` built around its `EventBusName`, a VPC `CidrBlock`, an `AWS::S3Tables::Table` `TableName`) now resolves the references it carries first, when the resource's own template spells each one literally, and the reader's record stores the expression back. A name assembled by an intrinsic or read from another stack is still served as stored (issue [#4805](https://github.com/go-to-k/cdkd/issues/4805)): its region is not proven. A reader that stored the plaintext ARN after an update of the queue is updated once more, with the resolved ARN, and then stays unchanged; that extra update after each update of the queue is issue [#4802](https://github.com/go-to-k/cdkd/issues/4802).
