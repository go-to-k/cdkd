- **`cdkd local start-service` / `start-alb` / `start-web-function` / `start-microvm` / `start-cloudfront` / `start-agentcore` under `--aws-emulator` run a region-pinned stack in its own region, and a cross-stack reference nested in `Fn::Join` / `Fn::Sub` resolves under `local invoke` and `local run-task` (issue [#6270](https://github.com/go-to-k/cdkd/issues/6270))** -- `package.json` (`cdk-local` `^0.167.0` -> `^0.167.1`, with go-to-k/cdk-local#964 and #965), `src/utils/emulator-default-region.ts`, `src/cli/aws-emulator.ts`, `src/local/ecs-task-resolver/{needs,container,cross-stack}.ts`, `src/cli/commands/local-invoke/template-env.ts`, `docs/aws-emulator.md`, `docs/local-run-task.md`. The emulator run's region that `--aws-emulator` copies into `AWS_REGION` is now recorded as cdk-local's ambient default region, so the engine commands rank it below the stack's `env.region` and the state record's region, as the cdkd-owned commands already did; cdkd keeps no second copy of that record. The checks that decide whether to build the cross-stack resolver now find an `Fn::ImportValue` / `Fn::GetStackOutput` at any depth, so `s3://${otherStack.bucket.bucketName}` in a Lambda's or a container's `Environment`, or in a container's `Command` / `EntryPoint` / health-check command, resolves (before: dropped with a warning, or the run refused). **Behavior change:** a `Command` / `EntryPoint` / health-check element whose cross-stack value is recorded as the secret mask (`***`) is refused instead of running the command with `***`; one that combines a cross-stack reference with a secret attribute of the consumer stack stays refused. Tests: `tests/unit/cli/emulator-ambient-region-engine-6270.test.ts`, `tests/unit/local/ecs-task-resolver-command-intrinsics.test.ts`, `tests/unit/cli/local-invoke-cross-stack.test.ts`.
