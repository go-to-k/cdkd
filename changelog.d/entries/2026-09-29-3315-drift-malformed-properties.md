- **`cdkd drift` no longer reports a resource with an unreadable `properties` map as clean, and `--accept` / `--revert` refuse it (issue [#3315](https://github.com/go-to-k/cdkd/issues/3315))** -- `src/cli/commands/drift.ts` and `src/state/malformed-resources-bag.ts`, with unit tests in `tests/unit/cli/drift.test.ts` and `tests/unit/state/malformed-resources-bag.test.ts`. A resource record whose `properties` map was absent, `null`, a string, a number, a boolean or a list was read as-is: a string became one drifted key per character, and any other shape compared nothing and reported the resource clean at exit 0. Plain `cdkd drift` now warns naming those records, leaves them out of the comparison and reports each as not compared with the cause `unreadableRecord`, so the run exits 2 (or 1 when something else drifted). `--accept` and `--revert` refuse the record before any readback, lock or write, naming the records and ending on the `cdkd state show` command to inspect it. `cdkd export`'s half of the issue is not covered here.
