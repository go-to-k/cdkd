- **`Fn::GetAtt` of an identity id CloudFormation does not expose is refused (issue [#6655](https://github.com/go-to-k/cdkd/issues/6655))**. cdkd records an AWS-minted id per resource for its own delete and rollback identity checks, and `Fn::GetAtt` served it from that record: `Fn::GetAtt [MyTable, TableId]` deployed under cdkd although CloudFormation rejects the template (`AWS::DynamoDB::Table` exposes only `Arn` and `StreamArn`), with or without `--strict-getatt`, and a record without the id fell through to the physical id. **A template that relied on this now fails like CloudFormation**: the deploy refuses, non-retryable, with `CloudFormation does not expose TableId as an attribute of this type`; read an attribute the type exposes, or use `Ref`. The same holds for each recorded id the type does not expose (`UserId`, `GroupId` and `InstanceProfileId` once recorded). Ids CloudFormation does expose (`RoleId`, `PolicyId`, `DbiResourceId`, `DBClusterResourceId`) and every other recorded attribute resolve as before. Files: `src/deployment/intrinsic-resolver/{getatt,getatt-refusals}.ts`.
