- **An AppSync, Auto Scaling, ELBv2 load balancer or IAM managed policy whose immutable value comes from a secret is updated in place again (issue [#4275](https://github.com/go-to-k/cdkd/issues/4275))** -- `src/provisioning/providers/{appsync,asg,elbv2,iam-managed-policy}-provider.ts`. State keeps a secret-derived value as its `{{resolve:...}}` reference while `update()` receives the resolved value, so the GraphQLApi `Name`, DataSource `ApiId` / `Name`, Resolver `ApiId` / `TypeName` / `FieldName`, ApiKey `ApiId`, AutoScalingGroup `AutoScalingGroupName` and LoadBalancer `Name` / `Type` / `Scheme` guards refused every in-place update, and a managed policy with a secret-derived `Path` or `Description` was REPLACED on every update (a create under the same name and path, which IAM refuses). Each guard now uses `unchangedBehindSecretReference`: the value the physical id carries (group name, load balancer ARN, policy ARN path, AppSync composite id), the GraphQL API's live name from `GetGraphqlApi` (a failed lookup refuses as a retryable `ProvisioningError`), or, for `Type` / `Scheme` / `Description`, the masker arm on a create-only key. A real rename and a rotated secret are still refused. The ASG updating line and the AppSync child ARN-rebuild warning mask the name. Tests: `tests/unit/provisioning/secret-reference-immutable-sites-appsync-asg-elbv2-iam.test.ts`; integ: `secret-derived-immutable-names`.
