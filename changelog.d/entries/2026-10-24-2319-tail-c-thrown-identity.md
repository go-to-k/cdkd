- **A failed EC2 networking resource or instance, DynamoDB table, Auto Scaling group or Cognito user pool now masks the run's secrets in the error class and in the debug text, and no longer prints the caller's assumed-role ARN in a cleanup warning (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/{ec2,dynamodb-table,asg,cognito}-provider.ts` unit cases. These wraps already named an AWS failure by its class in the persisted deployment events. The class now goes through the operation's secret masker, and so do the EC2 debug line and an EC2 transport error's text. A failed partial-create cleanup (a VPC, subnet, security group, Elastic IP, instance or DynamoDB table left behind), an EC2 tag write, a NAT gateway delete wait and the `--no-wait` instance-profile backfill now warn with the error class and keep AWS's text for the debug log. A delete failure whose class is another resource's not-found (for example `KMSNotFoundException`) no longer reads as "already deleted", so the state record is kept. An "already exists" from an EC2 or DynamoDB table post-create step is no longer restated as this resource's name collision. A non-`Error` value thrown at a DynamoDB table wrap is withheld, as at the other wraps.
