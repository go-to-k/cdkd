- **Re-spelling a Lambda `EventInvokeConfig`'s `FunctionName` as the same function (a name ↔ ARN change) no longer deletes the async-invoke configuration** (`src/analyzer/replacement-rules.ts`, go-to-k/cdkd#4118). `FunctionName` was an unconditional replacement property. For a re-spelling, the create-first half wrote the config onto the function, and the old half's delete then removed it from the same function: the deploy succeeded, and the function was left with no failure destination and default retries. `FunctionName` now replaces only when the function NAME changes. A full ARN or a partial ARN (`<account>:function:<name>`) of the same name is an in-place update through `PutFunctionEventInvokeConfig`. A qualified ARN and an unresolved value still replace, and `Qualifier` still always does. Tests: `tests/unit/analyzer/replacement-rules-lambda-event-invoke-config.test.ts`; integ `lambda-event-invoke-config-update` phase 2b.
