- **`cdkd destroy`: a stack recorded in a region other than the CLI's deletes its Cloud Control-routed resources again (issue [#5115](https://github.com/go-to-k/cdkd/issues/5115))** -- `src/cli/commands/destroy-runner.ts`. Since #4941 the cross-region destroy built its provider registry before entering the stack's AWS scope, and the registry's constructor builds its Cloud Control and custom-resource fallbacks there, so both captured the CLI region's clients. Every Cloud Control-routed resource (e.g. `AWS::ApiGateway::RestApi`) was then refused with `AWS client region us-east-1 does not match stack state region ...` and the stack was left half-destroyed (the refusal touched nothing in the wrong region). The registry is now built inside the scope, as deploy, diff, drift, rollback and orphan already do. Workaround on older versions: run destroy with `AWS_REGION=<stack region>`. Tests: `tests/unit/cli/destroy-nested-cross-region-scope-4941.test.ts`.
