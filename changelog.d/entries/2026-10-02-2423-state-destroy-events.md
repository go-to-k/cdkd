- **`cdkd state destroy` now records deployment events (issue [#2423](https://github.com/go-to-k/cdkd/issues/2423))** -- `src/cli/commands/state.ts`, `src/cli/commands/destroy-runner.ts`. `cdkd state destroy` ran the same destroy as `cdkd destroy` but opened no event recorder, so it wrote no `deployments/{runId}.jsonl` at all: its per-resource deletes, skips and suppressed safety checks left nothing for `cdkd events` to read once the run ended. It now records one run per destroyed stack and region, under `command: destroy`, with the same `RUN_FINISHED` result and counts `cdkd destroy` records (`FAILED` on a resource error or skip). `cdkd state destroy` still takes no `--purge-events`; `cdkd events prune '<stack>' --all` drops the history. The warning for an incomplete safety check now names only the nested-stack child destroy as recording nothing. Tests: `tests/unit/cli/state-destroy.test.ts`, `tests/unit/cli/destroy-runner-guard-indeterminate.test.ts`; integ `s3-lifecycle` phase 0c-OK.
