- **Less noise under `--aws-emulator`, and a bad option value is now a one-line usage error (issues [#6248](https://github.com/go-to-k/cdkd/issues/6248), [#6249](https://github.com/go-to-k/cdkd/issues/6249), [#6251](https://github.com/go-to-k/cdkd/issues/6251))**. Changed: `src/local/docker-runner.ts`, `src/provisioning/describe-type.ts`, `src/provisioning/create-only-properties.ts`, `src/provisioning/write-only-properties.ts`, `src/cli/arg-parser.ts` (new) and the option registrations that use it, and unit tests.
  - A local `s3deploy.BucketDeployment` run no longer warns `Env var(s) "AWS_CA_BUNDLE" ... Rename the env var`. CDK sets that variable on the handler, and under `--aws-emulator` cdkd replaces its value with the emulator's CA anyway. The container now gets `AWS_CA_BUNDLE` pointing at the emulator CA. A sensitive variable whose value cdkd does not replace still draws the warning.
  - `cdkd diff` / `deploy` under `--aws-emulator` no longer print one `Grant cloudformation:DescribeType` warning per resource type the emulator's registry lacks. A `TypeNotFoundException` from the emulator now prints one info line per run, and `--verbose` names each type. The fallbacks are unchanged. Against real AWS the warning is unchanged.
  - An invalid `--older-than` (`gc`), `--resource-timeout`, `--resource-warn-after`, `--keep` (`events prune`), `--timeout` (`local invoke-agentcore`), `--assume-role` (`local start-api`) or provisioning-route flag value printed `Fatal error:` with a stack trace. It now prints `error: option '...' argument '...' is invalid. ...` and exits 1. A value that contains a control character prints only cdkd's sanitised `error: ...` line, so the raw value is never echoed.
  - `--concurrency`, `--stack-concurrency`, `--asset-publish-concurrency` and `--image-build-concurrency` now require a positive integer. Before, a value such as `bogus` became `NaN` and a `deploy --dry-run` accepted it.
