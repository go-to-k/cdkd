- **`Fn::GetAtt` on an `AWS::EC2::Subnet` reads its return values live instead of answering the subnet ID (issue [#5944](https://github.com/go-to-k/cdkd/issues/5944))** -- `src/deployment/intrinsic-resolver/getatt-construct-compute.ts`, `src/deployment/intrinsic-resolver/getatt.ts`, `src/analyzer/orphan-rewriter/recorded-attributes.ts`. Before, every Subnet attribute but `SubnetId` that the state record lacked (`Ipv6CidrBlocks`, `NetworkAclAssociationId`, `BlockPublicAccessStates`, `OutpostArn`, and on records written before they were recorded `VpcId`, `CidrBlock`, `AvailabilityZoneId`) resolved to the subnet ID with an "Unknown attribute" warning, or was refused under `--strict-getatt`, so a template reading a subnet's allocated IPv6 block got `subnet-...` under a green deploy. These now come from `DescribeSubnets` (and `DescribeNetworkAcls` for `NetworkAclAssociationId`). `Ipv6CidrBlocks`, `NetworkAclAssociationId` and `BlockPublicAccessStates` are read live even when the record holds a value, since an in-place update changes them and records nothing; `Ipv6CidrBlocks` waits up to about 30 s for an associating block, like the VPC's. A value AWS does not report (an `OutpostArn` off an Outpost, a `CidrBlock` on an IPv6-only subnet) or a failed read is refused rather than replaced. `cdkd orphan` likewise takes the live answer, not a record's stale copy, for those three when it rewrites a dependent's `Fn::GetAtt`. Tests: `tests/unit/deployment/getatt-subnet-ipv6-5944.test.ts`, `tests/unit/analyzer/orphan-rewriter.test.ts`; integ: `ec2-subnet-dns64`.
