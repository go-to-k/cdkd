- **`resolveDockerContextDirectory` takes EVERY parameter in its options bag, so swapping the assembly-derived base with the attacker-chosen directory no longer compiles** (issue [#3544](https://github.com/go-to-k/cdkd/issues/3544), PR #3547) -- No user-visible change. `src/assets/docker-build.ts`, `src/local/invoke-agentcore-watch-loop.ts`. `resolveDockerContextDirectory` now takes every parameter in its options bag, not only the trailing ones go-to-k/cdkd#3537 moved. It had a SECOND transposable pair and that one was not cosmetic: `manifestDir` is the assembly-derived base a relative value resolves FROM, `directory` is the attacker-chosen `source.directory`, and both are `string`, so swapping them compiled and changed which directory was resolved and which was contained -- where go-to-k/cdkd#3537's pair only changed a word in a warning. `buildDockerImage`'s local `contextDirectory` closure takes a bag for the same reason (`(directory, sink)` were also two adjacent strings). `resolveFileAssetSourcePath` keeps its leading positionals deliberately: its second parameter is a `FileAsset`, so the swap does not typecheck, and the invariant is "no transposable adjacent same-typed pair" rather than "both twins look alike".
