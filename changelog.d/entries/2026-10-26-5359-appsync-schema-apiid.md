- **AppSync updates now match CloudFormation for a GraphQLSchema `ApiId`, a GraphQLApi `Name` and a DataSource `Type` (issue [#5359](https://github.com/go-to-k/cdkd/issues/5359))** -- `src/provisioning/providers/appsync-provider.ts`. A GraphQLSchema whose `ApiId` changed while its definition did not was reported as updated, yet the schema stayed on the old API; the change is now refused, as CloudFormation fails it, and the message points to `--replace` or a new logical ID. Renaming a GraphQLApi and changing a DataSource's `Type` used to be refused; both are now updated in place, keeping the API id and the data source, as CloudFormation does. A GraphQLApi `Name` read from a secret is renamed only when the template's reference changes, so a rotated secret no longer renames the API on an unrelated update.
