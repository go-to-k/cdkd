- **`Fn::GetAtt [<RDS DB cluster or DB instance>, MasterUserSecret.SecretArn]` now resolves, as under CloudFormation, so a CDK `DatabaseCluster` / `DatabaseInstance` with `manageMasterUserPassword: true` can pass its `secret` on (issue [#6913](https://github.com/go-to-k/cdkd/issues/6913))** -- `src/provisioning/providers/rds/cluster-attributes.ts`, `src/provisioning/providers/rds/instance-attributes.ts`, `src/deployment/intrinsic-resolver/getatt-construct-app.ts`, `src/analyzer/diff-calculator/shared.ts`, `tests/unit/deployment/getatt-rds-master-user-secret-6913.test.ts`. The RDS providers never recorded the attribute, so the reference was refused, and a `DescribeDBClusters` custom resource was the only workaround. The DB cluster's `StorageThroughput` is recorded too. A resource whose master password RDS does not manage is refused with that remedy instead of a request to file an issue. A reader is re-resolved when `ManageMasterUserPassword` changes. An unrelated update to the cluster does not count as changing a cross-stack export of the ARN.
