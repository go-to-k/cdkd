- **`cdkd diff` and `cdkd deploy --verbose` mask a secret-derived name that only a stored OLD value holds (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/secret-name-needles.ts`, `src/cli/commands/diff-recursive.ts`, `src/deployment/deploy-engine/{masking,deploy-flow,provision}.ts`. Consider a metric filter whose create-only `LogGroupName` moves from a log group named from a secret to an ordinary one. The row's old side is the state record's copy of the secret group's name, and nothing in the new template reads that group, so no resolution recorded the name. The `requires replacement (from <old> to <new>)` line of `cdkd diff --verbose` and `cdkd deploy --verbose` printed it. So did `cdkd diff --json`'s row, an output's stored old value, and a nested child's line for a name its parent's row used to pass. `storedSecretNameNeedles` now takes each record named from a secret, judged from state and the stack's whole `NoEcho` values, wherever another record or a stored output holds its name. A name segment the record itself stores in the clear is public and not taken (a secret-named metric filter's ordinary log group). `cdkd diff` masks every line and row with these, adopted orphan records included, and hands a nested child its parent's secret-named records. The deploy masks its replacement line, and a nested-stack row's printing bag carries the parent's records into the child's deploy. Masking only: nothing persisted, compared or sent changes. Tests: `tests/unit/cli/diff-secret-name-needles-3869.test.ts`, `tests/unit/deployment/deploy-engine-replacement-line-secret-name-3869.test.ts`. Integ `secret-derived-immutable-names` step 5c moves a metric filter off a secret-named log group under `cdkd diff --verbose` and `cdkd deploy --dry-run --verbose`, and fails when either log names the group.
