- **A failed RDS DB proxy or DB proxy endpoint no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events, and the RDS, Neptune, DocumentDB, ElastiCache, EFS, Route 53 and DynamoDB global table failures finish the same change (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/{rds-dbproxy,rds-dbproxy-endpoint,rds-dbproxy-targetgroup,rds,neptune,docdb,elasticache,efs,route53,dynamodb-globaltable}-provider.ts` unit cases, and `globaltable-fix-forward-orphan` / `rds-fix-forward-orphan` / `rds-aurora` / `docdb-neptune` integ checks. The DB proxy and DB proxy endpoint create, update, delete and tag failure messages quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDenied. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker. The AWS error is still the wrap's `cause`, so an IAM grant that is still propagating, or a throttle, is retried as before, and an "already exists" is still stated as such. In Route 53, EFS, the DynamoDB global table and the DB proxy target group, it is no longer stated when a call made after the resource itself was created fails. Across these providers, a delete failure whose class is another resource's not-found (for example `KMSNotFoundException`) no longer reads as "already deleted": the state record is kept. A rejection that is not an `Error` is withheld rather than quoted. An error class that spells a secret is masked in the DB proxy, DB proxy endpoint and DB proxy target group failures and in the RDS global-cluster detach failure. The partial-create cleanup and adopt warnings name an AWS failure by its class.
