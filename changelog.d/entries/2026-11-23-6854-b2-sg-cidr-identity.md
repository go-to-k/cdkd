- **A security group rule whose template spells its CIDR with host bits is now found as the rule EC2 stores (issue [#6854](https://github.com/go-to-k/cdkd/issues/6854))** -- `src/provisioning/providers/ec2/sg-support.ts`, `src/provisioning/providers/ec2/read-state.ts`, `src/provisioning/providers/ec2/sg-rule-by-id.ts`. EC2 stores `10.0.0.5/24` as `10.0.0.0/24` and an IPv6 block compressed and lower-cased (measured), but the inline-rule reconcile, the standalone ingress readback and the rule-id lookup compared CIDRs as written. Such a rule read as "cannot tell" in `cdkd drift`, recorded no rule id, and on a stale-id delete was judged gone, so the record was dropped while the rule stayed open. All of them now key a CIDR through one function (`sgCidrKey`), which never folds two networks or a spelling EC2 refuses, and the readback returns the paired rule in the record's spelling.
