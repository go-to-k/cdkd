- **A Ctrl-C or SIGTERM during the start-up of `cdkd local start-service` / `start-alb` / `start-cloudfront` / `start-agentcore` no longer leaves the containers it already started behind (PR [#6300](https://github.com/go-to-k/cdkd/pull/6300))** -- `package.json` (`cdk-local` `^0.167.1` -> `^0.167.2`, with go-to-k/cdk-local#975, #974 and #968). The shutdown handler is now armed before the containers boot, so a signal while the images are pulled or the containers start removes the ones that had started; before, they kept running until removed by hand. **Behavior change:** for `start-service` / `start-alb`, an ECS `Command` / `EntryPoint` element is refused when a cross-stack value (`Fn::ImportValue` / `Fn::GetStackOutput`) recorded as the secret mask is embedded in the middle of it, or when a cross-stack value is the `Fn::GetAtt` argument or `Fn::Sub` template that picks which resource attribute to read (go-to-k/cdk-local#968). `local invoke` and `local start-api` run on cdkd's own engine and are unchanged. No cdkd source change.
