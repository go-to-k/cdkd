- **A nested stack template's own `Transform` is now expanded before the deploy (issue [#6395](https://github.com/go-to-k/cdkd/issues/6395))** -- `src/synthesis/synthesizer.ts`, new `src/synthesis/nested-macro-expansion.ts`. Macro expansion ran over each stack's own template only, while a `cdk.NestedStack` child is read from its file, so a child carrying a transform was deployed raw: a `HostedRotation.*` in a NestedStack created the secret, failed with `To use the HostedRotationLambda property, you must use the AWS::SecretsManager transform` and rolled back, and an `AWS::Serverless::*` resource in a NestedStack never became the resources the SAM transform defines. CloudFormation expands a nested template's transforms when it creates the child. `cdkd deploy` and `cdkd diff` now expand every nested template that carries a macro, at any depth, through the same CloudFormation round-trip, printing a `[macros] Expanding CloudFormation macros for nested template <file> of stack <stack>` line. The expanded copy is written next to the original as `<name>.cdkd-expanded.json` (the original is not modified) and the stack's nested-template reference points at it; the write goes through a temporary file renamed into place, and a symbolic link at that name, or an assembly template whose own name already ends in `.cdkd-expanded.json`, is refused. A SAM-transform child now deploys, updates in place and destroys; a HostedRotation child is now refused before anything is created, by the remote-`TemplateURL` refusal (#6385). Integ fixture: `tests/integration/nested-stack-transform`.
