- **`cdkd drift --revert` turns an `AWS::RDS::DBCluster` Data API back on when the template declares `EnableHttpEndpoint: true` (issue [#5707](https://github.com/go-to-k/cdkd/issues/5707))** -- `src/cli/commands/drift.ts`, `src/types/resource.ts` (a new `UpdateContext.declaredTrueProperties`), `src/provisioning/providers/rds-provider.ts`, their unit tests, and a new phase in the `rds-aurora` integ. Since #5639, a revert never turned the Data API on, because its desired values come from the recorded AWS readback, which can hold a Data API turned on outside the template. That also meant a Data API the template declares, turned off by hand, stayed off after `drift --revert`, which only warned. The revert now passes the names of the properties the recorded template declares `true` to the provider, never their values, and turns the Data API on only when `EnableHttpEndpoint: true` is among them. When the template does not declare it, the revert still leaves it off and warns; turning it off still goes through.
