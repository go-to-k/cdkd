- **`cdkd drift` stops reading a stack after 5 reads in a row fail, instead of retrying an account-wide failure once per resource (issue [#2207](https://github.com/go-to-k/cdkd/issues/2207))** -- `src/cli/commands/drift.ts`, `docs/cli-drift.md`. An expired token, a revoked role or an account-wide throttle used to be read, and backed off, once for every resource of every stack before the run exited 2 anyway. Once 5 resources in a row in one stack have a read that throws, cdkd reads nothing more in that stack and reports each remaining resource under the new `notCompared` cause `readAborted` (`cdkd never read it: ...`), with one warning saying why; the exit code is still 2. A read that returns resets the count, so one unreadable resource among readable ones is still the per-resource `readFailed` it was, and the rest of the stack is compared; a comparison that throws after a good read, and a type with no Cloud Control READ handler, reset it too. The count is per stack, so other stacks in an `--all` run are still read. Tests: `tests/unit/cli/drift-per-resource-failure.test.ts`, `tests/unit/cli/drift-outcome.test-d.ts`.
