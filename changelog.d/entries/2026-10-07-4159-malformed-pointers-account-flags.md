- **The malformed-record refusals and warnings from `cdkd deploy`, `cdkd diff`, `cdkd drift`, `cdkd scrub`, `cdkd export`, `cdkd local --from-state` and `cdkd state show` / `cdkd state resources` now print their `cdkd state show` commands with the run's `--profile`, resolved `--state-bucket` and non-default `--state-prefix` (issue [#4159](https://github.com/go-to-k/cdkd/issues/4159))**. Changed files: `src/state/malformed-resources-bag.ts`, `src/state/export-index-store.ts`, `src/deployment/deploy-engine/{options,deploy-flow,update}.ts`, `src/analyzer/diff-calculator.ts`, `src/cli/commands/{deploy,destroy,diff,diff-recursive,drift,scrub,state,export,local-state-loader}.ts` and `src/local/s3-local-state-provider.ts`. Before this change only `cdkd destroy`, `cdkd import`, `cdkd orphan`, `cdkd rollback` and `cdkd state refresh-observed` carried the flags (issue [#3909](https://github.com/go-to-k/cdkd/issues/3909)). Every other command printed the inspect command bare, so on a non-default bucket or profile the pasted command read the wrong bucket. The deploy engine and the pre-lock `--recreate-via-*` check now print the same flags for the same record, and a nested child's engine inherits them. A value the shared paste gate refuses is printed as a quoted hole with its reason, as for #3909. A `--state-prefix` such as `team/dev` is now gated per `/`-separated part, so it prints as typed on these commands and on #3909's, where it used to be a `'<prefix>'` hole. One site remains: the nested-stack provider's read of a child's outputs during a deploy.
