- **A fix-forward deploy now deletes the EventBridge pipe an earlier failed CREATE left behind (issue [#4606](https://github.com/go-to-k/cdkd/issues/4606), Pipes slice)** -- `src/provisioning/providers/pipes-provider.ts`. When a `cdkd deploy --no-rollback` made an `AWS::Pipes::Pipe`, the pipe never settled (a `*_FAILED` state, the wait's cap, an interrupt, or a state read that failed) and cdkd could not delete it again, and a later deploy kept the logical id under another name, the successful deploy warned about the earlier pipe, left it in AWS and exited 2; `cdkd rollback` and `cdkd destroy` kept it the same way. The provider now answers both questions: a pipe name is unique per account and region and cannot be changed, so the earlier pipe is a different one once the record's reads back (two names equal ignoring case are never compared); and the failed deploy records the pipe's ARN and creation time (from `CreatePipe`'s answer, else read when the failure is journaled), so the earlier pipe is deleted only while its name still reads back with that creation time. One deleted by hand and re-created under the name has another creation time and is kept, with a warning, and so is one AWS reports `DELETING`. Such a failure is no longer retried by re-sending `CreatePipe` (which could only collide with the pipe it left), so its message keeps the `aws pipes delete-pipe` advice instead of ending in "already exists". No ordinary deploy makes an extra call. Tests: `tests/unit/provisioning/pipes-provider-same-resource-4606.test.ts`; integ: `pipes-fix-forward-orphan`.
