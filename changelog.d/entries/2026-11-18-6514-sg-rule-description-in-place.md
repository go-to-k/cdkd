- **A security group rule's `Description` edit is now applied in place instead of revoking and re-authorizing the rule (issue [#6514](https://github.com/go-to-k/cdkd/issues/6514))** -- `src/provisioning/providers/ec2/security-group.ts` (`applySecurityGroupRuleDiff`), `src/provisioning/providers/ec2/sg-ingress-update.ts` (`updateSecurityGroupIngress`), new `src/provisioning/providers/ec2/sg-rule-description.ts`, a new unit file and the new `sg-rule-description-update` integ fixture. A description-only change to an inline ingress / egress rule of an `AWS::EC2::SecurityGroup`, or to a standalone `AWS::EC2::SecurityGroupIngress`, used to revoke the rule and authorize it again: the rule was briefly absent (dropping the traffic it allowed) and came back with a new `sgr-` id, and the standalone rule was reported `replaced`. It now goes through `UpdateSecurityGroupRuleDescriptionsIngress` / `...Egress`, as CloudFormation does: the rule keeps its id, the standalone rule is updated rather than replaced, and a removed description is cleared. The inline diff no longer keys rules on their description. A rule revoked out of band is authorized again, as before; an identity change (protocol, ports, peer) is still a revoke + authorize, and a rule another record of the stack also holds keeps its shared description (#4492).
