- **`AWS::EMR::Cluster`: an `Instances` change CloudFormation replaces the cluster for is now a replacement (issue [#5418](https://github.com/go-to-k/cdkd/issues/5418))** -- `src/analyzer/replacement-rules.ts` and `src/provisioning/providers/emr-cluster-provider.ts`, with unit tests in `tests/unit/analyzer/replacement-rules-emr-cluster-instances.test.ts` and `tests/unit/provisioning/providers/emr-cluster-provider.test.ts` and a replacement phase in the `emr-cluster` integ fixture. The deploy diff called every `Instances` change an in-place update, which the provider then refused, so a change such as adding `AdditionalMasterSecurityGroups`, a subnet or instance type change, or a new task instance group failed the deploy while CloudFormation replaced the cluster. CloudFormation change-set executions showed which members it replaces; `cdkd diff` now marks those `[requires replacement]`, and the deploy replaces the cluster once `--force-stateful-recreation` confirms the loss of its local storage (the type is in the stateful-recreate guard set). The members CloudFormation updates in place (`TerminationProtected`, `UnhealthyNodeReplacement`, a core or task group's `InstanceCount` and `AutoScalingPolicy`, a core or task fleet's target capacities) stay in-place updates; cdkd applies `TerminationProtected` and refuses the others with a message that says CloudFormation applies them in place.
