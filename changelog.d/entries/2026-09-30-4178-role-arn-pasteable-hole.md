- **A run that assumed a role now prints the `'<role-profile>'` hole in its pasteable `aws ...` commands even without `--profile` (issue [#4178](https://github.com/go-to-k/cdkd/issues/4178))** -- `src/utils/pasteable-aws-profile.ts`. Before, `cdkd destroy --role-arn <arn>` with no `--profile` printed bare commands such as `aws rds modify-db-cluster ... --deletion-protection`; pasted, they ran as the operator's ambient identity, which can be another account than the role's, so they answered NotFound or acted on a same-named resource there. Now every role-assumed run (`--role-arn` or `CDKD_ROLE_ARN`) prints `aws --profile '<role-profile>' ...`, as a profiled role run already did since [#3959](https://github.com/go-to-k/cdkd/issues/3959): the AWS CLI refuses the unfilled placeholder before any call, so the operator names a profile that reaches the role's account. A run with neither a role nor `--profile` prints exactly what it did before.
