- **An `AWS::EC2::Instance` `EbsOptimized` change no longer replaces the instance (issue [#7023](https://github.com/go-to-k/cdkd/issues/7023))** -- `src/analyzer/replacement-rules/rules.ts`, `src/provisioning/providers/ec2/instance-ebs-optimized.ts` (new), `src/provisioning/providers/ec2/instance-apply.ts`, `src/provisioning/providers/ec2/instance-support.ts`, `src/provisioning/providers/ec2/instance-update.ts`, `src/provisioning/providers/ec2-provider.ts`. Adding, changing or turning off `EbsOptimized` (for example `ebsOptimized: true` on a CDK `ec2.Instance`) made `cdkd diff` show a replacement, and `cdkd deploy` created a new instance and terminated the old one with its root volume. CloudFormation applies it in place (measured: same instance id, stopped and started), and so does cdkd now: the instance is stopped, `ModifyInstanceAttribute { EbsOptimized }` is sent, and the instance is started again, in the same stop as an `InstanceType` / `UserData` change. A value the instance already has costs no stop. Removing `EbsOptimized` from the template is refused before any AWS call, as CloudFormation fails that update ("No attributes specified"); an instance-store-backed instance, which cannot be stopped, is refused with a pointer to `--replace`. Tests: `tests/unit/provisioning/ec2-provider-instance-ebs-optimized-7023.test.ts`, `tests/unit/analyzer/ec2-instance-ebs-optimized-7023.test.ts`; integ `ec2-instance`.
