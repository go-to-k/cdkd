- **An SSM parameter cdkd created as `/<name>` before #6272 is re-spelled `<name>` on the next deploy, so CDK's `grantRead` / `grantWrite` on it start working (issue [#6274](https://github.com/go-to-k/cdkd/issues/6274))** -- `src/deployment/ssm-slashed-name-heal.ts`. Only a record whose template declares no `Name` and whose physical id is exactly `/` + the name cdkd generated for that stack and logical id is touched; a declared name, a multi-level `/a/b` and any other spelling stay as recorded. SSM stores a one-level `/x` as `x`, so it is the same parameter and no AWS call is made. Every resource whose properties use the parameter's `Ref` (an IAM policy, a Lambda environment variable, an output) updates to the new spelling in the same deploy, and `cdkd diff` previews it. A stack that exports the name changes its export value: while another stack imports it, deploy the producer and the consumers together (the refusal names the re-spelled parameter as the cause). Tests: `tests/unit/deployment/ssm-slashed-name-heal-6274.test.ts`, `tests/unit/cli/diff-ssm-slashed-name-heal-6274.test.ts`, `tests/unit/deployment/export-change-guard.test.ts`; integ: `tests/integration/ssm-generated-name-grant`.
