- **A custom resource's handler now receives an `Fn::GetAtt` number, boolean or object with the JSON type CloudFormation delivers (issue [#6309](https://github.com/go-to-k/cdkd/issues/6309))** -- `src/provisioning/custom-resource-payload-types.ts`, `src/provisioning/providers/custom-resource/{response,create-update,delete}.ts`, `src/deployment/deploy-engine/{custom-resource-payload-leaves,create,update-in-place,update-replace}.ts`, every `delete()` caller, plus a new `custom-resource-payload-types` integ. Before, cdkd turned every number and boolean of `ResourceProperties` into a string, so a handler fed `Fn::GetAtt <ManagedPolicy>.AttachmentCount` got `"0"` where CloudFormation sends `0`. Measured against CloudFormation: a template literal is a string at any depth, through `Fn::If`, `Fn::Select`, `Fn::FindInMap` and a `Ref` of a `Number` parameter, and now also inside a literal list (cdkd used to pass a list's numbers through); a value an `Fn::GetAtt` serves keeps its type, inside a list or object too, except a custom resource's scalar attribute, which stays a string. The template decides, so cdkd records on the custom resource's state record which positions keep their type (`typedPayloadLeaves`, no schema bump), and `OldResourceProperties` and the `Delete` payload read it. A replacement's `Create` and a rollback's re-create, revert `Update` and deletes read the same positions. A record without them (one an earlier cdkd wrote, or a `cdkd import`ed one) keeps the previous rule for its `OldResourceProperties` and `Delete` payload until its next update or replacement. Which values are sent never changes, only their JSON type, and no deploy updates a custom resource because of it.
