- **A replacement or rollback delete of a Cloud Control-routed `AWS::RDS::DBCluster` or `AWS::RDS::DBInstance` no longer leaves an untagged final snapshot (issue [#4029](https://github.com/go-to-k/cdkd/issues/4029))** -- `src/deployment/deploy-engine.ts`, `src/deployment/rollback-executor.ts`, `src/provisioning/final-snapshot.ts`, `src/provisioning/region-check.ts`. The RDS Cloud Control delete handler takes a snapshot on every delete it runs, so cdkd deletes such a cluster or instance through RDS directly when the delete's policy is `Delete` ([#3993](https://github.com/go-to-k/cdkd/issues/3993)). Only destroy and a deploy's removal delete said which policy governed them. A replacement's delete of the old copy, a rollback's delete of a replacement's new copy, and a rollback of a creation still went through the handler, and each left a `rds-snapshot-<random>` snapshot that nothing recorded. Each of these deletes now passes its governing policy: `UpdateReplacePolicy` for the replacement deletes, whose CloudFormation default is `Delete` for every type, and the `DeletionPolicy` the rollback classified for a rolled-back creation. The `rds-full-stack` integration fixture now renames its Cloud Control-routed instance to force a replacement, and fails if the old instance's delete leaves a manual snapshot.
