- **A Ctrl-C during an engine retry backoff or inside a nested stack's deploy no longer rolls the stack back automatically (issue [#3875](https://github.com/go-to-k/cdkd/issues/3875))** -- `src/deployment/deploy-engine.ts`, with unit tests in `tests/unit/deployment/deploy-engine-type-change-routing.test.ts`. The engine's interrupt error reached its outer catch wrapped in a `ProvisioningError` when it was raised by the engine's own retry backoff (a top-level stack too) or by a nested child engine's between-ops poll, and the check matched neither the wrapper nor its cause. The deploy then took the failure path, and without `--no-rollback` that is the automatic rollback, deleting what the run had created. The check now also takes the interrupted branch when the engine's own SIGINT handler has recorded a user interrupt — partial state saved, an `interrupted` journal segment written, no rollback — while an abort caused by another resource's failure still rolls back.
