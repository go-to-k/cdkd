- **`cdkd state show` and `cdkd state resources` no longer invent rows from an `outputs`, `skippedOutputs`, `attributes` or `properties` that is not an object (issue [#3187](https://github.com/go-to-k/cdkd/issues/3187))** -- `src/cli/commands/state.ts`, `src/state/malformed-resources-bag.ts`, `docs/cli-state.md`, `tests/unit/cli/state-record-shape.test.ts`. Issue [#3172](https://github.com/go-to-k/cdkd/issues/3172) guarded the `resources` bag; these four containers are walked by the same renderers with the same `Object.entries`, out of the same unchecked cast, and kept fabricating a row per character or element. Measured on the shipped bundle: `cdkd state show` over a record whose `outputs` held a 5,000,000-character string and whose `resources` bag was HEALTHY cost ~1616 ms and ~1010 MB RSS and emitted 5,000,002 lines; the same shape in `skippedOutputs` cost ~2436 ms and ~2148 MB, and `--show-nested` paid it per node. Each unreadable container is now emptied at the render ENTRY -- through the plain-object predicate `isReadableBag` the `resources` guard already used, never a second spelling at the four walks -- and one warning per record (`malformedRenderedContainersWarning`) names every container that was emptied, once, whatever the resource count. `cdkd state show` renders the record without that block (no `Outputs:`, no `Skipped outputs:`, `Attributes: (none)`, `Properties: (none)`), judged per node under `--show-nested`; `cdkd state resources` reads only `attributes` and stays silent about the other three; `cdkd state show --json` still emits the stored value verbatim so the evidence survives. An absent or `null` container is NOT a defect here, unlike the `resources` bag: `skippedOutputs` is absent on every pre-#2740 record and `attributes` is optional, neither can invent a row, and both render exactly as an empty one with nothing said. A healthy container is untouched and silent.
