- **`AWS::Lambda::EventSourceMapping` refuses `SelfManagedKafkaEventSourceConfig.ConsumptionMode` instead of dropping it silently (issue [#3848](https://github.com/go-to-k/cdkd/issues/3848))** -- `src/provisioning/providers/lambda-eventsource-provider.ts`, with unit tests in `tests/unit/provisioning/lambda-eventsource-provider-consumption-mode.test.ts` and `tests/unit/provisioning/sdk-pending-members.test.ts`. CloudFormation added the member (`Stream` | `Queue`), but `@aws-sdk/client-lambda` does not model it yet and its serializer dropped the value. So a mapping deployed without the requested consumption mode, and the deploy reported success. A template-path create, and an update that adds or changes the member, now fail before any AWS call and name the remedy: remove the member. A rollback state replay or a `cdkd drift --revert` still proceeds and logs a warning. The new test goes red once an SDK bump sends the member, so the refusal can then be replaced by forwarding it.
