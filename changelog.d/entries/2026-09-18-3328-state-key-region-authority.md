- **A state record's S3 KEY now decides its region on read, so `cdkd destroy` / `cdkd state destroy` can no longer lock, save and delete against a region the record's BODY named (issue [#3328](https://github.com/go-to-k/cdkd/issues/3328))** -- `src/state/s3-state-backend.ts`, `src/cli/commands/export.ts`, `src/cli/commands/state.ts`, `src/state/malformed-resources-bag.ts`, `tests/unit/state/state-key-region-authority.test.ts`, `tests/unit/_state-read-double.ts`. Measured against the shipped binary: a resource-less record planted at `.../<stack>/us-east-1/state.json` carrying `"region": "eu-west-1"` made `cdkd state destroy <stack> --stack-region us-east-1` print `✓ State deleted` while the us-east-1 key survived -- only the LEGACY read path compared body against caller. With resources in the record the same divergence sent the lock and every incremental save to a region nobody looks at, and misdirected `DeleteContext.expectedRegion`, which is how a provider tells "genuinely gone" from "wrong-region miss". `getState` now replaces the loaded record's `region` with the key's (`adoptKeyRegion`), making the read symmetric with `saveState`, which has stamped the key's region into every body it writes since the v2 layout -- so a divergence means another writer. Replacement, not `??`: a `""` region built `cdkd/<stack>//state.json` and a numeric one reached `acquireLock` as a region, neither of which a nullish fallback catches. An absent region adopts the key's silently; anything else that disagrees WARNS at default verbosity naming only the value's KIND (`a string`, `an array`) -- the value is body content, and printing it is the misdirection channel this closes. `--verbose` shows it, sanitized. `cdkd export`'s nested-child region refusal reads the divergence from the new `divergentBodyRegion` field. Destroy-path code is unchanged: normalizing at the read fixes `destroy-runner.ts`'s four sites, `deploy.ts` and `drift.ts` with nothing threaded.
