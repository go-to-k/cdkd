- **An `AWS::SNS::TopicPolicy` is now actually removed from a topic: on destroy, and from a topic an update drops from `Topics` (issue [#4610](https://github.com/go-to-k/cdkd/issues/4610))** -- `src/provisioning/providers/sns-topic-policy-provider.ts`. `delete()` sent an empty `Policy`, which SNS rejects with `InvalidParameter`, and read that rejection as "already removed": the destroy reported the policy deleted and dropped its record while every topic kept granting what the statement granted. It now writes each topic the default policy SNS gives a new topic, as CloudFormation's own handler does, and an `InvalidParameter` fails the delete. `update()` wrote only the new `Topics`, so a topic the new list dropped kept the old statement (also what an in-place rollback of `Topics [T1] -> [T1,T2]` left on `T2`); it now resets each topic the record's id names that the new list drops, after writing the new list. A topic only the previous properties list (the attempted list a revert of a failed update passes) is reset only while its live policy matches that bag's `PolicyDocument` by content, so another writer's policy is left alone. Tests: `tests/unit/provisioning/sns-topic-policy-provider-dropped-topics-4610.test.ts`; integ arm in `tests/integration/sns-sqs-event/`.
