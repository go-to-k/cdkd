- **A property removed from the template is reset through a provider declaration, and a removal cdkd does not reset is now named in a warning instead of passing silently (issues [#1160](https://github.com/go-to-k/cdkd/issues/1160), [#4362](https://github.com/go-to-k/cdkd/issues/4362))** -- `src/provisioning/update-removal.ts`, `src/types/resource.ts`, `src/deployment/deploy-engine/update-in-place.ts`, `src/deployment/rollback-executor.ts`, `src/cli/commands/drift.ts`, the Lambda / IAM Role / ASG / ECS Service / RDS / Neptune / DocDB / ElastiCache / CloudTrail / Secrets Manager / Cloud Map namespace providers, `src/deployment/deploy-engine/observed-capture.ts`. A provider now declares `removalDefaults` (the CloudFormation default sent when a property disappears from the template); the deploy's in-place update and both rollback revert arms compute the removed properties once, template against template, and inject those values into the bag the provider receives, while state keeps the template. The constant resets those providers already sent move into the declaration unchanged; coerced, aliased, nested and conditional resets stay in the provider. A type whose update path is fully audited (`removalHandledInUpdate`: Lambda Function, IAM Role, the three Cloud Map namespaces) gets one warning per resource for a removed property cdkd leaves in place, e.g. Lambda `RecursiveLoop`. `drift --revert` injects nothing: its previous side is an AWS readback. No AWS call is added. The post-create / post-update observed-state readback now runs inside the resource's secret scope, so its log lines are masked (#4362). Tests: `tests/unit/provisioning/update-removal.test.ts`, `tests/unit/deployment/deploy-engine-removal-defaults.test.ts`, `tests/unit/deployment/observed-capture-secret-scope.test.ts`, plus rollback / drift / Lambda cases.
