- **`AWS::Glue::Crawler`: a deploy now names an optional property removed from the template, and says CloudFormation keeps the value too (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/glue-provider.ts`. A CloudFormation A/B on the issue (us-east-1) covered all ten optional schema properties: `DatabaseName`, `Description`, `Classifiers`, `TablePrefix`, `Schedule`, `SchemaChangePolicy`, `RecrawlPolicy`, `LakeFormationConfiguration`, `Configuration` and `CrawlerSecurityConfiguration`. They were removed all at once, first with no other change and then beside a `Targets` change. CloudFormation kept every live value, because its `UpdateCrawler` carries only `Name`, `Role` and `Targets`. cdkd already left them out, so what reaches AWS does not change. Before, the removal passed silently. Now the deploy prints one line, `... were removed from the template and keep their current AWS value, as CloudFormation leaves them; UpdateCrawler keeps a setting it is not sent.`, and a rollback revert prints its own wording. `LineageConfiguration`, which cdkd accepts but the CloudFormation schema lacks, is kept and named too, without the CloudFormation clause. Tests: `tests/unit/provisioning/glue-crawler-removal-1160.test.ts`. The `glue-update-hardening` integ fixture's phase 2g now removes four crawler properties and asserts that the values are kept and that the line is printed.
