- **`cdkd export` checks each `AWS::IAM::Policy` pre-delete against the template, and renders nested-tree failures like single-stack ones (issue [#3910](https://github.com/go-to-k/cdkd/issues/3910))** -- `src/cli/commands/export.ts`, `docs/_contents/cli-export.md`, with unit tests in `tests/unit/cli/export*.test.ts`. The IAM::Policy pre-delete removes the policy from the principals cdkd state records, while phase 2 re-attaches it to the ones the template names. A recorded principal or policy name the template does not carry now blocks the export before phase 1, instead of being removed for good under a note calling the gap brief. The block prints `cdkd diff` then `cdkd deploy` on the app stack. A principal passed as a Parameter is checked against the value the changeset submits, including one a parent passes a nested child; an SSM-typed parameter is not. A principal or `PolicyName` cdkd cannot resolve, or a missing `PolicyName`, is marked in the plan. Every recorded principal is listed, not 20 per kind. A legacy `policyName:roleName` record with no lists detaches from that role, as the provider does. A record with no principals now points at a re-import, not a hand edit of the state record. Nested-tree failures (pre-delete, phase 2, the Phase 1A / 1B `Cause:` lines) and the single-stack phase-2 failure now fold and cap AWS's text. The nested recovery, Phase 1A failures included, says a re-run is refused for the whole tree and gives a `cdkd state orphan` for every stack that finished; when nothing was imported, it says to delete the leftover stack and re-run. The by-hand recovery prints one pasteable delete per pre-delete type and IAM principal kind. The nested confirmation no longer calls the pre-deleted resources unchanged. A blocked-resource refusal says to destroy or remove only the rows without their own remedy.
