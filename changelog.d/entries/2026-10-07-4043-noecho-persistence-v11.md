- **A `NoEcho: true` parameter's value, and a value an attribute was declared `NoEcho` for, are no longer persisted in the clear: state schema v11 (issues [#4043](https://github.com/go-to-k/cdkd/issues/4043) Phase B, [#2449](https://github.com/go-to-k/cdkd/issues/2449))** -- `src/types/state.ts`, `src/deployment/secret-redaction/noecho-leaves.ts`, `src/deployment/deploy-engine/{noecho,update,masking}.ts`. `state.json`, `observedProperties`, `attributes`, `outputs`, the exports index and the rollback journal store `***` where such a value was used (at a position the template names whatever its type or length, elsewhere from 4 characters); `ResourceState.noEchoLeaves` names those positions and `noEchoAttributeNames` the declared attributes. A comparison reads the resource back from AWS instead: a held value is skipped, an updatable value AWS cannot report is re-sent with one info line, and a create-only property is never replaced on a readback (a warning names `--recreate-via-*`; a failed read fails the resource). The first deploy after upgrading migrates each stack, comparing every unchanged value with the one it last stored, so the migration neither updates nor replaces. A custom resource's handler gets `***` in `OldResourceProperties`, and no `Delete` (skipped, exit 2). A dependent reading a declared attribute out of an earlier run is still refused, now naming the attribute. `cdkd drift` reports a masked position in its own bucket without failing; `cdkd diff` no longer shows a changed `NoEcho` value (it prints one per-stack note, not counted for `--fail`); `cdkd export` blocks a resource such a value feeds. A replacement whose old resource could not be deleted (any provider skip reason) is reported as a partial update and exits 2 unless `--allow-unaddressed`. Older cdkd binaries fail on a v11 state with "Upgrade cdkd"; earlier object versions of `state.json` keep the old plaintext, so rotate such a value. Integ: `schema-v10-to-v11-migration` (new).
