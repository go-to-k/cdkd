- **A `NoEcho: true` parameter's value, and a value an attribute was declared `NoEcho` for, are no longer persisted in the clear: state schema v11 (issues [#4043](https://github.com/go-to-k/cdkd/issues/4043) Phase B, [#2449](https://github.com/go-to-k/cdkd/issues/2449))** -- `src/types/state.ts`, `src/deployment/secret-redaction/noecho-leaves.ts`, `src/deployment/deploy-engine/{noecho,update}.ts`. State, `observedProperties`, `outputs`, the exports index and the rollback journal store `***` where such a value was used (at a position the template names, nested children included, whatever its type or length; elsewhere from 4 characters); `noEchoLeaves` names those positions, `noEchoAttributeNames` the declared attributes. A comparison reads the resource back instead: a held value is skipped, an updatable one AWS cannot report is re-sent with an info line, and a create-only property is never replaced on a readback (a warning names `--recreate-via-*`; a failed read fails the resource). The first deploy after upgrading compares each value with the one last stored: an unchanged one is neither updated nor replaced, a changed one is applied as before, a create-only replacement included. A custom resource's `Update` runs every deploy with `***` in `OldResourceProperties`; its `Delete` is skipped (exit 2) where its record holds `***` for such a parameter or a declared attribute. A reader of a declared attribute out of an earlier run is still refused, naming it. `cdkd drift` reports a masked position in its own bucket; `cdkd diff` no longer shows a changed `NoEcho` value (one per-stack note, not counted for `--fail`); `cdkd export` blocks a resource such a value feeds. A replacement whose old resource's delete was skipped is a partial update (exit 2 unless `--allow-unaddressed`). Older binaries fail on v11 with "Upgrade cdkd"; earlier `state.json` versions keep the plaintext, so rotate it. Integ: `schema-v10-to-v11-migration` (new).
