- **`AWS::EMR::InstanceGroupConfig` now records `InstanceGroupId` as well as `Id` in its attributes (issue [#3632](https://github.com/go-to-k/cdkd/issues/3632))** -- `src/provisioning/providers/emr-instance-group-config-provider.ts`, plus tests. The CFn schema renamed the read-only attribute from `Id` to `InstanceGroupId` ([#3629](https://github.com/go-to-k/cdkd/pull/3629)). Before this change, a template reading the new name got its value only through the physical-ID fallback, with a warning. It was refused under `--strict-getatt`, and `cdkd orphan` could not rewrite it. An aws-cdk-lib regenerated from that schema emits the new name as `attrInstanceGroupId`. `create`, `update` and `getAttribute` now serve both names as the instance group id, which is also the physical id. A group whose state was written before this change keeps only `Id` until its next update or replacement. Until then, `InstanceGroupId` still resolves through the fallback.
