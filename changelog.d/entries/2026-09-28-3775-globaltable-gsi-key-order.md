- **`AWS::DynamoDB::GlobalTable` no longer treats a key-order-only difference as a change (issue [#3775](https://github.com/go-to-k/cdkd/issues/3775))** -- `src/provisioning/providers/dynamodb-globaltable-provider.ts`.
  - `update()` compared values with `JSON.stringify`, so key order mattered. `aws-cdk-lib` writes a GSI `Projection` as `{NonKeyAttributes, ProjectionType}`, but a readback has the reverse order. On `cdkd drift --revert`, an unchanged `INCLUDE` index was therefore classified as modified. cdkd then warned that `KeySchema` / `Projection` changed and advised recreating the index, or re-sent the index's on-demand ceilings for no reason.
  - The provider's comparisons now ignore object key order. This covers the GSI and replica diffs, the change gate behind the template-path refusals, and the stream, SSE, warm-throughput, auto-scaling and tag checks. Array order still counts.
