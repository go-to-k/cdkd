- **The SDK provider sends `DBName` and `AvailabilityZone` for `AWS::RDS::DBInstance` (issue [#5640](https://github.com/go-to-k/cdkd/issues/5640))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, and a new arm in the `rds-dbinstance-backfill` integ. Before, an instance declaring either one, such as a CDK `rds.DatabaseInstance` given `databaseName` or `availabilityZone`, routed through Cloud Control. Both now ride `CreateDBInstance` as declared, as CloudFormation sends them; RDS itself still refuses a database name on an engine that takes none (SQL Server) and a zone beside `MultiAZ: true`. A changed `DBName` replaces the instance, as under CloudFormation (it is create-only). A changed `AvailabilityZone` cannot be applied in place (`ModifyDBInstance` has no such member), so the update is refused before any change, as CloudFormation refuses it, unless the template drops the zone and declares `MultiAZ: true`, or the instance already sits in the declared zone; re-run with `--replace --force-stateful-recreation` to recreate the instance in the new zone. `cdkd drift` reads both back, the zone only for a single-AZ instance (a Multi-AZ instance's zone moves on every failover). Resources already deployed through Cloud Control stay there.
