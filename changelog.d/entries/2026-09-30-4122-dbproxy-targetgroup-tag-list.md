- **`AWS::RDS::DBProxyTargetGroup` `Tags` now follow the shared tag-list rules, so a number or boolean tag `Value` deploys as it does under CloudFormation** (`src/provisioning/providers/rds-dbproxy-targetgroup-provider.ts`, go-to-k/cdkd#4122). Until now the target group used its own reader: it refused a scalar `Value` that CloudFormation coerces to a string, and on update it could send `RemoveTagsFromResource` a recorded key that holds a dynamic reference or its mask, which names nothing AWS holds. It now reads both sides through `src/provisioning/tag-list.ts`, as the sibling `DBProxy` / `DBProxyEndpoint` providers do. A scalar `Value` is sent as a string, `Value` may be omitted, and a recorded secret-derived key is never untagged (a warning says so without naming it). A malformed desired list is still refused before any call. An update now refuses a client pointed at a region other than the stack's before its first call: every call addresses the proxy by name, and an already-deregistered target reads as success. Tests: `tests/unit/provisioning/rds-dbproxy-targetgroup-provider.test.ts`.
