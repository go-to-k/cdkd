- **`cdkd export` names the roles, users and groups an `AWS::IAM::Policy` pre-delete detaches from, in the plan printed before its confirmation (issue [#3857](https://github.com/go-to-k/cdkd/issues/3857))** -- `src/cli/commands/export.ts` (`preDeleteListingLines`), `docs/cli-export.md`, with unit tests in `tests/unit/cli/export-predelete-listing.test.ts` and `tests/unit/cli/export-plan-record-display.test.ts`. Between phases, the pre-delete removes the inline policy from every role, user and group recorded in cdkd state. The plan listed only the policy's own name, and the confirmation says to "see plan above" for what is deleted. The single-stack plan and the nested-tree summary now print a `removes inline policy <name> from roles: ...; users: ...; groups: ...` line under each such policy. It comes from the same check the pre-delete runs, so both name the same policy and principals. Each name is rendered with its own boundary, and each kind is capped at 20 names with the rest counted. A policy whose recorded `Roles` / `Users` / `Groups` is not a list of IAM names, or records none, is now a resource that blocks migration, reported before phase 1 changes any AWS resource. The pre-delete used to walk a string character by character and remove a same-named policy from one-letter roles, or refuse only after phase 1 had created the CloudFormation stack. The nested-tree summary also names each pre-delete resource, where it previously printed only a count.
