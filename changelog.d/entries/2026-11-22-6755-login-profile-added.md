- **`cdkd drift` reports a console login profile added out of band to an IAM user whose template declares none, and `--revert` deletes it (issue [#6755](https://github.com/go-to-k/cdkd/issues/6755))** -- `src/provisioning/providers/iam-user-group/read-state.ts`, `src/provisioning/providers/iam-user-group/user-update.ts`, `src/cli/commands/drift/baseline-keys.ts`, the `drift-iam-user-login-profile-added-6755` unit suite, and a login-profile arm in the `drift-verbatim-readback` integ. The `AWS::IAM::User` readback read `GetLoginProfile` only for a record declaring `LoginProfile`, so a profile added to any other user was never seen. It now records `LoginProfile: null` for a user without one (and the profile's `PasswordResetRequired` for a user with one; the write-only password is never read), and `LoginProfile` joins the undeclared keys drift compares even when captured empty, since only `CreateLoginProfile` makes one. `--revert` sends `null`, which the update turns into one `DeleteLoginProfile`, keeping the user; `--accept` records the profile's flag with no password. A failed `GetLoginProfile` other than `NoSuchEntity` throws instead of reading as no profile. A baseline captured before this change has no `LoginProfile` key and is not compared on it until the user's next capture (an update, or `cdkd state refresh-observed`). The capture right after an update that deleted the profile records `null` without a read, so a lagging read is not frozen into the baseline.
