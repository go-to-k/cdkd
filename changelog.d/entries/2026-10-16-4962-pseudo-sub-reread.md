- **`cdkd diff --recursive --fail` no longer reports a change on an unchanged nested stack in which one child resource reads a parameter the parent spelled as a literal embedding `{{resolve:...}}` tokens beside a sibling parameter spelling the same secret differently, through an `Fn::Select` / `Fn::Split` over an `Fn::Sub` (or `Fn::Join`) naming `AWS::Region`, `AWS::Partition` or `AWS::URLSuffix` (issue [#4962](https://github.com/go-to-k/cdkd/issues/4962)).** After upgrading, the first deploy of such a stack shows a change on the child resources reading the literal parameter, because their state now records the parameter's own `{{resolve:...}}` spelling instead of the sibling's; the deployed VALUE is unchanged, and a create-only property is replaced once with an identical value. The child's parameter resolution records those three values, each a function of the stack's region, and the redaction re-reads such a leaf with them, as `cdkd deploy`, `cdkd scrub` and the diff side all resolve them; no AWS call is added. `AWS::AccountId` ([#4975](https://github.com/go-to-k/cdkd/issues/4975)), `AWS::StackName`, `AWS::StackId` and `AWS::NotificationARNs` are not bound, so a leaf naming one still falls back to the sibling's spelling. Source: `src/deployment/secret-redaction/nested-stack.ts`, `src/deployment/intrinsic-resolver/{parameter-secrets,params-conditions}.ts`.
