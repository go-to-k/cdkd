- **Two `AWS::IAM::Policy` resources with no dependency between them that swap an inline policy name on one principal, or hand one off (a rename away from a name a new policy takes), no longer both lose it (issue [#4227](https://github.com/go-to-k/cdkd/issues/4227))** -- `src/deployment/inline-policy-claims.ts` (`orderInlinePolicyWriters`), `src/deployment/deploy-engine/execute.ts`, `src/deployment/deploy-engine.ts`. Such resources used to run at once, so each one's removal of its old name could miss the other's put, leaving the role with neither policy until a later deploy changed one of them. Before dispatch, the deploy now makes each create / update that writes the same inline policy name on the same role, group or user wait for the one before it; a pair the template already orders, and every other resource, run exactly as before, so an ordinary deploy is unchanged. A name or principal cdkd cannot read before resolving counts as any name or principal of that kind; a principal of the same stack is told apart by its logical id even when its name is a token, so policies on different such roles stay concurrent. An `AWS::IAM::Role` / `Group` / `User` update that drops a name from its own `Policies` now also keeps it when another resource of the same deploy has already put that name there, as a rollback already did. Covered by `tests/unit/deployment/inline-policy-write-order.test.ts`, `tests/unit/deployment/deploy-engine-inline-policy-claims.test.ts`, and an unordered arm in the `iam-role-policies-drift-clean` integ fixture.
