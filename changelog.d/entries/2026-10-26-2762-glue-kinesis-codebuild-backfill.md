- **Three resource types keep the SDK route for properties that used to send them through Cloud Control or refuse them (issue [#2762](https://github.com/go-to-k/cdkd/issues/2762)).** `AWS::Glue::Connection` `Tags` ride on `CreateConnection`, and an update changes, adds and removes tags through `TagResource` / `UntagResource`. `AWS::Kinesis::Stream` `RecordDistributionStrategy` rides on `CreateStream`, and an update calls `UpdateStreamRecordDistributionStrategy` after any stream-mode switch. Removing it from the template resets an ON_DEMAND stream to `USER_PARTITION_KEY`, as CloudFormation does. `AWS::CodeBuild::Project` `Visibility` and `ResourceAccessRole` are applied with `UpdateProjectVisibility` after `CreateProject`, and on update whenever either changes. Removing both resets the project to `PRIVATE` with no role, as CloudFormation does. Before this, a CodeBuild template declaring either was refused before deploy, since that type has no Cloud Control route. Unchanged: a CodeBuild `Triggers` (webhook) block is still refused, and Kinesis `WarmThroughputMiBps` still routes through Cloud Control ([#1695](https://github.com/go-to-k/cdkd/issues/1695)). Source: `src/provisioning/providers/glue-provider.ts`, `kinesis-provider.ts`, `codebuild-provider.ts`.
