- **`cdkd local run-task` / `cdkd local invoke` now refuse secret names that would inject code into a credential helper written in a scripting language (issue [#3599](https://github.com/go-to-k/cdkd/issues/3599))** -- `src/utils/docker-cmd.ts`, `docs/local-run-task.md`, plus tests. The template chooses the image, so it chooses which `docker-credential-*` helper the container client execs for the pull, and that helper inherits the client's environment. A secret named `CLOUDSDK_PYTHON_ARGS` reached `docker-credential-gcloud`, whose wrapper expands it unquoted onto the Python command line, so it could run code as the operator. The denylist now also covers bash's `SHELLOPTS` / `PS4` and the `BASH_FUNC_` exported-function prefix; Python's `PYTHONPATH`, `PYTHONHOME`, `PYTHONUSERBASE`, `PYTHONPYCACHEPREFIX`, `PYTHONPLATLIBDIR`, `PYTHONWARNINGS` and `BROWSER`; the CA bundles `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`, `HTTPLIB2_CA_CERTS`; Node's `NODE_OPTIONS`, `NODE_PATH`, `NODE_EXTRA_CA_CERTS`, `NODE_TLS_REJECT_UNAUTHORIZED`; Ruby's `RUBYOPT`, `RUBYLIB`, `GEM_PATH`, `GEM_HOME`; Perl's `PERL5OPT`, `PERL5LIB`, `PERLLIB`, `PERL5DB`; OpenSSL's `OPENSSL_CONF`, `OPENSSL_MODULES`, `OPENSSL_ENGINES`; gcloud's `GCE_METADATA_HOST` / `_ROOT` / `_IP`; and the whole `CLOUDSDK_` prefix, since every gcloud property is an environment variable. `CLOUDSDK_AUTH_ACCESS_TOKEN` is exempt from that prefix and still forwarded. A colliding secret is dropped with the existing warning; the operator's own value of each variable is untouched.
