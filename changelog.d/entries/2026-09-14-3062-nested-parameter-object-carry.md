- **A 1-3 character `secretsmanager` / `ssm-secure` secret a parent embeds in a nested-stack `Parameters` value through an `Fn::Join` / `Fn::Sub` frame (`cdk.Fn.join('', ['port:{{resolve:secretsmanager:', secretArn, ':SecretString:pin::}}'])`) now reaches the child's `state.json` as `port:{{resolve:...}}` instead of `port:q7` (issue [#3062](https://github.com/go-to-k/cdkd/issues/3062))** -- `src/deployment/secret-redaction.ts` (`recordNestedStackParameterExpressions`), unit tests, `tests/integration/nested-stack-secret/` (`PinJoinParam`). The sub-floor carry issue #2745 added required the parameter's SOURCE to be a string, so an object-spelled source was never carried: the parent's own row persisted the frame while the child persisted the plaintext, and `cdkd diff --recursive` reported that child leaf on every run. For an object source the recorder now takes the spelling the position pass wrote for the leaf, when the pass rewrote it, the source's own token spells `secretsmanager:` or `ssm-secure:` literally, and the value scan is silent on the value -- a combination only the intrinsic frame arm produces -- and applies the same five conditions to that spelling. The object spelling also counts as its frame in the one-frame-per-value condition. Residuals (recorder docstring): an `ssm:` token, or one whose service is itself an intrinsic part, is not carried, because the frame arm can match a recorded secret sibling for a public parameter's leaf; a frame that is not wholly literal is still refused; a child record persisted before this change keeps the plaintext until the child is next redeployed; at `--verbose` the parent resolver's `Resolved Fn::Join:` debug line still prints the framed value (issue [#3100](https://github.com/go-to-k/cdkd/issues/3100)).
