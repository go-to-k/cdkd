- **`cdkd state show` / `state resources` / `state list` render a record whose shape violates its declared types instead of aborting on it (issue [#2947](https://github.com/go-to-k/cdkd/issues/2947))** -- `src/utils/display-safe.ts` (`displaySafe` no longer throws on a JSON value, new `truncateCodePoints`), `src/state/s3-state-backend.ts`, `src/state/lock-manager.ts`, `src/cli/commands/state.ts`, `src/cli/commands/export.ts`, `docs/cli-state.md`, a new `tests/unit/cli/state-record-shape.test.ts`, and cases in three suites. A state record and a lock are unchecked casts, so a hand-edited one could abort those views with a raw `TypeError` before anything rendered. Inner record-shape validation stays out of the read boundary: `parseStateBody` is the read path for deploy, destroy, rollback and the recovery commands, so beyond invalid JSON and the schema-version check it refuses only a non-object ROOT, by name, and inner shapes are tolerated where they are dereferenced. A `null` resources entry or bag renders in every mode, `--show-nested` and both JSON walks included. `getLockRecord` turns an `expiresAt` whose number coercion throws into `NaN`, which reads as expired, so a takeover no longer deletes the lock and then throws. `displaySafe` falls back to `Object.prototype.toString` when `String` throws, closing the half of issue [#3003](https://github.com/go-to-k/cdkd/issues/3003)'s version refusal that its own entry records as still open. A `skippedOutputs` digest preview is cut by code point, so it never splits a surrogate pair. **Residuals**: [#3018](https://github.com/go-to-k/cdkd/issues/3018) -- consumers outside these views still abort on a malformed bag, `state destroy` and `state orphan` among them.
