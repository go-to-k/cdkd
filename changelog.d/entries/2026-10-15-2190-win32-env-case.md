- **On Windows, a container secret whose name differs only in letter case from a variable already in your shell now replaces it, and Windows system variables are no longer forwarded as secret names (issue [#2190](https://github.com/go-to-k/cdkd/issues/2190))** -- `src/utils/docker-cmd.ts`. Windows treats `MY_TOKEN` and `my_token` as one variable, but both spellings reached the container client's environment, so a secret named `my_token` reached the container as the host's `MY_TOKEN` value. cdkd now removes the other spelling before it starts the client, so the secret wins as it does when spelled the same, and it warns when two secrets differ only in letter case (the container then receives the last one's value under both names). A secret matching another name only through a letter outside A-Z (`ß` against `SS`) is dropped with a warning instead, so it can never remove the operator's variable. Secrets named `ComSpec`, `SystemRoot`, `windir`, `SystemDrive`, `PSModulePath` or `PSExecutionPolicyPreference`, in any letter case and on every platform, are now dropped with the existing rename warning, because they choose which programs and libraries the client and its credential helpers load or trust. `TEMP` and `TMP` are still forwarded. A new `windows-env-precedence` CI job runs this on a real Windows host. Linux and macOS behaviour is otherwise unchanged.
