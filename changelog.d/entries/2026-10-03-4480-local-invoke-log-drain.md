- **`cdkd local invoke`, `local invoke-agentcore` and `local run-task` no longer drop the container's last log lines when the Docker daemon is slow to relay them (issue [#4480](https://github.com/go-to-k/cdkd/issues/4480))** -- `src/local/docker-runner.ts` (`followContainerLogs`, `killContainer`, `killAndDrainContainerLogs`, `flushStdio`), `src/local/ecs-task-runner.ts`, `src/cli/commands/{local-invoke,local-invoke-agentcore,local-run-task}.ts`. The teardown SIGTERMed `docker logs -f` (after a fixed 250 ms on `invoke`) and then removed the container, so any line the daemon had not yet relayed was lost: under host load the handler's `console.log` output and the RIE's `END` / `REPORT` lines went missing while the invoke reported success. `invoke` / `invoke-agentcore` now run `docker kill`, wait (up to 5 s) for `docker logs -f` to end on its own, and only then write the response to stdout and remove the container, so every log line precedes the response. `run-task` waits for the essential container's follower after the container exits, and at teardown stops every container before draining the followers and removing the containers. A ^C flushes stdout and stderr before exiting with 130. `invoke-agentcore --watch` keeps the container between iterations, so it drains when the container is rebuilt or torn down. Tests: `tests/unit/local/docker-runner-log-drain.test.ts`, `tests/unit/local/ecs-task-runner{,-runner}.test.ts`, `tests/unit/cli/local-invoke{,-agentcore}-stdout-stream.test.ts`.
