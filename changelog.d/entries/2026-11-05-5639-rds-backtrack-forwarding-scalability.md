- **The SDK provider sends `BacktrackWindow`, `EnableLocalWriteForwarding` and `ClusterScalabilityType` for `AWS::RDS::DBCluster` (issue [#5639](https://github.com/go-to-k/cdkd/issues/5639))** -- `src/provisioning/providers/rds-provider.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, a new unit file, the RDS wire cases, a new arm in the `rds-aurora` integ, the RDS row of the `--no-wait` table in `docs/cli-deploy.md`, and the RDS removal rule in `docs/provider-rules.md`. Before, a cluster declaring any of them routed through Cloud Control. Each now rides `CreateDBCluster` as declared (`ClusterScalabilityType` is create-only). An update sends a changed `BacktrackWindow`, and removing it leaves the live window; it sends a changed `EnableLocalWriteForwarding`, and removing a declared `true` turns write forwarding off, as CloudFormation's handler does. A create or update that turns write forwarding on or off, or an update that changes the backtrack window, waits until the cluster reports the new setting, unless `--no-wait` is set. `cdkd drift` reads back `BacktrackWindow` and `EnableLocalWriteForwarding` (`requested` counts as on); `ClusterScalabilityType` is write-only and has no readback. Resources already deployed through Cloud Control stay there.
