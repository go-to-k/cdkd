- **`cdkd deploy --replace --force-stateful-recreation` now replaces an `AWS::DynamoDB::GlobalTable` (CDK `TableV2`) whose `KeySchema` or `LocalSecondaryIndexes` changed, as the refusal message advises (issue [#6363](https://github.com/go-to-k/cdkd/issues/6363))** -- `src/provisioning/providers/dynamodb-globaltable/update.ts`, plus the new `globaltable-keyschema-replace` integ. A KeySchema change, an added or changed LSI list, a removed attribute a key still references, or a `TableName` change that reached the provider was refused with a message telling you to re-deploy with `--replace --force-stateful-recreation`. That command then failed with the same refusal, so the only way out was a destroy and redeploy. The refusal now uses the error `--replace` acts on. Without the flags the change is still refused before any AWS call, and `--replace` alone is still refused by the stateful-resource guard.
