- **An out-of-bounds `Fn::Select` fails the deploy, as CloudFormation refuses the template (issue [#6181](https://github.com/go-to-k/cdkd/issues/6181))** -- `src/deployment/intrinsic-resolver/string-functions.ts`, `params-conditions.ts`, `src/utils/error-handler/refusal-errors.ts`, unit tests and the new `select-out-of-bounds` integ. Before, an index past the end of the resolved list (one a token decides at deploy time, such as `Fn.select(2, Fn.getAzs())` in a two-AZ region, or a `Fn::Split` over a value without its delimiter) logged a warning and sent the literal `{{Fn::Select:N:OutOfBounds}}` to AWS, where a free-text property such as an SSM parameter value or a tag kept it under a successful deploy. Now the resource fails with `Fn::Select: the index N is out of bounds (array length: M)`, nothing is sent, and the deploy rolls back as for any failed resource. A condition selecting out of bounds fails the deploy instead of evaluating to false, so it cannot remove a resource. A stack output reading such a value is skipped and the deploy still exits 0 (unless `--strict-getatt`), as for the other intrinsic refusals. One case keeps the warning and the placeholder: a list cut from `AWS::StackId` on a stack first deployed before cdkd derived its stack id from a UUID, whose stack id ends in `cdkd` for life. A stack already holding a placeholder from another out-of-bounds select fails its next deploy until the template selects an index inside the list.
