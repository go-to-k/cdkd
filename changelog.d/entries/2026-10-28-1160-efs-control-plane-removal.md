- **Removing `BackupPolicy`, `FileSystemPolicy` or `FileSystemProtection` from an `AWS::EFS::FileSystem` resets it on AWS as CloudFormation does (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160), efs-provider.ts row)** -- `src/provisioning/providers/efs-provider.ts` (`removalDefaults`, `updateFileSystem`, `deleteFileSystemPolicy`); unit tests in `tests/unit/provisioning/efs-control-plane-removal-1160.test.ts`, integ arm in `tests/integration/efs-standalone`. A redeploy that dropped one of these properties used to send nothing, so after a CDK app turned `enableAutomaticBackups` off or dropped its `fileSystemPolicy`, automatic backups stayed on and the access policy stayed attached while the deploy reported success. Measured against CloudFormation, each removal is a reset: cdkd now sends `PutBackupPolicy` with `Status: DISABLED`, `DeleteFileSystemPolicy`, and `UpdateFileSystemProtection` with `ReplicationOverwriteProtection: ENABLED`. Each call is accepted when the file system is already at that value. A changed or added policy is still a `PutFileSystemPolicy`.
