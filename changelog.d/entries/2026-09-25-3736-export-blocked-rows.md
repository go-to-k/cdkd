- **`cdkd export`'s blocked-resource summary no longer prints a template identifier that could forge a labelled line, and its masked-identifier refusal puts its repair command on a gated line (issue [#3736](https://github.com/go-to-k/cdkd/issues/3736))** -- `src/cli/commands/export.ts` (`groupBlockedReasons` with `blockedRowId` / `blockedRowType`; `buildImportPlan`'s redaction-mask refusal now routed through `importRepairCommand`), `scripts/check-pasteable-command-shapes.ts` (its one exemption deleted, a `CDKD_PASTEABLE_EXEMPTIONS` test seam honoured only with `--root=`), and unit tests in `tests/unit/cli/export-{identifier-overlay,composite-identifier}.test.ts` and `tests/unit/scripts/pasteable-command-shapes.test.ts`. Each blocked row printed its logical id and resource type raw, directly above reasons that can end in a `Repair with:` line, so a template key carrying a newline, or padding that wraps on screen, could print a counterfeit `Repair with: cdkd destroy --all --force #` row. The row now names a logical id only when it is a plain identifier and a type only when it has CloudFormation's `A::B` / `A::B::C` shape (`Custom::` names included); any other value is described. Every reason is folded to one line, so no template key or state value interpolated into one can start a line, and the one `Repair with:` line a row may carry is printed by the renderer from a separately gated command. A real template loses nothing. `buildImportPlan`'s refusal for an identifier that resolves to the redaction mask printed its `cdkd import ... --resource <id>=<physicalId> --force` remedy inside a quoted sentence with the logical id interpolated, where a pasted id ran. It now prints `Repair with: cdkd import '<stack>' --resource ...` on its own line, naming the id only when it is a plain identifier.
