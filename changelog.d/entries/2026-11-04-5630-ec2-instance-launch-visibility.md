- **`AWS::EC2::Instance` no longer terminates and relaunches a just-launched instance when EC2 has not listed it yet (issue [#5630](https://github.com/go-to-k/cdkd/issues/5630))** -- `src/provisioning/providers/ec2-provider.ts`. EC2's API is eventually consistent: under `--no-wait`, the `DescribeInstances` cdkd sends right after `RunInstances` could answer `InvalidInstanceID.NotFound` for the instance it had just launched. cdkd then terminated that instance and created it again. For an instance with a fixed `PrivateIpAddress` or `Ipv6Addresses`, the second launch failed with `InvalidIPAddress.InUse`, because the terminating instance still held the address. cdkd now retries that read, the `SourceDestCheck` change and the tagging of an instance launched without tags, for up to about 40 seconds while EC2 reports the instance as not found. Other errors fail the create as before.
