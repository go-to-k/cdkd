- **Lock and state messages on the deploy, destroy, rollback, force-unlock and renewal paths render the stack name, region and S3 error text on one line (issue [#3027](https://github.com/go-to-k/cdkd/issues/3027))** -- `src/state/lock-manager.ts`, `src/state/s3-state-backend.ts`, and unit tests in `tests/unit/state/stackname-display-sites.test.ts`. The two read commands (`cdkd state show` / `cdkd state resources`) already guarded their messages; the lock acquire / release / renewal / takeover lines, `cdkd force-unlock`'s banner, and `saveState` / `deleteState` / the rollback-journal delete still printed the stack name, region and S3's error text raw. A stack name taken from an S3 key segment (`cdkd state destroy`, `cdkd state orphan`) could therefore carry a newline and forge a line of cdkd's output or of a thrown error, and S3's error text, which echoes the key, carried the same bytes back in. Each of those values now renders through the identifier guard the read commands use: a plain name prints unchanged, and any other name prints flattened inside double quotes. The stack name in these messages is no longer wrapped in single quotes, so `Lost the lock for stack 'MyStack' (us-east-1)` now reads `Lost the lock for stack MyStack (us-east-1)`. The raw S3 keys `listRawObjects` and `deleteRawObjects` report, which embed a stack name, take the same guard.
