- **A rollback of a failed `AWS::CloudFront::Distribution` update now restores each custom origin's pre-deploy `OriginSSLProtocols` (issue [#6519](https://github.com/go-to-k/cdkd/issues/6519))** -- `src/types/resource/contexts.ts`, `src/deployment/rollback-executor/replay-revert.ts`, `src/deployment/rollback-executor/replay-failed.ts`, `src/provisioning/providers/cloudfront-distribution/update-config.ts`. When the failed deploy declared `OriginSSLProtocols` on an origin and the template the rollback restores omits it, the rollback used to keep the value the failed deploy applied and warn. Both revert arms now pass the restored record's `observedProperties` as the new optional `UpdateContext.restoredObservedProperties`, and the CloudFront provider sends that snapshot's value for the origin of the same `Id`. The value is used only when it is a non-empty list of known protocol names. A redacted, malformed or missing value, or no origin of that `Id`, keeps the live value with the warning, as before. Other providers ignore the field, and an update that is not a rollback never reads it.
