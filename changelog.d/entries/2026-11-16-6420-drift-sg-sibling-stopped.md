- **`cdkd drift --revert` no longer re-authorizes a security-group rule that a removed `AWS::EC2::SecurityGroupIngress` / `SecurityGroupEgress` used to add (issue [#6420](https://github.com/go-to-k/cdkd/issues/6420))** -- `src/provisioning/sg-sibling-rules.ts`, `src/deployment/deploy-engine/observed-capture.ts`. A security group's recorded snapshot taken by a cdkd before #6418, on an update of the group, could hold a rule a separate rule resource of the stack added. When a later deploy removed that rule resource (or replaced it with a different rule), its delete revoked the rule, but the snapshot kept it, so `cdkd drift` reported the rule as lost and `--revert` added it back, re-opening access the template no longer grants. The deploy that removes or replaces the rule resource now also removes its rule from the group's snapshot, unless the group's own template lists it. A snapshot whose rule resource was already removed by an older cdkd is re-read with `cdkd state refresh-observed --yes`.
