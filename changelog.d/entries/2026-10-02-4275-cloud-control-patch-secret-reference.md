- **A Cloud Control-routed resource whose create-only property comes from a secret reference no longer puts that property into every update's patch (issue [#4275](https://github.com/go-to-k/cdkd/issues/4275))** -- `src/provisioning/cloud-control-provider.ts`. State records a secret-derived value as its `{{resolve:...}}` expression, while `update()` receives the resolved value, so the JSON Patch built from the two always carried an op at that path, even though the template had not changed it. On a create-only path such as a Logs MetricFilter's `FilterName` that op asks Cloud Control to update a property it cannot update, and after a secret rotation it carries a value the resource does not have. Now, on a key the engine replaces on any change, the patch is left without that key when the record holds a reference and the desired value is a secret this deploy resolved. A changed literal, a missing masker and a mutable key still produce their op, as before. Tests: `tests/unit/provisioning/cloud-control-provider.test.ts`. The fixture `secret-derived-immutable-names` gains a secret-named MetricFilter.
