- **`AWS::Lambda::EventSourceMapping`: removing `Enabled: false` turns the mapping back on, and removing `BisectBatchOnFunctionError` turns it off (issue [#1160](https://github.com/go-to-k/cdkd/issues/1160))** -- `src/provisioning/providers/lambda-eventsource-provider.ts`, with unit tests in `tests/unit/provisioning/lambda-eventsource-provider.test.ts` and removal phases in the `sqs-esm-max-concurrency` and `kinesis-esm-filter` integ fixtures. An update omitted both keys once they left the template, and `UpdateEventSourceMapping` keeps an omitted field, so a mapping stayed disabled (or kept bisecting failed batches) after the template stopped asking for it, while the deploy reported success. A CloudFormation A/B showed CloudFormation sends `Enabled: true` on that removal and resets `BisectBatchOnFunctionError` to `false`; cdkd now sends the same, the Bisect reset only for the Kinesis and DynamoDB stream sources, and for a Kafka source while it keeps declaring `ProvisionedPollerConfig` (Kafka takes the key in provisioned mode only). Otherwise, as for a source cdkd cannot classify, the value is kept and a warning names it. Removing `DocumentDBEventSourceConfig` has no clear value to send, so cdkd keeps the live block and logs a warning naming it.
