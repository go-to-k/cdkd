- **A physical name derived from a secret no longer prints in the lines of the resources that read it, or in the engine's own lines about it (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/deploy-engine.ts`, `src/deployment/deploy-engine/{masking,resolver-context,provision,create,update,outputs,update-in-place}.ts`, `src/deployment/intrinsic-resolver/{context,getatt,refs}.ts`, `src/deployment/resource-secrets-scope.ts`, `src/deployment/rollback-executor/names.ts`, `src/deployment/secret-redaction/mask-errors.ts`. When a resource's name came from a secret or a `NoEcho` parameter (resolved this deploy, or still recorded as a `{{resolve:` reference after a rotation), a `Ref` / `Fn::GetAtt` to it resolves to a name or ARN no masker recognised. `cdkd deploy --verbose` printed it on the resolver's `resolved to` line, and the reading resource's provider lines, errors and events printed it too, a deleted reader's included. The read value and the name's spellings (the rollback's `secretDerivedNamePairs`) are now masked in those lines. The resource's own lines mask them too, from its create onward, including `Deleting old <id>` and `was replaced: <old> -> <new>`. No persisted property value, sent value or diff changes: the needles are print-only (a masked property's fingerprint can be refused more often, which fails closed). A nested-stack row, the outputs pass and the masked-input fingerprint pass record them into a print-only bag, so their decisions do not change. An event's `physicalId` field stays exact, and so does the id a failed CREATE journals for `--revert-failed`.
