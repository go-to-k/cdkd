- **The SDK provider wires `AWS::S3Tables::TableBucket` `LoggingConfiguration` (issue [#6167](https://github.com/go-to-k/cdkd/issues/6167))** -- `src/provisioning/providers/s3-tables-provider.ts`, `s3-tables/table-bucket.ts`, `read-state.ts`, `shared.ts`, the regenerated property-coverage map, `tests/fixtures/cfn-schemas/_todo-backfill.json`, unit tests, the S3 Tables wire case, the `s3-tables` integ, and a `@aws-sdk/client-s3tables` bump to 3.1167.0 (the first release with the table bucket logging API). Before, a table bucket declaring `LoggingConfiguration` routed through Cloud Control. Now `PutTableBucketLogging` sends it after `CreateTableBucket` and again on an update that changes it, and `readCurrentState` reads it back from `GetTableBucketLogging`, so `cdkd drift` sees a console-side change. Every member of the property is required, so no declared value turns logging off: removing it from the template turns the bucket's logging off, as removing `ReplicationConfiguration` deletes replication. `AWS::S3Tables::TableBucket` now has no SDK-unwired property. Resources already deployed through Cloud Control stay there.
