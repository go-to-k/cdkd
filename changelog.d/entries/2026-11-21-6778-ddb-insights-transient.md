- **`cdkd drift` compares a DynamoDB table's Contributor Insights setting again (issue [#6778](https://github.com/go-to-k/cdkd/issues/6778))** -- `src/provisioning/dynamodb-contributor-insights.ts`, `src/provisioning/providers/dynamodb-table/drift.ts`. The table-level read omitted `ContributorInsightsSpecification` while AWS reported `ENABLING` / `DISABLING`, which is what the post-deploy baseline capture sees, so a table deployed with `contributorInsightsEnabled: true` never had the setting compared and a disable made outside cdkd reported no drift. A transient status now reads as its target (with the mode AWS reports while enabling), as the per-index and GlobalTable replica reads already did. A baseline recorded by an earlier cdkd without the key is compared against the template's declared block while the live table reports one, so `cdkd drift` reports, and `cdkd drift --revert` re-enables, an out-of-band disable on an existing stack without a redeploy.
