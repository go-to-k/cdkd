- **The S3 Tables provider now uses explicitly supplied `AwsClients` credentials (issue [#3588](https://github.com/go-to-k/cdkd/issues/3588))** -- `src/provisioning/providers/s3-tables-provider.ts`; tests in `tests/unit/utils/ambient-client-defaults.test.ts` and `tests/unit/utils/ambient-client-defaults-fence.test.ts`. A library caller that installed `AwsClients` with an explicit `credentials` object had every `AWS::S3Tables::TableBucket` / `Namespace` / `Table` call sign with the SDK's default credential chain instead. Its client now goes through `ambientClientDefaults()`, like every other SDK provider, and the file leaves the fence allow-list. CLI runs are unaffected: no command passes explicit credentials. The two remaining allow-listed command handlers (`deploy.ts`'s caller-identity lookup and `export.ts`'s two lookups) are CLI-only, reached by no library entry point, and stay as they are.
