- **The intrinsic resolver masks a resolved secret AT the throw and in the log line beside it, and registers an `Fn::Base64` encoding as a derived needle so it is not persisted (issues [#2827](https://github.com/go-to-k/cdkd/issues/2827), [#2759](https://github.com/go-to-k/cdkd/issues/2759))** -- `src/deployment/intrinsic-function-resolver.ts`, `scripts/check-resolver-mask-coverage.ts`, `tests/unit/deployment/intrinsic-resolver-throw-masking.test.ts`, `tests/integration/secrets-dynamic-ref/`. **Bug (#2827):** the resolver masked a resolved value when it LOGGED it and left it bare when it THREW, so an assembled plaintext travelled to every caller inside an error message; [#2728](https://github.com/go-to-k/cdkd/issues/2728) and [#2803](https://github.com/go-to-k/cdkd/issues/2803) each fixed one boundary only. **Bug (#2759):** `Fn::Base64` over a dynamic reference returned the secret in a reversible encoding no needle matches, so it reached `state.json` and printed on the debug line that masked its own input. **Fix:** every throw and log statement naming a `resolveValue` result masks the RAW value, never the assembled message. The two truncating region gates mask around `stripControlChars`, never after `.slice(0, 64)`. `resolveBase64` records its OUTPUT as a mask-only needle when masking changed its input; JSON encodings are leaf-masked first. The population is no longer hand-enumerated -- three sweeps disagreed, so `scripts/check-resolver-mask-coverage.ts` (CI) requires every interpolating site in that file to be masked or carry a written exclusion note. That mask also reaches four refusals that name only their NoEcho source -- folded onto [#2881](https://github.com/go-to-k/cdkd/issues/2881), which owns them. Three residuals are stated at their sites; `Fn::Base64` also resolves differently on the deploy and diff paths ([#2909](https://github.com/go-to-k/cdkd/issues/2909), predating this change).
