- **A failed SNS Subscription create, update or delete, a rollback's reverse replacement, or an `Fn::GetAZs` lookup no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/sns-subscription-provider.ts`, `src/deployment/rollback-executor/replay-reverse-replacement.ts`, `src/deployment/intrinsic-resolver/functions.ts`, `src/deployment/work-graph.ts`, and unit cases. These messages quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. They now carry the error class (`AuthorizationErrorException. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, masked. In a rollback this covers the re-create of the old resource after the new one was deleted, the `Underlying collision:` line of a refused reverse replacement, and the reason recorded for a new resource that could not be deleted. The `N node(s) failed` summary at the end of a deploy names an AWS-authored failure (an asset upload's `AccessDenied`) the same way; its `Failed:` line above still prints AWS's text. A cdkd-authored or transport error keeps its text, and the AWS error stays as the `cause`, so a throttle or a still-propagating IAM grant is retried as before and a taken subscription still reads as a name collision.
