- **`cdkd deploy` masks a secret-derived name a parent passes to a nested stack (issue [#3869](https://github.com/go-to-k/cdkd/issues/3869))** -- `src/deployment/deploy-engine/resolver-context.ts`, `src/deployment/deploy-engine/create.ts`, `src/deployment/deploy-engine/update.ts`. Consider a nested stack whose parameter reads a resource named from a secret, such as `Parameters: { QueueArn: GetAtt SecretQueue.Arn }` where the queue's name comes from Secrets Manager. That read's needles went into a print-only bag that nothing used after the row's own resolver line. The child stack inherits only the row's own secrets, which deliberately hold no read needles, since they would seed the child's export-name verdict. So the child's `Resolved Ref to parameter: QueueArn` and `Parameter QueueArn: using user-provided value` lines, its provider lines and the row's own provider lines printed the name. The row's print-only bag is now its derived-name registry, which is bound as a printing bag around the row's whole body and therefore around the child's deploy. The child's inherited secrets are unchanged. The `cdkd diff` walk into a child is not covered yet. Tests: `tests/unit/deployment/deploy-engine-derived-name-needle-3869.test.ts`. Integ `secret-derived-immutable-names` gains the nested stack `QueueReaderChild`, fed SecretQueue's ARN; the deploy and update logs must not name the queue.
