- **A resource an SDK provider refuses to update in place is no longer replaced without `--replace` when the refusal's message happens to contain "does not support UPDATE" (issue [#3757](https://github.com/go-to-k/cdkd/issues/3757))** -- `src/deployment/retryable-errors.ts` (`isUpdateUnsupportedError`), with unit tests in `tests/unit/deployment/retryable-errors.test.ts` and `tests/unit/deployment/deploy-engine-replace.test.ts`. The update-failure fallback's Cloud Control classifier read any top-level message containing that phrase as "this type has no UPDATE handler" and ran the DELETE + CREATE with no flag. A typed `ResourceUpdateNotSupportedError` interpolates template-chosen text (the Glue rename refusal quotes both names), so a name carrying the phrase skipped the `--replace` opt-in. The classifier now refuses a typed rejection outright; it replaces only under `--replace`, as documented.
