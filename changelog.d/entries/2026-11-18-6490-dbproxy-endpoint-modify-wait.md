- **`cdkd deploy` waits for an `AWS::RDS::DBProxyEndpoint` to be `available` after a security-group update (issue [#6490](https://github.com/go-to-k/cdkd/issues/6490))** -- `src/provisioning/providers/rds-dbproxy-endpoint-provider.ts`. `ModifyDBProxyEndpoint` returns while the endpoint is still `modifying`, and the SDK provider used to return right after it, so the next modify or a delete in the same run could be refused. The update now polls until the endpoint is `available`, as its create does, as the `AWS::RDS::DBProxy` update does and as Cloud Control's update handler does. An endpoint that disappears or enters `incompatible-network` / `insufficient-resource-limits` fails the update instead of waiting out the deadline. `--no-wait` does not skip this wait, the same as for a proxy.
