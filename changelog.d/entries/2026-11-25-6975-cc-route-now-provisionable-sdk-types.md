- **Seven SDK-provider types AWS has since given Cloud Control handlers take the Cloud Control route again (issue [#6975](https://github.com/go-to-k/cdkd/issues/6975))** -- `src/provisioning/unsupported-types.ts`, the `codebuild`, `docdb`, `emr-cluster`, `emr-instance-group-config` and `emr-instance-fleet-config` providers, `src/provisioning/resource-name/fallback-rules.ts`, `scripts/audit-provider-coverage.ts`. `AWS::CodeBuild::Project`, `AWS::DocDB::DBInstance`, `AWS::EMR::Cluster`, `AWS::EMR::InstanceGroupConfig`, `AWS::EMR::InstanceFleetConfig`, `AWS::Budgets::Budget` and `AWS::Glue::Table` were `NON_PROVISIONABLE` when their SDK providers landed and are `FULLY_MUTABLE` today. A template setting a property their SDK provider does not handle was refused pre-flight; it now deploys through Cloud Control, as CloudFormation does, and `--recreate-via-cc-api` accepts them. An un-named budget created through Cloud Control gets the name its SDK provider generates. The provider-coverage audit records the registered types AWS still reports `NON_PROVISIONABLE` (`tier1NonProvisionable`), and a unit test fails when the hand-kept list or a provider's `disableCcApiFallback` disagrees with it.
