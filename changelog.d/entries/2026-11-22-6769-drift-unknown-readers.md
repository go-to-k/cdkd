- **`cdkd drift` now compares `AWS::IAM::UserToGroupAddition`, `AWS::CloudWatch::AnomalyDetector`, `AWS::EMR::InstanceFleetConfig` and `AWS::EMR::InstanceGroupConfig`, which were always drift unknown (issue [#6769](https://github.com/go-to-k/cdkd/issues/6769), part of [#6696](https://github.com/go-to-k/cdkd/issues/6696))** -- `src/provisioning/providers/iam-user-group/read-state.ts`, `src/provisioning/providers/cloudwatch-anomaly-detector-provider.ts`, `src/provisioning/providers/emr-instance-{fleet,group}-config{-provider.ts,/read-state.ts}`, `src/analyzer/drift-cc-api-deny-list.ts`, `docs/cli-drift.md`, unit tests, and drift arms in the `iam-recreate-reattach`, `cloudwatch-anomaly-detector`, `emr-instance-fleets` and `emr-instance-configs` integ fixtures. Since #6696 a drift-unknown resource makes a clean run exit 2, so a stack holding one of these exited 2 on every run, and an out-of-band change to them was never reported. Each now has a read-back: the addition lists each recorded user's groups (`ListGroupsForUser`); the detector is found by its recorded metric descriptor (`DescribeAnomalyDetectors`); the fleet and the group are read on their recorded cluster (`ListInstanceFleets` / `ListInstanceGroups`). A detector, fleet or group AWS no longer has, and an addition whose group is gone, report as deleted. A record whose address holds a redacted or secret-derived value stays drift unknown. The read also runs for the baseline cdkd records after each deploy, like every other read-back. These types and `AWS::EC2::LaunchTemplate` leave the Cloud Control deny-list; the launch template, which has no SDK provider, was already read through Cloud Control.
