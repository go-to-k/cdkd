- **`cdkd deploy` / `cdkd diff` no longer exit 0 having done nothing when a create-only schema lookup is throttled (issue [#3939](https://github.com/go-to-k/cdkd/issues/3939))** -- `src/provisioning/describe-type.ts`, `src/utils/concurrency-limiter.ts`, `src/deployment/resource-deadline.ts`, `src/cli/run-cli.ts` (new), `src/cli/index.ts`, and unit tests. The deploy-start schema prefetch sleeps its throttle backoff on an unref'd timer, so it never holds the process open. When the diff then awaited the same resource type, the call was promoted but kept sleeping on that unref'd timer; with nothing else holding the event loop, Node exited 0 mid-command, leaving the template unapplied and the stack lock held. The backoff is now ref'd whenever a command waits on it: when the call is promoted (including a sleep already under way), and when an awaited lookup is queued behind background calls that hold every slot. The per-resource `--resource-timeout` timer is now ref'd too, so a provider call that stalls times out instead of letting the process drain. Any remaining case of this kind now fails loudly: if the event loop empties while a command is still pending, cdkd prints an error with the `cdkd force-unlock` hint and exits 70 (`EX_SOFTWARE`), now listed in the exit-code table of `docs/_contents/cli-reference.md`.
