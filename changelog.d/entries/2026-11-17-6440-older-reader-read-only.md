- **An older cdkd can now read, but not write, a state record whose newer schema version only added fields (issue [#6440](https://github.com/go-to-k/cdkd/issues/6440))** -- `src/types/state.ts`, `src/state/s3-state-backend/legacy.ts`, `src/state/s3-state-backend/state-record.ts`. A record may name the oldest schema version that can read it (`minReaderVersion`). When a record's `version` is newer than this cdkd knows but its `minReaderVersion` is one it reads, read-only commands use it: `cdkd diff`, `cdkd state show` / `resources` / `list`, `Fn::GetStackOutput` and `Fn::ImportValue` reads of the stack, a nested parent reading its child, and `cdkd local`. A command that would write the record (`deploy`, `destroy`, `rollback`, `import` and the state-mutating commands) refuses it when it loads that stack's record, before changing anything in that stack, with an error that names the newer version and says to upgrade. `saveState` refuses it too. This is not a schema bump: records this release writes are unchanged, and releases before it still refuse any newer version. Contract and the rule for future bumps: [State schema internals](https://github.com/go-to-k/cdkd/blob/main/docs/state-schema-internals.md#minreaderversion-reading-a-newer-record-read-only).
