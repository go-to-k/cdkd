- **A custom resource whose properties name a just-created Lambda function no longer fails because that function is still `Pending` (issue [#5261](https://github.com/go-to-k/cdkd/issues/5261)).** `LambdaFunctionProvider.create` returns while the function is `Pending`, and a handler that hands such an ARN to AWS is rejected until the function is `Active`. The CDK `BucketNotifications` handler does exactly that with an S3 notification destination, so a VPC-attached destination failed with `Unable to validate the following destination configurations` and rolled the whole stack back. A custom resource now reads each Lambda function ARN in its resolved properties once per create / update (never its own backing function; on update only an ARN that is new since the previous properties) and, for a function that is `Pending`, waits for it to become `Active` before the handler runs, within one shared 600s budget. The wait is best effort: an unreadable function, a `Failed` one or a spent budget leaves the verdict to the handler, only Ctrl-C throws, and a resource that names no function ARN pays nothing. Source: `src/provisioning/providers/custom-resource-provider.ts`.
