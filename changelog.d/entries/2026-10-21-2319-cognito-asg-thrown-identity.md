- **A failed Cognito User Pool or Auto Scaling group create, update or delete no longer writes the caller's account id, assumed-role ARN and session name into the persisted deployment events (issue [#2319](https://github.com/go-to-k/cdkd/issues/2319))** -- `src/provisioning/providers/{cognito,asg}-provider.ts`, and unit cases. The thrown message quoted AWS's raw text, which names the caller on an access denial, and `deployments/{runId}.jsonl` outlives the run. The message now carries the error class (for example `AccessDeniedException. Re-run with --verbose for AWS's own message.`), and AWS's text goes to the debug log, through the operation's secret masker. This also covers the Auto Scaling group's note about a group whose create-time cleanup could not finish (the group and its delete command are still named), and the warning about a user pool whose partial-create cleanup failed. A cdkd-authored or transport error keeps its text, masked through the operation's secret masker on both providers (the Cognito wraps and the Auto Scaling group delete now apply it too). The AWS error stays as the `cause`, so an IAM grant that is still propagating is retried as before, and an "already exists" is still stated as such.
