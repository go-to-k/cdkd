- **The Provider Coverage Report and the Tier 3 pre-flight refusal list are current again (issue [#5214](https://github.com/go-to-k/cdkd/issues/5214))** -- `scripts/audit-provider-coverage.ts` (`listProvisioningTypes`), `docs/_generated/provider-coverage.{json,md}`, `src/provisioning/unsupported-types.generated.ts`, `src/provisioning/stateful-types.ts`, `docs/_generated/stateful-candidates.{json,md}`, `docs/cli-deploy-safety.md`. The report had not been regenerated since 2026-09-04: 220 types AWS publishes were in no tier (among them `AWS::Lambda::WebFunction`, now Tier 2), and 27 types AWS has since made provisionable (e.g. `AWS::AppStream::Fleet`, `AWS::Config::ConfigurationRecorder`) were still refused at pre-flight; they now deploy through Cloud Control. 88 newly published NON_PROVISIONABLE types are now refused up front. The regeneration reads each type's provisioning type from three filtered `ListTypes` walks instead of one `DescribeType` call per type. Of the newly covered types, 19 that hold data (snapshots and backups of DocDB Elastic, ElastiCache, FSx, MemoryDB, Redshift and Timestream InfluxDB, Storage Gateway volumes, FSx file caches, Managed Microsoft AD directories, SageMaker notebook instances, Cloud9 EC2 environments, and seven types whose emptiness cannot be proven) join the stateful guard, so a deploy that would replace one asks for `--force-stateful-recreation` as for the other data-bearing types.
