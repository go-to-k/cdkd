- **`cdkd destroy --purge-events` and `cdkd events prune` now purge the earlier versions of the deployment-event objects they delete (issue [#2624](https://github.com/go-to-k/cdkd/issues/2624), site 3)** -- `src/state/deployment-events-store.ts` (`deleteAndPurgeEventObjects`, used by all four deletes under `deployments/`), `src/cli/commands/events.ts`, `src/cli/commands/destroy.ts`, `docs/deployment-events.md`, `docs/cli-destroy.md`, `docs/cli-events.md`, `docs/ci-per-pr.md` and `docs/state-management.md`. Before, every delete there sent `DeleteObjects` with no `VersionId`. On the versioned state bucket that only wrote delete markers, and because each run's JSONL is re-PUT in full on every flush, one readable version per flush survived. The output said so instead of claiming removal. Each delete now also runs the shared fail-soft `purgeNoncurrentVersions` over the deleted keys, in a `finally`. The writer's self-bounding prune is included, because a stream it drops is no longer listed and a later `--all` could not reach it, so a deploy past 20 runs can print the purge's IAM or replication warning too. Without `s3:ListBucketVersions` / `s3:DeleteObjectVersion` the command still succeeds, and a warning prints before the `Pruned` / `Purged` line, which now says "unless a warning above says otherwise". On an unversioned bucket nothing extra is deleted. Not reached: streams deleted before a purge ran on them (an earlier release, or a purge that warned), the earlier versions of an `index.json` that a partial prune rewrites (run metadata only), and a replica.
