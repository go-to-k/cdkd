- **A `--revert-failed` rollback that re-creates an `AWS::EC2::SecurityGroupIngress` rule no longer keeps the revoked rule's `sgr-` id (issue [#4484](https://github.com/go-to-k/cdkd/issues/4484))** -- `src/provisioning/providers/ec2-provider.ts`. When the replay re-authorized a rule the refused update had already revoked, it answered an in-place update, so a response naming no single rule id left the revoked id under `attributes.Id` for `cdkd export` and `Fn::GetAtt <rule>.Id` to read. It now answers a replacement, so only an id found now is recorded: the one the response names, else the one rule matching it on the group, else none. A live rule the replay adopts is recorded the same way, since an earlier send of the same replay may have created it. Tests: `tests/unit/provisioning/ec2-sg-ingress-duplicate-ownership.test.ts`.
