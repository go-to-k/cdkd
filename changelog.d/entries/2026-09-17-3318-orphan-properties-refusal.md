- **`cdkd orphan` no longer saves a resource record whose `properties` map it could not read (issue [#3318](https://github.com/go-to-k/cdkd/issues/3318))** -- `src/cli/commands/orphan.ts`, `src/state/malformed-resources-bag.ts`, `docs/state-management.md`, `.claude/rules/state-malformed-properties.md`, `tests/unit/cli/orphan.test.ts`, `tests/unit/state/malformed-resources-bag.test.ts`. `rewriteResourceReferences` passes each surviving record's bag through `rewriteValue`, whose first line returns a non-object verbatim, and re-assigns the result through a bare cast; `refuseMalformedState` above it answers a question about the record ROOT only, and `unreadableResourcePropertyBags` deliberately returns `[]` for a record whose root bag is unreadable, so the per-ENTRY container was unguarded on a WRITE path. Measured through the real rewriter: `"abcdef"` came back `"abcdef"`, `5` as `5`, `null` as `null`, `[]` as `[]`, and an absent bag stayed absent -- so nothing was fabricated, but the command took a lock, saved, and reported success over a record the next `cdkd deploy` refuses ([#3191](https://github.com/go-to-k/cdkd/issues/3191)) and a `cdkd diff` in between previews as a replacement. A LIST bag is the one unreadable shape `rewriteValue` walks, so its rewrites landed in the audit table while the container stayed un-map-like. `refuseMalformedResourcePropertiesForOrphan` now refuses at the load, above the rewrite and above the `--dry-run` return, carrying its own text because the deploy sibling's diff verdict and the `outputs` refusal's laundering sentence are both false here. It is SCOPED to the records the save would KEEP -- it takes the orphan set and never names one -- which is what keeps `cdkd orphan <the damaged resource>` working as the per-resource way out of a torn record, and is why there is no `--force` bypass: forcing would still leave a record `cdkd deploy` refuses.
