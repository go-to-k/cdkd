- **`cdkd state show` / `state resources` no longer print `U+2028` / `U+2029` in a record key, logical id or value, and `cdkd diff` masks a secret that one of them split in a blocking reason (issue [#2888](https://github.com/go-to-k/cdkd/issues/2888))** -- `src/utils/regexp.ts`, `src/cli/commands/state.ts`, `src/cli/commands/diff-recursive.ts`, `src/analyzer/outputs-diff.ts`. The state views write to stdout directly and stripped control characters with `stripControlChars` alone, which keeps both separators, and a JSON or web log viewer breaks a line on either, so a hand-edited record could still forge a row there. They now go through `stripForDisplay`, which deletes the same class, replaces the two separators with a space and trims; a legitimate value renders as before apart from leading and trailing whitespace, which is now trimmed. The `cdkd diff` headers, blocking reasons, Outputs preview values and warnings and the Outputs debug lines take the same helper; the logger already printed both separators as a space there, so only the trim is new. A blocking reason is now masked after that substitution, so a `NoEcho` value holding a space, carried as `correct<U+2028>horse`, prints as `***` rather than `correct horse`, including in `--json`'s `blocking`. Tests: `tests/unit/utils/regexp.test.ts`, `tests/unit/cli/state-show.test.ts`, `tests/unit/cli/state-resources.test.ts`, `tests/unit/cli/diff-recursive.test.ts`, `tests/unit/cli/diff-noecho-render-4049.test.ts`, `tests/unit/analyzer/outputs-diff.test.ts`.
