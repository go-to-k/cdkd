- **`cdkd drift` reports an `AWS::CloudWatch::AnomalyDetector` as drift unknown again instead of exiting 2 (issue [#4668](https://github.com/go-to-k/cdkd/issues/4668))** -- `src/analyzer/drift-cc-api-deny-list.ts`. AWS gave the type Cloud Control handlers. The SDK provider has no `readCurrentState`, so drift fell back to Cloud Control `GetResource` with cdkd's descriptor-derived physicalId, which Cloud Control refuses with a ValidationException on every run. That was reported as a read failure (`NOT fully compared`, exit 2) on every drift run of any stack holding a detector. The type is now on the Cloud Control fallback deny-list, so the row reports drift unknown and the run exits 0 as it did before. Tests: `tests/unit/cli/drift-per-resource-failure.test.ts`; integ `cloudwatch-anomaly-detector`.
