- **`cdkd rollback` now refuses a state record whose `region` field disagrees with its key while it still lists resources (issue [#3370](https://github.com/go-to-k/cdkd/issues/3370))** -- `src/cli/commands/rollback.ts`, `docs/cli-rollback.md`, `docs/state-management.md`, plus `rollback-divergent-region.test.ts`.
  - `getState` reported the divergence and `cdkd rollback` dropped the report. The replay deletes and reverts in the KEY's region and reads a not-found delete as already rolled back, so if the record's own region was the honest half, a rolled-back CREATE was reported reverted, dropped from the record, and left live in the other region. `cdkd destroy` refused this record since #3328; rollback did not.
  - The refusal runs once, before the plan, the prompt and every replay arm, with code `STATE_REGION_DIVERGED`. Every arm that calls AWS needs a current state row: the CREATE delete, the in-place revert, both reverse-replacement arms (re-CREATE included) and `--revert-failed`. So a record listing no resources is let through, as on the destroy path.
  - The message prints the kind of the body's value (`a string`), never the value.
  - The retry save after a lost conditional write no longer writes over a record rewritten mid-run with a disagreeing `region`. The run stops after that operation, keeps the journal segment and the record, and exits 2; the re-run meets the refusal.
